# Assessment of the Termination Measure

## Verdict: **UNSOUND** ❌

The proposed lexicographic measure `(phase t, cost t)` does **not** guarantee termination for this rewrite system. Here's why:

## Critical Counterexample

Consider rule **R_rec_succ**:
```
Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

Let's trace what happens to the measure:

**Before:** `recDelta b s (delta n)`
- `phase = 1` (matches the pattern `recDelta _ _ (delta _)`)
- `cost = 1 + cost b + cost s + (1 + cost n)`

**After:** `app s (recDelta b s n)`
- `phase = 0` (no top-level `recDelta _ _ (delta _)` pattern)
- `cost = 1 + cost s + (1 + cost b + cost n)`

The phase **decreases** (1 → 0), which is good. However, let's examine what the cost actually becomes:

```
cost (app s (recDelta b s n)) 
  = 1 + cost s + (1 + cost b + cost n)
  = 2 + cost b + cost s + cost n
```

Compare to the original cost:
```
cost (recDelta b s (delta n))
  = 2 + cost b + cost s + cost n
```

**The costs are identical!** This means repeated applications of R_rec_succ can occur indefinitely while keeping the measure constant at `(0, 2 + cost b + cost s + cost n)`.

## The Problem

The measure design has a fundamental flaw: it only distinguishes `recDelta b s (delta n)` at phase 1, but the actual rewrite creates an `app` node that stays at phase 0. The cost structure doesn't capture the structural growth from unwrapping `delta n` into the recursive call.

## What Would Be Needed

A sound measure would need to either:
1. Track the nesting depth of `delta` constructors within arguments
2. Include a third component that measures structural reduction
3. Assign strictly decreasing costs that account for the `app` node creation
