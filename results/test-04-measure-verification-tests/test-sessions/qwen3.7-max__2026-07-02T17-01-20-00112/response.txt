## Assessment: The Measure is **Not Sound**

### The Problem

The `phase` function creates a measure that **increases** on certain rewrite steps, violating the requirement that the measure must strictly decrease on every step.

### Counterexample

Consider `R_merge_void_left` applied to the term `merge void (recDelta b s (delta n))`:

**LHS:** `merge void (recDelta b s (delta n))`
- `phase` = **0** (the top-level constructor is `merge`, not `recDelta`)
- `cost` = `1 + cost void + cost (recDelta b s (delta n))` = `3 + cost b + cost s + cost n`
- Measure: **(0, 3 + cost b + cost s + cost n)**

**RHS:** `recDelta b s (delta n)`
- `phase` = **1** (matches `.recDelta _ _ (.delta _)`)
- `cost` = `1 + cost b + cost s + 1 + cost n` = `2 + cost b + cost s + cost n`
- Measure: **(1, 2 + cost b + cost s + cost n)**

In the lexicographic order on `Nat × Nat`, we compare the first components first:

$$0 < 1 \implies (0,\; 3 + \cdots) \;<\; (1,\; 2 + \cdots)$$

The measure **strictly increases** from LHS to RHS. The same problem occurs with `R_merge_void_right` and `R_merge_cancel` when `t` is chosen to be a `recDelta` term whose third argument is a `delta`.

### Root Cause

The `phase` function only inspects the top-level constructor. Rules like `R_merge_void_left` strip away an outer `merge` and expose a subterm. If that subterm happens to be `recDelta _ _ (delta _)`, the phase jumps from 0 to 1. Since the lexicographic order prioritizes `phase` over `cost`, no decrease in `cost` can compensate for an increase in `phase`.

### Why `phase` Was Introduced (and Why `cost` Alone Fails)

The `phase` component was likely added to handle `R_rec_succ`:

| | `recDelta b s (delta n)` → `app s (recDelta b s n)` |
|---|---|
| LHS cost | `2 + cost b + cost s + cost n` |
| RHS cost | `2 + cost b + 2·cost s + cost n` |

Here `cost` **increases** by `cost s`, so `cost` alone is not a valid measure. The `phase` drop from 1 → 0 was intended to compensate. However, this fix is incomplete because other rules can cause the phase to rise.

### Note on Actual Termination

The rewrite system itself *is* terminating (every rule except `R_rec_succ` strictly decreases `cost`, and `R_rec_succ` produces an `app` at the root, which is a normal form — so it can fire at most once, at the end of any chain). However, the **proposed measure fails to prove it**.
