The proposed measure is **sound for the literal `Step` relation as written**, but **not sound for a usual first-order rewrite relation closed under contexts/subterms**.

Assuming lexicographic order on `(phase t, cost t)`:

- All root rules decrease the measure.
- The key special case is:

```lean
Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

At the root:

```lean
phase (recDelta b s (delta n)) = 1
phase (app s (recDelta b s n)) = 0
```

so the measure decreases lexicographically even though the cost may increase.

Indeed:

```lean
cost (recDelta b s (delta n))
= 2 + cost b + cost s + cost n

cost (app s (recDelta b s n))
= 2 + cost b + 2 * cost s + cost n
```

so the RHS cost is larger by `cost s`.

That is harmless only because the top-level `phase` drops from `1` to `0`.

However, if rewrites are allowed inside contexts, the measure fails. For example, take the context `integrate _`. Then the same rewrite gives:

```lean
integrate (recDelta b s (delta n))
  ↦ integrate (app s (recDelta b s n))
```

But both whole terms have phase `0`, since the top-level constructor is `integrate`. The cost increases by `cost s`, so the lexicographic measure increases.

Concrete instance:

```lean
b = void
s = delta void
n = void
```

Then:

```lean
measure (integrate (recDelta void (delta void) (delta void)))
= (0, 4)

measure (integrate (app (delta void) (recDelta void (delta void) void)))
= (0, 5)
```

So under contextual rewriting the measure goes from `(0, 4)` to `(0, 5)`, which is an increase.

Therefore:

- For the exact inductive relation `Step` in the file, the measure decreases on every rule.
- For a genuine first-order rewrite calculus with closure under contexts, the measure is **not sound**, because `phase` only inspects the top-level constructor and cannot compensate for cost increases caused by nested `R_rec_succ` steps.
