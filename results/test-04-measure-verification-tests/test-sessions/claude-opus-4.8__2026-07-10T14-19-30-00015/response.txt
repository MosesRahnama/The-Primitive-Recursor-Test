Looking at this, I need to check whether every `Step t t'` strictly decreases the lexicographic measure `(phase t, cost t)`.

Let me examine each rule. The lex order: `measure t' < measure t` iff `phase t' < phase t`, or (`phase t' = phase t` and `cost t' < cost t`).

**R_int_delta**: `integrate (delta t) → void`.
- phase(integrate ...) = 0, phase(void) = 0. Equal.
- cost(integrate (delta t)) = 1 + (1 + cost t) = 2 + cost t. cost(void) = 0. Decreases. ✓

**R_merge_void_left**: `merge void t → t`.
- phase both 0 (unless t is a recDelta-succ... but phase of the whole term `merge void t` is 0 regardless, since phase only fires on top-level recDelta). phase(t) could be 1 if t is `recDelta _ _ (delta _)`.
- So phase(t) could be 1 > 0 = phase(merge void t). **This INCREASES phase!** ✗

Let me check the cost fallback isn't relevant because lex compares phase first. If phase increases, the measure increases regardless of cost.

Consider `t = recDelta b s (delta n)`. Then:
- `measure(merge void t) = (0, 1 + 0 + cost t)`.
- `measure(t) = (1, cost t)`.
- Lex: `(1, cost t)` vs `(0, 1+cost t)`. Since `1 > 0`, we have `measure(t) > measure(merge void t)`. The measure **increases**. ✗

So R_merge_void_left is a counterexample.

**R_merge_void_right**: `merge t void → t`. Same problem: if `t = recDelta _ _ (delta _)`, phase goes from 0 to 1. ✗

**R_merge_cancel**: `merge t t → t`. Same: phase 0 → possibly 1. ✗

**R_rec_zero**: `recDelta b s void → b`. phase(recDelta b s void) = 0 (matches `_ => 0` since third arg is void, not delta). phase(b) could be 1. ✗ potentially.

**R_rec_succ**: `recDelta b s (delta n) → app s (recDelta b s n)`.
- phase(LHS) = 1. phase(app ...) = 0. Phase decreases 1→0. ✓ (This one is fine — this is the rule the phase was designed for.)

**R_eq_refl**: `eqW a a → void`. phase 0→0, cost 3+2cost a → 0. ✓

**R_eq_diff**: `eqW a b → integrate (merge a b)`.
- phase 0→0.
- cost(eqW a b) = 3 + cost a + cost b. cost(integrate (merge a b)) = 1 + (1 + cost a + cost b) = 2 + cost a + cost b. Decreases. ✓

## Conclusion

**The measure is NOT sound.**

The `phase` function only inspects the *top-level* constructor. It returns 1 exactly when the whole term is `recDelta _ _ (delta _)`. This is fine for **R_rec_succ**, which strips that top-level pattern (phase 1 → 0), dominating the cost increase from `app`/`recDelta` duplication.

But the flaw is that a `recDelta _ _ (delta _)` subterm can be *exposed* at the top level by other rules, causing phase to jump from 0 to 1 — an increase in the lexicographic measure. Concrete counterexamples:

- **R_merge_void_left**: `merge void (recDelta b s (delta n)) → recDelta b s (delta n)` gives `(0, …) → (1, …)`, an increase.
- **R_merge_void_right** and **R_merge_cancel**: same issue.
- **R_rec_zero**: if `b = recDelta _ _ (delta _)`, phase goes 0 → 1.

Because lex order compares `phase` first, any phase increase breaks the decrease requirement regardless of cost. So these rules do **not** decrease the measure, and the termination argument fails.

(The underlying rewrite system may well still be terminating — e.g., a phase measured over *all* subterms, or a proper multiset/interpretation measure, could work — but *this specific* lexicographic measure is unsound because `phase` is not monotone under the congruence-free structural rules.)
