## Assessment of the Termination Measure

### The Proposed Measure

The measure is `(phase t, cost t)` ordered lexicographically, where:
- `phase t = 1` if `t = recDelta _ _ (delta _)`, else `0`
- `cost t` is a structural size measure

For the measure to be sound, every rewrite step `Step t t'` must satisfy `measure t' < measure t` lexicographically, i.e., either `phase t' < phase t`, or `phase t' = phase t` and `cost t' < cost t`.

---

### Analysis of Each Rule

**R_int_delta**: `integrate (delta t) → void`
- phase: 0 → 0; cost: 1+(1+cost t) → 0. ✅

**R_merge_void_left**: `merge void t → t`
- phase: 0 → 0; cost: 1+0+cost t → cost t. ✅

**R_merge_void_right**: `merge t void → t`
- phase: 0 → 0; cost: 1+cost t+0 → cost t. ✅

**R_merge_cancel**: `merge t t → t`
- phase: 0 → 0; cost: 1+cost t+cost t → cost t. ✅

**R_rec_zero**: `recDelta b s void → b`
- phase: 0 → 0; cost: 1+cost b+cost s+0 → cost b. ✅

**R_rec_succ**: `recDelta b s (delta n) → app s (recDelta b s n)`
- Source phase = **1** (matches `recDelta _ _ (delta _)`)
- Target phase = 0 (since `recDelta b s n` has `n`, not `delta _` structurally at top of result — the result is `app`, so phase = 0)
- Since phase decreases (1 → 0), cost comparison is irrelevant. ✅

**R_eq_refl**: `eqW a a → void`
- phase: 0 → 0; cost: 3+cost a+cost a → 0. ✅

**R_eq_diff**: `eqW a b → integrate (merge a b)`
- phase: 0 → 0; cost: 3+cost a+cost b → 1+(1+cost a+cost b) = 2+cost a+cost b. 
- We need `2 + cost a + cost b < 3 + cost a + cost b`. ✅

---

### Critical Problem: The Measure Only Covers Top-Level Steps

The rules as stated apply only to **ground terms at the top level**. A rewrite calculus needs a **congruence closure** — rules must also apply under constructors (inside `delta`, `integrate`, `merge`, `app`, `recDelta`, `eqW`).

The measure as defined **does not account for reductions inside subterms**. For example, reducing inside `merge (eqW a b) t` produces `merge (integrate (merge a b)) t` via R_eq_diff applied to the left subterm. Here:
- Both terms have phase 0
- cost of result: `1 + (1 + 1 + cost a + cost b) + cost t = 3 + cost a + cost b + cost t`
- cost of source: `1 + (3 + cost a + cost b) + cost t = 4 + cost a + cost b + cost t`
- This still decreases. ✅ in this case.

However, **R_rec_succ under a context** is the real danger. If `recDelta b s (delta n)` appears inside another `recDelta` as the `n` argument, e.g., `recDelta b' s' (delta (recDelta b s (delta n)))`, the inner step changes phase of the inner subterm from 1→0, but the outer term's phase is **still 1** (it matches `recDelta _ _ (delta _)`). So the outer measure doesn't change on the phase component, and cost could increase if the inner reduct is larger — but R_rec_succ replaces `recDelta b s (delta n)` with `app s (recDelta b s n)`, which has cost `1 + cost s + (1 + cost b + cost s + cost n)`, which is larger than `1 + cost b + cost s + (1 + cost n)`. **Cost increases under contexts.**

---

### Verdict

**The measure is unsound.** It handles top-level steps correctly, but fails to account for reductions in subterm positions, particularly `R_rec_succ`, which **increases `cost`** while only decreasing `phase` locally. Under a context that preserves `phase = 1` at the outer level, neither component of the lexicographic measure decreases.
