Short answer: **no, this measure is not sound for proving termination of `Step` by strict decrease on every rule**.

A lexicographic measure `(phase t, cost t)` must strictly decrease from LHS to RHS for each rewrite rule. It already fails on multiple rules.

Counterexamples:

1. **`R_int_delta`**  
   `integrate (delta t) → void`  
   - phase: `0 → 0`  
   - cost: `2 + cost t → 0` (decreases) ✅

2. **`R_merge_void_left`**  
   `merge void t → t`  
   - phase: `0 → phase t`  
   If `t = recDelta b s (delta n)`, then `phase t = 1`, so phase goes `0 → 1` (increases) ❌  
   Lex order fails immediately.

3. **`R_rec_succ`**  
   `recDelta b s (delta n) → app s (recDelta b s n)`  
   - phase: `1 → 0` (good)  
   - but cost:  
     LHS = `1 + cost b + cost s + (1 + cost n) = 2 + cost b + cost s + cost n`  
     RHS = `1 + cost s + (1 + cost b + cost s + cost n) = 2 + cost b + 2*cost s + cost n`  
     So RHS is larger by `cost s`; if `cost s > 0`, cost increases.  
   This is okay only if lex uses phase first (which it does), so this rule is fine under lex.

4. **`R_eq_diff`**  
   `eqW a b → integrate (merge a b)`  
   - phase: `0 → 0`  
   - cost: `3 + cost a + cost b → 2 + cost a + cost b` (decreases) ✅

5. **`R_eq_refl`**  
   `eqW a a → void`  
   cost decreases ✅

So the fatal issue is rules like `merge void t → t` (and similarly `merge t void → t`) where phase on RHS can be larger. Therefore `(phase, cost)` is **not** a valid global decreasing measure for one-step rewriting.

If you wanted this style to work, you’d need either:
- a phase that is **context-monotone** and never increases under any RHS shape, or
- reorder/reshape measure (e.g. prioritize a size that always drops on merge rules), or
- use a more sophisticated termination argument than a simple per-step lex decrease on the whole term.
