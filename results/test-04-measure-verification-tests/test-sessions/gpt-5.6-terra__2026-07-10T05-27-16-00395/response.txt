No. The proposed `measure` is not strictly decreasing for all `Step` rules.

The problem is that `phase` only inspects the outermost constructor. Several rules have a left-hand side with phase `0` but can rewrite to an arbitrary subterm whose phase is `1`.

For example, let

```lean
b := recDelta void void (delta void)
```

Then:

```lean
phase b = 1
cost b = 2
```

Now apply `R_rec_zero`:

```lean
Step (recDelta b void void) b
```

The source has

```lean
phase (recDelta b void void) = 0
cost  (recDelta b void void) = 3
```

so the measures are:

```lean
measure (recDelta b void void) = (0, 3)
measure b                       = (1, 2)
```

Under the usual lexicographic order on `Nat × Nat`, `(1, 2)` is greater than `(0, 3)`, because its first component is greater. Thus this rewrite increases the measure.

The same issue occurs with, for example:

```lean
R_merge_void_left
R_merge_void_right
R_merge_cancel
```

since their right-hand side may be a term of phase `1`, while their left-hand side is headed by `merge` and therefore has phase `0`.

There is also a separate contextual issue if the intended rewrite relation permits rewriting below constructors. `R_rec_succ` decreases `phase` only when the redex itself is the whole term:

```lean
recDelta b s (delta n)
  ↦ app s (recDelta b s n)
```

At the root this goes from phase `1` to phase `0`, even though its cost can increase. But inside an enclosing constructor, both enclosing terms generally have phase `0`; then the cost increase is exposed. For example, if `cost s > 0`:

```lean
integrate (recDelta b s (delta n))
  ↦ integrate (app s (recDelta b s n))
```

has phase `0` on both sides, while the right-hand cost is larger by `cost s`.

So the measure is unsound already for the literal root-level `Step` relation, due to rules such as `R_rec_zero`, and it would also fail to establish termination for context-closed rewriting because `phase` is not compositional.
