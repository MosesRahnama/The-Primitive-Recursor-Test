# Assessment of the Lexicographic Termination Measure

I need to check whether for every `Step a b`, we have `measure a > measure b` in the lexicographic ordering on `Nat × Nat` — meaning either `phase a > phase b`, or `phase a = phase b ∧ cost a > cost b`.

Let me check each rule:

## Rule-by-rule analysis

### R_int_delta: `integrate (delta t) → void`
- **phase**: `integrate (delta t)` matches `_ => 0`; `void` matches `_ => 0`. Phase: 0 = 0.
- **cost**: `1 + (1 + cost t)` = `2 + cost t` vs `0`. ✅ Cost decreases.

### R_merge_void_left: `merge void t → t`
- **phase**: `merge void t` → 0; `t` → 0 or 1 (if `t` is `recDelta _ _ (delta _)`). 
- If `t = recDelta b s (delta n)`, then phase of LHS = 0, phase of RHS = 1. **Phase increases!** ❌

This is already a problem. Let me verify the costs in this case:
- `cost (merge void (recDelta b s (delta n)))` = `1 + 0 + (1 + cost b + cost s + (1 + cost n))` = `3 + cost b + cost s + cost n`
- `cost (recDelta b s (delta n))` = `1 + cost b + cost s + (1 + cost n)` = `2 + cost b + cost s + cost n`

So cost also decreases, but phase **increases** from 0 to 1. In the lexicographic order `(phase, cost)`, we need the first component to decrease, or stay equal while the second decreases. Here phase goes from 0 to 1, so the measure **increases**. The measure is **not sound** for this step.

### R_rec_succ: `recDelta b s (delta n) → app s (recDelta b s n)`
- **phase**: LHS matches `recDelta _ _ (.delta _) => 1`; RHS is `app ...` → 0. Phase: 1 > 0. ✅ Phase decreases.
- But **cost**: LHS = `1 + cost b + cost s + (1 + cost n)` = `2 + cost b + cost s + cost n`. RHS = `1 + cost s + (1 + cost b + cost s + cost n)` = `2 + cost b + 2*(cost s) + cost n`. Cost **increases** (unless `cost s = 0`). But phase strictly decreased, so this is fine lexicographically. ✅

### R_eq_diff: `eqW a b → integrate (merge a b)`
- **phase**: 0 = 0.
- **cost**: `3 + cost a + cost b` vs `1 + (1 + cost a + cost b)` = `2 + cost a + cost b`. ✅ Cost decreases.

The other rules (R_merge_void_right, R_merge_cancel, R_rec_zero, R_eq_refl) are straightforward to verify and all have cost strictly decreasing with phase equal.

## Conclusion

**The measure is unsound.** The rule `R_merge_void_left` (and symmetrically `R_merge_void_right`) can transform a term with `phase = 0` into a term with `phase = 1`. Specifically:

```
merge void (recDelta b s (delta n))  →  recDelta b s (delta n)
```

has `measure` going from `(0, 3 + cost b + cost s + cost n)` to `(1, 2 + cost b + cost s + cost n)`, which is an **increase** in the lexicographic order. The first component increases from 0 to 1, violating the requirement that the measure strictly decreases at each step.

A fix would require either redesigning the `phase` function so it accounts for `recDelta` subterms nested inside other constructors, or using a different measure altogether (e.g., a multiset ordering or a measure that counts the total number of `recDelta`-with-`delta` subterms throughout the term).
