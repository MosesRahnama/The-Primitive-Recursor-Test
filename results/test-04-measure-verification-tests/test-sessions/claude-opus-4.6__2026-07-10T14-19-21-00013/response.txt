# Assessment of the Lexicographic Termination Measure

I need to check whether for every rewrite rule `Step s t`, we have `measure s > measure t` in the lexicographic order on `Nat × Nat` — meaning either `phase s > phase t`, or `phase s = phase t ∧ cost s > cost t`.

Let me check each rule:

## Rule-by-rule analysis

### R_int_delta: `integrate (delta t) → void`
- `phase (integrate (delta t)) = 0`, `phase void = 0`
- `cost (integrate (delta t)) = 1 + (1 + cost t) = 2 + cost t`, `cost void = 0`
- ✅ Phase equal, cost strictly decreases.

### R_merge_void_left: `merge void t → t`
- `phase (merge void t) = 0`, `phase t = 0 or 1` — but actually phase could be 1 if `t` is `recDelta _ _ (delta _)`. Wait, but `phase (merge void t) = 0` regardless.
- If `phase t = 1`, then phase *increases*, which violates the measure. Let me check: we need `measure s > measure t`, i.e., `(0, cost s) > (1, cost t)` lexicographically. This is **false** since `0 < 1`.

**Concrete counterexample:** Let `t = recDelta void void (delta void)`.
- `s = merge void (recDelta void void (delta void))`
- `phase s = 0`, `phase t = 1`
- `measure s = (0, 1 + 0 + (1 + 0 + 0 + (1 + 0))) = (0, 4)`
- `measure t = (1, 3)`
- Lexicographically `(0, 4) < (1, 3)`, so the measure **increases**.

### R_rec_succ: `recDelta b s (delta n) → app s (recDelta b s n)`
- `phase (recDelta b s (delta n)) = 1`
- `phase (app s (recDelta b s n))`: The top-level is `app`, so `phase = 0`.
- Phase strictly decreases: `1 > 0`. ✅

But wait — the right-hand side `app s (recDelta b s n)` contains a `recDelta b s n` subterm. The measure is only on the top-level term, and rewrites are only defined at the root (there are no congruence/context rules in `Step`). So this is fine for root rewriting.

### R_merge_void_right: `merge t void → t`
- Same issue as R_merge_void_left. If `t = recDelta _ _ (delta _)`, phase goes from 0 to 1. ❌

### R_merge_cancel: `merge t t → t`
- Same issue. ❌

### R_eq_refl: `eqW a a → void`
- `phase = 0 → 0`, `cost = 3 + 2·cost a → 0`. ✅

### R_eq_diff: `eqW a b → integrate (merge a b)`
- `phase = 0 → 0`, `cost = 3 + cost a + cost b → 1 + (1 + cost a + cost b) = 2 + cost a + cost b`. Cost decreases by 1. ✅

## Verdict: **The measure is unsound.**

The rules `R_merge_void_left`, `R_merge_void_right`, and `R_merge_cancel` can all produce a right-hand side with `phase = 1` from a left-hand side with `phase = 0`. Since the first component of the lexicographic pair increases, the measure does not decrease. The fundamental issue is that `phase` assigns value 1 to `recDelta _ _ (delta _)`, but `merge` terms containing such a subterm (or equal to such a term after reduction) get `phase = 0`. The merge-elimination rules can "reveal" a high-phase term that was hidden under a `merge` constructor.

A fix would require either refining `phase` to account for these cases (e.g., taking a maximum phase over subterms) or increasing `cost` for `merge` to compensate, or restructuring the measure entirely.
