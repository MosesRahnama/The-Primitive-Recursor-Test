# Assessment of the Lexicographic Termination Measure

I need to check whether for every rule `Step t₁ t₂`, we have `measure t₁ > measure t₂` in the lexicographic order on `Nat × Nat` (i.e., either `phase` strictly decreases, or `phase` stays the same and `cost` strictly decreases).

Let me check each rule:

## R_int_delta: `integrate (delta t) → void`
- **phase**: `phase (integrate (delta t)) = 0`, `phase void = 0` ✓ (equal)
- **cost**: `cost (integrate (delta t)) = 1 + (1 + cost t) = 2 + cost t`, `cost void = 0` ✓ (strictly decreases)

## R_merge_void_left: `merge void t → t`
- **phase**: `phase (merge void t) = 0`, `phase t = 0` (unless `t` is `recDelta _ _ (delta _)`, in which case `phase t = 1`)
- If `phase t = 1`, then `phase` goes from 0 to 1, which is an **increase**. ❌

**This is unsound.** Consider `t = recDelta b s (delta n)`. Then:
- `measure (merge void (recDelta b s (delta n))) = (0, 1 + 0 + (1 + cost b + cost s + cost n))`
- `measure (recDelta b s (delta n)) = (1, 1 + cost b + cost s + cost n)`

The first component goes from 0 to 1, so the measure **increases** lexicographically.

## R_rec_succ: `recDelta b s (delta n) → app s (recDelta b s n)`
- **phase**: `phase (recDelta b s (delta n)) = 1`, `phase (app s (recDelta b s n)) = 0` ✓ (strictly decreases)
- So cost doesn't matter for this rule (though cost may increase since `s` is duplicated).

## R_eq_diff: `eqW a b → integrate (merge a b)`
- **phase**: both 0 ✓
- **cost**: `cost (eqW a b) = 3 + cost a + cost b`, `cost (integrate (merge a b)) = 1 + (1 + cost a + cost b) = 2 + cost a + cost b` ✓

## Other rules (R_merge_void_right, R_merge_cancel, R_rec_zero, R_eq_refl)
These all have phase 0 → 0 and straightforwardly decreasing cost. ✓

---

# Conclusion

**The measure is unsound.** The rule `R_merge_void_left` (and similarly `R_merge_void_right`) can increase the `phase` component from 0 to 1 while the lexicographic order requires it to be non-increasing when examining the first component. Specifically, `merge void (recDelta b s (delta n))` has measure `(0, _)` but rewrites to `recDelta b s (delta n)` with measure `(1, _)`, which is strictly larger.

The fundamental problem is that `phase` is defined only on the root constructor pattern, but rewriting can expose a subterm whose root has a higher phase. The `cost` function also cannot compensate because the second component isn't checked when the first component changes.

A fix would require either:
- Redefining `phase` to account for the maximum phase of all subterms, or
- Increasing the cost of `merge` (and other constructors) enough to dominate any phase increase, or
- Using a different termination argument (e.g., a multiset order or a more sophisticated recursive path ordering).
