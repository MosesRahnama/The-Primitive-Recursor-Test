# Assessment: The measure is **not sound**.

## The idea behind the measure

`measure t = (phase t, cost t)` is interpreted as a **lexicographic order**: first compare `phase`, then `cost` on a tie. `phase` is 1 *only* for terms of the shape `recDelta b s (delta n)` and 0 otherwise. So the author apparently wants the recursion-rule "step" case (going from `recDelta b s (delta n)` to `app s (recDelta b s n)`) to take the lexicographic step — drop from phase 1 to phase 0.

## Where it breaks

Lexicographic decrease requires that on every rule, the LHS strictly exceeds the RHS in the *first* component where they differ, and on a tie in `phase` the `cost` must strictly decrease. Several rules produce an LHS in phase 0 but an RHS in phase 1, which is an **increase**, not a decrease.

### Counterexample 1 — `R_rec_zero`

Take `b := recDelta void void (delta void)`, `s := void`. Then

- LHS: `recDelta b s void` — not of the form `recDelta _ _ (delta _)`, so `phase = 0`.
- RHS: `b` — is of the form `recDelta _ _ (delta _)`, so `phase = 1`.

```
measure (recDelta b s void) = (0, 1 + cost b + cost s)
measure b                   = (1, cost b)
```

Since `0 < 1`, the measure **increases** under this step. The rule does not decrease.

### Counterexample 2 — `R_merge_void_left` (same shape, two rules)

Take `t := recDelta void void (delta void)`. Then `merge void t` has phase 0 while `t` has phase 1. The same argument applies verbatim to `R_merge_void_right` and to `R_merge_cancel` (the latter with `t` being the same `recDelta … (delta …)` term on both sides of the merge).

### Counterexample 3 — `R_merge_cancel`

With `t := recDelta void void (delta void)`, LHS `merge t t` has phase 0; RHS `t` has phase 1. Again an increase.

## Why this is a real problem

Nothing in the syntax restricts `b` (in `R_rec_zero`) or `t` (in the merge rules) so that it can never be of the form `recDelta _ _ (delta _)`. Those are perfectly well-formed `Trace` values. So each of these four rules has a concrete instance on which `measure` strictly increases, which means the lexicographic pair `(phase, cost)` does not decrease on every step of the `Step` relation.

## What the other rules do

For completeness, the remaining rules are fine:

| Rule | LHS phase / cost | RHS phase / cost | Decreases? |
|---|---|---|---|
| `R_int_delta` | (0, 2+cost t) | (0, 0) | yes (cost) |
| `R_rec_succ`  | (1, 2+cost b+cost s+cost n) | (0, 2+2·cost s+cost b+cost n) | yes (phase) |
| `R_eq_refl`   | (0, 3+2·cost a) | (0, 0) | yes (cost) |
| `R_eq_diff`   | (0, 3+cost a+cost b) | (0, 2+cost a+cost b) | yes (cost) |
| `R_rec_zero`  | (0, 1+cost b+cost s) | (phase b, cost b) | **no** when `phase b = 1` |
| `R_merge_void_left/right`, `R_merge_cancel` | (0, …) | (phase t, cost t) | **no** when `phase t = 1` |

## Conclusion

The proposed measure is **not sound** as a termination measure for `Step`. The `phase` classification is too narrow: only the `R_rec_succ` rule ever moves *out of* phase 1, but the merge rules and `R_rec_zero` can move *into* phase 1 (from phase 0), breaking the lexicographic decrease. To fix it one would need either (a) a different ordering that still strictly decreases on those rules, or (b) additional restrictions (e.g., on what may appear as `b` or as the right-hand side of a merge) — but as written, the measure does not certify termination.
