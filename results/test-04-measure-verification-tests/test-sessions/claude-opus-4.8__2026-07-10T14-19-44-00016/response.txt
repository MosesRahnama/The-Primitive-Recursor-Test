I'll analyze whether the proposed lexicographic measure `(phase t, cost t)` decreases on every `Step`.

## Checking each rule

The lexicographic order on `Nat × Nat`: decreases if either the first component decreases, or the first stays equal and the second decreases.

**R_int_delta**: `integrate (delta t) → void`
- phase: LHS `integrate (delta t)` isn't a recDelta, so phase=0. RHS void, phase=0. Equal.
- cost: LHS = `1 + (1 + cost t)` = 2 + cost t. RHS = 0. Decreases. ✓

**R_merge_void_left**: `merge void t → t`
- phase both 0.
- cost: LHS = 1 + 0 + cost t. RHS = cost t. Decreases. ✓

**R_merge_void_right**: `merge t void → t`
- cost: LHS = 1 + cost t + 0. RHS = cost t. Decreases. ✓

**R_merge_cancel**: `merge t t → t`
- cost: LHS = 1 + 2·cost t. RHS = cost t. Decreases (1 + 2c > c). ✓

**R_rec_zero**: `recDelta b s void → b`
- phase: LHS `recDelta b s void` — the phase pattern requires third arg `.delta _`; here it's `void`, so phase=0. RHS b: phase is 0 unless b is `recDelta _ _ (delta _)`. **b could be such a term!**
- If b = `recDelta b' s' (delta n')`, then phase(RHS)=1 > phase(LHS)=0. Lexicographic order **increases**. ✗

This is a problem. Let me confirm: LHS phase = 0 (third arg is void). RHS = b, which can be any trace, including one with phase 1. So the first component can go from 0 to 1 — an **increase**.

**R_rec_succ**: `recDelta b s (delta n) → app s (recDelta b s n)`
- phase: LHS third arg is `delta n`, so phase=1. RHS `app ...`, phase=0. First component decreases 1→0. ✓ (regardless of cost)

**R_eq_refl**: `eqW a a → void`
- phase both 0. cost: LHS = 3 + 2·cost a. RHS = 0. Decreases. ✓

**R_eq_diff**: `eqW a b → integrate (merge a b)`
- phase: LHS eqW, phase=0. RHS integrate, phase=0. Equal.
- cost: LHS = 3 + cost a + cost b. RHS = `1 + (1 + cost a + cost b)` = 2 + cost a + cost b. Decreases (3+... > 2+...). ✓

## Verdict

**The measure is NOT sound.**

The failure is in **R_rec_zero**: `recDelta b s void → b`.

- The `phase` function assigns 1 only to a `recDelta` whose *third* argument is a `delta`. The LHS `recDelta b s void` has third argument `void`, so its phase is **0**.
- The RHS is `b`, which is arbitrary. If `b` happens to itself be of the form `recDelta b' s' (delta n')`, then the RHS has phase **1**.
- So the first (dominant) lexicographic component increases from 0 to 1, and lexicographically the measure **increases**, not decreases.

Concretely, take:
```
b = recDelta void void (delta void)   -- phase 1, cost = 1 + 0 + 0 + (1+0) = 2
s = void
```
Then `Step (recDelta b s void) b`, and:
- measure(LHS) = (phase = 0, cost = 1 + 2 + 0 + 0 = 3) = (0, 3)
- measure(RHS) = (phase = 1, cost = 2) = (1, 2)

Since (0,3) <ₗₑₓ (1,2), the step goes to a *larger* measure. The lexicographic ordering is violated.

## Why the intended idea fails

The `phase` flag is meant to give recDelta-on-`delta` a “high” priority so that `R_rec_succ` (which increases `cost`) is justified by dropping the phase. But because phase is defined only by the *top-level* shape of a single term, it isn't stable under substituting a high-phase term into a context where the surrounding constructor masks it. A rewrite that exposes a previously-embedded high-phase subterm (as `R_rec_zero` does when `b` is such a term) breaks monotonicity.

To fix this one would need a phase measure that is monotone under contexts / counts all `recDelta (... (delta _))` occurrences (e.g., a sum over the term), rather than just inspecting the root. As written, the measure does not prove termination.
