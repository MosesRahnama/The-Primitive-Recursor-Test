The measure is **not sound as a lexicographic termination measure** with the pair ordered by `(phase, cost)`.

For example, choose

```lean
t := recDelta void void (delta void)
```

Then:

```lean
Step (merge void t) t
```

by `R_merge_void_left`.

The measures are:

```lean
measure (merge void t) = (0, 3)
measure t              = (1, 2)
```

The source has phase `0` because its outer constructor is `merge`, while the target has phase `1` because it is a `recDelta` whose third argument is a `delta`. Thus the phase increases from `0` to `1`, so the target is **larger** in lexicographic order, despite its lower cost.

The same issue occurs with rules such as:

- `R_merge_void_right`
- `R_merge_cancel`
- `R_rec_zero`

because their right-hand sides can expose an arbitrary subterm whose phase is `1`.

The phase component does correctly handle `R_rec_succ`: its source has phase `1` and its target, whose outer constructor is `app`, has phase `0`. However, the phase definition is not preserved by the other rewrite rules, so it cannot serve as the leading lexicographic component globally.
