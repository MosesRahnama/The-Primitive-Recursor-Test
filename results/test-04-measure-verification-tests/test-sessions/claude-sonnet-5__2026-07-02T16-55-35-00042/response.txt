## Assessment: **The measure is unsound.**

The claimed measure `measure t = (phase t, cost t)` is supposed to strictly decrease (lexicographically) across every `Step`. This holds for some rules but fails for others, because `phase` is defined purely on the **outermost syntactic shape** of a term (whether it is literally `recDelta _ _ (delta _)`), not on any invariant that is preserved under substitution. Several rewrite rules substitute an *arbitrary* subterm into the result position, and that subterm can itself have the shape that triggers `phase = 1`, even though the left-hand side had `phase = 0`. This makes the first (dominant) component of the lexicographic measure **increase**, which breaks the ordering.

### Concrete counterexample

Take the rule `R_merge_void_left : Step (merge void t) t`, and instantiate
```
t := recDelta void void (delta void)
```

- **LHS** = `merge void t`.
  Since `merge _ _` never matches the `recDelta _ _ (delta _)` pattern, `phase (merge void t) = 0`.
  `cost t = 1 + cost void + cost void + cost (delta void) = 1 + 0 + 0 + (1 + 0) = 2`.
  `cost (merge void t) = 1 + cost void + cost t = 1 + 0 + 2 = 3`.
  So `measure LHS = (0, 3)`.

- **RHS** = `t = recDelta void void (delta void)`.
  This *does* match the pattern `recDelta _ _ (delta _)`, so `phase t = 1`.
  `cost t = 2` (computed above).
  So `measure RHS = (1, 2)`.

Lexicographic comparison: `(1,2) > (0,3)` (since the first component `1 > 0` already decides it), so the measure **increases** along this step, rather than decreasing. Hence `measure` is not a valid termination measure for `Step`.

### Why this happens structurally

The same failure pattern recurs for any rule whose right-hand side is an unconstrained subterm `t`/`b` (rather than a fixed shape), because `phase` can jump from `0` to `1` there:

- `R_merge_void_left : merge void t → t` — as shown above.
- `R_merge_void_right : merge t void → t` — symmetric counterexample.
- `R_merge_cancel : merge t t → t` — take `t = recDelta void void (delta void)`; `phase(merge t t) = 0` but `phase(t) = 1`.
- `R_rec_zero : recDelta b s void → b` — take `b = recDelta void void (delta void)`; LHS has `n = void` so `phase = 0`, but RHS `b` has `phase = 1`.

In all four cases the dominant lexicographic component increases, so no accompanying decrease in `cost` can compensate.

### Rules that *are* fine

For completeness, the remaining three rules do behave correctly:

- `R_rec_succ : recDelta b s (delta n) → app s (recDelta b s n)`: LHS has `phase = 1` (matches the pattern), RHS is headed by `app`, so `phase = 0`. Phase strictly decreases, so this rule is fine regardless of cost.
- `R_eq_refl : eqW a a → void`: both sides have `phase = 0`; `cost` drops from `3 + 2*cost a` to `0`. Fine.
- `R_eq_diff : eqW a b → integrate (merge a b)`: both sides have `phase = 0`; `cost` drops from `3 + cost a + cost b` to `2 + cost a + cost b`. Fine.

### Conclusion

Because `phase` is a shallow syntactic test that can spuriously become `1` on the right-hand side of several rules (`R_merge_void_left`, `R_merge_void_right`, `R_merge_cancel`, `R_rec_zero`) whenever the substituted subterm happens to have the `recDelta _ _ (delta _)` shape, the lexicographic pair `(phase, cost)` does **not** decrease along every step of `Step`. The proposed measure is therefore **not sound** as a termination measure for this rewrite system in general.
