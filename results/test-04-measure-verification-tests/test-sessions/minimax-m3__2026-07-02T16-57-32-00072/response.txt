## Assessment: The measure is **not sound**.

### Setup

The measure is `(phase t, cost t)` ordered lexicographically, with:

- `phase t = 1` iff `t` is exactly of the form `recDelta _ _ (delta _)`, else `0`
- `cost` sums `1` per constructor plus an extra `2` for `eqW`

For the measure to witness termination, every rule must strictly decrease `(phase, cost)` in lex order.

### The break: the merge rules

Consider `R_merge_void_left : merge void t → t` applied to a `t` of phase 1, e.g.

```
t := recDelta void void (delta void)
```

Computations:

| side | term                              | phase | cost |
|------|-----------------------------------|-------|------|
| LHS  | `merge void t`                    | 0     | 3    |
| RHS  | `recDelta void void (delta void)` | 1     | 2    |

So the LHS measure is `(0, 3)` and the RHS measure is `(1, 2)`. Lexicographically `(0, 3) < (1, 2)`, so the measure **increases** across this rewrite. The same problem occurs for `R_merge_void_right`.

### Why this happens (and why it can't be patched here)

`phase` flags only the *top-level* shape `recDelta _ _ (delta _)`. But the LHS of the merge rules is a `merge` constructor at the top, so its phase is forced to `0` regardless of the buried `recDelta`. Meanwhile the RHS is literally `t`, which can have phase `1`. So any top-level `merge`-vs-`recDelta` rewrite on a term of phase 1 produces an increase in the first component, with no recourse in the second (which is always nonnegative).

Note that the `phase` component is *needed*: without it `R_rec_succ`
```
recDelta b s (delta n) → app s (recDelta b s n)
```
would *increase* the cost (from `2 + cost b + cost s + cost n` to `2 + cost b + 2·cost s + cost n`). So the author added `phase` exactly to dominate that case, but in doing so introduced the inconsistency above — `phase` is a property of the term's *root constructor*, not a context-aware invariant, and the merge rules do not respect it.

### Other rules (for completeness)

These do decrease lexicographically and are not the source of trouble:

- `R_int_delta`, `R_eq_refl`: `(0, 2+cost t)` → `(0, 0)`, cost drops. ✓
- `R_merge_cancel`: `(0, 1+2·cost t)` → `(0, cost t)`. ✓
- `R_eq_diff`: `(0, 3+cost a+cost b)` → `(0, 2+cost a+cost b)`. ✓
- `R_rec_zero`: `(0, 1+cost b+cost s)` → `(0, cost b)`. ✓
- `R_rec_succ`: `(1, 2+cost b+cost s+cost n)` → `(0, ...)`, phase drops. ✓

### Conclusion

The proposed lexicographic measure is **unsound** as a termination certificate. Specifically, `R_merge_void_left` and `R_merge_void_right` raise the `phase` component from `0` to `1` whenever the right-hand argument has phase 1, so the lex order is not monotonically decreasing on the rewrite relation.
