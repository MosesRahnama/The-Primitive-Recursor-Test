The measure is **not sound as a lexicographic termination measure** for the given rewrite rules.

Assuming the intended order is the usual lexicographic order on `(phase, cost)`, with smaller values preferred:

- `phase` has priority over `cost`.
- A rewrite must strictly decrease either `phase`, or preserve `phase` and decrease `cost`.

Several rules can increase `phase`.

For example, let

```lean
t := recDelta void void (delta void)
```

Then `phase t = 1`, while `phase (merge void t) = 0`, because the outer constructor of `merge void t` is not `recDelta`. The rule

```lean
R_merge_void_left : Step (merge void t) t
```

therefore rewrites from phase `0` to phase `1`, so the measure increases lexicographically.

The same issue occurs with:

```lean
R_merge_void_right
R_merge_cancel
```

by choosing an argument whose phase is `1`.

There is also a problem with:

```lean
R_rec_zero : Step (recDelta b s void) b
```

The source has phase `0`, but `b` may itself be a `recDelta ... (delta ...)`, giving phase `1`.

Thus the phase component is not monotone under all rules.

Even if one instead gave `cost` priority, the measure would still fail. For `R_rec_succ`:

```lean
recDelta b s (delta n)
  ↦ app s (recDelta b s n)
```

the source cost is

```text
2 + cost b + cost s + cost n
```

whereas the target cost is

```text
2 + cost b + 2 * cost s + cost n.
```

Hence the target cost is larger whenever `cost s > 0`.

So neither natural lexicographic interpretation makes every rewrite step decrease the proposed measure.
