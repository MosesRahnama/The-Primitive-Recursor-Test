The proposed measure is **not sound**.

For a lexicographic pair `(phase t, cost t)` to be a sound termination measure, every rewrite step must make the pair strictly smaller. The first component, `phase`, is problematic because several rules can **expose a subterm whose `phase` is larger** than that of the whole redex.

### Counterexample using `R_rec_zero`

Take
- `b := recDelta void void (delta void)` (phase = 1, cost = 2)
- `s := void`                 (phase = 0, cost = 0)

Then the left-hand side of `R_rec_zero` is

```
recDelta b s void
```

- **phase** = 0 (because the third argument is `void`, not `delta`)
- **cost** = 1 + cost b + cost s + cost void = 1 + 2 + 0 + 0 = **3**
- **measure** = **(0, 3)**

The right-hand side is just `b`:

- **phase** = 1 (because `b` matches `.recDelta _ _ (.delta _)`)
- **cost** = **2**
- **measure** = **(1, 2)**

In the lexicographic order `(0, 3) < (1, 2)` because `0 < 1`.  
Thus this rewrite step **increases** the measure.

### Same issue in the merge rules

Similarly, using `t := recDelta void void (delta void)`:

- `merge void t` has measure `(0, 3)` but rewrites to `t` with measure `(1, 2)`.
- The same happens for `merge t void → t` (`R_merge_void_right`) and `merge t t → t` (`R_merge_cancel`).

### Why the other rules are fine

Rules like `R_int_delta`, `R_eq_refl`, and `R_eq_diff` decrease `cost` while keeping `phase` equal. `R_rec_succ` drops `phase` from 1 to 0, which dominates any `cost` change. But because `R_rec_zero` and the `merge` rules can increase `phase` from 0 to 1, the lexicographic ordering is not preserved globally.

**Conclusion:** The measure is unsound because the first component (`phase`) is not guaranteed to decrease (or even stay equal) on every step; it can jump upward when a rule exposes a subterm matching `.recDelta _ _ (.delta _)`.
