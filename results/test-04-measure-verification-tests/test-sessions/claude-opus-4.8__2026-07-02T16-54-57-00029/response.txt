I'll analyze whether the proposed lexicographic measure `(phase t, cost t)` decreases on every `Step`.

## Key observation about the measure

The measure is `(phase, cost)` compared lexicographically. For soundness, every step `Step t t'` must satisfy `measure t' < measure t`, meaning either:
- `phase t' < phase t`, or
- `phase t' = phase t` and `cost t' < cost t`.

Note `phase` is 0 everywhere **except** the top-level being `recDelta _ _ (delta _)`, which has phase 1.

## Checking each rule

**R_int_delta:** `integrate (delta t) → void`. Both phase 0. cost: `1 + (1 + cost t) = 2 + cost t` vs `0`. Decreases. ✓

**R_merge_void_left:** `merge void t → t`. Both phase 0 (t could be a recDelta-succ giving phase 1!). Let me check: if `t = recDelta b s (delta n)`, then `phase (merge void t) = 0` but `phase t = 1`. So phase **increases** from 0 to 1. Then we must check cost. cost: `1 + 0 + cost t` vs `cost t`. cost decreases, but phase increased, so lexicographically `(1, cost t) > (0, 1+cost t)`. **This is a violation!**

Let me verify this concretely. Take `t = recDelta void void (delta void)`.
- LHS: `merge void t`, phase = 0, cost = `1 + 0 + cost t`.
- RHS: `t`, phase = 1, cost = `cost t`.
- `measure LHS = (0, 1 + cost t)`, `measure RHS = (1, cost t)`.
- Lexicographically `(1, cost t) > (0, 1 + cost t)` since `1 > 0`.

So the measure **increases**. The termination measure is **unsound**.

## The core problem

The `phase` function only inspects the **top-level** structure. Reductions that expose a `recDelta _ _ (delta _)` at the top level (by stripping an outer constructor) can raise the phase from 0 to 1, and lexicographic ordering prioritizes phase.

## Other violating rules

The same problem affects:

**R_merge_void_right:** `merge t void → t`. Same issue with `t = recDelta b s (delta n)`. ✗

**R_merge_cancel:** `merge t t → t`. Same issue. ✗

**R_rec_succ:** `recDelta b s (delta n) → app s (recDelta b s n)`.
- LHS phase = 1. RHS is an `app`, phase = 0. Phase decreases (1→0). ✓ (This one is fine — indeed the phase seems designed for this rule.)

**R_eq_diff:** `eqW a b → integrate (merge a b)`. Both phase 0. cost: `3 + cost a + cost b` vs `1 + (1 + cost a + cost b) = 2 + cost a + cost b`. Decreases. ✓

## Conclusion

**The measure is unsound.** 

While `phase` was evidently introduced to handle `R_rec_succ` (where `cost` alone fails: LHS cost `1 + cost b + cost s + (1 + cost n)` = `2 + cost b + cost s + cost n` vs RHS cost `1 + cost s + (1 + cost b + cost s + cost n)` = `2 + cost b + 2·cost s + cost n`, which **increases** in `cost s`), the top-level-only `phase` breaks the `merge`-elimination rules.

The failure: **`R_merge_void_left`, `R_merge_void_right`, and `R_merge_cancel`** can increase the phase from 0 to 1 whenever the surviving subterm is a top-level `recDelta _ _ (delta _)`. Because phase dominates in the lexicographic order, the measure strictly increases on these steps, so it does not prove termination.

A correct measure would need a phase notion that is monotone under stripping outer constructors (e.g., counting all `recDelta _ _ (delta _)` occurrences throughout the term, not just at the root).
