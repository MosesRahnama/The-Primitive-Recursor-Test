**Assessment: the helper strategy is unsound as written.**

Both lemmas are universally quantified over arbitrary traces `b`, `s`, and `n`, but they fail whenever `n` itself has the form `delta n'`. The failure is easy to see from the definition of `kappa` and the structure of the rewrite rule `R_rec_succ`.

---

### 1. Why `kappa_rec_delta_step` is false

The definition of `kappa` treats `recDelta` differently depending on whether its third argument is a `delta`:

```
kappa (recDelta b s (.delta n)) = max (max (kappa b) (kappa s)) (kappa n) + 1
kappa (recDelta b s n)          = max (max (kappa b) (kappa s)) (kappa n)   -- if n is not a delta
```

Consider the instantiation `n := delta n'` (for any trace `n'`). Then:

*Left-hand side*
\[
\kappa(\mathsf{recDelta}\;b\;s\;(\delta n))
= \kappa(\mathsf{recDelta}\;b\;s\;(\delta(\delta n')))
= \max(\max(\kappa b,\kappa s),\kappa(\delta n'))+1
= \max(\max(\kappa b,\kappa s),\kappa n')+1 .
\]

*Right-hand side*
\[
\kappa(\mathsf{recDelta}\;b\;s\;n)+1
= \kappa(\mathsf{recDelta}\;b\;s\;(\delta n'))+1
= \bigl(\max(\max(\kappa b,\kappa s),\kappa n')+1\bigr)+1
= \max(\max(\kappa b,\kappa s),\kappa n')+2 .
\]

These differ by exactly one.  
**Concrete counterexample:** take `b = void`, `s = void`, `n = delta void`.

- `kappa void = 0`.
- `kappa (recDelta void void (delta (delta void))) = max(max(0,0),0)+1 = 1`.
- `kappa (recDelta void void (delta void)) = max(max(0,0),0)+1 = 1`, so the right-hand side of the lemma would be `1 + 1 = 2`.

Thus `1 = 2` would be required, which is impossible.

---

### 2. Why `kappa_rec_succ_drop` is false

The second lemma relies on the first to reduce its goal to showing
\[
\kappa(\mathsf{app}\;s\;(\mathsf{recDelta}\;b\;s\;n)) < \kappa(\mathsf{recDelta}\;b\;s\;n)+1 .
\]
Even ignoring the bogus rewrite, the strict inequality itself fails when `n = delta n'`.

Compute both sides for `n = delta n'`:

*Left-hand side*
\[
\kappa(\mathsf{app}\;s\;(\mathsf{recDelta}\;b\;s\;n))
= \max\bigl(\kappa s,\;\kappa(\mathsf{recDelta}\;b\;s\;(\delta n'))\bigr).
\]
Since
\[
\kappa(\mathsf{recDelta}\;b\;s\;(\delta n'))
= \max(\max(\kappa b,\kappa s),\kappa n')+1 \ge \kappa s,
\]
the outer `max` simplifies to that same value:
\[
= \max(\max(\kappa b,\kappa s),\kappa n')+1 .
\]

*Right-hand side*
\[
\kappa(\mathsf{recDelta}\;b\;s\;(\delta n))
= \kappa(\mathsf{recDelta}\;b\;s\;(\delta(\delta n')))
= \max(\max(\kappa b,\kappa s),\kappa(\delta n'))+1
= \max(\max(\kappa b,\kappa s),\kappa n')+1 .
\]

Hence the two sides are **equal**, not strictly ordered.  
**Concrete counterexample:** again `b = void`, `s = void`, `n = delta void`.

- `kappa (app void (recDelta void void (delta void))) = max(0,1) = 1`.
- `kappa (recDelta void void (delta (delta void))) = 1`.

The lemma would require `1 < 1`, which is false.

---

### Conclusion

Because `n` ranges over *all* traces, including those already headed by `delta`, both helper theorems are incorrect as stated:

- `kappa_rec_delta_step` erroneously adds an extra `+1` when `n` is a `delta`.
- `kappa_rec_succ_drop` collapses to an equality (not a strict decrease) in exactly the same situation.

Consequently, adopting these lemmas as part of a termination argument would be **unsound**. The measure `kappa` does account for a single `delta` guard on the third argument of `recDelta`, but it does not “count” nested `delta`s, so a redex like `recDelta b s (delta (delta n'))` and its contractum `app s (recDelta b s (delta n'))` receive the *same* `kappa` value. A sound termination argument would need a measure that strictly decreases in that case—e.g. one that adds the structural depth or total number of `delta` constructors in the third argument, rather than merely treating a single outermost `delta` specially.
