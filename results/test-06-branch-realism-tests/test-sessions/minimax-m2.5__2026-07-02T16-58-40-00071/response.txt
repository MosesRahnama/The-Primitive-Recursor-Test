**Assessment – the “helper strategy’’ is not sound as it stands.**  
Both lemmas are false in general; they cannot be proved from the given definitions and therefore cannot be used in a termination argument.

---

### 1.  `kappa_rec_delta_step`

The statement is  

\[
\kappa(\operatorname{recDelta}\;b\;s\;(\delta n))
\;=\;
\kappa(\operatorname{recDelta}\;b\;s\;n)+1 .
\]

Let us compute the two sides from the definition of `kappa`.

*If `n` is **not** a \(\delta\)**  

- Left‑hand side: because the third argument is \(\delta n\), the special clause for `recDelta` applies  
  \[
  \kappa(\operatorname{recDelta}b s(\delta n))
  =\max(\kappa b,\kappa s,\kappa n)+1 .
  \]

- Right‑hand side: the third argument is just `n`, so the ordinary clause applies  
  \[
  \kappa(\operatorname{recDelta}b s n)=\max(\kappa b,\kappa s,\kappa n) .
  \]
  Adding 1 gives \(\max(\kappa b,\kappa s,\kappa n)+1\), which equals the left‑hand side.  
  So the equality holds **when `n` is not a \(\delta\)**.

*If `n` **is** a \(\delta\) (i.e. \(n=\delta m\) for some `m`)*  

- Left‑hand side: now the third argument is \(\delta(\delta m)\). The special clause still applies, but the inner `n` is \(\delta m\), whose measure is \(\kappa(\delta m)=\kappa m\). Hence  
  \[
  \kappa(\operatorname{recDelta}b s(\delta(\delta m)))
  =\max(\kappa b,\kappa s,\kappa m)+1 .
  \]

- Right‑hand side: \(\kappa(\operatorname{recDelta}b s(\delta m))\) uses the special clause again, giving \(\max(\kappa b,\kappa s,\kappa m)+1\). Adding 1 yields \(\max(\kappa b,\kappa s,\kappa m)+2\).

Thus the two sides differ by 1:
\[
\kappa(\operatorname{recDelta}b s(\delta(\delta m)))
\;=\;
\max(\kappa b,\kappa s,\kappa m)+1
\neq
\max(\kappa b,\kappa s,\kappa m)+2
=
\kappa(\operatorname{recDelta}b s(\delta m))+1 .
\]

A concrete counter‑example (take `b = s = void` and `n = delta void`):

- LHS: \(\kappa(\operatorname{recDelta}\,void\,void\,(\delta(\delta\,void)))=1\)  
- RHS: \(\kappa(\operatorname{recDelta}\,void\,void\,(\delta\,void))+1 = (0+1)+1 = 2\)

Hence the lemma is **false** for arbitrary `n`. It would be correct only if one explicitly assumed that `n` is not a \(\delta\).

### 2.  `kappa_rec_succ_drop`

The claim is  

\[
\kappa(\operatorname{app}\;s\;(\operatorname{recDelta}\;b\;s\;n))
\;<\;
\kappa(\operatorname{recDelta}\;b\;s\;(\delta n)).
\]

Let \(X=\kappa b,\;Y=\kappa s,\;Z=\kappa n\).  
From the definition of `kappa`:

* RHS (the original term): because the third argument is \(\delta n\),  
  \[
  \kappa(\operatorname{recDelta}b s(\delta n)) = \max(X,Y,Z)+1 .
  \]

* LHS (the result after the rewrite): first compute \(\kappa(\operatorname{recDelta}b s n)\).  
  - If `n` is **not** a \(\delta\), the ordinary clause gives \(\max(X,Y,Z)\).  
  - If `n` **is** a \(\delta\) (i.e. \(n=\delta m\)), the special clause gives \(\max(X,Y,Z)+1\).

  In general we can write  
  \[
  \kappa(\operatorname{recDelta}b s n)=\max(X,Y,Z)+\mathbf{1}_{n\;\text{is a }\delta},
  \]
  where \(\mathbf{1}_{P}=1\) if \(P\) holds and \(0\) otherwise.

  Then  
  \[
  \kappa(\operatorname{app}s(\operatorname{recDelta}b s n))
  =\max\bigl(Y,\;\max(X,Y,Z)+\mathbf{1}_{n\;\text{is a }\delta}\bigr)
  =\max(X,Y,Z)+\mathbf{1}_{n\;\text{is a }\delta}.
  \]

Thus

\[
\kappa(\operatorname{app}s(\operatorname{recDelta}b s n))
=
\max(X,Y,Z)+\mathbf{1}_{n\;\text{is a }\delta}
\quad\text{vs.}\quad
\kappa(\operatorname{recDelta}b s(\delta n))
= \max(X,Y,Z)+1 .
\]

The strict inequality `<` holds **only** when \(\mathbf{1}_{n\;\text{is a }\delta}=0\), i.e. when `n` is **not** a \(\delta\). If `n` itself is a \(\delta\) (for example `n = delta void`), both sides are equal, so the inequality fails.

A concrete counter‑example (again `b = s = void`, `n = delta void`):

- RHS: \(\kappa(\operatorname{recDelta}void\,void(\delta(\delta\,void))) = 1\)  
- LHS: \(\kappa(\operatorname{app}void(\operatorname{recDelta}void\,void(\delta\,void))) = \max(0,0+1)=1\)

Thus the claimed `<` is false in general; the statement would need the hypothesis that `n` is not a \(\delta\).

---

### Conclusion

Both helper lemmas are **false** when `n` is allowed to be an arbitrary `Trace`. Consequently the “helper strategy’’ (the two theorems) cannot be used as a sound termination argument without additional restrictions on `n`. As written, the strategy is unsound.
