The helper strategy is **unsound** in its current form. Both lemmas fail for `n` that is itself a `delta`.

### Counterexample
Take `b := void`, `s := void`, and `n := delta void`. Compute:
- `kappa void = 0`
- `kappa (delta void) = 0`

**Lemma 1** (`kappa_rec_delta_step`):
```
kappa (recDelta void void (delta (delta void)))
  = max(max(0,0), kappa (delta void)) + 1  = max(0,0)+1 = 1

kappa (recDelta void void (delta void)) + 1
  = (max(max(0,0), kappa void) + 1) + 1    = (0+1)+1 = 2
```
`1 ≠ 2`, so the equality does **not** hold for all `n`.

**Lemma 2** (`kappa_rec_succ_drop`):
```
kappa (app void (recDelta void void (delta void)))
  = max( kappa void, kappa (recDelta void void (delta void)) )
  = max( 0, max(max(0,0),0)+1 ) = max(0,1) = 1

kappa (recDelta void void (delta (delta void)))
  = max(max(0,0),0)+1 = 1
```
We obtain `1 < 1`, which is false. The measure does **not strictly decrease** for this step, so the helper fails to justify termination of the `R_rec_succ` rule.

### Root cause
The definition of `kappa` adds `+1` for each leading `delta` in the third argument of `recDelta`. When `n` is already a `delta`, the inner `recDelta … n` also receives a `+1`. The `R_rec_succ` rule unfolds one `delta` layer, which, when `n = delta m`, reduces `recDelta … (delta (delta m))` to `app s (recDelta … (delta m))`. The `kappa` measure loses the outermost `+1` but the inner `+1` remains, and `max(kappa s, …)` picks up that same value, resulting in no net decrease. A sound termination measure would need to treat the depth of `delta`s differently (e.g., use a lexicographic order or a different size function).
