I need to assess whether the helper strategy is sound by checking if the two theorems are actually provable.

## Theorem 1: `kappa_rec_delta_step`

**Claim:** `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

**LHS:** By `kappa_rec_delta`:
```
kappa (recDelta b s (delta n)) = max (max (kappa b) (kappa s)) (kappa n) + 1
```

**RHS:** `kappa (recDelta b s n) + 1`. Now I need to evaluate `kappa (recDelta b s n)`. The definition has two cases for `recDelta`:
- `recDelta b s (delta n)` → `max (max (kappa b) (kappa s)) (kappa n) + 1`
- `recDelta b s n` (catch-all) → `max (max (kappa b) (kappa s)) (kappa n)`

So `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n)` when `n` is not of the form `delta _`.

**But when `n = delta m` for some `m`,** then:
```
kappa (recDelta b s (delta m)) = max (max (kappa b) (kappa s)) (kappa m) + 1
```
So `kappa (recDelta b s n) + 1 = max (max (kappa b) (kappa s)) (kappa m) + 1 + 1`

But LHS = `max (max (kappa b) (kappa s)) (kappa (delta m)) + 1 = max (max (kappa b) (kappa s)) (kappa m) + 1`

These are **not equal** when `n` itself is a `delta`. So **Theorem 1 is false in general**.

**Counterexample:** Let `n = delta void`, `b = void`, `s = void`.
- LHS: `kappa (recDelta void void (delta (delta void)))` = `max (max 0 0) (kappa (delta void)) + 1 = max 0 0 + 1 = 1`
- RHS: `kappa (recDelta void void (delta void)) + 1` = `(max (max 0 0) (kappa void) + 1) + 1 = (0 + 1) + 1 = 2`

LHS = 1 ≠ 2 = RHS. **Theorem 1 is false.**

## Theorem 2: `kappa_rec_succ_drop`

**Claim:** `kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`

After `rw [kappa_rec_delta_step]` (which relies on the false Theorem 1), the goal becomes:
```
kappa (app s (recDelta b s n)) < kappa (recDelta b s n) + 1
```
i.e., `kappa (app s (recDelta b s n)) ≤ kappa (recDelta b s n)`

Expanding: `max (kappa s) (kappa (recDelta b s n)) ≤ kappa (recDelta b s n)`

This requires `kappa s ≤ kappa (recDelta b s n)`, i.e., `kappa s ≤ max (max (kappa b) (kappa s)) (kappa n)`, which **is** always true (since `kappa s ≤ max (kappa b) (kappa s) ≤ max (max (kappa b) (kappa s)) (kappa n)`).

So Theorem 2's *mathematical content* is valid — but only if we use the correct value of `kappa (recDelta b s (delta n))` directly, **not** via the rewrite using Theorem 1. Since Theorem 1 is false, the proof strategy using `rw [kappa_rec_delta_step]` is broken.

## Conclusion

**The helper strategy is unsound as written.** Theorem 1 (`kappa_rec_delta_step`) is **false**: when `n = delta m`, the equality `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1` fails because `kappa (recDelta b s (delta m))` already adds 1 by the special case, making the RHS exceed the LHS by 1. Since Theorem 2's proof begins with `rw [kappa_rec_delta_step]`, it inherits this unsoundness. The termination argument built on these lemmas cannot be completed as written.
