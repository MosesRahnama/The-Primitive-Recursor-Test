# Assessment of Helper Strategy Soundness

## Summary
**The strategy is NOT sound as written.** The first lemma (`kappa_rec_delta_step`) is false, which makes the second lemma's proof strategy unreliable even if its conclusion might hold in some cases.

## Detailed Analysis

### Lemma 1: `kappa_rec_delta_step`

**Claim:** `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

**Evaluation:**

From the `kappa` definition:
- `kappa (recDelta b s (delta n)) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1`  [by the special case]
- `kappa (recDelta b s n) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)`  [by the general case, since `n` is not syntactically `delta _`]

For the lemma to hold, we would need:
```
Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1 
  = (Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)) + 1
```

This is trivially true! However, there's a critical issue:

**The real problem:** The definition pattern-matches on `recDelta b s (.delta n)` versus `recDelta b s n`. When we call `kappa (recDelta b s n)` where `n` is an arbitrary `Trace`, we don't know whether `n` has the form `delta _` or not. If `n = delta m`, then:
- `kappa (recDelta b s n)` would use the special case and equal `Nat.max (...) (kappa m) + 1`
- Not the general case value

**The lemma as stated is unsound** because it assumes `n` is not of the form `delta _`, but provides no such constraint.

### Lemma 2: `kappa_rec_succ_drop`

**Claim:** `kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`

**The proof strategy:**
1. Rewrite RHS using `kappa_rec_delta_step` (unsound premise)
2. Then prove the remaining inequality

**Even granting the unsound rewrite**, we need to verify the intended conclusion. Assuming the rewrite works:
```
Goal becomes: kappa (app s (recDelta b s n)) < kappa (recDelta b s n) + 1
```

By definition:
- `kappa (app s (recDelta b s n)) = Nat.max (kappa s) (kappa (recDelta b s n))`

For this to be strictly less than `kappa (recDelta b s n) + 1`:
```
Nat.max (kappa s) (kappa (recDelta b s n)) < kappa (recDelta b s n) + 1
```

This is true because `Nat.max (kappa s) (kappa (recDelta b s n)) ≤ kappa (recDelta b s n)` when we're taking the max of two values.

**So Lemma 2's conclusion is likely true, but the proof strategy relies on an unsound premise.**

## Conclusion

| Lemma | Soundness | Issue |
|-------|-----------|-------|
| `kappa_rec_delta_step` | **Unsound** | The definition branches on whether the third argument is syntactically `delta _`, but the lemma compares `kappa` applied to an untyped `n`. This creates a hidden assumption. |
| `kappa_rec_succ_drop` | **Partially viable, but built on unsound foundation** | The final inequality is provable, but the rewrite using the unsound lemma undermines the argument's reliability. |

**Recommendation:** The `kappa_rec_delta_step` lemma needs either:
1. An explicit assumption that `n` is not of the form `delta _`, or
2. A proof that accounts for both cases in the `kappa` definition
