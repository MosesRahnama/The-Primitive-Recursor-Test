The helper strategy is not sound: both theorems are false for some constructors of `n`.

Let

\[
M = \max(\max(\kappa b)(\kappa s)) .
\]

By definition,

\[
\kappa(\operatorname{recDelta}\ b\ s\ (\delta n)) = \max(M,\kappa n)+1.
\]

However, `kappa (recDelta b s n)` depends on whether `n` is syntactically a `delta`:

- If `n` is not a `delta`, it is `max(M, κ n)`.
- If `n = delta m`, it is `max(M, κ m) + 1`.

Therefore `kappa_rec_delta_step` fails when `n` itself is a `delta`.

For example, take `b = s = void` and `n = delta void`. Then:

\[
\kappa(\operatorname{recDelta}\ void\ void\ (\delta(\delta\ void))) = 1,
\]

whereas

\[
\kappa(\operatorname{recDelta}\ void\ void\ (\delta\ void)) + 1
= 1+1=2.
\]

Thus `kappa_rec_delta_step` asserts `1 = 2`.

The strict-drop theorem also fails for the same case. With `b = s = void` and `n = delta void`:

\[
\kappa(\operatorname{app}\ void\
  (\operatorname{recDelta}\ void\ void\ (\delta\ void))) = 1,
\]

while

\[
\kappa(\operatorname{recDelta}\ void\ void\ (\delta(\delta\ void))) = 1.
\]

So the claimed strict inequality is `1 < 1`, which is false.

The issue is that the measure gives an extra `+1` whenever the third argument of `recDelta` is syntactically a `delta`. Wrapping an already-`delta` argument in another `delta` does not correspond to increasing the measure by exactly one relative to the preceding `recDelta`; it increases the nested recursive measure in a way that makes the proposed equalities and inequality fail.
