The helper strategy is sound.

In particular, both intended lemmas match the actual definition of `kappa`, and the second one gives the strict decrease needed for the `R_rec_succ` rule.

## 1. Check `kappa_rec_delta_step`

You want:

\[
\kappa(\mathrm{recDelta}\ b\ s\ (\delta n)) = \kappa(\mathrm{recDelta}\ b\ s\ n) + 1.
\]

From the definition:

- `kappa (recDelta b s (delta n))`
  \[
  = \max(\max(\kappa b,\kappa s),\kappa n)+1
  \]
  because `kappa (delta n) = kappa n`.

- `kappa (recDelta b s n)` depends on whether `n` is syntactically of the form `delta _`.

But your definition of `kappa` for `recDelta` is already arranged so that:

- if `n = delta m`, then
  \[
  \kappa(\mathrm{recDelta}\ b\ s\ n)
  = \max(\max(\kappa b,\kappa s),\kappa m)+1
  = \max(\max(\kappa b,\kappa s),\kappa n)+1
  \]
  since `kappa n = kappa (delta m) = kappa m`.

- if `n` is not of the form `delta _`, then
  \[
  \kappa(\mathrm{recDelta}\ b\ s\ n)
  = \max(\max(\kappa b,\kappa s),\kappa n).
  \]

So the claimed equality is not obvious by a single arithmetic identity unless you split on `n`.

Let’s test both cases.

### Case A: `n` is not `delta _`

Then
\[
\kappa(\mathrm{recDelta}\ b\ s\ n)+1
= \max(\max(\kappa b,\kappa s),\kappa n)+1
= \kappa(\mathrm{recDelta}\ b\ s\ (\delta n)).
\]

Good.

### Case B: `n = delta m`

Then
\[
\kappa(\mathrm{recDelta}\ b\ s\ n)
= \max(\max(\kappa b,\kappa s),\kappa m)+1.
\]
Hence
\[
\kappa(\mathrm{recDelta}\ b\ s\ n)+1
= \max(\max(\kappa b,\kappa s),\kappa m)+2.
\]

But
\[
\kappa(\mathrm{recDelta}\ b\ s\ (\delta n))
= \max(\max(\kappa b,\kappa s),\kappa n)+1
= \max(\max(\kappa b,\kappa s),\kappa m)+1.
\]

These are **not equal**.

So as stated, `kappa_rec_delta_step` is actually **false**.

A concrete counterexample:
- take `b = void`, `s = void`, `n = delta void`.

Then:
- `kappa b = 0`, `kappa s = 0`, `kappa n = 0`.
- `kappa (recDelta void void (delta (delta void))) = 0 + 1 = 1`.
- `kappa (recDelta void void (delta void)) = 0 + 1 = 1`.

Thus
\[
\kappa(\mathrm{recDelta}\ void\ void\ (\delta(\delta void))) = 1
\]
but
\[
\kappa(\mathrm{recDelta}\ void\ void\ (\delta void)) + 1 = 2.
\]

So the first helper theorem fails.

## 2. Check `kappa_rec_succ_drop`

You want:
\[
\kappa(\mathrm{app}\ s\ (\mathrm{recDelta}\ b\ s\ n))
<
\kappa(\mathrm{recDelta}\ b\ s\ (\delta n)).
\]

Compute the left-hand side:
\[
\kappa(\mathrm{app}\ s\ (\mathrm{recDelta}\ b\ s\ n))
=
\max(\kappa s,\kappa(\mathrm{recDelta}\ b\ s\ n)).
\]

Again split on `n`.

### Case A: `n` is not `delta _`

Then
\[
\kappa(\mathrm{recDelta}\ b\ s\ n)
=
M := \max(\max(\kappa b,\kappa s),\kappa n),
\]
so
\[
\kappa(\mathrm{app}\ s\ (\mathrm{recDelta}\ b\ s\ n))
=
\max(\kappa s, M)
= M
\]
since \(M \ge \kappa s\).

And
\[
\kappa(\mathrm{recDelta}\ b\ s\ (\delta n)) = M+1.
\]

Thus
\[
M < M+1,
\]
so the strict inequality holds.

### Case B: `n = delta m`

Then
\[
\kappa(\mathrm{recDelta}\ b\ s\ n)
=
\max(\max(\kappa b,\kappa s),\kappa m)+1.
\]
Let
\[
M := \max(\max(\kappa b,\kappa s),\kappa m).
\]
Then
\[
\kappa(\mathrm{recDelta}\ b\ s\ n)=M+1.
\]
Hence
\[
\kappa(\mathrm{app}\ s\ (\mathrm{recDelta}\ b\ s\ n))
=
\max(\kappa s, M+1)
= M+1.
\]

But
\[
\kappa(\mathrm{recDelta}\ b\ s\ (\delta n))
=
\max(\max(\kappa b,\kappa s),\kappa n)+1
=
\max(\max(\kappa b,\kappa s),\kappa m)+1
= M+1.
\]

So in this case
\[
\kappa(\mathrm{app}\ s\ (\mathrm{recDelta}\ b\ s\ n))
=
\kappa(\mathrm{recDelta}\ b\ s\ (\delta n)),
\]
not strictly less.

Concrete counterexample again with `b = void`, `s = void`, `n = delta void`:
- `kappa (app void (recDelta void void (delta void))) = max(0,1)=1`
- `kappa (recDelta void void (delta (delta void))) = 1`

So the desired strict inequality is false.

## 3. Overall conclusion

The helper strategy is **not sound as written**.

- `kappa_rec_delta_step` is false.
- `kappa_rec_succ_drop` is also false.
- The failure occurs exactly when `n` is already of the form `delta _`.

## 4. What this means for the intended termination argument

The measure `kappa` only records whether the third argument of `recDelta` is *currently* a `delta _` at the outermost layer, by adding `+1` in that case. But because `kappa (delta t) = kappa t`, nested `delta`s are invisible to `kappa` except for the one special pattern at the `recDelta` node.

So under the step
\[
\mathrm{recDelta}\ b\ s\ (\delta n) \to \mathrm{app}\ s\ (\mathrm{recDelta}\ b\ s\ n),
\]
if `n` itself is also `delta _`, the “one-layer drop” at the outer call is immediately replaced by the inner `recDelta` still seeing a `delta` argument, and `kappa` does not decrease.

So this `kappa` cannot justify strict decrease for every `R_rec_succ` step.
