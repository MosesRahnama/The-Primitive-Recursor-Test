The helper strategy is unsound: both stated theorems are false.

The issue is that `kappa` has a special clause whenever the third argument of `recDelta` is itself a `delta`. Thus if `n = delta m`, both

```lean
recDelta b s n
```

and

```lean
recDelta b s (delta n)
```

receive the same single `+ 1`; the measure does not accumulate across nested `delta`s.

Let

```text
M = max (max (kappa b) (kappa s)) (kappa m).
```

For `n = delta m`, since `kappa n = kappa m`:

```text
kappa (recDelta b s (delta n)) = M + 1
kappa (recDelta b s n)         = M + 1.
```

Therefore `kappa_rec_delta_step` would assert

```text
M + 1 = (M + 1) + 1,
```

which is false.

The second theorem also fails. Because `M ≥ kappa s`,

```text
kappa (app s (recDelta b s n))
  = max (kappa s) (M + 1)
  = M + 1,
```

while

```text
kappa (recDelta b s (delta n)) = M + 1.
```

Thus it asserts `M + 1 < M + 1`.

A concrete counterexample is:

```text
b = void
s = void
n = delta void.
```

Then:

```text
kappa (recDelta void void (delta (delta void))) = 1
kappa (recDelta void void (delta void)) + 1      = 2,
```

so the first theorem claims `1 = 2`. For the second theorem:

```text
kappa (app void (recDelta void void (delta void))) = 1
kappa (recDelta void void (delta (delta void)))    = 1,
```

so it claims `1 < 1`.

The first equality would hold when `n` is not headed by `delta`, but not for arbitrary `n`. Consequently, using it to prove the recursive-successor decrease cannot support the intended termination argument. The `sorry`s merely allow these false propositions to be assumed.
