The helper strategy is **unsound** because the two lemmas it relies on are not true in general.  

### Counterexample for `kappa_rec_delta_step`  
Take any `b s : Trace` and set `n := delta void`.  

- Left-hand side:  
  `kappa (recDelta b s (delta (delta void)))`  
  By the definition of `kappa`, the third argument matches the pattern `.delta n` (with inner `n = delta void`), so  
  `= Nat.max (Nat.max (kappa b) (kappa s)) (kappa (delta void)) + 1`  
  `= Nat.max (Nat.max (kappa b) (kappa s)) (kappa void) + 1`  
  `= Nat.max (Nat.max (kappa b) (kappa s)) 0 + 1`  
  `= Nat.max (kappa b) (kappa s) + 1`.  

- Right-hand side:  
  `kappa (recDelta b s (delta void)) + 1`  
  Here the third argument is `delta void`, so  
  `= (Nat.max (Nat.max (kappa b) (kappa s)) (kappa void) + 1) + 1`  
  `= (Nat.max (Nat.max (kappa b) (kappa s)) 0 + 1) + 1`  
  `= (Nat.max (kappa b) (kappa s) + 1) + 1`  
  `= Nat.max (kappa b) (kappa s) + 2`.  

These are not equal unless `1 = 2`. Hence the claimed equality fails for `n = delta void`.  

### Consequence for `kappa_rec_succ_drop`  
The second lemma attempts to rewrite using `kappa_rec_delta_step` and then prove  
`kappa (app s (recDelta b s n)) < kappa (recDelta b s n) + 1`.  
Even ignoring the false first lemma, the inequality itself is not universally true: for example, if `kappa s` is huge and `kappa (recDelta b s n)` is small (which can happen when `b` and `s` have different sizes? Actually `kappa (recDelta b s n)` always contains `max(kappa b, kappa s)`, so it is at least `kappa s`. Thus the inequality might hold for the same reason, but the proof depends on the false first lemma. Since the first lemma is false, the proof is invalid.  

Therefore the helper strategy as written is **unsound**.
