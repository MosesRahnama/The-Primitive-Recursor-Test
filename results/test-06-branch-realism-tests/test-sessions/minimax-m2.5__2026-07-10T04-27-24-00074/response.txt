**Short answer:**  
The first helper theorem (`kappa_rec_delta_step`) is *not* a valid theorem in the given definition of `kappa`. The second theorem (`kappa_rec_succ_drop`) is actually true, but the proof that is started in the file (which rewrites with the false equality) would be unsound. Consequently the “helper strategy’’ as a whole is not sound.

---

## 1.  What the two statements say

```lean
theorem kappa_rec_delta_step (b s n : Trace) :
  kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1 := by
  sorry

theorem kappa_rec_succ_drop (b s n : Trace) :
  kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n)) := by
  rw [kappa_rec_delta_step]
  sorry
```

* `kappa_rec_delta_step` claims that adding a single `delta` in front of the third argument of `recDelta` always increases the measure by exactly 1.
* `kappa_rec_succ_drop` claims that the term `app s (recDelta b s n)` (the right‑hand side of the rewrite rule `R_rec_succ`) is strictly smaller, with respect to `kappa`, than the left‑hand side `recDelta b s (delta n)`.

---

## 2.  Checking `kappa_rec_delta_step`

### 2.1  The definition of `kappa` on `recDelta`

```lean
def kappa : Trace -> Nat
| .recDelta b s (.delta n) => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1
| .recDelta b s n         => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)
```

Hence, for any traces `b, s, n`:

* If the third argument is **exactly** `delta n` (i.e. it is a `delta`‑constructor), the measure is  
  `max(kappa b, kappa s, kappa n) + 1`.
* Otherwise the measure is just  
  `max(kappa b, kappa s, kappa n)`.

### 2.2  A concrete counter‑example

Take the simplest non‑zero “numeral’’: `delta void`.  
Let `b ≔ void`, `s ≔ void` (so `kappa b = kappa s = 0`).  
Choose `n ≔ delta void` (the numeral 1). Then:

* **Left‑hand side**  

  ```lean
  kappa (recDelta void void (delta (delta void)))
  ```
  matches the first pattern, giving  

  `max(0,0,kappa (delta void)) + 1 = max(0,0,0) + 1 = 1`.

* **Right‑hand side**  

  ```lean
  kappa (recDelta void void (delta void)) + 1
  ```
  The inner `kappa` is  

  `kappa (recDelta void void (delta void)) = max(0,0,kappa void) + 1 = max(0,0,0) + 1 = 1`.  

  Adding the extra `+1` yields `1 + 1 = 2`.

Thus  

```
kappa (recDelta void void (delta (delta void))) = 1
kappa (recDelta void void (delta void)) + 1        = 2
```

which contradicts the equality claimed by `kappa_rec_delta_step`.  
The same mismatch occurs for any `n` that is already a `delta` (i.e. for any numeral > 0). The statement is therefore **false** in general.

*If the theorem were restricted to the case `n = void` (the numeral 0) it would hold, but as written it is universally quantified and unsound.*

---

## 3.  Checking `kappa_rec_succ_drop`

### 3.1  What the measure actually does

For any traces `b, s, n` we have

```
kappa (app s (recDelta b s n))
    = Nat.max (kappa s) (kappa (recDelta b s n))
```

and

```
kappa (recDelta b s (delta n))
    = Nat.max (kappa b, kappa s, kappa n) + 1   (by the first pattern)
```

### 3.2  Direct proof (no equality needed)

Because `kappa (recDelta b s n)` is defined as `max(kappa b, kappa s, kappa n)` (or the same plus 1 when the argument is a `delta`), it is always **at least** `kappa s`. Consequently

```
kappa (app s (recDelta b s n)) = max(kappa s, kappa (recDelta b s n))
                               = kappa (recDelta b s n)          (≥ kappa s)
```

Now compare with the left‑hand side of the desired inequality:

```
kappa (recDelta b s (delta n))
    = max(kappa b, kappa s, kappa n) + 1
    ≥ kappa (recDelta b s n) + 1          (since the max already contains kappa b, kappa s, kappa n)
    > kappa (recDelta b s n)
    = kappa (app s (recDelta b s n))
```

Hence the strict inequality holds for **every** `b, s, n`. So the theorem `kappa_rec_succ_drop` is indeed true.

### 3.3  The proof attempt in the file

The proof begins with

```lean
rw [kappa_rec_delta_step]
```

If the equality from `kappa_rec_delta_step` were inserted, the goal would become

```
kappa (app s (recDelta b s n)) < kappa (recDelta b s n) + 1
```

which is also true (the right‑hand side is exactly one larger). However, because `kappa_rec_delta_step` is false, the rewrite step is illegitimate; the proof as written is unsound.

---

## 4.  Conclusion

* **The first helper theorem (`kappa_rec_delta_step`) is not valid.**  
  It fails for any `n` that is already a `delta` (e.g. the numeral 1). A counter‑example is given above.

* **The second helper theorem (`kappa_rec_succ_drop`) is true** and can be proved directly from the definition of `kappa` without any auxiliary equality.

* **The overall “helper strategy’’ is unsound**, because it relies on the false equality in the first lemma. If the first lemma were removed (or restricted to the case `n = void`), the second lemma could be proved correctly and the termination argument would be sound.

Therefore, as it stands, the file does **not** contain a sound set of helper lemmas for the termination proof.
