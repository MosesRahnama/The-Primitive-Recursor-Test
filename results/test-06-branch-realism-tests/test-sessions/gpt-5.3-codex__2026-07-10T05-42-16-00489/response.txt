Short answer: **the helper strategy is not sound as written** (at least not from the shown definitions alone).

Why:

For any `b s n`, let  
\[
M := \max(\max(\kappa b,\kappa s),\kappa n).
\]
Then by definition:

- \(\kappa(\text{recDelta } b\ s\ (\delta n)) = M + 1\).
- \(\kappa(\text{recDelta } b\ s\ n)\) is:
  - \(M + 1\) if \(n = \delta n'\),
  - \(M\) otherwise.

So the claimed theorem
\[
\kappa(\text{recDelta } b\ s\ (\delta n))
= \kappa(\text{recDelta } b\ s\ n)+1
\]
fails when \(n\) itself is a `delta` term. In that case:
- LHS \(= M+1\),
- RHS \(= (M+1)+1 = M+2\),
contradiction.

Concrete counterexample: \(b=s=n=\text{void}\).  
Then \(n=\delta\,\text{void}\) in the theorem’s `n` slot by taking theorem input `n := delta void`:

- \(\kappa(\text{recDelta } void\ void\ (\delta(\delta void))) = 1\),
- \(\kappa(\text{recDelta } void\ void\ (\delta void)) + 1 = 1+1=2\).

Not equal.

Because `kappa_rec_succ_drop` starts with `rw [kappa_rec_delta_step]`, it depends on that false equality, so the proof strategy collapses.

---

Also, independently of that rewrite, the inequality in `kappa_rec_succ_drop` is not generally valid:

\[
\kappa(\text{app } s\ (\text{recDelta } b\ s\ n))
= \max(\kappa s,\kappa(\text{recDelta } b\ s\ n)).
\]

If \(n=\delta n'\), then \(\kappa(\text{recDelta } b\ s\ n)=M+1\), hence LHS \(=M+1\), while RHS target is \(\kappa(\text{recDelta } b\ s\ (\delta n))=M+1\). So you get equality, not strict `<`.

So both helper goals (as universally quantified statements) are too strong for this `kappa`.
