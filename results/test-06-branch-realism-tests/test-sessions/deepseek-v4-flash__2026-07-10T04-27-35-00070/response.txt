The helper theorems are unsound. The definitions of `kappa` treat the third argument of `recDelta` differently based on whether it is a `delta` constructor. The statement `kappa_rec_delta_step` claims that for *any* `b, s, n`,

```
kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

However, if `n` itself is of the form `delta n'`, then both sides use the first clause of `kappa` for `recDelta`, and the equality fails. As a concrete counterexample, take `b := void`, `s := void`, `n := delta void`. Then:

- `kappa (recDelta void void (delta (delta void)))`  
  = `max(max(kappa void, kappa void), kappa (delta void)) + 1`  
  = `max(max(0,0), kappa void) + 1` = `max(0,0)+1` = `1`.

- `kappa (recDelta void void (delta void))`  
  = `max(max(kappa void, kappa void), kappa void) + 1`  
  = `max(0,0)+1` = `1`.

Thus `kappa (recDelta void void (delta (delta void))) = 1`, while the claimed right-hand side would be `1 + 1 = 2`. Hence the equality is false.

The second theorem `kappa_rec_succ_drop` depends on the first, and it also fails for the same counterexample:

- `kappa (app void (recDelta void void (delta void)))`  
  = `max(kappa void, kappa (recDelta void void (delta void)))`  
  = `max(0, 1)` = `1`.

- `kappa (recDelta void void (delta (delta void)))` = `1`.

Thus the inequality `1 < 1` is false.

Therefore the helper strategy is unsound as written.
