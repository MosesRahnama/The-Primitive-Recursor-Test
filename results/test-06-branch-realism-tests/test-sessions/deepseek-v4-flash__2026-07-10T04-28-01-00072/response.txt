The two helper lemmas are **not sound** as stated. Below are counterexamples (with explicit calculations) that demonstrate the failure.

### Counterexample for `kappa_rec_delta_step`
Take any `b, s` and let `n := delta void`.  
Then  
- `kappa (recDelta b s (delta n)) = kappa (recDelta b s (delta (delta void)))`  
  By definition: `kappa (recDelta b s (delta (delta void))) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa void) + 1`  
  = `Nat.max (max(B,S)) 0 + 1` where `B = kappa b, S = kappa s`.  
- `kappa (recDelta b s n) = kappa (recDelta b s (delta void))`  
  This matches the `delta` pattern again, so its value is `Nat.max (Nat.max B S) (kappa void) + 1 = max(B,S,0) + 1`.  

Thus both sides equal `max(B,S,0) + 1`, so `kappa (recDelta b s (delta n)) = kappa (recDelta b s n)`,  
but the lemma claims `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`. Hence the equality fails.

### Counterexample for `kappa_rec_succ_drop`
Take any `b, s` and let `n := delta void`.  
Compute:
- `kappa (app s (recDelta b s n)) = kappa (app s (recDelta b s (delta void)))`  
  = `Nat.max (kappa s) (kappa (recDelta b s (delta void)))`  
  = `Nat.max S (max(B,S,0)+1)` = `max(B,S,0)+1` (since `max(B,S,0)+1 > S`).
- `kappa (recDelta b s (delta n)) = kappa (recDelta b s (delta (delta void)))`  
  = `Nat.max (Nat.max B S) (kappa (delta void)) + 1` = `max(B,S,0)+1`.  

Both sides equal `max(B,S,0)+1`, so the strict inequality `<` is false.

### Conclusion
The lemmas are false for `n` that are themselves of the form `delta t`. The intended termination argument would therefore be unsound if it relies on these statements without additional restrictions.
