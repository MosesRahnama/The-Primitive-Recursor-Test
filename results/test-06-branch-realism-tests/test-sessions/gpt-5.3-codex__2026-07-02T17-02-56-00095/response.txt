The helper strategy is **not sound as written in full generality**.

### Why

The critical claimed lemma is:

\[
\texttt{kappa\_rec\_delta\_step: } 
\kappa(\texttt{recDelta } b\, s\, (\texttt{delta } n))
= \kappa(\texttt{recDelta } b\, s\, n) + 1.
\]

From your definition of `kappa`:

- \(\kappa(\texttt{recDelta } b\, s\, (\delta n)) = \max(\max(\kappa b,\kappa s),\kappa n)+1\).
- \(\kappa(\texttt{recDelta } b\, s\, n)\) is **by pattern match on `n`**:
  - if \(n = \delta m\), then it is \(\max(\max(\kappa b,\kappa s),\kappa m)+1\),
  - otherwise it is \(\max(\max(\kappa b,\kappa s),\kappa n)\).

So the RHS \(\kappa(\texttt{recDelta } b\, s\, n)+1\) is not uniformly the same as LHS.

### Concrete counterexample

Take \(b=s=\texttt{void}\), \(n=\delta\,\texttt{void}\).

- LHS:
  \[
  \kappa(\texttt{recDelta void void }(\delta(\delta\texttt{void})))
  = \max(\max(0,0),0)+1 = 1.
  \]
- RHS:
  \[
  \kappa(\texttt{recDelta void void }(\delta\texttt{void})) + 1
  = ( \max(\max(0,0),0)+1 ) + 1 = 2.
  \]

So \(1 \neq 2\). The theorem is false.

---

Because `kappa_rec_succ_drop` starts with `rw [kappa_rec_delta_step]`, that proof route is also invalid as stated.

(Separate note: the inequality in `kappa_rec_succ_drop` itself can still be true; the issue is the helper equality used to derive it.)
