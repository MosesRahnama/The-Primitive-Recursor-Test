**Conclusion:** The helper strategy is **not sound** as written. Both `kappa_rec_delta_step` and `kappa_rec_succ_drop` are false as general statements about the measure `kappa`. The measure fails to decrease on the `R_rec_succ` rewrite when the predecessor argument is already a `delta`.

---

### Why `kappa_rec_delta_step` fails

The definition of `kappa` distinguishes the third argument of `recDelta`:

| Pattern | Value |
|---|---|
| `.recDelta b s (.delta n)` | `Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1` |
| `.recDelta b s n` (catch‑all) | `Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)` |

Consider any traces `b`, `s` and any `n'` and let `n := delta n'`. Then:

* **Left‑hand side**  
  `kappa (recDelta b s (delta n))`  
  `= kappa (recDelta b s (delta (delta n')))`  
  `= Nat.max (Nat.max (kappa b) (kappa s)) (kappa n') + 1`

* **Right‑hand side**  
  `kappa (recDelta b s n) + 1`  
  `= kappa (recDelta b s (delta n')) + 1`  
  `= [Nat.max (Nat.max (kappa b) (kappa s)) (kappa n') + 1] + 1`  
  `= Nat.max (Nat.max (kappa b) (kappa s)) (kappa n') + 2`

The two sides differ by exactly one. Hence the equation is false whenever `n` is itself a `delta`.

**Concrete counterexample.**  
Take `b = void`, `s = void`, `n = delta void`.

* `kappa void = 0`.
* `kappa (delta void) = 0`.
* `kappa (recDelta void void (delta (delta void)))`  
  `= Nat.max (Nat.max 0 0) 0 + 1 = 1`.
* `kappa (recDelta void void (delta void))`  
  `= Nat.max (Nat.max 0 0) 0 + 1 = 1`.

The theorem claims `1 = 1 + 1`, i.e. `1 = 2`, which is impossible.

---

### Why `kappa_rec_succ_drop` fails

Using the same substitution `n = delta n'`:

* **Left‑hand side**  
  `kappa (app s (recDelta b s n))`  
  `= Nat.max (kappa s) (kappa (recDelta b s (delta n')))`  
  `= Nat.max (kappa s) (Nat.max (Nat.max (kappa b) (kappa s)) (kappa n') + 1)`

  Since `Nat.max (Nat.max (kappa b) (kappa s)) (kappa n') ≥ kappa s`, the outer `max` is the second argument:
  `= Nat.max (Nat.max (kappa b) (kappa s)) (kappa n') + 1`.

* **Right‑hand side**  
  `kappa (recDelta b s (delta n))`  
  `= kappa (recDelta b s (delta (delta n')))`  
  `= Nat.max (Nat.max (kappa b) (kappa s)) (kappa n') + 1`.

Both sides are **equal**, not strictly ordered. Therefore the strict inequality `<` is false in this case.

**Concrete counterexample (same instance).**  
With `b = void`, `s = void`, `n = delta void`:

* LHS: `kappa (app void (recDelta void void (delta void)))`  
  `= Nat.max 0 1 = 1`.
* RHS: `kappa (recDelta void void (delta (delta void))) = 1`.

The theorem claims `1 < 1`, which is false.

---

### What this means for termination

The rewrite rule

```
R_rec_succ : Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

produces a term whose `kappa` value is **not smaller** than the source when `n` is a `delta`. In fact the values are equal. Because the helper lemmas required to show a strict decrease are invalid in general, the proposed measure cannot establish termination (or even local decrease) for the calculus as defined.

**Summary:** The strategy is unsound. The measure `kappa` does not strictly decrease under `R_rec_succ` for nested `delta` arguments, and the two auxiliary theorems admit counterexamples that can be computed directly from the definition of `kappa`.
