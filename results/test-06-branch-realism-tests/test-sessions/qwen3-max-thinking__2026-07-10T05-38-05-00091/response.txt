The helper strategy is **unsound** due to critical flaws in both stated theorems. Below is a precise breakdown with counterexamples.

---

### 1. **`kappa_rec_delta_step` is false in general**
**Claimed**:  
`kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1` for all `b, s, n`.

**Counterexample**: Let `n = delta m` (for arbitrary `m`).  
- **LHS**:  
  `kappa (recDelta b s (delta (delta m)))`  
  = `max(max(κb, κs), κ(delta (delta m))) + 1` (by `kappa` definition for `.recDelta ... (.delta ...)`)  
  = `max(max(κb, κs), κm) + 1` (since `κ(delta t) = κt` repeatedly).  
- **RHS**:  
  `kappa (recDelta b s (delta m)) + 1`  
  = `[max(max(κb, κs), κ(delta m)) + 1] + 1` (again by `.recDelta ... (.delta ...)` case)  
  = `max(max(κb, κs), κm) + 2`.  

Thus:  
`LHS = M + 1`, `RHS = M + 2` (where `M = max(max(κb, κs), κm)`),  
so **`LHS ≠ RHS`**. The equality fails when `n` has a `delta` head constructor. Since the theorem quantifies universally over `n`, it is invalid.

---

### 2. **`kappa_rec_succ_drop` is false in general**
**Claimed**:  
`kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))` for all `b, s, n`.  
This is required to justify termination for rule `R_rec_succ`:  
`Step (recDelta b s (delta n)) (app s (recDelta b s n))`.

**Counterexample**: Again let `n = delta m`.  
- **LHS measure** (`app s (recDelta b s (delta m))`):  
  `κ(app ...) = max(κs, κ(recDelta b s (delta m)))`  
  = `max(κs, [max(max(κb, κs), κm) + 1])`  
  = `M + 1` (where `M = max(max(κb, κs), κm)`, and `M ≥ κs` ⇒ `max(κs, M+1) = M+1`).  
- **RHS measure** (`recDelta b s (delta (delta m))`):  
  `κ(...) = max(max(κb, κs), κ(delta (delta m))) + 1 = M + 1`.  

Thus: **`LHS measure = RHS measure`**, violating the strict inequality `<`.  
This is catastrophic for termination: a rewrite step exists where the measure *does not decrease*. An infinite reduction sequence is possible (e.g., repeatedly applying `R_rec_succ` to nested `delta` arguments under context closure), violating well-foundedness.

---

### Why the Strategy Fails
- **Flawed lemma dependency**: `kappa_rec_succ_drop` attempts to use `kappa_rec_delta_step` (via `rw`), but the latter is false. Even if patched, the core inequality fails as shown.
- **Measure design issue**: The `+1` in `kappa` for `.recDelta ... (.delta n)` depends *only* on the immediate `delta` constructor, not the depth of nesting. When `n` itself starts with `delta`, the recursive `recDelta` subterm in the RHS inherits a `+1`, nullifying the intended decrease.
- **Termination implication**: A valid termination argument requires *every* rewrite step (including all subterm reductions under context closure) to strictly decrease a well-founded measure. Here, `R_rec_succ` admits steps with *equal* measure, breaking the argument.

### Conclusion
Both helper theorems are **mathematically incorrect** for general inputs. The counterexamples (`n = delta m`) are syntactically valid traces within the system. Consequently, the proposed termination strategy—relying on these lemmas to show strict measure decrease for `R_rec_succ`—is **unsound**. No modification of proof tactics (e.g., filling `sorry`) can salvage the theorems as stated; the definitions of `kappa` or the rewrite rules would require revision to restore soundness.
