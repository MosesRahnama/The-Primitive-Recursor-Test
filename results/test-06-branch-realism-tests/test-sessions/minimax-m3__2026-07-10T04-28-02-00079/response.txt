## Assessment: The helper strategy is **unsound**.

### Analysis of `kappa_rec_delta_step`

The lemma as stated claims, for **all** `n : Trace`:

$$\kappa(\texttt{recDelta } b\, s\, (\delta\, n)) \;=\; \kappa(\texttt{recDelta } b\, s\, n) + 1$$

Reading off the definition of `kappa` clause by clause:

* **LHS.** The argument is *exactly* of the shape `recDelta b s (.delta n)`, so the first clause fires:
$$\kappa(\texttt{recDelta } b\, s\, (\delta n)) = \max\bigl(\max(\kappa b,\kappa s),\kappa n\bigr) + 1$$

* **RHS.** The computation of $\kappa(\texttt{recDelta } b\, s\, n)$ depends on the *shape of `n`*:
  * If `n` is **not** of the form `delta m`, the second clause applies:
    $$\kappa(\texttt{recDelta } b\, s\, n) = \max\bigl(\max(\kappa b,\kappa s),\kappa n\bigr),$$
    and the equation holds. ✅
  * If `n = delta m` for some `m`, the first clause applies **again**:
    $$\kappa(\texttt{recDelta } b\, s\, (\delta m)) = \max\bigl(\max(\kappa b,\kappa s),\kappa m\bigr) + 1,$$
    so the RHS becomes $\max(\max(\kappa b,\kappa s),\kappa m) + 2$, but the LHS is only $\max(\max(\kappa b,\kappa s),\kappa m) + 1$. ❌

**Counterexample.** Take $b = \texttt{void}$, $s = \texttt{void}$, $n = \delta\,\texttt{void}$ (so that the third argument of the outer call is $\delta(\delta\,\texttt{void})$, which still matches the first clause once).

* LHS: $\kappa(\texttt{recDelta void void}(\delta(\delta\,\texttt{void}))) = \max(\max(0,0),0) + 1 = 1.$
* RHS: $\kappa(\texttt{recDelta void void}(\delta\,\texttt{void})) + 1 = (\max(\max(0,0),0) + 1) + 1 = 2.$

So $1 = 2$ is false, and `kappa_rec_delta_step` is **not provable as stated**.

### Why the rewrite in `kappa_rec_succ_drop` doesn't save the situation

The second theorem begins with

```lean
rw [kappa_rec_delta_step]
```

which (in Lean, regardless of the lemma's truth) rewrites the goal

$$\kappa(\texttt{app } s\, (\texttt{recDelta } b\, s\, n)) \;<\; \kappa(\texttt{recDelta } b\, s\, (\delta\, n))$$

into

$$\kappa(\texttt{app } s\, (\texttt{recDelta } b\, s\, n)) \;<\; \kappa(\texttt{recDelta } b\, s\, n) + 1.$$

The intended *content* of the original inequality is real: since
$$\kappa(\texttt{app } s\, (\texttt{recDelta } b\, s\, n)) = \max\bigl(\kappa s,\; \kappa(\texttt{recDelta } b\, s\, n)\bigr) \;\le\; \kappa(\texttt{recDelta } b\, s\, n) < \kappa(\texttt{recDelta } b\, s\, n) + 1,$$
the inequality does hold. **But the rewrite is applied to a lemma that is false**, so the resulting proof obligation corresponds to a *different (and weaker) statement* than the original one — and indeed the rewrite only works in the cases where the first lemma happened to be true. In the pathological case $n = \delta m$, the rewrite silently replaces a true goal with one that is now consistent with the false equality, breaking the termination argument's chain of reasoning for that input.

### Verdict

The proof skeleton is **not sound as written**. The error is in `kappa_rec_delta_step`: the `kappa` definition's recursive position for `recDelta` is the third argument, and the `+1` is only added when that argument is literally of the form `delta _`. Stripping one `delta` therefore increases `kappa` by 1 only when the inner term is *not* another `delta`; otherwise it increases by 0 and the stated identity fails.

A correct fix is to either (a) state the lemma with the extra hypothesis `¬ ∃ m, n = delta m`, or (b) replace the rewrite with a direct argument that does not depend on the false identity — for instance, unfolding both sides of the inequality and using $\max(\kappa s, \kappa(\texttt{recDelta } b\, s\, n)) \le \kappa(\texttt{recDelta } b\, s\, n) < \kappa(\texttt{recDelta } b\, s\, n) + 1$, which already yields the strict decrease needed for the `R_rec_succ` step without the broken auxiliary lemma.
