The helper strategy is not sound as written. In particular, both stated helper theorems are false because `kappa` distinguishes a `recDelta` whose third argument is syntactically a `delta`, and the theorem quantifies over arbitrary `n`, including `n = delta m`.

Let

```lean
b = void
s = void
n = delta void
```

Then:

```lean
kappa b = 0
kappa s = 0
kappa n = kappa (delta void) = 0
```

For the left side of `kappa_rec_delta_step`:

```lean
kappa (recDelta void void (delta (delta void)))
= max (max 0 0) (kappa (delta void)) + 1
= max 0 0 + 1
= 1
```

But on the right side:

```lean
kappa (recDelta void void (delta void)) + 1
= (max (max 0 0) (kappa void) + 1) + 1
= (0 + 1) + 1
= 2
```

Thus the asserted equality specializes to `1 = 2`:

```lean
kappa (recDelta void void (delta (delta void)))
≠ kappa (recDelta void void (delta void)) + 1
```

So `kappa_rec_delta_step` cannot be proved.

The same example refutes `kappa_rec_succ_drop`. Its left side is:

```lean
kappa (app void (recDelta void void (delta void)))
= max 0 1
= 1
```

while its right side is:

```lean
kappa (recDelta void void (delta (delta void)))
= 1
```

Hence the claimed strict inequality is `1 < 1`, which is false.

More generally, if `n = delta m`, write

```text
M = max (max (kappa b) (kappa s)) (kappa m).
```

Then:

```text
kappa (recDelta b s (delta (delta m))) = M + 1
kappa (recDelta b s (delta m))         = M + 1
```

Therefore:

```text
kappa (app s (recDelta b s (delta m)))
= max (kappa s) (M + 1)
= M + 1,
```

since `kappa s ≤ M`. So the `R_rec_succ` source and target have equal `kappa` in this case, rather than the target having smaller `kappa`.

The issue is that `kappa` assigns the extra `+ 1` whenever the immediate third argument of `recDelta` is a `delta`. Rewriting

```lean
recDelta b s (delta n)
```

to

```lean
app s (recDelta b s n)
```

removes one such outer `delta`, but if `n` is itself a `delta`, the recursive call still receives a syntactic `delta` and retains the extra unit. Thus this measure does not strictly decrease for all instances of `R_rec_succ`.

Additionally, several other rules preserve `kappa` rather than strictly decreasing it—for example `R_eq_diff` has equal source and target `kappa`:

```text
kappa (eqW a b)
= max (kappa a) (kappa b)
= kappa (integrate (merge a b)).
```

So `kappa` cannot by itself support a global strict-decrease termination proof for the full `Step` relation.
