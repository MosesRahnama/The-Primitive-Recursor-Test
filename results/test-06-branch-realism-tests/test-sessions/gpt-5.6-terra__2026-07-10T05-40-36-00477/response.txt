The helper strategy is not sound as written. Both helper theorems are false for arbitrary `n`.

The issue is that `kappa` adds `1` to a `recDelta` only when its third argument is *immediately* a `delta`:

```lean
kappa (recDelta b s (.delta n))
  = max (max (kappa b) (kappa s)) (kappa n) + 1
```

It does not add another unit for nested `delta`s.

Take:

```lean
b = void
s = void
n = delta void
```

Then all of `kappa void`, `kappa (delta void)`, and `kappa (delta (delta void))` are `0`.

Let `B = max (kappa b) (kappa s) = 0`. We obtain:

```text
kappa (recDelta void void (delta void)) = 0 + 1 = 1
kappa (recDelta void void (delta (delta void))) = 0 + 1 = 1
```

Therefore `kappa_rec_delta_step` specializes to the false statement

```text
1 = 1 + 1
```

More explicitly, its claimed equation is:

```text
kappa (recDelta void void (delta (delta void)))
=
kappa (recDelta void void (delta void)) + 1
```

i.e.

```text
1 = 2.
```

So the first theorem would only be plausible under an additional condition that `n` is not itself of the form `delta _`; it is not true for arbitrary `n : Trace`.

Consequently, `kappa_rec_succ_drop` is also false. Under the same instantiation:

```text
kappa (app void (recDelta void void (delta void)))
= max 0 1
= 1
```

while

```text
kappa (recDelta void void (delta (delta void))) = 1.
```

Thus its claimed strict inequality becomes:

```text
1 < 1,
```

which is false.

This exactly corresponds to the `R_rec_succ` rewrite:

```text
recDelta void void (delta (delta void))
  ↦ app void (recDelta void void (delta void)).
```

The measure is unchanged across that step.

Moreover, `kappa` cannot by itself give strict decrease for several other rules either. For example, `R_eq_diff` preserves it exactly:

```text
kappa (eqW a b)
= max (kappa a) (kappa b)

kappa (integrate (merge a b))
= kappa (merge a b)
= max (kappa a) (kappa b).
```

Likewise, rules such as `merge void t ↦ t` preserve `kappa`.

Hence the admitted `sorry`s can make the file accept the statements formally, but mathematically the proposed helper lemmas—and a strict-decrease termination argument based on them—are invalid.
