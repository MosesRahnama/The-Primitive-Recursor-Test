## Analysis of `kappa_rec_delta_step`

The claim is:
```
kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

**Left side** (by `kappa_rec_delta`):
```
kappa (recDelta b s (delta n)) = max (max (kappa b) (kappa s)) (kappa n) + 1
```

**Right side** — I need to evaluate `kappa (recDelta b s n)`. This depends on the shape of `n`. The definition has a **special case only when the third argument is `delta _`**:
```
| .recDelta b s (.delta n) => max (max (kappa b) (kappa s)) (kappa n) + 1
| .recDelta b s n          => max (max (kappa b) (kappa s)) (kappa n)
```

So `kappa (recDelta b s n)` is **not** uniformly `max (max (kappa b) (kappa s)) (kappa n)`. If `n` happens to be `delta m` for some `m`, then:
```
kappa (recDelta b s n) = kappa (recDelta b s (delta m)) = max (max (kappa b) (kappa s)) (kappa m) + 1
```
which is **not** `max (max (kappa b) (kappa s)) (kappa n)`.

For the general case where `n` is not of the form `delta _`:
```
kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n)
```
Then `kappa (recDelta b s n) + 1 = max (max (kappa b) (kappa s)) (kappa n) + 1` ✓

But when `n = delta m`:
- LHS: `kappa (recDelta b s (delta (delta m))) = max (max (kappa b) (kappa s)) (kappa (delta m)) + 1 = max (max (kappa b) (kappa s)) (kappa m) + 1`
- RHS: `kappa (recDelta b s (delta m)) + 1 = (max (max (kappa b) (kappa s)) (kappa m) + 1) + 1`

These are **not equal** — the RHS is 1 larger than the LHS.

**`kappa_rec_delta_step` is unsound.**

## Analysis of `kappa_rec_succ_drop`

The claim is:
```
kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
```

This theorem uses `kappa_rec_delta_step` (which is already unsound), but let me check it independently.

**LHS:**
```
kappa (app s (recDelta b s n)) = max (kappa s) (kappa (recDelta b s n))
```

For the non-`delta` case of `n`: `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n)`

So LHS = `max (kappa s) (max (max (kappa b) (kappa s)) (kappa n)) = max (max (kappa b) (kappa s)) (kappa n)`

**RHS:**
```
kappa (recDelta b s (delta n)) = max (max (kappa b) (kappa s)) (kappa n) + 1
```

So the inequality becomes: `max (max (kappa b) (kappa s)) (kappa n) < max (max (kappa b) (kappa s)) (kappa n) + 1` ✓

This **does hold** for the case where `n` is not `delta _`. But again for `n = delta m`, the LHS includes `kappa (recDelta b s (delta m)) = max(...) + 1`, making LHS = `max (max (kappa b) (kappa s)) (kappa m) + 1`, and RHS = `max (max (kappa b) (kappa s)) (kappa m) + 1 + 1`, so the strict inequality still holds in that subcase too.

Actually `kappa_rec_succ_drop` appears to be **true** (the `+1` on the RHS provides the needed slack), but it cannot be proved via `kappa_rec_delta_step` since that lemma is false.

## Conclusion

**The helper strategy is unsound as written.** `kappa_rec_delta_step` is **false** when `n` is itself of the form `delta m`, because `kappa` adds an extra `+1` for each `delta`-wrapped third argument, causing the equation to fail. The second theorem happens to be true on its own merits, but the proof strategy (rewriting via the broken first lemma) is invalid.
