## Theorem 1: `kappa_rec_delta_step`

Claim: `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

**LHS:** By `kappa_rec_delta`, `kappa (recDelta b s (delta n)) = max (max (kappa b) (kappa s)) (kappa n) + 1`.

**RHS:** `kappa (recDelta b s n) + 1`. Here the value of `kappa (recDelta b s n)` depends on the shape of `n`, because `kappa` pattern-matches on the third argument:

- If `n` is **not** of the form `delta _` (e.g., `void`, `merge ...`, etc.), then the general `recDelta` case applies:
  `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n)`.
  Then RHS `= max (max (kappa b) (kappa s)) (kappa n) + 1`, which **equals** the LHS. ✓

- If `n` **is** of the form `delta m`, then the special case applies:
  `kappa (recDelta b s (delta m)) = max (max (kappa b) (kappa s)) (kappa m) + 1`.
  Then RHS `= max (max (kappa b) (kappa s)) (kappa m) + 2`.
  The LHS (with `n = delta m`) `= max (max (kappa b) (kappa s)) (kappa (delta m)) + 1 = max (max (kappa b) (kappa s)) (kappa m) + 1` (since `kappa (delta m) = kappa m`).
  So LHS `= X + 1` while RHS `= X + 2`. These are **not equal**. ✗

**Conclusion:** Theorem 1 is **false** in general. It fails whenever `n` itself has the shape `delta m`. For example, take `b = s = void`, `n = delta void`:
- LHS: `kappa (recDelta void void (delta (delta void))) = max (max 0 0) (kappa (delta void)) + 1 = 0 + 1 = 1`.
- RHS: `kappa (recDelta void void (delta void)) + 1 = (max (max 0 0) (kappa void) + 1) + 1 = 1 + 1 = 2`.

So `1 = 2` is required — unprovable. The `sorry` cannot be discharged.

## Theorem 2: `kappa_rec_succ_drop`

Claim: `kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`

The proof begins with `rw [kappa_rec_delta_step]`, rewriting the goal's RHS to `kappa (recDelta b s n) + 1`. The remaining goal is:

`kappa (app s (recDelta b s n)) < kappa (recDelta b s n) + 1`

i.e. `max (kappa s) (kappa (recDelta b s n)) < kappa (recDelta b s n) + 1`.

Let `R = kappa (recDelta b s n)`. The goal is `max (kappa s) R < R + 1`, i.e. `max (kappa s) R ≤ R`. This holds **iff** `kappa s ≤ R`.

Is `kappa s ≤ kappa (recDelta b s n)` always true? Check the two cases:
- General case: `R = max (max (kappa b) (kappa s)) (kappa n) ≥ kappa s`. ✓
- `delta` case: `R = max (max (kappa b) (kappa s)) (kappa m) + 1 > kappa s`. ✓

So the *remaining* goal after the rewrite is actually **true** and provable (though it needs its own argument, not just `sorry`, but it is at least sound).

**However**, the proof of Theorem 2 *depends on `kappa_rec_delta_step`* via the `rw`. Since Theorem 1 is proved by `sorry`, Theorem 2 relies on a false lemma. But note that Theorem 2's *statement* itself is actually **true**:

Direct check of the real statement `max (kappa s) R < kappa (recDelta b s (delta n))`:
- `kappa (recDelta b s (delta n)) = max (max (kappa b) (kappa s)) (kappa n) + 1`.
- Need `max (kappa s) R < max (max (kappa b) (kappa s)) (kappa n) + 1`.

Here `R = kappa (recDelta b s n)`. In the general case for `n`, `R = max (max (kappa b) (kappa s)) (kappa n)`, so LHS `= max (kappa s) R = R` (since `kappa s ≤ R`), and RHS `= R + 1`. So `R < R + 1` holds. ✓. In the `delta` sub-case it also holds by similar reasoning. So Theorem 2's statement is true.

## Overall Assessment

**The helper strategy is unsound as written.**

The failure is localized in `kappa_rec_delta_step`, whose statement is **false** because `kappa` pattern-matches on the shape of the third argument. When `n = delta m`, wrapping it in another `delta` does *not* increase `kappa` by the amount the lemma claims: the outer `delta` is "absorbed" (`kappa (delta m) = kappa m`), so the two `+1` contributions collapse into one. The lemma essentially assumes the `+1` in the special `recDelta`/`delta` case counts the number of leading `delta`s, but `kappa` only ever adds a single `+1` regardless of how deep the `delta` nesting goes.

Consequently:
- **Theorem 1 (`kappa_rec_delta_step`) cannot be proved** — the `sorry` is unfillable; concrete counterexample above (`1 ≠ 2`).
- **Theorem 2 (`kappa_rec_succ_drop`)** has a *true* statement and could be proved, but the given proof skeleton routes it through the false Theorem 1 via `rw [kappa_rec_delta_step]`. That step is only accepted because Theorem 1 was admitted by `sorry`; the intended strategy is therefore not sound. A correct proof of Theorem 2 must avoid `kappa_rec_delta_step` and instead work directly from `kappa_rec_delta` plus the fact `kappa s ≤ kappa (recDelta b s n)`.

**Recommendation:** discard `kappa_rec_delta_step` (it is not a theorem), and prove `kappa_rec_succ_drop` directly. Note also that `kappa` as defined does not strictly decrease across `R_rec_succ` in a way `kappa_rec_delta_step` presumes, so any termination argument built on that lemma is broken.
