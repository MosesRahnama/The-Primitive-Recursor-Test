**Conclusion:** The helper strategy is **unsound** as written. Both `kappa_rec_delta_step` and `kappa_rec_succ_drop` are false in general. The measure `kappa` does **not** strictly decrease under the rewrite rule `R_rec_succ` when the argument `n` is itself a `delta`.

---

### Why `kappa_rec_delta_step` fails

The definition of `kappa` gives a bonus `+ 1` **only when the third argument of `recDelta` is syntactically a `delta`**:

```lean
| .recDelta b s (.delta n) => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1
| .recDelta b s n          => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)
```

If `n` is already a `delta`, then `recDelta b s n` *already* receives that `+1`. Nesting another `delta` on the outside does **not** increase the measure by exactly one relative to the inner term.

**Counterexample.** Take  
`b = void`, `s = void`, `n = delta void`.

First compute the atomic measures:
* `kappa void = 0`
* `kappa (delta void) = kappa void = 0`
* `kappa (delta (delta void)) = kappa (delta void) = 0`

Now compute the `recDelta` measures:

1. `kappa (recDelta void void (delta void))`  
   matches the first clause with inner `n = void`:  
   `= max(max(0,0), 0) + 1 = 1`.

2. `kappa (recDelta void void (delta (delta void)))`  
   matches the first clause with inner `n = delta void`:  
   `= max(max(0,0), kappa (delta void)) + 1 = max(0,0) + 1 = 1`.

Now evaluate the theorem statement:
* LHS: `kappa (recDelta void void (delta (delta void))) = 1`
* RHS: `kappa (recDelta void void (delta void)) + 1 = 1 + 1 = 2`

`1 = 2` is false. ∎

---

### Why `kappa_rec_succ_drop` fails

The theorem claims
```lean
kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
```
for **all** `b, s, n`. Using the same counterexample we obtain equality, not a strict decrease.

**Counterexample.** Again let `b = void`, `s = void`, `n = delta void`.

* LHS:  
  `kappa (app void (recDelta void void (delta void)))`  
  `= max(kappa void, kappa (recDelta void void (delta void)))`  
  `= max(0, 1) = 1`.

* RHS:  
  `kappa (recDelta void void (delta (delta void))) = 1` (computed above).

So we get `1 < 1`, which is false. ∎

---

### General analysis

For arbitrary traces:

* `kappa (recDelta b s (delta n)) = M + 1`  
  where `M = max(max(kappa b, kappa s), kappa n)`.

* `kappa (recDelta b s n)` equals:
  * `M + 1` if `n` itself is a `delta`,
  * `M`     otherwise.

Hence:
* If `n` is **not** a `delta`, then `kappa_rec_delta_step` holds (difference is exactly 1) and `kappa_rec_succ_drop` also holds because  
  `kappa (app s (recDelta b s n)) = max(kappa s, M) = M < M + 1`.

* If `n` **is** a `delta`, then `kappa (recDelta b s (delta n)) = M + 1` while `kappa (recDelta b s n) = M + 1` as well. Consequently:
  * `kappa_rec_delta_step` would require `(M + 1) = (M + 1) + 1`, which is impossible.
  * `kappa_rec_succ_drop` becomes `M + 1 < M + 1`, which is also impossible.

Because the rewrite rule `R_rec_succ` applies to *any* trace of the form `recDelta b s (delta n)`, including those where `n` is a `delta`, the measure `kappa` fails to decrease strictly in all cases. Therefore the proposed termination argument is unsound.
