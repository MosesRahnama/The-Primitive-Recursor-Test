The helper strategy is **not sound** as written. The problem lies in the purported lemma `kappa_rec_delta_step`.

### The failure of `kappa_rec_delta_step`

The measure `kappa` is defined by recursion on `Trace` with special treatment of the `recDelta` constructor:

```lean
def kappa : Trace -> Nat
| .recDelta b s (.delta n) => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1
| .recDelta b s n          => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)
... (other clauses)
```

The lemma claims:

```lean
theorem kappa_rec_delta_step (b s n : Trace) :
  kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1 := ...
```

We can compute both sides for an arbitrary `n`.

**Left‑hand side:**
`kappa (recDelta b s (delta n))` matches the `.delta n` pattern, so  
`= max(max(kappa b, kappa s), kappa n) + 1`.

**Right‑hand side:**
`kappa (recDelta b s n) + 1` depends on whether `n` itself is a `delta`.
- If `n` is **not** a `delta` (e.g., `void`, `integrate`, …), then  
  `kappa (recDelta b s n) = max(max(kappa b, kappa s), kappa n)`, and the equality holds.
- If `n` **is** a `delta m`, then `kappa (recDelta b s n) = max(max(kappa b, kappa s), kappa m) + 1`, so the RHS becomes  
  `(max(max(kappa b, kappa s), kappa m) + 1) + 1 = max(...) + 2`.  
  The LHS is `max(max(kappa b, kappa s), kappa n) + 1 = max(...) + 1` (since `kappa (delta m) = kappa m`). Hence the two sides differ by 1.

**Concrete counterexample:** take `b = s = n = .delta .void`. Then  
`kappa b = kappa s = 0`, `kappa n = 0`.  
LHS = `kappa (recDelta (delta void) (delta void) (delta (delta void)))` = `max(0,0)+1 = 1`.  
RHS = `kappa (recDelta (delta void) (delta void) (delta void)) + 1` = `(max(0,0)+1)+1 = 2`.  
Thus `1 = 2` is false.

The lemma `kappa_rec_succ_drop` attempts to rewrite using this false equality, so it too becomes unsound (even if its direct inequality might be provable, the strategy as a whole relies on a false statement).

Therefore the intended helper strategy for a termination proof is invalid, because the key lemma `kappa_rec_delta_step` does not hold for all `Trace` terms.
