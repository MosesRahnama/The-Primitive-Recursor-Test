## Assessment: The helper strategy is **unsound**.

### The claimed lemma `kappa_rec_delta_step`

The strategy attempts to prove:
```
kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

Let me unfold both sides by case‑splitting on whether `n` itself is a `delta _`.

**Left‑hand side.** The third argument is `delta n`, so the first branch of `kappa` fires:
```
LHS = max (max (κ b) (κ s)) (κ (delta n)) + 1
    = max (max (κ b) (κ s)) (κ n) + 1
```

**Right‑hand side.** Two sub‑cases for `κ (recDelta b s n)`:

*Case A — `n` is NOT of the form `delta _`.* The second branch of `kappa` applies:
```
RHS = max (max (κ b) (κ s)) (κ n) + 1
```
So `LHS = RHS`. ✓

*Case B — `n = delta n'`.* The first branch of `kappa` applies (because the third argument is `delta n'`):
```
κ (recDelta b s (delta n')) = max (max (κ b) (κ s)) (κ n') + 1
RHS                        = max (max (κ b) (κ s)) (κ n') + 2
```
Since `κ (delta n) = κ n = κ n'`, we have `LHS = max(max(κb)(κs), κn') + 1`, but `RHS = max(max(κb)(κs), κn') + 2`. **Off by 1.** ✗

So the lemma is **false** whenever `n` is itself a `delta _`. A concrete counterexample:
```
b = void, s = void, n = delta void

LHS = κ (recDelta void void (delta (delta void)))
    = max (max 0 0) (κ (delta (delta void))) + 1
    = max 0 (κ (delta void)) + 1
    = 0 + 1 = 1

RHS = κ (recDelta void void (delta void)) + 1
    = max 0 (κ (delta void)) + 1 + 1
    = 0 + 1 + 1 = 2
```
Hence `kappa_rec_delta_step` is invalid as a general statement.

### Downstream effect on `kappa_rec_succ_drop`

The second helper rewrites with `kappa_rec_delta_step` and then (implicitly) needs
```
κ (app s (recDelta b s n)) ≤ κ (recDelta b s n)
```
which *is* true (because `κ (recDelta b s n) ≥ max(κ b, κ s) ≥ κ s`). So the *only* load‑bearing fact is `kappa_rec_delta_step` — and that fact is false.

To see the direct counterexample for the second lemma, take `b = s = n = void`:
```
LHS = κ (app void (recDelta void void void))
    = max (κ void) (κ (recDelta void void void))
    = max 0 (max 0 0) = 0

RHS = κ (recDelta void void (delta void))
    = max 0 (κ (delta void)) + 1
    = 0 + 1 = 1
```
OK, that one works. But take `b = s = void`, `n = delta void`:
```
LHS = κ (app void (recDelta void void (delta void)))
    = max (κ void) (κ (recDelta void void (delta void)))
    = max 0 (max 0 0 + 1) = 1

RHS = κ (recDelta void void (delta (delta void)))
    = max 0 (κ (delta (delta void))) + 1
    = max 0 0 + 1 = 1
```
**Equal, not strictly less.** So `kappa_rec_succ_drop` is false as a general statement.

### Why the measure fundamentally fails

The `+1` in `kappa` only triggers when the outermost constructor of the *third* argument is `delta`. It does **not** count how many `delta`s are wrapped. Concretely, for any `n`:
```
κ (recDelta b s n)            = max(max(κb)(κs), κn)         [n not a delta]
κ (recDelta b s (delta n))    = max(max(κb)(κs), κn) + 1
κ (recDelta b s (delta² n))   = max(max(κb)(κs), κn) + 1
κ (recDelta b s (delta^k n))  = max(max(κb)(κs), κn) + 1   for any k ≥ 1
```

So in the rewrite
```
recDelta b s (delta² n)  ⟶  app s (recDelta b s (delta n))
```
both sides have `κ = max(max(κb)(κs), κn) + 1`. The measure does not decrease, and no `sorry` can rescue this — the strategy is unsound as written.

### Verdict

Both helper theorems are **false in general**. The flaw is structural: `kappa` does not record the depth of leading `delta`s in the third argument of `recDelta`, so the `R_rec_succ` rule can be applied repeatedly with no decrease in the measure. The termination argument built on top of these two lemmas is therefore unsound.
