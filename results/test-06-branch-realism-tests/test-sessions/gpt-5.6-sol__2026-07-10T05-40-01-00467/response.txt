The helper strategy is **not sound as written**. Both helper theorems are false when `n` is itself headed by `delta`.

Take:

```lean
b = void
s = void
n = delta void
```

Then:

```lean
kappa void = 0
kappa (delta void) = 0
```

For the left side of `kappa_rec_delta_step`:

```lean
kappa (recDelta void void (delta (delta void)))
  = max (max 0 0) (kappa (delta void)) + 1
  = 1
```

But:

```lean
kappa (recDelta void void (delta void))
  = max (max 0 0) (kappa void) + 1
  = 1
```

so its asserted right side is:

```lean
kappa (recDelta void void (delta void)) + 1 = 2
```

Thus `kappa_rec_delta_step` would assert `1 = 2`.

The same example refutes `kappa_rec_succ_drop`:

```lean
kappa (app void (recDelta void void (delta void)))
  = max 0 1
  = 1
```

while:

```lean
kappa (recDelta void void (delta (delta void))) = 1
```

so the claimed inequality is `1 < 1`.

More generally, if `n = delta m` and

```lean
M = max (max (kappa b) (kappa s)) (kappa m),
```

then both

```lean
kappa (recDelta b s (delta n))
```

and

```lean
kappa (app s (recDelta b s n))
```

equal `M + 1`. The issue is that `kappa` gives only one extra unit whenever the third argument of `recDelta` is immediately `delta`-headed; nested `delta`s do not accumulate further units because `kappa (delta m) = kappa m`.

Consequently, `R_rec_succ` does not always strictly decrease `kappa`, and the two `sorry`s conceal genuinely false claims. The argument would work only under an additional condition that `n` is not `delta`-headed, or with a redesigned measure that handles nested successors.
