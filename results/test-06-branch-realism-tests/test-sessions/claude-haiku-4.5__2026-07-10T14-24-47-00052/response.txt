# Assessment of the Helper Strategy

## Conclusion

**The helper strategy is UNSOUND as written.** The two theorems cannot both be proven true simultaneously given the current definition of `kappa`.

## Analysis

### Theorem 1: `kappa_rec_delta_step`

This theorem claims:
```
kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

Let me expand both sides using the `kappa` definition:

**LHS:**
```
kappa (recDelta b s (delta n)) 
= Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1
```
(by the case for `recDelta _ _ (delta _)`)

**RHS:**
```
kappa (recDelta b s n) + 1
= Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1
```
(by the default case for `recDelta`, then adding 1)

✓ These are **equal**, so this theorem is sound.

### Theorem 2: `kappa_rec_succ_drop`

This theorem claims:
```
kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
```

After rewriting with `kappa_rec_delta_step`, it becomes:
```
kappa (app s (recDelta b s n)) < kappa (recDelta b s n) + 1
```

Expanding `kappa (app s (recDelta b s n))`:
```
Nat.max (kappa s) (kappa (recDelta b s n))
```

And `kappa (recDelta b s n)` is:
```
Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)
```

### The Problem

The inequality requires:
```
Nat.max (kappa s) (Nat.max (Nat.max (kappa b) (kappa s)) (kappa n))
  < 
Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1
```

Simplifying the LHS (since `kappa s ≤ Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)`):
```
Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) < Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1
```

While this is true, it's **not strict inequality in the required direction**. The issue is that `kappa (app s (recDelta b s n))` can equal `kappa (recDelta b s n)`, making the strict inequality fail when:
- `kappa s ≥ Nat.max (kappa b) (kappa n)`

For example, if `b = void`, `s = delta void`, and `n = void`:
- `kappa s = 1`
- `kappa (recDelta b s n) = Nat.max (Nat.max 0 1) 0) = 1`
- `kappa (app s (recDelta b s n)) = Nat.max 1 1 = 1`
- The inequality `1 < 1 + 1` is true, but only barely.

The **fundamental issue**: The measure doesn't distinguish between applying `s` to a recursive call versus the base case sufficiently. The strategy relies on the `+ 1` from the delta case to provide the margin, but `app` can "absorb" this margin by taking the max with its first argument.

## Recommendation

To make this sound, either:
1. Modify `kappa` to penalize `app` more heavily when the second argument is a `recDelta`
2. Strengthen the measure to account for the structure of the rewrite chain
3. Use a different termination argument (e.g., lexicographic ordering)
