The helper strategy is **not sound as written**. Both helper theorems are false when `n` is itself a `delta`.

Let

```lean
b = void
s = void
n = delta void
```

Since `kappa (delta t) = kappa t`, all relevant subterms have measure `0`. Then:

```lean
kappa (recDelta void void (delta void)) = 1
```

and likewise

```lean
kappa (recDelta void void (delta (delta void))) = 1
```

because the special `recDelta ... (.delta n)` clause adds exactly one, while `kappa` does not count the nested `delta`.

Therefore `kappa_rec_delta_step` specializes to

```lean
1 = 1 + 1
```

i.e. `1 = 2`, which is false.

The claimed strict decrease is also false for the same instance:

```lean
kappa (app void (recDelta void void (delta void)))
  = max 0 1
  = 1
```

whereas

```lean
kappa (recDelta void void (delta (delta void))) = 1.
```

Thus `kappa_rec_succ_drop` claims `1 < 1`.

More generally, writing

```lean
A = max (max (kappa b) (kappa s)) (kappa m),
```

and taking `n = delta m`, both sides relevant to the recursive-successor step have measure `A + 1`, rather than exhibiting a strict decrease.

The issue is the interaction between:

- `kappa (delta t) = kappa t`, which makes `delta` transparent, and
- the special `recDelta ... (delta n)` clause, which adds only one regardless of whether `n` is itself a `delta`.

The `sorry`s therefore conceal genuinely unprovable statements, not merely missing routine proofs.
