## Assessment: The Helper Strategy is **Unsound**

Both helper theorems are **false** as stated. The root cause is that `kappa` only pattern-matches a single `delta` layer in the third argument of `recDelta`, but because `kappa (delta t) = kappa t`, nested `delta` constructors collapse silently, preventing the `+1` increment from accumulating.

---

### Theorem 1: `kappa_rec_delta_step` is false

**Claim:** `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

**Counterexample:** Let `b = void`, `s = void`, `n = delta void`.

**LHS:**
```
kappa (recDelta void void (delta (delta void)))
```
The third argument `delta (delta void)` matches the pattern `delta n'` with `n' = delta void`, so:
```
= max (max (kappa void) (kappa void)) (kappa (delta void)) + 1
= max (max 0 0) (kappa void) + 1        -- since kappa (delta void) = kappa void = 0
= 0 + 1
= 1
```

**RHS:**
```
kappa (recDelta void void (delta void)) + 1
```
The third argument `delta void` matches `delta n'` with `n' = void`:
```
= (max (max (kappa void) (kappa void)) (kappa void) + 1) + 1
= (max (max 0 0) 0 + 1) + 1
= (0 + 1) + 1
= 2
```

**Result:** `1 ≠ 2`. The theorem fails whenever `n` is itself a `delta` term, because `kappa (delta m) = kappa m` erases the inner `delta` before the outer pattern match can account for it.

---

### Theorem 2: `kappa_rec_succ_drop` is false

**Claim:** `kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`

**Counterexample:** Same values — `b = void`, `s = void`, `n = delta void`.

**LHS:**
```
kappa (app void (recDelta void void (delta void)))
= max (kappa void) (kappa (recDelta void void (delta void)))
= max 0 1                                  -- from the RHS computation of Theorem 1
= 1
```

**RHS:**
```
kappa (recDelta void void (delta (delta void)))
= 1                                        -- from the LHS computation of Theorem 1
```

**Result:** `1 < 1` is false. The inequality degenerates to equality when `n` is a `delta` term.

---

### Diagnosis

The definition of `kappa` for `recDelta` is:

```lean
| .recDelta b s (.delta n) => max (max (kappa b) (kappa s)) (kappa n) + 1
| .recDelta b s n          => max (max (kappa b) (kappa s)) (kappa n)
```

The `+1` is intended to measure the depth of the `delta`-encoded natural number in the third argument. However, `kappa (delta t) = kappa t` means `kappa` sees through `delta` wrappers. So for a term like `recDelta b s (delta (delta (delta void)))`, the pattern match peels only the outermost `delta`, then `kappa n` (where `n = delta (delta void)`) flattens the remaining two `delta`s to `0`, yielding `max ... 0 + 1 = 1` instead of the intended `3`.

A correct measure for the third argument would need to explicitly count `delta` depth, e.g.:

```lean
def deltaDepth : Trace → Nat
| .delta t => deltaDepth t + 1
| _        => 0
```

and incorporate that count into `kappa` for `recDelta`, rather than relying on a single pattern-match layer.
