The helper strategy is **unsound**. Both theorems fail for specific inputs due to structural mismatches in the `kappa` definition. Below is the precise analysis:

### 1. `kappa_rec_delta_step` is false
**Claimed equality**:  
`kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`  
**Counterexample**: Let `n = delta void` (any `n` starting with `delta` suffices).  
- **LHS**: `kappa (recDelta b s (delta (delta void)))`  
  Matches `.recDelta _ _ (.delta _)` clause →  
  `max(max(κb, κs), κ(delta void)) + 1 = max(max(κb, κs), κ(void)) + 1 = M + 1`  
  (where `M = max(max(κb, κs), 0)`, and `κ(void)=0`, `κ(delta void)=κ(void)=0` by simp lemmas).  
- **RHS**: `kappa (recDelta b s (delta void)) + 1`  
  `recDelta b s (delta void)` *also* matches `.recDelta _ _ (.delta _)` clause →  
  `[max(max(κb, κs), κ(void)) + 1] + 1 = (M + 1) + 1 = M + 2`.  
**Result**: `M + 1 ≠ M + 2`. Equality fails.  
**Root cause**: The RHS `kappa (recDelta b s n)` depends on `n`'s structure. When `n` itself is `delta _`, the `.recDelta _ _ (.delta _)` clause applies *again*, adding an extra `+1` not accounted for in the theorem statement.

### 2. `kappa_rec_succ_drop` is false (and relies on unsound premise)
**Claimed inequality**:  
`kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`  
**Counterexample**: Same `n = delta void`.  
- **LHS**: `kappa (app s (recDelta b s (delta void)))`  
  `= max(κs, κ(recDelta b s (delta void)))`  
  `= max(κs, [max(max(κb, κs), κ(void)) + 1])` (by `.recDelta _ _ (.delta _)` clause)  
  `= max(κs, M + 1) = M + 1` (since `M ≥ κs`).  
- **RHS**: `kappa (recDelta b s (delta (delta void)))`  
  `= max(max(κb, κs), κ(delta void)) + 1 = M + 1` (as in LHS calculation above).  
**Result**: `M + 1 < M + 1` is false.  
**Additional flaw**: The proof attempts `rw [kappa_rec_delta_step]`, which is invalid (as shown above). Even without this rewrite, the inequality fails structurally when `n` contains `delta`.

### Why this breaks termination
The rewrite rule `R_rec_succ`:  
`recDelta b s (delta n) ↦ app s (recDelta b s n)`  
requires `κ(lhs) > κ(rhs)` for termination. However:  
- When `n` has outer `delta`, `κ(recDelta b s n)` *inherits* the `+1` from `n`'s structure.  
- This causes `κ(rhs) = max(κs, κ(recDelta b s n))` to reach `M + 1`, matching `κ(lhs) = M + 1`.  
- **No strict decrease occurs**, violating the core requirement for a termination measure.  

### Conclusion
The theorems are **mathematically incorrect** for traces where `n` begins with `delta`. The `kappa` definition's conditional `+1` (triggered solely by the *outermost* constructor of the third argument to `recDelta`) is insufficient to guarantee decrease under `R_rec_succ`, as nested `delta` constructors propagate measure increases into the recursive call. The helper strategy cannot support a termination proof for the given rewrite system. A lexicographic measure or structural recursion depth counter would be necessary instead.
