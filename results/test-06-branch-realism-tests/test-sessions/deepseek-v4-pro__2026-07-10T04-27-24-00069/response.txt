The helper strategy is **unsound** as written. The first theorem, `kappa_rec_delta_step`, is false for general `n : Trace`.

### Counterexample to `kappa_rec_delta_step`
Take any `b, s : Trace` and let `n := delta m` for some `m`. Compute both sides:

- **LHS**  
  `kappa (recDelta b s (delta n))`  
  = `kappa (recDelta b s (delta (delta m)))`  
  By the definition of `kappa` (first `recDelta` clause):  
  = `Nat.max (Nat.max (kappa b) (kappa s)) (kappa (delta m)) + 1`  
  Since `kappa (delta m) = kappa m`:  
  = `(max (max (kappa b) (kappa s)) (kappa m)) + 1`

- **RHS**  
  `kappa (recDelta b s n) + 1`  
  = `kappa (recDelta b s (delta m)) + 1`  
  By the first `recDelta` clause again:  
  = `(Nat.max (Nat.max (kappa b) (kappa s)) (kappa m) + 1) + 1`  
  = `(max …) + 2`

Hence LHS = `M + 1` and RHS = `M + 2` (where `M = max (max (kappa b) (kappa s)) (kappa m)`), so equality fails for every such `n`. Therefore `kappa_rec_delta_step` is not provable.

Because the second theorem `kappa_rec_succ_drop` rewrites with the false equality, it is also unjustified (and even under a corrected hypothesis the inequality `max (kappa s) (kappa (recDelta b s n)) < kappa (recDelta b s n) + 1` does not hold in general). The entire helper pair is unsound.
