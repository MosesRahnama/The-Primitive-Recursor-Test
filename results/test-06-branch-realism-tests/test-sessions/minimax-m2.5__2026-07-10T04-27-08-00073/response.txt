**Short answer:**  
Yes. Both statements are true for every `b s n : Trace`. They follow directly from the definition of `kappa` and from elementary properties of `Nat.max` and addition. The “helper strategy’’ is therefore sound; the two lemmas can be proved outright (the `sorry` placeholders are unnecessary).

---

### 1.  What the two lemmas say

```lean
theorem kappa_rec_delta_step (b s n : Trace) :
  kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1 := ...

theorem kappa_rec_succ_drop (b s n : Trace) :
  kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n)) := ...
```

The first lemma relates the measure of a `recDelta` whose third argument is wrapped in `delta` to the measure of the same `recDelta` with the unwrapped argument.  
The second lemma is exactly the inequality needed to show that the rewrite rule  

```
recDelta b s (delta n)  ⟶  app s (recDelta b s n)
```

decreases the measure `kappa`.

---

### 2.  Verification of `kappa_rec_delta_step`

By definition of `kappa` we have, for **any** traces `b, s, n`:

*If the third argument is `delta n`*  

```
kappa (recDelta b s (delta n))
   = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1      (1)
```

*If the third argument is just `n`*  

```
kappa (recDelta b s n)
   = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)          (2)
```

Subtracting (2) from (1) yields the claimed equality:

```
kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1 .
```

No extra hypothesis on `n` is required; the definition of `kappa` already treats the two cases exhaustively.

---

### 3.  Verification of `kappa_rec_succ_drop`

Write  

```
A := kappa b
S := kappa s
N := kappa n
M := Nat.max A S          -- the common “max‑b‑s’’ part
```

Then using the definitions of `kappa` for `app` and for `recDelta`:

```
kappa (app s (recDelta b s n))
   = Nat.max (kappa s) (kappa (recDelta b s n))
   = Nat.max S (Nat.max M N)                         (by (2))
   = Nat.max M N                                    (because S ≤ max M N)
   = max A S N                                       (definition of M)

kappa (recDelta b s (delta n))
   = Nat.max M N + 1                                 (by (1))
   = max A S N + 1 .
```

Hence  

```
kappa (app s (recDelta b s n)) = max A S N
                              < max A S N + 1
                              = kappa (recDelta b s (delta n)).
```

Since all three quantities are natural numbers, the strict inequality holds for **every** `b, s, n`.  

---

### 4.  Consequences for the termination argument

The rewrite rule `R_rec_succ` is the only one that can increase the size of the term (it moves from `recDelta b s (delta n)` to `app s (recDelta b s n)`).  
The lemma `kappa_rec_succ_drop` shows that even this “growth’’ step strictly *decreases* the measure `kappa`.  

Therefore, if one can also show that every other step of the relation `Step` does not increase `kappa` (the usual way is to prove a suite of similar inequalities for the remaining constructors), the overall rewrite system is terminating. The two lemmas above are **exactly** the needed pieces for the `recDelta` case and they are provable, so the helper strategy is sound.

---

### 5.  A minor practical note

In the file the proofs are left as `sorry`. In fact both statements are provable *directly* from the definition of `kappa` (e.g. by `rw [kappa_rec_delta]` or by `simp only [kappa_rec_delta, kappa_app, kappa_rec]`). The `sorry` placeholders are merely scaffolding; the underlying mathematics is correct.

---

**Conclusion:**  
The two helper theorems are mathematically correct, follow straightforwardly from the definition of `kappa`, and correctly capture the required decrease of the measure for the `recDelta` rewrite rule. Consequently the helper strategy is sound. (The full termination proof will also need analogous checks for the other rewrite rules, but those are orthogonal to the soundness of the two lemmas shown here.)
