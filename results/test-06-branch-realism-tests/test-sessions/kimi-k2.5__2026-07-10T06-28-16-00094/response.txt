The helper strategy is **unsound** as written. Both theorems are false, and the measure `kappa` fails to strictly decrease for the rewrite rule `R_rec_succ` when the term `n` is itself a `delta`.

Here is the detailed analysis:

## 1. Theorem `kappa_rec_delta_step` is false

**Claim:** `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1` for all `b, s, n`.

**Counterexample:** Take `b = void`, `s = void`, and `n = delta void`.

Calculating the left-hand side:
- `kappa (recDelta void void (delta (delta void)))`
- Matches the first pattern (`.recDelta b s (.delta n)`) with the bound `n` being `delta void`
- Result: `Nat.max (Nat.max (kappa void) (kappa void)) (kappa (delta void)) + 1`
- `= Nat.max (Nat.max 0 0) (kappa void) + 1`  [since `kappa (delta void) = kappa void`]
- `= Nat.max 0 0 + 1 = 1`

Calculating the right-hand side:
- `kappa (recDelta void void (delta void)) + 1`
- Matches the first pattern with bound `n` being `void`
- Result: `(Nat.max (Nat.max 0 0) (kappa void) + 1) + 1`
- `= (0 + 1) + 1 = 2`

Since `1 ≠ 2`, the equality fails.

**General case:** The theorem holds when `n` is not of the form `delta t`, but fails when `n = delta t` for any `t`. In that case:
- LHS: `kappa (recDelta b s (delta (delta t))) = max(max(kappa b, kappa s), kappa t) + 1`
- RHS: `kappa (recDelta b s (delta t)) + 1 = (max(max(kappa b, kappa s), kappa t) + 1) + 1 = max(max(kappa b, kappa s), kappa t) + 2`

## 2. Theorem `kappa_rec_succ_drop` is false

**Claim:** `kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))` for all `b, s, n`.

**Counterexample:** Again take `b = void`, `s = void`, `n = delta void`.

Left-hand side:
- `kappa (app void (recDelta void void (delta void)))`
- `= Nat.max (kappa void) (kappa (recDelta void void (delta void)))`
- `= Nat.max 0 (max(max(0, 0), 0) + 1)`  [using the first pattern for recDelta]
- `= Nat.max 0 1 = 1`

Right-hand side:
- `kappa (recDelta void void (delta (delta void)))`
- As calculated above, this equals `1`.

The inequality `1 < 1` is false.

**General case:** When `n = delta m`:
- `kappa (recDelta b s (delta n)) = max(max(kappa b, kappa s), kappa m) + 1`
- `kappa (recDelta b s n) = kappa (recDelta b s (delta m)) = max(max(kappa b, kappa s), kappa m) + 1`
- Thus `kappa (app s (recDelta b s n)) = max(kappa s, max(max(kappa b, kappa s), kappa m) + 1) = max(max(kappa b, kappa s), kappa m) + 1` (since the max is at least `kappa s`)

The two sides are equal, not strictly decreasing.

## Conclusion

The measure `kappa` does not strictly decrease under the rewrite `R_rec_succ : Step (recDelta b s (delta n)) (app s (recDelta b s n))` when `n` is itself a `delta`. The strategy assumes that peeling off a `delta` from the third argument always reduces the measure by exactly 1, but this is only true if the subterm `n` is not a `delta`. When `n` is a nested `delta`, the measure of `recDelta b s (delta n)` equals the measure of `app s (recDelta b s n)`, causing the termination argument to fail.
