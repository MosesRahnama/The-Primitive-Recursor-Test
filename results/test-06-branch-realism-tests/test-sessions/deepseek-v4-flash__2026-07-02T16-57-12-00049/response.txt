The helper strategy embodied in the two lemmas is sound. Both statements are true by direct calculation using the definition of `kappa`.

**Lemma `kappa_rec_delta_step`**:  
- Left side: `kappa (recDelta b s (delta n))` matches the first `recDelta` clause, giving `Nat.max (Nat.max (kappa b) (kappa s)) (kappa (delta n)) + 1`. Using `kappa_delta`, this equals `Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1`.  
- Right side: `kappa (recDelta b s n) + 1` matches the second `recDelta` clause (since `n` is not necessarily a `delta`), yielding `(Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)) + 1`.  
The two sides are identical, so the equality holds.

**Lemma `kappa_rec_succ_drop`**:  
- Left side: `kappa (app s (recDelta b s n)) = Nat.max (kappa s) (kappa (recDelta b s n))`.  
  Let `M := Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)`. Then `kappa (recDelta b s n) = M`.  
  Since `M ≥ kappa s` (because `M ≥ Nat.max (kappa b) (kappa s) ≥ kappa s`), we have `Nat.max (kappa s) M = M`.  
  So the left side equals `M`.  
- Right side: `kappa (recDelta b s (delta n)) = M + 1` by the first lemma.  
Thus the inequality becomes `M < M + 1`, which is true for any natural number `M`.

Both lemmas are therefore valid, and the termination argument that relies on them can be justified.
