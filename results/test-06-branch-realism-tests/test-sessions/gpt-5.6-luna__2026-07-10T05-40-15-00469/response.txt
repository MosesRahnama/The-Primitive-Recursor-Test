The helper strategy is not sound as written. Both theorem statements are false for some inputs.

Take

```lean
b := void
s := void
n := delta void
```

Since `kappa void = 0` and `kappa (delta void) = 0`, we have

```lean
kappa (recDelta void void (delta (delta void))) = 1
```

because the third argument is an outer `delta`.

But also

```lean
kappa (recDelta void void (delta void)) = 1
```

for the same reason. Therefore `kappa_rec_delta_step` would assert

```lean
1 = 1 + 1
```

which is false.

The second theorem fails on the same instance:

```lean
kappa (app void (recDelta void void (delta void)))
  = Nat.max 0 1
  = 1
```

while

```lean
kappa (recDelta void void (delta (delta void))) = 1.
```

Thus it would assert

```lean
1 < 1
```

which is also false.

The issue is that `kappa` adds `1` whenever the third argument of `recDelta` has the form `delta n`. If `n` itself is already a `delta`, then both

```lean
recDelta b s (delta n)
```

and

```lean
recDelta b s n
```

receive the extra `+1`; the proposed equality incorrectly adds another `1` on the right-hand side. Consequently, the `rw [kappa_rec_delta_step]` proof cannot establish a valid theorem.
