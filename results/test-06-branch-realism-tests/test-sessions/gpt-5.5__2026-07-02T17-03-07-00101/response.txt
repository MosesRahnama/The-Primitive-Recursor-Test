The helper strategy is **not sound as written**.

The main problem is this claimed theorem:

```lean
theorem kappa_rec_delta_step (b s n : Trace) :
  kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1 := by
  sorry
```

This is not true for all `n`.

Let

```lean
A = Nat.max (kappa b) (kappa s)
```

By definition,

```lean
kappa (recDelta b s (delta n)) =
  Nat.max A (kappa n) + 1
```

But `kappa (recDelta b s n)` depends on the syntactic shape of `n`.

If `n` is not of the form `delta m`, then indeed:

```lean
kappa (recDelta b s n) = Nat.max A (kappa n)
```

so the claimed equality holds.

However, if `n = delta m`, then:

```lean
kappa (recDelta b s n)
= kappa (recDelta b s (delta m))
= Nat.max A (kappa m) + 1
```

and since

```lean
kappa (delta m) = kappa m
```

we get:

```lean
kappa (recDelta b s (delta n))
= kappa (recDelta b s (delta (delta m)))
= Nat.max A (kappa m) + 1
```

whereas

```lean
kappa (recDelta b s n) + 1
= kappa (recDelta b s (delta m)) + 1
= Nat.max A (kappa m) + 2
```

So the theorem would assert:

```lean
Nat.max A (kappa m) + 1 = Nat.max A (kappa m) + 2
```

which is false.

A concrete counterexample is:

```lean
b = void
s = void
n = delta void
```

Then:

```lean
kappa (recDelta void void (delta (delta void)))
= Nat.max (Nat.max 0 0) 0 + 1
= 1
```

but:

```lean
kappa (recDelta void void (delta void)) + 1
= 1 + 1
= 2
```

So the claimed equality becomes:

```lean
1 = 2
```

which is impossible.

The second helper theorem is also false:

```lean
theorem kappa_rec_succ_drop (b s n : Trace) :
  kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n)) := by
  rw [kappa_rec_delta_step]
  sorry
```

Using the same counterexample:

```lean
b = void
s = void
n = delta void
```

Compute the left-hand side:

```lean
kappa (app void (recDelta void void (delta void)))
= Nat.max (kappa void) (kappa (recDelta void void (delta void)))
= Nat.max 0 1
= 1
```

Compute the right-hand side:

```lean
kappa (recDelta void void (delta (delta void)))
= 1
```

So the theorem claims:

```lean
1 < 1
```

which is false.

Therefore the proposed helper strategy does not establish a genuine decrease for the `R_rec_succ` rule. The issue is that `kappa` only adds `1` when the third argument of `recDelta` is immediately a `delta`, but nested `delta`s are ignored by `kappa` because:

```lean
kappa (delta t) = kappa t
```

Thus unfolding

```lean
recDelta b s (delta n) ↦ app s (recDelta b s n)
```

does not strictly decrease `kappa` when `n` itself is another `delta`.

So, as written, the helper theorems are mathematically invalid; the `sorry`s are hiding false statements.
