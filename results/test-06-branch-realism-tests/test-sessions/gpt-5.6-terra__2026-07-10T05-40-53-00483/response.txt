The helper strategy is not sound as written. Both helper theorems are false because `kappa` treats a `recDelta` whose third argument is syntactically a `delta _` specially, and that special case can occur again inside `n`.

Let

\[
B = \max(\kappa b)(\kappa s).
\]

Then:

- For any `n`,

\[
\kappa(\mathrm{recDelta}\ b\ s\ (\delta n))
= \max(B,\kappa n)+1.
\]

- But `kappa (recDelta b s n)` depends on whether `n` itself is a `delta`.

If `n = delta m`, then

\[
\kappa(\mathrm{recDelta}\ b\ s\ n)
=
\kappa(\mathrm{recDelta}\ b\ s\ (\delta m))
=
\max(B,\kappa m)+1.
\]

Meanwhile,

\[
\kappa(\mathrm{recDelta}\ b\ s\ (\delta n))
=
\kappa(\mathrm{recDelta}\ b\ s\ (\delta(\delta m)))
=
\max(B,\kappa m)+1.
\]

So in this case the two source terms have the same `kappa`, not values differing by one.

A concrete counterexample to `kappa_rec_delta_step` is:

```lean
b = void
s = void
n = delta void
```

Then:

\[
\kappa(\mathrm{recDelta}\ void\ void\ (\delta(\delta void))) = 1,
\]

while

\[
\kappa(\mathrm{recDelta}\ void\ void\ (\delta void)) + 1 = 1 + 1 = 2.
\]

Thus the claimed equality becomes \(1 = 2\).

The second theorem is false for the same example. Its left side is

\[
\begin{aligned}
&\kappa(\mathrm{app}\ void\ (\mathrm{recDelta}\ void\ void\ (\delta void)))\\
={}&\max(0,1)=1,
\end{aligned}
\]

and its right side is

\[
\kappa(\mathrm{recDelta}\ void\ void\ (\delta(\delta void)))=1.
\]

Hence the claimed strict inequality is \(1 < 1\), which is false.

More generally, for `n = delta m`,

\[
\kappa(\mathrm{app}\ s\ (\mathrm{recDelta}\ b\ s\ n))
=
\max(B,\kappa m)+1
=
\kappa(\mathrm{recDelta}\ b\ s\ (\delta n)).
\]

Therefore the `R_rec_succ` rewrite does not strictly decrease this `kappa` whenever its predecessor `n` is itself a `delta _`. The proposed first helper lemma would conceal that issue by asserting an invalid equality, so it cannot support a valid termination argument.
