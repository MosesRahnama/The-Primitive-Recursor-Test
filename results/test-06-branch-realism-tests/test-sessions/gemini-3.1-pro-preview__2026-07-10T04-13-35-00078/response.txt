The helper strategy is **unsound**. Both theorems, `kappa_rec_delta_step` and `kappa_rec_succ_drop`, are logically false as stated. 

The underlying problem stems from how `kappa` evaluates `delta` constructors. The measure `kappa` skips over `.delta` constructors entirely via `kappa (.delta t) = kappa t`. However, it explicitly adds `1` for the *outermost* `.delta` wrapped in a `.recDelta` via the rule:
`| .recDelta b s (.delta n) => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1`

As a result, deeply nested `.delta`s do not continuously increase the measure, leading to contradictions when induction attempts to peel them off.

### Counterexample & Calculations

Let's test both theorems with the following assignment:
`b = void`
`s = void`
`n = delta void`

First, let's establish a few base evaluations for `kappa` using its definition:
* `kappa void = 0`
* `kappa (delta void) = kappa void = 0`
* `kappa (recDelta void void (delta void))` matches the first `recDelta` rule (where the inner term is `delta void`, so the pattern variable `n` is bound to `void`):
  $= \max(\max(\text{kappa void}, \text{kappa void}), \text{kappa void}) + 1$
  $= \max(\max(0, 0), 0) + 1 = 1$

#### 1. Falsifying `kappa_rec_delta_step`
The theorem claims: `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

**Left-Hand Side (LHS):**
`kappa (recDelta void void (delta (delta void)))`
This matches the first `recDelta` rule. The pattern variable `n` binds to `delta void`.
$= \max(\max(\text{kappa void}, \text{kappa void}), \text{kappa (delta void)}) + 1$
$= \max(0, 0) + 1 = 1$

**Right-Hand Side (RHS):**
`kappa (recDelta void void (delta void)) + 1`
From our base evaluations, the `kappa` term evaluates to `1`.
$= 1 + 1 = 2$

Since $1 \neq 2$, `kappa_rec_delta_step` is false.

#### 2. Falsifying `kappa_rec_succ_drop`
The theorem claims: `kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`

**Left-Hand Side (LHS):**
`kappa (app void (recDelta void void (delta void)))`
According to the `.app` rule:
$= \max(\text{kappa void}, \text{kappa (recDelta void void (delta void))})$
$= \max(0, 1) = 1$

**Right-Hand Side (RHS):**
`kappa (recDelta void void (delta (delta void)))`
As evaluated in the LHS of the previous theorem, this equals `1`.

Since $1 < 1$ is False, `kappa_rec_succ_drop` is also false.

### Conclusion
Because `kappa (recDelta b s (delta (delta t)))` produces the exact same integer measure as `kappa (recDelta b s (delta t))`, the structural measure `kappa` fails to strictly decrease across `R_rec_succ` steps when nested `.delta`s are involved. Therefore, the stated termination measure and the helper theorems are unsound.
