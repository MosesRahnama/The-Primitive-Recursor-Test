No — the helper strategy is not sound as written.

### Core issue

The problem is the interaction between:

- `kappa (delta t) = kappa t`, but
- `kappa (recDelta b s (delta n)) = ... + 1`.

So `kappa` ignores how many nested `delta`s a term has, while `recDelta` adds `+1` whenever its third argument is *syntactically* `delta _`.

That mismatch makes the two helper theorems false in general.

---

## 1. `kappa_rec_delta_step` is false

Let

\[
M := \max(\max(\kappa b,\kappa s),\kappa n).
\]

Then by definition,

\[
\kappa(\mathrm{recDelta}\ b\ s\ (\delta n)) = M + 1.
\]

But `kappa (recDelta b s n)` depends on whether `n` itself is of the form `delta _`:

- if `n` is **not** `delta _`, then  
  \[
  \kappa(\mathrm{recDelta}\ b\ s\ n) = M,
  \]
  so the theorem would hold;

- if `n = delta m`, then since `kappa (delta m) = kappa m`,
  \[
  \kappa(\mathrm{recDelta}\ b\ s\ n)
  = \kappa(\mathrm{recDelta}\ b\ s\ (\delta m))
  = M + 1,
  \]
  so the theorem would claim
  \[
  M+1 = (M+1)+1,
  \]
  which is impossible.

### Concrete counterexample

Take:

- `b = void`
- `s = void`
- `n = delta void`

Then:

- `kappa void = 0`
- `kappa (delta void) = 0`

So:

\[
\kappa(\mathrm{recDelta}\ \mathrm{void}\ \mathrm{void}\ (\delta(\delta\ \mathrm{void}))) = 1
\]

but

\[
\kappa(\mathrm{recDelta}\ \mathrm{void}\ \mathrm{void}\ (\delta\ \mathrm{void})) + 1 = 1 + 1 = 2.
\]

So the theorem asserts `1 = 2`.

---

## 2. `kappa_rec_succ_drop` is also false

The theorem states:

\[
\kappa(\mathrm{app}\ s\ (\mathrm{recDelta}\ b\ s\ n))
< \kappa(\mathrm{recDelta}\ b\ s\ (\delta n)).
\]

But note that `kappa (recDelta b s n) ≥ kappa s`, so

\[
\kappa(\mathrm{app}\ s\ (\mathrm{recDelta}\ b\ s\ n))
= \max(\kappa s,\kappa(\mathrm{recDelta}\ b\ s\ n))
= \kappa(\mathrm{recDelta}\ b\ s\ n).
\]

So the theorem reduces to

\[
\kappa(\mathrm{recDelta}\ b\ s\ n)
< \kappa(\mathrm{recDelta}\ b\ s\ (\delta n)).
\]

And from the previous analysis, that is false whenever `n = delta m`, because then both sides are equal.

### Same counterexample

Take again:

- `b = void`
- `s = void`
- `n = delta void`

Then:

\[
\kappa(\mathrm{app}\ \mathrm{void}\ (\mathrm{recDelta}\ \mathrm{void}\ \mathrm{void}\ (\delta\ \mathrm{void})))
= \max(0,1)=1
\]

and

\[
\kappa(\mathrm{recDelta}\ \mathrm{void}\ \mathrm{void}\ (\delta(\delta\ \mathrm{void}))) = 1.
\]

So the theorem asserts `1 < 1`, which is false.

---

## 3. What this means for the termination idea

The intended idea seems to be:

- use `kappa_rec_delta_step` to show the `recDelta` argument drops by 1,
- then use `kappa_rec_succ_drop` to show the `R_rec_succ` rewrite decreases `kappa`.

That does **not** work as stated, because the decrease fails exactly when the recursive argument is already `delta`-headed.

In other words, for the rule

```lean
Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

the measure behaves as follows:

- if `n` is not `delta _`, source has measure `M+1` and target has measure `M`, so it decreases;
- if `n = delta m`, source and target both have measure `M+1`, so it does **not** decrease.

So `kappa` is not a strict descent measure for `R_rec_succ` on all terms.

---

## 4. Broader warning: `kappa` is not strictly decreasing for several rules anyway

Even beyond the two helper lemmas, `kappa` does not strictly drop across many `Step` rules:

- `R_merge_void_left`:
  \[
  \kappa(\mathrm{merge}\ \mathrm{void}\ t)=\max(0,\kappa t)=\kappa t
  \]
- `R_merge_void_right`:
  same
- `R_merge_cancel`:
  \[
  \kappa(\mathrm{merge}\ t\ t)=\kappa t
  \]
- `R_eq_diff`:
  \[
  \kappa(\mathrm{eqW}\ a\ b)=\max(\kappa a,\kappa b)
  = \kappa(\mathrm{integrate}(\mathrm{merge}\ a\ b))
  \]

So even a repaired `recDelta` lemma would not make `kappa` a global strict ranking function for all `Step`s.

---

## Conclusion

The helper strategy is **unsound as written**.

- `kappa_rec_delta_step` is false.
- `kappa_rec_succ_drop` is false.
- The failure occurs whenever `n` itself is of the form `delta _`.
- More broadly, `kappa` is not a strictly decreasing measure for several rewrite rules anyway.

So these lemmas cannot support a valid strict-`kappa` termination argument in the current file.
