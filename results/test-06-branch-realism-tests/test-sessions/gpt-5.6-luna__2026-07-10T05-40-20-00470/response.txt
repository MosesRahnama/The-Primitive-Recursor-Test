The helper strategy is not sound as written. Both theorems are false for some arguments because `kappa` distinguishes syntactically between a third argument of the form `delta n` and one that is merely equal in measure to such a term.

Take

```lean
b := void
s := void
n := delta void
```

Since `kappa void = 0` and `kappa (delta void) = 0`, we have:

```text
kappa (recDelta void void (delta (delta void)))
  = max (max 0 0) (kappa (delta void)) + 1
  = 1
```

But

```text
kappa (recDelta void void (delta void)) + 1
  = (max (max 0 0) (kappa void) + 1) + 1
  = 2
```

Therefore `kappa_rec_delta_step` asserts `1 = 2` in this instance, so it is false.

The second theorem also fails for the same instance:

```text
kappa (app void (recDelta void void (delta void)))
  = max 0 (kappa (recDelta void void (delta void)))
  = max 0 1
  = 1
```

while

```text
kappa (recDelta void void (delta (delta void))) = 1.
```

Thus it would require `1 < 1`, which is false.

The issue is that when `n = delta m`, both

```lean
recDelta b s n
```

and

```lean
recDelta b s (delta n)
```

match the special `delta` equation of `kappa`, while the latter does not gain an additional measure increment relative to the former. In general, for `n = delta m`,

```text
kappa (recDelta b s (delta n))
= max A (kappa m) + 1
= kappa (recDelta b s n),
```

where `A = max (kappa b) (kappa s)`. Consequently the proposed successor step need not decrease `kappa`.

If `n` is not itself syntactically a `delta`, the displayed equalities behave as intended, but the theorems quantify over arbitrary `n`. Hence the `sorry`s cannot be filled with valid proofs for the stated definitions.
