# Assessment: The Helper Strategy is **Unsound**

Both helper theorems are false as stated. The root cause is that `kappa (delta t) = kappa t` makes the measure blind to nested `delta` constructors, which breaks the intended arithmetic.

---

## Concrete Counterexample

Let `b = void`, `s = void`, `n = delta void`. We need a few base evaluations:

| Expression | Value |
|---|---|
| `kappa void` | `0` |
| `kappa (delta void)` | `kappa void = 0` |
| `kappa (delta (delta void))` | `kappa (delta void) = 0` |

### Evaluating `recDelta` terms

**`kappa (recDelta void void (delta void))`** — matches the first clause (`.delta n` with `n := void`):
$$\max(\max(0, 0), 0) + 1 = 1$$

**`kappa (recDelta void void (delta (delta void)))`** — matches the first clause (`.delta n` with `n := delta void`):
$$\max(\max(0, 0), \kappa(\delta\;\text{void})) + 1 = \max(0, 0) + 1 = 1$$

---

## Theorem 1: `kappa_rec_delta_step` is false

```
kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

Instantiating with `b = void, s = void, n = delta void`:

- **LHS:** `kappa (recDelta void void (delta (delta void)))` = **1**
- **RHS:** `kappa (recDelta void void (delta void)) + 1` = `1 + 1` = **2**

**1 ≠ 2**, so the theorem is false. The issue: when `n` is itself `delta n'`, the LHS pattern-matches `n = delta n'` and uses `kappa (delta n') = kappa n'`, while the RHS evaluates `kappa (recDelta b s (delta n'))` which already includes the `+1` bonus—resulting in a *double* `+1` on the RHS that the LHS doesn't match.

---

## Theorem 2: `kappa_rec_succ_drop` is false

```
kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
```

Same instantiation (`b = void, s = void, n = delta void`):

- **LHS:** `kappa (app void (recDelta void void (delta void)))` = `max(0, 1)` = **1**
- **RHS:** `kappa (recDelta void void (delta (delta void)))` = **1**

**1 < 1** is false. The measure does *not* strictly decrease for `R_rec_succ` when the third argument is a nested `delta`.

The proof attempt `rw [kappa_rec_delta_step]` rewrites the RHS using the (false) Theorem 1, producing the subgoal `kappa (app s (recDelta b s n)) < kappa (recDelta b s n) + 1`. While this subgoal happens to be true, the rewrite itself is invalid because it relies on a false lemma.

---

## Root Cause

The definition `kappa (delta t) = kappa t` erases the structural depth of `delta` nesting. The `+1` in the `recDelta` clause is keyed on `kappa n`, which is invariant under adding or removing `delta` wrappers. Consequently:

$$\kappa(\text{recDelta}\;b\;s\;(\delta^k\;t)) = \max(\max(\kappa\;b, \kappa\;s), \kappa\;t) + 1 \quad \text{for all } k \geq 1$$

Every nested `delta` beyond the first is invisible to the measure, so peeling one off via `R_rec_succ` does not guarantee a strict decrease.
