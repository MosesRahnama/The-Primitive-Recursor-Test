The helper strategy is not sound: both theorems are false for arbitrary `n`.

The issue is that `kappa` treats `delta` as transparent:

\[
\kappa(\delta t)=\kappa(t),
\]

but the `recDelta` equation adds `1` based on whether its third argument is syntactically a `delta`, not merely on its `kappa` value.

Take

```lean
b := void
s := void
n := delta void
```

Then:

\[
\kappa(\delta void)=0.
\]

For the first theorem, the left-hand side is

\[
\begin{aligned}
\kappa(\operatorname{recDelta}\ void\ void\ (\delta(\delta void)))
&= \max(\max(0,0),\kappa(\delta void))+1 \\
&= \max(0,0)+1 \\
&=1.
\end{aligned}
\]

The right-hand side is

\[
\begin{aligned}
\kappa(\operatorname{recDelta}\ void\ void\ (\delta void))+1
&=(\max(\max(0,0),\kappa(void))+1)+1\\
&=(0+1)+1\\
&=2.
\end{aligned}
\]

Thus `kappa_rec_delta_step` asserts `1 = 2` in this case, so it is false.

The second theorem also fails with the same choice:

\[
\begin{aligned}
\kappa(\operatorname{app}\ void\ (\operatorname{recDelta}\ void\ void\ (\delta void)))
&=\max(0,1)=1,\\
\kappa(\operatorname{recDelta}\ void\ void\ (\delta(\delta void)))
&=1.
\end{aligned}
\]

Consequently, it asserts

\[
1<1,
\]

which is false.

The first theorem would hold when `n` is not syntactically a `delta`, but it fails when `n` itself has the form `delta n'`. In that latter case, both `recDelta ... n` and `recDelta ... (delta n)` receive the extra `+1`, so the proposed “step” equality and strict decrease do not follow.
