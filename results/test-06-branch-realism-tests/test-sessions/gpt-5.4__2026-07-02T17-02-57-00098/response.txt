The helper strategy is not sound as written.

The key issue is the first helper theorem:

```lean
theorem kappa_rec_delta_step (b s n : Trace) :
  kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

This is false in general.

## Why it fails

Let

- \(B = \kappa b\)
- \(S = \kappa s\)
- \(N = \kappa n\)

Then by definition:

- `kappa (recDelta b s (delta n)) = max (max B S) N + 1`
- `kappa (recDelta b s n)` depends on the shape of `n`

The problem is that `kappa (recDelta b s n)` is **not** always `max (max B S) N`.

If `n` itself is a `delta m`, then the special `recDelta` clause fires again:

```lean
kappa (recDelta b s (delta m)) = max (max B S) (kappa m) + 1
```

and since `kappa (delta m) = kappa m`, we have \(N = \kappa n = \kappa m\). So in that case:

- `kappa (recDelta b s n) = max (max B S) N + 1`

hence

- RHS of the theorem becomes `max (max B S) N + 2`
- LHS is `max (max B S) N + 1`

so they are not equal.

## Concrete counterexample

Take

- `b = void`
- `s = void`
- `n = delta void`

Then:

- `kappa b = 0`
- `kappa s = 0`
- `kappa n = kappa (delta void) = 0`

Compute both sides.

### Left side
```lean
kappa (recDelta void void (delta (delta void)))
= max (max 0 0) (kappa (delta void)) + 1
= max 0 0 + 1
= 1
```

### Right side
```lean
kappa (recDelta void void (delta void)) + 1
= (max (max 0 0) (kappa void) + 1) + 1
= (0 + 1) + 1
= 2
```

So the claimed equality says `1 = 2`, impossible.

---

## Consequence for the second helper theorem

The second theorem is:

```lean
theorem kappa_rec_succ_drop (b s n : Trace) :
  kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n)) := by
  rw [kappa_rec_delta_step]
  sorry
```

Because it relies on rewriting by the false theorem `kappa_rec_delta_step`, the strategy is unsound.

In fact, the second theorem itself is also false in general.

## Check the inequality directly

Let again

- \(B = \kappa b\)
- \(S = \kappa s\)
- \(N = \kappa n\)

Then

```lean
kappa (app s (recDelta b s n)) = max S (kappa (recDelta b s n))
```

and

```lean
kappa (recDelta b s (delta n)) = max (max B S) N + 1
```

If `n` is **not** of the form `delta _`, then
`kappa (recDelta b s n) = max (max B S) N`, so

- LHS = `max S (max (max B S) N)` = `max (max B S) N`
- RHS = that quantity `+ 1`

and the inequality holds.

But if `n = delta m`, then

- `kappa (recDelta b s n) = max (max B S) (kappa m) + 1`
- and since `kappa n = kappa m`, RHS is also `max (max B S) (kappa m) + 1`

Thus

```lean
kappa (app s (recDelta b s n))
= max S (M + 1)
= M + 1
```

where \(M = max (max B S) (kappa m)\), because \(S \le M+1\).

And

```lean
kappa (recDelta b s (delta n)) = M + 1
```

So in this case the two sides are equal, not strict.

## Concrete counterexample to the second theorem

Again take `b = void`, `s = void`, `n = delta void`.

Then:

### Left side
```lean
kappa (app void (recDelta void void (delta void)))
= max 0 (kappa (recDelta void void (delta void)))
= max 0 1
= 1
```

### Right side
```lean
kappa (recDelta void void (delta (delta void)))
= 1
```

So the theorem claims `1 < 1`, false.

---

## Final assessment

The helper strategy is unsound as written because:

1. `kappa_rec_delta_step` is false in general.
2. `kappa_rec_succ_drop` depends on it.
3. `kappa_rec_succ_drop` is itself false in general.

The underlying reason is that `kappa` gives an extra `+1` whenever the third argument of `recDelta` is syntactically a `delta _`, so nested `delta` structure in `n` causes `kappa (recDelta b s n)` to already include that increment. Therefore passing from `n` to `delta n` does **not** always increase `kappa` by one relative to `kappa (recDelta b s n)`.
