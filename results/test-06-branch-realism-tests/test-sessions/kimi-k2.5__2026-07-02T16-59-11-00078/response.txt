The helper strategy is **unsound** as written. Both theorems are false when the parameter `n` is itself constructed with the `delta` constructor.

Here is the detailed analysis:

### 1. Failure of `kappa_rec_delta_step`

The theorem claims:
```lean
kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

**Calculation:**
- By definition, the LHS equals: `Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1`
- For the RHS, we must consider the structure of `n`:
  - **If `n` is not a `delta`:** `kappa (recDelta b s n) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)`, so the equation holds.
  - **If `n = delta m` for some `m`:** 
    - `kappa (recDelta b s n) = kappa (recDelta b s (delta m)) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa m) + 1`
    - RHS becomes: `(Nat.max (Nat.max (kappa b) (kappa s)) (kappa m) + 1) + 1 = X + 2`
    - LHS becomes: `Nat.max (Nat.max (kappa b) (kappa s)) (kappa (delta m)) + 1 = Nat.max (Nat.max (kappa b) (kappa s)) (kappa m) + 1 = X + 1`
    - Where `X = Nat.max (Nat.max (kappa b) (kappa s)) (kappa m)`.
    - **Result:** `X + 1 = X + 2` is false.

**Counterexample:** Take `b = void`, `s = void`, `n = delta void`.
- LHS: `kappa (recDelta void void (delta (delta void))) = max(max(0,0),0) + 1 = 1`
- RHS: `kappa (recDelta void void (delta void)) + 1 = (max(max(0,0),0) + 1) + 1 = 2`

### 2. Failure of `kappa_rec_succ_drop`

The theorem claims:
```lean
kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
```

This is intended to show that the `R_rec_succ` step (rewriting `recDelta b s (delta n)` to `app s (recDelta b s n)`) decreases the measure.

**Calculation:**
- RHS = `Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1`
- LHS = `Nat.max (kappa s) (kappa (recDelta b s n))`

When `n = delta m`:
- `kappa (recDelta b s n) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa m) + 1`
- Since `Nat.max (Nat.max (kappa b) (kappa s)) (kappa m) ≥ kappa s`, we have:
  - LHS = `Nat.max (kappa s) (Y + 1) = Y + 1` where `Y = Nat.max (Nat.max (kappa b) (kappa s)) (kappa m)`
- RHS = `Nat.max (Nat.max (kappa b) (kappa s)) (kappa (delta m)) + 1 = Y + 1`

**Result:** LHS = RHS, so the strict inequality `<` is false.

**Counterexample:** Take `b = void`, `s = void`, `n = delta void`.
- LHS: `kappa (app void (recDelta void void (delta void))) = max(0, (max(max(0,0),0)+1)) = 1`
- RHS: `kappa (recDelta void void (delta (delta void))) = max(max(0,0),0) + 1 = 1`
- We have `1 < 1` which is false.

### Conclusion

The strategy fails because `kappa` only adds 1 for the outermost `delta` in the third argument of `recDelta`. When `n` is already a `delta`, the recursive call `recDelta b s n` already includes a `+1` in its measure, causing the inequality to collapse to equality (or causing the equality in the first theorem to require `+2` instead of `+1`).

To make the strategy sound, the theorems would need to require that `n` is **not** of the form `delta m` (i.e., `n` represents the "zero" case in the inductive encoding), or the definition of `kappa` would need to be modified to accumulate the depth of nested `delta`s differently.
