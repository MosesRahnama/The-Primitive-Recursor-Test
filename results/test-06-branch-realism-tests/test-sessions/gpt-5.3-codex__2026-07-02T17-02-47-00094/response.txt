The helper strategy is **not sound as written** (at least not uniformly for all `b s n : Trace`), because the key strict inequality theorem is false in general.

## Why

You define:

- `kappa (app s (recDelta b s n)) = max (kappa s) (kappa (recDelta b s n))`
- `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1` (this one is actually true)

So the target theorem
\[
kappa(app\ s\ (recDelta\ b\ s\ n)) < kappa(recDelta\ b\ s\ (\delta n))
\]
becomes
\[
\max(\kappa s,\ \kappa(recDelta\ b\ s\ n)) < \kappa(recDelta\ b\ s\ n) + 1.
\]

This inequality holds **iff** `kappa s ≤ kappa(recDelta b s n)`, because:
- `kappa(recDelta b s n) < ... + 1` always true,
- but if `kappa s` is bigger than `kappa(recDelta b s n)+1`, max can exceed RHS.

And that bad case can happen.

## Concrete counterexample

Take:
- `b = void` so `kappa b = 0`
- `n = void` so `kappa n = 0`
- `s = recDelta void void (delta void)`

Then:
- `kappa s = kappa(recDelta void void (delta void)) = max(max 0 0) 0 + 1 = 1`.
- `kappa(recDelta b s n) = kappa(recDelta void s void) = max(max 0 1) 0 = 1`.
- So LHS:
  \[
  kappa(app\ s\ (recDelta\ b\ s\ n)) = max(1,1)=1.
  \]
- RHS:
  \[
  kappa(recDelta\ b\ s\ (\delta n)) = kappa(recDelta\ void\ s\ (\delta void))
  = max(max 0 1) 0 + 1 = 2.
  \]
This one still satisfies `<`. So push `s` higher:

Let  
`s = recDelta void (recDelta void void (delta void)) (delta void)`.

Compute:
- inner `recDelta void void (delta void)` has kappa `1`.
- hence `kappa s = max(max 0 1) 0 + 1 = 2`.
- with `b=void, n=void`:
  - `kappa(recDelta b s n)=max(max 0 2)0=2`,
  - LHS `=max(2,2)=2`,
  - RHS `=2+1=3` still fine.

So for this specific shape it keeps tying, not breaking. But the logical issue remains: from `max (kappa s) m < m+1` you need `kappa s ≤ m`, and your proof sketch (rewrite then `sorry`) does not provide that fact explicitly. In this setup, luckily `m = kappa(recDelta b s n)` is always at least `kappa s` (because `kappa recDelta ...` is a max including `kappa s`, with or without `+1`), so the inequality is actually true.

## Final assessment

- `kappa_rec_delta_step` is sound.
- `kappa_rec_succ_drop` is also mathematically true with this `kappa`.
- **But** the strategy as presented is incomplete: after rewriting by `kappa_rec_delta_step`, you still need a lemma like
  \[
  \kappa(app\ s\ (recDelta\ b\ s\ n)) \le \kappa(recDelta\ b\ s\ n),
  \]
  then conclude `< ... + 1`.

So the helper idea is on the right track, but as written it omits the essential monotonic/max bound needed to justify the strict inequality.
