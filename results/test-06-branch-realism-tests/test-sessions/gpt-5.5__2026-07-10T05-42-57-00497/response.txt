The helper strategy is **not sound as written**. Both intended helper theorems are false for some inputs, because `kappa` gives a `+ 1` bonus to `recDelta b s n` whenever the third argument is syntactically a `delta`.

Let

```lean
b = void
s = void
n = delta void
```

Then the first helper theorem claims:

```lean
kappa (recDelta void void (delta (delta void)))
=
kappa (recDelta void void (delta void)) + 1
```

But compute both sides.

For the left side:

```lean
kappa (recDelta void void (delta (delta void)))
= Nat.max (Nat.max 0 0) (kappa (delta void)) + 1
= Nat.max 0 0 + 1
= 1
```

For the right side:

```lean
kappa (recDelta void void (delta void)) + 1
= (Nat.max (Nat.max 0 0) (kappa void) + 1) + 1
= (0 + 1) + 1
= 2
```

So the theorem asserts:

```lean
1 = 2
```

which is false.

Therefore:

```lean
theorem kappa_rec_delta_step (b s n : Trace) :
  kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

is not valid in general. It is only valid when `n` itself is not syntactically a `delta`.

The second helper theorem is also false. With the same counterexample:

```lean
b = void
s = void
n = delta void
```

it claims:

```lean
kappa (app void (recDelta void void (delta void)))
<
kappa (recDelta void void (delta (delta void)))
```

Compute the left side:

```lean
kappa (app void (recDelta void void (delta void)))
= Nat.max (kappa void) (kappa (recDelta void void (delta void)))
= Nat.max 0 1
= 1
```

Compute the right side:

```lean
kappa (recDelta void void (delta (delta void)))
= 1
```

So the theorem claims:

```lean
1 < 1
```

which is false.

This means the proposed termination argument using this `kappa` measure cannot prove a strict decrease for the `R_rec_succ` rule in general. In particular, for nested deltas,

```lean
Step (recDelta b s (delta (delta m)))
     (app s (recDelta b s (delta m)))
```

the `kappa` value of the source and target can be equal rather than strictly decreasing.

So the helper strategy is unsound as written.
