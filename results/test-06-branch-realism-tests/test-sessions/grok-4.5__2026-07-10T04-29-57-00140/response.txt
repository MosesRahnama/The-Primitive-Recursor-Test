### Assessment

The helper strategy is **not sound**. Both helper theorems are false (as universal statements over all `b s n`), so they cannot support a termination argument based on strict decrease of `kappa` under `Step`. The rewrite in the second theorem is therefore also invalid in general. This is shown by direct calculation on the definition of `kappa` (no other files or evaluation needed).

#### Counterexample to `kappa_rec_delta_step`
Take `b = void`, `s = void` and `n = delta void`. Then:
- LHS = `kappa (recDelta void void (delta (delta void)))`
  - By the first `recDelta` equation of `kappa` (the one matching a `delta` argument):  
    `Nat.max (Nat.max (kappa void) (kappa void)) (kappa (delta void)) + 1`  
    = `Nat.max (Nat.max 0 0) 0 + 1`  
    = `1`.
- RHS = `kappa (recDelta void void (delta void)) + 1`
  - Inner term again by the first `recDelta` equation:  
    `Nat.max (Nat.max 0 0) (kappa void) + 1` = `1`,  
    so RHS = `1 + 1` = `2`.
- Thus `1 ≠ 2`.

(The equality holds only for those `n` that do not themselves match the pattern `delta _`; the catch-all equation of `kappa` then applies on the RHS and the two sides become identical. The statement as written quantifies over all `n`, so it is false.)

#### Counterexample to `kappa_rec_succ_drop`
The same values already give a counter-model (and the attempted proof via the first helper cannot succeed). Compute both sides of the desired strict inequality:
- RHS = `kappa (recDelta void void (delta (delta void)))` = `1` (identical calculation to the LHS above).
- LHS = `kappa (app void (recDelta void void (delta void)))`
  - By the `app` equation of `kappa`: `Nat.max (kappa void) (kappa (recDelta void void (delta void)))`.
  - The second argument is again `1` (identical calculation to the inner term above), so LHS = `Nat.max 0 1` = `1`.
- Thus `1 < 1` is false.

#### Why the strategy fails more generally
Even if one restricted attention to those `n` for which the first helper happened to hold, the second helper would still be unprovable from it alone: after the rewrite one would need
```
kappa (app s (recDelta b s n)) < kappa (recDelta b s n) + 1,
```
i.e.
```
Nat.max (kappa s) (kappa (recDelta b s n)) < kappa (recDelta b s n) + 1.
```
While `kappa (recDelta b s n) ≥ kappa s` always holds by the definition of `kappa` (both the `delta`-matching clause and the catch-all contain a `Nat.max` with `kappa s`), the numeric inequality can fail for other reasons once nested `delta`s appear; the counter-example above already exhibits the failure mode.

Consequently the two helpers cannot be used (as written) to discharge the `R_rec_succ` case of a termination argument.
