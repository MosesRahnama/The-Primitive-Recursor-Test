The helper strategy is **not sound as written**.

The issue is that `kappa` treats `recDelta b s (.delta n)` specially, adding `+ 1`, but `delta` itself does **not** increase `kappa`:

```lean
kappa (delta t) = kappa t
```

So the claimed theorem

```lean
theorem kappa_rec_delta_step (b s n : Trace) :
  kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

is false when `n` is itself a `delta`.

Let

```lean
b = void
s = void
n = delta void
```

Then the left-hand side is:

```lean
kappa (recDelta void void (delta (delta void)))
= Nat.max (Nat.max 0 0) (kappa (delta void)) + 1
= Nat.max 0 0 + 1
= 1
```

But the right-hand side is:

```lean
kappa (recDelta void void (delta void)) + 1
= (Nat.max (Nat.max 0 0) (kappa void) + 1) + 1
= (0 + 1) + 1
= 2
```

So the theorem asserts:

```lean
1 = 2
```

which is false.

The second helper theorem is also false:

```lean
theorem kappa_rec_succ_drop (b s n : Trace) :
  kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
```

Using the same counterexample:

```lean
b = void
s = void
n = delta void
```

The left-hand side is:

```lean
kappa (app void (recDelta void void (delta void)))
= Nat.max 0 (kappa (recDelta void void (delta void)))
= Nat.max 0 1
= 1
```

The right-hand side is:

```lean
kappa (recDelta void void (delta (delta void)))
= 1
```

So the claimed inequality becomes:

```lean
1 < 1
```

which is false.

Therefore, the proposed termination measure `kappa` does not strictly decrease for the rule

```lean
R_rec_succ : Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

when `n` is already of the form `delta m`. In that case, the measure can stay equal rather than decrease. Thus the helper strategy is unsound as written.
