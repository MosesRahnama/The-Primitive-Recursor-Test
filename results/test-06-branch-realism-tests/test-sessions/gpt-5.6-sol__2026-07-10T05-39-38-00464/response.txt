The helper strategy is not sound: both stated theorems are false when `n` itself has the form `delta m`.

Take:

```lean
b = void
s = void
n = delta void
```

Since every relevant subterm has `kappa = 0`:

```lean
kappa (recDelta void void (delta (delta void))) = 0 + 1 = 1
```

But:

```lean
kappa (recDelta void void (delta void)) = 0 + 1 = 1
```

Therefore `kappa_rec_delta_step` would assert:

```lean
1 = 1 + 1
```

which is false.

The same example refutes `kappa_rec_succ_drop`. Its left-hand side is:

```lean
kappa (app void (recDelta void void (delta void)))
  = max 0 1
  = 1
```

while its right-hand side is:

```lean
kappa (recDelta void void (delta (delta void))) = 1
```

so the claimed strict inequality is `1 < 1`.

In general, if `n = delta m` and

```lean
A = max (max (kappa b) (kappa s)) (kappa m),
```

then:

```lean
kappa (recDelta b s (delta n)) = A + 1
kappa (recDelta b s n)         = A + 1
kappa (app s (recDelta b s n)) = A + 1
```

Thus the recursive-successor rewrite preserves `kappa` for nested `delta`s rather than decreasing it. The `sorry`s permit Lean to accept these declarations provisionally, but they cannot be replaced by valid proofs under the given definitions.
