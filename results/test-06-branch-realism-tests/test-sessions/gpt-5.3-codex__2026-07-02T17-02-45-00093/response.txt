The helper strategy is **not sound in general** as written.

### Why

The critical claim is:

\[
\texttt{kappa\_rec\_delta\_step: } \kappa(\texttt{recDelta } b\, s\, (\texttt{delta } n))
= \kappa(\texttt{recDelta } b\, s\, n) + 1.
\]

But by definition:

- \(\kappa(\texttt{recDelta } b\, s\, (\texttt{delta } n)) = M + 1\), where  
  \(M := \max(\max(\kappa b,\kappa s),\kappa n)\).

- \(\kappa(\texttt{recDelta } b\, s\, n)\) is **not always** \(M\); it depends on the shape of \(n\):
  - if \(n = \texttt{delta } n'\), then it is \(\max(\max(\kappa b,\kappa s),\kappa n') + 1 = M+1\) (since \(\kappa(\delta n')=\kappa n'\)).
  - otherwise it is \(M\).

So the equality fails when \(n\) itself is a `delta`.

### Concrete counterexample

Take \(b=s=n=\texttt{void}\), and in the theorem instantiate \(n := \texttt{delta void}\).

Then:

- LHS:
  \[
  \kappa(\texttt{recDelta void void (delta (delta void))})
  = \max(\max(0,0),0)+1 = 1.
  \]

- RHS:
  \[
  \kappa(\texttt{recDelta void void (delta void)})+1
  = ( \max(\max(0,0),0)+1 )+1
  = 2.
  \]

So \(1 = 2\) would be required — false.

Hence `kappa_rec_delta_step` is false as stated.

---

Because `kappa_rec_succ_drop` rewrites with that theorem, its proof strategy is also unsound.  
(Separately, the inequality itself can still be true, but this particular helper rewrite is invalid globally.)
