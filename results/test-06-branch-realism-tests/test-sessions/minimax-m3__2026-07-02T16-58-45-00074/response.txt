## Assessment: The strategy is **unsound**.

The problem lies with the helper lemma `kappa_rec_delta_step`. As stated, it claims

```
kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

for *all* `n : Trace`. This is **false** when `n` itself is of the form `delta m`.

### The calculation

By the two clauses defining `kappa` on `recDelta`:

* `kappa (recDelta b s (delta n)) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1`
  (the first clause fires, using `kappa (delta n) = kappa n`).

* `kappa (recDelta b s n)` is *itself* either
  * `Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)` when `n` is *not* a `delta`, or
  * `Nat.max (Nat.max (kappa b) (kappa s)) (kappa m) + 1` when `n = delta m`.

So `kappa (recDelta b s n) + 1` is

* `Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1` if `n` is not a `delta` — matches the LHS ✓
* `Nat.max (Nat.max (kappa b) (kappa s)) (kappa m) + 2` if `n = delta m` — but the LHS is `… + 1` ✗

### Concrete counterexample

Take `b = void`, `s = void`, `n = delta void`.

* LHS: `kappa (recDelta void void (delta (delta void))) = Nat.max 0 0 (kappa void) + 1 = 1`.
* RHS: `kappa (recDelta void void (delta void)) + 1 = (0 + 1) + 1 = 2`.

The equality `1 = 2` is absurd, so `kappa_rec_delta_step` does not hold in general.

### Consequence for `kappa_rec_succ_drop`

`kappa_rec_succ_drop` begins with

```
rw [kappa_rec_delta_step]
```

After this rewrite the goal becomes

```
kappa (app s (recDelta b s n)) < kappa (recDelta b s n) + 1
```

This is a strictly weaker statement than the original goal, but the original goal was already only as strong as the (false) lemma permits. More importantly, **the rewrite relies on a lemma that is not universally true**, so the proof is unsound. Any term in which the recursive argument is "deep" (e.g. `recDelta b s (delta (delta t))`) will break the chain.

### Why the design is fragile

The measure is trying to play the role of an ordinal/depth: each visible `delta` layer around the recursion argument should contribute one unit. But because the "inner" `n` in `delta n` can itself be a `delta`, the +1 in the `delta` clause double-counts the outermost `delta` (since the recursive call's own `delta` clause will *also* add a 1 when later unwound). The lemma works for the *one-step* unrolling only under a side-condition `n ≠ delta _`, which the helper strategy does not impose.

### Verdict

`kappa_rec_delta_step` is unsound in general; therefore `kappa_rec_succ_drop`, which depends on it, is also unsound. The strategy as written does not establish termination.
