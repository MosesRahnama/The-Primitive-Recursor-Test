The helper strategy is not sound as written. Both theorems are false for some inputs because `kappa` gives a special `+1` whenever the third argument of `recDelta` is syntactically a `delta`.

Let

\[
A = \max(\kappa b,\kappa s).
\]

If `n = delta m`, then:

\[
\begin{aligned}
\kappa(\mathrm{recDelta}\ b\ s\ (\delta n))
&= \kappa(\mathrm{recDelta}\ b\ s\ (\delta(\delta m))) \\
&= \max(A,\kappa(\delta m))+1 \\
&= \max(A,\kappa m)+1,
\end{aligned}
\]

whereas

\[
\begin{aligned}
\kappa(\mathrm{recDelta}\ b\ s\ n)+1
&= \kappa(\mathrm{recDelta}\ b\ s\ (\delta m))+1 \\
&= (\max(A,\kappa m)+1)+1.
\end{aligned}
\]

Thus `kappa_rec_delta_step` would assert an equality differing by one.

A concrete counterexample is `b = void`, `s = void`, and `n = delta void`:

```text
kappa (recDelta void void (delta (delta void))) = 1
kappa (recDelta void void (delta void)) + 1 = 2
```

So `kappa_rec_delta_step` is false. It would only hold when `n` is not itself a `delta`.

The second theorem is also false for the same nested-`delta` case. With `b = s = void` and `n = delta void`:

```text
kappa (app void (recDelta void void (delta void))) = 1
kappa (recDelta void void (delta (delta void))) = 1
```

Hence the claimed strict inequality is actually `1 < 1`, which is false.

More generally, when `n = delta m`, the left side of `kappa_rec_succ_drop` can equal the right side, because both contain the same extra `+1` contributed by the recursive argument's syntactic `delta`. Therefore the proposed rewrite-based termination argument cannot be valid without separately handling or excluding the case where `n` is itself a `delta`.
