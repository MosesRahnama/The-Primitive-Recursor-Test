# Assessment

The helper strategy is **not sound**. Both helper theorems fail because of how `kappa` behaves on `recDelta` when the third argument is *not* a `delta`.

## The core problem: `kappa_rec_delta_step` is false

The theorem claims:
```
kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

Let me compute both sides.

**Left side:** By `kappa_rec_delta`:
```
kappa (recDelta b s (delta n)) = max (max (kappa b) (kappa s)) (kappa n) + 1
```

**Right side:** This depends on the *shape* of `n`, due to the overlapping patterns in `kappa`. The definition has two `recDelta` clauses:
- `.recDelta b s (.delta n)` → `max (max (kappa b) (kappa s)) (kappa n) + 1`
- `.recDelta b s n` (catch-all) → `max (max (kappa b) (kappa s)) (kappa n)`

**Case `n = delta m`:** Then `recDelta b s n = recDelta b s (delta m)` matches the *first* clause:
```
kappa (recDelta b s (delta m)) = max (max (kappa b) (kappa s)) (kappa m) + 1
```
So the equation becomes:
```
max (max (kappa b) (kappa s)) (kappa (delta m)) + 1
  = (max (max (kappa b) (kappa s)) (kappa m) + 1) + 1
```
Since `kappa (delta m) = kappa m`, the LHS is `X + 1` and the RHS is `X + 2`. **These are unequal.** The theorem is false in this case.

For example, take `n = delta void`, `b = s = void`:
- LHS: `kappa (recDelta void void (delta (delta void)))` = `max (max 0 0) (kappa (delta void)) + 1` = `0 + 1 = 1`
- RHS: `kappa (recDelta void void (delta void)) + 1` = `(max (max 0 0) 0 + 1) + 1` = `1 + 1 = 2`

`1 ≠ 2`. ❌

So `kappa_rec_delta_step` cannot be proved (the `sorry` covers a false goal).

## `kappa_rec_succ_drop` also fails independently

Even granting `kappa_rec_delta_step`, the proof strategy `rw [kappa_rec_delta_step]` reduces the goal to:
```
kappa (app s (recDelta b s n)) < kappa (recDelta b s n) + 1
```
i.e.
```
kappa (app s (recDelta b s n)) ≤ kappa (recDelta b s n)
```
Now `kappa (app s (recDelta b s n)) = max (kappa s) (kappa (recDelta b s n))`. This is `< kappa (recDelta b s n) + 1` **iff** `kappa s ≤ kappa (recDelta b s n)`.

But there is no such guarantee. When `n` is not a `delta`, `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n)`, which *does* dominate `kappa s`. However, the actual target `kappa_rec_succ_drop` itself is even independently problematic:

The true statement `kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`:
- RHS `= max (max (kappa b) (kappa s)) (kappa n) + 1`
- LHS `= max (kappa s) (kappa (recDelta b s n))`

**If `n` is not a delta:** `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n) =: M`, so LHS `= max (kappa s) M = M` (since `kappa s ≤ M`), and RHS `= M + 1`. Here `M < M + 1` holds — but only reachable via the *correct* fact that `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`, which holds **only when `n` is not a delta**.

**If `n = delta m`:** as shown above, `kappa_rec_delta_step` is off by one, and the rewrite corrupts the goal.

## Conclusion

The whole strategy hinges on the "clean" recurrence `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`, but the `kappa` definition does **not** satisfy this: the `+1` is attached only to the outermost `delta`, so:
- it holds when `n` is *not* a `delta`,
- it fails (off by one) when `n = delta m`.

Since `kappa_rec_delta_step` is stated unconditionally, it is **false**, and `kappa_rec_succ_drop`'s proof depends on rewriting with it.

**Fixes** would require redefining `kappa` on `recDelta` to genuinely count `delta`s uniformly (e.g. `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n) + delta_depth n`), or restating the helper lemmas without the false unconditional `+1` recurrence. As written, the helper strategy is unsound.
