We need to assess whether the helper strategy is sound. The two theorems:

1. `kappa_rec_delta_step`: claims `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`.

2. `kappa_rec_succ_drop`: claims `kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`.

Let me analyze.

For `kappa_rec_delta_step`:
- LHS: `kappa (recDelta b s (delta n))` matches the `recDelta b s (.delta n)` pattern, so it equals `Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1`.
- RHS: `kappa (recDelta b s n) + 1`. Here `n` is general. We need to know the form of `n` to compute `kappa (recDelta b s n)`.

Case 1: `n = delta n'` for some `n'`. Then `kappa (recDelta b s (delta n')) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n') + 1 = Nat.max (Nat.max (kappa b) (kappa s)) (kappa (delta n')) + 1 = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1`. And LHS is `kappa (recDelta b s (delta (delta n'))) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa (delta n')) + 1`. Same. ✓

Case 2: `n = void` (or any other constructor). Then `kappa (recDelta b s n) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)` (the second equation). RHS = `Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1`. LHS = `kappa (recDelta b s (delta n)) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa (delta n)) + 1 = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1`. Same. ✓

Wait, for case 2 we need `n` to not be `delta _`. The general lemma needs to work for arbitrary `n`, but `n` could be any Trace. The `kappa` function on `recDelta` is defined by pattern matching on the third argument. We can do induction on `n` to handle both cases.

Actually, the function `kappa` is defined by structural recursion on the Trace. For `recDelta b s n`, it recurses on `n`. So we can prove this by induction on `n`.

For `n = void`: `kappa (recDelta b s void) = Nat.max (kappa b) (kappa s)`. RHS = `Nat.max (kappa b) (kappa s) + 1`. LHS = `kappa (recDelta b s (delta void)) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa void) + 1 = Nat.max (Nat.max (kappa b) (kappa s)) 0 + 1 = Nat.max (kappa b) (kappa s) + 1`. ✓

For `n = delta n'`: LHS = `kappa (recDelta b s (delta (delta n'))) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa (delta n')) + 1 = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n') + 1`. RHS: by IH `kappa (recDelta b s (delta n')) = kappa (recDelta b s n') + 1`, so `kappa (recDelta b s (delta (delta n'))) = kappa (recDelta b s n') + 2`... wait, but we need to check this.

Hmm wait. For `n = delta n'`, `kappa (recDelta b s n) = kappa (recDelta b s (delta n')) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n') + 1` (by the first equation applied to argument `delta n'`).

And `kappa (recDelta b s (delta n))` where `n = delta n'` means `kappa (recDelta b s (delta (delta n'))) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa (delta n')) + 1 = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n') + 1`.

So LHS = `Nat.max (Nat.max (kappa b) (kappa s)) (kappa n') + 1`, RHS = `Nat.max (Nat.max (kappa b) (kappa s)) (kappa n') + 1`. ✓

OK so `kappa_rec_delta_step` is true.

Now `kappa_rec_succ_drop`:
- LHS: `kappa (app s (recDelta b s n)) = Nat.max (kappa s) (kappa (recDelta b s n))`.
- RHS: `kappa (recDelta b s (delta n)) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1` (using the first equation, since the third arg is `delta n`).

We need: `Nat.max (kappa s) (kappa (recDelta b s n)) < Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1`.

Let `M = Nat.max (kappa b) (kappa s)`, `K_n = kappa n`. Then RHS = `Nat.max M K_n + 1`.

For LHS, `kappa (recDelta b s n)`:
- If `n = delta n'`: `kappa (recDelta b s (delta n')) = M.max K_n' + 1` where `K_n' = kappa n' = kappa (delta n') = kappa n = K_n`. So `kappa (recDelta b s n) = Nat.max M K_n + 1`. LHS = `Nat.max (kappa s) (Nat.max M K_n + 1) = Nat.max M K_n + 1` (since `kappa s <= M <= M.max K_n + 1`). So LHS = RHS. NOT strictly less! They're equal.

So the lemma claims strict inequality, but in the case `n = delta n'`, we have equality, not strict inequality. The strategy is unsound.

Let me double-check. `n = delta n'`. Then `kappa n = kappa (delta n') = kappa n'`. The third arg of `recDelta b s n = recDelta b s (delta n')` is `delta n'`, so `kappa (recDelta b s n) = Nat.max M (kappa n') + 1 = Nat.max M (kappa n) + 1`.

LHS = `kappa (app s (recDelta b s n)) = Nat.max (kappa s) (kappa (recDelta b s n)) = Nat.max (kappa s) (Nat.max M (kappa n) + 1)`.

Since `M = Nat.max (kappa b) (kappa s)`, we have `kappa s <= M`, so `kappa s <= M <= Nat.max M (kappa n) + 1` (the +1 makes it strict if kappa n is anything). Actually, `M <= Nat.max M (kappa n) + 1` is true. So LHS = `Nat.max M (kappa n) + 1`.

RHS = `kappa (recDelta b s (delta n))` where the third arg is `delta n`, so this is `Nat.max M (kappa n) + 1`.

LHS = RHS. So strict inequality fails. The theorem is false.

Therefore the helper strategy is unsound.

Also, even in the case where the recursion is genuine (e.g., `n = void`), let's check:
- `n = void`: `kappa (recDelta b s n) = M` (no +1). LHS = `Nat.max (kappa s) M = M` (assuming kappa s <= kappa b; if not, then it's kappa s, but in any case ≤ M). RHS = `Nat.max M (kappa void) + 1 = M + 1`. So LHS < RHS. ✓
- `n = integrate t`: `kappa n = kappa t`. `kappa (recDelta b s n) = M.max (kappa t)`. LHS = `Nat.max (kappa s) (M.max (kappa t)) = M.max (kappa t)`. RHS = `M.max (kappa t) + 1`. ✓
- `n = merge a b'`: similar. LHS = M.max(kappa (merge a b')) = M.max (Nat.max (kappa a) (kappa b')). RHS = M.max (kappa n) + 1. Same. ✓
- `n = delta n'`: equality, not strict. ✗
- `n = app a b'`: similar, strict. ✓
- `n = recDelta b' s' n'`: similar strict. ✓
- `n = eqW a b'`: strict. ✓

So the issue is specifically when `n` has the form `delta _`. The strategy is unsound.

The intended goal of the strategy is presumably to support a termination argument for the rewrite system. If `Step (recDelta b s (delta n)) (app s (recDelta b s n))` is meant to be a measure-decreasing step, then we need the kappa measure to strictly decrease. But when `n = delta n'`, kappa stays the same. So the helper strategy as written doesn't establish the desired measure decrease.

This is a real bug in the strategy.
