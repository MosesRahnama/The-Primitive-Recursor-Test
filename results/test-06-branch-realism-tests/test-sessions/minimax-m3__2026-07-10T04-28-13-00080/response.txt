# Assessment: The helper strategy is **unsound**

The two helper theorems are not both true. The first one is fine, but the second one (`kappa_rec_succ_drop`) is false in general, and the `sorry` in it cannot be filled with a correct proof.

## Checking `kappa_rec_delta_step`

Let `M = Nat.max (kappa b) (kappa s)`. We proceed by structural induction on `n`.

- **Case `n = void`:** LHS = `kappa (recDelta b s (delta void)) = max M (kappa void) + 1 = M + 1`. RHS = `kappa (recDelta b s void) + 1 = M + 1`. ✓
- **Case `n = delta n'`:** LHS = `max M (kappa n') + 1`. RHS = `kappa (recDelta b s (delta n')) + 1 = (max M (kappa n') + 1) + 1`... wait, applying the IH gives `kappa (recDelta b s (delta n')) = kappa (recDelta b s n') + 1`, and `kappa (recDelta b s n') = max M (kappa n')` (since `n'` is *not* of the form `delta _`, by structural-induction inversion). So RHS = `max M (kappa n') + 1`. ✓
- **Other constructors for `n`:** LHS = `max M (kappa n) + 1`, RHS = `max M (kappa n) + 1`. ✓

So `kappa_rec_delta_step` holds (and is provable by induction on `n`).

## Checking `kappa_rec_succ_drop` — **counterexample**

The claim is
```
kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
```

Take any `b, s` and let `n = delta n'` for some `n'`. Then:

- **LHS:** `kappa (app s (recDelta b s (delta n'))) = max (kappa s) (kappa (recDelta b s (delta n')))`. Since the third argument of the inner `recDelta` is `delta n'`, the recursion clause with `+1` applies: `kappa (recDelta b s (delta n')) = max M (kappa n') + 1`. Because `kappa s ≤ M`, the outer `max` is `max M (kappa n') + 1`.

- **RHS:** `kappa (recDelta b s (delta (delta n'))) = max M (kappa (delta n')) + 1 = max M (kappa n') + 1`.

So **LHS = RHS**, and the claimed strict inequality is violated.

## Why the rewrite rule itself is at fault

The rule
```
R_rec_succ : Step (recDelta b s (delta n)) (app s (recDelta b s n))
```
is **not measure-decreasing under `kappa`** in the case `n = delta n'`. The `+1` in the `kappa` definition for `recDelta … (delta _)` accounts exactly for the `delta` constructor in the third argument, but the RHS also contains a `recDelta` with `delta n'` as its third argument, which contributes the same `+1`. The rule only strictly decreases `kappa` when the third argument of the inner `recDelta` is *not* of the form `delta _`.

## Conclusion

`kappa_rec_delta_step` is a valid lemma, but `kappa_rec_succ_drop` is false: with `n = delta n'` both sides evaluate to `max M (kappa n') + 1`. Therefore the helper strategy as written does **not** establish that `Step` strictly decreases `kappa` on the `R_rec_succ` rule, and the termination argument built on these helpers is unsound.
