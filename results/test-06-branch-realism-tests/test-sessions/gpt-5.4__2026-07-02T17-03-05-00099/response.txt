The helper strategy is not sound as written.

## Short reason

The first helper theorem

```lean
theorem kappa_rec_delta_step (b s n : Trace) :
  kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

is false in general.

Because it is false, the second helper theorem is also unsupported by this route, even though the second statement itself happens to be true.

---

## Why the first theorem is false

Let

- `B = kappa b`
- `S = kappa s`
- `N = kappa n`

Then by definition:

- `kappa (recDelta b s (delta n)) = max (max B S) N + 1`
- `kappa (recDelta b s n)` depends on the shape of `n`:
  - if `n = delta m`, then it is also a “special” clause with `+1`
  - otherwise it is `max (max B S) N`

So the theorem claims:

```text
max (max B S) N + 1 = kappa (recDelta b s n) + 1
```

This only works if `kappa (recDelta b s n) = max (max B S) N`, i.e. only when `n` is **not** syntactically of the form `delta _`.

But the theorem quantifies over arbitrary `n : Trace`, including `n = delta m`.

### Concrete counterexample

Take:

- `b = void`
- `s = void`
- `n = delta void`

Then:

- `kappa b = 0`
- `kappa s = 0`
- `kappa n = kappa (delta void) = 0`

Compute both sides.

#### Left-hand side

```lean
kappa (recDelta void void (delta (delta void)))
```

Since the third argument is `delta _`, use the special clause:

```text
= max (max 0 0) 0 + 1
= 1
```

#### Right-hand side

```lean
kappa (recDelta void void (delta void)) + 1
```

Again the third argument is `delta _`, so:

```text
kappa (recDelta void void (delta void)) = max (max 0 0) 0 + 1 = 1
```

Hence RHS is:

```text
1 + 1 = 2
```

So the claimed equality becomes:

```text
1 = 2
```

which is impossible.

Therefore `kappa_rec_delta_step` is false.

---

## What went wrong conceptually

The measure `kappa` is defined by **pattern matching on the outer constructor** of the third argument of `recDelta`:

- if the argument is exactly `.delta n`, then add `1`
- otherwise do not

So when you compare

```lean
recDelta b s (delta n)
```

with

```lean
recDelta b s n
```

you cannot conclude the latter is always exactly one less in `kappa`, because `n` itself may already be a `delta _`, in which case the “+1 bonus” also appears there.

In fact:

- if `n` is **not** of the form `delta _`, then the equality does hold;
- if `n` **is** of the form `delta _`, then both sides get the bonus, so the difference is `0`, not `1`.

---

## The second theorem

```lean
theorem kappa_rec_succ_drop (b s n : Trace) :
  kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n)) := by
  rw [kappa_rec_delta_step]
  sorry
```

### The proof strategy is unsound

It relies on rewriting by the false theorem `kappa_rec_delta_step`, so the strategy is invalid.

### But the statement itself is true

Let again:

- `B = kappa b`
- `S = kappa s`
- `N = kappa n`
- `M = max (max B S) N`

Then:

```text
kappa (recDelta b s (delta n)) = M + 1
```

Also:

- if `n` is not `delta _`, then `kappa (recDelta b s n) = M`
- if `n = delta m`, then `kappa (recDelta b s n) = M + 1`

But note that when `n = delta m`, we have `N = kappa n = kappa m`, so
`M ≥ S`, and in fact:

```text
kappa (recDelta b s n) = M + 1
```

Then

```text
kappa (app s (recDelta b s n))
= max (S, kappa (recDelta b s n))
```

We should check both cases.

#### Case 1: `n` is not `delta _`

Then:

```text
kappa (recDelta b s n) = M
kappa (app s (recDelta b s n)) = max(S, M) = M
```

since `M ≥ S`. Therefore:

```text
kappa (app s (recDelta b s n)) = M < M + 1 = kappa (recDelta b s (delta n))
```

#### Case 2: `n = delta m`

Then `kappa (recDelta b s n) = M + 1`, so:

```text
kappa (app s (recDelta b s n)) = max(S, M + 1) = M + 1
```

while

```text
kappa (recDelta b s (delta n)) = M + 1
```

So in this case we get equality, not strict inequality.

Wait—that means the second theorem is also false as stated.

### Concrete counterexample for theorem 2

Again take:

- `b = void`
- `s = void`
- `n = delta void`

Then:

```text
kappa (recDelta void void (delta (delta void))) = 1
```

And

```text
kappa (recDelta void void (delta void)) = 1
kappa (app void (recDelta void void (delta void))) = max(0,1) = 1
```

So the conclusion becomes:

```text
1 < 1
```

false.

---

## Final conclusion

The helper strategy is unsound in a strong sense:

1. `kappa_rec_delta_step` is false.
2. The intended proof of `kappa_rec_succ_drop` by rewriting with it is therefore invalid.
3. Moreover, `kappa_rec_succ_drop` is itself also false.

## Root cause

The measure `kappa` only detects whether the third argument of `recDelta` is **syntactically** a `delta _` at the top level. Because `delta` does not increase `kappa` on its own, nested `delta`s all have the same base measure, and the “+1” bonus is not strictly consumed by one `R_rec_succ` step when the predecessor `n` is itself a `delta _`.

So `kappa` as defined does not strictly decrease across `R_rec_succ` in all cases.
