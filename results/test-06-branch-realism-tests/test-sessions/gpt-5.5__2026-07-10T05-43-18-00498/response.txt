No. The helper strategy is not sound as written. The key issue is that `kappa` only adds `+ 1` when the third argument of `recDelta` is syntactically a top-level `delta`. Since `kappa (delta t) = kappa t`, nested `delta`s do not accumulate additional `kappa`, but the theorem `kappa_rec_delta_step` assumes that adding a `delta` always increases `kappa` by exactly one.

Consider the claimed theorem:

```lean
theorem kappa_rec_delta_step (b s n : Trace) :
  kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

This is false when `n` is itself a `delta`.

Take:

```lean
b = void
s = void
n = delta void
```

Then:

```lean
kappa (recDelta void void (delta (delta void)))
```

matches the special clause

```lean
kappa (recDelta b s (delta n)) =
  Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1
```

so

```lean
kappa (recDelta void void (delta (delta void)))
= Nat.max (Nat.max 0 0) (kappa (delta void)) + 1
= Nat.max 0 0 + 1
= 1
```

But the right-hand side of `kappa_rec_delta_step` is:

```lean
kappa (recDelta void void (delta void)) + 1
```

and

```lean
kappa (recDelta void void (delta void))
= Nat.max (Nat.max 0 0) (kappa void) + 1
= 1
```

so the RHS is:

```lean
1 + 1 = 2
```

Thus the theorem asserts:

```lean
1 = 2
```

which is false.

The second helper theorem is also false:

```lean
theorem kappa_rec_succ_drop (b s n : Trace) :
  kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
```

Using the same counterexample, `b = void`, `s = void`, `n = delta void`:

Left-hand side:

```lean
kappa (app void (recDelta void void (delta void)))
= Nat.max (kappa void) (kappa (recDelta void void (delta void)))
= Nat.max 0 1
= 1
```

Right-hand side:

```lean
kappa (recDelta void void (delta (delta void))) = 1
```

So the claimed strict inequality becomes:

```lean
1 < 1
```

which is false.

This directly affects the rewrite rule:

```lean
R_rec_succ :
  Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

For the concrete instance

```lean
Step
  (recDelta void void (delta (delta void)))
  (app void (recDelta void void (delta void)))
```

the source and target both have `kappa = 1`. So `kappa` does not strictly decrease across this step.

More generally, if `n = delta m`, let

```lean
A = Nat.max (Nat.max (kappa b) (kappa s)) (kappa m)
```

Then:

```lean
kappa (recDelta b s (delta (delta m))) = A + 1
```

and

```lean
kappa (recDelta b s (delta m)) = A + 1
```

so

```lean
kappa (app s (recDelta b s (delta m)))
= Nat.max (kappa s) (A + 1)
= A + 1
```

because `A ≥ kappa s`. Therefore the supposed strict drop is actually equality:

```lean
kappa (app s (recDelta b s (delta m)))
= kappa (recDelta b s (delta (delta m)))
```

So the helper strategy is unsound. The `sorry`s hide false statements; if accepted as axioms, they allow proving false arithmetic facts such as `1 = 2`.
