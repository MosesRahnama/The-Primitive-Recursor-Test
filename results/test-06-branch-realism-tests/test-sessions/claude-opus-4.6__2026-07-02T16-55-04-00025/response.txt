# Assessment of the Helper Strategy

## Goal: Prove termination of rewriting via `kappa` decreasing on each `Step`

The two helper theorems target the critical case: the `R_rec_succ` rule, which rewrites `recDelta b s (delta n)` to `app s (recDelta b s n)`. For termination, we need:

```
kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
```

## Analyzing `kappa_rec_delta_step`

**Claim:** `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

**LHS:** By the `recDelta b s (.delta n)` clause:
```
kappa (recDelta b s (delta n)) = max (max (kappa b) (kappa s)) (kappa n) + 1
```

**RHS:** `kappa (recDelta b s n) + 1`. We need to consider what `n` is.

- If `n = delta n'`, then `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n') + 1`, but `kappa n = kappa (delta n') = kappa n'`. So RHS = `max (max (kappa b) (kappa s)) (kappa n') + 1 + 1`, while LHS = `max (max (kappa b) (kappa s)) (kappa n') + 1`. **These are not equal.**

**This theorem is false** when `n` is itself a `delta` term. For example, let `b = void`, `s = void`, `n = delta void`:

- LHS: `kappa (recDelta void void (delta (delta void)))` = `max (max 0 0) (kappa (delta void)) + 1` = `max 0 0 + 1` = `1`
- RHS: `kappa (recDelta void void (delta void)) + 1` = `(max (max 0 0) (kappa void) + 1) + 1` = `(0 + 1) + 1` = `2`

So `1 ≠ 2`. The theorem `kappa_rec_delta_step` is **false**.

The root cause is that `kappa` has a special pattern-match clause for `recDelta b s (.delta n)` that adds `+1`, so `kappa (recDelta b s n)` does **not** simply equal `max (max (kappa b) (kappa s)) (kappa n)` in general — when `n` is itself a `delta`, the special clause fires and adds its own `+1`.

## Analyzing `kappa_rec_succ_drop`

**Claim:** `kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`

The LHS expands to:
```
max (kappa s) (kappa (recDelta b s n))
```

The RHS is:
```
max (max (kappa b) (kappa s)) (kappa n) + 1
```

For the fallthrough case (n is not a `delta`): `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n)`, so LHS = `max (kappa s) (max (max (kappa b) (kappa s)) (kappa n))` = `max (max (kappa b) (kappa s)) (kappa n)`. This is strictly less than RHS (which is that value + 1). ✓

For the case `n = delta n'`: `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n') + 1`, and `kappa n = kappa n'`. So LHS = `max (kappa s) (max (max (kappa b) (kappa s)) (kappa n') + 1)`. RHS = `max (max (kappa b) (kappa s)) (kappa n') + 1`. Since `kappa s ≤ max (max (kappa b) (kappa s)) (kappa n') + 1`, we get LHS = RHS. **Not strictly less.** ✗

So the second theorem is also **false** when `n` is a `delta` term (and the relevant max is achieved by the recursive component).

## Conclusion

**The helper strategy is unsound as written.** Both `kappa_rec_delta_step` and `kappa_rec_succ_drop` are false — they fail when `n` is itself a `delta`-headed term, because the definition of `kappa` on `recDelta` has a nested pattern match that adds `+1` specifically for the `delta` case, causing the "recursive peeling" identity to break down. A correct termination measure would likely need to account for the structural depth of the third argument of `recDelta` rather than (or in addition to) the `kappa` measure as defined.
