No. The helper strategy is not sound as written.

### Core issue

`kappa` treats `delta` transparently:

```lean
kappa (delta t) = kappa t
```

but it gives a special extra `+ 1` when the third argument of `recDelta` is *syntactically* `delta _`:

```lean
kappa (recDelta b s (delta n))
  = max (max (kappa b) (kappa s)) (kappa n) + 1
```

That means peeling one outer `delta` does **not** always reduce the measure by exactly 1, because the inner term `n` might itself already be a `delta _`, in which case `kappa (recDelta b s n)` also carries the same `+1`.

---

## 1. `kappa_rec_delta_step` is false

The theorem claims:

```lean
kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

for all `n`.

Take `n = delta m`. Let

\[
A := \max(\max(\kappa b,\kappa s), \kappa m).
\]

Then:

- Left side:
  \[
  \kappa(\mathrm{recDelta}\ b\ s\ (\delta(\delta m))) = A + 1
  \]

- Right side:
  \[
  \kappa(\mathrm{recDelta}\ b\ s\ (\delta m)) + 1 = (A + 1) + 1 = A + 2
  \]

So the theorem would require:

\[
A+1 = A+2,
\]

which is impossible.

### Concrete counterexample
Set `b = void`, `s = void`, `m = void`. Then:

- `kappa void = 0`
- `kappa (delta void) = 0`

Hence:

```lean
kappa (recDelta void void (delta (delta void))) = 1
kappa (recDelta void void (delta void)) + 1 = 2
```

So the claimed equality is `1 = 2`, false.

---

## 2. `kappa_rec_succ_drop` is also false

The theorem claims:

```lean
kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
```

Again take `n = delta m`, with the same

\[
A := \max(\max(\kappa b,\kappa s), \kappa m).
\]

Then:

- `kappa (recDelta b s (delta m)) = A + 1`
- so
  \[
  \kappa(\mathrm{app}\ s\ (\mathrm{recDelta}\ b\ s\ (\delta m)))
  = \max(\kappa s, A+1)
  = A+1
  \]
  since `A ≥ kappa s`.

- And
  \[
  \kappa(\mathrm{recDelta}\ b\ s\ (\delta(\delta m))) = A+1.
  \]

Thus the theorem would require:

\[
A+1 < A+1,
\]

false.

### Same concrete counterexample
With `b = s = m = void`:

```lean
kappa (app void (recDelta void void (delta void))) = 1
kappa (recDelta void void (delta (delta void))) = 1
```

So the claimed strict inequality is `1 < 1`, false.

---

## 3. What *is* true

These statements become true when `n` is **not** of the form `delta _`.

So the intended intuition works only for a restricted case:
- if `n` is not `delta _`, then
  ```lean
  kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
  ```
  and therefore
  ```lean
  kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
  ```

But the theorems in the file quantify over **all** `n`, so as stated they are unsound.

---

## 4. Broader termination consequence

As a global ranking function for `Step`, `kappa` is not strictly decreasing anyway on several rules. For example:

- `R_merge_void_left`:
  \[
  \kappa(\mathrm{merge}\ \mathrm{void}\ t) = \max(0,\kappa t) = \kappa t
  \]
  so source and target have equal `kappa`.

- `R_merge_cancel`:
  \[
  \kappa(\mathrm{merge}\ t\ t) = \kappa t
  \]

- `R_eq_diff`:
  \[
  \kappa(\mathrm{eqW}\ a\ b) = \max(\kappa a,\kappa b)
  \]
  and
  \[
  \kappa(\mathrm{integrate}(\mathrm{merge}\ a\ b)) = \max(\kappa a,\kappa b)
  \]

So `kappa` is at best a **weakly decreasing** measure on many rules, not a strict one.

---

## Conclusion

The helper strategy is **not sound as written**.

- `kappa_rec_delta_step` is false.
- `kappa_rec_succ_drop` is false.
- The failure occurs precisely on nested `delta` inputs.
- More generally, `kappa` is not a strict termination measure for the whole `Step` relation.

So a termination proof cannot rely on these helpers in their current form.
