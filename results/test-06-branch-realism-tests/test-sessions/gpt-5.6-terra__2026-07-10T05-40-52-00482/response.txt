The helper strategy is not sound as written: both stated helper theorems are false in general.

Let

- `b = void`
- `s = void`
- `n = delta void`.

Then:

\[
\kappa(void)=0,\qquad \kappa(\delta\ void)=0.
\]

For the left side of `kappa_rec_delta_step`:

```lean
kappa (recDelta void void (delta (delta void)))
```

the third argument has outer form `delta _`, so the special `recDelta` equation applies:

\[
\kappa(recDelta\ void\ void\ (\delta(\delta\ void)))
= \max(\max(0,0),\kappa(\delta\ void))+1
= \max(0,0)+1
=1.
\]

But on the proposed right side:

```lean
kappa (recDelta void void (delta void)) + 1
```

the inner `recDelta` also sees a third argument of the form `delta _`, so:

\[
\kappa(recDelta\ void\ void\ (\delta\ void))+1
= (1)+1
=2.
\]

Thus the proposed equality specializes to \(1=2\):

```lean
kappa (recDelta void void (delta (delta void)))
  ≠ kappa (recDelta void void (delta void)) + 1
```

The issue is that `kappa` gives an extra `+ 1` whenever the *immediate* third argument of `recDelta` is a `delta`. After the successor rewrite, if `n` itself begins with `delta`, the recursive call on the right again receives a `delta`-headed third argument and gains that extra unit.

Consequently, the strict-drop theorem is false as well. With the same values:

```lean
kappa (recDelta void void (delta (delta void))) = 1
```

whereas

```lean
kappa (app void (recDelta void void (delta void)))
```

is

\[
\max\bigl(\kappa(void),\kappa(recDelta\ void\ void\ (\delta\ void))\bigr)
= \max(0,1)
=1.
\]

Hence the claimed inequality becomes \(1 < 1\), which is false:

```lean
¬ kappa (app void (recDelta void void (delta void)) <
    kappa (recDelta void void (delta (delta void))))
```

More generally, write

\[
B=\max(\kappa b)(\kappa s).
\]

If `n = delta m`, then:

\[
\begin{aligned}
\kappa(recDelta\ b\ s\ (\delta n))
  &= \max(B,\kappa n)+1 \\
  &= \max(B,\kappa m)+1,
\end{aligned}
\]

while

\[
\begin{aligned}
\kappa(app\ s\ (recDelta\ b\ s\ n))
 &= \max(\kappa s,\max(B,\kappa m)+1)\\
 &=\max(B,\kappa m)+1.
\end{aligned}
\]

So for delta-headed `n`, the two measures are equal, not strictly decreasing.

There is also a broader issue if the intended termination proof is that every `Step` strictly decreases `kappa`: several rules preserve `kappa` outright. For example,

```lean
Step (eqW a b) (integrate (merge a b))
```

has

\[
\kappa(eqW\ a\ b)
= \max(\kappa a,\kappa b)
= \kappa(integrate(merge\ a\ b)).
\]

Likewise, `merge t void → t` and `merge t t → t` can preserve the measure. Therefore `kappa` cannot serve as a uniformly strictly decreasing natural-valued termination measure for all of `Step` without an additional component, a different ordering, or a different measure.
