The helper strategy for the termination argument is **unsound** as written. Both of the helper theorems are false and cannot be proven.

The underlying flaw is in how the structural measure `kappa` is defined. Specifically, the rule `kappa (.delta t) = kappa t` means `kappa` ignores `delta` constructors, but the pattern match `| .recDelta b s (.delta n) => ... + 1` only adds exactly `1` for the *outermost* `delta` of the third argument, regardless of how many nested `delta`s are inside it. 

We can demonstrate this by providing a counterexample where `n` is itself a `delta` expression. 

### Counterexample Calculation

Let `b = void`, `s = void`, and `n = delta void`.

**1. Falsifying `kappa_rec_delta_step`:**
The theorem states: 
`kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

Let's evaluate the Left-Hand Side (LHS) with our counterexample:
```lean
kappa (recDelta void void (delta (delta void)))
-- Matches the rule: .recDelta b s (.delta n) => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1
-- Here, the pattern variable `n` is bound to `delta void`.
= Nat.max (Nat.max (kappa void) (kappa void)) (kappa (delta void)) + 1
= Nat.max (Nat.max 0 0) (kappa void) + 1
= Nat.max 0 0 + 1
= 1
```

Now let's evaluate the Right-Hand Side (RHS):
```lean
kappa (recDelta void void (delta void)) + 1
-- The inner expression matches the exact same rule, this time binding `n` to `void`.
= (Nat.max (Nat.max (kappa void) (kappa void)) (kappa void) + 1) + 1
= (Nat.max 0 0 + 1) + 1
= 1 + 1
= 2
```
Because `1 ≠ 2`, `kappa_rec_delta_step` is false.

**2. Falsifying `kappa_rec_succ_drop`:**
The theorem states:
`kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`

Let's evaluate the LHS:
```lean
kappa (app void (recDelta void void (delta void)))
-- Matches the rule: .app a b => Nat.max (kappa a) (kappa b)
= Nat.max (kappa void) (kappa (recDelta void void (delta void)))
= Nat.max 0 1
= 1
```

Let's evaluate the RHS:
```lean
kappa (recDelta void void (delta (delta void)))
-- As calculated in the LHS above
= 1
```
Because `1 < 1` is false, `kappa_rec_succ_drop` is also false.

### Conclusion
Because the rule `R_rec_succ` pulls nested `delta` expressions out one-by-one, a sound termination measure must assign a strictly greater weight to deeply nested `delta` constructors. Since `kappa` strips inner `delta` wrappers without incrementing the measure, taking a step along `R_rec_succ` does not strictly decrease `kappa`, breaking the termination strategy.
