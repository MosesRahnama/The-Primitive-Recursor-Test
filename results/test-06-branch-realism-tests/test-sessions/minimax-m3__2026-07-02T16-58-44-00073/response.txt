## Assessment: the helper strategy is **unsound**

The flaw sits in the first lemma, `kappa_rec_delta_step`, which the second lemma then relies on via `rw`.

### What the definition of `kappa` actually says

For `recDelta`, the definition has two clauses:

```
| recDelta b s (.delta n) => max (max (kappa b) (kappa s)) (kappa n) + 1
| recDelta b s n         => max (max (kappa b) (kappa s)) (kappa n)
```

So the `+ 1` is keyed on the **outermost** `delta` constructor of the third argument, not on an arbitrary one.

### Counterexample to `kappa_rec_delta_step`

Take `b := void`, `s := void`, `n := delta void`. Then

* LHS = `kappa (recDelta void void (delta (delta void)))`
       = `max (max (kappa void) (kappa void)) (kappa (delta void)) + 1`
       = `max 0 0 + 1 = 1`.

* RHS = `kappa (recDelta void void (delta void)) + 1`
       = `(max (max (kappa void) (kappa void)) (kappa void) + 1) + 1`
       = `(0 + 1) + 1 = 2`.

So `kappa_rec_delta_step` claims `1 = 2` for this choice of `b, s, n`. In general the lemma fails whenever `n` is itself of the form `delta m`, because then `kappa (recDelta b s n)` already carries a `+ 1` from the `delta`‑clause, and the LHS only gets one `+ 1` while the RHS stacks two.

(When `n` is *not* a `delta`, the two clauses match up and the equality is fine — that is the only case the lemma correctly handles.)

### Why the second lemma inherits the problem

`kappa_rec_succ_drop` rewrites the goal using `kappa_rec_delta_step`, producing

```
kappa (app s (recDelta b s n)) < kappa (recDelta b s n) + 1
```

This rewritten goal is in fact *true* for all `b, s, n` (since `kappa (recDelta b s n) >= max (kappa b) (kappa s) >= kappa s`, the LHS equals `kappa (recDelta b s n)`, which is strictly less than itself plus one). But the rewrite step itself invokes a false equation, so the chain of reasoning is unsound even though the post‑rewrite target happens to be provable independently.

### What a sound version would look like

Either restrict the first lemma by a non‑delta hypothesis, e.g.

```
theorem kappa_rec_delta_step (b s n : Trace) (hn : ¬ ∃ m, n = delta m) :
    kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

or unfold `kappa` once and case‑split on whether `n` is `delta m`. As written, `kappa_rec_delta_step` is false, and any termination argument that depends on it cannot be trusted.
