The helper strategy is not sound as written.

## Short reason

The first helper theorem is false in general:

```lean
theorem kappa_rec_delta_step (b s n : Trace) :
  kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

Because `kappa` of `delta n` is definitionally the same as `kappa n`, but `kappa` of `recDelta b s n` depends on whether `n` is syntactically of the form `delta _`. So the left side always gets the “+1” branch, while the right side only gets that if `n` itself is already a `delta`.

This creates counterexamples.

---

## Calculation showing the failure

Let

- `b = void`
- `s = void`
- `n = void`

Then:

- `kappa b = 0`
- `kappa s = 0`
- `kappa n = 0`

Compute the left side:

```lean
kappa (recDelta void void (delta void))
= max (max 0 0) 0 + 1
= 1
```

Compute the right side:

```lean
kappa (recDelta void void void) + 1
= (max (max 0 0) 0) + 1
= 0 + 1
= 1
```

So this example happens to work.

But now choose:

- `b = void`
- `s = void`
- `n = delta void`

Then `kappa n = 0` again.

Left side:

```lean
kappa (recDelta void void (delta (delta void)))
= max (max 0 0) 0 + 1
= 1
```

Right side:

```lean
kappa (recDelta void void (delta void)) + 1
= (max (max 0 0) 0 + 1) + 1
= 2
```

So the claimed equality becomes:

```lean
1 = 2
```

which is false.

Hence `kappa_rec_delta_step` is invalid.

---

## Why this happens structurally

Your definition is:

```lean
| .recDelta b s (.delta n) => M + 1
| .recDelta b s n => M
```

where

```lean
M = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)
```

So:

- `kappa (recDelta b s (delta n)) = M + 1`
- `kappa (recDelta b s n)` is:
  - `M + 1` if `n = delta n'`
  - `M` otherwise

Thus in general:

```lean
kappa (recDelta b s (delta n)) = kappa (recDelta b s n)
```

can fail, and

```lean
kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

also fails whenever `n` is itself a `delta _`.

The best unconditional statement is only:

```lean
kappa (recDelta b s (delta n)) ≤ kappa (recDelta b s n) + 1
```

and even that is not the kind of strict decrease you likely want.

---

## Consequence for the second theorem

The second helper is:

```lean
theorem kappa_rec_succ_drop (b s n : Trace) :
  kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n)) := by
  rw [kappa_rec_delta_step]
  sorry
```

This theorem itself is actually true, but not for the reason supplied by the first theorem.

Let
```lean
B = kappa b
S = kappa s
N = kappa n
M = max (max B S) N
```

Then:

### Left side
```lean
kappa (app s (recDelta b s n))
= max S (kappa (recDelta b s n))
```

Now `kappa (recDelta b s n)` is either `M` or `M+1`, depending on whether `n` is syntactically `delta _`.

But in the theorem, `n` is arbitrary, and the target source term is specifically `recDelta b s (delta n)`, so for the recursive-call reduct we have:

```lean
kappa (recDelta b s n)
```

which is at least `M` and maybe `M+1` only if `n = delta _`.

However, because `S ≤ M`, we get

- if `kappa (recDelta b s n) = M`, then
  ```lean
  kappa (app s (recDelta b s n)) = max S M = M
  ```
- if `kappa (recDelta b s n) = M+1`, then
  ```lean
  kappa (app s (recDelta b s n)) = max S (M+1) = M+1
  ```

But note carefully: in the actual `R_rec_succ` step, the source is `recDelta b s (delta n)`, whose measure is exactly `M+1`.

So if `n` itself is a `delta _`, then the reduct can also have measure `M+1`, not strictly smaller.

Let's check that directly with a concrete counterexample.

Take again:

- `b = void`
- `s = void`
- `n = delta void`

Then:

### Source
```lean
kappa (recDelta void void (delta (delta void))) = 1
```

### Target
```lean
kappa (app void (recDelta void void (delta void)))
= max 0 (kappa (recDelta void void (delta void)))
= max 0 1
= 1
```

So the claimed strict inequality becomes:

```lean
1 < 1
```

which is false.

Therefore the second theorem is also false in general.

---

## Final assessment

The helper strategy is unsound in two ways:

1. **`kappa_rec_delta_step` is false** because `recDelta`’s measure distinguishes syntactic shape of the third argument, not just its `kappa`.
2. **`kappa_rec_succ_drop` is also false**: the `R_rec_succ` rule does not strictly decrease `kappa` when `n` is already of the form `delta _`.

## Concrete counterexamples

### Counterexample to `kappa_rec_delta_step`
Set `b = void`, `s = void`, `n = delta void`:

- `kappa (recDelta b s (delta n)) = 1`
- `kappa (recDelta b s n) + 1 = 2`

So false.

### Counterexample to `kappa_rec_succ_drop`
Same choice:

- `kappa (app s (recDelta b s n)) = 1`
- `kappa (recDelta b s (delta n)) = 1`

So `1 < 1` is false.

---

So the intended termination argument based on these helpers does not go through as written.
