The helper strategy is sound.

The key question is whether the two stated theorems are actually true for the given `kappa`. They are.

## 1. Check `kappa_rec_delta_step`

We compare:

- `kappa (recDelta b s (delta n))`
- `kappa (recDelta b s n) + 1`

By definition,

- `kappa (recDelta b s (delta n)) = max (max (kappa b) (kappa s)) (kappa n) + 1`

For `kappa (recDelta b s n)`, there are two possibilities:

### Case A: `n = delta m`
Then by the special `recDelta` equation again,
- `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa m) + 1`

But `kappa n = kappa (delta m) = kappa m`, so
- RHS = `max (max (kappa b) (kappa s)) (kappa n) + 1`

Thus
- `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

still holds, because:
- LHS = `max(max(kb)(ks))(kappa n) + 1`
- RHS = `(max(max(kb)(ks))(kappa n)) + 1`

### Case B: `n` is not of the form `delta _`
Then by the non-special equation,
- `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n)`

Hence
- `kappa (recDelta b s n) + 1 = max (max (kappa b) (kappa s)) (kappa n) + 1`

which matches exactly the formula for `kappa (recDelta b s (delta n))`.

So the theorem is correct for all `n`.

A concise way to see why this works: the distinction in `kappa` for `recDelta` depends on whether the third argument is syntactically `delta _`, but `kappa (delta n) = kappa n`, so wrapping `n` in one extra `delta` always raises the outer `recDelta` measure by exactly `1`, regardless of the form of `n`.

---

## 2. Check `kappa_rec_succ_drop`

We need:
- `kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`

Using the previous theorem,
- RHS = `kappa (recDelta b s n) + 1`

And
- `kappa (app s (recDelta b s n)) = max (kappa s) (kappa (recDelta b s n))`

So it suffices to show
- `max (kappa s) (kappa (recDelta b s n)) ≤ kappa (recDelta b s n)`

because then
- `max (kappa s) (kappa (recDelta b s n)) < kappa (recDelta b s n) + 1`

The only nontrivial part is whether `kappa s ≤ kappa (recDelta b s n)` always holds. It does, by definition of `kappa` on `recDelta`:

- if `n = delta m`, then
  `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa m) + 1`
- otherwise,
  `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n)`

In either case, `kappa (recDelta b s n)` is at least `max (kappa b) (kappa s)`, hence at least `kappa s`.

Therefore
- `max (kappa s) (kappa (recDelta b s n)) = kappa (recDelta b s n)`

and so
- `kappa (app s (recDelta b s n)) = kappa (recDelta b s n) < kappa (recDelta b s n) + 1`
- hence the theorem holds.

---

## 3. What this means for the rewrite rule `R_rec_succ`

The rule is:
- `recDelta b s (delta n)  ↦  app s (recDelta b s n)`

The two lemmas show exactly:
- source measure = target measure + 1? Not quite.
- More precisely:
  - `kappa(source) = kappa(recDelta b s n) + 1`
  - `kappa(target) = kappa(recDelta b s n)`

So indeed
- `kappa(target) < kappa(source)`

This is the desired strict decrease for that rewrite step.

---

## 4. Caveat: sound for this helper step, not necessarily for full termination

These helper theorems are sound as written, but that does **not** by itself prove the whole calculus terminates under `kappa`. To use `kappa` as a global termination measure, every rewrite rule must weakly or strictly decrease appropriately.

A quick check of the other rules:

- `integrate (delta t) -> void`
  - `kappa`: `kappa t -> 0`, decreases or equal if `kappa t = 0`; not strictly decreasing in general only if `kappa t > 0`, but if `t = void`, then equal.
- `merge void t -> t`
  - `max 0 (kappa t) = kappa t`, so equal, not strict.
- `merge t void -> t`
  - equal.
- `merge t t -> t`
  - equal.
- `recDelta b s void -> b`
  - `max (max (kappa b) (kappa s)) 0 -> kappa b`; can be equal.
- `eqW a a -> void`
  - `max (kappa a) (kappa a) = kappa a -> 0`; can be equal if `kappa a = 0`.
- `eqW a b -> integrate (merge a b)`
  - both sides have measure `max (kappa a) (kappa b)`; exactly equal.

So `kappa` is **not** a strict descent measure for the whole system. But for the specific `recDelta` successor helper strategy, it is correct.

## Conclusion

Yes: the helper strategy embodied in `kappa_rec_delta_step` and `kappa_rec_succ_drop` is mathematically sound as written.

- `kappa_rec_delta_step` is true for all `b s n`.
- `kappa_rec_succ_drop` follows because `kappa(app s (recDelta b s n)) = kappa(recDelta b s n)` and the predecessor theorem gives a `+1` gap on the source.

So the helper lemmas are valid for proving strict decrease of the `R_rec_succ` rule, even though `kappa` is not by itself a strict termination measure for all rewrite rules in `Step`.
