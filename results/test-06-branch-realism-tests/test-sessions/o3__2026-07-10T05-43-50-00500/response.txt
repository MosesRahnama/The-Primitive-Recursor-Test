Conclusion : the two helper lemmas, and therefore the strategy that is supposed to rely on them, are NOT sound in the form written in the file.

Why `kappa_rec_delta_step` is false  
------------------------------------------------  
Put  

  b = void, s = void, n = delta void.  

Compute the two sides of the claimed equality.

1.  Left hand side  
    kappa (recDelta b s (delta n))
      = kappa (recDelta void void (delta (delta void)))
      = 0 + 1                      -- sixth equation of kappa  
      = 1.

2.  Right hand side  
    kappa (recDelta b s n) + 1
      = kappa (recDelta void void (delta void)) + 1
      = (0 + 1) + 1                -- sixth equation again  
      = 2.

Hence `1 = 2` would have to hold, so the lemma is false.  The reason is that in the
definition of `kappa`

    | .recDelta b s (.delta n) => … + 1
    | .recDelta b s n         => …

the first clause already covers the case where the third argument is a `delta`.
Therefore, if the `n` in the lemma itself is already a `delta`–term, the right-hand
expression is evaluated by the first clause as well, so the “extra + 1” that the
lemma postulates is not present.

Formally,

    kappa (recDelta b s (delta n))
      = kappa (recDelta b s n)          whenever n is itself (delta _).

Thus the lemma is only true when `n` is NOT of the form `delta _`; stated without
this side condition it is wrong.

Why `kappa_rec_succ_drop` is false  
----------------------------------  
The second lemma tries to use the first lemma to prove

    kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n)).

Take the same counter-example as above with b = s = void, n = delta void.

•  kappa (app s (recDelta b s n))
     = kappa (app void (recDelta void void (delta void)))
     = max 0 1
     = 1.

•  kappa (recDelta b s (delta n)) = 1   (computed above).

Hence the two sides are equal, not “<”.  In cases where `kappa s` is larger than
`kappa (recDelta b s n)`, the inequality can even fail in the opposite direction.

Therefore both helper lemmas are unsound in their present form; any termination
argument that depends on them is currently invalid.  One has to restrict the
statements to `n` that are **not** of the form `delta _` (or adjust `kappa`) in
order to obtain correct, usable lemmas.
