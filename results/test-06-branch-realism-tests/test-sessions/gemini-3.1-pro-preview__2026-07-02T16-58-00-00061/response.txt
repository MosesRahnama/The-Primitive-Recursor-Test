The helper strategy is **unsound**. Both `kappa_rec_delta_step` and `kappa_rec_succ_drop` are false statements and cannot be proven.

### The Problem
The fundamental flaw lies in how the structural measure `kappa` evaluates nested `.delta` constructors. 

According to your definition of `kappa`:
```lean
| .delta t => kappa t
| .recDelta b s (.delta n) => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1
```
The `.delta t` case ignores the `delta` and simply returns `kappa t`, meaning `kappa` strips away any number of nested `.delta`s without incrementing the measure. 

When `kappa` evaluates `recDelta b s (.delta n)`, it only matches the outermost `.delta`. It then calls `kappa n`, which immediately strips away any remaining `.delta`s. Because of this, `kappa` does not accurately count the depth of nested `delta`s. 

### Counterexample & Calculations
We can demonstrate that both theorems are false by evaluating them with the following assignment:
`b = .void`
`s = .void`
`n = .delta .void`

First, let's establish a few base evaluations:
- `kappa .void = 0`
- `kappa (.delta .void) = kappa .void = 0`
- `kappa (.recDelta .void .void (.delta .void))` matches the first `recDelta` case, which evaluates to `max (max 0 0) (kappa .void) + 1 = 0 + 1 = 1`.

#### 1. Disproving `kappa_rec_delta_step`
The theorem states: 
`kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

Let's evaluate the Left-Hand Side (LHS) and Right-Hand Side (RHS) using our counterexample variables:
* **LHS:** `kappa (recDelta .void .void (delta (delta .void)))`
  This matches the `.recDelta b s (.delta n)` pattern where `n` is `delta .void`.
  `= max (max (kappa .void) (kappa .void)) (kappa (delta .void)) + 1`
  `= max 0 (kappa .void) + 1 = 0 + 1 = 1`
* **RHS:** `kappa (recDelta .void .void (delta .void)) + 1`
  As established above, `kappa (recDelta .void .void (delta .void)) = 1`.
  `= 1 + 1 = 2`

**1 ≠ 2**, making `kappa_rec_delta_step` logically false.

#### 2. Disproving `kappa_rec_succ_drop`
The theorem states: 
`kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`

Using the same assignments:
* **LHS:** `kappa (app .void (recDelta .void .void (delta .void)))`

  `= max 0 1 = 1`
* **RHS:** `kappa (recDelta .void .void (delta (delta .void)))`
  As evaluated in the previous LHS calculation, this evaluates to `1`.

**1 < 1 is False**, making `kappa_rec_succ_drop` logically false as well.

### Conclusion
Because `kappa` collapses nested `.delta`s down to the same integer value instead of scaling with the `delta` depth, your two helper theorems are structurally untrue.
