Looking at the provided Lean 4 definitions, the helper strategy is **unsound**. Both theorems are invalid as written, with `kappa_rec_delta_step` being false when `n` is a successor, and `kappa_rec_succ_drop` yielding equality (not strict inequality) in that case.

Here is the detailed analysis:

## 1. Analysis of `kappa_rec_delta_step`

The theorem claims:
```lean
kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

Let us compute both sides using the definition of `kappa`:

**Left side:** `kappa (recDelta b s (delta n))`
By the first clause of the `recDelta` case in `kappa`:
$$= \max(\max(\kappa(b), \kappa(s)), \kappa(n)) + 1$$

**Right side:** `kappa (recDelta b s n) + 1`
This depends on whether `n` is itself of the form `delta n'`:

- **Case A:** If `n` is **not** of the form `delta n'`, then by the second clause:
  $$\kappa(\text{recDelta } b\ s\ n) = \max(\max(\kappa(b), \kappa(s)), \kappa(n))$$
  So the right side equals $\max(\max(\kappa(b), \kappa(s)), \kappa(n)) + 1$, matching the left side.

- **Case B:** If `n = delta n'` for some `n'`, then by the first clause:
  $$\kappa(\text{recDelta } b\ s\ n) = \kappa(\text{recDelta } b\ s\ (\delta n')) = \max(\max(\kappa(b), \kappa(s)), \kappa(n')) + 1$$
  
  Since $\kappa(\delta n') = \kappa(n')$, the left side becomes:
  $$\max(\max(\kappa(b), \kappa(s)), \kappa(n')) + 1$$
  
  The right side becomes:
  $$(\max(\max(\kappa(b), \kappa(s)), \kappa(n')) + 1) + 1 = \max(\max(\kappa(b), \kappa(s)), \kappa(n')) + 2$$

**Conclusion:** When `n` is a successor (`delta n'`), the theorem claims:
$$\max(\dots) + 1 = \max(\dots) + 2$$
which is false. The correct relationship is $\text{LHS} = \text{RHS} - 1$.

## 2. Analysis of `kappa_rec_succ_drop`

The theorem claims:
```lean
kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
```

Using the definition of `kappa` for `app`:
$$\kappa(\text{app } s\ (\text{recDelta } b\ s\ n)) = \max(\kappa(s), \kappa(\text{recDelta } b\ s\ n))$$

And for the right side (as computed above):
$$\kappa(\text{recDelta } b\ s\ (\delta n)) = \max(\max(\kappa(b), \kappa(s)), \kappa(n)) + 1$$

**Case where `n = delta n'`:**

- $\kappa(\text{recDelta } b\ s\ n) = \max(\max(\kappa(b), \kappa(s)), \kappa(n')) + 1$
- $\kappa(\text{app } s\ (\text{recDelta } b\ s\ n)) = \max(\kappa(s), \max(\max(\kappa(b), \kappa(s)), \kappa(n')) + 1)$
  
  Since $\max(\max(\kappa(b), \kappa(s)), \kappa(n')) + 1 \geq \max(\kappa(b), \kappa(s)) \geq \kappa(s)$, this simplifies to:
  $$= \max(\max(\kappa(b), \kappa(s)), \kappa(n')) + 1$$

- Meanwhile, $\kappa(\text{recDelta } b\ s\ (\delta n)) = \kappa(\text{recDelta } b\ s\ (\delta(\delta n')))$
  $$= \max(\max(\kappa(b), \kappa(s)), \kappa(\delta n')) + 1 = \max(\max(\kappa(b), \kappa(s)), \kappa(n')) + 1$$

**Conclusion:** When `n` is a successor, both sides equal $\max(\max(\kappa(b), \kappa(s)), \kappa(n')) + 1$, yielding equality, not strict inequality. The `<` relation is false.

## Concrete Counterexample

Let $b = \text{void}$, $s = \text{void}$, $n = \delta(\text{void})$:
- $\kappa(b) = 0$, $\kappa(s) = 0$, $\kappa(n) = \kappa(\text{void}) = 0$
- **LHS of step:** $\kappa(\text{recDelta } b\ s\ (\delta n)) = \max(\max(0,0), 0) + 1 = 1$
- **RHS of step:** $\kappa(\text{app } s\ (\text{recDelta } b\ s\ n))$
  - $\kappa(\text{recDelta } b\ s\ n) = \kappa(\text{recDelta void void } (\delta\text{ void})) = \max(\max(0,0), 0) + 1 = 1$
  - $\kappa(\text{app void } (\dots)) = \max(0, 1) = 1$
- Result: $1 < 1$ is **false**.

## Summary

The measure `kappa` fails to strictly decrease on the `R_rec_succ` step when the recursive argument `n` is already a successor term. The helper theorems are therefore unsound as written and cannot be used to prove termination of the rewrite system.
