## Verdict: The strategy is unsound — both helper lemmas are **false**, not merely unproven.

### Root cause

Look at the two clauses of `kappa` that fire for `recDelta`:

```
| .recDelta b s (.delta n) => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1
| .recDelta b s n          => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)
```

The "+1" bonus is added exactly once whenever the **outermost** third argument is a bare `delta _`. It is computed from `kappa n`, not from `kappa (recDelta b s n)`. So the "+1" does **not** compound when `n` itself already starts with `delta`. This makes `kappa_rec_delta_step` false whenever `n = delta m`.

### Counterexample

Take `b = s = void`, `n = delta void`.

- `kappa void = 0`
- `kappa (delta void) = kappa void = 0`
- `kappa (recDelta void void (delta void))`: matches the delta‑pattern with inner arg `void`, giving `max(max(0,0), kappa void) + 1 = 1`.
- `kappa (recDelta void void (delta (delta void)))` (this is `kappa (recDelta b s (delta n))`): matches the delta‑pattern with inner arg `delta void`, giving `max(max(0,0), kappa (delta void)) + 1 = max(0,0)+1 = 1`.

So:

* `kappa (recDelta b s (delta n)) = 1`
* `kappa (recDelta b s n) = 1`

**`kappa_rec_delta_step`** claims `1 = 1 + 1`, i.e. `1 = 2`. False.

More generally, for any `b,s,m`, taking `n := delta m`:
- LHS `kappa (recDelta b s (delta n)) = max(max(κb,κs), κm) + 1`
- RHS `kappa (recDelta b s n) + 1 = (max(max(κb,κs), κm) + 1) + 1`

These differ by exactly 1 in general, so the lemma is not a special edge case failure — it is systematically off whenever the recursion argument is itself `delta`-headed.

### The second lemma is independently false too

Using the same instantiation (`b = s = void`, `n = delta void`), directly (no need to invoke the broken rewrite):

- `kappa (recDelta b s n) = kappa (recDelta void void (delta void)) = 1`
- `kappa (app s (recDelta b s n)) = kappa (app void (recDelta void void (delta void))) = max(0,1) = 1`
- `kappa (recDelta b s (delta n)) = 1` (computed above)

So **`kappa_rec_succ_drop`** requires `1 < 1`, which is false. The measure does not strictly decrease across the `R_rec_succ` rewrite step `recDelta b s (delta n) ↦ app s (recDelta b s n)` when `n` is itself of the form `delta m`.

### Conclusion

Both `kappa_rec_delta_step` and `kappa_rec_succ_drop` are false statements (concrete counterexample: `b = s = void`, `n = delta void`), not just lemmas awaiting proof. The `sorry`s cannot be discharged in a sound proof system, so this `kappa` measure as defined cannot support the intended termination argument for the `R_rec_succ` rewrite rule. The definition of `kappa` would need to be changed (e.g., so that the recursive/third-argument term contributes recursively rather than via a flat one-shot "+1" tied only to the outermost constructor) before any such decreasing-measure lemma could hold.
