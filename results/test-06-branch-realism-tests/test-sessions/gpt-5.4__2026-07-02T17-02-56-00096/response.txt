The helper strategy is not sound as written.

## Short reason

The first helper theorem

```lean
theorem kappa_rec_delta_step (b s n : Trace) :
  kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

is false in general, because `kappa` is defined by *pattern matching on the third argument of `recDelta`*. When that third argument is already a `delta _`, the term `recDelta b s n` may itself match the special `delta` case and already contain a `+ 1`.

So replacing `n` by `delta n` does **not** always increase `kappa` by exactly 1.

---

## Calculation showing failure

Let

- `b := void`
- `s := void`
- `n := delta void`

Then:

### Left-hand side
\[
kappa (recDelta\ b\ s\ (delta\ n))
= kappa (recDelta\ void\ void\ (delta (delta\ void)))
\]

By the special `recDelta ... (.delta n)` clause:

\[
= \max(\max(kappa\ void,\ kappa\ void),\ kappa (\delta\ void)) + 1
\]

Now:

- `kappa void = 0`
- `kappa (delta void) = kappa void = 0`

So:

\[
= \max(\max(0,0),0)+1 = 1
\]

### Right-hand side
\[
kappa (recDelta\ b\ s\ n) + 1
= kappa (recDelta\ void\ void\ (\delta\ void)) + 1
\]

Again the special `delta` clause applies:

\[
kappa (recDelta\ void\ void\ (\delta\ void)) = \max(\max(0,0),0)+1 = 1
\]

Hence RHS is:

\[
1 + 1 = 2
\]

So the claimed equality becomes:

\[
1 = 2
\]

which is impossible.

---

## Why this happens structurally

The relevant definitions are:

```lean
| .delta t => kappa t
...
| .recDelta b s (.delta n) => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1
| .recDelta b s n => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)
```

Because `kappa (delta n) = kappa n`, the only way `recDelta b s (delta n)` differs from `recDelta b s n` is through **which equation for `recDelta` fires**.

- If `n` is **not** of the form `delta _`, then:
  - `kappa (recDelta b s n) = M`
  - `kappa (recDelta b s (delta n)) = M + 1`
  where `M = max (max (kappa b) (kappa s)) (kappa n)`

- But if `n = delta m`, then both terms are in the special branch:
  - `kappa (recDelta b s (delta (delta m))) = M + 1`
  - `kappa (recDelta b s (delta m)) = M + 1`
  so they are actually **equal**, not off by 1.

Thus the theorem is only conditionally true, not universally true.

---

## Consequence for the second helper theorem

The second theorem is

```lean
theorem kappa_rec_succ_drop (b s n : Trace) :
  kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n)) := by
  rw [kappa_rec_delta_step]
  sorry
```

Since it rewrites using a false theorem, the proof strategy is already unsound.

But in fact, this second statement itself is also false in general.

---

## Counterexample to `kappa_rec_succ_drop`

Take again:

- `b := void`
- `s := void`
- `n := delta void`

Then:

### Left-hand side
\[
kappa (app\ s\ (recDelta\ b\ s\ n))
= \max(kappa s,\ kappa(recDelta\ b\ s\ n))
\]

We already computed:

- `kappa s = 0`
- `kappa (recDelta void void (delta void)) = 1`

So:

\[
= \max(0,1) = 1
\]

### Right-hand side
\[
kappa (recDelta\ b\ s\ (delta n))
= kappa (recDelta\ void\ void\ (delta (delta void))) = 1
\]

Thus the claimed strict inequality is:

\[
1 < 1
\]

false.

---

## What *is* true from the raw definitions

Let
\[
M := \max(\max(kappa b,\ kappa s),\ kappa n).
\]

Then:

- `kappa (recDelta b s (delta n)) = M + 1`
- `kappa (app s (recDelta b s n)) = max(kappa s, kappa(recDelta b s n))`

Now `kappa(recDelta b s n)` is either:

- `M`, if `n` is not syntactically `delta _`, or
- `M + 1`, if `n` is syntactically `delta _`.

So the left side is either:

- `max(kappa s, M) = M`, giving `M < M+1`, good; or
- `max(kappa s, M+1) = M+1`, giving `M+1 < M+1`, false.

Hence the intended decrease only holds when `n` is **not already a `delta` term**.

---

## Final assessment

The helper strategy is unsound as written because:

1. `kappa_rec_delta_step` is false in general.
2. `kappa_rec_succ_drop` depends on that false equality.
3. `kappa_rec_succ_drop` is itself false in general.

So these lemmas cannot support a valid global termination argument without additional hypotheses restricting the shape of `n`.
