No. The helper strategy is not sound as written.

The key issue is that `kappa` treats `delta` as measure-preserving,

- `kappa (delta t) = kappa t`

but `kappa (recDelta b s n)` still distinguishes whether the third argument is *syntactically* of the form `delta _`:

- `kappa (recDelta b s (delta n)) = max (max (kappa b) (kappa s)) (kappa n) + 1`
- `kappa (recDelta b s n) = ...` with **no** `+1` unless `n` itself is syntactically `delta _`

So `kappa (recDelta b s n)` is not determined just by `kappa n`.

## First helper theorem is false

Claimed:

```lean
theorem kappa_rec_delta_step (b s n : Trace) :
  kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

Take `n = delta m`. Let

- `A := Nat.max (Nat.max (kappa b) (kappa s)) (kappa m)`.

Then:

- `kappa (recDelta b s (delta (delta m))) = A + 1`
- `kappa (recDelta b s (delta m)) = A + 1`

so the theorem would assert

- `A + 1 = (A + 1) + 1`

which is false.

Concrete counterexample: `b = void`, `s = void`, `n = delta void`.

Then:

- `kappa (recDelta void void (delta (delta void))) = 1`
- `kappa (recDelta void void (delta void)) + 1 = 1 + 1 = 2`

so it would say `1 = 2`.

## Second helper theorem is also false

Claimed:

```lean
theorem kappa_rec_succ_drop (b s n : Trace) :
  kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
```

Again take `n = delta m` and the same `A`.

Then:

- `kappa (recDelta b s (delta m)) = A + 1`
- `kappa (app s (recDelta b s (delta m))) = max (kappa s) (A + 1) = A + 1`
  because `A ≥ kappa s`
- `kappa (recDelta b s (delta (delta m))) = A + 1`

So the theorem becomes

- `A + 1 < A + 1`

which is false.

Concrete counterexample: `b = void`, `s = void`, `n = delta void`.

Then:

- `kappa (app void (recDelta void void (delta void))) = 1`
- `kappa (recDelta void void (delta (delta void))) = 1`

so it asserts `1 < 1`.

## What *is* true

These statements do work if `n` is **not** syntactically `delta _`. In that case:

- `kappa (recDelta b s n) = M`
- `kappa (recDelta b s (delta n)) = M + 1`

with `M := max (max (kappa b) (kappa s)) (kappa n)`,

and then indeed

- `kappa (app s (recDelta b s n)) = M < M + 1`.

But the theorems as stated quantify over **all** `n`, so they are false.

## Broader termination note

If the intended global strategy is “every `Step` strictly decreases `kappa`,” that also fails for other rules, e.g.

- `merge void t -> t` has equal `kappa`
- `merge t void -> t` has equal `kappa`
- `merge t t -> t` has equal `kappa`
- `eqW a b -> integrate (merge a b)` has equal `kappa`
- `integrate (delta void) -> void` has equal `kappa`

So `kappa` is not a strict one-step descent measure for the whole system.

Bottom line: the helper strategy is unsound as written; both helper theorems are false in general.
