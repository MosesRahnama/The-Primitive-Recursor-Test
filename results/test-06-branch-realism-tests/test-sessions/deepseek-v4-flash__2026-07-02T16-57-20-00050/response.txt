The helper theorems are unsound because they do not hold for all `Trace` arguments. The issue lies in the pattern matching in the definition of `kappa` for `recDelta`. The first clause only applies when the third argument is exactly `delta n`; if `n` itself is a `delta` term, the second clause for `recDelta b s n` also matches the first clause, leading to a different value than the one assumed in the lemmas.

**Counterexample to `kappa_rec_delta_step`:**  
Take `b = void`, `s = void`, `n = delta void`. Then:

- Left-hand side:  
  `kappa (recDelta void void (delta (delta void)))`  
  = `Nat.max (Nat.max (kappa void) (kappa void)) (kappa (delta void)) + 1`  
  = `Nat.max (Nat.max 0 0) (kappa void) + 1` = `0 + 1 = 1`.

- Right-hand side:  
  `kappa (recDelta void void (delta void)) + 1`  
  = `(Nat.max (Nat.max (kappa void) (kappa void)) (kappa void) + 1) + 1`  
  = `(0 + 1) + 1 = 2`.

Thus `1 = 2` is false.

**Counterexample to `kappa_rec_succ_drop`:**  
Using the same `b, s, n` as above:

- Left-hand side:  
  `kappa (app void (recDelta void void (delta void)))`  
  = `Nat.max (kappa void) (kappa (recDelta void void (delta void)))`  
  = `Nat.max 0 (1) = 1`.

- Right-hand side:  
  `kappa (recDelta void void (delta (delta void)))`  
  = `1` (from previous calculation).

So `1 < 1` is false.

These counterexamples show that the claimed equalities and inequalities are not universally valid. Therefore the helper strategy is **not sound** as written.
