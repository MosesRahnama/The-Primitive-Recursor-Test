The helper strategy is not sound. Both helper theorem statements are false because `kappa` treats `recDelta` specially whenever its third argument is syntactically a `delta`.

Take

```lean
b = void
s = void
n = delta void
```

Then:

```lean
kappa (recDelta void void (delta (delta void)))
  = max (max 0 0) (kappa (delta void)) + 1
  = 1
```

But

```lean
kappa (recDelta void void (delta void)) + 1
  = (max (max 0 0) (kappa void) + 1) + 1
  = 2
```

Thus `kappa_rec_delta_step` asserts `1 = 2` for this instance.

The same example refutes `kappa_rec_succ_drop`. Its left-hand side is

```lean
kappa (app void (recDelta void void (delta void)))
  = max 0 1
  = 1
```

while its right-hand side is

```lean
kappa (recDelta void void (delta (delta void))) = 1.
```

Hence the claimed strict inequality is `1 < 1`.

The underlying issue is that when `n = delta m`, the recursive occurrence

```lean
recDelta b s n
```

also matches the special `.delta` equation and already receives the `+ 1`. Consequently,

```lean
kappa (recDelta b s (delta n))
```

and

```lean
kappa (app s (recDelta b s n))
```

can be equal rather than strictly decreasing. The `sorry` placeholders allow Lean to accept these false propositions as assumptions, but they cannot be proved from the definitions as given.
