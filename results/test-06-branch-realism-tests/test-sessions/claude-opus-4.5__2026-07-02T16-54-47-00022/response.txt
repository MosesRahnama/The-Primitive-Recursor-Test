# Assessment of the Helper Strategy Soundness

## Overview

The helper strategy aims to prove that `kappa` decreases across the `R_rec_succ` rewrite step:
```
recDelta b s (delta n) → app s (recDelta b s n)
```

Let me analyze whether the two helper theorems are sound as stated.

## Analysis of `kappa_rec_delta_step`

**Claim:** `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

**LHS calculation:**
```
kappa (recDelta b s (delta n)) = max (max (kappa b) (kappa s)) (kappa n) + 1
```
This follows directly from the special case in the `kappa` definition.

**RHS calculation:**
```
kappa (recDelta b s n) + 1
```

Here's the problem: `kappa (recDelta b s n)` depends on the structure of `n`:
- If `n = delta m` for some `m`, then `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa m) + 1`
- If `n` is not of the form `delta m`, then `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n)`

**Case 1: `n` is not a `delta`**
- LHS = `max (max (kappa b) (kappa s)) (kappa n) + 1`
- RHS = `max (max (kappa b) (kappa s)) (kappa n) + 1`
- ✓ Equal

**Case 2: `n = delta m`**
- LHS = `max (max (kappa b) (kappa s)) (kappa (delta m)) + 1 = max (max (kappa b) (kappa s)) (kappa m) + 1`
- RHS = `kappa (recDelta b s (delta m)) + 1 = (max (max (kappa b) (kappa s)) (kappa m) + 1) + 1`
- ✗ **Not equal** (off by 1)

**Conclusion:** `kappa_rec_delta_step` is **FALSE** when `n` is itself a `delta` term.

## Analysis of `kappa_rec_succ_drop`

**Claim:** `kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`

**RHS:** `max (max (kappa b) (kappa s)) (kappa n) + 1`

**LHS:** 
```
kappa (app s (recDelta b s n)) = max (kappa s) (kappa (recDelta b s n))
```

For this to hold, we need:
```
max (kappa s) (kappa (recDelta b s n)) < max (max (kappa b) (kappa s)) (kappa n) + 1
```

**Counterexample:** Let `b = void`, `s = void`, `n = delta void`.

- `kappa (recDelta void void (delta void))`:
  - This matches the special case: `max (max 0 0) (kappa void) + 1 = max 0 0 + 1 = 1`

- `kappa (app void (recDelta void void (delta void)))`:
  - `kappa (recDelta void void (delta void)) = max (max 0 0) 0 + 1 = 1`
  - `kappa (app void ...) = max 0 1 = 1`

- We need `1 < 1`, which is **FALSE**.

## Conclusion

**The helper strategy is UNSOUND.**

1. **`kappa_rec_delta_step`** fails when `n` is itself a `delta` term, because the `kappa` function has a special +1 case for `recDelta b s (delta n)`, so nesting deltas accumulates additional +1 terms.

2. **`kappa_rec_succ_drop`** has counterexamples even for simple terms. The measure `kappa` does not strictly decrease across the `R_rec_succ` step because `kappa (recDelta b s n)` can equal `max (max (kappa b) (kappa s)) (kappa n) + 1` when `n` is a delta, matching the "+1" bonus on the LHS.

The fundamental issue is that `kappa` only adds +1 for *one level* of `delta` wrapping in the third argument position, but the rewrite step may preserve or even increase this count depending on the structure of `n`.
