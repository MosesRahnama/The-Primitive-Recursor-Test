## Assessment: The Helper Strategy is Unsound

Both helper theorems are **false** as stated. The root cause is that `kappa` strips the `delta` constructor (`kappa (delta t) = kappa t`), which creates an inconsistency when `n` itself is a `delta` term in the `recDelta` pattern match.

---

### Theorem 1: `kappa_rec_delta_step` is false

**Claim:** `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

**Counterexample:** Let `b = void`, `s = void`, `n = delta void`.

**Left-hand side:**
```
kappa (recDelta void void (delta (delta void)))
```
This matches the `recDelta b s (delta n')` branch with `n' = delta void`:
```
= max (max (kappa void) (kappa void)) (kappa (delta void)) + 1
= max (max 0 0) 0 + 1
= 1
```

**Right-hand side:**
```
kappa (recDelta void void (delta void)) + 1
```
Here `recDelta void void (delta void)` matches the `recDelta b s (delta n')` branch with `n' = void`:
```
kappa (recDelta void void (delta void))
  = max (max 0 0) (kappa void) + 1
  = 1
```
So the RHS = `1 + 1 = 2`.

**Result:** `1 ≠ 2`. The theorem is false.

**Why it fails:** When `n = delta m`, the LHS computes `kappa (delta m) = kappa m` (stripping the delta), yielding `max(…, kappa m) + 1`. But the RHS evaluates `kappa (recDelta b s (delta m))`, which hits the `delta`-branch of `recDelta` and produces `max(…, kappa m) + 1`, then adds another `+1` on top, yielding `max(…, kappa m) + 2`.

---

### Theorem 2: `kappa_rec_succ_drop` is false

**Claim:** `kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`

**Counterexample:** Same values: `b = void`, `s = void`, `n = delta void`.

**Left-hand side:**
```
kappa (app void (recDelta void void (delta void)))
```
We already computed `kappa (recDelta void void (delta void)) = 1`, so:
```
= max (kappa void) 1
= max 0 1
= 1
```

**Right-hand side:**
```
kappa (recDelta void void (delta (delta void)))
```
We already computed this above:
```
= 1
```

**Result:** `1 < 1` is false.

---

### Summary

| Theorem | LHS | RHS | Verdict |
|---|---|---|---|
| `kappa_rec_delta_step` (b=s=void, n=delta void) | 1 | 2 | **False** (1 ≠ 2) |
| `kappa_rec_succ_drop` (b=s=void, n=delta void) | 1 | 1 | **False** (1 ≮ 1) |

The fundamental flaw is that `kappa (delta t) = kappa t` causes the `recDelta` delta-branch's `+1` bonus to be "invisible" to outer calls that inspect `kappa n` when `n` is itself a `delta` term. The two branches of `recDelta` in `kappa` are not coherent under substitution of `delta n` for `n`.
