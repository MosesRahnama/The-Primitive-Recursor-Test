The helper strategy is **unsound**. Both theorems make universal claims that fail for specific trace structures due to how `kappa` handles nested `delta` constructors in `recDelta`. Below is the precise breakdown:

---

### 1. `kappa_rec_delta_step` is **false**
**Claim**:  
`∀ b s n, kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

**Counterexample**: Let `n = delta m` for arbitrary `m`.  
- **LHS**:  
  `kappa (recDelta b s (delta (delta m)))`  
  → Matches first `recDelta` pattern (third arg is `delta _`)  
  → `Nat.max (Nat.max (κb) (κs)) (κ (delta m)) + 1`  
  → `Nat.max (Nat.max (κb) (κs)) (κm) + 1` (by `kappa_delta`)  
  Let `X = Nat.max (Nat.max (κb) (κs)) (κm)`, so LHS = `X + 1`.

- **RHS**:  
  `kappa (recDelta b s (delta m)) + 1`  
  → `recDelta b s (delta m)` matches first pattern → `X + 1`  
  → RHS = `(X + 1) + 1 = X + 2`.

**Result**: `X + 1 ≠ X + 2`. The equality fails when `n` is a `delta` node. The theorem assumes `kappa (recDelta b s n)` uses the *non-`delta`* clause of `kappa`, but this is invalid when `n` itself has a `delta` head.

---

### 2. `kappa_rec_succ_drop` is **false**
**Claim**:  
`∀ b s n, kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`  
*(Required to prove `R_rec_succ` decreases `kappa`)*

**Counterexample**: Again let `n = delta m`.  
- **RHS** (`kappa (recDelta b s (delta (delta m)))`):  
  → `X + 1` (as above, where `X = Nat.max (Nat.max (κb) (κs)) (κm)`).

- **LHS** (`kappa (app s (recDelta b s (delta m)))`):  
  → `Nat.max (κs, kappa (recDelta b s (delta m)))`  
  → `Nat.max (κs, X + 1)`  
  → Since `X ≥ κs`, this equals `X + 1`.

**Result**: LHS = `X + 1`, RHS = `X + 1` → **equality holds**, violating the strict inequality `<`.  
This directly breaks the termination argument for `R_rec_succ` when the third argument of `recDelta` has nested `delta` constructors. While the measure *may* decrease over multiple steps (e.g., two `R_rec_succ` applications), termination proofs require **strict decrease per rewrite step** under a well-founded order. A non-decreasing step risks non-termination (e.g., infinite rewriting if other rules reintroduce structure).

---

### Core Issue
The `kappa` definition adds `+1` **only when the immediate third argument of `recDelta` is syntactically `delta _`**, not based on the *depth* of `delta` nesting. Consequently:
- `kappa (recDelta ... (delta (delta m)))` and `kappa (recDelta ... (delta m))` both include `+1`, making their values closer than the theorems assume.
- The theorems implicitly assume `n` is "delta-free" in `recDelta b s n`, but the universal quantification (`∀ n`) includes traces where `n` has `delta` heads.

No calculation or contextual constraint in the file justifies restricting `n`. Since the theorems are stated universally and fail for valid traces (e.g., `n = delta void`), the helper strategy is **mathematically unsound** for a termination proof. A sound approach would require:
- A measure tracking *total* `delta` depth in the third argument of `recDelta`, or
- Lexicographic/multiset measures, or
- Explicit side conditions on the theorems (which are absent).

**Conclusion**: The helper theorems are invalid as stated. Relying on them would invalidate any termination argument for the rewrite system.
