The helper strategy is **not sound**. Both stated helper theorems are false because `kappa` treats every `recDelta` whose third argument begins with `delta` using the special `+ 1` branch, including nested deltas.

Take:

```lean
b = void
s = void
n = delta void
```

Since all underlying `kappa` values are `0`:

```lean
kappa (recDelta void void (delta (delta void))) = 1
```

But:

```lean
kappa (recDelta void void (delta void)) + 1 = 1 + 1 = 2
```

Thus `kappa_rec_delta_step` would assert `1 = 2`.

The second theorem also fails for the same example. Its left side is:

```lean
kappa (app void (recDelta void void (delta void)))
= max 0 1
= 1
```

while its right side is:

```lean
kappa (recDelta void void (delta (delta void))) = 1
```

so the claimed strict inequality is `1 < 1`.

More generally, if `n = delta m` and

```lean
A = max (max (kappa b) (kappa s)) (kappa m),
```

then both sides of the `R_rec_succ` step have measure `A + 1`:

```lean
kappa (recDelta b s (delta (delta m))) = A + 1
```

and

```lean
kappa (app s (recDelta b s (delta m))) = A + 1.
```

Therefore `kappa` does decrease for `R_rec_succ` when `n` does not begin with `delta`, but it does **not** decrease when `n` itself is a `delta`. Consequently, the proposed lemmas cannot support a global strict-decrease termination argument as written.
