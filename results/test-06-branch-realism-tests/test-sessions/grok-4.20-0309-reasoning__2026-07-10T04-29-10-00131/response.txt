The provided helper theorems are not sound (i.e., `kappa_rec_delta_step` is not a theorem, and the strict decrease claimed by `kappa_rec_succ_drop` does not always hold).

**Counterexample calculations** (let `b = void`, `s = void`, `n = delta void`):

- `kappa b = 0`, `kappa s = 0`, `kappa n = 0`.
- `kappa(recDelta b s n) = kappa(recDelta void void (delta void)) = Nat.max(Nat.max(0, 0), 0) + 1 = 1` (third arg matches the `(.delta _)` case).
- `kappa(recDelta b s (delta n)) = kappa(recDelta void void (delta (delta void))) = Nat.max(Nat.max(0, 0), 0) + 1 = 1`.
- Thus `kappa_rec_delta_step` fails: `1 ≠ 1 + 1`.
- `kappa(app s (recDelta b s n)) = kappa(app void (recDelta void void (delta void))) = Nat.max(0, 1) = 1`.
- Thus `kappa_rec_succ_drop` fails: `1 ≮ 1` (equality, not strict decrease).

(The claimed relations hold for some but not all inputs, e.g., they hold if `n = void` but fail as above if `n` matches the `delta` constructor.)

**End-to-end termination argument.** The `Step` relation is not guaranteed to strictly decrease `kappa` (e.g., `R_rec_succ` yields `kappa` equality in the counterexample above). Thus `kappa` is not a valid termination measure for the calculus.
