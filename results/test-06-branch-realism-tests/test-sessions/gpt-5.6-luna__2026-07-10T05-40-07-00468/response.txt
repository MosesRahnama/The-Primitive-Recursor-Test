The helper strategy is not sound as written. Both theorems are false for some `n`, because `kappa` gives an extra `+1` whenever the third argument of `recDelta` is syntactically a `delta`.

Take:

```lean
b := void
s := void
n := delta void
```

Since `kappa void = 0` and `kappa (delta void) = 0`:

```text
kappa (recDelta void void (delta n))
  = max (max 0 0) (kappa (delta void)) + 1
  = 1
```

But:

```text
kappa (recDelta void void n) + 1
  = kappa (recDelta void void (delta void)) + 1
  = (max (max 0 0) (kappa void) + 1) + 1
  = 2
```

Thus `kappa_rec_delta_step` asserts `1 = 2` in this instance, so it cannot be proved.

The second theorem also fails for the same example:

```text
kappa (app void (recDelta void void (delta void)))
  = max 0 1
  = 1
```

while:

```text
kappa (recDelta void void (delta (delta void)))
  = max (max 0 0) (kappa (delta void)) + 1
  = 1
```

Therefore it would require `1 < 1`.

The intended inequalities hold only when `n` is not itself of the form `delta m`. If `n = delta m`, the recursive `recDelta` term already receives the extra `+1`, and wrapping it in another `delta` causes the two sides of the proposed comparison to have equal `kappa` rather than a strict decrease.
