The helper strategy is not sound. Both helper theorems are false when `n` itself has the form `delta m`.

Let

\[
M = \max(\max(\kappa b)(\kappa s))(\kappa m)
\]

and take `n = delta m`. Since `kappa (delta m) = kappa m`:

\[
\kappa(\mathrm{recDelta}\ b\ s\ (\delta(\delta m))) = M+1.
\]

But the right-hand side of `kappa_rec_delta_step` is

\[
\begin{aligned}
\kappa(\mathrm{recDelta}\ b\ s\ (\delta m))+1
&= (M+1)+1\\
&= M+2.
\end{aligned}
\]

Thus the theorem would assert `M + 1 = M + 2`.

A concrete counterexample is `b = s = m = void`:

```text
kappa (recDelta void void (delta (delta void))) = 1
kappa (recDelta void void (delta void)) + 1 = 2
```

So `kappa_rec_delta_step` is false.

The strict-drop theorem fails for the same case. With `n = delta m`:

\[
\kappa(\mathrm{recDelta}\ b\ s\ n)=M+1.
\]

Because `M` is at least `kappa s`,

\[
\begin{aligned}
\kappa(\mathrm{app}\ s\ (\mathrm{recDelta}\ b\ s\ n))
&=\max(\kappa s)(M+1)\\
&=M+1.
\end{aligned}
\]

The source also has measure

\[
\kappa(\mathrm{recDelta}\ b\ s\ (\delta n))=M+1.
\]

Hence the recursive-successor rule preserves `kappa`, rather than decreasing it, whenever `n` is itself a `delta`:

```text
kappa (app void (recDelta void void (delta void))) = 1
kappa (recDelta void void (delta (delta void))) = 1
```

The underlying issue is that the special `recDelta ... (.delta n)` equation examines the constructor shape of its third argument. Stripping one `delta` can reveal another special case, so the claimed uniform “exactly one more” relationship does not hold. It would hold only when `n` is not itself headed by `delta`.

The `sorry` declarations can admit these false propositions, but any termination argument relying on them is therefore invalid.
