I'll analyze whether these two helper theorems are provable as stated.

## Theorem 1: `kappa_rec_delta_step`

Claim: `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

**LHS** (via `kappa_rec_delta`): `max (max (kappa b) (kappa s)) (kappa n) + 1`

**RHS**: `kappa (recDelta b s n) + 1`, where `kappa (recDelta b s n)` depends on the shape of `n`.

Here's the critical issue: `kappa` on `recDelta` pattern-matches on the **third argument**. There are two cases:

- If `n = delta m` for some `m`, then `recDelta b s n` matches the **first** `recDelta` clause:
  `kappa (recDelta b s (delta m)) = max (max (kappa b) (kappa s)) (kappa m) + 1`
- Otherwise, `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n)`.

**Case n is not of the form `delta m`** (e.g., `n = void`):
- RHS `= max (max (kappa b) (kappa s)) (kappa n) + 1`
- LHS `= max (max (kappa b) (kappa s)) (kappa n) + 1` ✓ These match.

**Case `n = delta m`:**
- LHS `= max (max (kappa b) (kappa s)) (kappa (delta m)) + 1 = max (max (kappa b) (kappa s)) (kappa m) + 1`
- RHS `= kappa (recDelta b s (delta m)) + 1 = [max (max (kappa b) (kappa s)) (kappa m) + 1] + 1`

So LHS `= X + 1` while RHS `= X + 2`, where `X = max (max (kappa b) (kappa s)) (kappa m)`. **These differ by 1.**

**Conclusion: Theorem 1 is FALSE.** Concrete counterexample: take `b = s = void`, `n = delta void`.
- `kappa (recDelta void void (delta (delta void)))` = `max (max 0 0) (kappa (delta void)) + 1` = `0 + 1` = `1`.
- `kappa (recDelta void void (delta void)) + 1` = `(max (max 0 0) 0 + 1) + 1` = `1 + 1` = `2`.
- `1 = 2` is false.

So `kappa_rec_delta_step` cannot be proved (the `sorry` is unfillable).

## Theorem 2: `kappa_rec_succ_drop`

Claim: `kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`

The proof begins with `rw [kappa_rec_delta_step]`, rewriting the RHS to `kappa (recDelta b s n) + 1`. The remaining goal is:

`kappa (app s (recDelta b s n)) < kappa (recDelta b s n) + 1`

i.e. `max (kappa s) (kappa (recDelta b s n)) < kappa (recDelta b s n) + 1`.

This is **not** provable in general! We need `kappa s < kappa (recDelta b s n) + 1`, i.e. `kappa s ≤ kappa (recDelta b s n)`. When `n` is not of `delta` form, `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n) ≥ kappa s`, so that side is fine. But regardless, this theorem *itself* is even the actual target statement, and its truth must be examined directly too.

Let me check the **original statement** of Theorem 2 directly (independent of the broken rewrite):
`max (kappa s) (kappa (recDelta b s n))  <  kappa (recDelta b s (delta n))`

By `kappa_rec_delta`, RHS `= max (max (kappa b) (kappa s)) (kappa n) + 1`. Let `M = max (max (kappa b) (kappa s)) (kappa n)`.
- `kappa s ≤ M < M + 1` ✓
- Need `kappa (recDelta b s n) < M + 1`, i.e. `kappa (recDelta b s n) ≤ M`.
  - If `n` not `delta`-form: `kappa (recDelta b s n) = M ≤ M` ✓
  - If `n = delta m`: `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa m) + 1`. Here `M = max (max (kappa b) (kappa s)) (kappa (delta m)) = max(max (kappa b) (kappa s)) (kappa m)`. So `kappa (recDelta b s n) = M + 1 ≤ M`? **FALSE.**

So even the target statement of Theorem 2 is **false** when `n` has the form `delta m` (with the higher of the branches). Counterexample: `b = s = void`, `n = delta void`:
- LHS: `kappa (app void (recDelta void void (delta void)))` = `max 0 (max (max 0 0) 0 + 1)` = `max 0 1` = `1`.
- RHS: `kappa (recDelta void void (delta (delta void)))` = `max (max 0 0) (kappa (delta void)) + 1` = `1`.
- `1 < 1` is false.

## Overall Assessment

**The helper strategy is UNSOUND as written.** The root cause is that `kappa` only adds `+1` at a single `delta`-guard layer instead of counting all nested `delta`s. Consequently:

1. `kappa_rec_delta_step` is false (fails whenever `n = delta m`; discrepancy is 1 vs 2).
2. `kappa_rec_succ_drop` is false as a statement (fails whenever `n = delta m`; e.g., `b = s = void, n = delta void` gives `1 < 1`), and additionally its proof depends on the already-unprovable Theorem 1.

Both `sorry`s are unfillable. To fix this, `kappa` would need to count nested `delta` layers under `recDelta` (e.g., add `kappa n + 1` or recurse so that each `delta` contributes to the measure), so that stripping one `delta` via `R_rec_succ` strictly decreases the measure uniformly.
