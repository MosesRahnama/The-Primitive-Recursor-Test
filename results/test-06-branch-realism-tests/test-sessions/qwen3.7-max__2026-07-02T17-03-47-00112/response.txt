# Assessment: The Helper Strategy is **Unsound**

## Root Cause

The measure `kappa` is transparent to `delta`:

```
kappa (delta t) = kappa t
```

This means `kappa` cannot distinguish a term `n` from `delta n`. However, the `recDelta` clause in `kappa` awards a `+1` bonus based on whether the third argument is *syntactically* a `delta`:

```lean
| .recDelta b s (.delta n) => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1
| .recDelta b s n          => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)
```

This creates a critical mismatch when `n` is itself of the form `delta n'`.

---

## Concrete Counterexample

Let `b = void`, `s = void`, `n' = void`, and `n = delta void`.

Recall `kappa void = 0` and `kappa (delta void) = 0`.

### Theorem 1: `kappa_rec_delta_step` claims `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

**LHS:** `kappa (recDelta void void (delta (delta void)))`
The third argument `delta (delta void)` matches `.delta n` with pattern variable `n ↦ delta void`:
$$= \max(\max(0, 0),\; \kappa(\delta\;\text{void})) + 1 = \max(0, 0) + 1 = 1$$

**RHS:** `kappa (recDelta void void (delta void)) + 1`
The third argument `delta void` matches `.delta n` with pattern variable `n ↦ void`:
$$= (\max(\max(0, 0),\; \kappa(\text{void})) + 1) + 1 = (0 + 1) + 1 = 2$$

**Result:** $1 \neq 2$. The theorem is **false**.

### Theorem 2: `kappa_rec_succ_drop` claims `kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`

**LHS:** `kappa (app void (recDelta void void (delta void)))`
$$= \max(\kappa(\text{void}),\; \kappa(\text{recDelta void void}(\delta\;\text{void})))$$
$$= \max(0,\; 1) = 1$$

**RHS:** `kappa (recDelta void void (delta (delta void)))`
$$= 1 \quad \text{(computed above)}$$

**Result:** $1 < 1$ is **false**.

---

## Why Both Theorems Fail in General

For any `n = delta n'`, we get:

| Expression | Value |
|---|---|
| `kappa (recDelta b s (delta n))` | `max(max(κb, κs), κn') + 1` |
| `kappa (recDelta b s n)` | `max(max(κb, κs), κn') + 1` |

These are **equal**, because `kappa n = kappa (delta n') = kappa n'`. The extra `delta` wrapping is invisible to `kappa`, so:

- `kappa_rec_delta_step` claims a difference of `+1` where the difference is actually `0`.
- `kappa_rec_succ_drop` claims a strict decrease where the two sides are actually equal.

## Fix Required

The measure `kappa` must count `delta` depth in the third argument of `recDelta`. For example, changing the `delta` clause to:

```lean
| .delta t => kappa t + 1
```

would make `kappa` sensitive to `delta` nesting and restore the validity of both helper theorems (with appropriately adjusted arithmetic). Alternatively, one could define a separate depth-counting function for the third argument of `recDelta`.
