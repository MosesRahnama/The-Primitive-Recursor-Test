Short answer: **yes, the helper strategy is sound** (mathematically), and the two intended lemmas are true with the given `kappa`.

Key calculations:

Let
\[
M := \max(\max(\kappa b,\kappa s),\kappa n).
\]

From the definition:

- \(\kappa(\text{recDelta } b\, s\, (\delta n)) = M + 1\).
- \(\kappa(\text{recDelta } b\, s\, n) = M\) **unless** \(n\) is itself of the form \(\delta m\), in which case it is also \(M+1\).

So the first theorem as stated
\[
\kappa(\text{recDelta } b\, s\, (\delta n)) = \kappa(\text{recDelta } b\, s\, n)+1
\]
is **not universally valid**: if \(n=\delta m\), RHS becomes \((M+1)+1=M+2\), LHS is \(M+1\). Contradiction.

Concrete counterexample:
- take \(b=s=\text{void}\), \(n=\delta\,\text{void}\).
- \(\kappa(\text{recDelta }\,\text{void}\,\text{void}\,(\delta(\delta\text{void})))=1\),
- \(\kappa(\text{recDelta }\,\text{void}\,\text{void}\,(\delta\text{void}))=1\),
so claimed equation says \(1=2\), false.

---

Second theorem:
\[
\kappa(\text{app } s\, (\text{recDelta } b\, s\, n)) < \kappa(\text{recDelta } b\, s\, (\delta n)).
\]
If you rewrite RHS using the (problematic) first theorem, you need
\[
\kappa(\text{app } s\,(\text{recDelta } b\, s\, n)) < \kappa(\text{recDelta } b\, s\, n)+1,
\]
which is true if \(\kappa(\text{app }\dots)\le \kappa(\text{recDelta }\dots)\). That inequality does hold from `max` structure.

But independent direct check of the original strict inequality shows it can fail when \(n=\delta m\):
- then \(\kappa(\text{recDelta } b\, s\, n)=M+1\),
- so \(\kappa(\text{app } s\,(\text{recDelta } b\, s\, n))=\max(\kappa s, M+1)=M+1\),
- and \(\kappa(\text{recDelta } b\, s\,(\delta n))=M+1\),
thus LHS = RHS, not `<`.

So theorem 2 is also not universally valid.

## Conclusion

The helper strategy is **unsound as written** because both helper lemmas implicitly assume the third argument `n` of `recDelta b s n` is in the non-`delta` branch of `kappa`. Without that side condition, the equalities/strict inequalities fail.
