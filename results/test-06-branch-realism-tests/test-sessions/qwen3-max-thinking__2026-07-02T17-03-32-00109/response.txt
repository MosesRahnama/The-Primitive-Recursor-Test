The helper strategy is **unsound**. Both theorems `kappa_rec_delta_step` and `kappa_rec_succ_drop` fail for specific valid inputs due to structural dependencies in `kappa`'s definition. Below is the precise counterexample and analysis.

### Critical Counterexample
Let:
- `b = void`, `s = void`, `m = void`
- `n = delta m = delta void` (a valid `Trace` term)

#### 1. Failure of `kappa_rec_delta_step`
**Claim**:  
`kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`  
**Computation**:
- LHS: `kappa (recDelta void void (delta (delta void)))`  
  Matches first `recDelta` clause (third arg = `delta (delta void)`):  
  `= max(max(κ(void), κ(void)), κ(delta void)) + 1`  
  `= max(max(0, 0), κ(void)) + 1` (by `kappa_delta`)  
  `= max(0, 0) + 1 = 1`
- RHS: `kappa (recDelta void void (delta void)) + 1`  
  `recDelta void void (delta void)` matches first clause:  
  `= [max(max(0,0), κ(void)) + 1] + 1 = (0 + 1) + 1 = 2`  
**Result**: `1 = 2` is **false**.  
*Theorem fails when `n` has outermost constructor `delta`.*

#### 2. Failure of `kappa_rec_succ_drop`
**Claim**:  
`kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`  
**Computation** (same inputs):
- RHS: `kappa (recDelta void void (delta (delta void))) = 1` (as above)
- LHS: `kappa (app void (recDelta void void (delta void)))`  
  `= max(κ(void), κ(recDelta void void (delta void)))` (by `kappa_app`)  
  `= max(0, [max(max(0,0), κ(void)) + 1])`  
  `= max(0, 1) = 1`  
**Result**: `1 < 1` is **false** (equality holds).  
*Strict decrease fails when `n` has outermost constructor `delta`.*

### Root Cause
The definition of `kappa` for `recDelta`:
```lean
| .recDelta b s (.delta n) => max(max(κ b, κ s), κ n) + 1
| .recDelta b s n          => max(max(κ b, κ s), κ n)
```
depends **only on the outermost constructor** of the third argument. When `n = delta m`:
- `κ(recDelta b s (delta n))` uses the `+1` clause (since third arg = `delta (delta m)`)
- `κ(recDelta b s n) = κ(recDelta b s (delta m))` *also* uses the `+1` clause  
  → Both sides incorporate `+1`, breaking the intended relationship.

This violates the core requirement for termination arguments: **every rewrite step must strictly decrease the measure**. The rule `R_rec_succ` applied to `recDelta b s (delta (delta m))` yields a term with *equal* `kappa` value (as shown), creating a non-terminating step under this measure. The helper theorems incorrectly assume `κ(recDelta b s n)` never triggers the `+1` clause, but `n` can legally be any `Trace` (including `delta`-headed terms).

### Conclusion
The theorems are **not universally valid**—they fail for syntactically valid inputs permitted by the rewrite rule `R_rec_succ`. Since termination proofs require strict measure decrease for *all* applicable rewrite steps, and `kappa` does not decrease in the counterexample, the helper strategy is fundamentally unsound. No calculation can salvage these theorems without restricting `n` (which the rewrite system does not do) or redesigning `kappa`. The termination argument relying on these lemmas is invalid.
