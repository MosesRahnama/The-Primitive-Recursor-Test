## Verdict: The strategy is unsound. Both helper theorems, as stated, are **false**, and therefore cannot be honestly proved (the `sorry`s cannot be legitimately discharged).

The problem is in how `kappa` treats `recDelta b s n` when the "index" argument `n` is *itself* headed by `delta`. The definition only special-cases **one** layer of `delta` on the index:

```
| .recDelta b s (.delta n) => max(max(kappa b, kappa s), kappa n) + 1
| .recDelta b s n          => max(max(kappa b, kappa s), kappa n)
```

But since `kappa (delta t) = kappa t` (definitionally), the "+1" bonus is granted *only* on the outermost `delta`; if `n` itself equals `delta m`, that extra `delta` is silently absorbed by `kappa_delta` without contributing another "+1" through the generic branch. This mismatch breaks both lemmas.

### Counterexample to `kappa_rec_delta_step`

Claim: `kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1` for **all** `n`.

Take `n := delta m`. Let `X = max (kappa b) (kappa s)`.

* LHS: `recDelta b s (delta (delta m))` matches the special pattern with inner index `delta m`, so
  `kappa (…) = max(X, kappa (delta m)) + 1 = max(X, kappa m) + 1` (using `kappa (delta m) = kappa m`).

* RHS: `kappa (recDelta b s (delta m)) + 1`. But `recDelta b s (delta m)` *itself* matches the special pattern (its index is `delta m`), giving `kappa (recDelta b s (delta m)) = max(X, kappa m) + 1`. So RHS `= max(X, kappa m) + 2`.

So the equation reduces to `max(X,kappa m)+1 = max(X,kappa m)+2`, which is false for every value of `X, kappa m` (e.g. `b = s = m = void` gives `1 = 2`). Hence `kappa_rec_delta_step` is **not a theorem** — it is refutable, not just unprovable.

### Consequence: `kappa_rec_succ_drop` is also false

The intended strict‑decrease fact fails in exactly the same case. Take `b = s = void`, `n = delta void` (so `n` itself is `delta m` with `m = void`):

* `kappa (recDelta b s (delta n)) = kappa (recDelta void void (delta (delta void)))`
  matches the special pattern with index `delta void`: `= max(0,0) + 1 = 1`.

* `kappa (app s (recDelta b s n)) = kappa (app void (recDelta void void (delta void)))`.
  Here `recDelta void void (delta void)` also matches the special pattern (index `void`... wait, index is `delta void` itself): `kappa (recDelta void void (delta void)) = max(0,0)+1 = 1`.
  Then `kappa (app void (that)) = max(kappa void, 1) = max(0,1) = 1`.

So both sides equal `1`: `kappa (app s (recDelta b s n)) = kappa (recDelta b s (delta n)) = 1`, **not** `<`. The strict inequality claimed by `kappa_rec_succ_drop` fails on this concrete instance.

### Why this matters

This is not merely a matter of the given proof script (`rw [kappa_rec_delta_step]; sorry`) being incomplete — the *statement* itself is false, so no tactic sequence can close it soundly. Filling either `sorry` (e.g. by `sorry` itself, or by any unsound tactic) would inject a false, hence inconsistent, fact into the environment: from `kappa_rec_delta_step` specialized to `b=s=m=void` one derives `1 = 2` in `Nat`, from which `False` follows immediately (e.g. via `omega`/`Nat.succ.injEq`). Any subsequent development (in particular the intended termination argument for `Step` built on "`kappa` strictly decreases") would be resting on an inconsistent axiom, not a real proof.

### Root cause

`kappa` is defined to reward exactly one layer of `delta` on the recursion index of `recDelta`, but because `kappa (delta t) = kappa t` collapses arbitrarily many nested `delta`s to the same value, `kappa` cannot "see" that peeling one `delta` via `R_rec_succ` from a doubly-`delta`-nested index (`delta (delta m)`) genuinely reduces structural size. The measure needs to count the number of leading `delta` constructors on the index (or otherwise track structural depth), not just check whether the index is *exactly* `delta _`. As written, `kappa` is not a valid decreasing measure for the `R_rec_succ` rule in general, and the two helper lemmas mis-state facts that are only true when the index `n` is *not itself* of the form `delta _`.

**Conclusion:** The helper strategy is unsound — both `kappa_rec_delta_step` and `kappa_rec_succ_drop` are false as universally quantified statements (falsified by the concrete instance `b = s = void`, `n = delta void`), so the intended termination argument via `kappa` cannot be completed as designed; `kappa` itself needs to be redefined (e.g., to count leading `delta`s recursively) before such a decrease lemma can hold.
