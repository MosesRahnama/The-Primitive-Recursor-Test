The helper strategy is **unsound** as written. Both `kappa_rec_delta_step` and `kappa_rec_succ_drop` are false. 

The underlying flaw is that the measure `kappa (delta t)` is defined as exactly `kappa t` rather than `kappa t + 1`. When computing the measure of `recDelta b s n`, the pattern match `| .recDelta b s (.delta n)` adds 1, but nesting multiple `delta`s does not continue to increase the measure.

We can prove this by evaluating both theorems with the counterexample **`b = void`**, **`s = void`**, and **`n = delta void`**. 

### 1. Disproving `kappa_rec_delta_step`
The theorem claims: 
`kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1`

**Evaluating the LHS:**
```lean
  kappa (recDelta void void (delta (delta void)))
```
This matches the definition's rule `| .recDelta b s (.delta n') => Nat.max (Nat.max (kappa b) (kappa s)) (kappa n') + 1` where `n'` is `delta void`:
```lean
= Nat.max (Nat.max (kappa void) (kappa void)) (kappa (delta void)) + 1
= Nat.max (Nat.max 0 0) 0 + 1 
= 1
```

**Evaluating the RHS:**
```lean
  kappa (recDelta void void (delta void)) + 1
```
The inner expression matches the same rule but where `n'` is `void`:
```lean
= (Nat.max (Nat.max (kappa void) (kappa void)) (kappa void) + 1) + 1
= (Nat.max (Nat.max 0 0) 0 + 1) + 1 
= 1 + 1 
= 2
```
Because **`1 ≠ 2`**, `kappa_rec_delta_step` is false.

### 2. Disproving `kappa_rec_succ_drop`
The theorem claims: 
`kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))`

Using the exact same counterexample variables:

**Evaluating the LHS:**
```lean
  kappa (app void (recDelta void void (delta void)))
= Nat.max (kappa void) (kappa (recDelta void void (delta void)))
= Nat.max 0 1
= 1
```

**Evaluating the RHS:**
```lean
  kappa (recDelta void void (delta (delta void)))
```
As shown in the previous calculation, this evaluates to `1`.

Because **`1 < 1`** is false, `kappa_rec_succ_drop` is also false.
