The helper strategy is **unsound**. Both theorems are false as stated. Specifically, `kappa_rec_delta_step` fails when the argument `n` is itself a `delta` term, and consequently `kappa_rec_succ_drop` fails to establish a strict decrease for the `R_rec_succ` rewrite step in that same case.

Here is the detailed analysis:

## 1. The measure function `kappa`

For `recDelta`, the measure is defined as:
- `kappa (recDelta b s (.delta n)) = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1`
- `kappa (recDelta b s n)          = Nat.max (Nat.max (kappa b) (kappa s)) (kappa n)` (when `n` is not a `delta`)

## 2. Failure of `kappa_rec_delta_step`

The theorem claims:
```lean
kappa (recDelta b s (delta n)) = kappa (recDelta b s n) + 1
```

**Counterexample:** Let `b = void`, `s = void`, and `n = delta void`.

- **Left-hand side:** `kappa (recDelta void void (delta (delta void)))`
  - Since the third argument is `delta (delta void)`, we apply the first clause with `n' = delta void`:
  - `= Nat.max (Nat.max (kappa void) (kappa void)) (kappa (delta void)) + 1`
  - `= Nat.max (Nat.max 0 0) 0 + 1 = 1`

- **Right-hand side:** `kappa (recDelta void void (delta void)) + 1`
  - Since `n = delta void`, this matches the first clause:
  - `kappa (recDelta void void (delta void)) = Nat.max (Nat.max 0 0) 0 + 1 = 1`
  - So RHS = `1 + 1 = 2`

Since `1 ≠ 2`, the theorem is false.

**Root cause:** When `n` is already of the form `delta n'`, the expression `recDelta b s n` incurs the `+1` penalty in its measure. The theorem incorrectly assumes `recDelta b s n` uses the "non-delta" branch of the definition.

## 3. Failure of `kappa_rec_succ_drop`

The theorem claims:
```lean
kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
```

This is intended to prove termination for the rewrite step:
```
R_rec_succ : recDelta b s (delta n) → app s (recDelta b s n)
```

**Counterexample:** Again let `b = void`, `s = void`, `n = delta void`.

- **Target (left side of step):** `kappa (recDelta void void (delta (delta void))) = 1` (calculated above)
- **Result (right side of step):** `kappa (app void (recDelta void void (delta void)))`
  - `= Nat.max (kappa void) (kappa (recDelta void void (delta void)))`
  - `= Nat.max 0 1 = 1`

The alleged strict inequality becomes `1 < 1`, which is false.

**General case:** When `n = delta n'`:
- `kappa (recDelta b s (delta n)) = max(max(kappa b, kappa s), kappa n') + 1`
- `kappa (recDelta b s n) = kappa (recDelta b s (delta n')) = max(max(kappa b, kappa s), kappa n') + 1`
- Thus `kappa (app s (recDelta b s n)) = max(kappa s, max(max(kappa b, kappa s), kappa n') + 1) = max(max(kappa b, kappa s), kappa n') + 1` (since the `+1` dominates `kappa s`)

The two measures are **equal**, not strictly decreasing.

## Conclusion

The termination strategy fails because the measure `kappa` does not strictly decrease (it remains unchanged) when applying `R_rec_succ` to a term `recDelta b s (delta n)` where `n` is already a successor (`delta n'`). To repair the proof, the definition of `kappa` would need to be refined—for example, by making the weight of `recDelta` depend on the actual natural number depth of its third argument, or by using a lexicographic measure that distinguishes nested `delta` constructors.
