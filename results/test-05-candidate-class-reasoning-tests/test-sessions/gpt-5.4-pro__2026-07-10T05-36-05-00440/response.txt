A `Nat`-valued termination measure for `Step` should satisfy:

\[
\forall x\, y,\; Step\ x\ y \to \mu(y) < \mu(x).
\]

By inspection, all three candidates fail on the same rule shape, `R_rec_succ`, though `mu3` fails more strongly.

## Per-rule deltas

Let \(\Delta_i = \mu_i(\text{lhs}) - \mu_i(\text{rhs})\).

| Rule | \(\Delta_1\) | \(\Delta_2\) | \(\Delta_3\) |
|---|---:|---:|---:|
| `R_int_delta` | \(2 + \mu_1 t\) | \(3 + \mu_2 t\) | \(3 + \mu_3 t\) |
| `R_merge_void_left` / `right` | \(1\) | \(2\) | \(1\) |
| `R_merge_cancel` | \(1 + \mu_1 t\) | \(2 + \mu_2 t\) | \(1 + \mu_3 t\) |
| `R_rec_zero` | \(1 + \mu_1 s\) | \(5 + \mu_2 s\) | \(1 + \mu_3 s\) |
| `R_rec_succ` | \(-\mu_1 s\) | \(-\mu_2 s\) | \(-(1+\mu_3 s)\) |
| `R_eq_refl` | \(3 + 2\mu_1 a\) | \(5 + 2\mu_2 a\) | \(4 + 2\mu_3 a\) |
| `R_eq_diff` | \(1\) | \(1\) | \(1\) |

So:

- `mu1` decreases on every rule except `R_rec_succ`.
- `mu2` decreases on every rule except `R_rec_succ`.
- `mu3` decreases on every rule except `R_rec_succ`.

## Why `R_rec_succ` breaks them

The problematic rewrite is:

```lean
recDelta b s (delta n)  -->  app s (recDelta b s n)
```

### Candidate 1
\[
\mu_1(\text{lhs}) = 2 + \mu_1 b + \mu_1 s + \mu_1 n
\]
\[
\mu_1(\text{rhs}) = 2 + \mu_1 b + 2\mu_1 s + \mu_1 n
\]
So
\[
\mu_1(\text{lhs}) - \mu_1(\text{rhs}) = -\mu_1 s.
\]

- If `s = void`, it is **equal**, not strictly decreasing.
- If `s` is nontrivial, it **increases**.

Concrete counterexample:
```lean
b := void, s := delta void, n := void
```
Then
- `mu1 (recDelta void (delta void) (delta void)) = 3`
- `mu1 (app (delta void) (recDelta void (delta void) void)) = 4`

So `mu1` is **not** a valid termination measure.

---

### Candidate 2
Similarly:
\[
\mu_2(\text{lhs}) = 6 + \mu_2 b + \mu_2 s + \mu_2 n
\]
\[
\mu_2(\text{rhs}) = 6 + \mu_2 b + 2\mu_2 s + \mu_2 n
\]
So
\[
\mu_2(\text{lhs}) - \mu_2(\text{rhs}) = -\mu_2 s.
\]

Same issue:
- tie when `s = void`
- increase when `s` is nontrivial

So `mu2` is also **not** a valid termination measure.

---

### Candidate 3
Here it is even worse:
\[
\mu_3(\text{lhs}) = 2 + \mu_3 b + \mu_3 s + \mu_3 n
\]
\[
\mu_3(\text{rhs}) = 3 + \mu_3 b + 2\mu_3 s + \mu_3 n
\]
So
\[
\mu_3(\text{lhs}) - \mu_3(\text{rhs}) = -(1+\mu_3 s).
\]

That is **always negative**. So `R_rec_succ` always increases `mu3`.

Concrete example with all arguments `void` except the required outer `delta`:
- `mu3 (recDelta void void (delta void)) = 2`
- `mu3 (app void (recDelta void void void)) = 3`

So `mu3` is **definitely not** a valid termination measure.

---

## Overall assessment

- **`mu1`: invalid**
- **`mu2`: invalid**
- **`mu3`: invalid**

### Relative quality
- `mu1` and `mu2` are qualitatively similar: both fail only because `R_rec_succ` duplicates the `s` argument.
- `mu2` gives larger margins on several other rules, but that does not fix the fatal flaw.
- `mu3` is the weakest of the three, because `R_rec_succ` always strictly increases it.

## Structural reason none of these work
All three are of the same additive form: constructor constant + sum of submeasures with coefficient 1. But `R_rec_succ` duplicates `s` on the right-hand side:

- left contains one copy of `s`
- right contains two copies of `s`

So any such plain additive measure is fighting duplication, and these constants are not enough to compensate.
