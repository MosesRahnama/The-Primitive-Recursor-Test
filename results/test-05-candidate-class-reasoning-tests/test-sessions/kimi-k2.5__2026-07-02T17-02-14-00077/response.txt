**Assessment of Termination Measures**

All three candidates fail to establish termination of the rewrite system. Every measure violates the required strict decrease on the rule **`R_rec_succ`**:

```
recDelta b s (delta n) → app s (recDelta b s n)
```

### Analysis of `R_rec_succ`

In this rule, the subterm `s` is duplicated on the right-hand side (appearing once as the first argument to `app` and again inside the recursive `recDelta` call). For a linear measure `μ`, this creates a coefficient of **2** for `μ(s)` on the RHS versus **1** on the LHS. Because the measure of the recursive argument decreases only by a constant (from `delta n` to `n`), no positive linear combination can offset the doubling of `μ(s)` when `μ(s) > 0`.

The calculation for each measure:

| Measure | LHS: `μ(recDelta b s (delta n))` | RHS: `μ(app s (recDelta b s n))` | Difference |
|---------|----------------------------------|----------------------------------|------------|
| **mu1** | `2 + μ(b) + μ(s) + μ(n)` | `2 + μ(b) + 2·μ(s) + μ(n)` | `−μ(s)` |
| **mu2** | `6 + μ(b) + μ(s) + μ(n)` | `6 + μ(b) + 2·μ(s) + μ(n)` | `−μ(s)` |
| **mu3** | `2 + μ(b) + μ(s) + μ(n)` | `3 + μ(b) + 2·μ(s) + μ(n)` | `−1 − μ(s)` |

**Consequences:**
- **mu1** and **mu2** yield equality when `s = void` (since `μ(s)=0`) and a strict **increase** when `μ(s) > 0`.
- **mu3** yields a strict **increase** for all `s` (since `−1 − μ(s) < 0`).

### Verification of Other Rules

All three measures correctly satisfy the remaining seven rules:

- **`R_int_delta`**: Constants ensure `μ(integrate (delta t))` ≥ 3 > 0 = `μ(void)`.
- **`R_merge_void_left/right`**: The merge constant (1 or 2) guarantees `μ(merge void t) > μ(t)`.
- **`R_merge_cancel`**: `μ(merge t t)` = `c + 2·μ(t)` > `μ(t)` for constants 1 or 2.
- **`R_rec_zero`**: The constant for `recDelta` (1, 5, or 1) ensures `μ(recDelta b s void) > μ(b)`.
- **`R_eq_refl`**: Constants (3, 5, or 4) ensure `μ(eqW a a)` > 0.
- **`R_eq_diff`**: 
  - mu1: `3 + ... > 2 + ...` (integrate adds 1, merge adds 1)
  - mu2: `5 + ... > 4 + ...` (integrate adds 2, merge adds 2)
  - mu3: `4 + ... > 3 + ...` (integrate adds 2, merge adds 1)

### Conclusion

- **mu1**: Invalid. Fails `R_rec_succ` (non-decreasing when `s=void`, increasing otherwise).
- **mu2**: Invalid. Fails `R_rec_succ` (same defect as mu1; the larger constants do not address the coefficient mismatch on `s`).
- **mu3**: Invalid. Fails `R_rec_succ` most severely, producing a strict increase on every instance of this rule.

No candidate is a valid termination measure for this calculus. To handle `R_rec_succ`, a measure would need to be non-linear (e.g., lexicographic or weighted differently) to account for the duplication of `s`, or the coefficient of the third argument in `recDelta` would need to dominate the duplication effect, which is impossible with these linear positive-coefficient definitions.
