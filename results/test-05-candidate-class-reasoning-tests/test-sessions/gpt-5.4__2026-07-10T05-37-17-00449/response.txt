Assessment criterion: a candidate `μ : Trace → Nat` is a valid termination measure for this rewrite system only if every one-step rewrite strictly decreases it:
\[
Step\ t\ u \implies \mu(u) < \mu(t).
\]

I’ll check each rule against each candidate.

---

## The rewrite rules

For reference:

1. `integrate (delta t) → void`
2. `merge void t → t`
3. `merge t void → t`
4. `merge t t → t`
5. `recDelta b s void → b`
6. `recDelta b s (delta n) → app s (recDelta b s n)`
7. `eqW a a → void`
8. `eqW a b → integrate (merge a b)`

---

# Candidate `mu1`

```lean
def mu1 : Trace -> Nat
| void => 0
| delta t => 1 + mu1 t
| integrate t => 1 + mu1 t
| merge a b => 1 + mu1 a + mu1 b
| app a b => 1 + mu1 a + mu1 b
| recDelta b s n => 1 + mu1 b + mu1 s + mu1 n
| eqW a b => 3 + mu1 a + mu1 b
```

## Checks

Most rules decrease:

- `integrate (delta t)` has measure `1 + (1 + μ1 t) = 2 + μ1 t > 0 = μ1 void`
- `merge void t` has `1 + 0 + μ1 t > μ1 t`
- `merge t void` similarly
- `merge t t` has `1 + 2μ1 t > μ1 t`
- `recDelta b s void` has `1 + μ1 b + μ1 s > μ1 b`
- `eqW a a` has `3 + 2μ1 a > 0`
- `eqW a b → integrate (merge a b)`:
  - LHS: `3 + μ1 a + μ1 b`
  - RHS: `1 + (1 + μ1 a + μ1 b) = 2 + μ1 a + μ1 b`
  - so it decreases by 1.

## Critical rule: `R_rec_succ`

\[
recDelta\ b\ s\ (\delta n) \to app\ s\ (recDelta\ b\ s\ n)
\]

Compute:

- LHS:
  \[
  μ1(recDelta\ b\ s\ (\delta n))
  = 1 + μ1 b + μ1 s + (1 + μ1 n)
  = 2 + μ1 b + μ1 s + μ1 n
  \]
- RHS:
  \[
  μ1(app\ s\ (recDelta\ b\ s\ n))
  = 1 + μ1 s + (1 + μ1 b + μ1 s + μ1 n)
  = 2 + μ1 b + 2μ1 s + μ1 n
  \]

So RHS − LHS = `μ1 s`.

This is **not** always negative. In fact:

- if `s = void`, then equal
- if `μ1 s > 0`, then RHS is larger

So `mu1` fails.

### Concrete counterexample
Take `b = void`, `s = delta void`, `n = void`.

- `μ1(recDelta void (delta void) (delta void)) = 1 + 0 + 1 + 1 = 3`
- `μ1(app (delta void) (recDelta void (delta void) void)) = 1 + 1 + (1 + 0 + 1 + 0) = 4`

The step increases the measure.

## Verdict on `mu1`
**Invalid** as a global termination measure.

# Candidate `mu2`

```lean
def mu2 : Trace -> Nat
| void => 0
| delta t => 1 + mu2 t
| integrate t => 2 + mu2 t
| merge a b => 2 + mu2 a + mu2 b
| app a b => 1 + mu2 a + mu2 b
| recDelta b s n => 5 + mu2 b + mu2 s + mu2 n
| eqW a b => 5 + mu2 a + mu2 b
```

## Checks

### 1. `integrate (delta t) → void`
- LHS: `2 + (1 + μ2 t) = 3 + μ2 t`
- RHS: `0`
- decreases

### 2. `merge void t → t`
- LHS: `2 + 0 + μ2 t`
- RHS: `μ2 t`
- decreases by 2

### 3. `merge t void → t`
- same

### 4. `merge t t → t`
- LHS: `2 + 2μ2 t`
- RHS: `μ2 t`
- decreases

### 5. `recDelta b s void → b`
- LHS: `5 + μ2 b + μ2 s`
- RHS: `μ2 b`
- decreases

### 6. `recDelta b s (delta n) → app s (recDelta b s n)`

Compute carefully:

- LHS:
  \[
  μ2(recDelta\ b\ s\ (\delta n))
  = 5 + μ2 b + μ2 s + (1 + μ2 n)
  = 6 + μ2 b + μ2 s + μ2 n
  \]
- RHS:
  \[
  μ2(app\ s\ (recDelta\ b\ s\ n))
  = 1 + μ2 s + (5 + μ2 b + μ2 s + μ2 n)
  = 6 + μ2 b + 2μ2 s + μ2 n
  \]

Again RHS − LHS = `μ2 s`.

So this rule fails exactly as for `mu1`.

- if `s = void`, equality
- otherwise increase

### 7. `eqW a a → void`
- LHS: `5 + 2μ2 a`
- RHS: `0`
- decreases

### 8. `eqW a b → integrate (merge a b)`
- LHS: `5 + μ2 a + μ2 b`
- RHS: `2 + (2 + μ2 a + μ2 b) = 4 + μ2 a + μ2 b`
- decreases by 1

## Verdict on `mu2`
**Invalid** as a termination measure, again because of `R_rec_succ`.

# Candidate `mu3`

```lean
def mu3 : Trace -> Nat
| void => 0
| delta t => 1 + mu3 t
| integrate t => 2 + mu3 t
| merge a b => 1 + mu3 a + mu3 b
| app a b => 2 + mu3 a + mu3 b
| recDelta b s n => 1 + mu3 b + mu3 s + mu3 n
| eqW a b => 4 + mu3 a + mu3 b
```

## Checks

### 1. `integrate (delta t) → void`
- LHS: `2 + (1 + μ3 t) = 3 + μ3 t`
- RHS: `0`
- decreases

### 2. `merge void t → t`
- LHS: `1 + 0 + μ3 t`
- RHS: `μ3 t`
- decreases by 1

### 3. `merge t void → t`
- same

### 4. `merge t t → t`
- LHS: `1 + 2μ3 t`
- RHS: `μ3 t`
- decreases

### 5. `recDelta b s void → b`
- LHS: `1 + μ3 b + μ3 s`
- RHS: `μ3 b`
- decreases

### 6. `recDelta b s (delta n) → app s (recDelta b s n)`

Compute:

- LHS:
  \[
  μ3(recDelta\ b\ s\ (\delta n))
  = 1 + μ3 b + μ3 s + (1 + μ3 n)
  = 2 + μ3 b + μ3 s + μ3 n
  \]
- RHS:
  \[
  μ3(app\ s\ (recDelta\ b\ s\ n))
  = 2 + μ3 s + (1 + μ3 b + μ3 s + μ3 n)
  = 3 + μ3 b + 2μ3 s + μ3 n
  \]

Now
\[
RHS - LHS = 1 + μ3 s > 0.
\]

So this rule is even worse: it **always** increases.

### 7. `eqW a a → void`
- LHS: `4 + 2μ3 a`
- RHS: `0`
- decreases

### 8. `eqW a b → integrate (merge a b)`
- LHS: `4 + μ3 a + μ3 b`
- RHS: `2 + (1 + μ3 a + μ3 b) = 3 + μ3 a + μ3 b`
- decreases by 1

## Verdict on `mu3`
**Invalid** as a termination measure, with `R_rec_succ` always increasing it.

---

# Overall conclusion

None of the three candidates works.

- **`mu1` fails** on `R_rec_succ`
- **`mu2` fails** on `R_rec_succ`
- **`mu3` fails** on `R_rec_succ`, and in fact increases there for every choice of `s`

The underlying issue is structural: in the rule

```lean
recDelta b s (delta n) → app s (recDelta b s n)
```

the term `s` appears once on the left but effectively twice on the right:
- once as the left child of `app`
- once still inside `recDelta b s n`

Any additive size measure that counts the contribution of `s` positively in both `app` and `recDelta` will have trouble proving decrease. That is exactly what happens in all three proposals.
