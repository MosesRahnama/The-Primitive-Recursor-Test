# Assessment of Termination Measures

I checked each candidate against all eight rewrite rules, computing the value of the measure on the LHS and the RHS of each rule and looking for a strict decrease.

## The shared problem: rule `R_rec_succ`

The three measures are *indistinguishable* on the difficult rule, namely

```
R_rec_succ :  recDelta b s (delta n)  ⟶  app s (recDelta b s n)
```

For each measure the structural cost of unwrapping `delta n` is cancelled out (or worse) by re-wrapping the recursive call inside `app s (…)`.

### `mu1`

* LHS:  `1 + mu1 b + mu1 s + (1 + mu1 n) = 2 + mu1 b + mu1 s + mu1 n`
* RHS:  `1 + mu1 s + (1 + mu1 b + mu1 s + mu1 n) = 2 + mu1 b + 2·mu1 s + mu1 n`
* `mu1(LHS) − mu1(RHS) = −mu1 s`  → **strictly negative for any non‑void `s`**. ✗

### `mu2`

* LHS:  `5 + mu2 b + mu2 s + (1 + mu2 n) = 6 + mu2 b + mu2 s + mu2 n`
* RHS:  `1 + mu2 s + (5 + mu2 b + mu2 s + mu2 n) = 6 + mu2 b + 2·mu2 s + mu2 n`
* `mu2(LHS) − mu2(RHS) = −mu2 s`  → **strictly negative for any non‑void `s`**. ✗

### `mu3`

* LHS:  `1 + mu3 b + mu3 s + (1 + mu3 n) = 2 + mu3 b + mu3 s + mu3 n`
* RHS:  `2 + mu3 s + (1 + mu3 b + mu3 s + mu3 n) = 3 + mu3 b + 2·mu3 s + mu3 n`
* `mu3(LHS) − mu3(RHS) = −(1 + mu3 s)`  → **always strictly negative**. ✗

## The other rules

To rule out the other rules as a saving grace, I checked every other rule for all three measures. For the `merge`, `rec_zero`, `integrate/delta`, `eq_refl`, and `eq_diff` rules the differences are:

| rule | `mu1` diff | `mu2` diff | `mu3` diff |
|---|---|---|---|
| `R_int_delta`         | `2 + mu1 t`           | `3 + mu2 t`           | `3 + mu3 t`           |
| `R_merge_void_left`   | `1`                   | `2`                   | `1`                   |
| `R_merge_void_right`  | `1`                   | `2`                   | `1`                   |
| `R_merge_cancel`      | `1 + mu1 t`           | `2 + mu2 t`           | `1 + mu3 t`           |
| `R_rec_zero`          | `1 + mu s`            | `5 + mu s`            | `1 + mu s`            |
| `R_eq_refl`           | `3 + 2·mu a`          | `5 + 2·mu a`          | `4 + 2·mu a`          |
| `R_eq_diff`           | `1`                   | `1`                   | `1`                   |

All of those are positive, so the **only** failure point for every candidate is `R_rec_succ`.

## Verdict

* **`mu1` — invalid.** Fails on `R_rec_succ` whenever the step function `s` is not `void`; the measure actually *increases* by `mu1 s`.
* **`mu2` — invalid.** Fails on `R_rec_succ` for the same reason; the increased constants on the constructors (5/2/2) only made `R_eq_diff` and the `rec_zero` cases looser, but did not help here.
* **`mu3` — invalid.** Fails on `R_rec_succ` even more dramatically: the LHS/RHS gap is `−(1 + mu3 s)`, negative even when `s = void`.

**None of the three candidates is a valid termination measure for this rewrite system.** They all share the same fundamental flaw: the rewrite `recDelta b s (delta n) → app s (recDelta b s n)` peels one `delta` off the recursion counter but immediately rebuilds an `app` node around the recursive call. A correct measure would have to either (a) make the contribution of `app` smaller than that of `delta` (e.g. give `delta` a weight of 2 and `app` a weight of 0), or (b) use a lexicographic / well‑founded relation that tracks that the *third* argument of `recDelta` strictly decreases independently of how `b` and `s` are sized. None of the three additive, structural size measures does this.
