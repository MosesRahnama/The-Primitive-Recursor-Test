**Short answer:**  
None of the three candidates is a valid termination measure. Every one of them fails on the rule `R_rec_succ` because the right‑hand side duplicates the subterm `s`, and all three measures are linear with coefficient 1 on each argument. The duplication makes the right‑hand side at least as large as the left‑hand side (and usually larger). The other seven rules are handled correctly by all three measures.

---

### Detailed analysis

A termination measure `μ : Trace → ℕ` must satisfy  
`∀ t u, Step t u → μ t > μ u`.

Below is a rule‑by‑rule check. For brevity I write `a`, `b`, `s`, `n` for the measures of the corresponding subterms.

#### The problematic rule: `R_rec_succ`
```
recDelta b s (delta n)  →  app s (recDelta b s n)
```

| Measure | `μ(lhs)` | `μ(rhs)` | Difference |
|---------|----------|----------|------------|
| **mu1** | `2 + b + s + n` | `2 + b + 2·s + n` | `rhs = lhs + s` |
| **mu2** | `6 + b + s + n` | `6 + b + 2·s + n` | `rhs = lhs + s` |
| **mu3** | `2 + b + s + n` | `3 + b + 2·s + n` | `rhs = lhs + 1 + s` |

*Why this happens.*  
In `lhs` the subterm `s` occurs once inside `recDelta`. In `rhs` it occurs once as the first argument of `app` **and** once again inside the nested `recDelta`. Because each measure counts every occurrence of a subterm with weight 1, the right side picks up an extra copy of `μ(s)`. The constant offsets in `mu2` (the `5` in `recDelta` and the `1` in `app`) cancel out because a `recDelta` subterm appears on **both** sides. Consequently:

* **mu1** and **mu2** are *equal* to the left side when `s = void` and **strictly larger** otherwise.
* **mu3** is **strictly larger** for *every* `s` (even when `s = void`).

Thus no candidate strictly decreases on this rule.

---

#### The other rules (all three measures pass)

| Rule | `μ(lhs) > μ(rhs)?` |
|------|-------------------|
| `integrate (delta t) → void` | Yes (lhs ≥ 2, rhs = 0). |
| `merge void t → t` | Yes (coefficient on `merge` ≥ 1). |
| `merge t void → t` | Yes. |
| `merge t t → t` | Yes (coefficient on `merge` plus an extra copy of `t`). |
| `recDelta b s void → b` | Yes (`μ(s) ≥ 0` and constant ≥ 1). |
| `eqW a a → void` | Yes (constant ≥ 3/4/5 > 0). |
| `eqW a b → integrate (merge a b)` | Yes for all three: the `eqW` constant exceeds the sum of the `integrate` and `merge` constants by exactly 1. |

---

### Verdict

* **mu1** – Invalid. Fails on `R_rec_succ` (stagnates when `s = void`, grows otherwise).
* **mu2** – Invalid. Fails on `R_rec_succ` for the same reason; the large constant `5` in `recDelta` is irrelevant because `recDelta` occurs on both sides of the rule.
* **mu3** – Invalid. Fails on `R_rec_succ` and in fact makes the measure *worse* (always strictly increases on that rule).

**No proposed measure works.** To obtain a termination proof one would need a measure that does not simply add the duplicated subterm `s` on the right‑hand side—for example, by giving the first argument of `app` weight 0, or by using a lexicographic/product ordering rather than a plain linear size.
