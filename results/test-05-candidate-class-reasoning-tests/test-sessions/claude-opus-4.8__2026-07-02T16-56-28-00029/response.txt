# Assessment of the Three Termination Measures

I need to check whether each measure `mu` strictly decreases (`mu(lhs) > mu(rhs)`) across all 8 rewrite rules.

Let me evaluate each rule for each candidate.

## The 8 rules

1. `R_int_delta`: `integrate (delta t)` → `void`
2. `R_merge_void_left`: `merge void t` → `t`
3. `R_merge_void_right`: `merge t void` → `t`
4. `R_merge_cancel`: `merge t t` → `t`
5. `R_rec_zero`: `recDelta b s void` → `b`
6. `R_rec_succ`: `recDelta b s (delta n)` → `app s (recDelta b s n)`
7. `R_eq_refl`: `eqW a a` → `void`
8. `R_eq_diff`: `eqW a b` → `integrate (merge a b)`

The interesting/dangerous rules are 4 (`merge t t`), 6 (`rec_succ`), and 8 (`eq_diff`), since RHS can be as large as or larger than LHS.

## Candidate mu1

- **R1**: `1+(1+mu1 t)` = `2+mu1 t` vs `0`. ✓
- **R2**: `1+0+mu1 t` = `1+mu1 t` vs `mu1 t`. ✓
- **R3**: `1+mu1 t+0` vs `mu1 t`. ✓
- **R4**: `1+mu1 t+mu1 t` vs `mu1 t`. ✓
- **R5**: `1+mu1 b+mu1 s+0` vs `mu1 b`. ✓
- **R6**: LHS `1+mu1 b+mu1 s+(1+mu1 n)` = `2+mu1 b+mu1 s+mu1 n`. RHS `app s (recDelta b s n)` = `1+mu1 s+(1+mu1 b+mu1 s+mu1 n)` = `2+mu1 b+2·mu1 s+mu1 n`. **LHS − RHS = −mu1 s ≤ 0.** ✗ **FAILS** (when `mu1 s > 0`).
- **R7**: `3+2·mu1 a` vs `0`. ✓
- **R8**: LHS `3+mu1 a+mu1 b`. RHS `integrate (merge a b)` = `1+(1+mu1 a+mu1 b)` = `2+mu1 a+mu1 b`. LHS>RHS. ✓

**mu1 FAILS on R6** — duplicating `s` in the RHS is not compensated because `recDelta` gives `s` no extra weight over `app`.

## Candidate mu2

- **R1**: `2+(1+mu2 t)` = `3+mu2 t` vs `0`. ✓
- **R2**: `2+mu2 t` vs `mu2 t`. ✓
- **R3**: `2+mu2 t` vs `mu2 t`. ✓
- **R4**: `2+2·mu2 t` vs `mu2 t`. ✓

**mu2 FAILS on R6** — same problem. The base constant `5` for `recDelta` doesn't help: the duplicated `s` weight cancels exactly, but the additive constants match (`6` vs `6`), so strict decrease fails whenever `mu2 s > 0`.

- **R2**: `1+mu3 t` vs `mu3 t`. ✓
- **R3**: `1+mu3 t` vs `mu3 t`. ✓

**mu3 FAILS on R6**, and even more decisively — here `app` weight (2) exceeds `recDelta` weight (1), so the measure *increases* on R6 unconditionally.

## Summary

|------|-----|-----|-----|
| R_int_delta | ✓ | ✓ | ✓ |

| R_merge_void_right | ✓ | ✓ | ✓ |

| R_eq_refl | ✓ | ✓ | ✓ |
| R_eq_diff | ✓ | ✓ | ✓ |

**All three candidates fail**, all on the same rule: **`R_rec_succ`**.

### Root cause
The rule `recDelta b s (delta n) → app s (recDelta b s n)` duplicates the subterm `s`: `s` appears once on the LHS but twice on the RHS. For a strict decrease with a plain additive measure, the constant weight of `recDelta` must exceed the constant weight of the newly-introduced `app` node **plus** cover the extra copy of `s`. Since `s` can have arbitrarily large measure, no *fixed additive* weighting scheme (where each variable is counted with coefficient 1) can compensate — the extra `mu(s)` term is unbounded.

- mu1, mu2: the `mu(s)` terms cancel and constants tie (LHS − RHS = `−mu(s)`), so non-strict.
- mu3: constants also go the wrong way (LHS − RHS = `−1 − mu(s)`), strictly increasing.

### Fix direction (not requested to implement, but relevant)
To handle `R_rec_succ`, a simple additive `Nat` measure is insufficient because of the duplication of `s`. One would need a measure where `recDelta`'s weight *multiplies* the weight of its numeral argument (e.g., something like `mu(recDelta b s n) = mu(b) + (1 + mu(s))·(mu(n)+1)`), so that peeling one `delta` off `n` releases enough weight to pay for the extra copy of `s`. No linear/additive candidate here can succeed.

**Conclusion: None of `mu1`, `mu2`, `mu3` is a valid termination measure for this calculus.**
