Use the standard check:

\[
\forall \, t u,\; Step\ t\ u \to \mu(u) < \mu(t).
\]

Under that criterion, **none of `mu1`, `mu2`, `mu3` is a valid termination measure** for `Step`.

### Per-rule decrease

Let \(\Delta_i = \mu_i(\text{lhs}) - \mu_i(\text{rhs})\).

| Rule | \(\Delta_1\) | \(\Delta_2\) | \(\Delta_3\) |
|---|---:|---:|---:|
| `R_int_delta` | \(2 + \mu_1 t\) | \(3 + \mu_2 t\) | \(3 + \mu_3 t\) |
| `R_merge_void_left/right` | \(1\) | \(2\) | \(1\) |
| `R_merge_cancel` | \(1 + \mu_1 t\) | \(2 + \mu_2 t\) | \(1 + \mu_3 t\) |
| `R_rec_zero` | \(1 + \mu_1 s\) | \(5 + \mu_2 s\) | \(1 + \mu_3 s\) |
| `R_eq_refl` | \(3 + 2\mu_1 a\) | \(5 + 2\mu_2 a\) | \(4 + 2\mu_3 a\) |
| `R_eq_diff` | \(1\) | \(1\) | \(1\) |

So all three decrease on every rule **except** `R_rec_succ`.

---

## The failing rule: `R_rec_succ`

Rule:

```lean
Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

### `mu1`
\[
\mu_1(recDelta\ b\ s\ (delta\ n)) = 2 + \mu_1 b + \mu_1 s + \mu_1 n
\]
\[
\mu_1(app\ s\ (recDelta\ b\ s\ n)) = 2 + \mu_1 b + 2\mu_1 s + \mu_1 n
\]

Hence
\[
\Delta_1 = -\mu_1 s.
\]

So:
- if `s = void`, then \(\Delta_1 = 0\): **not strictly decreasing**
- if `s ≠ void`, then \(\Delta_1 < 0\): **it increases**

So **`mu1` fails**.

---

### `mu2`
\[
\mu_2(recDelta\ b\ s\ (delta\ n)) = 6 + \mu_2 b + \mu_2 s + \mu_2 n
\]
\[
\mu_2(app\ s\ (recDelta\ b\ s\ n)) = 6 + \mu_2 b + 2\mu_2 s + \mu_2 n
\]

Hence
\[
\Delta_2 = -\mu_2 s.
\]

Same conclusion:
- equality when `s = void`
- increase when `s ≠ void`

So **`mu2` fails**.

---

### `mu3`
\[
\mu_3(recDelta\ b\ s\ (delta\ n)) = 2 + \mu_3 b + \mu_3 s + \mu_3 n
\]
\[
\mu_3(app\ s\ (recDelta\ b\ s\ n)) = 3 + \mu_3 b + 2\mu_3 s + \mu_3 n
\]

Hence
\[
\Delta_3 = -(1+\mu_3 s),
\]
which is **always negative**.

So **`mu3` fails even more strongly**: `R_rec_succ` always increases the measure.

---

## Concrete counterexample

Take `b = void`, `s = void`, `n = void`. Then:

```lean
Step (recDelta void void (delta void)) (app void (recDelta void void void))
```

and:
- `mu1` gives `2 -> 2`  (not decreasing)
- `mu2` gives `6 -> 6`  (not decreasing)
- `mu3` gives `2 -> 3`  (increases)

This single step refutes all three candidates.

---

## Verdict

- **`mu1`: invalid**
- **`mu2`: invalid**
- **`mu3`: invalid**

`mu1` and `mu2` are “almost” okay, but both fail on `R_rec_succ` because that rule duplicates `s`.  
`mu3` also fails on `R_rec_succ`, and in fact strictly increases there.

## Stronger observation

This is not just a bad choice of constants. Any measure of this same additive “sum of constructor weights” form will fail on `R_rec_succ`, because the RHS contains **two copies of `s`** while the LHS contains only one. So tweaking the numeric weights alone will not fix this family. A successful proof would need a different style of measure, e.g. a lexicographic or non-additive interpretation.
