Assuming the intended criterion is:

> for every `Step t u`, the measure should strictly decrease: `muᵢ u < muᵢ t`.

Then **none of `mu1`, `mu2`, `mu3` is a valid termination measure for the full `Step` relation**.

## Key observation

All three candidates work on every rule **except**:

```lean
R_rec_succ : Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

That rule duplicates `s`: it appears once on the left, but effectively twice on the right (once as the function in `app`, once inside the recursive call). Any purely additive size measure is in trouble here.

---

## Rule-by-rule summary

Let `mb = muᵢ b`, `ms = muᵢ s`, `mn = muᵢ n`.

### `mu1`

- `R_int_delta`:  
  lhs = `1 + (1 + mu1 t) = 2 + mu1 t`  
  rhs = `0`  
  ✅ decreases

- `R_merge_void_left/right`:  
  lhs = `1 + 0 + mu1 t = 1 + mu1 t`  
  rhs = `mu1 t`  
  ✅ decreases

- `R_merge_cancel`:  
  lhs = `1 + mu1 t + mu1 t`  
  rhs = `mu1 t`  
  ✅ decreases

- `R_rec_zero`:  
  lhs = `1 + mu1 b + mu1 s`  
  rhs = `mu1 b`  
  ✅ decreases

- `R_rec_succ`:  
  lhs = `1 + mu1 b + mu1 s + (1 + mu1 n)`
      = `2 + mb + ms + mn`  
  rhs = `1 + mu1 s + (1 + mu1 b + mu1 s + mu1 n)`
      = `2 + mb + 2*ms + mn`

  So:
  ```text
  lhs - rhs = - ms
  ```
  ❌ not strictly decreasing  
  - if `s = void`, then `ms = 0`, so the measure is **equal**
  - if `s ≠ void`, the measure actually **increases**

- `R_eq_refl`: ✅ decreases
- `R_eq_diff`:  
  lhs = `3 + ma + mb`, rhs = `1 + (1 + ma + mb) = 2 + ma + mb`  
  ✅ decreases by 1

### Verdict for `mu1`
**Invalid**, because of `R_rec_succ`.

A concrete counterexample:
```lean
recDelta void void (delta void)  ->  app void (recDelta void void void)
```
gives
```text
mu1 lhs = 2
mu1 rhs = 2
```

---

### `mu2`

Same story.

- `R_int_delta`: ✅
- `R_merge_void_left/right`: ✅
- `R_merge_cancel`: ✅
- `R_rec_zero`: ✅
- `R_eq_refl`: ✅
- `R_eq_diff`: ✅

But for `R_rec_succ`:

lhs:
```text
5 + mu2 b + mu2 s + (1 + mu2 n)
= 6 + mb + ms + mn
```

rhs:
```text
1 + mu2 s + (5 + mu2 b + mu2 s + mu2 n)
= 6 + mb + 2*ms + mn
```

So:
```text
lhs - rhs = - ms
```

❌ again not strictly decreasing.

Concrete counterexample:
```lean
recDelta void void (delta void)  ->  app void (recDelta void void void)
```
gives
```text
mu2 lhs = 6
mu2 rhs = 6
```

### Verdict for `mu2`
**Invalid**, for exactly the same reason as `mu1`.

`mu2` does not improve the critical rule; its larger constants cancel out there.

---

### `mu3`

Again all non-`rec_succ` rules decrease:

- `R_int_delta`: ✅
- `R_merge_void_left/right`: ✅
- `R_merge_cancel`: ✅
- `R_rec_zero`: ✅
- `R_eq_refl`: ✅
- `R_eq_diff`: ✅

But `R_rec_succ` is even worse:

lhs:
```text
1 + mu3 b + mu3 s + (1 + mu3 n)
= 2 + mb + ms + mn
```

rhs:
```text
2 + mu3 s + (1 + mu3 b + mu3 s + mu3 n)
= 3 + mb + 2*ms + mn
```

So:
```text
lhs - rhs = -(1 + ms)
```

❌ the measure **always increases** on `R_rec_succ`.

Concrete counterexample:
```lean
recDelta void void (delta void)  ->  app void (recDelta void void void)
```
gives
```text
mu3 lhs = 2
mu3 rhs = 3
```

### Verdict for `mu3`
**Invalid**, and strictly worse than `mu1`/`mu2`.

---

## Overall assessment

- **`mu1`**: fails only on `R_rec_succ`
- **`mu2`**: fails only on `R_rec_succ`
- **`mu3`**: fails on `R_rec_succ`, and there it increases strictly

So the best summary is:

- **No candidate is a valid global decreasing measure for `Step`.**
- **`mu1` and `mu2` are tied**: both are “almost right” but still invalid.
- **`mu3` is the weakest** of the three.

## Why they all fail

The obstruction is structural:

```lean
recDelta b s (delta n)  ->  app s (recDelta b s n)
```

The right-hand side contains `s` twice in an additive sense, while the left-hand side contains it once. So a flat additive size measure of the form “constructor constant + sum of subterm measures” is not a good fit.

## One nuance about this file

As written, `Step` is a **root-only** relation: there are no context/congruence rules. In particular, `app _ _` has no rewrite rule at the root, so after `R_rec_succ` the term is stuck.

That means the calculus may still be terminating, but these particular **structural size** measures are too coarse because they keep counting the `recDelta` sitting under `app`, even though `Step` cannot rewrite under `app`.
