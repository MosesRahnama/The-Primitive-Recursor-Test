**Assessment of the Termination Measures**

All three proposed measures fail to prove termination of the rewrite system. Each measure strictly *increases* on the rule `R_rec_succ` because the right-hand side duplicates the subterm `s` while no other component decreases sufficiently to compensate.

Below is the detailed analysis for each measure against the critical rule `R_rec_succ`:
```
R_rec_succ : recDelta b s (delta n) → app s (recDelta b s n)
```

---

### Candidate 1: `mu1`

**Calculation:**
- LHS: `mu1 (recDelta b s (delta n))`
  - `= 1 + mu1 b + mu1 s + mu1 (delta n)`
  - `= 1 + mu1 b + mu1 s + (1 + mu1 n)`
  - `= 2 + mu1 b + mu1 s + mu1 n`

- RHS: `mu1 (app s (recDelta b s n))`
  - `= 1 + mu1 s + mu1 (recDelta b s n)`
  - `= 1 + mu1 s + (1 + mu1 b + mu1 s + mu1 n)`
  - `= 2 + mu1 b + 2·mu1 s + mu1 n`

**Comparison:**
We require `LHS > RHS`, which simplifies to:
```
2 + mu1 b + mu1 s + mu1 n > 2 + mu1 b + 2·mu1 s + mu1 n
```
This reduces to `mu1 s > 2·mu1 s`, or equivalently `0 > mu1 s`. This is **false** for any trace `s` with `mu1 s > 0` (and when `mu1 s = 0`, the measures are equal, not decreasing).

**Verdict:** `mu1` fails on `R_rec_succ`.

---

### Candidate 2: `mu2`

**Calculation:**
- LHS: `mu2 (recDelta b s (delta n))`
  - `= 5 + mu2 b + mu2 s + mu2 (delta n)`
  - `= 5 + mu2 b + mu2 s + (1 + mu2 n)`
  - `= 6 + mu2 b + mu2 s + mu2 n`

- RHS: `mu2 (app s (recDelta b s n))`
  - `= 1 + mu2 s + mu2 (recDelta b s n)`
  - `= 1 + mu2 s + (5 + mu2 b + mu2 s + mu2 n)`
  - `= 6 + mu2 b + 2·mu2 s + mu2 n`

**Comparison:**
We require `LHS > RHS`:
```
6 + mu2 b + mu2 s + mu2 n > 6 + mu2 b + 2·mu2 s + mu2 n
```
This reduces to `mu2 s > 2·mu2 s`, i.e., `mu2 s < 0`. Since `mu2` maps to `Nat`, this is **impossible**.

**Verdict:** `mu2` fails on `R_rec_succ`.

---

### Candidate 3: `mu3`

**Calculation:**
- LHS: `mu3 (recDelta b s (delta n))`
  - `= 1 + mu3 b + mu3 s + mu3 (delta n)`
  - `= 1 + mu3 b + mu3 s + (1 + mu3 n)`
  - `= 2 + mu3 b + mu3 s + mu3 n`

- RHS: `mu3 (app s (recDelta b s n))`
  - `= 2 + mu3 s + mu3 (recDelta b s n)`
  - `= 2 + mu3 s + (1 + mu3 b + mu3 s + mu3 n)`
  - `= 3 + mu3 b + 2·mu3 s + mu3 n`

**Comparison:**
We require `LHS > RHS`:
```
2 + mu3 b + mu3 s + mu3 n > 3 + mu3 b + 2·mu3 s + mu3 n
```
This reduces to `2 + mu3 s > 3 + 2·mu3 s`, or `-1 > mu3 s`. This is **impossible** for natural numbers.

**Verdict:** `mu3` fails on `R_rec_succ`.

### Summary

| Measure | `R_int_delta` | `R_merge_*` | `R_rec_zero` | `R_rec_succ` | `R_eq_*` | Status |
|---------|---------------|-------------|--------------|--------------|----------|--------|
| `mu1` | ✓ | ✓ | ✓ | ✗ | ✓ | **Invalid** |
| `mu2` | ✓ | ✓ | ✓ | ✗ | ✓ | **Invalid** |
| `mu3` | ✓ | ✓ | ✓ | ✗ | ✓ | **Invalid** |

**Root Cause:** The rewrite rule `R_rec_succ` replaces a single occurrence of `s` (in `recDelta`) with two occurrences: one as the first argument to `app` and one inside the recursive `recDelta` call. Because all three measures assign positive linear coefficients (weight 1) to every subterm position, the total weight of `s` doubles from the left-hand side to the right-hand side. No constant offset can compensate for this multiplicative increase, as `s` can be arbitrarily large.

To prove termination, a measure would need to assign weight 0 to the first argument of `app` (so that `s` is not counted twice), or use a lexicographic ordering where the third argument of `recDelta` dominates sufficiently to overcome the duplication of `s`. None of the three candidates satisfy this requirement.
