For the usual termination requirement

```lean
Step x y → mu y < mu x
```

none of the three candidates is a valid global termination measure.

The only problematic rule is:

```lean
R_rec_succ :
  Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

Let `B = μ b`, `S = μ s`, and `N = μ n`.

| Measure | LHS: `μ (recDelta b s (delta n))` | RHS: `μ (app s (recDelta b s n))` | Result |
|---|---:|---:|---|
| `mu1` | `2 + B + S + N` | `2 + B + 2*S + N` | RHS − LHS = `S` |
| `mu2` | `6 + B + S + N` | `6 + B + 2*S + N` | RHS − LHS = `S` |
| `mu3` | `2 + B + S + N` | `3 + B + 2*S + N` | RHS − LHS = `1 + S` |

## `mu1`

`mu1` is not strictly decreasing on `R_rec_succ`.

If `s = void`, then `S = 0` and the two sides have equal measure. For example:

```lean
recDelta void void (delta void)
  → app void (recDelta void void void)
```

has `mu1` value `2` on both sides.

If `s` has positive measure, the measure actually increases. For instance, with `s = delta void`, it goes from `3` to `4`.

All other rewrite rules strictly decrease `mu1`, including `R_eq_diff`, where the measure drops from `3 + μ a + μ b` to `2 + μ a + μ b`.

## `mu2`

`mu2` has exactly the same structural problem on `R_rec_succ`.

Again, when `s = void`, the measure is preserved:

```lean
recDelta void void (delta void)
  → app void (recDelta void void void)
```

has `mu2` value `6` on both sides.

For nonzero `s`, it increases. Thus `mu2` is also not a strict termination measure.

Its other rules do strictly decrease; in particular, `R_eq_diff` changes the outer contribution from `5` to `2 + 2 = 4`.

## `mu3`

`mu3` fails even more directly on `R_rec_succ`: it always increases on that rule.

The difference is:

```text
μ₃(rhs) − μ₃(lhs) = 1 + μ₃(s)
```

which is always positive. In particular:

```lean
recDelta void void (delta void)
  → app void (recDelta void void void)
```

has `mu3` values `2 → 3`.

The remaining rules strictly decrease `mu3`, but this unavoidable increase on `R_rec_succ` rules it out.

## Conclusion

- `mu1`: invalid; `R_rec_succ` is non-increasing only when `s = void`, and increasing otherwise.
- `mu2`: invalid for the same reason.
- `mu3`: invalid; `R_rec_succ` always strictly increases it.

The common issue is that `R_rec_succ` duplicates `s`: it occurs once in the left-hand `recDelta`, but on the right it occurs both as the left argument of `app` and inside the recursive `recDelta`. Any simple additive measure of these forms must account for that duplication differently, or use a more sophisticated measure than these single natural-number sizes.
