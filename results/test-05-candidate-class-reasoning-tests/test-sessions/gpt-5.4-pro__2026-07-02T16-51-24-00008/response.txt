Assuming “termination measure” means a `Nat`-valued ranking function with

\[
Step\ x\ y \;\Rightarrow\; \mu(x) > \mu(y),
\]

then **none of `mu1`, `mu2`, `mu3` works**.

### Rule-by-rule summary

Let `Δi = mui(lhs) - mui(rhs)`.

| Rule | `Δ1` | `Δ2` | `Δ3` | Verdict |
|---|---:|---:|---:|---|
| `integrate (delta t) → void` | `2 + mu1 t` | `3 + mu2 t` | `3 + mu3 t` | good |
| `merge void t → t` | `1` | `2` | `1` | good |
| `merge t void → t` | `1` | `2` | `1` | good |
| `merge t t → t` | `1 + mu1 t` | `2 + mu2 t` | `1 + mu3 t` | good |
| `recDelta b s void → b` | `1 + mu1 s` | `5 + mu2 s` | `1 + mu3 s` | good |
| `recDelta b s (delta n) → app s (recDelta b s n)` | `- mu1 s` | `- mu2 s` | `-(1 + mu3 s)` | **bad** |
| `eqW a a → void` | `3 + 2*mu1 a` | `5 + 2*mu2 a` | `4 + 2*mu3 a` | good |
| `eqW a b → integrate (merge a b)` | `1` | `1` | `1` | good |

### The failure point

All three fail on `R_rec_succ`.

#### `mu1`
- LHS:
  \[
  \mu_1(recDelta\ b\ s\ (delta\ n)) = 2 + \mu_1 b + \mu_1 s + \mu_1 n
  \]
- RHS:
  \[
  \mu_1(app\ s\ (recDelta\ b\ s\ n)) = 2 + \mu_1 b + 2\mu_1 s + \mu_1 n
  \]

So RHS exceeds LHS by `mu1 s`.  
It is **equal** when `s = void`, and **larger** when `s ≠ void`.

#### `mu2`
Same problem:
\[
\mu_2(lhs)=6+\mu_2 b+\mu_2 s+\mu_2 n,\quad
\mu_2(rhs)=6+\mu_2 b+2\mu_2 s+\mu_2 n.
\]

Again, equality at `s = void`, increase otherwise.

#### `mu3`
Even worse:
\[
\mu_3(lhs)=2+\mu_3 b+\mu_3 s+\mu_3 n,\quad
\mu_3(rhs)=3+\mu_3 b+2\mu_3 s+\mu_3 n.
\]

So RHS is always strictly larger.

### Concrete counterexamples

Take `b = void`, `s = void`, `n = void`.

- `mu1`:
  \[
  \mu_1(recDelta\ void\ void\ (delta\ void)) = 2,
  \quad
  \mu_1(app\ void\ (recDelta\ void\ void\ void)) = 2.
  \]
  Not strictly decreasing.

- `mu2`:
  \[
  6 = 6.
  \]
  Not strictly decreasing.

- `mu3`:
  \[
  2 < 3.
  \]
  Goes the wrong way.

### Overall assessment

- **`mu1`**: reject
- **`mu2`**: reject
- **`mu3`**: reject

### Comparative note

- `mu1` and `mu2` are basically tied: they both fail for the same structural reason.
- `mu3` is strictly worse, because it makes the bad rule increase even when `s = void`.

### Why this happens

`R_rec_succ` duplicates the contribution of `s`:

- on the left, `s` appears once inside `recDelta`
- on the right, `s` appears once as the left argument of `app` and again inside `recDelta`

So a simple additive size measure with coefficient `1` on all subterms cannot orient that rule.

One subtlety: **this only shows the measures fail**, not that the rewrite system is nonterminating. Based on this file alone, `Step` is only a root-step relation, and `app` has no rewrite rule, so `R_rec_succ` may still be terminating even though these size measures do not prove it.
