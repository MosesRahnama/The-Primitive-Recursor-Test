Assuming the intended check is:

> for every rewrite `Step t u`, the measure strictly drops: `mu? u < mu? t`

then **none of `mu1`, `mu2`, `mu3` works**.

## Quick summary

All three measures decrease on 7 of the 8 rules.  
They all fail on:

```lean
R_rec_succ :
  Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

The reason is that the RHS contains **two copies of `s`** from the measure’s point of view: one in `app s ...`, one inside `recDelta b s n`.

---

## Rule-by-rule deltas

Let `Δi = mui(lhs) - mui(rhs)`.  
A valid ranking function needs `Δi > 0` for every rule.

| Rule | `Δ1` | `Δ2` | `Δ3` | Verdict |
|---|---:|---:|---:|---|
| `R_int_delta` | `2 + mu1 t` | `3 + mu2 t` | `3 + mu3 t` | good |
| `R_merge_void_left` | `1` | `2` | `1` | good |
| `R_merge_void_right` | `1` | `2` | `1` | good |
| `R_merge_cancel` | `1 + mu1 t` | `2 + mu2 t` | `1 + mu3 t` | good |
| `R_rec_zero` | `1 + mu1 s` | `5 + mu2 s` | `1 + mu3 s` | good |
| `R_rec_succ` | `- mu1 s` | `- mu2 s` | `-(1 + mu3 s)` | **bad** |
| `R_eq_refl` | `3 + 2*mu1 a` | `5 + 2*mu2 a` | `4 + 2*mu3 a` | good |
| `R_eq_diff` | `1` | `1` | `1` | good |

---

## Individual assessment

### 1. `mu1`
Fails on `R_rec_succ`.

- LHS:
  ```lean
  mu1 (recDelta b s (delta n))
  = 2 + mu1 b + mu1 s + mu1 n
  ```
- RHS:
  ```lean
  mu1 (app s (recDelta b s n))
  = 2 + mu1 b + 2 * mu1 s + mu1 n
  ```

So:
```lean
mu1(lhs) - mu1(rhs) = - mu1 s
```

Therefore:

- if `s = void`, the measure is **equal**
- if `s ≠ void`, the measure **increases**

So `mu1` is **not** a valid strict termination measure.

---

### 2. `mu2`
Same fatal issue.

- LHS:
  ```lean
  mu2 (recDelta b s (delta n))
  = 6 + mu2 b + mu2 s + mu2 n
  ```
- RHS:
  ```lean
  mu2 (app s (recDelta b s n))
  = 6 + mu2 b + 2 * mu2 s + mu2 n
  ```

Hence:
```lean
mu2(lhs) - mu2(rhs) = - mu2 s
```

So again:

- equal when `s = void`
- increases when `s ≠ void`

So `mu2` also **fails**.

---

### 3. `mu3`
Also fails on `R_rec_succ`, and more strongly.

- LHS:
  ```lean
  mu3 (recDelta b s (delta n))
  = 2 + mu3 b + mu3 s + mu3 n
  ```
- RHS:
  ```lean
  mu3 (app s (recDelta b s n))
  = 3 + mu3 b + 2 * mu3 s + mu3 n
  ```

Thus:
```lean
mu3(lhs) - mu3(rhs) = - (1 + mu3 s)
```

So the measure **always increases**, even when `s = void`.

`mu3` is therefore the worst of the three for this purpose.

---

## Concrete counterexamples

- `mu1` fails, e.g. with `b = void`, `s = delta void`, `n = void`:
  - LHS measure = `3`
  - RHS measure = `4`

- `mu2` fails on the same example:
  - LHS measure = `7`
  - RHS measure = `8`

- `mu3` fails even with `s = void`, e.g. `recDelta void void (delta void)`:
  - LHS measure = `2`
  - RHS measure = `3`

---

## Bottom line

- **`mu1`: reject**
- **`mu2`: reject**
- **`mu3`: reject**

If the goal is a one-step ranking function for `Step`, **none of the three is valid**.

## Why this is structural, not just a bad constant choice

All three are additive “size-like” measures.  
The bad rule

```lean
recDelta b s (delta n) -> app s (recDelta b s n)
```

duplicates the contribution of `s` on the RHS. So merely changing constructor constants does not fix the core problem for this family of measures.

These failures do **not** show the rewrite system is nonterminating; they only show that these particular `Nat`-valued measures are not suitable as strict per-step termination measures.
