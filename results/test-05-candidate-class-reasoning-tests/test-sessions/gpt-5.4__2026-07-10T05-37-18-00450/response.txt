Assessment criterion: a candidate `μ : Trace → Nat` is a valid termination measure for this rewrite system only if every one-step rewrite strictly decreases it, i.e. for every `Step t u`, we have `μ u < μ t`.

## Candidate `mu1`
`mu1` is **not** a valid termination measure.

Counterexample: rule `R_eq_diff`
- source: `eqW a b`
- target: `integrate (merge a b)`

Compute:
- `mu1 (eqW a b) = 3 + mu1 a + mu1 b`
- `mu1 (integrate (merge a b)) = 1 + mu1 (merge a b) = 1 + (1 + mu1 a + mu1 b) = 2 + mu1 a + mu1 b`

So for this rule it does decrease by `1`, which is fine.

But rule `R_rec_succ` fails:
- source: `recDelta b s (delta n)`
- target: `app s (recDelta b s n)`

Compute:
- `mu1 (recDelta b s (delta n)) = 1 + mu1 b + mu1 s + (1 + mu1 n) = 2 + mu1 b + mu1 s + mu1 n`
- `mu1 (app s (recDelta b s n)) = 1 + mu1 s + (1 + mu1 b + mu1 s + mu1 n) = 2 + mu1 b + 2*mu1 s + mu1 n`

Difference:
- target − source = `mu1 s`

So if `s ≠ void`, the measure does **not** decrease; it increases when `mu1 s > 0`, and stays equal when `s = void`.

Therefore `mu1` fails.

## Candidate `mu2`
`mu2` is **not** a valid termination measure.

Again check `R_rec_succ`:
- `mu2 (recDelta b s (delta n)) = 5 + mu2 b + mu2 s + (1 + mu2 n) = 6 + mu2 b + mu2 s + mu2 n`
- `mu2 (app s (recDelta b s n)) = 1 + mu2 s + (5 + mu2 b + mu2 s + mu2 n) = 6 + mu2 b + 2*mu2 s + mu2 n`

Difference:
- target − source = `mu2 s`

So the same issue occurs:
- if `mu2 s > 0`, the measure increases,
- if `s = void`, it is unchanged.

Thus `mu2` fails.

## Candidate `mu3`
`mu3` is also **not** a valid termination measure.

For `R_rec_succ`:
- `mu3 (recDelta b s (delta n)) = 1 + mu3 b + mu3 s + (1 + mu3 n) = 2 + mu3 b + mu3 s + mu3 n`
- `mu3 (app s (recDelta b s n)) = 2 + mu3 s + (1 + mu3 b + mu3 s + mu3 n) = 3 + mu3 b + 2*mu3 s + mu3 n`

Difference:
- target − source = `1 + mu3 s`

So the target is always strictly larger than the source. Hence `mu3` definitely fails.

## Summary
All three candidates are invalid as global step-decreasing termination measures.

- `mu1`: fails on `R_rec_succ`
- `mu2`: fails on `R_rec_succ`
- `mu3`: fails on `R_rec_succ`

## Brief sanity check on the other rules
The other rewrite rules are not the problem for these candidates; the decisive obstruction is `R_rec_succ`, because the right-hand side duplicates `s`:
- source contains `s` once,
- target contains `s` both as the left child of `app` and inside `recDelta b s n`.

Any additive size measure like these will therefore struggle, since duplication of `s` tends to prevent decrease unless `recDelta` is given a sufficiently strong negative/lexicographic treatment rather than a simple additive weight.
