**Criterion.**  
A function `μ : Trace → Nat` is a termination measure for the given rewrite system iff for **every** rule `l → r` we have `μ(l) > μ(r)`.  
Below we check the eight rules for each candidate. The only problematic rule turns out to be `R_rec_succ`; the other seven are strictly decreasing for all three measures.

---

### 1. `mu1`

| Rule | `mu1` of LHS | `mu1` of RHS | Status |
|------|--------------|--------------|--------|
| `R_int_delta` | `2 + mu1 t` | `0` | ✓ |
| `R_merge_void_left` | `1 + mu1 t` | `mu1 t` | ✓ |
| `R_merge_void_right` | `1 + mu1 t` | `mu1 t` | ✓ |
| `R_merge_cancel` | `1 + 2·mu1 t` | `mu1 t` | ✓ |
| `R_rec_zero` | `1 + mu1 b + mu1 s` | `mu1 b` | ✓ |
| `R_rec_succ` | `2 + mu1 b + mu1 s + mu1 n` | `2 + mu1 b + 2·mu1 s + mu1 n` | **✗** |
| `R_eq_refl` | `3 + 2·mu1 a` | `0` | ✓ |
| `R_eq_diff` | `3 + mu1 a + mu1 b` | `2 + mu1 a + mu1 b` | ✓ |

**Failure on `R_rec_succ`.**  
`mu1(recDelta b s (delta n)) = 2 + mu1 b + mu1 s + mu1 n`  
`mu1(app s (recDelta b s n)) = 2 + mu1 b + 2·mu1 s + mu1 n`

The RHS contains **two** copies of `s` (one inside `app`, one inside the nested `recDelta`) whereas the LHS contains only one. The difference is `−mu1 s`.  
- If `s = void` the two sides are **equal** (not strictly smaller).  
- If `s` is larger, the RHS is strictly **bigger** than the LHS.  

Hence `mu1` does not decrease on this rule.

---

### 2. `mu2`

| Rule | `mu2` of LHS | `mu2` of RHS | Status |
|------|--------------|--------------|--------|
| `R_int_delta` | `3 + mu2 t` | `0` | ✓ |
| `R_merge_void_left` | `2 + mu2 t` | `mu2 t` | ✓ |
| `R_merge_void_right` | `2 + mu2 t` | `mu2 t` | ✓ |
| `R_merge_cancel` | `2 + 2·mu2 t` | `mu2 t` | ✓ |
| `R_rec_zero` | `5 + mu2 b + mu2 s` | `mu2 b` | ✓ |
| `R_rec_succ` | `6 + mu2 b + mu2 s + mu2 n` | `6 + mu2 b + 2·mu2 s + mu2 n` | **✗** |
| `R_eq_refl` | `5 + 2·mu2 a` | `0` | ✓ |
| `R_eq_diff` | `5 + mu2 a + mu2 b` | `4 + mu2 a + mu2 b` | ✓ |

**Failure on `R_rec_succ`.**  
Exactly the same structural duplication of `s` defeats the larger constants. The difference is again `−mu2 s`.  
- If `s = void` the measures are **equal**.  
- Otherwise the RHS is larger.  

Thus `mu2` is also not a valid termination measure.

---

### 3. `mu3`

| Rule | `mu3` of LHS | `mu3` of RHS | Status |
|------|--------------|--------------|--------|
| `R_int_delta` | `3 + mu3 t` | `0` | ✓ |
| `R_merge_void_left` | `1 + mu3 t` | `mu3 t` | ✓ |
| `R_merge_void_right` | `1 + mu3 t` | `mu3 t` | ✓ |
| `R_merge_cancel` | `1 + 2·mu3 t` | `mu3 t` | ✓ |
| `R_rec_zero` | `1 + mu3 b + mu3 s` | `mu3 b` | ✓ |
| `R_rec_succ` | `2 + mu3 b + mu3 s + mu3 n` | `3 + mu3 b + 2·mu3 s + mu3 n` | **✗** |
| `R_eq_refl` | `4 + 2·mu3 a` | `0` | ✓ |
| `R_eq_diff` | `4 + mu3 a + mu3 b` | `3 + mu3 a + mu3 b` | ✓ |

**Failure on `R_rec_succ`.**  
Here the RHS is even heavier because `app` carries weight `2` while `delta` carries weight `1`. The difference is `−1 − mu3 s`, which is **strictly negative for every `s`** (even when `s = void`). So `mu3` actually **increases** on this rule.

---

### Summary

- **None of the three candidates is a correct termination measure.**  
- The common fatal flaw is the rule `R_rec_succ`:  
  `recDelta b s (delta n) → app s (recDelta b s n)`.  
  The right-hand side duplicates the subterm `s`. Because `mu1`, `mu2`, and `mu3` are all additive tree-size measures, the extra copy of `s` on the right contributes an additional `μ(s)` that no fixed constructor weight can offset.  
- **Consequences:**  
  - `mu1` and `mu2` preserve measure when `s = void` and grow when `s` is larger.  
  - `mu3` strictly grows on `R_rec_succ` for every `s`.  

All other seven rules strictly decrease under all three measures, but because a termination measure must decrease on **every** rule, all three candidates are invalid.
