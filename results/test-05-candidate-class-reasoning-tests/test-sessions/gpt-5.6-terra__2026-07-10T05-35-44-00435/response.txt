None of the three candidates is a valid strict termination measure for all `Step` rules.

The problematic rule is:

```lean
R_rec_succ :
  Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

Let `B = μ b`, `S = μ s`, and `N = μ n`.

| Measure | LHS of `R_rec_succ` | RHS of `R_rec_succ` | LHS − RHS | Result |
|---|---:|---:|---:|---|
| `mu1` | `2 + B + S + N` | `2 + B + 2*S + N` | `-S` | Equal when `s = void`; increases when `s` is non-void |
| `mu2` | `6 + B + S + N` | `6 + B + 2*S + N` | `-S` | Equal when `s = void`; increases when `s` is non-void |
| `mu3` | `2 + B + S + N` | `3 + B + 2*S + N` | `-1 - S` | Always increases |

Concrete counterexample for `mu1` and `mu2`: take `b = s = n = void`.

```lean
recDelta void void (delta void)
  --> app void (recDelta void void void)
```

Then:

- `mu1` is `2` on both sides.
- `mu2` is `6` on both sides.

So neither gives strict decrease.

For `mu3`, on that same example:

- LHS has value `2`;
- RHS has value `3`;

so the rewrite strictly increases the measure.

All other rules do strictly decrease under each candidate:

- `R_int_delta`, both `R_merge_void_*`, `R_merge_cancel`, `R_rec_zero`, and `R_eq_refl` decrease by an evidently positive amount.
- `R_eq_diff` decreases by exactly `1` for all three measures.

In particular, the `R_eq_diff` constants were chosen adequately:

```lean
eqW a b --> integrate (merge a b)
```

has measure changes:

- `mu1`: `3 + μ(a) + μ(b)` to `2 + μ(a) + μ(b)`;
- `mu2`: `5 + μ(a) + μ(b)` to `4 + μ(a) + μ(b)`;
- `mu3`: `4 + μ(a) + μ(b)` to `3 + μ(a) + μ(b)`.

Thus the assessment is:

- **`mu1`: invalid**, due to `R_rec_succ`.
- **`mu2`: invalid**, due to `R_rec_succ`.
- **`mu3`: invalid**, due to `R_rec_succ`, and worse: that rule always increases it.

The failure is caused by the recursive occurrence of `s`: it appears once on the left inside `recDelta`, but on the right it appears both as the outer `app` argument and inside the recursive `recDelta`.
