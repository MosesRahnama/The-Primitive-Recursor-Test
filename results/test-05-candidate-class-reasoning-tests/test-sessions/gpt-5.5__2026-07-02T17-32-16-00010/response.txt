All three candidates **fail** as strict `Nat` termination measures for `Step`.

The obstruction is the same in each case: the rule

```lean
R_rec_succ :
  Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

does not decrease the proposed measure.

### `mu1`

For the recursive-successor rule:

```lean
mu1 (recDelta b s (delta n))
= 1 + mu1 b + mu1 s + (1 + mu1 n)
= 2 + mu1 b + mu1 s + mu1 n
```

but

```lean
mu1 (app s (recDelta b s n))
= 1 + mu1 s + (1 + mu1 b + mu1 s + mu1 n)
= 2 + mu1 b + 2 * mu1 s + mu1 n
```

So the RHS is larger by `mu1 s`, or equal when `mu1 s = 0`.

Example counterexample:

```lean
b = void, s = void, n = void
```

Both sides have `mu1 = 2`, so there is no strict decrease.

Thus `mu1` is invalid.

---

### `mu2`

For `R_rec_succ`:

```lean
mu2 (recDelta b s (delta n))
= 5 + mu2 b + mu2 s + (1 + mu2 n)
= 6 + mu2 b + mu2 s + mu2 n
```

while

```lean
mu2 (app s (recDelta b s n))
= 1 + mu2 s + (5 + mu2 b + mu2 s + mu2 n)
= 6 + mu2 b + 2 * mu2 s + mu2 n
```

Again the RHS is larger by `mu2 s`, or equal when `s = void`.

Example:

```lean
b = void, s = void, n = void
```

Both sides have `mu2 = 6`.

Thus `mu2` is invalid.

---

### `mu3`

For `R_rec_succ`:

```lean
mu3 (recDelta b s (delta n))
= 1 + mu3 b + mu3 s + (1 + mu3 n)
= 2 + mu3 b + mu3 s + mu3 n
```

but

```lean
mu3 (app s (recDelta b s n))
= 2 + mu3 s + (1 + mu3 b + mu3 s + mu3 n)
= 3 + mu3 b + 2 * mu3 s + mu3 n
```

The RHS exceeds the LHS by

```lean
1 + mu3 s
```

so this rule always increases the measure.

Thus `mu3` is invalid.

---

### Summary

| Measure | Valid termination measure? | Reason |
|---|---:|---|
| `mu1` | No | `R_rec_succ` is non-decreasing; equal when `s = void` |
| `mu2` | No | `R_rec_succ` is non-decreasing; equal when `s = void` |
| `mu3` | No | `R_rec_succ` strictly increases |

The other rules appear to decrease these measures, but since each candidate fails on `R_rec_succ`, none of the three is a valid strict termination measure for the whole rewrite relation.
