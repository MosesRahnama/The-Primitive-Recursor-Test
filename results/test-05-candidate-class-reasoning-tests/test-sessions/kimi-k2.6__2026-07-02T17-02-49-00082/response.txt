**Short answer:** none of the three functions is a valid termination measure for the rewrite system.  
All of them work for every rule **except** `R_rec_succ`, where every candidate either stagnates or increases. The culprit is the duplication of the step argument `s` on the right-hand side of that rule.

---

### What a termination measure must satisfy

A function `mu : Trace → Nat` is a termination measure for `Step` iff for **every** rule  
`l ⟶ r` and **every** substitution of the variables, `mu l > mu r`.  
If even one rule can be instantiated so that `mu l ≤ mu r`, the measure fails.

---

### Rules that all three measures satisfy

For the following rules a direct calculation shows strict decrease for `mu1`, `mu2` and `mu3`:

| Rule | `mu1` | `mu2` | `mu3` |
|------|-------|-------|-------|
| `R_int_delta` | `2+mu1(t) > 0` | `3+mu2(t) > 0` | `3+mu3(t) > 0` |
| `R_merge_void_left` | `1+mu1(t) > mu1(t)` | `2+mu2(t) > mu2(t)` | `1+mu3(t) > mu3(t)` |
| `R_merge_void_right` | same | same | same |
| `R_merge_cancel` | `1+2·mu1(t) > mu1(t)` | `2+2·mu2(t) > mu2(t)` | `1+2·mu3(t) > mu3(t)` |
| `R_rec_zero` | `1+mu1(b)+mu1(s) > mu1(b)` | `5+mu2(b)+mu2(s) > mu2(b)` | `1+mu3(b)+mu3(s) > mu3(b)` |
| `R_eq_refl` | `3+2·mu1(a) > 0` | `5+2·mu2(a) > 0` | `4+2·mu3(a) > 0` |
| `R_eq_diff` | `3+a+b > 2+a+b` | `5+a+b > 4+a+b` | `4+a+b > 3+a+b` |

So the only possible obstruction is `R_rec_succ`.

---

### The killer rule: `R_rec_succ`

```
recDelta b s (delta n)  ⟶  app s (recDelta b s n)
```

Let us write `b,s,n` as shorthand for `mu(b), mu(s), mu(n)`.

#### `mu1`
- LHS: `mu1(recDelta b s (delta n)) = 1 + b + s + (1 + n) = 2 + b + s + n`
- RHS: `mu1(app s (recDelta b s n)) = 1 + s + (1 + b + s + n) = 2 + b + 2s + n`

**Result:** `RHS = LHS + s = LHS + mu1(s)`.  
If `s = void` the two sides are **equal**; otherwise the RHS is **strictly larger**.  
`mu1` does **not** strictly decrease.

#### `mu2`
- LHS: `5 + b + s + (1 + n) = 6 + b + s + n`
- RHS: `1 + s + (5 + b + s + n) = 6 + b + 2s + n`

**Result:** `RHS = LHS + s = LHS + mu2(s)`.  
Again, equality when `s = void`, and a strict increase otherwise.  
`mu2` does **not** strictly decrease.

#### `mu3`
- LHS: `1 + b + s + (1 + n) = 2 + b + s + n`
- RHS: `2 + s + (1 + b + s + n) = 3 + b + 2s + n`

**Result:** `RHS = LHS + 1 + s = LHS + 1 + mu3(s)`.  
Here the RHS is **strictly larger for every** `s`, including `void`.  
`mu3` does **not** strictly decrease; it actually increases on this rule.

---

### Why this happens

All three candidates are *additive* (or *linear*) measures: each occurrence of a subterm contributes its measure positively, and constructor symbols contribute only a constant.  
`R_rec_succ` duplicates the variable `s`—it occurs once on the left but twice on the right (once as the first argument of `app`, once inside the recursive `recDelta`). Because the coefficients of all arguments are `1`, the extra occurrence of `s` on the right adds an additional `mu(s)` that no choice of positive constants can cancel. Changing the constant attached to `recDelta` or `app` does not help, because the constant appears on **both** sides and cancels out.

---

### Verdict

| Measure | Verdict | Reason |
|---------|---------|--------|
| **`mu1`** | **Invalid** | Stagnates when `s = void`; increases when `s` is non-void on `R_rec_succ`. |
| **`mu2`** | **Invalid** | Same defect as `mu1`: stagnates for `s = void`, otherwise increases on `R_rec_succ`. |
| **`mu3`** | **Invalid** | Strictly increases on `R_rec_succ` for **all** instantiations of `s`. |

**Conclusion:** *None* of the proposed measures proves termination of the calculus. A valid measure would need to assign a higher weight to the third argument of `recDelta` (so that reducing `delta n` to `n` offsets the duplication of `s`) or use a non-linear/lexicographic encoding rather than a simple sum-of-subterms.
