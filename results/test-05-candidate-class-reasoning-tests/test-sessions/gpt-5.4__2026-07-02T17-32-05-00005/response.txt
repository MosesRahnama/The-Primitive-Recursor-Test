Here’s the assessment of the three proposed measures as potential **strictly decreasing termination measures** for every `Step`.

We check, for each rule, whether `μ(lhs) > μ(rhs)` always holds.

---

## Candidate `mu1`

### Quick verdict
**Fails**.

### Why
Most rules decrease, but `R_eq_diff` does not.

Rule:
```lean
Step (eqW a b) (integrate (merge a b))
```

Compute both sides under `mu1`:

- LHS:
  \[
  \mu1(eqW\ a\ b) = 3 + \mu1(a) + \mu1(b)
  \]

- RHS:
  \[
  \mu1(integrate (merge a b)) = 1 + (1 + \mu1(a) + \mu1(b)) = 2 + \mu1(a) + \mu1(b)
  \]

So this rule **does** decrease by 1.

But `R_rec_succ` fails:

```lean
Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

LHS:
\[
\mu1(recDelta\ b\ s\ (\delta n))
= 1 + \mu1(b) + \mu1(s) + (1 + \mu1(n))
= 2 + \mu1(b) + \mu1(s) + \mu1(n)
\]

RHS:
\[
\mu1(app\ s\ (recDelta\ b\ s\ n))
= 1 + \mu1(s) + (1 + \mu1(b) + \mu1(s) + \mu1(n))
= 2 + \mu1(b) + 2\mu1(s) + \mu1(n)
\]

Difference:
\[
\text{RHS} - \text{LHS} = \mu1(s)
\]

So if `s ≠ void`, RHS is larger; if `s = void`, they are equal. In no case is there a strict decrease for all `s`.

### Conclusion
`mu1` is **not** a valid termination measure for `Step`.

## Candidate `mu2`

### Quick verdict
**Works**.

### Check each rule

#### 1. `R_int_delta`
```lean
integrate (delta t) → void
```

- LHS:
  \[
  2 + (1 + \mu2(t)) = 3 + \mu2(t)
  \]
- RHS:
  \[
  0
  \]

Strict decrease.

---

#### 2. `R_merge_void_left`
```lean
merge void t → t
```

- LHS:
  \[
  2 + 0 + \mu2(t) = 2 + \mu2(t)
  \]
- RHS:
  \[
  \mu2(t)
  \]

Strict decrease by 2.

---

#### 3. `R_merge_void_right`
Same reasoning: strict decrease by 2.

---

#### 4. `R_merge_cancel`
```lean
merge t t → t
```

- LHS:
  \[
  2 + \mu2(t) + \mu2(t) = 2 + 2\mu2(t)
  \]
- RHS:
  \[
  \mu2(t)
  \]

Strict decrease.

---

#### 5. `R_rec_zero`
```lean
recDelta b s void → b
```

- LHS:
  \[
  5 + \mu2(b) + \mu2(s) + 0
  \]
- RHS:
  \[
  \mu2(b)
  \]

Strict decrease.

---

#### 6. `R_rec_succ`
```lean
recDelta b s (delta n) → app s (recDelta b s n)
```

LHS:
\[
5 + \mu2(b) + \mu2(s) + (1 + \mu2(n))
= 6 + \mu2(b) + \mu2(s) + \mu2(n)
\]

RHS:
\[
1 + \mu2(s) + (5 + \mu2(b) + \mu2(s) + \mu2(n))
= 6 + \mu2(b) + 2\mu2(s) + \mu2(n)
\]

Difference:
\[
\text{LHS} - \text{RHS} = -\mu2(s)
\]

So this is **not** decreasing unless `s = void`, and equal when `s = void`. Thus it fails.

So `mu2` does **not** work.

## Candidate `mu3`

### Quick verdict
**Fails**.

### Critical rule: `R_rec_succ`

```lean
recDelta b s (delta n) → app s (recDelta b s n)
```

LHS:
\[
\mu3(recDelta\ b\ s\ (\delta n))
= 1 + \mu3(b) + \mu3(s) + (1 + \mu3(n))
= 2 + \mu3(b) + \mu3(s) + \mu3(n)
\]

RHS:
\[
\mu3(app\ s\ (recDelta\ b\ s\ n))
= 2 + \mu3(s) + (1 + \mu3(b) + \mu3(s) + \mu3(n))
= 3 + \mu3(b) + 2\mu3(s) + \mu3(n)
\]

Again RHS exceeds LHS by:
\[
1 + \mu3(s)
\]

So it definitely fails.

Also `R_eq_diff` is only barely decreasing:

- LHS:
  \[
  4 + \mu3(a) + \mu3(b)
  \]
- RHS:
  \[
  2 + (1 + \mu3(a) + \mu3(b)) = 3 + \mu3(a) + \mu3(b)
  \]

That one is fine, but `R_rec_succ` already kills the candidate.

### Conclusion
`mu3` is **not** a valid termination measure.

# Final summary

- **`mu1`**: **invalid**
- **`mu2`**: **invalid**
- **`mu3`**: **invalid**

## Common reason for failure
All three candidates fail on the recursive successor rule
```lean
recDelta b s (delta n) → app s (recDelta b s n)
```
because the right-hand side contains both:
- the recursive term `recDelta b s n`, and
- an additional copy of `s` via `app s ...`

Any purely additive size measure of the form used here will count `s` twice on the RHS but only once on the LHS, so it cannot strictly decrease for all `s`.
