## Assessment of Termination Measures

I will assess each candidate `mu` by checking whether `mu(lhs) > mu(rhs)` holds for every rule `Step lhs rhs`. The decisive test is the **`R_rec_succ`** rule

```
recDelta b s (delta n)   →   app s (recDelta b s n)
```

because the body `s` is *kept* on the RHS (inside an `app` node) and is therefore counted in **both** `app` and `recDelta` subterms, but the head `recDelta` only "removes" the single `delta` constructor at the front of `n`.

---

### Candidate `mu1`

For `R_rec_succ` with `b = void`, `s = delta void`, `n = void`:

* `mu1 (recDelta void (delta void) (delta void))` = 1 + 0 + 1 + 1 = **3**
* `mu1 (app (delta void) (recDelta void (delta void) void))` = 1 + 1 + (1 + 0 + 1 + 0) = **4**

`3 < 4`, so the measure **increases**. ❌

In general,
```
mu1(lhs) − mu1(rhs) = (1 + μ(b) + μ(s) + 1 + μ(n))
                    − (1 + μ(s) + 1 + μ(b) + μ(s) + μ(n))
                    = −μ(s)  ≤  0
```
which is strictly negative whenever `s` is non-`void`.

---

### Candidate `mu2`

Same rule, `b = void`, `s = delta void`, `n = void`:

* `mu2 (recDelta void (delta void) (delta void))` = 5 + 0 + 1 + 1 = **7**
* `mu2 (app (delta void) (recDelta void (delta void) void))` = 1 + 1 + (5 + 0 + 1 + 0) = **8**

`7 < 8`. ❌

The arithmetic is
```
mu2(lhs) − mu2(rhs) = (5 + μ(b) + μ(s) + 1 + μ(n))
                    − (1 + μ(s) + 5 + μ(b) + μ(s) + μ(n))
                    = −μ(s)  ≤  0
```
Same defect as `mu1`: the constant `+5` on `recDelta` does not help, because it is also inherited by the inner recursive call on the RHS.

---

### Candidate `mu3`

Same rule, `b = void`, `s = delta void`, `n = void`:

* `mu3 (recDelta void (delta void) (delta void))` = 1 + 0 + 1 + 1 = **3**
* `mu3 (app (delta void) (recDelta void (delta void) void))` = 2 + 1 + (1 + 0 + 1 + 0) = **5**

`3 < 5`. ❌

Here
```
mu3(lhs) − mu3(rhs) = (1 + μ(b) + μ(s) + 1 + μ(n))
                    − (2 + μ(s) + 1 + μ(b) + μ(s) + μ(n))
                    = −1 − μ(s)  <  0
```
The `+2` on `app` (chosen, one assumes, to dominate `recDelta`'s `+1`) actually makes things *worse* for the recursion rule, because the `s` is paid for in **both** the `app` and the inner `recDelta` on the RHS.

---

## Summary

| Measure | All other rules | `R_rec_succ` | Valid? |
|---------|----------------|--------------|--------|
| `mu1`   | OK             | increases    | **No** |
| `mu2`   | OK             | increases    | **No** |
| `mu3`   | OK             | increases    | **No** |

**None of the three candidates is a valid termination measure.** They all fail on the same rule, `R_rec_succ`, for the same structural reason: the body `s` of the recursor survives the rewrite inside an `app` node, and no purely additive weighting of the constructors can simultaneously (a) make `app` strictly larger than the `s` it wraps, (b) make `recDelta` strictly larger than its recursion, and (c) ensure that the head `delta` peeling in the LHS is enough to dominate the *doubled* cost of `s` on the RHS. A correct measure would need a non-additive structure (e.g., a lexicographic or multiset order), or the rewrite rule itself would need to be restricted (e.g., a guard ensuring `s` is smaller in a separate well-founded ordering).
