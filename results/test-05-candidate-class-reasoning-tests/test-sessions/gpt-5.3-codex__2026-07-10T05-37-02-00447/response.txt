Here’s the audit of the three measures as **strict one-step decrease candidates** for `Step`:

## Criterion
A valid simple termination measure `μ : Trace → Nat` should satisfy, for every rule `Step l r`,
\[
μ(l) > μ(r).
\]

---

## `mu1` — **fails**

Counterexample rule: `R_merge_void_left : Step (merge void t) t`

- `mu1 (merge void t) = 1 + mu1 void + mu1 t = 1 + 0 + mu1 t = 1 + mu1 t`
- `mu1 t = mu1 t`

This one is fine (decreases by 1). But failure occurs at:

`R_rec_succ : Step (recDelta b s (delta n)) (app s (recDelta b s n))`

- LHS:
  \[
  mu1(recDelta\, b\, s\, (delta\, n))
  = 1 + mu1 b + mu1 s + (1 + mu1 n)
  = 2 + mu1 b + mu1 s + mu1 n
  \]
- RHS:
  \[
  mu1(app\, s\, (recDelta\, b\, s\, n))
  = 1 + mu1 s + (1 + mu1 b + mu1 s + mu1 n)
  = 2 + mu1 b + 2\cdot mu1 s + mu1 n
  \]

Need `LHS > RHS`, i.e. `2 + b + s + n > 2 + b + 2s + n`, impossible unless `s < 0`.  
So `mu1` is **not** strictly decreasing.

(Also `R_eq_diff` is nondecreasing/equal for some terms: `mu1 (eqW a b)=3+...`, RHS `integrate (merge a b)=1+(1+...)=2+...`, that part is okay; main failure is `R_rec_succ`.)

---

## `mu2` — **valid**

Check the critical rules quickly:

- `R_int_delta`:  
  `mu2(integrate(delta t)) = 2 + (1 + mu2 t) = 3 + mu2 t > 0 = mu2(void)`
- `R_merge_void_left/right`: `2 + ... > ...`
- `R_merge_cancel`:  
  `mu2(merge t t)=2+2mu2 t > mu2 t`
- `R_rec_zero`:  
  `mu2(recDelta b s void)=5+mu2 b+mu2 s > mu2 b`
- `R_rec_succ`:
  - LHS: `5 + b + s + (1+n) = 6 + b + s + n`
  - RHS: `1 + s + (5 + b + s + n) = 6 + b + 2s + n`
  This seems problematic at first glance, but actually yes: RHS has extra `s`, so not always smaller.  
  So this **fails** unless `s=0`.

So `mu2` is **also invalid** because of `R_rec_succ`.

---

## `mu3` — **fails**

Again `R_rec_succ`:

- LHS:
  \[
  mu3(recDelta\, b\, s\, (delta\, n))
  = 1 + b + s + (1+n)
  = 2 + b + s + n
  \]
- RHS:
  \[
  mu3(app\, s\, (recDelta\, b\, s\, n))
  = 2 + s + (1 + b + s + n)
  = 3 + b + 2s + n
  \]
Need `2 + b + s + n > 3 + b + 2s + n`, impossible. So fails.

Also `R_eq_diff`:
- LHS `4 + a + b`
- RHS `mu3(integrate(merge a b)) = 2 + (1 + a + b)=3+a+b`
This one decreases, but `R_rec_succ` already kills it.

---

## Final verdict

- **`mu1`: invalid**
- **`mu2`: invalid**
- **`mu3`: invalid**

All three fail because of the `R_rec_succ` rule, where the RHS duplicates/retains `s` through `app s (...)`, and each proposed measure gives nonnegative weight to that duplication, preventing strict decrease in general.
