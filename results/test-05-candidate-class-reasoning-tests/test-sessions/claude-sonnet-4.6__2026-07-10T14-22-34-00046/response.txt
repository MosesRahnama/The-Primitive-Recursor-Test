## Checking mu1

**R_int_delta**: `integrate(delta t)` → `void`
- LHS: 1 + (1 + mu1 t) = 2 + mu1 t. RHS: 0. ✓

**R_merge_void_left**: `merge void t` → `t`
- LHS: 1 + 0 + mu1 t = 1 + mu1 t > mu1 t. ✓

**R_merge_void_right**: `merge t void` → `t`
- LHS: 1 + mu1 t + 0 > mu1 t. ✓

**R_merge_cancel**: `merge t t` → `t`
- LHS: 1 + mu1 t + mu1 t > mu1 t. ✓

**R_rec_zero**: `recDelta b s void` → `b`
- LHS: 1 + mu1 b + mu1 s + 0 = 1 + mu1 b + mu1 s > mu1 b. ✓

**R_rec_succ**: `recDelta b s (delta n)` → `app s (recDelta b s n)`
- LHS: 1 + mu1 b + mu1 s + (1 + mu1 n) = 2 + mu1 b + mu1 s + mu1 n
- RHS: 1 + mu1 s + (1 + mu1 b + mu1 s + mu1 n) = 2 + mu1 b + 2·mu1 s + mu1 n
- Need LHS > RHS: 2 + mu1 b + mu1 s + mu1 n > 2 + mu1 b + 2·mu1 s + mu1 n → 0 > mu1 s. **FAILS** when s ≠ void.

**mu1 is not a valid termination measure.**

## Conclusion

**All three candidates fail**, all on `R_rec_succ`. The core problem: `app` gets weight `≥ 1` added, but `recDelta b s n` reappears inside the RHS, and `s` appears twice on the right but once on the left, so no measure with `mu(app a b) = c + mu(a) + mu(b)` can decrease unless `recDelta` is weighted much more heavily than `app` to absorb the extra copy of `s`.
