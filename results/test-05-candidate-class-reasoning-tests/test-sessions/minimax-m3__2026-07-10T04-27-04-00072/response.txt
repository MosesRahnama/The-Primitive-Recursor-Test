# Assessment of Termination Measures

I evaluated each measure `mu` by checking whether `mu(lhs) > mu(rhs)` holds for every constructor of `Step`. The critical case for all three is `R_rec_succ`:

> `recDelta b s (delta n)  →  app s (recDelta b s n)`

The lhs carries one copy of `s` and the recursive spine `(b, s, n)`, while the rhs carries **two** copies of `s` plus the same recursive spine. So the right-hand side gains exactly `mu(s)` extra weight that the lhs does not pay, and no candidate gives `s` weight that is forced to be zero.

## Counterexample for the failing rule

Take `b = void`, `s = delta void`, `n = void`. Then `mu(s) = 1` for all three measures.

| | `recDelta void (delta void) (delta void)` | `app (delta void) (recDelta void (delta void) void)` | Δ |
|--|--|--|--|
| `mu1` | `1+0+1+1 = 3` | `1+1+(1+0+1+0) = 4` | **LHS < RHS** |
| `mu2` | `5+0+1+1 = 7` | `1+1+(5+0+1+0) = 8` | **LHS < RHS** |
| `mu3` | `1+0+1+1 = 3` | `2+1+(1+0+1+0) = 5` | **LHS < RHS** |

In fact, the gap grows with `mu(s)`, so this is not a borderline equality.

## Per-measure verdict

### `mu1` — **fails**
Verified for the other rules:

- `R_int_delta`: `2 + mu1(t) > 0` ✓
- `R_merge_void_left/right`: `1 + mu1(t) > mu1(t)` ✓
- `R_merge_cancel`: `1 + 2·mu1(t) > mu1(t)` ✓
- `R_rec_zero`: `1 + mu1(b) + mu1(s) > mu1(b)` ✓
- `R_eq_refl`: `3 + 2·mu1(a) > 0` ✓
- `R_eq_diff`: `3 + mu1(a) + mu1(b) > 2 + mu1(a) + mu1(b)` ✓

But `R_rec_succ` gives `2 + mu1(b) + mu1(s) + mu1(n) < 2 + mu1(b) + 2·mu1(s) + mu1(n)`. **Invalid.**

### `mu2` — **fails**
Other rules check out (e.g. `R_eq_diff`: `5 + … > 4 + …`; `R_rec_zero`: `5 + mu2(b) + mu2(s) > mu2(b)`), but `R_rec_succ` yields `6 + mu2(b) + mu2(s) + mu2(n) < 6 + mu2(b) + 2·mu2(s) + mu2(n)`. **Invalid.**

### `mu3` — **fails**
`R_eq_diff` works because `4 + … > 3 + …`, and the merge/rec_zero rules are fine. But `R_rec_succ` gives `2 + mu3(b) + mu3(s) + mu3(n) < 3 + mu3(b) + 2·mu3(s) + mu3(n)`. **Invalid.**

## Summary

| Measure | Valid for `R_int_delta` | Valid for `R_merge_*` | Valid for `R_rec_zero` | Valid for `R_rec_succ` | Valid for `R_eq_*` | **Verdict** |
|---|---|---|---|---|---|---|
| `mu1` | ✓ | ✓ | ✓ | **✗** | ✓ | not a termination measure |
| `mu2` | ✓ | ✓ | ✓ | **✗** | ✓ | not a termination measure |
| `mu3` | ✓ | ✓ | ✓ | **✗** | ✓ | not a termination measure |

All three candidates share the same structural defect: `R_rec_succ` introduces an additional occurrence of the step term `s` on the rhs that is not present on the lhs, and none of the weightings compensate for that. To obtain a sound measure, one would need either a multiset/polynomial interpretation that penalises the duplicated `s`, or a different measure that tracks the recursion depth (e.g. `mu(recDelta b s n) = mu(n) + 1`, ignoring `b` and `s`).
