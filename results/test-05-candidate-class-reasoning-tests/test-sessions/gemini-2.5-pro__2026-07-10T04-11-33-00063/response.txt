Here is an assessment of the three candidate termination measures for the given rewrite calculus.

A function `μ: Trace -> Nat` is a valid termination measure for the `Step` relation if for every rule `Step t₁ t₂`, the inequality `μ(t₁) > μ(t₂)` holds for all possible sub-traces.

### Summary

All three proposed measures (`mu1`, `mu2`, and `mu3`) are **invalid** termination measures. They all fail to prove termination for the recursive rule `R_rec_succ`. The core issue is that in the `R_rec_succ` step, the term `s` is duplicated, and none of the measures assign a sufficiently large weight to the `recDelta` constructor compared to the `app` constructor to account for this duplication.

---

### Candidate 1: `mu1`

`mu1` is a simple size-based measure where each constructor adds 1, except for `void` (0) and `eqW` (3).

Let's check each rewrite rule:
*   **R_int_delta:** `Step (integrate (delta t)) void`
    *   `mu1(integrate (delta t)) = 1 + mu1(delta t) = 1 + (1 + mu1 t) = 2 + mu1 t`
    *   `mu1(void) = 0`
    *   `2 + mu1 t > 0`. **Holds.**

*   **R_merge_void_left:** `Step (merge void t) t`
    *   `mu1(merge void t) = 1 + mu1(void) + mu1 t = 1 + 0 + mu1 t = 1 + mu1 t`
    *   `mu1(t)`
    *   `1 + mu1 t > mu1 t`. **Holds.**

*   **R_merge_void_right:** `Step (merge t void) t`
    *   `mu1(merge t void) = 1 + mu1 t + mu1(void) = 1 + mu1 t`
    *   `mu1(t)`
    *   `1 + mu1 t > mu1 t`. **Holds.**

*   **R_merge_cancel:** `Step (merge t t) t`
    *   `mu1(merge t t) = 1 + mu1 t + mu1 t = 1 + 2 * mu1 t`
    *   `mu1(t)`
    *   `1 + 2 * mu1 t > mu1 t` is equivalent to `1 + mu1 t > 0`, which is true. **Holds.**

*   **R_rec_zero:** `Step (recDelta b s void) b`
    *   `mu1(recDelta b s void) = 1 + mu1 b + mu1 s + mu1(void) = 1 + mu1 b + mu1 s`
    *   `mu1(b)`
    *   `1 + mu1 b + mu1 s > mu1 b` is equivalent to `1 + mu1 s > 0`, which is true. **Holds.**

*   **R_rec_succ:** `Step (recDelta b s (delta n)) (app s (recDelta b s n))`
    *   `mu1(LHS) = 1 + mu1 b + mu1 s + mu1(delta n) = 1 + mu1 b + mu1 s + (1 + mu1 n) = 2 + mu1 b + mu1 s + mu1 n`
    *   `mu1(RHS) = 1 + mu1 s + mu1(recDelta b s n) = 1 + mu1 s + (1 + mu1 b + mu1 s + mu1 n) = 2 + mu1 b + 2 * mu1 s + mu1 n`
    *   The condition is `2 + mu1 b + mu1 s + mu1 n > 2 + mu1 b + 2 * mu1 s + mu1 n`.
    *   This simplifies to `mu1 s > 2 * mu1 s`, which is false for any `mu1 s >= 0`. **FAILS.**

**Conclusion for `mu1`:** Invalid. It fails on rule `R_rec_succ`.

---

### Candidate 2: `mu2`

`mu2` adjusts the weights of some constructors, notably `integrate`, `merge`, `recDelta`, and `eqW`. Let's see if this fixes the issue.

*   **R_int_delta:** `3 + mu2 t > 0`. **Holds.**
*   **R_merge_void_left:** `2 + mu2 t > mu2 t`. **Holds.**
*   **R_merge_void_right:** `2 + mu2 t > mu2 t`. **Holds.**
*   **R_merge_cancel:** `2 + 2 * mu2 t > mu2 t`. **Holds.**
*   **R_rec_zero:** `5 + mu2 b + mu2 s > mu2 b`. **Holds.**

*   **R_rec_succ:** `Step (recDelta b s (delta n)) (app s (recDelta b s n))`
    *   `mu2(LHS) = 5 + mu2 b + mu2 s + mu2(delta n) = 5 + mu2 b + mu2 s + (1 + mu2 n) = 6 + mu2 b + mu2 s + mu2 n`
    *   `mu2(RHS) = 1 + mu2 s + mu2(recDelta b s n) = 1 + mu2 s + (5 + mu2 b + mu2 s + mu2 n) = 6 + mu2 b + 2 * mu2 s + mu2 n`
    *   The condition is `6 + mu2 b + mu2 s + mu2 n > 6 + mu2 b + 2 * mu2 s + mu2 n`.
    *   This simplifies to `mu2 s > 2 * mu2 s`, which is false for any `mu2 s >= 0`. **FAILS.**

**Conclusion for `mu2`:** Invalid. Despite different weights, it has the exact same structural flaw as `mu1` and fails on `R_rec_succ` for the same reason.

---

### Candidate 3: `mu3`

`mu3` changes the weights again, specifically giving `app` a weight of 2. This directly targets the constructor on the RHS of the problematic `R_rec_succ` rule.

*   **R_int_delta:** `3 + mu3 t > 0`. **Holds.**
*   **R_merge_void_left:** `1 + mu3 t > mu3 t`. **Holds.**
*   **R_merge_void_right:** `1 + mu3 t > mu3 t`. **Holds.**
*   **R_merge_cancel:** `1 + 2 * mu3 t > mu3 t`. **Holds.**
*   **R_rec_zero:** `1 + mu3 b + mu3 s > mu3 b`. **Holds.**

*   **R_rec_succ:** `Step (recDelta b s (delta n)) (app s (recDelta b s n))`
    *   `mu3(LHS) = 1 + mu3 b + mu3 s + mu3(delta n) = 1 + mu3 b + mu3 s + (1 + mu3 n) = 2 + mu3 b + mu3 s + mu3 n`
    *   `mu3(RHS) = 2 + mu3 s + mu3(recDelta b s n) = 2 + mu3 s + (1 + mu3 b + mu3 s + mu3 n) = 3 + mu3 b + 2 * mu3 s + mu3 n`
    *   The condition is `2 + mu3 b + mu3 s + mu3 n > 3 + mu3 b + 2 * mu3 s + mu3 n`.
    *   Subtracting common terms from both sides gives `2 > 3 + mu3 s`.
    *   Since `mu3 s` is a `Nat` (i.e., `mu3 s >= 0`), this inequality can never be true. In fact, the measure *increases* during this step. **FAILS.**

*   **R_eq_refl:** `Step (eqW a a) void`
    *   `mu3(eqW a a) = 4 + mu3 a + mu3 a = 4 + 2 * mu3 a`
    *   `mu3(void) = 0`
    *   `4 + 2 * mu3 a > 0`. **Holds.**

*   **R_eq_diff:** `Step (eqW a b) (integrate (merge a b))`
    *   `mu3(LHS) = 4 + mu3 a + mu3 b`
    *   `mu3(RHS) = 2 + mu3(merge a b) = 2 + (1 + mu3 a + mu3 b) = 3 + mu3 a + mu3 b`
    *   `4 + mu3 a + mu3 b > 3 + mu3 a + mu3 b`. **Holds.**

**Conclusion for `mu3`:** Invalid. It also fails on `R_rec_succ`. Increasing the weight of `app` was not sufficient to make the measure decrease.

---
### Final Assessment

All three candidates are **unsuitable** as termination measures. The `R_rec_succ` rule is the critical case that invalidates all of them. A valid measure for this system would likely need to assign a much larger weight to the `recDelta` constructor, such that its value is greater than the sum of the `app` constructor and the duplicated `s` term. For instance, a measure `μ` would need to satisfy `μ(recDelta b s n) > μ(app s (recDelta b s n)) - μ(recDelta b s (delta n))` which suggests `μ(recDelta b s n)` needs to be larger than `μ(app s (...))` plus an additional `μ(s)`. None of the proposed candidates achieve this.
