## Setup

To certify termination (strong normalization) of `Step` via a measure `μ : Trace → Nat`, one needs, for *every* instance of *every* rule (the rules are universally quantified over arbitrary `Trace`s), that

```
Step t t'  →  μ t' < μ t
```

I check this for all eight rule schemas against `mu1`, `mu2`, `mu3`.

## Rules 1–5, 7, 8: all three candidates succeed

Writing out the definitions, these six/seven rules reduce to simple arithmetic facts that hold for *all three* measures (the specific integer coefficients differ but never matter):

- `R_int_delta`: `μ(integrate(delta t)) = c_int + c_δ + μ t > 0 = μ(void)`. ✓ (all three)
- `R_merge_void_left/right`: `μ(merge void t) = c_merge + μ t > μ t`, symmetric case likewise. ✓ (all three)
- `R_merge_cancel`: `μ(merge t t) = c_merge + 2 μ t > μ t`. ✓ (all three)
- `R_rec_zero`: `μ(recDelta b s void) = c_rec + μ b + μ s > μ b`. ✓ (all three)
- `R_eq_refl`: `μ(eqW a a) = c_eq + 2 μ a > 0`. ✓ (all three)
- `R_eq_diff`: `μ(eqW a b) = c_eq + μ a + μ b` vs `μ(integrate(merge a b)) = c_int + c_merge + μ a + μ b`; in each candidate `c_eq > c_int + c_merge` by exactly 1, so this strictly decreases in all three (mu1: 3 vs 2, mu2: 5 vs 4, mu3: 4 vs 3). ✓ (all three)

So on 7 of the 8 rules, **all three measures behave correctly**.

## Rule 6 (`R_rec_succ`): all three candidates fail

This is the load-bearing case: `recDelta b s (delta n) → app s (recDelta b s n)`.

Generic computation (let `c_δ, c_app, c_rec` be the constructor coefficients):

```
LHS = c_rec + c_δ + μ b + μ s + μ n
RHS = c_app + c_rec + μ b + 2·μ s + μ n
RHS - LHS = (c_app - c_δ) + μ s
```

Because `s` is duplicated syntactically in the RHS (once as the direct argument of `app`, once again inside the nested `recDelta b s n`), **the coefficient of `μ s` is 1 on the left but 2 on the right** — this is structural and independent of the chosen constants. The result:

- **mu1** (`c_δ=1, c_app=1`): `RHS - LHS = μ1 s ≥ 0`. Non-strict: equality when `s = void`, strict *increase* whenever `μ1 s > 0`. **Fails.**
- **mu2** (`c_δ=1, c_app=1`): identical situation, `RHS - LHS = μ2 s ≥ 0`. **Fails** for exactly the same reason (the extra weight on `recDelta`/`eqW` in mu2 is irrelevant here, it cancels out).
- **mu3** (`c_δ=1, c_app=2`): `RHS - LHS = 1 + μ3 s ≥ 1 > 0` for *every* `s`. This measure doesn't just fail sometimes — it **strictly increases on every instance** of this rule. Worse than mu1/mu2.

So none of the three candidates witnesses `Step (recDelta b s (delta n)) (app s (recDelta b s n))` as measure-decreasing; each fails on this single rule, with mu3 being uniformly wrong and mu1/mu2 being wrong for all non-trivial `s`.

## Diagnosis

This isn't a matter of picking better constants: **no additive/weighted node-count measure of this shape can ever validate `R_rec_succ`**, because the right-hand side literally contains two syntactic copies of `s` while the left-hand side contains one, and only `n` shrinks (by a fixed constant, one `delta` layer). Any fixed positive coefficients give `RHS - LHS = (c_app - c_δ) + μ s`, which cannot be made negative for all `s` since `μ s` is unbounded. Tuning `c_app, c_δ` only shifts where the crossover is (mu1/mu2 vs mu3), it can't eliminate the unbounded `μ s` term.

A working measure would need to avoid double-counting the duplicated subterm `s`, e.g.:
- a **lexicographic** measure with the size of the third argument of `recDelta` (or its `delta`-depth) as the primary component, and total size only as a tie-breaker not affected by duplication of `s`/`b`; or
- a genuine **recursive path / multiset order** rather than a scalar `Nat`; or
- a measure where `s` and `b` are not counted in the "decreasing" component at all (only `n`'s structure matters for that rule), tracked separately from the ordinary size measure used for the other rules.

## Verdict

- **mu1**: invalid termination measure — fails to strictly decrease on `R_rec_succ` (weakly increases/ties).
- **mu2**: invalid termination measure — same failure as mu1, for the identical structural reason.
- **mu3**: invalid termination measure — fails on `R_rec_succ` even more severely (strictly *increases* on every instance, no ties).

All other seven rules are handled correctly by all three candidates, but since termination requires *all* rule instances to decrease the measure, **none of mu1, mu2, mu3 is a valid termination measure for this rewrite system** as given.
