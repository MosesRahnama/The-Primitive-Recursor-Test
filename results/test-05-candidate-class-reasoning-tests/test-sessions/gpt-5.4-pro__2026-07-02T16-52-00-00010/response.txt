Assuming the intended check is:

> for every `Step t u`, does `muᵢ t > muᵢ u` hold?

then **none of the three candidates is a valid strict termination measure**.

## Quick rule-by-rule summary

Let `Δᵢ = muᵢ(lhs) - muᵢ(rhs)` for each rewrite rule.

| Rule | `Δ₁` | `Δ₂` | `Δ₃` |
|---|---:|---:|---:|
| `integrate (delta t) → void` | `2 + mu1 t` | `3 + mu2 t` | `3 + mu3 t` |
| `merge void t → t` | `1` | `2` | `1` |
| `merge t void → t` | `1` | `2` | `1` |
| `merge t t → t` | `1 + mu1 t` | `2 + mu2 t` | `1 + mu3 t` |
| `recDelta b s void → b` | `1 + mu1 s` | `5 + mu2 s` | `1 + mu3 s` |
| `recDelta b s (delta n) → app s (recDelta b s n)` | `- mu1 s` | `- mu2 s` | `-(1 + mu3 s)` |
| `eqW a a → void` | `3 + 2*mu1 a` | `5 + 2*mu2 a` | `4 + 2*mu3 a` |
| `eqW a b → integrate (merge a b)` | `1` | `1` | `1` |

So:

- All three candidates decrease on every rule **except** `R_rec_succ`.
- `R_rec_succ` kills all three.

---

## Candidate-by-candidate

### `mu1`
For the problematic rule:

```lean
recDelta b s (delta n) → app s (recDelta b s n)
```

we get

- LHS:
  `mu1 (recDelta b s (delta n)) = 2 + mu1 b + mu1 s + mu1 n`
- RHS:
  `mu1 (app s (recDelta b s n)) = 2 + mu1 b + 2*mu1 s + mu1 n`

So

```lean
mu1(lhs) - mu1(rhs) = - mu1 s
```

This is:

- `0` if `s = void`
- negative if `s` is nontrivial

So `mu1` is **not** strictly decreasing.

Concrete counterexample:
```lean
recDelta void void (delta void) → app void (recDelta void void void)
```
and both sides have `mu1 = 2`.

---

### `mu2`
Same issue:

- LHS:
  `mu2 (recDelta b s (delta n)) = 6 + mu2 b + mu2 s + mu2 n`
- RHS:
  `mu2 (app s (recDelta b s n)) = 6 + mu2 b + 2*mu2 s + mu2 n`

Hence

```lean
mu2(lhs) - mu2(rhs) = - mu2 s
```

Again:

- equal when `s = void`
- larger on the RHS when `s` is nontrivial

So `mu2` is also **not** a valid strict termination measure.

Concrete counterexample:
```lean
recDelta void void (delta void) → app void (recDelta void void void)
```
with `mu2 = 6` on both sides.

---

### `mu3`
This one fails even harder on `R_rec_succ`:

- LHS:
  `mu3 (recDelta b s (delta n)) = 2 + mu3 b + mu3 s + mu3 n`
- RHS:
  `mu3 (app s (recDelta b s n)) = 3 + mu3 b + 2*mu3 s + mu3 n`

So

```lean
mu3(lhs) - mu3(rhs) = -(1 + mu3 s)
```

This is **always negative**, so the rewrite always increases the measure.

Concrete counterexample:
```lean
recDelta void void (delta void) → app void (recDelta void void void)
```
with `mu3(lhs) = 2` and `mu3(rhs) = 3`.

---

## Bottom line

- **`mu1`: invalid**
- **`mu2`: invalid**
- **`mu3`: invalid**

The common structural problem is `R_rec_succ`: the RHS contains **two copies of `s`** (`app s (...)` and again inside `recDelta b s n`), while the LHS contains only one. Any purely additive “constructor weight + sum of subterm measures” metric of this shape is very likely to fail there.

One subtlety: this does **not** mean the rewrite relation itself is nonterminating. As written, `Step` is only a **root-step** relation (no context closure), so `app ...` has no outgoing rule at all. It just means these three `Nat`-valued measures do **not** certify termination by strict descent on every `Step`.
