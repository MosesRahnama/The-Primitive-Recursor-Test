Here is the audit of the three proposed measures as termination measures for the rewrite relation `Step`.

Goal for a valid candidate: for every rule `Step l r`, we need `μ l > μ r`.

---

## 1. Candidate `mu1`

```lean
def mu1 : Trace -> Nat
| .void => 0
| .delta t => 1 + mu1 t
| .integrate t => 1 + mu1 t
| .merge a b => 1 + mu1 a + mu1 b
| .app a b => 1 + mu1 a + mu1 b
| .recDelta b s n => 1 + mu1 b + mu1 s + mu1 n
| .eqW a b => 3 + mu1 a + mu1 b
```

### Check each rule

- `R_int_delta`:
  - LHS `integrate (delta t)` has measure `1 + (1 + μ₁ t) = 2 + μ₁ t`
  - RHS `void` has measure `0`
  - decreases

- `R_merge_void_left`:
  - `merge void t` has `1 + 0 + μ₁ t = 1 + μ₁ t`
  - RHS `t` has `μ₁ t`
  - decreases

- `R_merge_void_right`: same, decreases

- `R_merge_cancel`:
  - `merge t t` has `1 + 2μ₁ t`
  - RHS `t` has `μ₁ t`
  - decreases

- `R_rec_zero`:
  - `recDelta b s void` has `1 + μ₁ b + μ₁ s`
  - RHS `b` has `μ₁ b`
  - decreases

- `R_rec_succ`:
  - LHS `recDelta b s (delta n)`:
    `1 + μ₁ b + μ₁ s + (1 + μ₁ n) = 2 + μ₁ b + μ₁ s + μ₁ n`
  - RHS `app s (recDelta b s n)`:
    `1 + μ₁ s + (1 + μ₁ b + μ₁ s + μ₁ n) = 2 + μ₁ b + 2μ₁ s + μ₁ n`
  - need LHS > RHS, i.e.
    `2 + μb + μs + μn > 2 + μb + 2μs + μn`
    which is equivalent to `μs > 2μs`, impossible unless negative
  - in fact RHS is larger whenever `μ₁ s > 0`, and equal when `s = void`

So `mu1` **fails** on `R_rec_succ`.

- `R_eq_refl`:
  - `eqW a a` has `3 + 2μ₁ a > 0`
  - decreases

- `R_eq_diff`:
  - LHS `eqW a b`: `3 + μ₁ a + μ₁ b`
  - RHS `integrate (merge a b)`:
    `1 + (1 + μ₁ a + μ₁ b) = 2 + μ₁ a + μ₁ b`
  - decreases by 1

### Verdict on `mu1`
**Invalid** as a termination measure.  
It fails because `R_rec_succ` duplicates `s`, but `mu1` only counts `recDelta` with too small a weight.

---

## 2. Candidate `mu2`

```lean
def mu2 : Trace -> Nat
| .void => 0
| .delta t => 1 + mu2 t
| .integrate t => 2 + mu2 t
| .merge a b => 2 + mu2 a + mu2 b
| .app a b => 1 + mu2 a + mu2 b
| .recDelta b s n => 5 + mu2 b + mu2 s + mu2 n
| .eqW a b => 5 + mu2 a + mu2 b
```

### Check each rule

- `R_int_delta`:
  - LHS `integrate (delta t)`:
    `2 + (1 + μ₂ t) = 3 + μ₂ t`
  - RHS `0`
  - decreases

- `R_merge_void_left`:
  - `merge void t = 2 + μ₂ t > μ₂ t`
  - decreases

- `R_merge_void_right`: same

- `R_merge_cancel`:
  - `merge t t = 2 + 2μ₂ t > μ₂ t`
  - decreases

- `R_rec_zero`:
  - `recDelta b s void = 5 + μ₂ b + μ₂ s`
  - RHS `μ₂ b`
  - decreases

- `R_rec_succ`:
  - LHS:
    `recDelta b s (delta n)`
    = `5 + μ₂ b + μ₂ s + (1 + μ₂ n)`
    = `6 + μ₂ b + μ₂ s + μ₂ n`
  - RHS:
    `app s (recDelta b s n)`
    = `1 + μ₂ s + (5 + μ₂ b + μ₂ s + μ₂ n)`
    = `6 + μ₂ b + 2μ₂ s + μ₂ n`
  - need `6 + μb + μs + μn > 6 + μb + 2μs + μn`, i.e. `μs > 2μs`
  - false unless impossible; equal only if `μ₂ s = 0`

So `mu2` **fails** on `R_rec_succ` for the same structural reason.

- `R_eq_refl`:
  - `eqW a a = 5 + 2μ₂ a > 0`
  - decreases

- `R_eq_diff`:
  - LHS `5 + μ₂ a + μ₂ b`
  - RHS `integrate (merge a b)`:
    `2 + (2 + μ₂ a + μ₂ b) = 4 + μ₂ a + μ₂ b`
  - decreases by 1

### Verdict on `mu2`
**Invalid** as a termination measure.  
Again the blocker is `R_rec_succ`: the step introduces an extra copy of `s`, and the measure does not compensate.

## 3. Candidate `mu3`

```lean
def mu3 : Trace -> Nat
| .void => 0
| .delta t => 1 + mu3 t
| .integrate t => 2 + mu3 t
| .merge a b => 1 + mu3 a + mu3 b
| .app a b => 2 + mu3 a + mu3 b
| .recDelta b s n => 1 + mu3 b + mu3 s + mu3 n
| .eqW a b => 4 + mu3 a + mu3 b
```

### Check each rule

- `R_int_delta`:
  - `integrate (delta t) = 2 + (1 + μ₃ t) = 3 + μ₃ t > 0`
  - decreases

- `R_merge_void_left`:
  - `merge void t = 1 + μ₃ t > μ₃ t`
  - decreases

- `R_merge_void_right`: same

- `R_merge_cancel`:
  - `merge t t = 1 + 2μ₃ t > μ₃ t`
  - decreases

- `R_rec_zero`:
  - `recDelta b s void = 1 + μ₃ b + μ₃ s > μ₃ b`
  - decreases

- `R_rec_succ`:
  - LHS:
    `recDelta b s (delta n)`
    = `1 + μ₃ b + μ₃ s + (1 + μ₃ n)`
    = `2 + μ₃ b + μ₃ s + μ₃ n`
  - RHS:
    `app s (recDelta b s n)`
    = `2 + μ₃ s + (1 + μ₃ b + μ₃ s + μ₃ n)`
    = `3 + μ₃ b + 2μ₃ s + μ₃ n`
  - need `2 + μb + μs + μn > 3 + μb + 2μs + μn`
  - equivalent to `-1 > μs`, impossible

So `mu3` also **fails**, and even more strongly than the first two.

- `R_eq_refl`:
  - `eqW a a = 4 + 2μ₃ a > 0`
  - decreases

- `R_eq_diff`:
  - LHS `4 + μ₃ a + μ₃ b`
  - RHS `integrate (merge a b)`:
    `2 + (1 + μ₃ a + μ₃ b) = 3 + μ₃ a + μ₃ b`
  - decreases by 1

### Verdict on `mu3`
**Invalid** as a termination measure.  
It fails on `R_rec_succ`, and by a larger margin than `mu1`/`mu2`.

---

## Overall conclusion

None of the three candidates works.

### Common reason
All three are additive size-style measures. The problematic rule is:

```lean
Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

The RHS contains:
- one copy of `s` directly in `app s ...`
- another copy of `s` inside `recDelta b s n`

So any purely additive measure of the form
- constructor constant + sum of subterm measures

will tend to count `s` twice on the RHS but only once on the LHS. Unless the `recDelta` constructor carries enough extra “potential” specifically to pay for that duplication, the measure will not decrease.

In these three candidates, the extra constant on `recDelta` is never enough, because the failure depends on the size of `s`, not just a fixed constant.

---

## Short verdict table

- `mu1`: **reject**
- `mu2`: **reject**
- `mu3`: **reject**

All fail on `R_rec_succ`.
