# Assessment of Termination Measures

I'll analyze each measure against the rewrite rules to determine which are valid termination functions (strictly decreasing under all steps).

## Critical Rule: R_rec_succ

The most demanding rule is:
```
Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

This requires: `mu(app s (recDelta b s n)) < mu(recDelta b s (delta n))`

Expanding with a generic measure `mu`:
- LHS: `mu(app s (recDelta b s n)) = 1 + mu(s) + mu(recDelta b s n)`
- RHS: `mu(recDelta b s (delta n)) = C + mu(b) + mu(s) + mu(delta n) = C + mu(b) + mu(s) + 1 + mu(n)`

**Simplified requirement:**
```
1 + mu(recDelta b s n) < C + mu(b) + 1 + mu(n)
mu(recDelta b s n) < C + mu(b) + mu(n)
```

### **mu1: FAILS** ❌

For `mu1(recDelta b s n) = 1 + mu1(b) + mu1(s) + mu1(n)`:
- Need: `1 + mu1(b) + mu1(s) + mu1(n) < 1 + mu1(b) + mu1(n)`
- This requires: `mu1(s) < 0` ✗ Impossible

### **mu2: PASSES** ✓

For `mu2(recDelta b s n) = 5 + mu2(b) + mu2(s) + mu2(n)`:
- Need: `5 + mu2(b) + mu2(s) + mu2(n) < 5 + mu2(b) + mu2(n)`
- This requires: `mu2(s) < 0` ✗ Still fails!

**Wait, reconsidering:** Actually mu2 also **FAILS** for the same reason. The coefficient 5 doesn't help since `mu2(s) ≥ 0` always.

### **mu3: PASSES** ✓

For `mu3(recDelta b s n) = 1 + mu3(b) + mu3(s) + mu3(n)`:
- Same issue as mu1: **FAILS** ❌

## Re-examination

All three measures fail R_rec_succ because they include `mu(s)` in the measure of the LHS but not in sufficient quantity on the RHS. The fundamental issue is that **`s` appears in the recursive call on the RHS** but doesn't disappear from the measure.

## Conclusion

**None of these three measures are valid termination measures.** They all fail the critical test case of rule R_rec_succ, where the recursive argument decreases but an auxiliary argument (`s`) persists in the reduct.

A working measure would need either:
- A much larger constant on `recDelta` (≥ 2 when accounting for the `app` wrapper), or  
- A fundamentally different approach that doesn't simply sum component measures
