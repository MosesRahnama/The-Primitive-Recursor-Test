Assuming a “termination measure” means a ranking function `μ : Trace → Nat` such that every rewrite step strictly decreases it,

\[
Step\ t\ u \;\Rightarrow\; \mu(t) > \mu(u),
\]

then **none of `mu1`, `mu2`, `mu3` works**.

## Rule-by-rule summary

All three candidates are fine on every rule **except** `R_rec_succ`.

### `mu1`
For
```lean
R_rec_succ : Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

we get:
- lhs:
  \[
  \mu_1(recDelta\ b\ s\ (delta\ n)) = 1 + \mu_1 b + \mu_1 s + (1 + \mu_1 n)
  = 2 + \mu_1 b + \mu_1 s + \mu_1 n
  \]
- rhs:
  \[
  \mu_1(app\ s\ (recDelta\ b\ s\ n)) = 1 + \mu_1 s + (1 + \mu_1 b + \mu_1 s + \mu_1 n)
  = 2 + \mu_1 b + 2\mu_1 s + \mu_1 n
  \]

So
\[
\mu_1(lhs) - \mu_1(rhs) = -\mu_1(s).
\]

Hence:
- if `s = void`, the measure is **equal**
- if `s ≠ void`, the measure **increases on the rhs**

So `mu1` is **not** a valid termination measure.

Explicit counterexample:
```lean
recDelta void void (delta void)  -->  app void (recDelta void void void)
```
with
- `mu1(lhs) = 2`
- `mu1(rhs) = 2`

---

### `mu2`
Similarly:
- lhs:
  \[
  \mu_2(recDelta\ b\ s\ (delta\ n)) = 5 + \mu_2 b + \mu_2 s + (1 + \mu_2 n)
  = 6 + \mu_2 b + \mu_2 s + \mu_2 n
  \]
- rhs:
  \[
  \mu_2(app\ s\ (recDelta\ b\ s\ n)) = 1 + \mu_2 s + (5 + \mu_2 b + \mu_2 s + \mu_2 n)
  = 6 + \mu_2 b + 2\mu_2 s + \mu_2 n
  \]

So
\[
\mu_2(lhs) - \mu_2(rhs) = -\mu_2(s).
\]

Same failure:
- equal when `s = void`
- increases when `s ≠ void`

Thus `mu2` is **not** valid.

Explicit counterexample:
- `mu2(recDelta void void (delta void)) = 6`
- `mu2(app void (recDelta void void void)) = 6`

---

### `mu3`
Now:
- lhs:
  \[
  \mu_3(recDelta\ b\ s\ (delta\ n)) = 1 + \mu_3 b + \mu_3 s + (1 + \mu_3 n)
  = 2 + \mu_3 b + \mu_3 s + \mu_3 n
  \]
- rhs:
  \[
  \mu_3(app\ s\ (recDelta\ b\ s\ n)) = 2 + \mu_3 s + (1 + \mu_3 b + \mu_3 s + \mu_3 n)
  = 3 + \mu_3 b + 2\mu_3 s + \mu_3 n
  \]

So
\[
\mu_3(lhs) - \mu_3(rhs) = -(1 + \mu_3(s)).
\]

This is **always negative**. So `R_rec_succ` always makes `mu3` go up.

Thus `mu3` is the worst of the three: it fails **for every** choice of `s`.

---

## What does work / fail overall?

| Measure | All rules except `R_rec_succ` | `R_rec_succ` |
|--------|-------------------------------|--------------|
| `mu1`  | strictly decreases            | fails (equal or increases) |
| `mu2`  | strictly decreases            | fails (equal or increases) |
| `mu3`  | strictly decreases            | fails (always increases) |

So the verdict is:

- **`mu1`: invalid**
- **`mu2`: invalid**
- **`mu3`: invalid**

## Structural reason all three fail

All three are of the same additive shape: “constructor cost + sum of subterm measures”.

That shape is fundamentally incompatible with

```lean
recDelta b s (delta n)  -->  app s (recDelta b s n)
```

because the rhs contains **another copy of `s`** outside the recursive call.

In a generic additive measure with constants
- `cδ` for `delta`
- `capp` for `app`
- `crec` for `recDelta`

you would get

\[
\mu(lhs) = crec + \mu(b) + \mu(s) + c_\delta + \mu(n)
\]
\[
\mu(rhs) = c_{app} + \mu(s) + crec + \mu(b) + \mu(s) + \mu(n)
\]

so
\[
\mu(lhs) - \mu(rhs) = c_\delta - c_{app} - \mu(s).
\]

Since `μ(s)` is unbounded, no fixed constants can make this always positive.

So it’s not just that these three particular constants were chosen badly: **any measure of this simple additive form will fail on `R_rec_succ`.**
