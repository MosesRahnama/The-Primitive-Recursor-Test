All three candidates fail to be strict termination measures, due to the `R_rec_succ` rule:

```lean
Step (recDelta b s (delta n))
     (app s (recDelta b s n))
```

For arbitrary `b`, `s`, and `n`:

### `mu1`

Left-hand side:

```text
mu1 (recDelta b s (delta n))
= 2 + mu1 b + mu1 s + mu1 n
```

Right-hand side:

```text
mu1 (app s (recDelta b s n))
= 2 + mu1 b + 2 * mu1 s + mu1 n
```

Thus the right-hand side is larger whenever `mu1 s > 0`, and equal when `mu1 s = 0`. It never strictly decreases.

### `mu2`

```text
mu2 (recDelta b s (delta n))
= 6 + mu2 b + mu2 s + mu2 n
```

while

```text
mu2 (app s (recDelta b s n))
= 6 + mu2 b + 2 * mu2 s + mu2 n
```

Again, the result duplicates the contribution of `s`, so strict decrease fails.

### `mu3`

```text
mu3 (recDelta b s (delta n))
= 2 + mu3 b + mu3 s + mu3 n
```

while

```text
mu3 (app s (recDelta b s n))
= 3 + mu3 b + 2 * mu3 s + mu3 n
```

The right-hand side is strictly larger, even when `mu3 s = 0`.

All other rewrite rules decrease each of the three measures, but `R_rec_succ` invalidates all of them. Therefore:

- `mu1`: invalid
- `mu2`: invalid
- `mu3`: invalid
