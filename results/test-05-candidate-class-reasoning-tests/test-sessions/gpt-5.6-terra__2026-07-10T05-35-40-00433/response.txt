None of the three candidates is a valid strict termination measure for all `Step` rules.

The problematic rule is:

```lean
R_rec_succ :
  Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

Its right-hand side contains an additional occurrence of `s`, so each proposed additive measure fails there.

## `mu1`

For `R_rec_succ`:

- Left:

\[
\mu1(\mathrm{recDelta}\ b\ s\ (\delta n))
= 2 + \mu1(b) + \mu1(s) + \mu1(n)
\]

- Right:

\[
\mu1(\mathrm{app}\ s\ (\mathrm{recDelta}\ b\ s\ n))
= 2 + \mu1(b) + 2\mu1(s) + \mu1(n)
\]

Thus:

\[
\mu1(\text{RHS}) - \mu1(\text{LHS}) = \mu1(s).
\]

So the measure increases whenever `s` is non-`void`, and is equal when `s = void`.

For example, with `b = void`, `s = delta void`, and `n = void`:

```lean
mu1 (recDelta void (delta void) (delta void)) = 3
mu1 (app (delta void) (recDelta void (delta void) void)) = 4
```

Therefore `mu1` is invalid.

All its other rules do strictly decrease, including `R_eq_diff`, where the decrease is exactly one:

\[
3+\mu1(a)+\mu1(b)
\;>\;
2+\mu1(a)+\mu1(b).
\]

## `mu2`

For `R_rec_succ`:

- Left:

\[
\mu2(\mathrm{recDelta}\ b\ s\ (\delta n))
= 6 + \mu2(b) + \mu2(s) + \mu2(n)
\]

- Right:

\[
\mu2(\mathrm{app}\ s\ (\mathrm{recDelta}\ b\ s\ n))
= 6 + \mu2(b) + 2\mu2(s) + \mu2(n)
\]

Again:

\[
\mu2(\text{RHS}) - \mu2(\text{LHS}) = \mu2(s).
\]

So it increases for any positive-measure step trace and is unchanged for `s = void`.

With the same example:

```lean
mu2 (recDelta void (delta void) (delta void)) = 7
mu2 (app (delta void) (recDelta void (delta void) void)) = 8
```

Therefore `mu2` is invalid.

Its other rules strictly decrease. In particular, `R_eq_diff` has:

\[
5+\mu2(a)+\mu2(b)
\;>\;
4+\mu2(a)+\mu2(b).
\]

## `mu3`

For `R_rec_succ`:

- Left:

\[
\mu3(\mathrm{recDelta}\ b\ s\ (\delta n))
= 2 + \mu3(b) + \mu3(s) + \mu3(n)
\]

- Right:

\[
\mu3(\mathrm{app}\ s\ (\mathrm{recDelta}\ b\ s\ n))
= 3 + \mu3(b) + 2\mu3(s) + \mu3(n)
\]

Hence:

\[
\mu3(\text{RHS}) - \mu3(\text{LHS}) = 1 + \mu3(s).
\]

This rule always strictly increases `mu3`, even when `s = void`.

For example:

```lean
mu3 (recDelta void void (delta void)) = 2
mu3 (app void (recDelta void void void)) = 3
```

Therefore `mu3` is invalid, and it fails more strongly than the first two.

## Summary

| Candidate | `R_rec_succ` behavior | Valid strict measure? |
|---|---:|---|
| `mu1` | RHS exceeds LHS by `mu1 s` | No |
| `mu2` | RHS exceeds LHS by `mu2 s` | No |
| `mu3` | RHS exceeds LHS by `1 + mu3 s` | No |

The fundamental issue is that `R_rec_succ` duplicates `s` on the right:

```lean
recDelta b s (delta n)
```

contains one `s`, while

```lean
app s (recDelta b s n)
```

contains two. All three candidates are additive size-like measures assigning nonnegative cost to `s`, so they cannot establish strict descent for this rule as defined.
