- **R1**: LHS = 1+1+mu1 t = 2+mu1 t; RHS = 0. ✓ (2+... > 0)
- **R2**: LHS = 1+0+mu1 t = 1+mu1 t; RHS = mu1 t. ✓

## Analysis of mu3

- **R1**: LHS = 2+(1+mu3 t) = 3+mu3 t; RHS = 0. ✓
- **R2**: LHS = 1+0+mu3 t; RHS = mu3 t. ✓
- **R3**: LHS = 1+mu3 t; RHS = mu3 t. ✓

- **R7**: LHS = 4+2·mu3 a; RHS = 0. ✓

## Conclusion

**All three candidates fail**, and they all fail on the **same rule: R_rec_succ**.

The root cause is structural: in `recDelta b s (delta n) → app s (recDelta b s n)`, the subterm `s` appears **once** on the left but **twice** on the right (once as the applied function, once inside the recursive `recDelta`). Since all three measures are additive with non-negative weight on `s`, the difference RHS − LHS = (weight of `s`) always duplicates `s`'s measure:

- **mu1, mu2**: `RHS − LHS = mu(s)`, so it fails to strictly decrease whenever `mu(s) > 0`; even for `s = void` it only stays equal, never strictly decreases.
- **mu3**: additionally the constant offset makes RHS strictly *larger* by `1 + mu3(s)` in every case.

No simple additive size measure with fixed per-constructor weights can handle R6, because the term `s` is duplicated. A correct termination argument for this system would need a measure where `recDelta` weights the recursion argument `n` multiplicatively against `s` (e.g., something like `mu(recDelta b s n) = mu(b) + (1 + mu(n))·(1 + mu(s))`, or a lexicographic/multiset ordering on the `delta`-depth of the third argument). None of the three linear candidates achieves this.

**Verdict: none of mu1, mu2, mu3 is a valid termination measure; all break on R_rec_succ due to duplication of `s`.**
