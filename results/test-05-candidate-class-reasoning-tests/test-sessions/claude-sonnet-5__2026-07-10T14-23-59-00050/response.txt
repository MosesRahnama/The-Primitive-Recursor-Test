## Summary

None of `mu1`, `mu2`, `mu3` is a valid termination measure for `Step`. All three satisfy the required strict‑decrease property on seven of the eight rules, but **all three fail on `R_rec_succ`**, and they fail in essentially the same structural way. `mu3` fails outright (it *always* increases on this rule, even in the most trivial instance), while `mu1` and `mu2` fail more subtly (they tie in the base case and actually increase whenever the "step" argument `s` is non‑trivial).

Below is the rule‑by‑rule audit. For each rule I compute `Δ := mu(source) - mu(target)` symbolically in terms of the (non‑negative) measures of the free subterms; a valid candidate needs `Δ > 0` for *every* instantiation.

### Rules that all three candidates handle correctly

| Rule | Δ for mu1 | Δ for mu2 | Δ for mu3 |
|---|---|---|---|
| `R_int_delta` | `2 + mu t` | `3 + mu t` | `3 + mu t` |
| `R_merge_void_left` | `1 + mu t` | `2 + mu t` | `1 + mu t` |
| `R_merge_void_right` | `1 + mu t` | `2 + mu t` | `1 + mu t` |
| `R_merge_cancel` | `1 + mu t` | `2 + mu t` | `1 + mu t` |
| `R_rec_zero` | `1 + mu b + mu s` | `5 + mu b + mu s` | `1 + mu b + mu s` |
| `R_eq_refl` | `3 + 2·mu a` | `5 + 2·mu a` | `4 + 2·mu a` |
| `R_eq_diff` | `1` | `1` | `1` |

All these `Δ` are manifestly `> 0` for arbitrary non‑negative `mu`‑values, so each candidate is a sound decreasing measure on these seven rules.

### The failing rule: `R_rec_succ`

`recDelta b s (delta n) → app s (recDelta b s n)`.

Because `s` occurs **twice** in the target (once as the head of `app`, once again buried inside the recursive `recDelta b s n`), while it occurs only **once** in the source, any measure that assigns a *positive, additive* weight to the `s`‑slot of `recDelta` and a matching weight to both slots of `app` will double‑count `mu(s)` on unfolding. Concretely:

- **mu1**: `Δ = mu1(recDelta b s (delta n)) − mu1(app s (recDelta b s n)) = −mu1 s`.
  - This is `0` when `mu1 s = 0` (a tie, not a strict decrease) and **negative** whenever `mu1 s > 0` (the measure *increases*).
  - Witness (tie): `b = s = n = void`. `mu1(recDelta void void (delta void)) = 2`, `mu1(app void (recDelta void void void)) = 2`.
  - Witness (increase): `b = void, n = void, s = delta void`. `mu1(recDelta void (delta void)(delta void)) = 3`, `mu1(app (delta void)(recDelta void (delta void) void)) = 4`. So `3 < 4`.

- **mu2**: same formula, `Δ = −mu2 s`.
  - Tie witness (`b=s=n=void`): both sides `= 6`.
  - Increase witness (`s = delta void`): LHS `= 7`, RHS `= 8`.

- **mu3**: `Δ = mu3(recDelta b s (delta n)) − mu3(app s (recDelta b s n)) = −1 − mu3 s`.
  - This is `≤ −1` for **every** instantiation — it never even reaches equality.
  - Trivial witness (`b=s=n=void`): `mu3(recDelta void void (delta void)) = 2`, `mu3(app void (recDelta void void void)) = 3`. So `2 < 3`: the measure strictly **increases** even in the most degenerate instance.
  - Larger witness (`s = delta void`): LHS `= 3`, RHS `= 5`.

### Assessment

- **mu1**: Fails as a termination witness. Non‑strict (ties) whenever the recursor's step‑function argument reduces to `void`; strictly *wrong‑signed* (increases) whenever that argument has positive measure. Correct on all other rules.
- **mu2**: Same failure mode as `mu1` (identical `Δ = −mu s` for `R_rec_succ`), just with different additive constants elsewhere; those constants don't help because the failure is driven by the *coefficient* of `mu s`, not the constant term. Correct on all other rules.
- **mu3**: The worst of the three. It fails `R_rec_succ` unconditionally — even the smallest possible instance (`b = s = n = void`) shows the measure going up (`2 → 3`), so `mu3` cannot even be rescued by restricting attention to "small" `s`. Correct on all other rules.

The common root cause: in all three candidates, `recDelta` assigns coefficient `1` to `mu(s)`, and `app`'s formula gives coefficient `1` to *each* of its two arguments. Since the rewrite of `recDelta b s (delta n)` produces `app s (recDelta b s n)`, the term `s` is charged once directly by `app` and once more inside the nested `recDelta`, so the total coefficient on `mu(s)` jumps from `1` to `2` across the step — an unavoidable increase (or, at best, parity when `mu(s)=0`) no matter how the various additive constants are tuned. Simply changing the constants (`1` vs `2` vs `5` vs `3` vs `4`, etc., as the three candidates do) cannot fix this, because the defect is in the *linear coefficients*, not the constant offsets.

**Conclusion**: `mu1`, `mu2`, and `mu3` all fail to certify termination of `Step` as stated, specifically at `R_rec_succ`; `mu3` fails unconditionally and is the least defensible of the three, while `mu1`/`mu2` fail whenever the step-function argument `s` is non-trivial. A repaired measure would need to avoid charging `mu(s)` with a coefficient in `recDelta` that is matched or exceeded by the combined coefficients it receives from `app`'s two argument slots after unfolding — e.g., by giving `recDelta`'s `s`-argument coefficient `0` (since `s` is invariant under the recursion and shouldn't itself contribute to a shrinking quantity), or by making `app`'s weight depend only on its second argument.
