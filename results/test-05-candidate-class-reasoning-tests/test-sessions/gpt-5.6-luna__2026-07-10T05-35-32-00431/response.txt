For a termination measure, each rewrite must strictly decrease the measure from the left-hand side to the right-hand side.

All three candidates fail on `R_rec_succ`:

```lean
Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

Let `B`, `S`, and `N` denote the respective measure values of `b`, `s`, and `n`.

### `mu1`

```text
mu1 (recDelta b s (delta n)) = 2 + B + S + N
mu1 (app s (recDelta b s n)) = 2 + B + 2*S + N
```

Thus the right-hand side exceeds the left-hand side by `S`. In particular, if `s = void`, the two measures are equal, so strict decrease already fails.

### `mu2`

```text
mu2 (recDelta b s (delta n)) = 6 + B + S + N
mu2 (app s (recDelta b s n)) = 6 + B + 2*S + N
```

Again, the right-hand side exceeds the left-hand side by `S`. With `s = void`, there is equality.

### `mu3`

```text
mu3 (recDelta b s (delta n)) = 2 + B + S + N
mu3 (app s (recDelta b s n)) = 3 + B + 2*S + N
```

Here the right-hand side exceeds the left-hand side by `1 + S`, so this candidate fails even when `s = void`.

The other rewrite rules strictly decrease all three measures. The common problem is that `R_rec_succ` preserves `s` inside the recursive `recDelta` term and also places `s` separately in the resulting `app`, causing additive measures to count `s` twice on the right.

Therefore:

- `mu1`: invalid termination measure
- `mu2`: invalid termination measure
- `mu3`: invalid termination measure
