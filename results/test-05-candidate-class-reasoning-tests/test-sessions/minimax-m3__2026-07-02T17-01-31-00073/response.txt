## Assessment of the Three Termination Measures

A termination measure on `Trace` must be a map into a well-ordered set (here, `Nat`) such that `mu(L) > mu(R)` for every step `L → R`. I'll check each step for each candidate, then explain why **all three fail on the same rule**.

### The trouble: `R_rec_succ`

The killer rule is

```
recDelta b s (delta n)  →  app s (recDelta b s n)
```

Notice that the body `s` appears **once** in the LHS but **twice** in the RHS (both as the left argument of `app` *and* inside the recursive call). Any measure that is a fixed positive linear combination of constructor weights and subterm weights will count `s` twice on the right and once on the left, so the difference can never be positive.

Computing the delta for each measure with the abbreviations `b, s, n` for `mu(b), mu(s), mu(n)`:

| measure | LHS | RHS | LHS − RHS |
|---|---|---|---|
| mu1 | 2 + b + s + n | 2 + b + 2s + n | **−s** |
| mu2 | 6 + b + s + n | 6 + b + 2s + n | **−s** |
| mu3 | 2 + b + s + n | 3 + b + 2s + n | **−s − 1** |

In every case the difference is `≤ 0`, so the measure does **not** strictly decrease on this step. In fact, when `s` is non-void, the value *increases* (it just happens to stay flat at `s = void` for mu1 and mu2, but mu3 even increases in that case).

#### Concrete witness

Take `b = s = n = .void`. The step is
```
recDelta .void .void (.delta .void)  →  .app .void (recDelta .void .void .void)
```
| measure | LHS | RHS |
|---|---|---|
| mu1 | 2 | 2  (not strict) |
| mu2 | 6 | 6  (not strict) |
| mu3 | 2 | 3  (strictly *increases*) |

So:
- **mu1** is flat (not strictly decreasing).
- **mu2** is flat (not strictly decreasing).
- **mu3** actively goes up.

All three fail to be a termination measure, and mu3 is the worst offender since it *increases* on `R_rec_succ` for *every* choice of `b, s, n`.

### Why no constant-tweaking fixes this

If we let `W(C)` be the constant added at constructor `C`, then for `R_rec_succ`
```
LHS − RHS = (W(delta) + W(recDelta)) − (W(app) + W(recDelta)) − mu(s)
          =  W(delta) − W(app) − mu(s).
```
This is `> 0` iff `W(delta) > W(app) + mu(s)`, which is impossible because `mu(s) ≥ 0`. The structural‑size approach is fundamentally wrong for this calculus; the recursion in `recDelta` is on the *counter* `n` and the body `s` should not be charged twice.

### Other rules (for completeness)

The other seven rules are fine for all three measures:
- `R_int_delta`, `R_merge_*`, `R_merge_cancel`, `R_rec_zero`, `R_eq_refl`, `R_eq_diff` all strictly decrease (by at least 1, 1, 1+mu(t), 1+mu(s), 3+2·mu(a), and 1 respectively), and these are easily verified case‑by‑case. The single failure mode is `R_rec_succ`.

### Verdict

| Candidate | Valid termination measure? | Where it fails |
|---|---|---|
| **mu1** | ❌ | `R_rec_succ` — value is non‑strict (flat at `s = void`, increases otherwise) |
| **mu2** | ❌ | `R_rec_succ` — value is non‑strict (flat at `s = void`, increases otherwise) |
| **mu3** | ❌ | `R_rec_succ` — value strictly *increases* for every input |

A correct proof of termination for this calculus requires a **lexicographic / depth‑tracking** measure, e.g. `(size, recDelta‑depth)`, because the body `s` is duplicated on the right of `R_rec_succ` and no single natural‑number size function can detect that one of those copies "came from" the original term.
