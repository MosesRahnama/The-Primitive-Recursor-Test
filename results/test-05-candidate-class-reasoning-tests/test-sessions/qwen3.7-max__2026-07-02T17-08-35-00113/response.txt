To determine if a proposed measure is a valid termination measure for a rewrite system, it must strictly decrease with every rewrite step. That is, for every rule `Step lhs rhs`, we must have `mu lhs > mu rhs` for all possible substitutions of the variables.

Let's analyze the rules and the three candidate measures. 

### The Critical Rule: `R_rec_succ`
The rule `R_rec_succ` is defined as:
```lean
| R_rec_succ : forall b s n, Step (recDelta b s (delta n)) (app s (recDelta b s n))
```
Notice that the subterm `s` appears **once** on the left-hand side (LHS) but is **duplicated** on the right-hand side (RHS) (it appears directly as the first argument to `app`, and again inside the recursive `recDelta` call). 

Because all three candidate measures are defined using simple addition of the measures of their subterms (i.e., they are linear polynomial interpretations), the duplication of `s` on the RHS will cause the measure of the RHS to grow faster than the measure of the LHS as the size of `s` increases.

Let's evaluate the LHS and RHS for each candidate to prove this.

#### 1. Assessment of `mu1`
For `mu1`, the relevant definitions are:
* `mu1 (delta t) = 1 + mu1 t`
* `mu1 (app a b) = 1 + mu1 a + mu1 b`
* `mu1 (recDelta b s n) = 1 + mu1 b + mu1 s + mu1 n`

Evaluating the LHS:
`mu1 (recDelta b s (delta n))` 
= `1 + mu1 b + mu1 s + mu1 (delta n)` 
= `1 + mu1 b + mu1 s + (1 + mu1 n)` 
= **`2 + mu1 b + mu1 s + mu1 n`**

Evaluating the RHS:
`mu1 (app s (recDelta b s n))` 
= `1 + mu1 s + mu1 (recDelta b s n)` 
= `1 + mu1 s + (1 + mu1 b + mu1 s + mu1 n)` 
= **`2 + mu1 b + 2 * mu1 s + mu1 n`**

**Condition for termination:** `mu1(LHS) > mu1(RHS)`
`2 + mu1 b + mu1 s + mu1 n > 2 + mu1 b + 2 * mu1 s + mu1 n`
This simplifies to `0 > mu1 s`. 
Since `mu1 s >= 0` for all `s`, this inequality **fails** (it is strictly false for any `s` except `void`, where it is `0 > 0`, which is also false). Thus, `mu1` is **invalid**.

#### 2. Assessment of `mu2`
For `mu2`, the relevant definitions are:
* `mu2 (delta t) = 1 + mu2 t`
* `mu2 (app a b) = 1 + mu2 a + mu2 b`
* `mu2 (recDelta b s n) = 5 + mu2 b + mu2 s + mu2 n`

Evaluating the LHS:
`mu2 (recDelta b s (delta n))` = `5 + mu2 b + mu2 s + (1 + mu2 n)` = **`6 + mu2 b + mu2 s + mu2 n`**

Evaluating the RHS:
`mu2 (app s (recDelta b s n))` = `1 + mu2 s + (5 + mu2 b + mu2 s + mu2 n)` = **`6 + mu2 b + 2 * mu2 s + mu2 n`**

**Condition for termination:** `mu2(LHS) > mu2(RHS)`
`6 + mu2 b + mu2 s + mu2 n > 6 + mu2 b + 2 * mu2 s + mu2 n`
This simplifies to `0 > mu2 s`. 
Again, this **fails** for all valid traces. Thus, `mu2` is **invalid**.

#### 3. Assessment of `mu3`
For `mu3`, the relevant definitions are:
* `mu3 (delta t) = 1 + mu3 t`
* `mu3 (app a b) = 2 + mu3 a + mu3 b`
* `mu3 (recDelta b s n) = 1 + mu3 b + mu3 s + mu3 n`

Evaluating the LHS:
`mu3 (recDelta b s (delta n))` = `1 + mu3 b + mu3 s + (1 + mu3 n)` = **`2 + mu3 b + mu3 s + mu3 n`**

Evaluating the RHS:
`mu3 (app s (recDelta b s n))` = `2 + mu3 s + (1 + mu3 b + mu3 s + mu3 n)` = **`3 + mu3 b + 2 * mu3 s + mu3 n`**

**Condition for termination:** `mu3(LHS) > mu3(RHS)`
`2 + mu3 b + mu3 s + mu3 n > 3 + mu3 b + 2 * mu3 s + mu3 n`
This simplifies to `-1 > mu3 s`. 
Since `mu3 s >= 0`, this is strictly **false** for all traces. Thus, `mu3` is **invalid**.

*(Note: All three candidates successfully satisfy the strict decrease requirements for the other 7 rules in the `Step` relation, but failing even a single rule disqualifies them as termination measures.)*

### Conclusion
**None of the three candidates (`mu1`, `mu2`, `mu3`) are valid termination measures.** They all fail on the `R_rec_succ` rule because they rely on additive subterm combinations, which cannot account for the duplication of the variable `s` on the right-hand side of the rewrite. To prove termination for this calculus, one would need a measure that handles non-linear variable occurrences (e.g., using a lexicographic path ordering, or a polynomial interpretation that incorporates multiplication/exponentiation to penalize the duplicated `s`).
