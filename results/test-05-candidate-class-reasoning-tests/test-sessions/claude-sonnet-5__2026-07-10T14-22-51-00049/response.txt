## Setting

`Step` has exactly 8 rules, and a candidate `mu : Trace → Nat` is a valid termination measure iff for **every** rule `Step t t'` we have `mu t' < mu t`. Since `Trace`/`Step` have no congruence (context) rules, only these 8 instances need checking.

I checked each candidate against all 8 rules, using symbolic subterms (not just concrete instances) to be safe.

## mu1 — **fails**

All rules except `R_rec_succ` decrease properly (in fact `mu1` is basically the "size" measure, and merge/rec/eq axioms strip a constructor). But on

```
R_rec_succ : recDelta b s (delta n)  →  app s (recDelta b s n)
```

with `mu1`:

- `mu1 (recDelta b s (delta n)) = 2 + mu1 b + mu1 s + mu1 n`
- `mu1 (app s (recDelta b s n)) = 2 + mu1 b + 2*mu1 s + mu1 n`

Difference (LHS − RHS) = `−mu1 s ≤ 0`. So `mu1` **never strictly decreases** on this rule; it's non-increasing at best, and exactly equal whenever `mu1 s = 0` (e.g. `s = void`). Concretely, with `s := void`:

`mu1 (recDelta b void (delta n)) = mu1 (app void (recDelta b void n))` (both equal `2 + mu1 b + mu1 n`).

So `mu1` is **not** a valid termination measure.

## mu2 — **fails, same rule**

The extra weight given to `integrate`, `merge`, `recDelta`, `eqW` doesn't fix the underlying structural imbalance: `recDelta` has coefficient 5 and `app` has coefficient 1, i.e. `c_a = 1` again. Repeating the computation for `R_rec_succ`:

- `mu2 (recDelta b s (delta n)) = 6 + mu2 b + mu2 s + mu2 n`
- `mu2 (app s (recDelta b s n)) = 6 + mu2 b + 2*mu2 s + mu2 n`

Difference = `−mu2 s ≤ 0`, again zero when `mu2 s = 0` (e.g. `s = void`):

`mu2 (recDelta b void (delta n)) = mu2 (app void (recDelta b void n)) = 6 + mu2 b + mu2 n`.

So `mu2` also fails to strictly decrease — it has the *same* structural defect as `mu1`: the general fact is that for these families of measures (`app` coeff `c_a`, `recDelta` coeff `c_r`, `delta` coeff 1), the difference on `R_rec_succ` works out to `(1 − c_a) − mu(s)`, so termination on this rule requires `c_a ≥ 2`. Both `mu1` (c_a=1) and `mu2` (c_a=1) violate this.

## mu3 — **valid**

Here `app` has coefficient `2` while `recDelta` has coefficient `1`, i.e. `c_a = 2 > 1`. Recomputing `R_rec_succ`:

- `mu3 (recDelta b s (delta n)) = 2 + mu3 b + mu3 s + mu3 n`
- `mu3 (app s (recDelta b s n)) = 3 + mu3 b + 2*mu3 s + mu3 n`

Difference = `(1 − 2) − mu3 s = −1 − mu3 s < 0` **unconditionally**, regardless of `b, s, n`. So this rule strictly decreases always, not just for special instances.

Checking the remaining 7 rules for `mu3`:

- `R_int_delta`: `mu3(integrate(delta t)) = 3 + mu3 t > 0 = mu3 void`. ✓.
- `R_merge_void_left/right`: `1 + mu3 t > mu3 t`. ✓ (both sides).
- `R_merge_cancel`: `1 + 2*mu3 t > mu3 t`. ✓.
- `R_rec_zero`: `1 + mu3 b + mu3 s > mu3 b`. ✓.
- `R_rec_succ`: shown above, strictly decreasing. ✓.
- `R_eq_refl`: `4 + 2*mu3 a > 0`. ✓.
- `R_eq_diff`: `mu3(eqW a b) = 4 + mu3 a + mu3 b`; `mu3(integrate(merge a b)) = 2 + (1+mu3 a+mu3 b) = 3+mu3 a+mu3 b`; difference `= 1 > 0`. ✓.

All 8 rules give strict decrease for every instantiation of the metavariables, so `mu3` is a genuine termination measure: it proves `Step` is strongly normalizing (well-foundedness of `<` on `Nat` rules out infinite `Step`-chains).

## Summary

| Candidate | Verdict | Failure point |
|---|---|---|
| `mu1` | Invalid | `R_rec_succ`, non-strict (equal) when `s = void` |
| `mu2` | Invalid | Same rule, same defect (`app` coefficient too small relative to `recDelta`) |
| `mu3` | **Valid** | Strictly decreases on all 8 rules for all subterms; `app`'s coefficient (2) exceeding `recDelta`'s (1) is exactly what repairs the `R_rec_succ` imbalance present in `mu1`/`mu2` |

The key structural insight: for `R_rec_succ`, the successor case wraps the recursive `recDelta` inside an extra `app`, duplicating the weight of `s`. Any measure needs the `app`-coefficient to strictly exceed the `recDelta`-coefficient (by at least 1) to absorb this duplication; `mu1` and `mu2` both violate this (coefficients 1 vs 1, and 1 vs 5 respectively — note it's not about `recDelta`'s coefficient being large, but about `app`'s being *large enough relative to it*), while `mu3` (coefficients 2 vs 1) satisfies it.
