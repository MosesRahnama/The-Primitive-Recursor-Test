## Setup

Each candidate has the generic shape

```
mu(void)            = 0
mu(delta t)          = c_d  + mu(t)
mu(integrate t)      = c_i  + mu(t)
mu(merge a b)        = c_m  + mu(a) + mu(b)
mu(app a b)          = c_a  + mu(a) + mu(b)
mu(recDelta b s n)   = c_r  + mu(b) + mu(s) + mu(n)
mu(eqW a b)          = c_e  + mu(a) + mu(b)
```

with constants:

| | c_d | c_i | c_m | c_a | c_r | c_e |
|---|---|---|---|---|---|---|
|mu1|1|1|1|1|1|3|
|mu2|1|2|2|1|5|5|
|mu3|1|2|1|2|1|4|

For a valid termination measure we need `Step t t' → mu t > mu t'` for **every** instance of every rule.

## Rules 1–5, 7, 8: all three candidates are fine

Checking `R_int_delta`, `R_merge_void_left/right`, `R_merge_cancel`, `R_rec_zero`, `R_eq_refl`, `R_eq_diff` against all three measures, every one gives a genuine strict decrease (the arithmetic works out because these rules only *delete* subterms or *duplicate at most trivially*, and the chosen constants are all ≥1 where needed). I verified each numerically for mu1, mu2, mu3 and none of them has a problem here. So the "easy" rules are not where the differences matter.

## Rule 6 (`R_rec_succ`) is the crux — and **all three fail it**

```
recDelta b s (delta n)  --->  app s (recDelta b s n)
```

Here `s` occurs **once** on the left and **twice** on the right (once directly, once nested inside the recursive `recDelta`). For any measure of the additive shape above,

```
LHS = c_r + mu(b) + mu(s) + (c_d + mu(n))
RHS = c_a + mu(s) + (c_r + mu(b) + mu(s) + mu(n))
```

so

```
RHS - LHS = (c_a - c_d) + mu(s).
```

Since `mu(s)` is unbounded as `s` ranges over all traces, **no choice of nonnegative constants `c_a, c_d` can make `LHS > RHS` for all `s`.** This is not a matter of tuning coefficients — it's a structural impossibility for any "sum-of-children" measure, because the rule literally duplicates `s`.

Applying this formula to each candidate:

- **mu1** (`c_a=1, c_d=1`): `RHS - LHS = mu1(s)`. At `s = void` we get equality (no strict decrease at all, already a failure), and for any nontrivial `s` the measure strictly **increases**.
- **mu2** (`c_a=1, c_d=1`): identical defect to mu1 — `RHS - LHS = mu2(s)`, equality at `s=void`, increasing otherwise. The large constant `c_r = 5` used for `recDelta` only helps with rule 5, not with this cancellation.
- **mu3** (`c_a=2, c_d=1`): `RHS - LHS = 1 + mu3(s)`. This is strictly **positive even at `s = void`** (the base instance already fails, not just the "duplicated growth" case), and gets worse as `s` grows.

Concrete witness (`b = void`, `s = delta void`, `n = void`), i.e. the step
`recDelta void (delta void) (delta void) → app (delta void) (recDelta void (delta void) void)`:

| | mu(LHS) | mu(RHS) | decreased? |
|---|---|---|---|
|mu1| 3 | 4 | ✗ (increased) |
|mu2| 7 | 8 | ✗ (increased) |
|mu3| 3 | 5 | ✗ (increased, worst margin) |

## Verdict

- **None of mu1, mu2, mu3 is a valid termination measure** for the full `Step` relation: all three fail on `R_rec_succ`.
- The failure is not a minor bookkeeping slip; it is forced by the fact that `s` is duplicated by the rule while every candidate measure is a flat linear "sum of subterm sizes plus a per-constructor constant." No adjustment of the constants `c_a, c_d, c_r` can repair this, since the gap `RHS - LHS` grows without bound in `mu(s)` regardless of constants.
- Relative ranking, for what it's worth: **mu1 and mu2** are "closest to working" — they at least achieve equality (a non-strict weak bound) on the base case `s = void`, failing only once `s` has positive size. **mu3** is strictly worse, failing even on the base case, with a constant +1 gap on top of the same unbounded growth term.
- A correct measure would need to avoid counting `mu(s)` linearly in the recursive case — e.g. a measure depending only on the shape/depth of the `n` argument (which does shrink), or a lexicographic measure that ignores/bounds the contribution of `s`, since `s` itself is not being consumed by this rule, only replicated.
