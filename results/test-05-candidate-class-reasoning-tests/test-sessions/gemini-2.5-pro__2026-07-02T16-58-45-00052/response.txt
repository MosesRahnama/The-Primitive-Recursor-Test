This document assesses the three candidate termination measures (`mu1`, `mu2`, `mu3`) for the first-order rewrite calculus defined by `Trace` and `Step`.

A function `mu : Trace -> Nat` is a valid termination measure if for every rewrite rule `Step a b`, it can be proven that `mu a > mu b`. We will analyze each candidate against every rewrite rule.

---

### Assessment of `mu1`

`mu1` is a simple structural size measure, where most constructors add 1 to the size of their children. `eqW` is weighted more heavily.

```lean
def mu1 : Trace -> Nat
| .void => 0
| .delta t => 1 + mu1 t
| .integrate t => 1 + mu1 t
| .merge a b => 1 + mu1 a + mu1 b
| .app a b => 1 + mu1 a + mu1 b
| .recDelta b s n => 1 + mu1 b + mu1 s + mu1 n
| .eqW a b => 3 + mu1 a + mu1 b
```

Let's check each rule:

*   **R_int_delta**: `Step (integrate (delta t)) void`
    *   `mu1 (integrate (delta t))` = `1 + mu1 (delta t)` = `1 + (1 + mu1 t)` = `2 + mu1 t`
    *   `mu1 void` = `0`
    *   `2 + mu1 t > 0` holds. **OK.**

*   **R_merge_void_left**: `Step (merge void t) t`
    *   `mu1 (merge void t)` = `1 + mu1 void + mu1 t` = `1 + 0 + mu1 t` = `1 + mu1 t`
    *   `1 + mu1 t > mu1 t` holds. **OK.**

*   **R_merge_void_right**: `Step (merge t void) t`
    *   `mu1 (merge t void)` = `1 + mu1 t + mu1 void` = `1 + mu1 t`
    *   `1 + mu1 t > mu1 t` holds. **OK.**

*   **R_merge_cancel**: `Step (merge t t) t`
    *   `mu1 (merge t t)` = `1 + mu1 t + mu1 t` = `1 + 2 * (mu1 t)`
    *   `1 + 2 * (mu1 t) > mu1 t` holds, as it simplifies to `1 + mu1 t > 0`. **OK.**

*   **R_rec_zero**: `Step (recDelta b s void) b`
    *   `mu1 (recDelta b s void)` = `1 + mu1 b + mu1 s + mu1 void` = `1 + mu1 b + mu1 s`
    *   `1 + mu1 b + mu1 s > mu1 b` holds, as it simplifies to `1 + mu1 s > 0`. **OK.**

*   **R_rec_succ**: `Step (recDelta b s (delta n)) (app s (recDelta b s n))`
    *   `mu1 (recDelta b s (delta n))` = `1 + mu1 b + mu1 s + mu1 (delta n)` = `1 + mu1 b + mu1 s + (1 + mu1 n)` = `2 + mu1 b + mu1 s + mu1 n`
    *   `mu1 (app s (recDelta b s n))` = `1 + mu1 s + mu1 (recDelta b s n)` = `1 + mu1 s + (1 + mu1 b + mu1 s + mu1 n)` = `2 + mu1 b + 2 * (mu1 s) + mu1 n`
    *   We need to check if `2 + mu1 b + mu1 s + mu1 n > 2 + mu1 b + 2 * (mu1 s) + mu1 n`.
    *   This simplifies to `mu1 s > 2 * (mu1 s)`, which is false for any `s` (since `mu1 s` is a natural number).
    *   **FAILURE.** This rule causes the measure to increase or stay the same, not decrease.

*   **R_eq_refl**: `Step (eqW a a) void`
    *   `mu1 (eqW a a)` = `3 + mu1 a + mu1 a` = `3 + 2 * (mu1 a)`
    *   `mu1 void` = `0`
    *   `3 + 2 * (mu1 a) > 0` holds. **OK.**

*   **R_eq_diff**: `Step (eqW a b) (integrate (merge a b))`
    *   `mu1 (eqW a b)` = `3 + mu1 a + mu1 b`
    *   `mu1 (integrate (merge a b))` = `1 + mu1 (merge a b)` = `1 + (1 + mu1 a + mu1 b)` = `2 + mu1 a + mu1 b`
    *   `3 + mu1 a + mu1 b > 2 + mu1 a + mu1 b` holds. **OK.**

**Conclusion for `mu1`**: Not a valid termination measure because it fails on rule `R_rec_succ`. The duplication of the term `s` on the right-hand side causes the measure to grow.

### Assessment of `mu2`

`mu2` assigns different weights to constructors, notably giving a large weight to `recDelta` and `eqW`.

```lean
def mu2 : Trace -> Nat
| .void => 0
| .delta t => 1 + mu2 t
| .integrate t => 2 + mu2 t
| .merge a b => 2 + mu2 a + mu2 b
| .app a b => 1 + mu2 a + mu2 b
| .recDelta b s n => 5 + mu2 b + mu2 s + mu2 n
| .eqW a b => 5 + mu2 a + mu2 b
```

Let's check each rule:

*   **R_int_delta**: `Step (integrate (delta t)) void`
    *   `mu2 (integrate (delta t))` = `2 + mu2 (delta t)` = `2 + (1 + mu2 t)` = `3 + mu2 t`
    *   `3 + mu2 t > 0` holds. **OK.**

*   **R_merge_void_left**: `Step (merge void t) t`
    *   `mu2 (merge void t)` = `2 + mu2 void + mu2 t` = `2 + mu2 t`
    *   `2 + mu2 t > mu2 t` holds. **OK.**

*   **R_merge_void_right**: `Step (merge t void) t`
    *   `mu2 (merge t void)` = `2 + mu2 t + mu2 void` = `2 + mu2 t`
    *   `2 + mu2 t > mu2 t` holds. **OK.**

*   **R_merge_cancel**: `Step (merge t t) t`
    *   `mu2 (merge t t)` = `2 + mu2 t + mu2 t` = `2 + 2 * (mu2 t)`
    *   `2 + 2 * (mu2 t) > mu2 t` holds. **OK.**

*   **R_rec_zero**: `Step (recDelta b s void) b`
    *   `mu2 (recDelta b s void)` = `5 + mu2 b + mu2 s + mu2 void` = `5 + mu2 b + mu2 s`
    *   `5 + mu2 b + mu2 s > mu2 b` holds. **OK.**

*   **R_rec_succ**: `Step (recDelta b s (delta n)) (app s (recDelta b s n))`
    *   `mu2 (recDelta b s (delta n))` = `5 + mu2 b + mu2 s + mu2 (delta n)` = `5 + mu2 b + mu2 s + (1 + mu2 n)` = `6 + mu2 b + mu2 s + mu2 n`
    *   `mu2 (app s (recDelta b s n))` = `1 + mu2 s + mu2 (recDelta b s n)` = `1 + mu2 s + (5 + mu2 b + mu2 s + mu2 n)` = `6 + mu2 b + 2 * (mu2 s) + mu2 n`
    *   We need to check if `6 + mu2 b + mu2 s + mu2 n > 6 + mu2 b + 2 * (mu2 s) + mu2 n`.
    *   This simplifies to `mu2 s > 2 * (mu2 s)`, which is false.
    *   **FAILURE.** Despite the higher weight on `recDelta`, this candidate fails for the exact same reason as `mu1`. The additive nature of the measure cannot handle the duplication of `s`.

*   **R_eq_refl**: `Step (eqW a a) void`
    *   `mu2 (eqW a a)` = `5 + 2 * (mu2 a)`
    *   `5 + 2 * (mu2 a) > 0` holds. **OK.**

*   **R_eq_diff**: `Step (eqW a b) (integrate (merge a b))`
    *   `mu2 (eqW a b)` = `5 + mu2 a + mu2 b`
    *   `mu2 (integrate (merge a b))` = `2 + mu2 (merge a b)` = `2 + (2 + mu2 a + mu2 b)` = `4 + mu2 a + mu2 b`
    *   `5 + mu2 a + mu2 b > 4 + mu2 a + mu2 b` holds. **OK.**

**Conclusion for `mu2`**: Not a valid termination measure because it fails on rule `R_rec_succ`.

### Assessment of `mu3`

`mu3` attempts a different weighting, notably giving `app` a higher weight than `recDelta` and `merge`.

```lean
def mu3 : Trace -> Nat
| .void => 0
| .delta t => 1 + mu3 t
| .integrate t => 2 + mu3 t
| .merge a b => 1 + mu3 a + mu3 b
| .app a b => 2 + mu3 a + mu3 b
| .recDelta b s n => 1 + mu3 b + mu3 s + mu3 n
| .eqW a b => 4 + mu3 a + mu3 b
```

Let's check each rule:

*   **R_int_delta**: `Step (integrate (delta t)) void`
    *   `mu3 (integrate (delta t))` = `2 + mu3 (delta t)` = `2 + (1 + mu3 t)` = `3 + mu3 t`
    *   `3 + mu3 t > 0` holds. **OK.**

*   **R_merge_void_left**: `Step (merge void t) t`
    *   `mu3 (merge void t)` = `1 + mu3 void + mu3 t` = `1 + mu3 t`
    *   `1 + mu3 t > mu3 t` holds. **OK.**

*   **R_merge_void_right**: `Step (merge t void) t`
    *   `mu3 (merge t void)` = `1 + mu3 t + mu3 void` = `1 + mu3 t`
    *   `1 + mu3 t > mu3 t` holds. **OK.**

*   **R_merge_cancel**: `Step (merge t t) t`
    *   `mu3 (merge t t)` = `1 + mu3 t + mu3 t` = `1 + 2 * (mu3 t)`
    *   `1 + 2 * (mu3 t) > mu3 t` holds. **OK.**

*   **R_rec_zero**: `Step (recDelta b s void) b`
    *   `mu3 (recDelta b s void)` = `1 + mu3 b + mu3 s + mu3 void` = `1 + mu3 b + mu3 s`
    *   `1 + mu3 b + mu3 s > mu3 b` holds. **OK.**

*   **R_rec_succ**: `Step (recDelta b s (delta n)) (app s (recDelta b s n))`
    *   `mu3 (recDelta b s (delta n))` = `1 + mu3 b + mu3 s + mu3 (delta n)` = `1 + mu3 b + mu3 s + (1 + mu3 n)` = `2 + mu3 b + mu3 s + mu3 n`
    *   `mu3 (app s (recDelta b s n))` = `2 + mu3 s + mu3 (recDelta b s n)` = `2 + mu3 s + (1 + mu3 b + mu3 s + mu3 n)` = `3 + mu3 b + 2 * (mu3 s) + mu3 n`
    *   We need to check if `2 + mu3 b + mu3 s + mu3 n > 3 + mu3 b + 2 * (mu3 s) + mu3 n`.
    *   This simplifies to `2 + mu3 s > 3 + 2 * (mu3 s)`, which further simplifies to `-1 > mu3 s`.
    *   This inequality is never true for a natural number `mu3 s`.
    *   **FAILURE.** This measure fails on `R_rec_succ` even more significantly than the previous two. The chosen weights make the RHS strictly larger than the LHS.

*   **R_eq_refl**: `Step (eqW a a) void`
    *   `mu3 (eqW a a)` = `4 + 2 * (mu3 a)`
    *   `4 + 2 * (mu3 a) > 0` holds. **OK.**

*   **R_eq_diff**: `Step (eqW a b) (integrate (merge a b))`
    *   `mu3 (eqW a b)` = `4 + mu3 a + mu3 b`
    *   `mu3 (integrate (merge a b))` = `2 + mu3 (merge a b)` = `2 + (1 + mu3 a + mu3 b)` = `3 + mu3 a + mu3 b`
    *   `4 + mu3 a + mu3 b > 3 + mu3 a + mu3 b` holds. **OK.**

**Conclusion for `mu3`**: Not a valid termination measure because it fails on rule `R_rec_succ`.

---

### Final Summary

None of the three proposed functions (`mu1`, `mu2`, `mu3`) are valid termination measures for the given rewrite system.

All three candidates fail on the same rule: `R_rec_succ`.
`Step (recDelta b s (delta n)) (app s (recDelta b s n))`

The fundamental problem is that this rule duplicates the term `s` on the right-hand side. All three measures are defined additively over the structure of the `Trace`, meaning that the measure of a term is a constant plus the sum of the measures of its children. This structure cannot handle the duplication of `s` in the `R_rec_succ` rule, as the contribution of `mu(s)` is counted once on the left but twice on the right, causing the total measure to grow rather than shrink. A valid termination measure would require a different structure, perhaps one where the weight of `recDelta` is significantly larger and dependent on the size of its arguments in a non-linear way.
