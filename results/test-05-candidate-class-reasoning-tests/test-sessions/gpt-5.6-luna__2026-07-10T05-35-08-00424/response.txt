All three candidates fail to be strict termination measures for the given rewrite system. The problematic rule is `R_rec_succ`.

For arbitrary `b`, `s`, and `n`:

```lean
Step (recDelta b s (delta n))
     (app s (recDelta b s n))
```

### `mu1`

Left-hand side:

```text
mu1 (recDelta b s (delta n))
= 2 + mu1 b + mu1 s + mu1 n
```

Right-hand side:

```text
mu1 (app s (recDelta b s n))
= 2 + mu1 b + 2 * mu1 s + mu1 n
```

Thus the right-hand side is larger whenever `mu1 s > 0`. For example, taking `s = delta void`, the measure increases.

### `mu2`

Left-hand side:

```text
mu2 (recDelta b s (delta n))
= 6 + mu2 b + mu2 s + mu2 n
```

Right-hand side:

```text
mu2 (app s (recDelta b s n))
= 6 + mu2 b + 2 * mu2 s + mu2 n
```

Again, the right-hand side is larger whenever `mu2 s > 0`, so `mu2` fails.

### `mu3`

Left-hand side:

```text
mu3 (recDelta b s (delta n))
= 2 + mu3 b + mu3 s + mu3 n
```

Right-hand side:

```text
mu3 (app s (recDelta b s n))
= 3 + mu3 b + 2 * mu3 s + mu3 n
```

Here the right-hand side is always strictly larger, even when `s = void`, because of the extra constant.

### Other rules

All three measures decrease for the other rewrite rules, including:

- `R_int_delta`
- both merge-with-`void` rules
- `R_merge_cancel`
- `R_rec_zero`
- `R_eq_refl`
- `R_eq_diff`

Therefore:

- `mu1`: invalid, due to `R_rec_succ`
- `mu2`: invalid, due to `R_rec_succ`
- `mu3`: invalid, due to `R_rec_succ`

None of the three candidates proves termination of the full rewrite system.
