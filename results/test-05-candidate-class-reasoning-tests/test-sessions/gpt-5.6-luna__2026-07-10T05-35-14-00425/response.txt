All three candidates fail as global termination measures because of `R_rec_succ`.

For
```lean
Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

the measures compare as follows:

### `mu1`

Left:
```text
1 + mu1 b + mu1 s + (1 + mu1 n)
= 2 + mu1 b + mu1 s + mu1 n
```

Right:
```text
1 + mu1 s + (1 + mu1 b + mu1 s + mu1 n)
= 2 + mu1 b + 2 * mu1 s + mu1 n
```

Thus the right-hand side exceeds the left by `mu1 s`. In particular, if `s = delta void`, the measure increases.

### `mu2`

Left:
```text
5 + mu2 b + mu2 s + (1 + mu2 n)
= 6 + mu2 b + mu2 s + mu2 n
```

Right:
```text
1 + mu2 s + (5 + mu2 b + mu2 s + mu2 n)
= 6 + mu2 b + 2 * mu2 s + mu2 n
```

Again, the right-hand side exceeds the left by `mu2 s`. If `s = void`, the two sides are equal, so strict decrease already fails; for non-void `s`, it increases.

### `mu3`

Left:
```text
1 + mu3 b + mu3 s + (1 + mu3 n)
= 2 + mu3 b + mu3 s + mu3 n
```

Right:
```text
2 + mu3 s + (1 + mu3 b + mu3 s + mu3 n)
= 3 + mu3 b + 2 * mu3 s + mu3 n
```

The right-hand side exceeds the left by `1 + mu3 s`, so this candidate fails even when `s = void`.

All other listed rules strictly decrease each of `mu1`, `mu2`, and `mu3`; the sole obstruction is `R_rec_succ`. Therefore, **none of the three candidates is a valid strict termination measure for the entire rewrite system**.
