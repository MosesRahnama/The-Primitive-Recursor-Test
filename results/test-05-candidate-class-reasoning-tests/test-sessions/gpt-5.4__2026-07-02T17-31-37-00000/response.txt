Here’s a direct audit of the three proposed measures as termination measures for the rewrite relation `Step`.

A valid candidate should satisfy:

- for every rule `Step lhs rhs`,
- we have `mu lhs > mu rhs`.

I’ll check each rewrite rule against each `mu`.

---

## The rewrite rules

For reference:

1. `integrate (delta t) -> void`
2. `merge void t -> t`
3. `merge t void -> t`
4. `merge t t -> t`
5. `recDelta b s void -> b`
6. `recDelta b s (delta n) -> app s (recDelta b s n)`
7. `eqW a a -> void`
8. `eqW a b -> integrate (merge a b)`

---

# Candidate `mu1`

```lean
def mu1 : Trace -> Nat
| .void => 0
| .delta t => 1 + mu1 t
| .integrate t => 1 + mu1 t
| .merge a b => 1 + mu1 a + mu1 b
| .app a b => 1 + mu1 a + mu1 b
| .recDelta b s n => 1 + mu1 b + mu1 s + mu1 n
| .eqW a b => 3 + mu1 a + mu1 b
```

## Check each rule

### 1. `integrate (delta t) -> void`
- LHS: `1 + (1 + mu1 t) = 2 + mu1 t`
- RHS: `0`
- Strictly decreases: yes

### 2. `merge void t -> t`
- LHS: `1 + 0 + mu1 t = 1 + mu1 t`
- RHS: `mu1 t`
- yes

### 3. `merge t void -> t`
- LHS: `1 + mu1 t + 0 = 1 + mu1 t`
- RHS: `mu1 t`
- yes

### 4. `merge t t -> t`
- LHS: `1 + mu1 t + mu1 t`
- RHS: `mu1 t`
- yes

### 5. `recDelta b s void -> b`
- LHS: `1 + mu1 b + mu1 s + 0`
- RHS: `mu1 b`
- yes

### 6. `recDelta b s (delta n) -> app s (recDelta b s n)`
Compute both sides:
- LHS:
  `1 + mu1 b + mu1 s + (1 + mu1 n)
   = 2 + mu1 b + mu1 s + mu1 n`
- RHS:
  `1 + mu1 s + (1 + mu1 b + mu1 s + mu1 n)
   = 2 + mu1 b + 2*mu1 s + mu1 n`

Compare:
- RHS = LHS + `mu1 s`

So:
- if `mu1 s = 0`, equal
- if `mu1 s > 0`, RHS is larger

Thus this rule does **not** decrease.

### 7. `eqW a a -> void`
- LHS: `3 + 2*mu1 a`
- RHS: `0`
- yes

### 8. `eqW a b -> integrate (merge a b)`
- LHS: `3 + mu1 a + mu1 b`
- RHS: `1 + (1 + mu1 a + mu1 b) = 2 + mu1 a + mu1 b`
- yes, decreases by `1`

## Verdict on `mu1`

`mu1` is **not valid** as a termination measure, because it fails on:

- `R_rec_succ : recDelta b s (delta n) -> app s (recDelta b s n)`

In fact it usually increases.

# Candidate `mu2`

```lean
def mu2 : Trace -> Nat
| .void => 0
| .delta t => 1 + mu2 t
| .integrate t => 2 + mu2 t
| .merge a b => 2 + mu2 a + mu2 b
| .app a b => 1 + mu2 a + mu2 b
| .recDelta b s n => 5 + mu2 b + mu2 s + mu2 n
| .eqW a b => 5 + mu2 a + mu2 b
```

## Check each rule

### 1. `integrate (delta t) -> void`
- LHS: `2 + (1 + mu2 t) = 3 + mu2 t`
- RHS: `0`
- yes

### 2. `merge void t -> t`
- LHS: `2 + 0 + mu2 t = 2 + mu2 t`
- RHS: `mu2 t`
- yes

### 3. `merge t void -> t`
- LHS: `2 + mu2 t + 0 = 2 + mu2 t`
- RHS: `mu2 t`
- yes

### 4. `merge t t -> t`
- LHS: `2 + 2*mu2 t`
- RHS: `mu2 t`
- yes

### 5. `recDelta b s void -> b`
- LHS: `5 + mu2 b + mu2 s`
- RHS: `mu2 b`
- yes

### 6. `recDelta b s (delta n) -> app s (recDelta b s n)`
- LHS:
  `5 + mu2 b + mu2 s + (1 + mu2 n)
   = 6 + mu2 b + mu2 s + mu2 n`
- RHS:
  `1 + mu2 s + (5 + mu2 b + mu2 s + mu2 n)
   = 6 + mu2 b + 2*mu2 s + mu2 n`

Again:
- RHS = LHS + `mu2 s`

So this fails exactly the same way:
- equal if `s = void`
- larger otherwise

### 7. `eqW a a -> void`
- LHS: `5 + 2*mu2 a`
- RHS: `0`
- yes

### 8. `eqW a b -> integrate (merge a b)`
- LHS: `5 + mu2 a + mu2 b`
- RHS:
  `2 + (2 + mu2 a + mu2 b)
   = 4 + mu2 a + mu2 b`
- yes, decreases by `1`

## Verdict on `mu2`

`mu2` is also **not valid**, again because of:

- `R_rec_succ`

Everything else decreases, but that one rule does not.

# Candidate `mu3`

```lean
def mu3 : Trace -> Nat
| .void => 0
| .delta t => 1 + mu3 t
| .integrate t => 2 + mu3 t
| .merge a b => 1 + mu3 a + mu3 b
| .app a b => 2 + mu3 a + mu3 b
| .recDelta b s n => 1 + mu3 b + mu3 s + mu3 n
| .eqW a b => 4 + mu3 a + mu3 b
```

## Check each rule

### 1. `integrate (delta t) -> void`
- LHS: `2 + (1 + mu3 t) = 3 + mu3 t`
- RHS: `0`
- yes

### 2. `merge void t -> t`
- LHS: `1 + 0 + mu3 t = 1 + mu3 t`
- RHS: `mu3 t`
- yes

### 3. `merge t void -> t`
- LHS: `1 + mu3 t`
- RHS: `mu3 t`
- yes

### 4. `merge t t -> t`
- LHS: `1 + 2*mu3 t`
- RHS: `mu3 t`
- yes

### 5. `recDelta b s void -> b`
- LHS: `1 + mu3 b + mu3 s`
- RHS: `mu3 b`
- yes

### 6. `recDelta b s (delta n) -> app s (recDelta b s n)`
- LHS:
  `1 + mu3 b + mu3 s + (1 + mu3 n)
   = 2 + mu3 b + mu3 s + mu3 n`
- RHS:
  `2 + mu3 s + (1 + mu3 b + mu3 s + mu3 n)
   = 3 + mu3 b + 2*mu3 s + mu3 n`

So:
- RHS = LHS + `1 + mu3 s`

This is even worse: RHS is **always strictly larger**.

### 7. `eqW a a -> void`
- LHS: `4 + 2*mu3 a`
- RHS: `0`
- yes

### 8. `eqW a b -> integrate (merge a b)`
- LHS: `4 + mu3 a + mu3 b`
- RHS:
  `2 + (1 + mu3 a + mu3 b)
   = 3 + mu3 a + mu3 b`
- yes, decreases by `1`

## Verdict on `mu3`

`mu3` is **not valid**, and it fails decisively on:

- `R_rec_succ`

---

# Overall conclusion

None of the three candidates is a valid strict termination measure for `Step`.

## Why they all fail
All three measures are additive, and the problematic rule

```lean
recDelta b s (delta n) -> app s (recDelta b s n)
```

duplicates the contribution of `s` on the right:

- on the left, `s` appears once inside `recDelta`
- on the right, `s` appears
  - once as the left child of `app`
  - once again inside `recDelta`

So any plain additive size measure of the form used here will struggle, because the right-hand side counts `s` twice.

- `mu2`: **invalid**
- `mu3`: **invalid**

All fail on `R_rec_succ`.
