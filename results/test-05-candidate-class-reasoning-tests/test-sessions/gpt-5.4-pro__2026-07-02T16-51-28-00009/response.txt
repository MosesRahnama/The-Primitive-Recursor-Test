For a `Nat`-valued termination measure, you need:

\[
\text{if } Step\ l\ r \text{ then } \mu(l) > \mu(r).
\]

All three candidates fail this test.

## Per-rule deltas

Let \(\Delta_i := \mu_i(\text{lhs}) - \mu_i(\text{rhs})\).

| Rule | \(\Delta_1\) | \(\Delta_2\) | \(\Delta_3\) |
|---|---:|---:|---:|
| `R_int_delta` | \(2 + \mu_1 t\) | \(3 + \mu_2 t\) | \(3 + \mu_3 t\) |
| `R_merge_void_left` | \(1\) | \(2\) | \(1\) |
| `R_merge_void_right` | \(1\) | \(2\) | \(1\) |
| `R_merge_cancel` | \(1 + \mu_1 t\) | \(2 + \mu_2 t\) | \(1 + \mu_3 t\) |
| `R_rec_zero` | \(1 + \mu_1 s\) | \(5 + \mu_2 s\) | \(1 + \mu_3 s\) |
| `R_rec_succ` | \(-\mu_1 s\) | \(-\mu_2 s\) | \(-1 - \mu_3 s\) |
| `R_eq_refl` | \(3 + 2\mu_1 a\) | \(5 + 2\mu_2 a\) | \(4 + 2\mu_3 a\) |
| `R_eq_diff` | \(1\) | \(1\) | \(1\) |

So the only problematic rule is:

```lean
R_rec_succ :
  Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

and it breaks **all three** measures.

---

## Candidate-by-candidate assessment

### `mu1`
Fails on `R_rec_succ`:

- lhs:
  \[
  \mu_1(recDelta\ b\ s\ (delta\ n)) = 2 + \mu_1 b + \mu_1 s + \mu_1 n
  \]
- rhs:
  \[
  \mu_1(app\ s\ (recDelta\ b\ s\ n)) = 2 + \mu_1 b + 2\mu_1 s + \mu_1 n
  \]

Difference:
\[
-\mu_1 s.
\]

So:
- if `s = void`, the measure is **equal**
- if `s ≠ void`, the measure **increases**

Hence `mu1` is **not** a valid termination measure.

---

### `mu2`
Same issue:

- lhs:
  \[
  6 + \mu_2 b + \mu_2 s + \mu_2 n
  \]
- rhs:
  \[
  6 + \mu_2 b + 2\mu_2 s + \mu_2 n
  \]

Difference:
\[
-\mu_2 s.
\]

Again:
- `s = void` gives equality
- non-`void` `s` gives increase

So `mu2` is also **not** a valid termination measure.

---

### `mu3`
This one is worse:

- lhs:
  \[
  2 + \mu_3 b + \mu_3 s + \mu_3 n
  \]
- rhs:
  \[
  3 + \mu_3 b + 2\mu_3 s + \mu_3 n
  \]

Difference:
\[
-1 - \mu_3 s,
\]
which is **always negative**.

So `mu3` strictly **increases** on every `R_rec_succ` step.

Thus `mu3` is definitely **not** a valid termination measure.

---

## Concrete counterexample

Take:

```lean
recDelta void void (delta void)  →  app void (recDelta void void void)
```

Then:

- `mu1`: `2 → 2`
- `mu2`: `6 → 6`
- `mu3`: `2 → 3`

So one explicit step already refutes all three.

---

## Overall conclusion

- **`mu1`: invalid**
- **`mu2`: invalid**
- **`mu3`: invalid**

If you want to rank them:

- `mu1` and `mu2` are equally close: they fail only because `R_rec_succ` is nondecreasing/increasing depending on `s`.
- `mu3` is strictly worse: `R_rec_succ` always increases it.

## Structural reason

All three are simple additive “size” measures.  
But `R_rec_succ` duplicates `s`:

```lean
recDelta b s (delta n)  →  app s (recDelta b s n)
```

So any measure of this same additive shape will struggle, because the rhs contains one extra copy of `s`. You need something more refined than plain additive size—likely a lexicographic or non-linear measure that treats the third `recDelta` argument as recursion fuel.

Failure of these candidates does **not** mean the system itself is nonterminating; it only means these three measures do not prove termination.
