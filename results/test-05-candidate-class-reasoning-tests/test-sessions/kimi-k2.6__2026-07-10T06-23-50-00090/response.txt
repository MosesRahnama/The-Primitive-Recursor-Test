**Short answer:** none of the three candidates is a valid termination measure. All of them fail on the rule `R_rec_succ`.

---

### What is required

A function `μ : Trace → Nat` is a termination measure for `Step` iff **every** instance of a rewrite strictly decreases `μ`:

```
Step t u  ⇒  μ t > μ u
```

If even one rule instance makes `μ` stay the same or increase, the candidate is invalid.

---

### The critical rule

The rule that defeats all three candidates is

```
R_rec_succ : recDelta b s (delta n)  →  app s (recDelta b s n)
```

On the left-hand side the subterm `s` occurs **once** (inside `recDelta`).  
On the right-hand side `s` occurs **twice**: once as the left argument of `app` and once inside the embedded `recDelta`.

Because the measures are simple additive/structural mappings, this duplication of `s` is fatal: the contribution of `s` on the right is always at least as large as on the left, and usually larger.

---

### Candidate‑by‑candidate analysis

#### `mu1`

Values of key constructors:
* `delta t`  → `1 + mu1 t`
* `app a b`  → `1 + mu1 a + mu1 b`
* `recDelta b s n` → `1 + mu1 b + mu1 s + mu1 n`

For `R_rec_succ`:
* LHS: `mu1 (recDelta b s (delta n)) = 2 + mu1 b + mu1 s + mu1 n`
* RHS: `mu1 (app s (recDelta b s n)) = 2 + mu1 b + 2·mu1 s + mu1 n`

The right-hand side exceeds the left by exactly `mu1 s`.

* If `s = void` (so `mu1 s = 0`) the two sides are **equal**.
* If `s` is larger, the RHS is **strictly larger** than the LHS.

`mu1` never decreases on this rule, so it is **invalid**.

---

#### `mu2`

Values of key constructors:
* `delta t`  → `1 + mu2 t`
* `app a b`  → `1 + mu2 a + mu2 b`
* `recDelta b s n` → `5 + mu2 b + mu2 s + mu2 n`

For `R_rec_succ`:
* LHS: `mu2 (recDelta b s (delta n)) = 6 + mu2 b + mu2 s + mu2 n`
* RHS: `mu2 (app s (recDelta b s n)) = 6 + mu2 b + 2·mu2 s + mu2 n`

The extra constant `5` on `recDelta` appears on **both** sides (the `recDelta` survives inside the RHS), so it cancels out. Again the RHS exceeds the LHS by `mu2 s`.

* If `s = void` the measures are **equal**.
* If `s` is larger the RHS is **larger**.

`mu2` is therefore **invalid** as well. The heavy weight on `recDelta` does not help because the constructor is not eliminated.

---

#### `mu3`

Values of key constructors:
* `delta t`  → `1 + mu3 t`
* `app a b`  → `2 + mu3 a + mu3 b`
* `recDelta b s n` → `1 + mu3 b + mu3 s + mu3 n`

For `R_rec_succ`:
* LHS: `mu3 (recDelta b s (delta n)) = 2 + mu3 b + mu3 s + mu3 n`
* RHS: `mu3 (app s (recDelta b s n)) = 3 + mu3 b + 2·mu3 s + mu3 n`

Here the RHS is **always strictly larger** than the LHS by `1 + mu3 s` (even when `s = void`).

`mu3` actually **increases** on this rule. It does decrease on every other rule (e.g. `eqW` drops by `1`, `merge` drops by at least `1`, etc.), but because it goes up on `R_rec_succ`, it is **invalid**.

---

### Summary

| Measure | Verdict | Why it fails |
|---------|---------|--------------|
| **mu1** | ❌ Invalid | On `R_rec_succ` the RHS measure equals the LHS when `s = void` and exceeds it otherwise. |
| **mu2** | ❌ Invalid | Same structural problem as `mu1`; the large `recDelta` constant cancels out, leaving the RHS equal or larger. |
| **mu3** | ❌ Invalid | On `R_rec_succ` the RHS is **always** larger than the LHS (by `1 + mu3 s`), so the measure increases. |

**Root cause:** `R_rec_succ` duplicates the subterm `s`. No simple linear, additive weighting with the coefficients chosen above can compensate for an arbitrary `s` being copied, so none of the three candidates proves termination.
