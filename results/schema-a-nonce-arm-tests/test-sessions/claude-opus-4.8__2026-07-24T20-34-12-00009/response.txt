## Reasoning

The system has two rules:

```
Velk(x, y, Mek)    -> x
Velk(x, y, Oru(n)) -> Tarn(y, Velk(x, y, n))
```

**Key observation:** The only symbol that can be reduced (the only defined/redex-forming symbol on a left-hand side root) is `Velk`. The symbols `Mek`, `Oru`, and `Tarn` never appear at the root of a left-hand side, so they are constructors and are never eliminated by any rule.

**Termination argument via a simple measure:**

Assign to each term a natural-number weight counting the number of `Velk` occurrences, but weighted by the "size" of their third argument. Concretely, define a measure on terms that decreases with each rewrite step:

- **Rule 1** (`Velk(x, y, Mek) -> x`): This strictly removes one `Velk` occurrence and introduces no new function symbols (the result `x` is a subterm of the redex). The number of `Velk` symbols strictly decreases.

- **Rule 2** (`Velk(x, y, Oru(n)) -> Tarn(y, Velk(x, y, n))`): This replaces a `Velk` whose third argument is `Oru(n)` with a `Velk` whose third argument is the strictly smaller `n`. The `Oru` constructor is consumed; a `Tarn` is created but `Tarn` can never form a redex, so it introduces no future reduction potential. The third argument of the surviving `Velk` strictly decreases in size.

A suitable termination ordering: interpret each term over the naturals with, e.g.,

- `Mek = 0`, `Oru(n) = n + 1`, `Tarn(a, b) = a + b`, and `Velk(x, y, m) = 2·m + x + y + 1` (or similar polynomial interpretation).

Checking the rules under such a polynomial interpretation:
- Rule 1: `Velk(x,y,Mek) = x + y + 1 > x`. ✓ (strict decrease)
- Rule 2: `Velk(x,y,Oru(n)) = 2(n+1) + x + y + 1 = 2n + x + y + 3`, while `Tarn(y, Velk(x,y,n)) = y + (2n + x + y + 1) = 2n + x + 2y + 1`. The difference is `2 - y`, which is not always positive.

So the naive polynomial needs adjustment, but the **structural argument** is decisive regardless: define the measure as the multiset (or lexicographic pair) tracking the size of the third argument of each `Velk`. Each rule strictly decreases this:
- Rule 1 removes a `Velk` entirely.
- Rule 2 strictly reduces the `Oru`-depth of the third argument of the involved `Velk`, and the newly created `Tarn` is inert.

Since `Oru`-nesting depth is finite in any given term and no rule ever increases it, every reduction chain terminates.

## Conclusion

Strong normalization follows **purely from the rules themselves** — no external structural axioms, no imported object-level assumptions. The essential facts (`Tarn`, `Oru`, `Mek` are constructors that never trigger further reduction; each rule strictly decreases the recursion argument of `Velk`) are all directly derivable from the two rules as written.
