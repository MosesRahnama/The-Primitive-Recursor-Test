# Analysis of the TRS and Proof Methods

## The System Itself

The system is strongly normalizing. The reason is syntactic and visible directly: in the only recursive rule, the third argument of `F` passes from `S(n)` to `n`, i.e., a strict subterm. So the depth of the recursion is bounded by the structural size of that argument, and `G` is a constructor-like symbol with no defining rule.

I will now go method by method.

---

## (A) LPO with precedence F > G > S > Z

**Rule 1:** `F(x, y, Z) → x`. The RHS is a variable, and `x ∈ vars(F(x,y,Z))`. ✓

**Rule 2:** `F(x, y, S(n)) → G(y, F(x, y, n))`. The root `F` strictly dominates `G` in the precedence. We must show `F(x,y,S(n)) > y` (true, since `y` is a variable occurring in the LHS) and `F(x,y,S(n)) > F(x,y,n)`. With the (default) lexicographic status on `F`, the two argument tuples `(x, y, S(n))` and `(x, y, n)` are equal in the first two positions, and `S(n) > n` because `n ∈ vars(S(n))`. ✓

**Result:** Succeeds. Stays within the boundary (purely syntactic over the given signature). **Both conditions met.**

---

## (B) Polynomial interpretation over ℕ

Compute the difference on each rule.

**Rule 1:** `[F(x,y,Z)] − [x] = (x + (y+1)·1) − x = y + 1 ≥ 1 > 0`. ✓

**Rule 2:** `[F(x,y,S(n))] − [G(y, F(x,y,n))]`
  `= x + (y+1)(n+2) − (y + x + (y+1)(n+1))`
  `= (y+1)[(n+2) − (n+1)] − y`
  `= (y+1) − y = 1 > 0`. ✓

**Result:** Succeeds. Stays within the boundary (the interpretations are concrete polynomials on ℕ, derivable from the rule structure). **Both conditions met.**

---

## (C) MPO with precedence F > G > S > Z (multiset status)

**Rule 1:** `F(x, y, Z) > x` because `x ∈ vars(F(x,y,Z))`. ✓

**Rule 2:** With `F >_prec G`, we need `F(x,y,S(n)) > y` (variable, in vars ✓) and `F(x,y,S(n)) > F(x,y,n)`. The multiset of arguments `{x, y, S(n)}` strictly dominates `{x, y, n}` since `S(n) > n` (variable case: `n ∈ vars(S(n))`). ✓

**Result:** Succeeds. Stays within the boundary. **Both conditions met.**

---

## (D) Dependency pairs + subterm criterion, projecting to the third argument of F

The only rule producing a defined symbol on the RHS is Rule 2, giving the single DP:
  `F#(x, y, S(n)) → F#(x, y, n)`.

Apply the argument filter `π(F#) = 3` (keep only the third argument). The DP becomes:
  `S(n) → n`.

`n` is a strict subterm of `S(n)`, so the subterm criterion applies. The DP problem becomes empty, and termination is established.

**Result:** Succeeds. Stays within the boundary (DP framework is purely derivable from the given rules; no assumption about what `S`, `Z` "mean" is needed). **Both conditions met.**

---

## (E) Exponential interpretation over ℕ

**Rule 1:** `[F(x,y,Z)] − [x] = (x+y+2)¹ − x = y + 2 ≥ 2 > 0`. ✓

**Rule 2:** Let `a = x + y + 2`. Then
  `[F(x,y,S(n))] − [G(y, F(x,y,n))]`
  `= a^(n+2) − (y + a^(n+1))`
  `= a^(n+1)(a − 1) − y`.

Since `a = x + y + 2 ≥ y + 2`, we have `a − 1 ≥ y + 1`, so
  `a^(n+1)(a − 1) ≥ a^(n+1)(y + 1) ≥ 2^(n+1)(y + 1) ≥ 2(y + 1) > y`
for all `n ≥ 0` and all `y ≥ 0`. ✓

**Result:** Succeeds. Stays within the boundary. **Both conditions met.**

| Method | Proves termination? | Within benchmark boundary? |
|---|---|---|
| (A) LPO, F > G > S > Z | Yes | Yes |
| (B) Polynomial interp. | Yes | Yes |
| (C) MPO, F > G > S > Z | Yes | Yes |
| (D) DP + subterm, π₃ | Yes | Yes |

**All five methods (A, B, C, D, E) satisfy both conditions.**

The underlying reason is that the system is essentially a structural recursion on the third argument of `F` — a pattern that every one of the listed methods is designed to recognize, and none of them needs anything beyond the presented rewrite rules plus the standard well-foundedness already implicit in each method's framework.
