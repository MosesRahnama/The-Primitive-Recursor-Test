Using the quoted boundary in a **strict** sense, the results are:

| Method | Proves termination? | Stays within benchmark boundary? | Reason |
|---|---|---:|---|
| **(A) LPO, F > G > S > Z** | **Yes** | **Yes** | `F(x,y,Z) > x` by subterm. For `F(x,y,S(n)) -> G(y,F(x,y,n))`, since `F > G`, it suffices that the lhs is bigger than `y` and `F(x,y,n)`; `y` is a subterm, and `F(x,y,S(n)) > F(x,y,n)` because `S(n) > n`. |
| **(B) Polynomial interpretation over N** | **Yes** | **No** | Rule 1: `x + (y+1)(0+1) = x+y+1 > x`. Rule 2: lhs = `x + (y+1)(n+2)`, rhs = `y + x + (y+1)(n+1) = lhs - 1`. So it orients both rules. But it uses an external arithmetic interpretation over `N`, which goes beyond “the rewrite system alone” under the strict reading. |
| **(C) MPO, F > G > S > Z** | **Yes** | **Yes** | Rule 1 by subterm. Rule 2: with `F > G`, need lhs > `y` and lhs > `F(x,y,n)`. The latter holds because `{x,y,S(n)} >mul {x,y,n}` via `S(n) > n`. Purely syntactic. |
| **(D) Dependency pairs + subterm criterion, project 3rd arg of F** | **Yes** | **Yes** | Only DP is `F#(x,y,S(n)) -> F#(x,y,n)`. Projecting to the 3rd argument gives `S(n) ▹ n`, a proper subterm decrease, so the only SCC is chain-free. Purely syntactic. |
| **(E) Exponential interpretation over N** | **Yes** | **No** | Let `b = x+y+2 >= 2`. Rule 1: `b > x`. Rule 2: lhs = `b^(n+2)`, rhs = `y + b^(n+1)`, and `b^(n+2) - (y + b^(n+1)) = b^(n+1)(b-1) - y >= (b-1)-y = x+1 > 0`. So it proves termination. But again it relies on external arithmetic semantics over `N`. |
