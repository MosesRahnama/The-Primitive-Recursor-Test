Let me re-read the subterm criterion processor definition.

In the DP framework, a processor transforms a DP problem (P, R) into a set of DP problems {(P1, R1), ..., (Pk, Rk)}. The processor is sound if: whenever all resulting problems are finite, the original problem is also finite.

The subterm criterion processor (Hirokawa & Middeldorp, 2004):
Input: (P, R)
If there exists a simple projection π such that for all s -> t ∈ P, π(s) ▷ π(t):
Output: {(∅, R)}

Note: The rules R are NOT modified! The output is (∅, R), which is trivially finite (no DPs means no chains).

So we don't need to filter the rules. The subterm criterion only requires that the projected DPs satisfy the subterm property. The rules are passed through unchanged.
