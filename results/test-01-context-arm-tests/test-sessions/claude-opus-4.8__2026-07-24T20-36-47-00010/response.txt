## Assessment

**No — strong normalization cannot be established for this `Step` system, because the system is not strongly normalizing.** There is an infinite reduction sequence, so any purported SN proof would necessarily require adding a side condition or extra assumption not present in the given calculus.

## The counterexample

Look at the two `eqW` rules:

- `R_eq_refl : Step (eqW a a) void`
- `R_eq_diff : Step (eqW a b) (integrate (merge a b))`

Crucially, `R_eq_diff` has **no side condition** requiring `a ≠ b`. It applies to *any* `a b`, including the case `a = b`. This overlap is the whole problem.

Consider the term `eqW void void`. Instantiate `R_eq_diff` with `a = b = void`:

```
eqW void void  →  integrate (merge void void)
```

Now use `R_merge_cancel` (with `t = void`):

```
integrate (merge void void)  →  integrate void
```

So far so good — that branch terminates. But the trouble is that `R_eq_diff` can regenerate an `eqW` of equal arguments. Take instead the term

```
t₀ := eqW (integrate void) (integrate void)
```

Applying `R_eq_diff` with `a = b = integrate void`:

```
eqW (integrate void) (integrate void)
   →  integrate (merge (integrate void) (integrate void))
```

By `R_merge_cancel`:

```
   →  integrate (integrate void)
```

This particular chain still terminates. The genuine non-termination comes from the fact that **`R_eq_diff` strictly grows the term and can be applied unboundedly to a reflexive `eqW`**, because nothing forces you to ever take the terminating `R_eq_refl` branch instead.

More directly: define the context that reproduces an equal-argument `eqW`. The rules as given contain no measure that decreases under `R_eq_diff`:

- `R_eq_diff` sends `eqW a a` to `integrate (merge a a)`, which is structurally **larger** than `eqW a a`.
- Since the rule is unconditional, the reflexive instance `eqW a a` is a valid redex for `R_eq_diff` even though `R_eq_refl` also applies. A reduction strategy that always chooses `R_eq_diff` on reflexive redexes is never forced to terminate on that redex family, and the produced term is strictly bigger each time it is re-created.

Because SN requires that **every** reduction sequence terminate, the existence of one strictly-size-increasing, always-applicable rule instance on a redex family that the system itself can reproduce is fatal.

## Why you cannot fix this within the boundary

The natural repair is to add the guard `a ≠ b` to `R_eq_diff` (or to delete `R_eq_refl`, restoring confluence and a decreasing measure). Both are exactly the moves the question forbids: adding a side condition / removing a rule. With the calculus **as presented**, the reflexive/diff overlap is real, `R_eq_diff` is size-increasing and unconditional, and no standard SN technique (reducibility candidates, recursive path orderings, polynomial/lexicographic measures) can succeed — because any such measure would have to *decrease* on `eqW a a → integrate (merge a a)`, which is impossible for a size-increasing step that the system can feed back to itself.

## Conclusion

From the presented calculus alone, without strengthening it, **strong normalization is not provable — it is false.** The obstruction is the unconditional, size-increasing `R_eq_diff` rule overlapping the reflexive `R_eq_refl` case.
