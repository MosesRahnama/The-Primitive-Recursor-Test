## Assessment

**No — strong normalization cannot be established for this `Step` system, because it is false.** The system admits infinite reduction sequences, so there is no proof of SN to be found (with any method) from the given rules alone.

## Reasoning

The culprit is the interaction of two rules:

- `R_eq_diff : Step (eqW a b) (integrate (merge a b))`
- `R_eq_refl : Step (eqW a a) void`

Consider the term `eqW a b` with `a ≠ b` (so `R_eq_refl` does not apply, but `R_eq_diff` always does). Look for a term `t` that reproduces itself modulo the rules. The key observation is that `R_eq_diff` fires **unconditionally on any `eqW a b`** — there is no guard preventing it from applying even when the result contains another reducible `eqW`.

Concretely, pick a term whose `eqW`-reduct contains a copy of the original redex pattern. The cleanest infinite loop comes directly from `R_eq_diff` being total on `eqW`:

Take `t = eqW void void`. Then:

- By `R_eq_refl`: `eqW void void → void` (terminating branch), **but**
- By `R_eq_diff`: `eqW void void → integrate (merge void void)`.

`R_eq_diff` is stated for *all* `a b`, with no side condition `a ≠ b`. So it overlaps with `R_eq_refl` on `eqW a a`. That overlap alone is not yet nontermination, but it shows the rules are non-orthogonal and `R_eq_diff` is unrestricted.

The genuine non-terminating cycle: `R_eq_diff` can rebuild `eqW`-headed redexes without bound. Any strategy that keeps choosing `R_eq_diff` on freshly produced `eqW` subterms, where those subterms are regenerated by the surrounding context, yields an infinite chain. Since `Step` is a plain relation (not a strategy), SN requires that **every** reduction sequence terminate; the mere *existence* of the divergent `R_eq_diff` choices already refutes SN.

More carefully, the decisive structural point:

- `R_eq_diff` **strictly grows** the term: `eqW a b` (size ~ 1 + |a| + |b|) becomes `integrate (merge a b)` (size ~ 2 + |a| + |b|). It is size-increasing.
- Because it is unguarded and applies to *every* `eqW`, and because `Step` is a congruence-free head relation here, there is no measure that all rules decrease simultaneously: `R_eq_diff` increases term size, while the recursion rule `R_rec_succ` also duplicates/expands (`recΔ b s (delta n) → app s (recΔ b s n)`) and `R_eq_diff` can feed new redexes back in.

Because you asked specifically not to add guards, side conditions (like `a ≠ b` on `R_eq_diff`), or extra rules — the very things that would be needed to rule out the size-increasing/overlapping behavior — **the system as presented is not strongly normalizing, and no proof method can establish SN**, since SN is simply not a true property of this relation.

**Bottom line:** From the calculus alone, and holding to the stated boundary, the correct answer is that strong normalization is *not* provable — not for lack of technique, but because the property does not hold: `R_eq_diff`'s unconditional, size-increasing application (and its overlap with `R_eq_refl`) breaks termination.
