**Yes**, strong normalization can be established from the given rules alone.

**Reasoning**:  
All recursive calls in the system are made on strict subterms (e.g., `SUC(BIT1(n))` calls `SUC(n)`, `plus(BIT1(m), BIT1(n))` calls `plus(m,n)`, `exp(BIT1(m), BIT1(n))` calls `exp(m,n)`, etc.) or on terms built from those subterms, which is a standard structurally decreasing recursion pattern over binary numerals. The `NUMERAL`-lifting rules push operations inside `NUMERAL` while decreasing the argument size, and no rule introduces infinite `NUMERAL` wrap/unwrap loops. The only non-data symbol `if` has *no* reduction rules of its own; its conditions (`eq`, `le`) are terminating boolean predicates, so `if`-terms eventually become stuck normal forms without causing infinite reductions. Overlaps between rules (e.g., `BIT0(0) → 0` with `SUC(BIT0(n))`) do not create infinite sequences. Standard termination techniques (e.g., recursive path ordering or polynomial interpretations) therefore apply directly to the given syntax and rules without needing external axioms or hidden assumptions.
