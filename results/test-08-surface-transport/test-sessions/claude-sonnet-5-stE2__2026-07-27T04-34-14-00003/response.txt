## Verdict: **Terminating** — provable directly from the given rules using the Lexicographic Path Order (LPO).

No additional axioms, guards, or side conditions are needed; a single well‑founded simplification order suffices to orient all three rules.

### Setup

Take the *precedence* on function symbols

```
extract_prefix  ≻  extract_prefix_k  ≻  append  ≻  cons  ≻  best_eclass_term  ≻  nth  ≻  {nil, zero, succ}
```

(any strict order respecting these groupings works; the constants `nil`, `zero`, `succ` are minimal).

For symbols compared with themselves (`extract_prefix` vs `extract_prefix`) use the standard **lexicographic** status on argument tuples, comparing left‑to‑right.

Recall the LPO rule: for `s = f(s₁,…,sₙ)` and `t = g(t₁,…,tₘ)`,

* if `f ≻ g`, then `s ≻ t` iff `s ≻ tⱼ` for every `j`;
* if `f = g`, then `s ≻ t` iff the argument tuples compare lexicographically (with each `s ≻ tⱼ` needed for later positions), using the recursive definition of `≻`.

We check each rule.

---

**Rule 1.**
`extract_prefix(w,graph,zero) → nil`

Head symbols: `extract_prefix ≻ nil`. Since `nil` is a constant (no arguments to dominate), the LPO clause for `f ≻ g` is satisfied vacuously. Hence `lhs ≻ rhs`.

---

**Rule 2.**
`extract_prefix(w,graph,succ(i)) → extract_prefix_k(w,graph,i, extract_prefix(w,graph,i))`

Head symbols: `extract_prefix ≻ extract_prefix_k`. We must show the LHS dominates *every* argument of the RHS:

* `w`, `graph`: literal subterms of LHS ⇒ dominated.
* `i`: subterm of `succ(i)`, itself a subterm of LHS ⇒ dominated.
* `extract_prefix(w,graph,i)`: same head symbol as LHS (`extract_prefix`), so compare argument tuples lexicographically:
  `w = w`, `graph = graph`, and finally `succ(i) ≻ i` (since `i` is a strict subterm of `succ(i)`).
  Hence `extract_prefix(w,graph,succ(i)) ≻ extract_prefix(w,graph,i)`.

All four RHS-top arguments are dominated ⇒ `lhs ≻ rhs`.

---

**Rule 3.**
`extract_prefix_k(w,graph,i,memo) → append(memo, cons(best_eclass_term(w,memo,nth(graph,i)), nil))`

Head symbols: `extract_prefix_k ≻ append`. Need LHS to dominate both arguments of `append`:

* `memo`: a literal subterm of LHS ⇒ dominated.
* `cons(best_eclass_term(w,memo,nth(graph,i)), nil)`:
  head `cons`, and `extract_prefix_k ≻ cons`, so need LHS to dominate both arguments of `cons`:
  * `nil`: constant, `extract_prefix_k ≻ nil` ⇒ dominated.
  * `best_eclass_term(w,memo,nth(graph,i))`: head `best_eclass_term`, `extract_prefix_k ≻ best_eclass_term`, need LHS to dominate its arguments:
    * `w`, `memo`: literal subterms ⇒ dominated.
    * `nth(graph,i)`: head `nth`, `extract_prefix_k ≻ nth`, and its arguments `graph`, `i` are literal subterms of LHS ⇒ dominated.
  So `best_eclass_term(...)` is dominated.
  So `cons(...)` is dominated.

Thus `append(...)` is dominated ⇒ `lhs ≻ rhs`.

---

### Conclusion

All three rewrite rules are strictly decreasing with respect to the same LPO instance (fixed precedence, lexicographic status). Since LPO is a well‑founded order on terms, every rewrite step strictly decreases the term in this order, so no infinite rewrite sequence exists. Hence the system is **terminating**, and this is established purely from the rule shapes themselves — no extra structural assumptions were used beyond the standard LPO machinery.
