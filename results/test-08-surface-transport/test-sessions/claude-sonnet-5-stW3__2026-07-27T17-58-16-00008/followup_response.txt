I picked the methods incrementally, driven by what each rule actually demands, rather than committing up front to a single technique.

**Why I first tried a simplification order (RPO) at all.** The system has no genuine mutual recursion visible in rules 1–7 — each of `f0`, `f2`, `f3` recurses only by stripping one `f1`-layer off one argument and calling itself (or a lower function in the intended precedence) on the remainder. That is exactly the shape simplification orders are built for: monotonicity plus subterm-domination handles "peel a constructor, recurse" patterns for free. So I tried the cheapest, most syntactic method first, and checked rule by rule:

- R1, R3, R4, R7 are trivial subterm eliminations — no order is even needed beyond subterm property.
- R2, R5, R6 are the classic "recurse on immediate subterm, keep the wrapper" pattern, which is precisely what RPO's lexicographic/precedence machinery is designed to certify, given a precedence where the defined symbol dominates its own auxiliary calls (`f4>f2>f0>f3>f1`). I didn't need polynomial weights or any semantic content — pure syntax sufficed, so I preferred the syntactic method (Occam's razor: don't invoke semantics where subterm structure already proves it).

I specifically avoided polynomial/matrix interpretations for these rules because R5 duplicates `v1` on the right (`f0(f2(v0,v1),v1)`), which is harmless for RPO (multiset/lex status doesn't care about duplication as long as the head decreases) but is exactly the kind of thing that forces careful weight-monotonicity bookkeeping in a polynomial interpretation. RPO sidesteps that complication entirely, so it was the more economical choice.

**Why I switched away from a simplification order for rule 8.** I didn't switch by preference — I switched because I checked whether RPO/KBO/polynomial-with-subterm-property could possibly work, and found a structural obstruction: the recursive argument `f3(f1(v0))` in R8 properly *contains* `f1(v0)` as a subterm. Every simplification order must give subterms strictly less than their containing term (that's the subterm property, which is part of the definition of "simplification order"), so any such order would force `f3(f1(v0)) > f1(v0)`, hence `f4(f3(f1(v0))) > f4(f1(v0))`, exactly reversing the inequality termination of R8 requires. This isn't a failure of search — it's a theorem-level incompatibility. So I had to abandon simplification orders for this rule specifically, on principle, not by trial and error.

**Why dependency pairs + a semantic interpretation.** Once simplification orders are ruled out for R8, the standard next tool for "recursion where the argument shrinks only in a non-syntactic, semantic sense" is the dependency pair framework, precisely because DP compares only the recursive call sites (`F4(f1(v0)) -> F4(f3(f1(v0)))`) and does not require the comparison to respect subterm ordering globally — only weak monotonicity on the underlying interpretation is needed, not the strict subterm property. This is the standard remedy exactly for cases like this one, where the recursive argument passes through an auxiliary "destructor" function (`f3`, behaving like predecessor) before the call.

I then chose the simplest semantic interpretation that makes the single resulting cycle decrease: since rules 6–7 already show `f3` behaves as predecessor on `f1`-towers, I reused that same reading (`f1↦+1`, `f3↦∸1`) as a natural number interpretation, which is minimal and directly justified by the given rules — not an imported assumption, but the semantics the rules themselves encode. This gave a strict decrease on the one existing cycle without needing to invent anything beyond what R6/R7 already establish.

**Why not something even heavier (e.g. full matrix interpretations or semantic labeling from scratch, or a size-change principle)?** Because the problem only had one non-simplification-orderable rule, and its recursion structure was already exposed by rules 6–7. Using DP plus the minimal, rule-motivated interpretation solves exactly that one obstruction with no extra machinery, keeping the whole proof modular: syntactic order for the "easy" rules, dependency pairs only where structurally forced, and a semantic weight taken directly from what R6/R7 already mean. That is the least additional apparatus sufficient to cover every rule.
