# Why I chose RPO for this system

**1. The syntactic shape of the rules immediately suggested a simplification order.**

Looking at the three rules:

```
f5(v0,v1,c0)        -> c1
f5(v0,v1,f0(v2))    -> f6(v0,v1,v2, f5(v0,v1,v2))
f6(v0,v1,v2,v3)     -> f2(v3, f1(f4(v0,v3,f3(v1,v2)), c1))
```

I noticed two structural facts that are the classic signature of an RPO-provable system:

- **Rule 2** is a *recursive call pattern*: the same head symbol `f5` appears on both sides, with one argument shrinking from `f0(v2)` to `v2` (a proper-subterm decrease) while the other arguments stay literally identical. This is exactly what the lexicographic/multiset comparison in RPO is built to detect — "same function symbol, one argument gets structurally smaller, rest are equal or smaller."

- **Rule 3** is a *pure unfolding/flattening* step: every variable on the right (`v0,v1,v2,v3`) already occurs in the left-hand side, and no new recursive call is introduced — `f6` disappears entirely and is replaced by a bureaucratic rearrangement using strictly "lower" auxiliary symbols (`f2,f1,f4,f3,c1`). This is exactly the pattern RPO's precedence-step rule handles: introduce a term headed by a symbol lower in the precedence, built only from pieces already dominated by the left side.

- **Rule 1** is trivial — a base case collapsing to a constant, which is dominated for free once the constant is placed low enough in the precedence.

**2. No measure/interpretation was needed — the decrease is purely structural.**

None of the rules require counting, size arithmetic, or numeric interpretations of subterms; the decrease is always explainable by "this is a subterm" or "this rearranges already-available pieces under a smaller head symbol." That’s precisely when RPO is the natural and minimal tool — it works directly on syntax and requires only:
- a precedence (total order) on function symbols, and
- a status (lex or multiset) for argument comparison,

both of which are *derived choices about how to compare terms*, not extra axioms about the semantics of `f5, f6`, etc. This satisfies the constraint of using only what's derivable from the given syntax/rules.

**3. Why not other methods?**

- **Polynomial/size interpretations**: would work here too (e.g. weight-based decrease), but they require picking numeric weights per symbol — an extra "interpretation" layer. RPO is more minimal since it only needs a symbol ordering, and the rules' shape (recursive shrinking + pure unfolding) fits RPO's built-in cases exactly, with no need to invent numeric weights.
- **Dependency pairs / more powerful techniques**: unnecessary machinery here, since a single, simple RPO precedence suffices to orient all three rules directly — no need for the extra dependency-pair transformation, SCC analysis, or usable-rules refinements.
- **Manual well-founded measure via induction**: possible, but it would essentially *reconstruct* what RPO gives for free (subterm relation + precedence), so RPO was the more economical, standard, and rule-agnostic choice — it doesn't presuppose anything beyond "compare symbols, compare subterms."

**In short:** the recursive rule literally recurses on a proper subterm of one argument while holding others fixed, and the unfolding rule only reshuffles already-present subterms under new, precedence-lower function symbols. That is the textbook use case for RPO, so I picked it as the simplest, syntax-only order that provably terminates the system without inventing any additional structure.
