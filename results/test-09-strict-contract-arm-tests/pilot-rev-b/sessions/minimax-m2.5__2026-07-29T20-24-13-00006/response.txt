### Why the system terminates

Define a lex‑ordered measure  

\[
M(t)=\bigl(
\#_{\text{eqW}}(t),\;
\#_{\text{recΔ}}(t),\;
\#_{\text{merge}}(t),\;
\#_{\text{integrate}}(t),\;
\#_{\delta}(t)
\bigr)
\]

where each \(\#_C(t)\) is the number of occurrences of constructor \(C\) in \(t\).  
The ordering is lexicographic: the first component is compared first, then the second, and so on.

Now check every rule:

| Rule | Effect on \(M\) |
|------|-----------------|
| `R_int_delta` – `integrate (delta t) → void` | removes one `integrate` and one `δ` → the 4‑th and 5‑th components drop. |
| `R_merge_void_left/right` – `merge void t → t` / `merge t void → t` | removes one `merge` → the 3‑rd component drops. |
| `R_merge_cancel` – `merge t t → t` | removes one `merge` (and collapses two copies of `t`) → the 3‑rd component drops. |
| `R_rec_zero` – `recΔ b s void → b` | removes the whole `recΔ` → the 2‑nd component drops. |
| `R_rec_succ` – `recΔ b s (δ n) → app s (recΔ b s n)` | the 5‑th component (total number of `δ`) decreases (one `δ` is removed from the argument). The 2‑nd component stays the same, but the 5‑th drops, so the whole vector drops lexicographically. |
| `R_eq_refl` – `eqW a a → void` | removes an `eqW` → the 1‑st component drops. |
| `R_eq_diff` – `eqW a b → integrate (merge a b)` | **removes** the leading `eqW` (the 1‑st component drops) at the cost of adding a `merge` and an `integrate`. The increase occurs only in later components (3‑rd and 4‑th), which are lexicographically *after* the first component that already dropped. Hence the whole vector strictly decreases. |

Thus every rewrite step makes \(M\) decrease in the well‑founded lexicographic order, guaranteeing that no infinite reduction sequence exists.

### Duplication check (as required by the contract)

The contract asks us to detect steps that *duplicate* a subterm \(S\).  
None of the rules create a term in which a proper subterm appears more times than it did in the source term:

* `R_rec_succ` replaces `recΔ b s (δ n)` by `app s (recΔ b s n)`. The recursive call `recΔ b s n` is **smaller** (its third argument lost one `δ`), not a duplicate of a larger subterm.
* `R_eq_diff` builds `merge a b`; each of `a` and `b` occurs exactly once.
* All other rules either delete duplicated structure (`R_merge_cancel`) or remove constructors.

Since no step duplicates a subterm, the “additive failure’’ situation never arises, and no corrective fix is needed.
