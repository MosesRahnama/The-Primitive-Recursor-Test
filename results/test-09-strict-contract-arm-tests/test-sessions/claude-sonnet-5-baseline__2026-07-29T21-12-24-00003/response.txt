## Assessment

**Yes — strong normalization follows from the calculus as given, by an elementary well‑founded induction on term size, using nothing beyond the automatic properties of the inductive type `Trace` (constructor injectivity/disjointness) and case analysis on the eight rules.**

### Why this is straightforward here

The crucial structural fact is that `Step` has **no congruence/context‑closure constructors**. Every rule is a *root* pattern match on the *whole* term:

```
integrate(delta t), merge(void,t), merge(t,void), merge(t,t),
recΔ(b,s,void), recΔ(b,s,delta n), eqW(a,a), eqW(a,b)
```

There is no rule of the shape "if `Step t t'` then `Step (f … t …) (f … t' …)`". Hence a term can only be rewritten if its *outermost* symbol already matches one of these eight shapes; nothing ever gets rewritten "underneath" a mismatching head.

Now inspect what each rule produces:

- `merge(void,t) → t`, `merge(t,void) → t`, `merge(t,t) → t`, `recΔ(b,s,void) → b`, `eqW(a,a) → void`: in every one of these cases the result is a **strict immediate subterm** of the redex, so its size (constructor count) strictly decreases.

- `integrate(delta t) → void`: result is a normal form (nothing matches `void` as a root).

- `eqW(a,b) → integrate(merge a b)` (a ≠ b, or even a = b via the other branch): the result's root is `integrate`, but the sole rule for `integrate` requires its argument to be headed by `delta`. Since `merge` and `delta` are distinct constructors of the same inductive type, `merge a b` can **never** be syntactically `delta t'`. So `integrate(merge a b)` is automatically irreducible — a normal form, regardless of what `a,b` are.

- `recΔ(b,s,delta n) → app(s, recΔ(b,s,n))`: although this step can *increase* term size (by `size(s)`), the root of the result is `app`, and **no rule has `app` as an outermost pattern at all**. So this result is immediately irreducible — a normal form — no matter how large it is or what redexes are buried inside it (they can never be reached, since there is no congruence rule to descend into `app`'s arguments).

So *every* one-step reduct of any term is either (a) a strictly smaller subterm, or (b) already a normal form. A straightforward strong induction on the size of `t` then proves SN for all `t`:

- If `t` has no `Step`-successor, it is trivially SN.
- If `t` does step to some `t'`, then `t'` falls into case (a) or (b) above; case (b) is immediately SN, and case (a) is SN by the induction hypothesis (since `size(t') < size(t)`).

This uses only: well-founded induction on ℕ, and the basic no‑confusion/injectivity facts that Lean generates automatically for any `inductive` type (e.g. `merge a b ≠ delta t`, and `app _ _` is not equal to any of the other constructors' patterns). None of this requires adding axioms, side conditions, congruence rules, or external assumptions — it is a direct consequence of the syntax and the eight rules exactly as stated.

### Conclusion

Strong normalization is **provable within the system as presented**, essentially *because* the calculus lacks contextual closure: reduction is confined to root matches, and the non‑matching-constructor and strict-subterm facts jointly bound every reduction sequence to finite length. The proof is elementary (structural/size induction) and needs no imported structural axioms or hidden assumptions beyond what `inductive Trace` already provides.
