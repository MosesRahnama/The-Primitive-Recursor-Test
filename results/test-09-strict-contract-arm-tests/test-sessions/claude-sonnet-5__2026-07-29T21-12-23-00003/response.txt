**Yes** — strong normalization can be established for this system using a standard order‑theoretic method (a Recursive Path Ordering, in the sense of Dershowitz), without adding rules, side‑conditions, guards, or object‑level axioms. ### 1. The failing step

The dangerous rule is

```
R_rec_succ : recΔ(b, s, delta n) → app(s, recΔ(b, s, n))
```

It duplicates the subterm `S := s`: on the left `s` occurs once, on the right it occurs twice (once bare, once nested inside `recΔ(b,s,n)`).

Take the natural node‑count measure `M` (`M(void)=1`, unary = `1+M(arg)`, binary/ternary = `1+`sum of args).

- `M(before) = M(recΔ(b,s,delta n)) = 1 + M(b) + M(s) + (1+M(n)) = M(b)+M(s)+M(n)+2`
- `M(after) = M(app(s, recΔ(b,s,n))) = 1 + M(s) + (1+M(b)+M(s)+M(n)) = M(b)+2M(s)+M(n)+2`

So exactly as the contract predicts:

`M(after) = M(before) + M(S)`, with `S = s`.

Since every trace satisfies `M(t) ≥ 1` (the minimum is `M(void)=1`), we get `M(S) ≥ 1` always, hence `M(after) ≥ M(before) + 1`. **There is never a strict drop under `M`; the measure strictly increases on every firing of this rule.** A naive size/weight argument is dead on arrival for this system.

(The other duplication-like rule, `R_eq_diff : eqW(a,b) → integrate(merge(a,b))`, does *not* duplicate — `a`,`b` each occur once on both sides — so it only causes a harmless constant `+1`; it is not the obstruction.)

### 2. Proposed fix and its required premise

The standard fix for exactly this failure pattern (structural recursor duplicating a step term) is a **Recursive Path Order**: instead of comparing raw sizes, compare terms via a precedence on function symbols plus a status (lexicographic on `recΔ`'s arguments), using the subterm property built into RPO.

Key premise to discharge: *there exists a precedence and status making all 8 rules RPO-decreasing.*

Take precedence `recΔ > eqW > merge > integrate > delta > app > void`, lexicographic status on `recΔ`'s argument tuple. Check:

- `integrate(delta t) → void`, all `merge`/`recΔ` projection rules (`void`-left/right, cancel, `rec_zero`), `eqW(a,a)→void`: all instances of the **subterm property** (`f(t̄) ≻ tᵢ`), automatically RPO-decreasing, precedence-independent.
- `recΔ(b,s,delta n) → app(s, recΔ(b,s,n))`: since `prec(recΔ)>prec(app)`, need `recΔ(b,s,delta n) ≻ s` (subterm, ✓) and `recΔ(b,s,delta n) ≻ recΔ(b,s,n)` (same head, lex comparison on `(b,s,delta n)` vs `(b,s,n)`: first two tie, `delta n ≻ n` by subterm — ✓). Both hold, so RPO gives strict decrease **despite** the duplication of `s`, because `s` itself is only ever a *proper subterm* being copied, never something that grows.
- `eqW(a,b) → integrate(merge(a,b))`: with `prec(eqW) > prec(integrate), prec(merge)`, reduces to `eqW(a,b) ≻ a` and `≻ b` (subterm, ✓), giving `eqW(a,b) ≻ merge(a,b) ≻`-dominated, hence `≻ integrate(merge(a,b))`.

All inequalities needed for the precedence are mutually consistent (no rule requires the reverse), so a genuine total precedence exists. **Premise verified explicitly**, not merely asserted.

### 3. Conclusion

By Dershowitz's theorem (a standard, axiom-free, order-theoretic fact: RPO-compatibility ⇒ termination), this concrete calculus is compatible with such an ordering, hence **strongly normalizing**. The duplication in `R_rec_succ` blocks a size argument but does not block RPO, because the duplicated material (`s`) is always a *subterm already present*, never freshly synthesized or enlarged by any rule (no rule ever introduces a new `delta`), so the well-founded decrease on the recursor's numeral argument suffices once measured structurally rather than by raw size.

No premise here required strengthening the rule set, adding side-conditions, or importing extra axioms — only the standard (and here, explicitly checked) RPO compatibility argument. **No CONSTRAINT BLOCKER.**
