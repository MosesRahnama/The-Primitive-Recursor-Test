**1. Step that duplicates a subterm**

Rule `R_rec_succ`:
```
recΔ b s (delta n) → app s (recΔ b s n)
```

The subterm `s` appears once on the left and twice on the right.

**2. Additive failure with a naive measure**

Take the measure `M(t)` = number of constructors in `t` (size).  
Left side size:  
`M(recΔ b s (delta n)) = 1 + M(b) + M(s) + 1 + M(n) = 2 + M(b) + M(s) + M(n)`.

Right side size:  
`M(app s (recΔ b s n)) = 1 + M(s) + (1 + M(b) + M(s) + M(n)) = 2 + M(b) + 2·M(s) + M(n)`.

Hence  
`M(after) = M(before) + M(s)`.  
When `M(s) ≥ 1`, the measure does not strictly drop – additive failure.

**3. Proposed fix**

Use the **lexicographic path order (LPO)** with a well‑chosen precedence. LPO is a well‑founded simplification order; it does not suffer from the duplication problem because it compares terms structurally rather than by linear size.

Choose the precedence:
```
recΔ > app > eqW > integrate > delta > merge > void
```

**4. Key premise: every rewrite rule is strictly oriented by the chosen LPO**
