## Assessment: Yes — strong normalization is derivable from this calculus alone.

**Reasoning.**

The eight rules split cleanly into two groups, and each group is strongly normalizing by an entirely standard, self-contained argument — no extra axioms, congruence rules, or side conditions need to be smuggled in.

**1. The purely "first-order collapsing" rules are strictly size-decreasing.**

`R_int_delta`, `R_merge_void_left`, `R_merge_void_right`, `R_merge_cancel`, `R_rec_zero`, `R_eq_refl` all replace a term by a proper subterm (or by `void`). Any measure counting constructors strictly decreases on each of these, so no infinite chain can consist only of these rules — this is immediate well-founded induction on the (finite, inductively defined) `Trace` type, using nothing but the fact that `Trace` is a standard strictly-positive inductive type with disjoint, well-founded constructors.

**2. `R_rec_succ` behaves like a primitive-recursive iterator, and is SN for a classical reason.**

`recΔ b s (delta n) → app s (recΔ b s n)` does not decrease raw size (it duplicates `s`), but it is *exactly* the reduction rule for the unary-natural-number recursor (Gödel's T style iterator). Its termination does not depend on any extra assumption: the only thing that can trigger another instance of this rule at the same "spot" is a strict decrease of the third argument `n` along the subterm order (peeling one `delta`), and `Trace` terms have finite `delta`-depth. Crucially, `app` itself has **no reduction rule at all** in this system — it is inert, never a beta-redex — so there is none of the higher-order substitution complexity that forces one to use full reducibility-candidate machinery for System T; duplication of `s` only duplicates *independent*, already-decreasing sub-recursions. A direct structural induction on the delta-depth of the recursion argument (the classical argument for primitive-recursive term rewriting) suffices.

**3. `R_eq_diff` increases size but cannot re-trigger growth.**

`eqW a b → integrate (merge a b)` strictly increases size, but the result is controlled: `integrate` can only fire again via `R_int_delta`, which needs its argument to be *syntactically* headed by `delta`. Since `merge` and `delta` are distinct, disjoint constructors, `merge a b` can only become `delta`-headed after `merge` itself reduces (via the strictly decreasing merge rules) and, if `a`/`b` themselves reduce further, only through the already-covered strictly decreasing (or independently terminating) rules. So this rule cannot generate an unbounded chain; it contributes at most a bounded, finite continuation governed by the measures already established in (1)–(2). (Note also that as literally written, `Step` contains **no compatible/congruence-closure constructors** — it only rewrites whole terms matching a pattern at the root — which makes this observation even more immediate, since `integrate(merge a b)` is then a normal form outright.)

**4. Non-confluence is irrelevant to SN.**

The critical overlaps (`eqW a a` matching both `R_eq_refl` and `R_eq_diff`; `merge void void` matching three rules) make the system non-confluent, but strong normalization only requires *every* reduction path to terminate, not that they agree. Both branches terminate independently by the measures above.

**Conclusion.** Combining (1) a strict-decrease argument for five rules, (2) a classical structural/well-founded induction on the recursion argument for `R_rec_succ` (made easier than System T by the inertness of `app`), and (3) the constructor-disjointness fact bounding the growth from `R_eq_diff`, one obtains a full strong-normalization proof using only ordinary well-founded/structural induction on the given inductive type and rules — nothing beyond what Lean's definitions already provide. No additional rewrite rules, guards, side conditions, or external axioms are needed.
