**Assessment:** **Yes**, strong normalization can be established from the presented calculus alone.

**Reasoning:**

The system essentially encodes primitive recursion over a unary natural number representation (`void` = zero, `delta` = successor) with first-order term constructors. Strong normalization holds for the following reasons:

1. **No delta creation**: Crucially, no rewrite rule introduces a new `delta` constructor. Rules like `R_int_delta` and `R_rec_succ` consume `delta` constructors, while other rules either preserve existing subterms or eliminate constructors. Since `delta` never appears on any right-hand side unless it was on the left, the total number of `delta` constructors in any term is non-increasing and strictly decreases with `R_int_delta` and each application of `R_rec_succ`.

2. **Structural recursion**: The `recΔ` rules implement standard primitive recursion. `R_rec_succ` requires the third argument to be of the form `delta n` and reduces it to `n` in the recursive call. Although the step term `s` is duplicated in the output `app s (recΔ b s n)`, the recursion argument `n` is structurally smaller than `delta n`. This is exactly the primitive recursion schema known to terminate (analogous to Gödel's System T recursor).

3. **No back-edges**: The `eqW` rules eliminate `eqW` constructors (`R_eq_refl` produces `void`; `R_eq_diff` produces `integrate (merge a b)`). Since `eqW` never appears in any right-hand side, it cannot be recreated. Similarly, `integrate` and `merge` either reduce to subterms or become stuck (normal forms), never generating new redexes for `recΔ` or `eqW`.

4. **Interaction is harmless**: The only potentially "expansive" rule is `R_rec_succ`, but the duplicated `s` is wrapped in a passive `app` constructor (which has no reduction rules). Reductions inside `s` or the recursive call proceed independently, and the recursive call is on a strictly smaller third argument with respect to the well-founded ordering induced by the `delta`-depth.

Since the number of `delta` constructors bounds the number of `R_rec_succ` applications, and all other rules terminate finitely without creating new active redexes of the recursive kind, every reduction sequence must terminate. Standard termination proofs for primitive recursion (e.g., Tait's computability method or a weight function measuring `recΔ`-depth) apply directly without requiring external axioms.
