## Assessment: **Strong normalization holds, and can be established directly from the given system — but for a structural reason that must be made explicit.**

### Step 1 — Locate the duplication and show the additive failure

The only rule that duplicates a subterm is

```
R_rec_succ : Step (recΔ b s (delta n)) (app s (recΔ b s n))
```

Here `s` occurs once on the left and twice on the right (once directly under `app`, once inside the nested `recΔ b s n`).

Take the canonical size measure
`M(void)=1`, `M(delta t)=1+M(t)`, `M(integrate t)=1+M(t)`, `M(merge a b)=M(app a b)=M(eqW a b)=1+M(a)+M(b)`, `M(recΔ b s n)=1+M(b)+M(s)+M(n)`.

Compute:

- `M(before) = M(recΔ b s (delta n)) = 2 + M(b) + M(s) + M(n)`
- `M(after)  = M(app s (recΔ b s n)) = 2 + M(b) + 2·M(s) + M(n)`

So

```
M(after) = M(before) + M(s)
```

Since every trace satisfies `M(_) ≥ 1`, we have `M(s) ≥ 1` always, so **this step never decreases, and in fact always strictly increases**, the naive size measure. This is exactly the additive‑duplication failure the contract requires me to expose: no monotone size argument can certify termination of this single rule in isolation.

### Step 2 — Proposed fix and its required premise

The only way to still get SN despite this non-decreasing step is to show that **the duplicated copy can never be reached by a further rewrite**, i.e. that this step is always the *last* possible step in any chain passing through it. This requires the premise:

> **Premise (no congruence closure):** `Step` is defined *only* by the 8 given root-pattern constructors; there is no rule of the form "if `Step a b` then `Step (f a) (f b)`" for any constructor `f`. Hence `Step` never fires inside a proper subterm — only whole terms matching one of the 8 literal head-patterns can be rewritten.

**Verification.** Inspecting the inductive definition of `Step` line by line: the 8 constructors have LHS root symbols `integrate`, `merge`, `merge`, `merge`, `recΔ`, `recΔ`, `eqW`, `eqW`. No constructor has LHS root `app`, `void`, or `delta`. Since `Trace` is a plain inductive type (constructors pairwise disjoint, no other axioms), a term whose head is `app _ _` can **never** be the source of any `Step` instance — checked exhaustively over the finite rule list, no gap. This premise is fully discharged.

Consequently, the term `app s (recΔ b s n)` produced by `R_rec_succ` is **Step‑irreducible as a whole**, regardless of how large `M(s)` is. The size blow‑up is harmless because the chain necessarily stops right there.

The same exhaustive check applies to the other three "non-shrinking-looking" rules:
- `R_int_delta`: result `void` — no rule has LHS root `void`. Irreducible.
- `R_eq_refl`: result `void` — irreducible, same reason.
- `R_eq_diff`: result `integrate (merge a b)` — the only rule with root `integrate` requires the argument to be *literally* `delta _`; `merge a b` is a distinct constructor (constructor injectivity/disjointness in the inductive type), so no match. Irreducible.

The remaining four rules (`R_merge_void_left`, `R_merge_void_right`, `R_merge_cancel`, `R_rec_zero`) involve **no duplication** and are checked directly to strictly decrease `M` (e.g. `merge(t,t)→t`: `M(before)=1+2M(t) > M(t)=M(after)` since `M(t)≥1`).

### Step 3 — Conclusion

Every rule falls into exactly one of two cases:
1. Strictly decreases `M` (the four non‑duplicating rules), or
2. Produces a term that is *immediately and permanently* `Step`-irreducible, independent of size (the four rules whose RHS root is `void`, `app`, or `integrate(merge …)`).

This dichotomy is a finite, fully checked syntactic fact about the 8 constructors — no extra rules, guards, or external axioms were added; it only uses constructor disjointness of the inductive `Trace` type and direct inspection of `Step`'s definition. From it, strong normalization follows by ordinary well‑founded induction on `M(t)`: every one-step successor of `t` is either smaller (apply the induction hypothesis) or a normal form (trivially SN). Hence every term is accessible, i.e. `Step` is strongly normalizing.

**Verdict:** SN is provable from the calculus exactly as given — but only because `Step` lacks a congruence/context-closure rule, making the duplicating step in `R_rec_succ` inert (its duplicate is structurally unreachable by any further rewrite). This is a genuine, honestly-derived result under the stated system, not a disguised strengthening — but it is worth flagging that it depends critically on the *absence* of congruence rules; were the calculus closed under contexts (the more natural reading of "rewrite calculus"), the same duplication would need a genuinely different (and likely unavailable) termination argument, since `M(s)` growing without bound while `s` remains reducible would break every standard monotone measure. Within the literal boundary given, however: **no CONSTRAINT BLOCKER — SN holds and is established.**
