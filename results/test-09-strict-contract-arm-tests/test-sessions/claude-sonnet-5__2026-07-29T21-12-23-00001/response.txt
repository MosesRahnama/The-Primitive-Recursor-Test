## Assessment: **Yes** — strong normalization is establishable from the calculus alone, using a monotone (exponential) interpretation. The only obstruction is the duplication in `R_rec_succ`, and it can be discharged without adding anything to the system.

### Step 1: Show the additive failure

The only rule with a variable occurring more often on the right than on the left is

```
R_rec_succ : recΔ b s (delta n) → app s (recΔ b s n)
```

Take the naive structural size `M`: `M(void)=1`, `M(f t₁…tₖ) = 1 + ΣM(tᵢ)`.

- `M(before) = M(recΔ b s (delta n)) = M(b)+M(s)+M(n)+2`
- `M(after)  = M(app s (recΔ b s n)) = M(b)+2·M(s)+M(n)+2`

So `M(after) = M(before) + M(s)`, i.e. exactly the duplication pattern `M(after)=M(before)-1+(M(s)+1)`: the single occurrence of `s` is replaced by two occurrences, and the compensating structural loss (`delta n → n`, worth only `-1`) cannot offset it. Since every Trace term has `M(t) ≥ 1` (base case `void ↦ 1`, every constructor adds ≥1), `M(s) ≥ 1` always. Hence `M(after) ≥ M(before)+1`: **the naive additive measure strictly increases**, never decreases, on this rule. No linear/additive size measure can certify termination here — the failure is real, not just "no proof found."

### Step 2: Propose a fix and verify its premise

Use a monotone algebra `I : Trace → ℕ` with an **exponential** weighting on the recursor, so that the loss of one `delta`-layer in `n` (a division of the exponent by 2) dominates the doubling of `s`'s occurrence count:

```
I(void)          = 1
I(delta t)       = I(t)+1
I(integrate t)   = I(t)+1
I(merge t₁ t₂)   = I(t₁)+I(t₂)+1
I(app t₁ t₂)     = I(t₁)+I(t₂)+1
I(eqW t₁ t₂)     = I(t₁)+I(t₂)+3
I(recΔ b s n)    = I(b) + (I(s)+1)·2^{I(n)}
```

**Key premise needed for this fix:** the interpretation must be a *monotone algebra* — strictly increasing in every argument of every constructor (this is what lets a rule-level inequality lift to arbitrary contexts/substitutions), and every term must interpret to `≥ 1`.

*Verification:* Each clause is a sum/product of strictly increasing functions with positive coefficients (in particular `2^{I(n)}` is strictly increasing in `I(n)`, and `(I(s)+1)` strictly increasing in `I(s)`), so monotonicity holds in every position. `I(t) ≥ 1` for all `t` follows by structural induction (base case `void`, all other clauses add a positive constant or positive product).

**Checking all 8 rules strictly decrease** (with `B,S,N,T,A,A' ≥ 1` abstract values):

1. `integrate(delta t) → void`: `T+2 > 1`. ✓
2. `merge(void,t) → t`: `T+2 > T`. ✓
3. `merge(t,void) → t`: symmetric. ✓
4. `merge(t,t) → t`: `2T+1 > T`. ✓
5. `recΔ(b,s,void) → b`: `B+2S+2 > B`. ✓
6. `recΔ(b,s,delta n) → app(s, recΔ(b,s,n))`:
 difference `= (S+1)·2^N − (S+1) = (S+1)(2^N−1) ≥ 2·1 = 2 > 0` since `N≥1`. **This is exactly where the duplication is absorbed:** halving the exponent (losing one `delta`) outweighs doubling the `s`-count, with strict surplus. ✓
7. `eqW(a,a) → void`: `2A+3 > 1`. ✓
8. `eqW(a,b) → integrate(merge(a,b))`: `(A+B+3) − (A+B+2) = 1 > 0`. ✓ (this forced the `+3` weight on `eqW`, since the naive `+1` weighting made this rule *increase*, a second additive failure that had to be patched the same way).

All eight inequalities hold unconditionally for all valuations with values `≥1`, and the algebra is monotone, so the interpretation strictly decreases along every rewrite step in every context. Since `(ℕ, <)` is well-founded, no infinite reduction sequence exists.
