### Step 1 — Mandatory failure check (duplication in `R_rec_succ`)

The only rule that duplicates a subterm is

```
R_rec_succ : recΔ b s (delta n) → app s (recΔ b s n)
```

Here `S = s` is copied: it occurs once on the LHS and twice on the RHS (once directly, once inside the residual `recΔ b s n`).

Using the plain node‑count measure `M`,

- `M(before) = M(recΔ b s (delta n)) = 2 + |b| + |s| + |n|`
- `M(after)  = M(app s (recΔ b s n)) = 2 + 2|s| + |b| + |n|`

so indeed `M(after) = M(before) - 1 + M(S)` with `M(S) = |s|`.

Since every term has size `≥ 1` (the minimal term `void` already has size 1), `M(S) ≥ 1`, hence

```
M(after) - M(before) = M(S) - 1 ≥ 0.
```

There is **no strict drop** — size can stay equal (when `s = void`) or *increase without bound* as `s` grows. Plain size (or any measure additive/monotone purely in structural size) is **not** a valid termination measure for this rule. This is the expected obstruction: primitive‑recursion‑style duplication is never handled by a naive size argument.

Interpret terms into `(ℕ, >)`:

```
[void]        = 1
[delta](x)    = x + 1
[integrate](x)= x + 1
[merge](x,y)  = x + y + 1
[app](x,y)    = x + y + 1
[eqW](x,y)    = x + y + 3
[recΔ](b,s,n) = (n+2)(s+2) + b
```

**Key premises required by this method, stated explicitly:**

1. **Weak monotonicity**: each interpretation is (weakly, in fact strictly) increasing in every argument.
2. **Strict compatibility**: for every rule `L → R`, `[L] > [R]` holds for *all* natural‑number assignments to the metavariables (not merely for term‑realizable values).

If both hold, `>` on `ℕ` is a well‑founded order compatible with all contexts (by monotonicity), so every rewrite step strictly decreases `[t]`, and well‑foundedness of `(ℕ,>)` rules out infinite reduction sequences — i.e. strong normalization.
