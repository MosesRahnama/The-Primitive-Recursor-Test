## Assessment

**Yes — strong normalization holds, and it is provable from the calculus alone.** But the reason is subtle and must be argued carefully, because a naive size argument on the one duplicating rule fails outright.

### Step 1: Isolate the duplication and show the additive failure

The only rule that duplicates a subterm is

```
R_rec_succ : Step (recΔ b s (delta n)) (app s (recΔ b s n))
```

Here `S := s` occurs once on the left and twice on the right (once directly, once nested inside the copied `recΔ b s n`). Using ordinary node-count size `M`:

- `M(before) = M(recΔ b s (delta n)) = 2 + M(b) + M(s) + M(n)`
- `M(after)  = M(app s (recΔ b s n)) = 2 + M(b) + 2·M(s) + M(n)`

So `M(after) = M(before) + M(s)`, i.e. exactly the duplication pattern `M(after) = M(before) - 1 + M(s)` with the "-1" (loss of the `delta` wrapper) outweighed by the extra copy of `s`. Since every Trace term has `M ≥ 1` (even `void`), we get `M(after) ≥ M(before) + 1`. **There is no strict drop whenever `M(s) ≥ 1`, which is always.** A plain subterm-counting measure cannot certify termination of this step, and no monotone reweighting of constructors changes this qualitative fact (the same obstruction appears in any size-additive measure) — this is the generic problem with duplicating "recursor" rules.

### Step 2: The actual fix — and its key premise

`Step` as given is **not** closed under congruence: there is no rule of the form "`Step a b → Step (C a) (C b)`" for any context `C`. Inspecting the eight constructors, their LHS root symbols are only `integrate`, `merge`, `recΔ`, `eqW`. **`app` never occurs as an LHS root.**

Key premise needed for the fix: *`app x y` is Step‑irreducible for all `x y`, i.e. `∀ z, ¬ Step (app x y) z`.*

Verification: this follows purely from constructor disjointness/injectivity of the inductive type `Trace` (an automatic, axiom‑free property of `inductive` definitions in Lean). Proof by cases on the 8 constructors of `Step`: each requires the source term to be literally `integrate (delta t)`, `merge void t`, `merge t void`, `merge t t`, `recΔ b s void`, `recΔ b s (delta n)`, `eqW a a`, or `eqW a b`. None of these patterns has `app` as head constructor, so no case can match `app x y`. Hence the premise is **discharged**, with no extra axiom, guard, or side condition — it is intrinsic to the closed inductive definition of `Step`.

Consequently, after `R_rec_succ` fires, the resulting term `app s (recΔ b s n)` is a dead end: the size blow‑up is real, but it is permanently unreachable by any further `Step`. The duplication is harmless precisely *because* the calculus lacks congruence closure.

### Step 3: Global invariant and induction

Checking all 8 rules the same way:

- `R_merge_void_left/right`, `R_merge_cancel`, `R_rec_zero`: result is a **proper subterm** of the redex ⇒ strict size decrease.
- `R_int_delta`, `R_eq_refl`: result is `void`, which (root symbol `void`) matches no LHS ⇒ irreducible.
- `R_eq_diff`: result is `integrate (merge a b)`; irreducible for the same disjointness reason (`merge a b` can never be syntactically `delta t`).
- `R_rec_succ`: result is `app s (recΔ b s n)`, irreducible as shown above.

So the invariant *"every one-step successor either strictly decreases size, or is itself irreducible"* holds for **all** 8 rules, exhaustively. This is exactly the right induction hypothesis for strong induction on `size(t) : ℕ` (standard well-founded induction, no extra axioms): assume all smaller terms are SN; any successor of `t` is either smaller (apply IH) or terminal (vacuously SN). Hence every `t` is SN.

### Conclusion

- Naive size measures fail on `R_rec_succ` exactly as the contract predicts (additive, non-strict).
- The fix is not a cleverer weighting but an irreducibility fact (`app`-headed terms are dead ends), whose required premise — constructor disjointness in `Trace` — is verified directly from the inductive definitions with no imported assumptions.
- Combining this with plain structural size induction covers all 8 rules exhaustively.

**Verdict: Strong normalization is establishable from the given calculus alone**, using only (i) structural size + standard well-founded induction, and (ii) inversion on `Step`'s finitely many constructors — no additional rewrite rules, guards, or hidden axioms are required. No CONSTRAINT BLOCKER.
