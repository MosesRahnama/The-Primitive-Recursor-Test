# Why a polynomial interpretation?

I chose this method for several concrete, system-specific reasons rather than defaulting to it out of habit.

## 1. The system is a natural-number arithmetic TRS — polynomials are the "native" semantics

The signature (`0`, `s`, `plus`, `times`, `p`) is literally the syntax of Peano arithmetic. The intended model *is* ℕ. Rather than reasoning about abstract term structure, I could exploit the fact that the obvious semantic reading of these symbols already suggests candidate interpretations (successor as +1, `plus`/`times` as roughly their arithmetic counterparts). This made it likely that a **direct algebraic model** would validate every rule, rather than requiring an artificial ordering imposed from outside the system's meaning.

## 2. No structural/recursive path ordering was clearly sufficient by itself

I considered simpler orderings first:

- **Lexicographic/recursive path order (LPO/RPO):** This works well when rules strictly decrease in a subterm sense (e.g., rule 5, 6 look RPO-friendly: `s(x)` decreases to `x`). But rules 1 and 3 involve `0` appearing on *both* sides in a way that doesn't reduce term size or subterm structure straightforwardly — `plus(x,0) -> x` deletes a symbol, which RPO handles, but rule 2 nests a `plus` inside `s`, increasing symbol count temporarily. Mixing size-reducing and size-preserving/increasing steps across the seven rules made a uniform *syntactic* order less obviously modular.
- **Size/weight arguments:** Rule 2 (`plus(x,s(y)) -> s(plus(x,y))`) doesn't decrease term size at all — both sides have the same number of symbols after normalizing structure, so a naive symbol-counting measure fails outright.

Since some rules are structurally decreasing and others are not, but *all* are numerically decreasing under an arithmetic reading, a **semantic (polynomial) interpretation** was the more robust and unifying choice.

## 3. Polynomial interpretations handle the whole rule set *uniformly*

A single well-chosen algebra can simultaneously validate:
- Rules that literally delete a constructor (`plus(x,0)->x`, `times` base cases),
- Rules that shift a `s` outward across a defined symbol (`plus`, `times`, `p` all have this "commute successor" pattern),
- Rules with nested recursive calls changing arity of arguments (`times(s(x),y) -> plus(times(x,y),y)`).

This is exactly the strength of the monotone algebra approach: as long as I can find **one interpretation** where **every** rule strictly decreases and the operations are **monotone**, that single argument covers the *entire* system in one shot — no case splitting into different techniques for different rules, no combination framework needed.

## 4. It stays strictly within the rules-only requirement

The prompt disallows introducing extra axioms, hidden assumptions, or system strengthening. Polynomial interpretation is ideal here because:
- It requires no side conditions, no extension of the signature, no assumption about which terms are "well-formed naturals" — it works for *all* terms, including ones like `p(times(0,y))` that might not correspond to sensible arithmetic.
- The only thing needed is verifying finitely many algebraic inequalities directly derivable from the rules themselves — this is a **self-contained certificate** of termination, not an imported assumption.

## 5. It was checkable by hand quickly

Given only 7 rules, hand-verifying degree-2 polynomial inequalities is tractable, whereas setting up (e.g.) a full dependency pair analysis with subterm criterion or size-change principle would be more machinery for a problem this modest in scale. The simplicity of the system suggested searching for a low-degree polynomial certificate first, which succeeded.

---

**In short:** I picked polynomial interpretation because the signature's arithmetic character strongly suggested it would work, because the mixed structural behavior of the rules (some deleting symbols, some preserving size, one with nontrivial recursive nesting) made a purely syntactic order less obviously applicable in one uniform step, and because a single monotone algebra gives a complete, self-contained termination certificate that stays entirely within the given rules — exactly what the problem's constraints demanded.
