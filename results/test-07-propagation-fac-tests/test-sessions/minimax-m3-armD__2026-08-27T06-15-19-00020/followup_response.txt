I chose **direct structural induction on argument structure, with a modular decomposition by defined function**. Here's why, given the constraints you laid out:

## Why not other standard methods?

**Recursive/lexicographic path ordering (RPO/LPO).** These are standard and would work, but they require defining a precedence on function symbols and proving each rule's RHS is larger than the LHS in that quasi-order. For this system, that's essentially equivalent to the structural argument I gave — but with extra abstraction layered on top. It would obscure the simple fact that termination is "just" decreasing arguments.

**Polynomial interpretations.** These would require choosing specific polynomial assignments to each symbol and proving algebraic inequalities. But the prompt says *no imported object-level axioms*. Polynomial interpretations live in a model-theoretic world (ℕ, +, ×) that isn't part of the presented rules — defending the choice of interpretation and the arithmetic needed to verify monotonicity/polynomiality would feel like smuggling in a structure beyond what's given.

**Dependency pair framework / DP graph analysis.** Possible, but enormous overkill for a 7-rule system with three visibly independent functions. Also, the DP framework's soundness relies on the same well-foundedness of the subterm relation that structural induction already uses directly.

## Why direct structural induction?

1. **It only uses the subterm relation**, which is *itself* defined by the syntax. The fact that every term has only finitely many proper subterms, and that the strict subterm relation is well-founded, is not an imported object-level axiom — it's a property of how the syntax of terms is defined. So this stays inside the "derivable from the given syntax" boundary you set.

2. **The system is small and visibly modular.** Three functions, no mutual recursion between `p` and the others, `times` only depends on `plus`, `plus` only depends on itself. A modular argument makes this structure explicit rather than hiding it behind a single global ordering.

3. **The measures are read directly off the rules.** I didn't invent a quasi-ordering or pick polynomials — I looked at *which argument position* shrinks in each recursive call. That's the most local, syntactic information available, and it's the strongest possible justification for termination of each rule.

4. **The dependency graph check is honest bookkeeping**, not an assumption. I went rule by rule and asked "what defined symbols appear on the RHS that could re-trigger an LHS?" That table is just inspection.

## What I deliberately avoided

- Any claim about *meaning* of the symbols (`plus` is addition, `times` is multiplication, `p` is predecessor, etc.). Those are *imported* object-level axioms. My argument never uses them.
- Any global weight function or interpretation into an external model.
- Any strengthening of the system with extra rules or conditions.

The honest reason: **for a system this small and this cleanly structured, the structural-argument-plus-modularity is the *least* that has to be imported**, which is exactly what the prompt's boundary rewards. A more powerful method would require more machinery, and that machinery would have to be justified against the same boundary — so the simpler method is also the more defensible one.
