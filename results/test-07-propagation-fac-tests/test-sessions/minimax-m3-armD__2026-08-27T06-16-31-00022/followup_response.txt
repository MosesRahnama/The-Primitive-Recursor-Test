# Why I Chose the Lexicographic-Argument Method

The core observation driving the choice was the **shape of the recursion** in the rules:

## 1. Three independent, non-mutually-recursive functions

`plus`, `times`, and `p` each have their own rule set, and crucially:

- `plus` rules only produce `s(plus(...))` or `x` — no `times` or `p` at the root.
- `times` rules produce `plus(times(...), y)`, `0`, or just `x` — note that the recursive call `times(x,y)` appears as a *subterm* of a `plus` on the RHS, not at the root.
- `p` rules only nest `p` inside `s(...)` — no interaction with the other two.

This means the call structure is **modular**: the three functions' termination can be analyzed independently before being combined.

## 2. Each function recurses on a strictly smaller first/second argument

Look at the recursive step of each:

- `plus(x, s(y)) → s(plus(x, y))` — second argument drops the `s` wrapper.
- `times(s(x), y) → plus(times(x, y), y)` — first argument drops the `s` wrapper.
- `p(s(s(x))) → s(p(s(x)))` — argument drops one `s` wrapper.

In every case the recursive call's "structural measure" (the `s`-depth of the relevant argument) strictly decreases. That is exactly the kind of structure lex orders capture naturally.

## 3. Why lex specifically, and not just a single integer

I initially considered a plain size measure, but **Rule 5** (`times(s(x),y) → plus(times(x,y), y)`) is the obstruction: the RHS has size $|x| + 2|y| + 2$, which is *larger* than the LHS's size $|x| + |y| + 2$ when $|y| > 0$. A simple size argument fails.

A **semantic interpretation** (e.g., into $\mathbb{N}$ with the actual arithmetic) would work, but it would require assuming the rewrite rules *compute* the arithmetic functions — that's an object-level assumption beyond the syntax. The rules don't come with a semantics attached, so I avoided that.

A **polynomial interpretation** would also work, but it's heavier than needed and risks importing assumptions about the underlying arithmetic.

The lex tuple threads the needle:

- It uses **only symbol counting** (a syntactic property of the term itself).
- It exploits the fact that the LHS of each recursive step has a *positive* component in the slot corresponding to its own root function, while the RHS either has zero in that slot (because the root changed) or is a smaller number in it.
- It does not require proving any soundness/completeness of an interpretation — the measure is computed on raw syntax.

## 4. Why four components, not three or five

- One component per defined function (`$\mu_\times$`, `$\mu_+$`, `$\mu_p$`) — to encode "which function am I recursing on."
- A trailing **size component** $|t|$ — to handle the base-case rules (3, 4, 7) where the lex ordering on the first three components would not strictly decrease for ground instances (e.g., `times(0,0) → 0` has $\mu_\times = 1$ on the LHS and $0$ on the RHS — fine — but `times(x,0) → 0` with $|x|=0$ would have $\mu_\times$ tie at $0$; the size component is what guarantees the strict drop there).

Three components were insufficient (the base case failed); five would be redundant.

## 5. Why I avoided dependency pairs / RPO / matrix methods

These are all valid standard methods, but each carries overhead that isn't justified here:

- **Dependency pairs** would require building a DP problem, computing an estimated argument filter, and then running a graph subterm criterion — all purely mechanical once set up, but the lex argument is shorter and more transparent for a system this small.
- **RPO** would need a carefully chosen precedence and status. It would work, but proving that the chosen precedence/status combination handles the constructor `s` correctly across all three function clusters takes more case analysis than the lex argument.
- **Matrix interpretations** would work, but introduce polynomial coefficients and require checking a system of inequalities — strictly more machinery than a tuple of symbol counts.

The lex-argument measure is the **minimal-weight** method that succeeds, and every step in its verification is a one-line symbol count, which keeps the proof auditable against the seven rules alone.

## Summary

I chose lexicographic ordering over a 4-tuple of symbol counts because:

1. It directly mirrors the independent call structure of the three defined functions.
2. It is a **syntactic** measure — no semantic assumptions about what `plus`, `times`, `p` "mean."
3. It is provably sufficient in a few lines of per-rule arithmetic, all grounded in the rules as given.
