## Verdict: **Terminating** — provable by a standard Lexicographic Path Order (LPO)

This system is exactly the classical "Peano arithmetic" TRS (recursive definition of `plus` by cases on the second argument via `s`/`0`, and `times` reduced to iterated `plus`). Termination can be established with a **Lexicographic Path Order** using the precedence

$$
\texttt{times} \;\succ\; \texttt{plus} \;\succ\; \texttt{s} \;\succ\; \texttt{0}
$$

with left-to-right lexicographic status on both `plus` and `times`. No extra rules, guards, or side conditions are introduced — this is a pure syntactic ordering derived from the signature, and LPO-compatibility is checked rule by rule using only the *subterm property* and the *precedence/lexicographic comparison* clauses of the LPO definition.

### Rule-by-rule verification

**1. `times(x,0) → 0`**
`0` is an immediate subterm of `times(x,0)`. By the subterm property, `times(x,0) >_lpo 0`. ✔

**2. `times(x,s(y)) → plus(times(x,y), x)`**
Since `times ≻ plus`, it suffices that `times(x,s(y))` dominates *both* arguments of the right-hand side:
- `times(x,s(y)) >_lpo x`: `x` is an immediate argument (subterm property).
- `times(x,s(y)) >_lpo times(x,y)`: same head `times`; compare argument tuples lexicographically: first components equal (`x = x`); second components: `s(y) >_lpo y` by the subterm property. All side conditions (`times(x,s(y)) >_lpo x`, `>_lpo y`) hold via subterm/transitivity.
Hence `times(x,s(y)) >_lpo plus(times(x,y),x)`. ✔

**3. `plus(x,0) → x`**
`x` is an immediate argument of `plus(x,0)`; subterm property gives `plus(x,0) >_lpo x`. ✔

**4. `plus(0,x) → x`**
Symmetric to rule 3: `x` is an immediate argument. ✔

**5. `plus(x,s(y)) → s(plus(x,y))`**
Since `plus ≻ s`, it suffices that `plus(x,s(y)) >_lpo plus(x,y)` (the sole argument of the right side).
Same head `plus`; lexicographic comparison: first components equal (`x=x`); second components `s(y) >_lpo y` (subterm property). The needed side conditions `plus(x,s(y)) >_lpo x` and `>_lpo y` follow from the subterm property and transitivity through `s(y)`.
Hence `plus(x,s(y)) >_lpo plus(x,y)`, and by the precedence clause `plus(x,s(y)) >_lpo s(plus(x,y))`. ✔

**6. `plus(s(x),y) → s(plus(x,y))`**
Same argument as rule 5, using the first argument position instead: `plus(s(x),y) >_lpo plus(x,y)` because `s(x) >_lpo x` (subterm property) while the second components are literally equal (`y = y`), and the extra side conditions again reduce to subterm/transitivity facts. By precedence `plus ≻ s`, this yields `plus(s(x),y) >_lpo s(plus(x,y))`. ✔

### Conclusion

Every rule's left-hand side strictly dominates its right-hand side in the LPO induced by the precedence `times ≻ plus ≻ s ≻ 0` with left-to-right lexicographic status. Since LPO is a well-founded order that is closed under substitutions and contexts (standard properties of any path order built purely from the signature), this establishes termination of the whole rewrite system using only the given rules and signature — no additional axioms, guards, or structural assumptions about arithmetic (e.g., no imported commutativity/associativity of `plus`) were required.
