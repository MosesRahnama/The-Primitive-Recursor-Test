**Verdict: yes.** The system is terminating as presented. No arithmetic axioms about `0`, `s`, `p`, `plus`, `times`, or `fac` are needed; the claim follows from the syntax and the listed rewrite rules.

The only superficially difficult rule is

```text
fac(s(x)) -> times(fac(p(s(x))), s(x))
```

because its recursive `fac` call is not on a syntactically smaller argument. Nevertheless, the `p` rules ensure that this cannot produce an infinite recursive `fac` lineage.

## 1. The non-`fac` subsystem terminates

Consider the subsystem \(B\) consisting of all rules except the `fac` rule:

```text
plus(x, 0) -> x
plus(x, s(y)) -> s(plus(x, y))
times(0, y) -> 0
times(x, 0) -> 0
times(s(x), y) -> plus(times(x, y), y)
p(s(s(x))) -> s(p(s(x)))
p(s(0)) -> 0
```

It is oriented by a standard recursive path ordering, for example with precedence satisfying

```text
times > plus > s
p > s
```

with `0` minimal; `fac` may be treated merely as an uninterpreted constructor for this part of the proof.

The relevant decreases are:

```text
plus(x, s(y)) -> s(plus(x, y))
```

The recursive `plus` call has second argument `y`, a proper subterm of `s(y)`.

```text
times(s(x), y) -> plus(times(x, y), y)
```

The outer root changes from `times` to lower-precedence `plus`, and the recursive `times(x,y)` call has first argument `x`, a proper subterm of `s(x)`.

```text
p(s(s(x))) -> s(p(s(x)))
```

The recursive `p` call has argument `s(x)`, a proper subterm of `s(s(x))`.

The remaining base rules erase a root symbol or replace it by a proper subterm/constant. Thus \(B\) terminates.

This statement remains valid when arbitrary terms, including terms headed by `fac`, occur as arguments: the proof concerns the roots rewritten by \(B\), and treats other-headed subterms as ordinary subterms.

## 2. What the `fac` rule can do

A `fac` redex has the form

```text
fac(s(u)).
```

Its contraction is

```text
fac(s(u))
  -> times(fac(p(s(u))), s(u)).
```

The only new recursive `fac` occurrence is

```text
fac(p(s(u))).
```

That occurrence is not immediately another `fac` redex, since its argument has root `p`, not root `s`.

For it to become a `fac` redex again, the `p(s(u))` argument must be rewritten until it has the form `s(v)`. The only rule capable of changing the root of such a `p` term into `s` is

```text
p(s(s(x))) -> s(p(s(x))).
```

That rule removes one successor from the argument of the active `p`:

```text
p(s(s(x)))  ->  s(p(s(x))).
```

The other `p` rule stops the computation:

```text
p(s(0)) -> 0.
```

If the term following the outer `s` is not itself headed by `s`, then no `p` root rule applies, and the recursive `fac` call is stuck:

```text
fac(p(s(u)))
```

cannot match `fac(s(v))`.

Hence a recursive `fac` continuation is possible only by consuming successor structure through the displayed `p` rule. It cannot regenerate an unlimited supply of successor structure at the same recursive `fac` level.

## 3. Finite-descent argument for `fac`

A standard finite-descent lemma applies here.

Take an occurrence

```text
fac(s(u)).
```

All `fac` occurrences already inside `u` are strictly nested below this occurrence. By induction on nesting depth of `fac`, those inner occurrences terminate. The subsystem \(B\) also terminates, as established above.

Now follow one recursive lineage created by the outer `fac` occurrence. Every time that lineage can make another root-level `fac` contraction, the intervening computation must expose an outer `s` from a term of the form `p(s(...))`. The only way to do that is through

```text
p(s(s(x))) -> s(p(s(x))),
```

which advances the active `p` one successor inward. Eventually one of the following happens:

1. the successor spine ends in `0`, yielding

   ```text
   p(s(0)) -> 0;
   ```

2. the successor spine ends in a term not headed by `s`, so the active `p` is no longer reducible at its root;

3. reductions inside the argument finish, because they belong to the already terminating lower-nesting part or to \(B\).

Thus every individual recursive `fac` lineage is finite.

The right-hand side of the `fac` rule has only one recursive `fac` occurrence:

```text
times(fac(p(s(x))), s(x)).
```

Although `x` is duplicated indirectly through this right-hand side, this creates only finitely many terminating lower-nesting computations along a finite lineage. The terminating `times`/`plus`/`p` subsystem cannot turn this finite branching into an infinite rewrite sequence.

Therefore `fac` cannot introduce an infinite reduction.

## 4. Every rule is covered

| Rule family | Reason for termination |
|---|---|
| `plus(x,0) -> x` | Erases `plus`. |
| `plus(x,s(y)) -> s(plus(x,y))` | Recursive second argument decreases from `s(y)` to `y`. |
| `times(0,y) -> 0` | Erases `times`. |
| `times(x,0) -> 0` | Erases `times`. |
| `times(s(x),y) -> plus(times(x,y),y)` | Recursive `times` argument decreases from `s(x)` to `x`; outer root goes to lower-precedence `plus`. |
| `p(s(s(x))) -> s(p(s(x)))` | Recursive `p` argument decreases from `s(s(x))` to `s(x)`. |
| `p(s(0)) -> 0` | Erases `p`. |
| `fac(s(x)) -> times(fac(p(s(x))),s(x))` | A later recursive `fac` step requires `p` to expose an `s`; the only such rule consumes successor structure, and the `p` process eventually stops. |

Accordingly, the complete rewrite system is terminating on all first-order terms over the displayed signature.
