I chose the **Dependency Pair (DP) framework** because standard global termination techniques—such as Recursive Path Ordering (RPO), Knuth-Bendix Ordering (KBO), and standard polynomial interpretations—provably fail on this specific rewrite system. 

The DP framework was necessary to bypass the structural conflicts inherent in the rules. Here is the detailed breakdown of why the standard methods fail and why the DP framework succeeds.

### 1. Why Knuth-Bendix Ordering (KBO) Fails
KBO requires a strict variable condition: for every rule $l \to r$, every variable must appear at least as many times in $l$ as it does in $r$. 
* Look at **Rule 8**: `fac(s(x)) -> times(fac(p(s(x))), s(x))`. 
* The variable `x` appears **once** on the left-hand side, but **twice** on the right-hand side (inside `p(s(x))` and `s(x)`). 
Because of this variable duplication, KBO is immediately disqualified.

### 2. Why Recursive Path Ordering (RPO / LPO) Fails
Simplification orderings like RPO rely on a strict precedence relation among function symbols (e.g., $f > g$). This system creates an unresolvable precedence contradiction:
* To orient **Rule 6** (`p(s(s(x))) -> s(p(s(x)))`), the root symbol of the LHS (`p`) must be strictly greater than the root symbol of the RHS (`s`). Thus, RPO requires **`p > s`**.
* To orient **Rule 8** (`fac(s(x)) -> times(fac(p(s(x))), s(x))`), assuming `fac > times`, RPO requires the arguments to decrease: `s(x)` must be strictly greater than `p(s(x))`. For this to hold, the root of `s(x)` must be greater than the root of `p(s(x))`. Thus, RPO requires **`s > p`**.
The contradiction (`p > s` and `s > p`) makes it impossible to find a valid precedence for RPO or LPO.

### 3. Why Standard Polynomial Interpretations Fail
Standard polynomial interpretations over the natural numbers $\mathbb{N}$ require polynomials with non-negative coefficients. Let's see what the rules force upon the predecessor function `p`:
* Let $s(x) = x + 1$. 
* **Rule 6** (`p(s(s(x))) -> s(p(s(x)))`) translates to the recurrence: $p(x + 2) = p(x + 1) + 1$. The only polynomial solution to this is $p(x) = x + c$ for some constant $c$.
* **Rule 7** (`p(s(0)) -> 0`) translates to $p(1) = 0$. Substituting this into our solution gives $1 + c = 0$, meaning $c = -1$.
Therefore, the rules force $p(x) = x - 1$. Because this polynomial can yield negative numbers (e.g., $p(0) = -1$), it violates the non-negativity requirement of standard polynomial interpretations over $\mathbb{N}$.

---

### Why the Dependency Pair Framework Succeeds
The DP framework overcomes all of these roadblocks because it **does not require a single global reduction ordering** to orient all rules. Instead, it offers three massive advantages for this specific system:

1. **Isolation of Recursive Calls:** DPs separate the "recursive calls" from the "internal reductions." We don't need to prove that `fac(s(x))` is strictly greater than the massive RHS `times(fac(p(s(x))), s(x))`. We only need to prove that the recursive call `fac#(s(x)) -> fac#(p(s(x)))` decreases. This completely sidesteps the RPO precedence clash and the KBO variable duplication issue.
2. **Modularity via SCCs:** The framework breaks the termination proof into Strongly Connected Components (SCCs). This means I didn't have to force the `fac` cycle to use the same mathematical logic as the `plus` or `times` cycles. 
3. **Mixing Proof Techniques:** Because the proof is modular, I could use a trivial **subterm ordering** to instantly terminate the `plus`, `times`, and `p` SCCs, and reserve a **custom semantic evaluation function** (the invariant $E$) exclusively for the `fac` SCC. The semantic function easily handles the $p(x) = x - 1$ behavior by using $\max(0, x-1)$, which is perfectly valid in a localized semantic argument but illegal in a global standard polynomial interpretation. 

In short, the Dependency Pair framework was chosen because it is the only standard method capable of untangling the mutual nesting, variable duplication, and precedence cycles present in this arithmetic rewrite system.
