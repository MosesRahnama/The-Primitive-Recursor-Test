In a standard simplification ordering (like RPO), we need the LHS to be strictly greater than the RHS. But `fac(s(x))` has root `fac`, while the RHS has root `times`. If `fac > times`, then `fac(s(x)) > times(...)`. But wait, `times` is also a defined symbol, and in rule 5: `times(s(x), y) -> plus(times(x, y), y)`. Here `times` is on the LHS and `plus` is on the RHS (root), with `times` nested inside `plus`. So we would need `times > plus`.
  - In rule 2: `plus(x, s(y)) -> s(plus(x, y))`. `plus` is on LHS, `s` on RHS root, `plus` nested. So `plus > s`.
  - This means we need a precedence `fac > times > plus > s`.
  - Let's check RPO with this precedence.
    - Rule 8: `fac(s(x)) > times(fac(p(s(x))), s(x))`. Since `fac > times`, we just need `fac(s(x)) > fac(p(s(x)))` and `fac(s(x)) > s(x)`. The latter is true by subterm. The former requires `s(x) > p(s(x))`. But `p` is a defined symbol. If `s > p`, then `s(x) > p(s(x))` holds.
    - Let's check Rule 6: `p(s(s(x))) -> s(p(s(x)))`. Here LHS root is `p`, RHS root is `s`. But we just said we need `s > p` for Rule 8! If `s > p`, then RPO cannot orient `p(...) -> s(...)` because the root of LHS (`p`) is smaller than the root of RHS (`s`).
  - So **RPO/LPO and standard Knuth-Bendix Order (KBO) fail** because of the conflicting precedence requirements between `p` and `s` (or more generally, the mutual nesting of defined symbols and the predecessor function). Specifically, `fac` calls `times` and `p`, `times` calls `plus`, and `p` produces `s`. This creates a cycle in the required precedence or weight assignments if we try to use simple reduction orders.
- **Semantic interpretations (like polynomial interpretations)**:
  - Rule 6: `p(s(s(x))) -> s(p(s(x)))`. If we use polynomials, `p(s(s(x))) = p(x+2)`. `s(p(s(x))) = p(x+1) + 1`. So `p(x+2) = p(x+1) + 1`, which implies `p(x) = x + c`.

We could use $\max(0, x-1)$, which leads to weakly monotonic algebras or matrix interpretations, but standard polynomial interpretations over $\mathbb{N}$ fail.
- **Dependency Pairs (DP)**:
  - The DP framework elegantly sidesteps the need for a single global reduction ordering that orients all rules. Instead, it only requires finding a well-founded ordering that orients the *dependency pairs* (which capture the recursive calls) and the *usable rules* (which capture the evaluations that can happen between recursive calls).
  - By isolating the recursive calls, we can see that the actual recursive structure is:
    - `plus` recurses on the second argument.
    - `times` recurses on the first argument.
    - `p` recurses on the argument (stripping an `s`).
    - `fac` recurses on the result of `p(s(x))`.
  - The DP framework allows us to break the termination proof into Strongly Connected Components (SCCs) of the dependency graph. This modularization means we don't have to find one single ordering for the whole system. We can use a simple subterm-based argument (or projection) for `plus`, `times`, and `p`, and a more specialized semantic argument (like the evaluation function $E$) just for `fac`.
