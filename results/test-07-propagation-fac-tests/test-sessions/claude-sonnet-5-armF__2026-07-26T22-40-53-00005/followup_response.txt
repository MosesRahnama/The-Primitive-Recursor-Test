# Why LPO

I chose the **Lexicographic Path Order** for a few concrete reasons tied to the specific shape of this system, rather than picking a heavier or less appropriate tool.

**1. The recursion pattern is a classic "recursive definition with an accumulator" scheme.**
Rules like `times(x,s(y)) -> plus(times(x,y), x)` and `plus(x,s(y)) -> s(plus(x,y))` / `plus(s(x),y) -> s(plus(x,y))` are textbook examples of *primitive recursion*: the head symbol calls a "smaller" function (or itself) on a subterm obtained by stripping one `s`. This is exactly the pattern LPO is designed to handle — it was invented (Dershowitz) precisely to automate termination proofs for this style of recursive/nested rule set, without needing a hand-crafted measure function.

**2. All the "shrinking" happens on subterms, which is LPO's core strength.**
Every right-hand side is built either from (a) actual subterms of the left-hand side (`plus(x,0)->x`, `plus(0,x)->x`), or (b) recursive calls with one argument replaced by a proper subterm (`s(y)->y`, `s(x)->x`). LPO's subterm property and its recursive "compare arguments if heads are equal" rule capture *exactly* this without any arithmetic encoding — I didn't need to invent numeric weights.

**3. A precedence alone suffices — no need for polynomial interpretations.**
Because `times` always reduces to something headed by `plus` or `0`, and `plus` always reduces to something headed by `s`, `0`, or recursive `plus`-terms, a simple **strict precedence** `times > plus > s > 0` cleanly separates the "levels" of the recursion. This is a strong signal that LPO (which is driven by precedence + subterm comparisons) is the natural fit, as opposed to methods like polynomial/interpretation orderings, which would require guessing numeric weights and are more work to justify from "rules alone."

**4. It stays strictly within the allowed boundary.**
LPO is a syntactic, mechanically checkable order defined purely from the signature and term structure of the rules — it doesn't require introducing new rewrite rules, side conditions, or semantic assumptions about what `0`, `s`, `plus`, `times` "mean" arithmetically. This matches the constraint of using **only** what's derivable from the given syntax and rules, since I only needed to declare a precedence on the four symbols already present.

**5. It succeeded on every rule with a single, uniform argument.**
I checked all 6 rules and found that one precedence (`times > plus > s > 0`) with lexicographic status on the binary symbols orients every rule `l >_lpo r`. The uniformity of the pattern (multiplicative rule reduces to a `plus`-headed term dominated via subterm + recursive-call arguments; additive rules reduce via subterm property or via the `s`-stripping recursion) meant I didn't need to mix methods (e.g., no need for a separate measure for `times` vs. `plus`) — one ordering handled the whole system in a single uniform proof, which is the cleanest and most defensible route to a full termination certificate.

**In short:** the rules exhibit a nested "peel off a constructor `s`, recurse, wrap in a smaller-priority symbol" pattern, and LPO is the standard, minimal-assumption ordering precisely tailored to certify termination of that pattern without smuggling in extra structure.
