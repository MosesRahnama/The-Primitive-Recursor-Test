## Why I chose polynomial/matrix interpretations

I picked this method for several concrete, system-specific reasons:

**1. The obvious naive approaches fail, ruling out simpler certificates.**
My first instinct for a rule like `p(s(s(x))) -> s(p(s(x)))` would be to check simplification orderings (RPO, LPO, KBO) or a plain subterm/size measure. But a symbol-counting argument gives a *tie* (both sides have the same number of symbols when `p` is counted uniformly), so no naive size argument works, and this signals that any termination proof needs an interpretation where `p` is not "weight-neutral" — i.e., something that can amplify the argument of `p` disproportionately compared to the `s` wrapped around it. That immediately points toward **weighted/polynomial interpretations** rather than syntactic orderings, since polynomial interpretations let me freely choose coefficients (e.g., interpreting `p` with a multiplicative factor `> 1`) to break exactly this kind of tie.

**2. The system is quasi-standard Peano arithmetic — a class with known compatible interpretations.**
`plus`, `times`, and `p` are the textbook recursive definitions of addition, multiplication, and predecessor over successor-based naturals. This is a very well-studied benchmark class (it's essentially the standard TRS for Peano arithmetic used throughout the term-rewriting literature, e.g., in AProVE/TTT2 termination competitions). Polynomial interpretations are the classical, first-choice technique for exactly this style of system because:
   - the rules are simple (shallow recursion, one recursive call per rule, no complex nesting like nested recursion or higher-order use of accumulators)
   - the recursion structure is "structurally decreasing" (each recursive call peels one constructor), which polynomial interpretations naturally capture via monotonicity + strict decrease conditions on each rule.

**3. Compatibility can be checked compositionally, rule-by-rule.**
Since polynomial interpretations only require checking a per-rule inequality `[lhs] > [rhs]` (or `≥` for non-strict rules, with at least one strict decrease per cycle), I could reason about each defined symbol's rules mostly independently (`plus`, then `times` reusing `plus`'s interpretation monotonically, then `p`, then `fac` reusing `p` and `times`). This modularity matches how the system itself is layered (`fac` depends on `times`/`p`, `times` depends on `plus`), so the proof structure mirrors the definitional hierarchy of the rules — making it easy to build the certificate incrementally rather than needing a global, monolithic ordering.

**4. It's a self-contained, purely syntactic/semantic criterion.**
The question asked specifically whether termination is derivable *from the rules alone*, without extra imported axioms. Polynomial interpretation is exactly such a technique: it only requires exhibiting a well-founded, monotone algebra over the naturals (or another ordered domain) under which each rule's left side maps to something strictly greater than the right side. This doesn't presuppose any extra background theory beyond arithmetic over ℕ (or matrices/ℕ), so it satisfies the "no imported structural axioms" constraint cleanly, unlike, say, invoking a semantic argument based on the *intended* meaning of `plus`/`times`/`fac` as arithmetic operations.

**5. It's the minimal technique sufficient for this instance.**
I didn't reach for heavier machinery (dependency pairs, semantic labeling, matrix interpretations of higher dimension, or recursive path orders with status) because the system's recursion patterns are shallow enough that plain polynomial interpretations suffice — using DP framework or matrix interpretations would be over-engineering for a problem this size, though they'd also work. I chose the simplest technique that plausibly closes the proof for every rule in the system.
