## Verdict: **Terminating**

Termination can be established directly from the given rules using the **Recursive Path Ordering (RPO)** with the following precedence on function symbols:

$$\text{times} > \text{plus} > p > s > 0$$

and left-to-right lexicographic status for all function symbols.

### Rule-by-rule verification

**Rule 1:** `plus(x, 0) -> x`
The RHS is the variable `x`, which is a proper subterm of the LHS. ✓

**Rule 2:** `plus(x, s(y)) -> s(plus(x, y))`
- Root `plus > s` in precedence.
- Must show LHS `>_rpo` the argument of `s` on the RHS, i.e., `plus(x, y)`.
  - Same root `plus`; compare arguments lexicographically: first components are equal (`x = x`), second component `s(y) >_rpo y` (since `y` is a subterm of `s(y)`). ✓
- Must also show LHS `>_rpo y` (the argument of `s`); `y` is a subterm of `s(y)`, which is a subterm of the LHS. ✓

**Rule 3:** `times(0, y) -> 0`
- Root `times > 0` in precedence. The constant `0` has no arguments to check. ✓

**Rule 4:** `times(x, 0) -> 0`
- Root `times > 0` in precedence. Vacuously satisfied. ✓

**Rule 5:** `times(s(x), y) -> plus(times(x, y), y)`
- Root `times > plus` in precedence.
- Must show LHS `>_rpo` each argument of `plus`:
  - `times(x, y)`: same root `times`; lexicographic comparison of arguments gives `s(x) >_rpo x` (subterm), so `(s(x), y) >_lex (x, y)`. ✓
  - `y`: is a subterm of the LHS. ✓

**Rule 6:** `p(s(s(x))) -> s(p(s(x)))`
- Root `p > s` in precedence.
- Must show LHS `>_rpo p(s(x))` (the argument of `s` on the RHS).
  - Same root `p`; compare arguments: `s(s(x)) >_rpo s(x)` because same root `s` and `s(x) >_rpo x` (subterm). ✓
- Must also show LHS `>_rpo s(x)` (argument of `p(s(x))`); `s(x)` is a subterm of `s(s(x))`, which is a direct subterm of the LHS, and `s(s(x)) >_rpo s(x)`, so LHS `>_rpo s(x)` by the subterm property. ✓

**Rule 7:** `p(s(0)) -> 0`
- Root `p > 0` in precedence. The constant `0` has no arguments. ✓
