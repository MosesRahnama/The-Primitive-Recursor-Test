## Verdict: **Termination holds, and can be proved from the rules alone** — but only via the Dependency Pair method, not by a single simplification order (RPO/KBO) or a single monolithic polynomial interpretation.

### Why a naive simplification order fails (diagnostic remark)

This system is in fact the classical example (Arts–Giesl) showing that plain simplification orderings cannot certify termination here. The obstruction is rule 8 together with rules 6–7:

```
p(s(s(x))) -> s(p(s(x)))      (6)
p(s(0))    -> 0                (7)
fac(s(x))  -> times(fac(p(s(x))), s(x))   (8)
```

Any reduction order compatible with rewriting must be monotone w.r.t. subterms, but `p(s(x))` is **not** a subterm of `s(x)` — it is a syntactically larger term that only *semantically* equals a smaller value once rules 6–7 have fired. No single monotone algebra can simultaneously make `p` "expand" enough to strictly shrink rule 6 (recursion on nested `s`'s under `p`) and "shrink" enough to justify the recursive call in rule 8. This is exactly why the Dependency Pair (DP) framework — not a bare reduction order — is needed.

### Dependency Pairs

Defined symbols: `plus, times, p, fac`. Building DPs from each rule (marking defined roots with capitals):

- (1) `plus(x,0)->x` : no DP (variable RHS).
- (2) `plus(x,s(y))->s(plus(x,y))` : **DP1** `PLUS(x,s(y)) -> PLUS(x,y)`
- (3),(4): no DP (RHS = `0`).
- (5) `times(s(x),y)->plus(times(x,y),y)`: **DP2** `TIMES(s(x),y)->PLUS(times(x,y),y)`, **DP3** `TIMES(s(x),y)->TIMES(x,y)`
- (6) `p(s(s(x)))->s(p(s(x)))`: **DP4** `P(s(s(x))) -> P(s(x))`
- (7): no DP.
- (8) `fac(s(x))->times(fac(p(s(x))),s(x))`: **DP5** `FAC(s(x))->TIMES(fac(p(s(x))),s(x))`, **DP6** `FAC(s(x))->FAC(p(s(x)))`, **DP7** `FAC(s(x))->P(s(x))`

### Dependency graph / SCCs

Using the standard (CAP-based) estimation, the non‑trivial cycles are exactly the self‑loops:

`{DP1}`, `{DP3}`, `{DP4}`, `{DP6}`.

`DP2, DP5, DP7` are one‑way connectors (`FAC`‑component → `TIMES`‑component → `PLUS`‑component; `FAC`‑component → `P`‑component) and create no larger cycle, since `PLUS`'s and `P`'s DPs never call back into `TIMES`/`FAC`. By the DP soundness theorem, it suffices to kill each SCC separately (different SCCs may use different reduction pairs).

### Killing each SCC

**{DP1}** (usable rules: 1,2). Interpretation `[0]=0,[s](n)=n+1,[plus](x,y)=x+y`: rule1 gives `x≥x`, rule2 gives `x+y+1≥x+y+1` (weak, ✓). With `[PLUS](x,y)=y`: `y+1 > y` — strict. ✔ (covers rules 1,2)

**{DP3}** (usable rules: 1,2,3,4,5). Same `[plus],[s],[0]`, plus `[times](x,y)=xy`: rule3 `0≥0`, rule4 `0≥0`, rule5 `xy+y ≥ xy+y` (weak, ✓). With `[TIMES](x,y)=x`: `x+1 > x` — strict. ✔ (covers rules 1–5 as usable, DP3 strict)

**{DP4}** (usable rules: 6,7). Interpretation `[0]=0,[s](n)=n+1,[p](n)=n`: rule6 gives `x+2 ≥ x+2` (weak equality ✓), rule7 gives `1≥0` ✔. With `[P](n)=n`: `x+2 > x+1` — strict. ✔ (covers rules 6,7)

**{DP6}** (usable rules: 6,7 only — `fac`'s own rule is *not* usable here). Interpretation `[0]=0,[s](n)=n+1,[p](n)=max(n-1,0)` (truncated predecessor — a legitimate monotone algebra): rule6 gives `x+1 ≥ x+1` (equality, real semantics, ✓ weak), rule7 gives `1 ≥ 0` ✔. With `[FAC](n)=n`: `[FAC(s(x))]=x+1 > [FAC(p(s(x)))]=x` since `[p(s(x))]=(x+1)\dot-1=x`. Strict. ✔ (covers rule 8 via DP6, and re‑confirms rules 6,7 as usable rules)

Every original rule (1–8) has now been used as an ordinary rule (checked weakly, `≥`) inside the "usable rules" of the SCC(s) where it is relevant, and every genuine cycle (DP1, DP3, DP4, DP6) has been strictly oriented. The non‑cyclic pairs DP2, DP5, DP7 require no separate treatment by the SCC‑decomposition soundness theorem.

### Conclusion

By the Dependency Pair theorem (a TRS terminates iff there is no infinite chain over its dependency pairs and rules), and since every SCC of the dependency graph has been shown to admit no infinite chain using only genuine monotone interpretations over the natural numbers (including the standard truncated-subtraction algebra for `p`), the whole rewrite system is terminating.

**Verdict: Terminating — provable purely from the given eight rules via the Dependency Pair / SCC-decomposition method, with no extra rules, guards, or hidden assumptions.**
