I chose a polynomial/ℕ-interpretation argument because it works directly off the rules' syntactic shape and requires nothing the rules don't already define.

Concretely, three things pushed me to it:

1. **The system is a clean, constructor-based TRS.** `0` and `s(_)` are constructors; `plus`, `times`, `p`, `fac` are defined. That structure is exactly what an interpretation over ℕ is designed to handle — you don't need to import any "meaning" of `0`/`s`; you just read them as 0 and successor and check the inequalities.

2. **Each rule has an obviously decreasing component.** I didn't have to invent an ordering or find a clever weighting:
   - `plus(x, s(y)) → …` — second arg drops.
   - `times(s(x), y) → …` — first arg drops.
   - `p(s(s(x))) → s(p(s(x)))` — `s` count drops by one.
   - `fac(s(x)) → … fac(x) …` (after `p` reduces) — arg drops.
   The `0` rules and `p(s(0)) → 0` are base cases. So a lexicographic/component-wise ℕ interpretation is the most direct witness.

3. **I wanted something rule-internal.** Other methods I considered and rejected:
   - **RPO/LPO directly on syntax:** works here too, but it needs a precedence and status. For a short answer, an ℕ-interpretation is more transparent because you can literally show the number on each side of each rule going down.
   - **Semantic labeling / matrix interpretations:** overkill for 8 rules.
   - **Dependency pair / size-change:** would also work, but it relies on the same observation (each defined symbol's recursion argument decreases) that the interpretation makes immediate.
   - **Importing Peano arithmetic as object-level axioms** to prove termination (e.g., proving `x < s(x)` etc.): that would have violated your constraint. The ℕ interpretation stays meta-theoretic — no axioms imported.

The point of the ℕ argument is precisely that it is the *least* committal termination proof: it uses only the constants, constructors, and recursion structure visible in the rules themselves, with the ℕ semantics being a tool on the outside rather than a hypothesis inside the system.
