## Verdict: **Yes** — termination can be established from the rules alone.

**Method:** Lexicographic Path Order (LPO), a standard, purely syntactic termination technique that requires no auxiliary rules, side conditions, or semantic assumptions beyond a precedence on the function symbols occurring in the system.

### Precedence

Take the total precedence on function symbols:

```
times > plus > p > s > 0
```

with the *lexicographic* status on arguments for every symbol (compare argument tuples left-to-right). Recall the two basic LPO facts used repeatedly below:

- **Subterm property:** any term `f(t1,...,tn)` is `>_lpo` any of its subterms `ti` (or any subterm thereof).
- **Case f > g:** if `f > g` in the precedence, then `f(s1,...,sm) >_lpo g(t1,...,tk)` provided `f(s1,...,sm) >_lpo tj` for every `j`.
- **Case f = f (same head):** `f(s1,...,sn) >_lpo f(t1,...,tn)` if the tuples `(s1,...,sn)` and `(t1,...,tn)` compare lexicographically left-to-right using `>_lpo` (with equality allowed on a tie until the first strict difference).

### Rule-by-rule verification

**1. `plus(x,0) -> x`**
`x` is a proper subterm of `plus(x,0)`. By the subterm property, `plus(x,0) >_lpo x`. ✔

**2. `plus(x,s(y)) -> s(plus(x,y))`**
Head symbols: `plus` (LHS) vs `s` (RHS), and `plus > s`. It suffices to show
`plus(x,s(y)) >_lpo plus(x,y)`.
Same head `plus`: compare argument tuples `(x, s(y))` vs `(x,y)` lexicographically. First components equal (`x = x`); second components: `s(y) >_lpo y` by the subterm property. Hence `plus(x,s(y)) >_lpo plus(x,y)`, which gives the required inequality. ✔

**3. `times(0,y) -> 0`**
`times > 0` in the precedence, and `0` has no arguments, so the “case f > g” condition is vacuously satisfied: `times(0,y) >_lpo 0`. ✔

**4. `times(x,0) -> 0`**
Same reasoning as rule 3: `times > 0`. ✔

**5. `times(s(x),y) -> plus(times(x,y), y)`**
Head symbols: `times > plus`. Need `times(s(x),y) >_lpo times(x,y)` and `times(s(x),y) >_lpo y`.
- Same head `times`: compare `(s(x), y)` vs `(x,y)` lexicographically. First components: `s(x) >_lpo x` (subterm property), which already decides the lexicographic comparison in favor of the left side. So `times(s(x),y) >_lpo times(x,y)`.
- `y` is a direct subterm of `times(s(x),y)`, so by the subterm property `times(s(x),y) >_lpo y`.

Both conditions hold, so `times(s(x),y) >_lpo plus(times(x,y),y)`. ✔

**6. `p(s(s(x))) -> s(p(s(x)))`**
Head symbols: `p` (LHS) vs `s` (RHS), and `p > s`. Need `p(s(s(x))) >_lpo p(s(x))`.
Same head `p`: compare single arguments `s(s(x))` vs `s(x)`. Same head `s` again: compare `s(x)` vs `x`: `s(x) >_lpo x` by subterm property, hence `s(s(x)) >_lpo s(x)`. Propagating up, `p(s(s(x))) >_lpo p(s(x))`. ✔

**7. `p(s(0)) -> 0`**
`p > 0` in the precedence, `0` is a constant, so vacuously `p(s(0)) >_lpo 0`. ✔

### Conclusion

Every rewrite rule `l -> r` satisfies `l >_lpo r` under the precedence `times > plus > p > s > 0` with lexicographic status. Since LPO is a well-founded order that is closed under contexts and substitutions, this implies that every rewrite step strictly decreases the term in this order, and therefore the rewriting system is **terminating**.

No extra rules, guards, side conditions, or semantic (object-level) axioms beyond the ordinary syntactic definition of LPO and the given rules were used.
