I chose LPO because it is the standard textbook tool for this exact situation: a small, first-order TRS with no higher-order features, where I want a proof that is (a) mechanical, (b) fully derivable from the rules alone, and (c) as lightweight as possible.

**Why LPO fits the system**

1. **It only needs syntactic information.** LPO's inputs are just the rewrite rules and a precedence on the function symbols. That matches your constraint exactly — no semantic interpretation of `s`, `0`, `p`, no external axioms about what "successor" or "predecessor" mean, and no quotient/commutativity assumptions.

2. **The system is LPO-orientable without trickery.** Termination techniques like dependency pairs, polynomial interpretations, or matrix orders can also work, but each carries heavier machinery (dependency-pair framework, well-founded monotone algebras, etc.). For a system this small, LPO gives a one-shot proof in a few lines. I would only escalate to those tools if LPO genuinely failed.

3. **The argument structure is transparent.** You can read each rule's justification off the precedence and the subterm relation, so it's easy to verify the proof by hand. That matters when the user is asking "can *you* show termination from the rules alone" — the proof should be auditable from the rules, not dependent on a sophisticated meta-framework.

4. **It captures the natural "measure" of this TRS.** Every recursive function in the system (`plus`, `times`, `p`, `fac`) decreases on a structural subterm. LPO is the canonical order that formalizes "rewrite inside a strictly smaller subterm of a bigger function symbol." A polynomial interpretation or matrix order would also work, but they introduce a semiring and an interpretation; for a "minimal machinery" answer, that's overkill.

**Why I avoided some alternatives**

- **Recursion-theoretic / semantic arguments** (e.g., "interpret `s(x)` as `x+1`, `p(x)` as `x-1`, and observe that all rules decrease a well-founded measure on the natural numbers"): these silently *import* object-level axioms about arithmetic. The successor/predecessor properties of `s` and `p` are *not* derivable from the given rules alone — they are a *model*, not a theorem of the system. Using them would violate the constraint.
- **Dependency pairs / termination modules** would also work, but are heavier and require more setup (DP-problem decomposition, reduction pairs, etc.) for a system this small.
- **An automatic termination prover** would be fine, but I wanted the reasoning to be explicit and self-contained so the user can see *why* the system terminates, not just that some tool said so.

**Why LPO is still legitimate here**

A common worry: "doesn't LPO require the precedence to be compatible with the system, and aren't you assuming properties of the symbols to set the precedence?" The answer is no — the precedence is an *assumption* of the proof, not a property I derive. Any precedence that *orients* the rules gives a valid termination proof by the well-foundedness of LPO. The fact that I found one is a constructive demonstration that the system is LPO-terminating, which implies termination.

**Why I didn't try to prove termination more abstractly**

You asked whether termination can be established *from the rewrite system alone*. LPO is a syntactic method that operates on exactly that input. Attempting a more semantic argument (e.g., "every term in the system denotes a natural number and the rules decrease a measure on N") would, as noted, smuggle in non-derivable arithmetic. So LPO is the right level of abstraction for the question.

### A more honest framing

LPO is one tool among many. The honest reason I picked it is that it's the first one I reach for with small TRSs because it tends to succeed, gives a short proof, and needs nothing beyond the rules. If the user wanted a more automated or more powerful argument (e.g., handling a bigger system that LPO can't orient), I would have moved to dependency pairs or polynomial interpretations — but those would be heavier without adding to the answer.
