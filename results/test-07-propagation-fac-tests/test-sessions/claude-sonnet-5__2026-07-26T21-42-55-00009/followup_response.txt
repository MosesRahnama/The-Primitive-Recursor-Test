I chose the Dependency Pair framework rather than a direct simplification ordering (RPO/LPO/KBO) or a single global well‑founded measure for several concrete reasons tied to the actual shape of this TRS.

**1. A single monotone order over the whole signature is hard to find here.**
The problematic rule is
```
fac(s(x)) -> times(fac(p(s(x))), s(x))
```
On the right, `fac` is applied to `p(s(x))`, i.e. to a *term built from `x` via a different defined function*, not to a direct subterm reduction like `x` or `s(x)`. Any simplification order that must orient this rule **monotonically and globally** (as plain RPO/LPO do) needs `fac(s(x))` to dominate `times(fac(p(s(x))), s(x))` as whole terms, which forces comparing `p(s(x))` against `x` — but `p(s(s(x))) -> s(p(s(x)))` makes `p` non-decreasing in an immediately obvious syntactic sense (its right side even has an `s` wrapped around a recursive `p`-call). A naive precedence/status assignment struggles to certify `s(x) ⊐ p(s(x))` uniformly along with everything else at once, because that inequality is only true *semantically* (as natural numbers), not visibly at the syntactic level demanded by RPO.

This is exactly the symptom that DP methods are designed for: **local, per-cycle** reasoning instead of one global order.

**2. The system's recursion structure is naturally "layered" and mostly simple.**
Three of the four recursive rules (`plus`, `times`, `p`) are plain structural recursions where the recursive call's argument is a genuine subterm of the left-hand side's argument. This is precisely the situation the **subterm criterion** was built for — it lets us discharge `PLUS`, `TIMES`, `P` cycles "for free," with a one-line projection argument, no orders, no algebras. It would be wasteful to invoke a semantic algebra for these when a subterm-based (syntactic, guaranteed terminating) argument suffices.

**3. Only one genuinely semantic difficulty remains, and it's confined to a single small SCC.**
Once the DP graph is computed, the only cycle where the subterm criterion fails is the `FAC` self-loop, and its *usable rules* are exactly `p(s(s(x))) -> s(p(s(x)))` and `p(s(0)) -> 0` — a tiny fragment of the whole system. The **usable rules** technique lets me ignore `plus`/`times` entirely when justifying this one inequality, and solve it with a small monotone algebra (`p` as truncated predecessor, `FAC` as identity) tailored just to that fragment. This is far cheaper and more transparent than trying to build one polynomial interpretation that must simultaneously orient all eight rules at once.

**4. Modularity matches the proof obligation stated in the prompt.**
Since I'm required to justify termination using nothing beyond the given rules (no side conditions, no extra assumptions), the DP framework is attractive precisely because each processor (SCC decomposition, subterm criterion, usable rules + reduction pair) is a *sound, self-contained* transformation justified purely by the rules' own left/right-hand sides — nothing hidden is smuggled in. Every ingredient (cap-based graph estimation, projections, the small algebra) is derived directly from the syntax of rules (1)–(8), which fits the boundary set by the question.

**In short:** the direct/global approach fails cleanly because of the `fac`/`p` interaction, the DP framework's divide‑and‑conquer nature isolates that one hard spot into a single small SCC, and the rest of the system (three clean structural recursions) is dispatched almost trivially by the subterm criterion — making DP the most economical and rule‑faithful method available.
