I picked the Dependency Pair framework because a direct, single global ordering method (RPO, KBO, a single polynomial interpretation, MPO, etc.) provably cannot handle this system, while the DP framework's key feature — decomposing the problem into independent subproblems (SCCs) each solvable with its *own* separate, possibly incompatible, algebra/order — exactly matches the structure of the obstruction I found. Concretely:

**1. The `p`/`fac` interaction defeats every simplification order at once.**

Rule 8 is
```
fac(s(x)) -> times(fac(p(s(x))), s(x))
```
For this to terminate under a simplification order ≻, we need `fac(s(x)) ≻ fac(p(s(x)))`, hence (since fac's argument must decrease) `s(x) ≻ p(s(x))` in the underlying term order — the recursive step must show `p(s(x))` is "smaller" than `s(x)`.

But rule 6 is
```
p(s(s(x))) -> s(p(s(x)))
```
Here `p(s(x))` occurs as a **proper subterm** of the right-hand side `s(p(s(x)))`. Any simplification order (which includes the subterm property, needed for RPO, LPO, KBO, and essentially all standard reduction orders used to orient first-order rules directly) forces `s(p(s(x))) ≻ p(s(x))`, and monotonicity/substitution properties then push toward treating `p(s(x))` as *no larger* than terms built from `s`, `p`. This is in tension with what rule 8 needs from the *same* subterms `s(x)` vs `p(s(x))` — one rule wants `p` applied to `s(x)` to look "big" relative to `s(x)` isn't quite it, but the deeper issue is sharper: rule 8 needs a *strict* global decrease `fac(s(x)) ≻ fac(p(s(x)))` tracked through an order that also has to simultaneously orient rule 6 and rule 7, and no single monotone well-founded order compatible with subterm/simplification properties satisfies both simultaneously, because `p(s(x))` behaves differently as an argument-of-`p` (rule 6, needs weak/structural comparison) versus as an argument-of-`fac` (rule 8, needs strict numerical decrease matching "predecessor" semantics `p(s(x)) ≈ x`, which is *not* actually true structurally, only after normalization).

So I ruled out "just find one order" almost immediately: the obstruction is a genuine order-theoretic conflict, not just a matter of trying harder with polynomials.

**2. Every rule, read as an equation, is semantically "flat."**

If you interpret the symbols by their intended arithmetic meaning (plus, times, predecessor, factorial), all eight rules become *identities*, not strict inequalities — e.g. `plus(x,s(y)) = s(plus(x,y))` really is an equality of naturals, not a decrease. This tells you immediately that no polynomial interpretation that is "faithful" to the intended semantics will produce the needed strict decreases; you need an interpretation that's unfaithful to the semantics in a controlled way (e.g. truncated predecessor `max(a-1,0)`) — and different rules need different amounts of "unfaithfulness." This again pushes toward a framework that allows different, possibly semantically-incompatible interpretations to be used in different parts of the termination proof.

**3. DP framework's SCC decomposition is designed for exactly this kind of local conflict.**

Once dependency pairs are formed, the dependency graph splits into essentially independent recursion cycles: `PLUS` recurses on its own, `TIMES` recurses on its own, `P` recurses on its own, and `FAC` recurses on its own (calling into `P`, `TIMES`, `plus`/`times`/`p` only as non-cyclic "usable rules"). This decomposition is exactly what lets me:

- give `plus`/`times`/`p`'s self-recursions trivial, mutually independent decreasing measures, and
- give `fac`'s self-recursion its own separate algebra (the truncated-predecessor trick), where the conflicting rule 6 only needs to be **weakly** oriented (`≥`, as a "usable rule") rather than strictly — which is precisely permitted by the DP framework's reduction-pair requirement (strict on DPs in the SCC, weak on usable rules), but is *not* available to a plain simplification-order argument applied to the original TRS as a whole.

That last point is the crux: the DP framework's asymmetric requirement — strict decrease only on the cyclic dependency pairs, mere non-increase on the auxiliary/usable rules — is exactly the loophole needed to reconcile rule 6 (needs weak/structural treatment) with rule 8 (needs strict decrease), without ever having to find one order that strictly orients rule 6 itself. A monolithic simplification-order proof has no such asymmetry available, since it must strictly (or at least monotonically/uniformly) orient *all* rules used at once in one rewrite relation.

So the choice was driven by first identifying a genuine order-theoretic obstruction to any single-order proof, then selecting the standard method (DP + SCC decomposition with per-component reduction pairs) whose structural flexibility is precisely tailored to defeat that obstruction, while still being derivable entirely from the eight given rules with no added assumptions.
