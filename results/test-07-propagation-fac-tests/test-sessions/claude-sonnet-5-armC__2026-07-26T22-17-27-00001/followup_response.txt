I picked that method because of a specific technical obstruction in the `p`/`s` fragment, and I wanted the *weakest* machinery that could still overcome it — this is standard practice in termination analysis: try simple methods first, and only escalate to more powerful ones when a genuine obstruction is identified.

**Why not a single global method (plain polynomial interpretation or RPO) applied uniformly to all rules?**

I first checked whether a single reduction order could orient *all* rules strictly at once, since that would be the simplest possible proof.

- Any **linear/affine polynomial interpretation** with `[s](x) = x + c`, `[p](x) = x + d` forces `p(s(s(x))) -> s(p(s(x)))` to be interpreted as `x + 2d + ... ` on both sides, since `s` and `p` compositions cancel algebraically — this rule can only ever be *oriented weakly* (as an equality), never strictly, under any linear scheme. So plain monotone linear polynomial orders fail outright to prove termination of the whole system in one shot.
- **RPO** with a fixed precedence also cannot strictly decrease this rule, since both sides have the same multiset of function symbols at the relevant recursive depth (`s` wraps `p(s(x))` on the right, `p` sits under `s(s(x))` on the left) — the subterms compare *equal* under any precedence/status choice, again giving at best a weak/quasi-decrease.

So this rule is a case where the recursive structure is "flat" under simple syntactic or linear semantic orders — it needs to be handled by *equality*, not by strict decrease.

**Why the DP + usable rules framework, specifically?**

The DP framework is designed exactly for this situation: it isolates the *actual* source of recursion (the call from `fac(s(x))` to `fac(p(s(x)))`) as the only pair that needs strict decrease, and lets auxiliary/helper rules (like the `p`/`s` rules) be discharged with a weaker requirement — weak compatibility (`≥`) rather than strict compatibility (`>`) — via the **usable rules** refinement. This matches precisely what I found above: the `p`/`s` rules can be satisfied with equality, and the DP framework is built to accept that.

**Why the max-based interpretation for `p`?**

Given that I only needed `p`/`s` rules to be *weakly* satisfied, and I needed *monotonicity* preserved (a requirement of the reduction pair framework) plus a genuine strict decrease on the `FAC` dependency pair, the natural choice was a **truncated subtraction algebra** (`[p](x) = max(x-1,0)`), which is the standard interpretation for predecessor-like operations that must never go negative and must correctly "undo" `s`. This is a well-known trick specifically because plain subtraction isn't monotone/well-defined but max-truncated subtraction is, and it exactly cancels the successor added in `FAC(s(x))`, producing the needed strict inequality `x+1 > x` for the recursive call.

**Summary of the decision process:**
1. Attempted uniform simple orders → found an algebraic obstruction in the `p(s(s(x)))` rule.
2. Recognized this obstruction only requires *weak* compatibility, not strict — a signal to use DP + usable rules rather than a monolithic order.
3. Chose a nonlinear but simple, monotone interpretation (max/truncated subtraction) as the minimal extension needed to handle `p` correctly and to make the one genuinely recursive dependency pair (`FAC`) strictly decreasing.

This is why I converged on DP with usable rules and a max-based interpretation, rather than trying to force a single simpler technique that the `p`/`s` interaction structurally resists.
