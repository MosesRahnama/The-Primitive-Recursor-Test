# Verdict: **Terminating**

Termination of this rewrite system can be established using a **polynomial interpretation** (equivalently, a simple weight/multiset argument), a standard, syntax-only method.

## Interpretation

Assign to each function symbol a polynomial interpretation over the natural numbers, monotone in each argument:

- `[0] = 1`
- `[s(x)] = [x] + 1`
- `[plus(x, y)] = [x] + [y]`
- `[times(x, y)] = 2·[x]·[y] + [y]`   (with `[x], [y] ≥ 1` guaranteed since `[0]=1`)

This gives every term a strictly positive natural number value, and each interpretation is weakly monotone in its arguments (indeed strictly monotone), which justifies using it as a reduction order compatible with the rewrite relation (closed under contexts and substitutions).

## Checking each rule: LHS value > RHS value

Let `X = [x] ≥ 1`, `Y = [y] ≥ 1`.

**1. `times(x, 0) -> 0`**
LHS = `2·X·1 + 1 = 2X + 1`
RHS = `1`
Since `X ≥ 1`, LHS ≥ 3 > 1 = RHS. ✔

**2. `times(x, s(y)) -> plus(times(x, y), x)`**
LHS = `2·X·(Y+1) + (Y+1) = 2XY + 2X + Y + 1`
RHS = `(2XY + Y) + X = 2XY + X + Y`
LHS − RHS = `X + 1 > 0`. ✔

**3. `plus(x, 0) -> x`**
LHS = `X + 1`, RHS = `X`. LHS > RHS. ✔

**4. `plus(0, x) -> x`**
LHS = `1 + X`, RHS = `X`. LHS > RHS. ✔

**5. `plus(x, s(y)) -> s(plus(x, y))`**
LHS = `X + (Y + 1) = X + Y + 1`
RHS = `(X + Y) + 1 = X + Y + 1`
LHS = RHS — **not strictly decreasing** under this interpretation. Need a refinement.

## Refinement

Use instead:
- `[s(x)] = 2·[x] + 1`
- `[plus(x,y)] = [x] + [y]`
- keep `[times(x,y)] = 2·[x]·[y] + [y]`, `[0] = 1`.

Recheck all rules with `X, Y ≥ 1`:

**1.** LHS = `2X+1`, RHS = `1` ⇒ LHS > RHS. ✔

**2.** Unaffected by change to `s`, still LHS − RHS = `X+1 > 0`. ✔

**3.** `X+1 > X`. ✔

**4.** `1+X > X`. ✔

**5. `plus(x, s(y)) -> s(plus(x, y))`**
LHS = `X + (2Y+1) = X + 2Y + 1`
RHS = `2(X+Y) + 1 = 2X + 2Y + 1`
LHS − RHS = `−X < 0` for `X ≥ 1`. **Fails the other direction.**

This shows plain polynomial orders with these shapes are delicate; instead use a **multiset path order / recursive path order (RPO)** argument, which handles rules 5–6 naturally via subterm counting.

## Correct Termination Argument via RPO

Use RPO with the precedence `times > plus > s > 0`, and comparing arguments recursively (standard RPO with, say, lexicographic status left-to-right):

- **Rule 1** `times(x,0) -> 0`: LHS has head `times` which is maximal in precedence, and `0` is a proper subterm-level object appearing structurally smaller — LHS ≻ RHS by the subterm property (0 is simpler).
- **Rule 2** `times(x,s(y)) -> plus(times(x,y), x)`: head symbol `times ≻ plus`, and all arguments of RHS (`times(x,y)`, `x`) are ≼ some argument of LHS (`times(x,y) ◁ times(x,s(y))` since `y ◁ s(y)`; `x` is a direct argument) — RPO rule (case: head decrease) applies. ✔
- **Rule 3** `plus(x,0) -> x`: RHS is a proper subterm of LHS — subterm property gives LHS ≻ RHS. ✔
- **Rule 4** `plus(0,x) -> x`: same, RHS is a proper subterm. ✔
- **Rule 5** `plus(x,s(y)) -> s(plus(x,y))`: head `plus ≻ s`; RHS's argument `plus(x,y)` is ◁ `plus(x,s(y))` since `y ◁ s(y)` — RPO applies. ✔
- **Rule 6** `plus(s(x),y) -> s(plus(x,y))`: symmetric to rule 5, `plus(x,y) ◁ plus(s(x),y)` since `x ◁ s(x)` — RPO applies. ✔

All six rules are compatible with this RPO instance (precedence `times > plus > s`, `0` minimal), and RPO is well-founded by König's lemma / Dershowitz's theorem, using only the term structure given — no external axioms.

## Conclusion

**The system terminates.** The recursive path order with precedence `times > plus > s > 0` orients every rule strictly, decreasing in each rewrite step, establishing termination directly from the syntactic shape of the rules with no additional axioms or side conditions needed.
