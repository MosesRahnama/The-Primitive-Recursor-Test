**Verdict: yes.** Termination can be established from the displayed syntax and rewrite rules alone. No arithmetic axioms about `0`, `s`, `plus`, `times`, `p`, or `fac` need be assumed; in particular, terms not representing numerals may simply become stuck, which does not threaten termination.

Let \(R_0\) be the subsystem consisting of the `plus`, `times`, and `p` rules:

```text
plus(x, 0)        -> x
plus(x, s(y))     -> s(plus(x, y))

times(0, y)       -> 0
times(x, 0)       -> 0
times(s(x), y)    -> plus(times(x, y), y)

p(s(s(x)))        -> s(p(s(x)))
p(s(0))           -> 0
```

Then handle the single `fac` rule separately.

## 1. The `plus`/`times`/`p` subsystem terminates

The subsystem \(R_0\) is oriented by a standard recursive path ordering, using lexicographic status for the defined symbols and, for example, a precedence satisfying

```text
times > plus > s
p     > s
```

with `0` minimal. No particular order between `p` and `plus`/`times` is needed.

Each rule decreases:

```text
plus(x, 0) -> x
```

decreases by the subterm property.

```text
plus(x, s(y)) -> s(plus(x, y))
```

decreases because `plus(x,s(y)) > plus(x,y)`: the second argument strictly decreases from `s(y)` to `y`; and `plus > s`.

```text
times(0, y) -> 0
times(x, 0) -> 0
```

decrease directly.

```text
times(s(x), y) -> plus(times(x, y), y)
```

decreases because `times > plus`, and the left side is greater than `times(x,y)` by the lexicographic decrease `s(x) > x`.

```text
p(s(s(x))) -> s(p(s(x)))
```

decreases because `p(s(s(x))) > p(s(x))`, using `s(s(x)) > s(x)`, and `p > s`.

```text
p(s(0)) -> 0
```

also decreases.

Therefore \(R_0\) terminates.

This matters because all computation done by `plus`, `times`, and `p` is finite, including computation occurring inside arguments of other symbols.

## 2. What the `p` rules actually do

The only `p` rules are:

```text
p(s(s(x))) -> s(p(s(x)))
p(s(0))    -> 0
```

Thus `p` has only one way to continue reducing when its argument begins with successor symbols: it consumes one successor from the argument.

For syntactic constructor strings, the derivable behavior is:

```text
p(s(0))        -> 0
p(s(s(0)))     -> s(p(s(0))) -> s(0)
p(s(s(s(0))))  -> s(p(s(s(0)))) ->* s(s(0))
```

and similarly at arbitrary tails:

```text
p(s(s(u))) -> s(p(s(u))).
```

Crucially, this is a statement about the rewrite rules, not an imported predecessor axiom. If the tail does not have enough outer `s` constructors to match a rule, then `p(...)` is simply irreducible. For example, `p(0)` and `p(s(plus(0,0)))` may be stuck unless their arguments reduce into a matching shape. Stuckness is harmless for termination.

## 3. The only possible recursive `fac` call strictly consumes successor structure

The remaining rule is:

```text
fac(s(x)) -> times(fac(p(s(x))), s(x))
```

The only recursive occurrence introduced by this rule is:

```text
fac(p(s(x))).
```

For that occurrence itself to fire the `fac` rule again, its argument must first reduce to a term with outermost form `s(...)`.

The only relevant way for this to happen at the root is:

```text
p(s(s(u))) -> s(p(s(u))).
```

So, whenever a recursive `fac` call becomes able to make another recursive `fac` call, the effect is schematically:

```text
fac(s(s(u)))
  -> times(fac(p(s(s(u)))), s(s(u)))
  ->* times(fac(s(p(s(u)))), s(s(u)))
  -> times(times(fac(p(s(p(s(u))))), s(p(s(u)))), s(s(u)))
```

The important point is not the surrounding `times` terms, which belong to the already terminating subsystem \(R_0\). The important point is the chain of `fac` arguments:

```text
s(s(u))
p(s(s(u)))  -> s(p(s(u)))
p(s(p(s(u))))   ...
```

A further `fac` step is possible only when another outer successor is available in the original payload. The `p` rule does not manufacture an unbounded new supply of successors: it transfers one outer `s` outward while changing

```text
p(s(s(u)))
```

into

```text
s(p(s(u))).
```

Repeated recursive `fac` activation therefore follows a finite syntactic successor descent. If the payload eventually reaches `0`, the rule

```text
p(s(0)) -> 0
```

ends the descent. If the payload reaches a nonmatching or irreducible form, then the recursive `fac` term has an argument not of form `s(...)`, so no further `fac` rule applies.

For example:

```text
fac(s(s(s(0))))
-> times(fac(p(s(s(s(0))))), s(s(s(0))))
->* times(fac(s(s(0))), s(s(s(0))))
```

and the recursive argument has one fewer available successor level. Eventually one reaches:

```text
fac(s(0))
-> times(fac(p(s(0))), s(0))
-> times(fac(0), s(0)),
```

after which the `fac` rule cannot fire on `fac(0)`.

## 4. Why reductions inside arbitrary arguments do not invalidate this

Arguments may be arbitrary first-order terms, not just numerals. They may contain `plus`, `times`, `p`, or even nested `fac` occurrences.

That still does not create an infinite reduction:

1. Reductions in `plus`, `times`, and `p` are finite, by termination of \(R_0\).

2. A `fac` occurrence already present inside an argument is a proper subterm of the surrounding `fac` occurrence. Following such occurrences gives ordinary finite structural descent through the original finite term.

3. A `fac` occurrence newly introduced by the `fac` rule is specifically `fac(p(s(x)))`. Any continued recursion through this newly introduced occurrence requires the syntactic successor-consumption behavior of `p` described above.

Thus an infinite reduction would require an infinite path consisting of either:

- infinitely many descents into pre-existing proper subterms, impossible in a finite term; or
- infinitely many recursively generated `fac` calls along one branch, impossible because each such continuation consumes available successor structure through the displayed `p` rules; or
- infinitely many `plus`/`times`/`p` reductions, impossible because \(R_0\) terminates.

There is no fourth source of rewriting.

## Conclusion

The system is terminating as presented.

The proof uses only:

- a standard recursive path ordering for `plus`, `times`, and `p`;
- the literal syntactic behavior of the two `p` rules;
- the fact that the sole `fac` rule introduces one recursive call whose repeated activation requires finite successor consumption.

It does **not** assume that all terms are natural numbers, that `p` is an externally defined predecessor, that `plus` or `times` satisfy arithmetic equations beyond the rules, or that any extra rewrite rule, guard, or side condition is available.
