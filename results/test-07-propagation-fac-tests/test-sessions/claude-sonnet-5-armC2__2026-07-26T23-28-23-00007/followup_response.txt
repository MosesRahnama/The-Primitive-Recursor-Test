I picked the dependency pair (DP) method specifically because the simpler, more "direct" termination techniques fail on this system, and DPs are the natural next tool that handles exactly the kind of problem this system poses.

**Why simpler methods don't work directly:**

1. **Plain simplification orderings (LPO/RPO/KBO) struggle with `p(s(s(x))) -> s(p(s(x))))`.** The left and right sides have the same multiset of function symbols (two `s`'s and one `p` on each side, just rearranged) and the same size. This rule is not size-decreasing and isn't a subterm-style decrease either — it needs an argument that the *nesting/precedence* between `p` and `s` causes progress, not the term size itself. A monolithic reduction ordering on the whole system would need to simultaneously handle this "shuffle" step for `p` and the straightforward recursive-decrease steps for `plus`, `times`, `fac`, which is awkward to do in one global order (especially since `fac`'s termination also depends on `p` eventually reducing its argument, an indirect/nested dependency).

2. **This is precisely the class of examples DPs were introduced for**: systems where a naive reduction order works for *most* rules but a few rules require decomposing the property into separate, smaller "decrease" obligations tied to specific recursive call sites, rather than proving one global order compatible with *all* rules (including non-recursive, non-decreasing ones like `p(s(s(x))) -> s(p(s(x))))` as a whole rule).

**Why DPs specifically fit here:**

- DPs let you isolate *only the recursive call sites* (the arguments that matter for looping) into separate inequality constraints, ignoring the "constructor packaging" around them (the outer `s(...)` wrapper in the `p` rule, the outer `times(...)`/`plus(...)` context, etc.). This turns one hard global ordering problem into several easier local ones.
- The **dependency graph** structure naturally captures that `FAC`'s termination depends on `P`'s termination (via the chain `FAC(s(x)) -> FAC(p(s(x)))`), which mirrors the actual logical dependency in the rules (`fac` calls `p` in its own recursive argument) — something a single global well-founded order would have to encode implicitly, while DPs make it explicit and modular.
- Each resulting DP subproblem is small and can be discharged by simple, easily automatable orders (polynomial or matrix interpretations), which is why this is also the method automated termination provers (AProVE, TTT2) use for essentially this exact system.

So I chose DP + reduction pairs not because it's the only possible method in principle, but because it's the minimal machinery actually needed to handle the one "non-trivially-decreasing" rule (`p`) while decomposing the rest into manageable, independently verifiable pieces — matching the standard proof strategy for this well-known benchmark system.
