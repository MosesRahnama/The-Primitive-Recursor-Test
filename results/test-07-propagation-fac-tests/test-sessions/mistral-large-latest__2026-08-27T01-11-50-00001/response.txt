### **Termination Argument**

#### **1. Lexicographic Path Order (LPO) / Recursive Path Order (RPO)**
We attempt to orient all rules using a **precedence** on function symbols. A plausible precedence is:
`fac > times > plus > s > p > 0`

We check each rule:

- **Rule 1:** `plus(x, 0) → x`
  - `plus(x, 0) > x` holds if `plus > 0` (which it is, since `plus > s > 0`).
- **Rule 2:** `plus(x, s(y)) → s(plus(x, y))`
  - `plus(x, s(y)) > s(plus(x, y))` holds if `plus > s` (which it is).
- **Rule 3:** `times(0, y) → 0`
  - `times(0, y) > 0` holds if `times > 0` (which it is).
- **Rule 4:** `times(x, 0) → 0`
  - `times(x, 0) > 0` holds if `times > 0` (which it is).
- **Rule 5:** `times(s(x), y) → plus(times(x, y), y)`
  - `times(s(x), y) > plus(times(x, y), y)` holds if `times > plus` (which it is).
  - Also, `times(s(x), y) > times(x, y)` by subterm property.
- **Rule 6:** `p(s(s(x))) → s(p(s(x)))`
  - `p(s(s(x))) > s(p(s(x)))` holds if `p > s` (but this is **false** in our precedence, since `s > p`).
  - **Problem:** This rule does not orient under LPO/RPO with `s > p`. We need another approach for `p`.

**Conclusion for LPO/RPO:**
All rules except **Rule 6** (`p(s(s(x))) → s(p(s(x)))`) orient under the precedence `fac > times > plus > s > p > 0`. Rule 6 is problematic because `p` is below `s` in the precedence, so `p(s(s(x)))` is not greater than `s(p(s(x)))` under LPO/RPO.

#### **2. Dependency Pairs (DP) for `p`**
Since Rule 6 does not orient under LPO/RPO, we analyze it separately using **dependency pairs**.

The **dependency pair** for Rule 6 is:
`P(s(s(x))) → P(s(x))` (where `P` is the marked version of `p`).

The **DP problem** is:
`P(s(s(x))) → P(s(x))`

This is a **single-rule DP system**. To prove termination, we need to show that this DP rule cannot be applied infinitely.

- The DP rule strictly decreases the size of the term (since `s(s(x))` is larger than `s(x)`).
- Thus, the DP rule terminates.

**Conclusion for `p`:**
The `p` function terminates because its DP rule strictly decreases the term size.

#### **3. Fac Function and Recursive Calls**

`fac(s(x)) → times(fac(p(s(x))), s(x))`

The **dependency pair** for `fac` is:
`FAC(s(x)) → FAC(p(s(x)))` (where `FAC` is the marked version of `fac`).

The **DP problem** is:
`FAC(s(x)) → FAC(p(s(x)))`

We need to show that this cannot be applied infinitely.

- The argument to `FAC` is `p(s(x))`. Since `p` is terminating (as shown above), `p(s(x))` reduces to a smaller term (either `0` or `s(p(s(y)))` for some `y`).
- The key observation is that `p(s(x))` is **strictly smaller** than `s(x)` in the **embedding order** (since `p` peels off an `s`).
- Thus, the DP rule `FAC(s(x)) → FAC(p(s(x)))` strictly decreases the argument to `FAC` in the embedding order, so it terminates.

**Conclusion for `fac`:**
The `fac` function terminates because its recursive calls strictly decrease the argument in the embedding order.
