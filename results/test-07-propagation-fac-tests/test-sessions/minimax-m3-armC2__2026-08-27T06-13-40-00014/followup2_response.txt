## What does work

You need a *semantic* / interpretation-based argument. The standard one is a **polynomial interpretation** over ℕ, e.g.:

| Symbol | Interpretation |
|---|---|
| `0` | `0` |
| `s(x)` | `x + 1` |
| `p(x)` | `x` (or any monotone poly) |
| `plus(x, y)` | `x + y` |
| `times(x, y)` | `x · y` |
| `fac(x)` | `x!` (or a suitable polynomial/exp bound) |

One then checks each rule's interpretation strictly decreases (or is bounded above), and the `p` rules give the needed strict drop: e.g. `[p(s(s(x)))] = x+2 > x+1 = [s(p(s(x)))]`, and `[p(s(0))] = 1 > 0 = [0]`. Other options: **matrix interpretations**, **RPO with a non-standard status**, or a **dependency-pair processor** with a model — but they all essentially commit to an interpretation in which `s` and `p` behave like successor/predecessor on ℕ.
