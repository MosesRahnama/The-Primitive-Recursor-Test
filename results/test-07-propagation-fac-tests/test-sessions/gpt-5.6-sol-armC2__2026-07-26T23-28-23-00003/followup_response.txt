I picked a **dependency-pair / semantic measure argument** because the difficulty is not ordinary term size: some rules increase syntactic size. For example,

```text
p(s(s(x))) -> s(p(s(x)))
```

does not decrease symbol count, and the `fac` rule expands substantially. So a simple “every step makes the term smaller” argument would fail.

Dependency pairs isolate the calls that could sustain an infinite computation:

- `plus` calls `plus` on a smaller second argument.
- `times` calls `times` on a smaller first argument and delegates to the already terminating `plus`.
- `p` calls `p` with one fewer surrounding `s`.
- `fac(s(x))` calls `fac(p(s(x)))`.

The predecessor-style numerical interpretation is useful specifically for the last item: it proves that the argument of the recursive `fac` call decreases, while the actual `p` rewrite preserves the interpreted value as needed. Symbol precedence then handles the one-way call hierarchy `fac → times → plus`.

I chose this method because it separates **recursive descent** from harmless term expansion and does not require assuming an unstated equation such as `p(s(x)) = x`. It is therefore well matched to what can be derived from the rewrite rules alone.
