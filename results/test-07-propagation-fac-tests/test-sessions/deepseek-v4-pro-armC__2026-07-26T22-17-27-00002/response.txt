**Reasoning:**  
The system consists of standard terminating definitions for `plus` and `times` (with recursion on the first argument for `times`) and a two-rule predecessor `p`. The only potential source of non-termination is the interaction between `fac` and `p` in the rule  
`fac(s(x)) -> times(fac(p(s(x))), s(x))`.  

A dependency-pair analysis yields the recursive call `fac#(s(x)) -> fac#(p(s(x)))`. For an infinite sequence, `p(s(x))` would need to repeatedly reduce to some `s(y)`. However, `p` is defined only for `s(s(_))` and `s(0)`, and any reduction of `p(s(x))` eventually halts or yields a term whose top symbol is not `s` (e.g., `p(s(p(...)))` is a normal form). Thus the chain of `fac`-calls is bounded by the number of `s`-symbols that can be stripped away, which is finite for any input term.  

Crucially, in the `times` call created by `fac`, the first argument is a `fac`-term and the second is an `s`-term. The rules for `times` only reduce when the first argument is `0` or `s(_)`, or when the second argument is `0`. Since a `fac`-term never reduces to `0` or `s(_)` and the second argument `s(x)` never reduces to `0`, the `times`-nest built by `fac` is completely inert—it never triggers further multiplication steps. Consequently, every reduction sequence is finite, and termination is provable (e.g., by a suitable combination of dependency pairs and a recursive path ordering).
