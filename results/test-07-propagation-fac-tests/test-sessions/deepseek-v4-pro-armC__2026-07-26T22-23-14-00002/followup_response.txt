I chose the dependency pair framework with polynomial interpretations because the system’s termination is **not immediate from simple structural orders** — the troublesome rule is:

```
fac(s(x)) -> times(fac(p(s(x))), s(x))
```

Here, the recursive call `fac(p(s(x)))` is not a direct subterm of `fac(s(x))`, and the argument shrinks via the `p` rules (`p(s(s(x))) -> s(p(s(x)))`, `p(s(0)) -> 0`) in a *non‑monotonic* way that requires reasoning about the eventual decrease of terms. A plain recursive path order or lexicographic path order cannot handle this because `p(s(x))` is not necessarily smaller than `s(x)` under a straightforward precedence.  

The dependency pair method separates the top-level recursive call into a *dependency pair* `FAC(s(x)) -> FAC(p(s(x)))` and then uses a well-founded order (like a polynomial interpretation) that assigns a measure making `p(s(x))` smaller than `s(x)`. For instance, the polynomial interpretation `[0] = 0`, `[s](x) = x + 1`, `[p](x) = x - 1` (clipped appropriately) will make the dependency pair decrease, while also handling `plus`, `times`, and the other rules.  

Thus, the method was chosen because it is a general, self-contained technique that works *directly on the rules without importing induction schemas or external knowledge* — it only uses the given rewrite system to construct a termination proof.
