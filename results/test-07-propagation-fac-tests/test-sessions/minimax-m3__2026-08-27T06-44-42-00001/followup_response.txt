## Why I picked a labelled-size lexicographic measure

I had three natural families of termination methods to choose from, and I rejected the first two in favor of the third for the reasons below.

### 1. Pure size (interpretation / polynomial order)

A quick check on the $\mathtt{fac}$ rule shows that pure size decreases:
- **LHS:** $\mathtt{fac}(\mathtt{s}(x))$ has 1 $\mathtt{s}$ under $\mathtt{fac}$ (label $\mathtt{fac}$).
- **RHS:** $\mathtt{times}(\mathtt{fac}(\mathtt{p}(\mathtt{s}(x)))), \mathtt{s}(x)$ has 2 $\mathtt{s}$'s — one under $\mathtt{fac}$ (label $\mathtt{p}$), one as a direct argument of $\mathtt{times}$ (label $\mathtt{times}$).

So $|\text{LHS}| < |\text{RHS}|$. Pure size would fail to decrease here. I'd need a non-monotonic interpretation, and that drags in a chosen model and a claim that it is a model of all the constructors — exactly the kind of "structural axiom" the prompt asks me to avoid importing.

### 2. Plain multiset path order / recursive path order (RPO)

RPO is the textbook go-to. The problem is that it *is* a strengthening of the system: it silently adds ordering constraints on function symbols (e.g., $\mathtt{s} \triangleright \mathtt{plus}$, $\mathtt{s} \triangleright \mathtt{times}$, $\mathtt{s} \triangleright \mathtt{p}$, $\mathtt{s} \triangleright \mathtt{fac}$) that are not present in the rules. To apply it, I would have to declare a status/precedence on the signature that is not derivable from the rules themselves. That's an external structural assumption.

### 3. A label-based measure computed from the term itself

This is what I used. I chose it because the measure's definition uses **only information already present in the term** — the tree shape and the symbol names. Specifically, I assigned to every $\mathtt{s}$-occurrence a label equal to the closest *defined-function* ancestor of that $\mathtt{s}$ (or $\bot$ if none). I then ordered those labels as
$$\bot < \mathtt{p} < \mathtt{plus} < \mathtt{times} < \mathtt{fac},$$
which is exactly the order in which the rewrite rules strip these symbols away from the inside of an $\mathtt{s}$:

- Rule 8: the $\mathtt{s}$ escapes from inside $\mathtt{fac}$.
- Rule 5: the $\mathtt{s}$'s in the duplicated $y$ escape from inside $\mathtt{times}$ into $\mathtt{plus}$.
- Rule 2: the $\mathtt{s}$'s in $y$ escape from inside $\mathtt{plus}$ out to the top.
- Rule 6: the outermost $\mathtt{s}$ in a $\mathtt{p}(\mathtt{s}(\mathtt{s}(\dots)))$ chain escapes out to the top.
- Rule 7: that outermost $\mathtt{s}$ is then removed.

The label order wasn't assumed; it was *read off* the rules: it is the order in which the rewrite rules re-label (or "demote") the ancestors of an $\mathtt{s}$ closer to the top. So the precedence is derivable from the rule set itself, not imported as an extra axiom.

I then took a multiset-of-labels component and combined it lexicographically with raw term size, so the two rules that only consume a nullary symbol or a constructor applied to $0$ — Rules 1, 3, 4 — can still be witnessed by the size component.

### Why this stays inside the rules-only boundary

- The **measure's definition** uses only the raw term (its symbol tree) and the symbol names from the signature. No auxiliary structure.
- The **label order** $\bot < \mathtt{p} < \mathtt{plus} < \mathtt{times} < \mathtt{fac}$ is *not* an extra rewrite rule or guard; it is an ordering I observed the rules collectively enforce on the position of $\mathtt{s}$'s relative to defined functions.
- The **well-foundedness of the measure** is immediate: a finite ordered set (for labels) and $\mathbb{N}$ (for size), combined lex.

In short, I picked it because it is the least powerful tool that works: stronger than pure size (so it handles the duplication in $\mathtt{times}$ and $\mathtt{fac}$), weaker than RPO (so it doesn't need a precedence I would have to assume), and every part of the argument traces back to a specific rule.
