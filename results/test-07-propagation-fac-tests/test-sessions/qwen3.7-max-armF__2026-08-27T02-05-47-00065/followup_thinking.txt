    *   **Why LPO over MPO/RPO (Multiset Path Ordering):** This is the most critical technical point.
        *   Look at Rule 2: `times(x, s(y)) -> plus(times(x, y), x)`.
        *   The recursive call `times(x, y)` has the *same* first argument `x` and a *smaller* second argument `y`.

This would require `s(y) >_rpo times(x, y)`. But `times` is a "larger" function than `s` (since it calls `plus` which calls `s`), so `s(y) > times(x, y)` is impossible in any sensible precedence. Thus, **MPO fails**.
        *   LPO solves this by comparing arguments *lexicographically* from left to right. Since the first arguments are identical (`x` == `x`), it moves to the second argument, where it easily sees `s(y) > y`. This perfectly captures the "recursive descent on the second argument while keeping the first constant" pattern.
    *   **Why LPO over KBO (Knuth-Bendix Ordering):**
        *   KBO could technically work, but it requires assigning integer weights to symbols and variables, and dealing with admissibility conditions (e.g., in standard KBO, binary symbols usually must have weight $\ge 1$, forcing $w(s)$ to be artificially large to satisfy the weight drop in Rule 2). LPO is purely symbolic and qualitative, making the proof simpler and more elegant to write and verify by hand.

        *   Dictated by the call graph / rule nesting. `times` calls `plus`, so `times > plus`. `plus` calls `s` on the RHS, so `plus > s`. `0` is a base constant, so it sits at the bottom.
