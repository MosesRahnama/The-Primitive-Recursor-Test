I chose the dependency pair framework combined with polynomial (or matrix) interpretations because a simple simplification order like LPO or Knuth-Bendix order fails for this system.  

The main obstacle is the rule  
`fac(s(x)) -> times(fac(p(s(x))), s(x))`.  
The recursive call `fac(p(s(x)))` does **not** use a syntactic subterm of `s(x)`; instead the argument `p(s(x))` first reduces to something smaller (either `0` or `s(...)`). So purely syntactic orders that rely on the “subterm property” cannot directly orient this rule.  

Dependency pairs separate the top-level recursive call into a dependency pair  
`FAC(s(x)) -> FAC(p(s(x)))`,  
and then we only need to prove that `p(s(x))` is “smaller” than `s(x)` in a well-founded order that also makes the other rules (for `p`, `plus`, `times`) terminating. A polynomial interpretation like `s(x)=x+1`, `p(x)=max(x-1,0)`, `FAC(x)=x` (with `times` and `plus` handled by simple additive polynomials) does exactly that: it strictly decreases the interpreted size of the argument to `FAC`.  

Relying on this technique is natural when a system has a defined auxiliary function (`p`) whose output is not a direct subterm but is structurally smaller after the inner evaluation—a situation where semantic termination orders are much more flexible than purely syntactic ones.
