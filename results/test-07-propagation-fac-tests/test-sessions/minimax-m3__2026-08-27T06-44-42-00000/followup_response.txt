I chose dependency pairs (DP) for three practical reasons that fall out of the system's structure, not because I was hoping DP would work:

1. **The rules don't obviously terminate under a naive measure.** The most direct guess would be a "size" or "size-of-numeral" measure on the recursive arguments. That fails for `fac`: rule 8 recurses on `p(s(x))`, which can have a *smaller* numeral than `x` (e.g., `p(s(s(0))) = s(0)`, and `p(s(0)) = 0`). So `s(x) → p(s(x))` strictly decreases, and a single‑argument‑decrease proof for `fac` would only need the 1‑step measure on `p`. But to *show* that the nested `times(..., s(x))` cannot blow up, you need a reason — a "syntactic" reason, derivable from the rules alone — why that term is a dead redex. DP is a clean way to organize that "reason": the times redex is a sink in the DP graph.

2. **The recursive call in `fac` is wrapped in `times(..., ...)`, and the surrounding `times` may, in general, expand (think of `times(s(x), y) → plus(times(x,y), y)` which can grow).** Before proving termination, I have to rule out the possibility that rule 5 keeps firing on the term created by rule 8 forever. That suspicion is exactly what DP separates: each defined symbol gets its own DPs, and you check acyclicity in the *call graph* between DPs. If I had tried a monolithic "rank function" / interpretation argument, I would have had to deal with the cross‑rule interaction (rule 8 emits a `times` redex whose first argument starts as `fac(...)` — head `fac`, not `s` — so rule 5's LHS doesn't match) in a less structured way. DP's per‑symbol heads make the "no rule applies to the first argument because its head is `fac`, never `s`" case analysis natural.

3. **No variable‑binding, no extra symbols, finitely many rules.** These are the exact hypotheses under which DP applies without any extensions. I didn't have to add weight pairs, arctic/coral interpretations, matrix interpretations, or any "guarded" notion like context‑sensitive rewriting. The eight rules are enough to do the analysis by hand.

Could another standard method have worked? Yes, several — and that's part of why DP was a reasonable default here:

- A **polynomial / linear interpretation** over a well‑founded domain (e.g., `ℕ`) would also work, and would only need values for `0`, `s`, `plus`, `times`, `p`, `fac`. It's also a "rules‑only" method with no guards. I didn't pick it because hand‑solving the inequalities for `times` (which is not simply terminating, since `times(s(x),y) → plus(times(x,y),y)` grows the term tree) is finicky, and the choice of interpretation has to be guessed. DP is more mechanical.
- A **reduction‑order / lexicographic path order (LPO)** argument works, but the LPO would need a precedence and a status. The recursion in `times` (rule 5 replaces the head with `plus`, which is greater in precedence) and the recursion in `fac` (rule 8 replaces the head with `times`, but the recursive call sits inside `p(s(x))`, which strictly decreases in some nested sense) are awkward to package in LPO without a manual precedence that mirrors exactly the DP‑graph acyclicity proof. So LPO wouldn't have been materially simpler.
- A **recursive‑function / call‑matrix** approach is essentially equivalent to DP for innermost termination, and a non‑innermost argument here would be strictly harder because rule 5's RHS `plus(times(x,y),y)` builds a `plus` on top of a `times` — i.e. cross‑symbol structure has to be tracked. DP is the standard tool designed for exactly that.
- A **manual induction on a "rank"** (e.g., the `s`‑depth of the top‑level argument) would also work, and is in fact the DP argument in disguise (the DP graph for `p` and `fac` is a strict‑decrease chain, and `plus`/`times` DPs are acyclic on the call graph). I did not present it that way because the DP formulation is more uniform and it makes the cross‑symbol interaction (rule 8 ↔ rule 5) explicit rather than smuggling it into the rank definition.

So the choice was driven by the shape of the rules: one rule (`fac`) whose recursion's argument is handled by a helper (`p`) that decreases, and one rule (`times`) whose expansion could in principle threaten the `fac` recursion unless shown otherwise. DP separates the two concerns (per‑symbol call graph + per‑symbol head analysis) which is exactly the "rules‑only" proof structure I wanted. No strengthening, no guards, no extra axioms — just the eight rules and the standard DP theorem.
