# Analysis of Termination Proof Methods

## System recap
```
F(x, y, Z)    -> x
F(x, y, S(n)) -> G(y, F(x, y, n))
```

---

## (A) LPO with precedence F > G > S > Z

**Check:**
- Rule 1: `F(x,y,Z) -> x` — RHS is an argument of LHS, holds by the subterm property.
- Rule 2: `F(x,y,S(n)) -> G(y,F(x,y,n))` — Since F > G, need `F(x,y,S(n)) >_lpo y` (subterm, ✓) and `F(x,y,S(n)) >_lpo F(x,y,n)` (same head, compare tuples lexicographically: x=x, y=y, `S(n) >_lpo n` by subterm property, ✓).

**1. Succeeds:** Yes.
**2. Stays in bounds:** Yes — purely syntactic order derived from signature/precedence, no external assumptions.

---

## (B) Polynomial interpretation

`[F](x,y,n) = x+n+1`, `[S](n)=n+1`, `[G](a,b)=b`, `[Z]=0`.

- Rule 1: `x+0+1 = x+1 > x`. ✓
- Rule 2: `x+(n+1)+1 = x+n+2 > x+n+1 = [G(y,F(x,y,n))]`. ✓

**1. Succeeds:** Yes.
**2. Stays in bounds:** Yes — standard algebraic interpretation over ℕ, fully justified by the rules.

---

## (C) KBO with uniform weight 1

KBO requires that the number of occurrences of each variable in the RHS not exceed its occurrences in the LHS. In rule 2, `y` occurs **once** in `F(x,y,S(n))` but **twice** in `G(y,F(x,y,n))`. This violates the necessary variable-coincidence condition of KBO, independent of precedence or weight choice (even varying the variable weight w₀ cannot repair this, and for w₀>0 the weight comparison itself fails too).

**1. Succeeds:** No — KBO cannot orient rule 2 at all.
**2. Stays in bounds:** Yes (trivially) — the method itself imports nothing extra; it simply fails to prove the result.

---

## (D) Dependency pairs + subterm criterion

Only defined symbol is F; the only dependency pair (from rule 2, since rule 1's RHS is a variable) is:

`F#(x,y,S(n)) -> F#(x,y,n)`

Projecting to the third argument: `π(F#(x,y,S(n))) = S(n)`, `π(F#(x,y,n)) = n`, and `S(n) ⊐ n` (proper subterm). This strictly decreasing single-pair cycle is exactly what the subterm criterion needs to eliminate all infinite chains.

**1. Succeeds:** Yes.
**2. Stays in bounds:** Yes — a standard, self-contained application of the DP framework to the given rules.

---

## (E) Direct descent measure via depth_S(n)

The measure `μ(F(x,y,n)) = depth_S(n)+1` is only naturally defined by induction over terms built from `S`/`Z`. But the TRS as given is **unsorted**: `x, y, n` range over *arbitrary* terms of the signature {F,G,S,Z}, so the third argument of F could be instantiated with e.g. `G(p,q)` or another `F`-term during rewriting. The method never specifies `depth_S` on such terms, so `μ` is not shown to be a well-defined, monotone measure over the whole term algebra generated by the rules — it silently assumes the third argument is always a "Peano numeral," i.e. imports an implicit sort/typing discipline not present in or derivable from the bare rules.

**1. Succeeds:** No — as literally stated, it is not a complete, rigorous SN proof over all instantiations permitted by the untyped system.
**2. Stays in bounds:** No — it relies on an unstated structural/sort assumption about the shape of the third argument, going beyond what the given rules alone provide.

---

## Summary

| Method | Succeeds? | Stays in bounds? |
|---|---|---|
| A (LPO) | Yes | Yes |
| B (Polynomial) | Yes | Yes |
| C (KBO) | No | Yes |
| D (DP + subterm criterion) | Yes | Yes |
| E (ad hoc descent measure) | No | No |

**Methods satisfying both conditions: A, B, and D.**
