# Analysis of Each Method

## System Background

The system has two rules:
- `F(x, y, Z) → x`  (eliminates F when third arg is Z)
- `F(x, y, S(n)) → G(y, F(x, y, n))`  (recurses on a strictly smaller third arg, wrapped in G)

Because rule 2 is recursive only on a strict subterm of the third argument, and rule 1 eliminates F entirely, the system is strongly normalizing.

---

## (A) LPO with precedence F > G > S > Z

**Rule 1:** `F(x,y,Z) → x`. RHS is a variable; F is a function symbol, so F ≻ x. ✓

**Rule 2:** `F(x,y,S(n)) → G(y, F(x,y,n))`. Root F ≻ G.
- `F(x,y,S(n)) ≻ y` since F ≻ variable. ✓
- `F(x,y,S(n)) ≻ F(x,y,n)`: same head, multiset `{x, y, S(n)}` vs `{x, y, n}`. Since `S(n) ≻ n` (function symbol > variable), multiset ordering holds. ✓

**Verdict:** Succeeds. Stays within boundary (purely syntactic, no imported axioms).

---

## (B) Polynomial Interpretation over ℕ

- `[F(x,y,n)] = x + n + 1`
- `[S(n)] = n + 1`, `[Z] = 0`
- `[G(a,b)] = b`

**Rule 1:** `[F(x,y,Z)] = x + 0 + 1 = x + 1` vs `[x] = x`. Difference = 1 > 0. ✓

**Rule 2:** `[F(x,y,S(n))] = x + (n+1) + 1 = x + n + 2` vs `[G(y,F(x,y,n))] = [F(x,y,n)] = x + n + 1`. Difference = 1 > 0. ✓

**Verdict:** Succeeds. Uses only standard arithmetic on ℕ as a meta-level framework — no object-level axioms about S/Z are assumed.

---

## (C) KBO with Uniform Weights w = 1

With precedence F ≻ G (S, Z can be placed anywhere, since they never appear as root of any RHS):

**Rule 1:** `F(x,y,Z) → x`. `weight(LHS) = 2 > 0 = weight(RHS)`. `var(x) ⊆ var(LHS)`. ✓

**Rule 2:** `F(x,y,S(n)) → G(y, F(x,y,n))`. `weight(LHS) = 2 = weight(RHS) = 2`, `vars(RHS) ⊆ vars(LHS)`. F ≻ G applies:
- `F(x,y,S(n)) ≻ y` (weight 2 > 0). ✓
- `F(x,y,S(n)) ≻ F(x,y,n)`: equal weight, same head, multiset `{x,y,S(n)} > {x,y,n}` because `S(n) ≻ n` (weight 1 > 0). ✓

**Verdict:** Succeeds. KBO is a standard syntactic + weight-based technique; no imported axioms.

---

## (D) Dependency Pairs with Subterm Criterion

Defined symbols: F, G. The dependency pairs are:

1. `F#(x, y, S(n)) → F#(x, y, n)`
2. `F#(x, y, S(n)) → G#(y, F(x, y, n))`

DP (2) cannot be extended into an infinite chain (no DP has G# on its LHS, since no rule defines G).

DP (1): project to the third argument, π = {3}. Then `s₃ = S(n)` and `t₃ = n`, and `S(n) ⊵ n` (n is a strict subterm of S(n)). The subterm criterion is satisfied.

**Verdict:** Succeeds. Purely derivable from the rules via the standard DP framework.

---

## (E) Direct Descent Measure

`μ(F(x,y,n)) = depth_S(n) + 1`, `μ(G(a,b)) = μ(b)`, `μ(x) = 0` for variables.

**Rule 1:** `μ(F(x,y,Z)) = depth_S(Z) + 1 = 0 + 1 = 1` vs `μ(x) = 0`. Drop by 1. ✓

**Rule 2:** `μ(F(x,y,S(n))) = depth_S(S(n)) + 1 = depth_S(n) + 2` vs `μ(G(y,F(x,y,n))) = μ(F(x,y,n)) = depth_S(n) + 1`. Drop by 1. ✓

Since μ maps into ℕ (well-founded) and strictly decreases on every rewrite step, no infinite derivation exists.

**Verdict:** Succeeds. The measure uses only structural recursion on terms — no external object-level axioms are imported.
