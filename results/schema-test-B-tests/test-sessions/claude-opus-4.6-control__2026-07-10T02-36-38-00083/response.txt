# Analysis of Proposed Proof Methods

## The Rewrite System

```
F(x, y, Z)    -> x
F(x, y, S(n)) -> G(y, F(x, y, n))
```

This system computes a function where the third argument controls recursion depth, and `G` is applied to `y` and the recursive result.

---

## Method (A): LPO with precedence F > G > S > Z

**Rule 1: F(x, y, Z) → x**
`x` is a subterm of `F(x, y, Z)`, so this follows by the subterm property of LPO. ✓

**Rule 2: F(x, y, S(n)) → G(y, F(x, y, n))**
With F > G, we need F(x, y, S(n)) >_LPO y and F(x, y, S(n)) >_LPO F(x, y, n).
- F(x, y, S(n)) >_LPO y: yes, `y` is a subterm.
- F(x, y, S(n)) >_LPO F(x, y, n): same root F, so compare arguments lexicographically: x = x, y = y, then S(n) >_LPO n (since n is a subterm of S(n)). ✓

**Succeeds?** Yes. **Within boundary?** Yes — LPO is a standard metatheoretic tool requiring only a precedence choice, which is a parameter of the method, not an imported structural axiom.

---

## Method (B): Polynomial interpretation over ℕ

```
[F(x,y,n)] = x + n + 1
[G(a,b)]   = b
[Z]        = 0
[S(n)]     = n + 1
```

**Rule 1: F(x, y, Z) → x:** [LHS] = x + 0 + 1 = x + 1 > x = [RHS]. ✓

**Rule 2: F(x, y, S(n)) → G(y, F(x, y, n)):**
[LHS] = x + (n+1) + 1 = x + n + 2
[RHS] = [G(y, F(x,y,n))] = [F(x,y,n)] = x + n + 1
x + n + 2 > x + n + 1. ✓

**Succeeds?** Yes. **Within boundary?** Yes — polynomial interpretations over ℕ are a standard termination proof technique.

---

## Method (C): KBO with uniform weights w = 1

For KBO, we need weight(lhs) ≥ weight(rhs) and additional conditions.

**Rule 2: F(x, y, S(n)) → G(y, F(x, y, n))**
- w(LHS) = 1 + w(x) + w(y) + 1 + w(n) = w(x) + w(y) + w(n) + 2
- w(RHS) = 1 + w(y) + 1 + w(x) + w(y) + w(n) = w(x) + 2·w(y) + w(n) + 2

w(RHS) - w(LHS) = w(y), which is ≥ 0 and can be > 0. So w(LHS) < w(RHS) in general.

**Succeeds?** No — the weight condition fails.

**Within boundary?** Yes (standard technique), but moot since it fails.

---

## Method (D): Dependency pairs with subterm criterion, projecting to third argument of F

The only dependency pair is:
```
F#(x, y, S(n)) -> F#(x, y, n)
```
(G is not defined, so no DP for G.)

Projecting F# to its third argument: S(n) → n. Since n is a proper subterm of S(n), the subterm criterion is satisfied, proving no infinite chains exist.

**Succeeds?** Yes. **Within boundary?** Yes — dependency pairs with subterm criterion is a standard automated termination technique.

---

## Method (E): Direct descent measure

mu(F(x,y,n)) = depth_S(n) + 1, mu(G(a,b)) = mu(b), mu(x) = 0 for variables.

**Rule 2: F(x, y, S(n)) → G(y, F(x, y, n))**
mu(LHS) = depth_S(S(n)) + 1. mu(RHS) = mu(G(y, F(x,y,n))) = mu(F(x,y,n)) = depth_S(n) + 1.

This requires depth_S(S(n)) > depth_S(n), which holds. ✓

**Rule 1: F(x, y, Z) → x:** mu(LHS) = 0 + 1 = 1 > 0 = mu(x). ✓

However, this measure is not defined on all reachable terms in a rigorous way (it conflates object-level and meta-level reasoning), but the argument is essentially sound.

**Succeeds?** Yes. **Within boundary?** Yes.

---

## Conclusion

**Methods (A), (B), (D), and (E)** all succeed and remain within the benchmark boundary. **Method (C) fails** to prove termination.
