# Analysis of Termination Proof Methods

## System Overview

The TRS has two rules:
1. `F(x, y, Z) → x`
2. `F(x, y, S(n)) → G(y, F(x, y, n))`

F recurses on its third argument, stripping one `S` per step until reaching `Z`.

---

## Method A: LPO with precedence F > G > S > Z

**Rule 1:** `F(x, y, Z) >_lpo x` — Yes, `x` is a direct subterm of the LHS.

**Rule 2:** `F(x, y, S(n)) >_lpo G(y, F(x, y, n))` — Since `F > G` in the precedence, LPO requires the LHS to be strictly greater than each argument of `G`:
- `F(x, y, S(n)) >_lpo y` — Yes, `y` is a subterm.
- `F(x, y, S(n)) >_lpo F(x, y, n)` — Same root `F`; comparing arguments, `x = x`, `y = y`, and `S(n) >_lpo n` (since `n` is a proper subterm of `S(n)`). This holds under either multiset or lexicographic status.

**Result:** Succeeds. LPO is a well-known reduction order.
**Boundary:** Stays within — LPO operates purely on the syntax of the given rules and a chosen precedence.

---

## Method B: Polynomial interpretation `[F(x,y,n)] = x + n + 1`

**Rule checks:**
- Rule 1: `x + 0 + 1 = x + 1 > x` ✓
- Rule 2: `x + (n+1) + 1 = x + n + 2 > x + n + 1` ✓

**Critical flaw:** The interpretation `[F](x, y, n) = x + n + 1` is **not strictly monotone in `y`**. If a rewrite occurs inside the second argument of `F`, e.g., `F(a, s, Z) → F(a, t, Z)`, the measure remains `a + 0 + 1 = a + 1` regardless of how `s` and `t` differ. The interpretation does not define a valid reduction order (closure under contexts fails).

**Result:** Fails. The interpretation cannot guarantee decrease for rewrite steps inside the `y`-argument.
**Boundary:** N/A

---

## Method C: KBO with uniform weights `w(F) = w(G) = w(S) = w(Z) = 1`

With standard variable weight `w_var = 1`:

**Rule 2 weights:**
- LHS: `w(F(x, y, S(n))) = 1 + 1 + 1 + 1 + 1 = 5`
- RHS: `w(G(y, F(x, y, n))) = 1 + 1 + (1 + 1 + 1 + 1) = 6`

The variable `y` appears **twice** on the RHS (once in `G`, once in the inner `F`) but only once on the LHS. Thus `w(LHS) = 5 < 6 = w(RHS)`, violating the fundamental KBO weight condition `w(LHS) ≥ w(RHS)`.

**Result:** Fails.
**Boundary:** N/A

---

## Method D: Dependency pairs with subterm criterion

**Dependency pair** (from Rule 2, the only rule whose RHS contains a defined symbol):
`F#(x, y, S(n)) → F#(x, y, n)`

Projecting onto the third argument of `F#`:
- `π(LHS) = S(n)`
- `π(RHS) = n`

Since `n` is a proper subterm of `S(n)` (i.e., `S(n) ▷ n`), the subterm criterion processor removes this pair. The resulting DP problem is empty, which is trivially finite.

**Result:** Succeeds.
**Boundary:** Stays within — the dependency pair framework with the subterm criterion operates entirely on the given rules.

---

## Method E: Direct descent measure `μ`

**Counterexample:** Consider the term `F(F(x, y, S(Z)), y', Z)`.

Applying Rule 1 at the root: `F(F(x, y, S(Z)), y', Z) → F(x, y, S(Z))`

- `μ(F(F(x,y,S(Z)), y', Z)) = depth_S(Z) + 1 = 0 + 1 = 1`
- `μ(F(x, y, S(Z))) = depth_S(S(Z)) + 1 = 1 + 1 = 2`

The measure **increases** from 1 to 2. Because `μ` does not recurse into the first or second arguments of `F`, eliminating an outer `F` can expose an inner `F`-term with greater `S`-depth, causing `μ` to rise. The claim that "each rewrite step strictly decreases μ" is false.

**Result:** Fails.
**Boundary:** N/A

---

## Summary

| Method | Proves Termination? | Within Boundary? |
|--------|-------------------|-----------------|
| A      | Yes               | Yes             |
| B      | No                | N/A             |
| C      | No                | N/A             |
| D      | Yes               | Yes             |
| E      | No                | N/A             |

**Methods satisfying both conditions: A and D.**
