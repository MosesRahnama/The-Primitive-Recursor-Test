**Raw assessment: yes — strong normalization is establishable from the presented calculus alone**, assuming “the system” is exactly the syntax and `Step` rules shown, with no extra operational principles hidden in the background.

Briefly:

- The rules do **not** introduce any way to recreate an `eqW`, `merge`, `integrate(delta _)`, or `recΔ _ _ (delta _)` redex in a cyclic manner.
- The only rule that expands syntactic size is

  ```lean
  recΔ b s (delta n) ↦ app s (recΔ b s n)
  ```

  but the recursive argument strictly decreases from `delta n` to `n`. The duplication of `s` can increase size, but it does not create a cycle.
- The unguarded rule

  ```lean
  eqW a b ↦ integrate (merge a b)
  ```

  overlaps with

  ```lean
  eqW a a ↦ void
  ```

  so the system is nondeterministic and likely non-confluent, but this overlap does **not** by itself threaten termination.
- A standard simplification ordering, e.g. lexicographic path ordering / recursive path ordering, can orient all rules. One possible precedence has `eqW` above `integrate` and `merge`, and `recΔ` above `app`; the `recΔ` successor rule is oriented because the third argument goes from `delta n` to `n`.

So the system can be shown strongly normalizing without adding guards such as `a ≠ b` to `R_eq_diff`, without adding rewrite rules, and without importing object-level axioms.

One caveat: the Lean file defines only the root-step relation `Step`. It does **not** define contextual closure, i.e. rewriting inside subterms. For the root-step relation, termination is even more immediate. If one separately defines the usual compatible/contextual closure of these rules, strong normalization still appears provable by a standard path-ordering argument, but that closure itself is extra structure not literally present in the file.
