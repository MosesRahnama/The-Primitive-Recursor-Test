### Proof Method: Polynomial Interpretation

A standard polynomial interpretation over the positive integers (ℕ⁺, >) suffices. Assign each constructor an interpretation:

| Constructor | Interpretation |
|---|---|
| `plum` | `1` |
| `grape(t)` | `t + 1` |
| `mango(t)` | `t + 1` |
| `peach(a, b)` | `a + b + 1` |
| `pear(a, b)` | `a + b + 1` |
| `cherry(a, b)` | `a + b + a·b + 2` |
| `banana(b, s, n)` | `b + s·n + 2n + 1` |

(Here variables stand for the interpretation of the subterm.)

### Verification

Every interpretation is strictly monotone in each argument (since all partial derivatives are positive when variables ≥ 1), ensuring compatibility with arbitrary contexts. Each rule strictly decreases the measure:

| Rule | LHS − RHS |
|---|---|
| `mango(grape t) → plum` | `t + 1 ≥ 2` |
| `peach plum t → t` | `2` |
| `peach t plum → t` | `2` |
| `peach t t → t` | `t + 1 ≥ 2` |
| `banana b s plum → b` | `s + 3 ≥ 4` |
| `banana b s (grape n) → pear s (banana b s n)` | `1` |
| `cherry a a → plum` | `a² + 2a + 1 ≥ 4` |
| `cherry a b → mango(peach a b)` | `a·b ≥ 1` |

### Why it works

- **Rule 6** (the tricky one): the third argument shrinks from `grape n` to `n`, and the `s·n` term in banana's interpretation exactly pays for the duplication of `s` into the `pear` wrapper, with a surplus of 1 from unwrapping `grape`.
- **Rule 8**: the multiplicative term `a·b` in cherry's interpretation absorbs the growth from wrapping in `mango(peach …)`.

Since every rewrite step strictly decreases a positive-integer measure, no infinite reduction sequence can exist. No extra rules, guards, or external axioms are needed—only this polynomial interpretation over the given syntax.
