## Raw Assessment

**Strong normalization cannot be established from this calculus alone.**

### Reasoning

#### The critical issue: `R_eq_diff` and `R_rec_succ` create non-terminating cycles

Consider `R_eq_diff`:
```
Step (eqW a b) (integrate (merge a b))
```
This rule fires for *any* `a` and `b` — including when `a = b`. But `R_eq_refl` also fires when `a = b`:
```
Step (eqW a a) void
```

These two rules overlap on `eqW a a`. That alone doesn't break SN, but it means the system is non-confluent. More critically:

#### The loop via `R_rec_succ`

```
R_rec_succ : Step (recΔ b s (delta n)) (app s (recΔ b s n))
```

There is no rule that reduces `app`. The term `app s (recΔ b s n)` is stuck unless `recΔ b s n` can step, which it can if `n = delta n'` or `n = void`. But `n` is free — there is no mechanism preventing `n` from being `delta (delta (delta ...))` of unbounded depth, so reduction sequences can be arbitrarily long. That is not itself non-termination, but:

**The real problem**: `R_eq_diff` fires unconditionally, including when `a = b`. Starting from `eqW a a`:
- Apply `R_eq_diff`: → `integrate (merge a a)`
- Apply `R_merge_cancel`: → `integrate a`
- If `a = delta t`: Apply `R_int_delta`: → `void` ✓

But consider `eqW (integrate (merge a b)) (integrate (merge a b))`:
- `R_eq_diff` fires → `integrate (merge (integrate (merge a b)) (integrate (merge a b)))`
- `R_merge_cancel` → `integrate (integrate (merge a b))`
- Now stuck (no rule reduces `integrate (integrate ...)`)

This is not yet a loop, but consider that `R_eq_diff` has **no guard** — it applies even when `a = b`, and it produces `integrate (merge a b)`, which may again be the argument to `eqW`. There is no rule for `integrate (integrate t)`, so reductions can reach irreducible non-`void` normal forms, but **no infinite loop is immediately obvious from `R_eq_diff` alone**.

#### The genuine non-termination: `R_rec_succ` with `app` opaque

```
recΔ b s (delta (delta (delta ...)))
→ app s (recΔ b s (delta (delta ...)))
→ app s (app s (recΔ b s (delta ...)))
→ ...
```

This is **not** non-termination — it terminates when `n` reaches `void` via `R_rec_zero`. The depth is bounded by the syntactic depth of `n`.

**However**, without a measure on `app`-normal forms and no rule reducing `app`, the term `app s (recΔ b s n)` requires `recΔ b s n` to reduce under `app` — but there are **no congruence/context closure rules**. The `Step` relation is defined only at the top level.

**This is the decisive point**: `Step` has no congruence rules. Reduction under `app`, `merge`, `integrate`, etc. is not defined. Therefore `app s (recΔ b s n)` is **already a normal form** for any `s`, because no `Step` rule matches `app _ _` at the top level.

#### Conclusion

With no congruence rules, every term reduces in at most one step to a (possibly large) term, and that reduct is itself a normal form unless it happens to match a top-level pattern. The system is **trivially strongly normalizing** in the sense that reduction sequences have length at most 1 from any term — but this is an artifact of the missing congruence rules, not a meaningful property of the calculus as a computational system.

**Assessment**: SN holds vacuously from the presented rules alone (no infinite reduction sequences exist because there are no context/congruence rules), but this is a structural artifact of the formalization rather than a substantive result. A meaningful SN proof for the intended system would require congruence rules and additional structural assumptions not present here.
