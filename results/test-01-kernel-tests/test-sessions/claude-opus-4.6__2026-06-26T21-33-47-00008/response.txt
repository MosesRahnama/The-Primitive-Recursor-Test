# Assessment: Strong Normalization Does NOT Hold

Strong normalization (SN) of this system cannot be established from the presented calculus alone. The system is **not strongly normalizing** — in fact, it admits infinite reduction sequences.

## Key Reasoning

The critical problem lies in the interaction between **R_eq_diff** and **R_eq_refl**:

**Rule R_eq_diff** applies to `eqW a b` for *any* `a` and `b` — including when `a = b`. There is no side condition requiring `a ≠ b`. Since `Step` is defined inductively with:

```
| R_eq_refl : ∀ a, Step (eqW a a) void
| R_eq_diff : ∀ a b, Step (eqW a b) (integrate (merge a b))
```

Both rules apply when `a = b`. In particular, `R_eq_diff` applies to `eqW a a`, producing:

```
eqW a a  →  integrate (merge a a)  →  integrate a  →  ...
```

Wait — this terminates. Let me reconsider more carefully by looking for actual non-termination.

**The real issue is R_rec_succ.** Consider:

```
recΔ b s (delta n)  →  app s (recΔ b s n)
```

This rule does not reduce the overall term complexity in any obvious way because `s` is duplicated (it appears both as an argument to `app` and inside the recursive call `recΔ b s n`). If `s` itself contains a `delta`, the term can grow.

More critically, consider a self-referential term. Let `t = recΔ void (delta void) (delta (delta void))`:

```
recΔ void (delta void) (delta (delta void))
→ app (delta void) (recΔ void (delta void) (delta void))
→ app (delta void) (app (delta void) (recΔ void (delta void) void))
→ app (delta void) (app (delta void) void)
```

This terminates. But there is no rule reducing `app`, so `app` terms just accumulate — they are normal once their subterms are normal. The third argument to `recΔ` strictly decreases (one `delta` is peeled off each time), so `recΔ` alone terminates.

**Revisiting R_eq_diff more carefully:** Since there is **no guard** `a ≠ b`, the overlap with R_eq_refl means the system is **non-deterministic** but both branches still terminate for `eqW a a`:
- Via R_eq_refl: `void` (done)
- Via R_eq_diff: `integrate (merge a a) → integrate a` (done, since no rule applies to `integrate` of a non-`delta` term)

**Re-examining for non-termination:** Actually, after careful analysis, all rules either:
1. Reduce the third argument of `recΔ` by one `delta` layer (R_rec_succ/R_rec_zero)
2. Eliminate a constructor (R_int_delta, R_merge_void_*, R_merge_cancel, R_eq_refl)
3. Replace `eqW` with `integrate (merge ...)` (R_eq_diff — bounded application)

No rule reduces under subterms (there are no congruence/compatibility rules), so `Step` is a **root reduction** only. Without congruence closure, a term like `app (delta void) void` is already in normal form — no rule looks inside subterms.

Since `Step` only applies at the root and each rule either eliminates or peels a constructor, and `recΔ` strictly decreases its third argument (with no congruence rules to re-trigger reductions in subterms), every reduction sequence is finite.

## Revised Assessment: Strong Normalization HOLDS

Yes, strong normalization can be established. A suitable measure is a multiset/lexicographic ordering combining:
1. The count of `recΔ` weighted by the depth of `delta`-nesting in their third argument
2. The total number of `eqW`, `merge`, and `integrate` constructors

Each rule strictly decreases this measure. Crucially, **no congruence rules** are present, so reductions happen only at the root of the term, and R_rec_succ's output (`app s (recΔ b s n)`) contains no new redex at the root (since `app` heads no left-hand side). The `recΔ` inside has a strictly smaller third argument.

**Final answer: Yes**, strong normalization is establishable from the presented calculus alone, using a straightforward well-founded measure argument, without any additional axioms or assumptions.
