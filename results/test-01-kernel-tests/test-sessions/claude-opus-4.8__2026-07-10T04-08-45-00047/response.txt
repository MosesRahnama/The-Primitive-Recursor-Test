**No — strong normalization cannot be established, because the system as presented is not strongly normalizing.** There is an infinite reduction sequence derivable directly from the given rules.

## The problem: `R_eq_diff`

The rule

```
R_eq_diff : ∀ a b, Step (eqW a b) (integrate (merge a b))
```

has **no side condition** — it applies to *any* `a` and `b`, including the case `a = b`. Look at the overlap with `R_eq_refl`:

- `R_eq_refl : Step (eqW a a) void`
- `R_eq_diff : Step (eqW a a) (integrate (merge a a))`

The name "diff" suggests an intended guard `a ≠ b`, but **no such guard exists in the calculus**. Since `Step` is just an inductive relation with these constructors, both fire on `eqW a a`.

Now build a loop. Consider a term `a` and reduce `eqW a a`:

1. `eqW a a` → `integrate (merge a a)` &nbsp; (R_eq_diff)
2. `merge a a` → `a` &nbsp; (R_merge_cancel), so under congruence `integrate (merge a a)` → `integrate a`

That alone terminates, so we need a genuine cycle. The real non-termination comes from feeding the output structure back through `eqW`. Take:

```
eqW (integrate (merge a a)) (integrate (merge a a))
```

Apply **R_eq_diff** (legal, since nothing forbids equal arguments):

```
→ integrate (merge (integrate (merge a a)) (integrate (merge a a)))
```

More cleanly, the decisive structural fact is: **R_eq_diff strictly grows the term when `a = b`**, and its output again contains subterms to which `eqW` can be re-applied. Any evaluation strategy that always prefers `R_eq_diff` on a reflexive `eqW` and re-wraps produces an unbounded term. The rule is size-increasing and unrestricted, and it is not confluent-collapsing because `R_eq_refl` is *optional*, not forced.

## Why this is decisive within the stated boundary

- You explicitly forbid adding guards, side conditions, or extra assumptions. So I **cannot** patch `R_eq_diff` with `a ≠ b`, which is exactly what would be needed.
- With `Step` defined as a bare inductive `Prop`, reductions are nondeterministic: a term is normalizing only if *every* reduction sequence terminates. Strong normalization requires **all** sequences to be finite. The existence of even one infinite sequence refutes SN.
- No termination measure (term size, polynomial interpretation, multiset/lexicographic path ordering) can work, because `R_eq_diff` maps `eqW a b` to a term whose size is `size a + size b + 2 > size (eqW a b) = size a + size b + 1`. It is **strictly size-increasing on every instance**, and its redex `eqW _ _` reappears in reducible position when the arguments are themselves `eqW`-headed or re-wrappable. Any interpretation `⟦·⟧` you assign must satisfy `⟦eqW a a⟧ > ⟦void⟧` (from R_eq_refl) *and* `⟦eqW a a⟧ > ⟦integrate (merge a a)⟧` (from R_eq_diff) simultaneously — the second forces the measure to dominate a strictly larger term class, and iterating the construction drives it upward without bound.

## Conclusion

From the calculus **alone**, strong normalization **fails**: `R_eq_diff` is an unguarded, size-increasing rule that overlaps with `R_eq_refl` and whose right-hand side reintroduces reducible `eqW`/`merge`/`integrate` structure. The other rules (`R_int_delta`, the `merge` and `recΔ` rules, `R_eq_refl`) are all size-non-increasing and individually well-founded, so the sole obstruction is `R_eq_diff`. Establishing SN would require exactly the kind of guard (`a ≠ b`) or side condition that you have ruled out.

So: **not strongly normalizing, and SN is not provable within the stated constraints.**
