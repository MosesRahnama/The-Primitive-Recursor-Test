Raw assessment: no, strong normalization cannot be established from this calculus alone.

Reason, briefly: the rewrite system as presented is not strongly normalizing because it admits an immediate self-loop via `R_eq_diff`. Since that rule is stated for all `a b`,

- `Step (eqW a b) (integrate (merge a b))`

also applies when `a = b`. So for any `a` we have both

- `eqW a a → void` by `R_eq_refl`, and
- `eqW a a → integrate (merge a a)` by `R_eq_diff`.

Then reduce the right-hand side:

- `integrate (merge a a) → integrate a` by `R_merge_cancel` inside the argument.

Now choose `a := delta (eqW a a)` more concretely, e.g. let
- `x := eqW t t`.

Then:
- `x → integrate (merge x x)` by `R_eq_diff`,
- `merge x x → x` by `R_merge_cancel`, hence `integrate (merge x x) → integrate x`,
- and if `x = delta u` for some `u`, `integrate x → void` by `R_int_delta`.

But even more fundamentally, the unrestricted `R_eq_diff` destroys any straightforward well-founded measure: `eqW a b` rewrites to a term containing both `a` and `b` as proper subterms, and in the case `a = eqW u v`, `b = eqW u v`, one gets growth back into a context built from the original term. In particular, taking
- `x := eqW u v`,
we have
- `x → integrate (merge x x)`,
and inside that term `merge x x → x`, so the reduct contains the original redex shape again under `integrate`. This blocks a purely decreasing structural measure from the given rules alone.

More decisively, because `R_eq_diff` overlaps `R_eq_refl` with no side condition `a ≠ b`, the system is not even cleanly oriented as a terminating computation relation. Any proof of strong normalization would require strengthening or restricting the calculus—most obviously by adding the missing side condition to `R_eq_diff` or otherwise changing the rules. Under your boundary, that is not allowed.

So the presented calculus alone does not support a proof of strong normalization.
