**The critical problem: R_eq_diff creates divergence**

Consider the interaction between `R_eq_diff` and `R_eq_refl`:

- `R_eq_refl`: `eqW a a → void`
- `R_eq_diff`: `eqW a b → integrate (merge a b)`

Both rules apply to `eqW a a` (when `a = b`). This is a **critical pair** — non-confluent overlap. But more importantly for strong normalization:

**Divergence via R_rec_succ:**

`R_rec_succ` rewrites `recΔ b s (delta n) → app s (recΔ b s n)`. This peels off one `delta`, but there is no rule that reduces bare `app` applications or bounds recursion depth. The term `recΔ b s (delta (delta (delta ...)))` requires a finite number of steps, so recursion itself is terminating *if* the `n` argument is structurally smaller.

However, the **real problem** is `R_eq_diff`:

```
eqW a b → integrate (merge a b)
```

There is no restriction that `a ≠ b`. So `eqW a a` rewrites by `R_eq_diff` to `integrate (merge a a)`, which by `R_merge_cancel` gives `integrate a`. If `a = delta t`, then `R_int_delta` applies giving `void`. But if `a = eqW c c`, we get:

```
eqW (eqW c c) (eqW c c)
  →[R_eq_diff] integrate (merge (eqW c c) (eqW c c))
  →[R_merge_cancel] integrate (eqW c c)
```

Now `integrate (eqW c c)` has no rule that fires directly (only `R_int_delta` applies to `integrate (delta t)`), so this particular path terminates. But:

```
eqW a a →[R_eq_diff] integrate (merge a a) →[R_merge_cancel] integrate a
         →[R_eq_refl] void
```

This is a **non-confluent** system (two rules apply to `eqW a a`), but both paths terminate here. The deeper issue:

**R_rec_succ is not obviously terminating** because `app s (recΔ b s n)` — the `app` node is not reduced by any rule. The term grows: `recΔ b s (delta (delta void))` → `app s (recΔ b s (delta void))` → `app s (app s (recΔ b s void))` → `app s (app s b)`. This terminates because `delta` is peeled and no rule recreates `delta` from nothing.

**However**, `R_eq_diff` combined with `R_rec_succ` can interact: if `b` or `s` contain `eqW` subterms, `R_eq_diff` can produce `merge` and `integrate` terms, but cannot recreate `delta` or `recΔ` terms from scratch.

**Conclusion:**

The system *appears* to be strongly normalizing on structural grounds — no rule increases the count of `recΔ`/`delta` constructors, and `R_rec_succ` strictly decreases `delta`-depth. However, **the calculus as presented lacks**:

1. A well-founded measure that is explicitly proven invariant (no such proof is given)
2. Confluence (R_eq_refl and R_eq_diff overlap on `eqW a a` without resolution)
3. Any termination certificate within the file

**From the presented file alone** — containing only syntax and rewrite rules with no termination proof, no measure function, no well-foundedness argument, and a non-confluent critical pair — **strong normalization cannot be established**. The file provides no proof infrastructure whatsoever; it only declares the system. Whether SN *holds* as a mathematical fact is plausible but unproven, and the non-confluence of `R_eq_diff`/`R_eq_refl` means standard decreasing diagrams would need careful case analysis not present here.

**Assessment: No, strong normalization is not established by this file.**
