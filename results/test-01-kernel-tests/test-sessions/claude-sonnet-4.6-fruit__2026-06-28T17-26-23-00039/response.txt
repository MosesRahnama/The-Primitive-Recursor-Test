## Raw Assessment

**Strong normalization cannot be established from this calculus alone without additional structural assumptions.**

Here is the reasoning:

### What the calculus provides

The rewrite rules are:
1. `mango (grape t) → plum`
2. `peach plum t → t`
3. `peach t plum → t`
4. `peach t t → t`
5. `banana b s plum → b`
6. `banana b s (grape n) → pear s (banana b s n)`
7. `cherry a a → plum`
8. `cherry a b → mango (peach a b)` (when `a ≠ b`)

### The critical problem: Rule 6 and unbounded unfolding

Rule 6 is the dangerous one:
```
banana b s (grape n) → pear s (banana b s n)
```

This peels off one `grape` layer from the third argument and produces a `pear s (banana b s n)`. If `n` itself is `grape n'`, then `banana b s n` can step again by rule 6, and so on. This is structurally decreasing in the third argument — **if** the third argument is a finite `grape`-tower terminated by `plum`.

However, note that **`pear` has no rewrite rules**. The `pear` constructor accumulates results but is never reduced. So terms of the form `pear s (pear s (pear s ... (banana b s plum)...))` do terminate via rule 5 (`banana b s plum → b`). In isolation, rule 6 **is** terminating because it strictly decreases the `grape`-depth of the third argument.

### The critical problem: Rule 8 interaction

Rule 8 fires when `a ≠ b` (a **propositional** side condition on object-level term inequality). This produces `mango (peach a b)`. Rule 2/3 can simplify `peach` if one argument is `plum`, but in general `mango (peach a b)` is **stuck** unless `peach a b` reduces to `grape t` for some `t` — which it cannot, since `peach` has no rules producing `grape`.

More critically: the side condition `a ≠ b` is a **meta-level** (propositional) condition. This is not a purely syntactic guard. The system as written in Lean relies on decidability or proof-irrelevance of term equality to fire rule 8. **This is an imported structural assumption** (decidable equality on `Trace`) that is not derivable from the rewrite rules themselves.

### The deeper issue: no measure is definable from the rules alone

To prove strong normalization, one typically defines a well-founded measure (e.g., a size function, a polynomial interpretation, or a lexicographic order) and shows every rule strictly decreases it. The obstacle here:

- **Rule 8** produces `mango (peach a b)` from `cherry a b`. The size of `mango (peach a b)` is **strictly larger** than `cherry a b` if we use naive term size (cherry has 2 subterms; mango(peach(a,b)) has 3 nodes plus a and b). Any naive size measure **increases** under rule 8.
- One might use a different measure, but rule 8 combined with rules 1–4 can create a chain: `cherry a b → mango (peach a b)`, and `peach` with general arguments has no further reductions, leaving `mango (peach a b)` in normal form — so the chain does terminate in this specific path. But establishing this requires case analysis on whether `peach a b` ever rewrites to `grape t`, which it structurally cannot — but **proving** this requires induction on term structure, which is a structural axiom external to the rewrite rules.

### Conclusion

**No.** Strong normalization of this system **cannot** be established from the rewrite rules alone without importing:
1. A well-founded induction principle on `Trace` (structural recursion — a metatheoretic assumption),
2. Decidable equality on `Trace` (needed to evaluate the `a ≠ b` side condition in rule 8),
3. A size/complexity measure whose well-foundedness must be imported from arithmetic or set theory.

The calculus as presented is **likely terminating** in practice (no evident cycles, third-argument decreasing in rule 6, rule 8 produces stuck terms), but the **proof** of strong normalization necessarily requires structural induction on `Trace` and decidable equality — neither of which is derivable from the rewrite rules themselves. These are irreducible metatheoretic imports.
