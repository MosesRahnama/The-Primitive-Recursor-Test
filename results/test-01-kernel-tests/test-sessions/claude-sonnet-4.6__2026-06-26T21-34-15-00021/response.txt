## Raw Assessment

**Strong normalization cannot be established from this calculus alone.**

### Reasoning

**The critical problem: R_eq_diff creates divergence**

Consider the interaction between `R_eq_diff` and `R_eq_refl`. The rule:

```
R_eq_diff : ∀ a b, Step (eqW a b) (integrate (merge a b))
```

applies to *any* `a b`, including when `a = b`. So for any term `t`, we have:

- `R_eq_refl`:  `eqW t t → void`
- `R_eq_diff`:  `eqW t t → integrate (merge t t)`

This is a non-deterministic choice, but that alone doesn't break SN. The question is whether any *single* reduction sequence is infinite.

**The deeper issue: R_rec_succ introduces growth without a measure**

```
R_rec_succ : ∀ b s n, Step (recΔ b s (delta n)) (app s (recΔ b s n))
```

This rule strips one `delta` from the third argument and produces `app s (recΔ b s n)`. If `n` itself contains `delta` constructors, this continues. This is fine for concrete ground terms — the `delta`-depth of `n` strictly decreases.

**However**, there is no typing discipline or size constraint preventing `s` from being a term that, when applied via `app`, reconstructs a larger `recΔ` redex. Since `app` has **no reduction rule** in the calculus (there is no `R_app_*` rule), `app s (recΔ b s n)` is a stuck term. This means `recΔ` terminates trivially by getting stuck, not by strong normalization in the meaningful sense.

**The actual fatal issue: R_eq_diff + R_merge_cancel loop**

```
eqW t t 
  →[R_eq_diff]  integrate (merge t t)
  →[R_merge_cancel]  integrate t
```

Now if `t = delta u`:
```
integrate (delta u) →[R_int_delta] void
```

That terminates. But if `t = eqW a a`:
```
integrate (eqW a a)
```
is stuck (no rule for `integrate` of non-`delta` terms). So no loop there either.

**Re-examining for actual non-termination:**

There is **no rule for `app`**, so any term headed by `app` is irreducible. The `recΔ` recursion strictly decreases the `delta`-depth of its third argument, terminating in `R_rec_zero`. The `integrate`/`merge`/`eqW` rules all reduce term size.

**Revised conclusion:**

Actually, a *syntactic* argument nearly works: define a measure combining constructor count and `delta`-depth. Every rule strictly decreases this measure *except* `R_eq_diff` on `eqW a a`, which goes to `integrate (merge a a)` — larger than `void` but not larger than `eqW a a` in constructor count (eqW a a has size 2|a|+1; integrate(merge a a) has size 2|a|+2 — **this is strictly larger**).

So `R_eq_diff` can increase term size, and since it applies even when `a = b`, and the result `integrate (merge a a) → integrate a` (via merge_cancel) which might expose new `eqW` redexes if `a` contains them — **but only finitely many**, since `a` is a fixed finite term.

**Final assessment:** Strong normalization *likely holds* for ground terms due to the absence of `app` reduction rules (preventing β-like loops) and the finite structure of all terms, but **it cannot be established cleanly from the calculus alone** without a careful well-founded measure or type-theoretic argument external to the stated rules. The `R_eq_diff` rule violating naive size measures means a straightforward syntactic SN proof fails, and the calculus provides no intrinsic termination certificate. A proof would require importing a well-foundedness argument (e.g., a multiset or lexicographic ordering) that is **not derivable from the given syntax and rules alone**.
