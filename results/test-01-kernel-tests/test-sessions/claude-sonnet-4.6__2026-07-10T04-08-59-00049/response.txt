## Raw Assessment

**Strong normalization cannot be established from this calculus alone.**

### Reasoning

**The critical problem: R_eq_diff creates divergence cycles.**

Consider the interaction between `R_eq_diff` and `R_rec_succ`:

**Cycle via `recΔ`:**

Take `t = recΔ b s (delta n)`. By `R_rec_succ`:
```
recΔ b s (delta n)  →  app s (recΔ b s n)
```
This alone is fine if `n` is structurally smaller. But consider what happens when `s` itself is constructed to reproduce the recursive call — there is no guard preventing `app s (recΔ b s n)` from reducing back to something of the same or greater size, because `app` has no reduction rules shown, meaning it is **stuck** — but that also means the term does not normalize to a value either.

**More directly — the `R_eq_diff` / `R_int_delta` interaction:**

`R_eq_diff` says: `eqW a b → integrate (merge a b)`.  
`R_eq_refl` says: `eqW a a → void`.

These two rules overlap on `eqW a a`: both `R_eq_refl` and `R_eq_diff` apply. Under `R_eq_diff`, `eqW a a → integrate (merge a a)`. Then `R_merge_cancel` gives `integrate a`. If `a = delta t`, then `R_int_delta` gives `void`. Fine.

But what if `a` itself is `eqW c c`? Then `integrate (eqW c c)` has no rule. That's just stuck.

**The actual non-termination:** Consider `R_rec_succ` with no base that reaches `void`:

```
recΔ b s (delta (delta (delta ...)))
```
Each step of `R_rec_succ` peels one `delta`, but if the argument is infinite... except terms are finite inductively.

Wait — terms are **finite** by the inductive definition of `Trace`. So `R_rec_succ` always decreases the structural size of the `delta`-nesting.

**Reconsidering:** With *finite* terms, `R_rec_succ` terminates by structural induction on the third argument. `R_int_delta`, `R_merge_*`, `R_eq_refl` are all clearly terminating individually.

**The problem is `R_eq_diff`:** `eqW a b → integrate (merge a b)`. The *right-hand side* `integrate (merge a b)` is **strictly larger** (more constructors) than `eqW a b`. This means no standard measure on term size is monotonically decreasing.

Specifically, if `a = delta t` and `b = delta t` (so `a = b`), then `R_eq_diff` applies and gives `integrate (merge (delta t) (delta t))`, which is larger. This is not a cycle per se (the term changes), but it breaks size-decreasing measures.

More critically: can `R_eq_diff` cause **non-termination**? We need a reduction sequence that loops. Take:

```
eqW (delta void) (delta void)
```
- `R_eq_diff`: → `integrate (merge (delta void) (delta void))`  
- `R_merge_cancel`: → `integrate (delta void)`  
- `R_int_delta`: → `void`

This terminates. But `R_eq_refl` also applies to the start, giving `void` directly. No loop here.

**Conclusion:**

Because all terms are **finitely constructed** and there is **no rule that introduces a subterm of the original redex back as a redex in a larger context cyclically**, a termination argument based on a *lexicographic combination* of (number of `eqW` nodes, total size) can be made to work — `R_eq_diff` increases size but eliminates an `eqW` node, and no rule introduces new `eqW` nodes.

**Therefore: Strong normalization IS plausibly establishable from the calculus alone**, using a lexicographic measure: first count `eqW` subterms (strictly decreased by both `R_eq_refl` and `R_eq_diff`), then total term size (decreased by all other rules). No rule creates new `eqW` nodes. This measure is well-founded and strictly decreasing under all rules.

**Final verdict: Strong normalization holds, and can be proven from the given rules alone using a two-component lexicographic measure on (eqW-count, term size), with no additional axioms required.**
