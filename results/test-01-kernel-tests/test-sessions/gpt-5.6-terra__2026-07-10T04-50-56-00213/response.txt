In fact, the displayed `Step` relation is only a root-step relation—there are no congruence/context closure rules in the file—so termination is already quite direct. But even if one considers the usual compatible closure allowing reductions inside subterms, the system remains strongly normalizing.

A standard recursive path ordering suffices. For example, choose a precedence containing

```text
recΔ  ≻ app
eqW   ≻ integrate ≻ merge
```

with `void` below the relevant defined symbols; the remaining constructors may be placed arbitrarily consistently. Use lexicographic status for `recΔ`.

Then every rule decreases:

- `merge void t → t`, `merge t void → t`, and `merge t t → t` decrease to a proper subterm.
- `recΔ b s void → b` decreases to a subterm.
- `recΔ b s (delta n) → app s (recΔ b s n)` decreases because `recΔ ≻ app`, and the recursive occurrence is smaller lexicographically: its third argument is `n`, strictly below `delta n`.
- `eqW a a → void` decreases by precedence.
- `eqW a b → integrate (merge a b)` decreases using `eqW ≻ integrate ≻ merge`; the left side dominates both `a` and `b`.
- `integrate (delta t) → void` likewise decreases.

Recursive path ordering is well-founded on these finite first-order terms, so there can be no infinite rewrite sequence. No additional structural axioms, guards, object-level assumptions, or extra rewrite rules are needed.
