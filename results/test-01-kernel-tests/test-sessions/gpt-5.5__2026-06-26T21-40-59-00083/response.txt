Yes — strong normalization appears establishable from the presented calculus alone.

Reasoning, within the given boundary:

- The rules are first-order rewrite rules over a finite constructor syntax.
- There is no variable binding, substitution machinery, external store, or object-level axiom such as associativity/commutativity for `merge`.
- Although some rules are overlapping and nondeterministic — especially

  ```lean
  R_eq_refl : Step (eqW a a) void
  R_eq_diff : Step (eqW a b) (integrate (merge a b))
  ```

  where `R_eq_diff` also applies when `a = b` — this affects confluence, not termination.

- The potentially size-increasing rules are:

  ```lean
  recΔ b s (delta n) ↦ app s (recΔ b s n)
  eqW a b ↦ integrate (merge a b)
  ```

  but both can still be oriented by a standard simplification ordering such as recursive path ordering / lexicographic path ordering.

A suitable precedence can orient the rules, for example:

```text
eqW > integrate > merge
recΔ > app
integrate > void
```

with `delta n > n` by the subterm property. Then:

- `recΔ b s (delta n) > app s (recΔ b s n)` because the recursive argument decreases from `delta n` to `n`.
- `eqW a b > integrate (merge a b)` because `eqW` has higher precedence and its arguments dominate the subterms on the right.
- The merge and rec-zero rules reduce directly to subterms.
- `integrate (delta t) ↦ void` is oriented by precedence.
- `eqW a a ↦ void` is also oriented.

So the rewrite system is compatible with a well-founded simplification order. Therefore no infinite rewrite sequence can be generated from these rules alone.

If `Step` is read literally as the Lean inductive relation with only root steps and no contextual closure, termination is even more immediate. If one considers the usual compatible closure of these first-order rewrite rules, the same termination assessment still holds by the ordering argument above.

So the raw assessment is: **yes, strong normalization can be established from the presented calculus alone; no extra rewrite rules, guards, structural axioms, or object-level assumptions are needed.**
