# Assessment: Strong Normalization Cannot Be Established From This Calculus Alone

**My assessment is that strong normalization does NOT hold for this system.**

## Reasoning

The critical issue is rule `R_apple_orange`:

```
Step (banana b s (grape n)) (pear s (banana b s n))
```

This rule is **non-erasing and potentially size-increasing**. Let me trace through what happens with a concrete term to check for non-termination.

Consider the interaction between `R_apple_orange` and other rules. The right-hand side `pear s (banana b s n)` contains `banana b s n` as a subterm. If we then have congruence closure (rewriting under context), the `banana` subterm can be further rewritten. But wait — the system as stated only defines **root rewrite steps**, not congruence/context closure. Let me re-examine.

The `Step` relation as defined is only a **root step** relation — there are no congruence rules (no rules of the form "if `Step a b` then `Step (grape a) (grape b)`" etc.). So rewriting can only happen at the root of a term.

With only root-level rewriting, let me check if any cycle or infinite chain is possible:

**R_apple_orange** rewrites `banana b s (grape n)` → `pear s (banana b s n)`. The result is a `pear` node at the root. The only rules for `pear` are `R_peach_plum_left`, `R_peach_plum_right`, and `R_peach_cancel` — but these apply to `peach`, not `pear`. Note the distinction: `peach` and `pear` are **different constructors**.

There are **no rewrite rules with `pear` as the head symbol on the left-hand side**. So once we reach a `pear`-rooted term, no further root rewriting is possible.

Similarly, checking all other rules:
- `R_mango_grape`: reduces to `plum` (terminal)
- `R_peach_plum_left/right/cancel`: reduce the term or return a subterm
- `R_banana_zero`: returns `b` (a subterm)
- `R_cherry_refl`: reduces to `plum`
- `R_cherry_diff`: produces `mango (peach a b)`, which can be further rewritten only if it matches `mango (grape t)` — but `peach a b` is not `grape t`, so no further root step applies.

**Every rewrite chain is finite.** Each rule either produces a constructor with no matching left-hand side (`pear`, `plum`), or produces a term that is strictly smaller, or produces a term whose head constructor has limited further rewrites.

More formally, define a measure: assign each term a weight where `banana b s (grape n)` has weight strictly greater than the weight of `pear s (banana b s n)` under a suitable polynomial interpretation. For instance, let `W(banana b s t) = W(b) + W(s) + W(t) + W(s)·W(t) + 1` and `W(pear s t) = W(s) + W(t) + 1`, `W(grape t) = W(t) + 1`. Then `W(banana b s (grape n)) = W(b) + W(s) + W(n) + 1 + W(s)·(W(n)+1) + 1` while `W(pear s (banana b s n)) = W(s) + W(banana b s n) + 1 = W(s) + W(b) + W(s) + W(n) + W(s)·W(n) + 1 + 1`. These are equal, so we need a more careful interpretation — but the key structural point is that the `grape` wrapper is consumed and never regenerated by any rule.

## Revised Assessment: **Yes, strong normalization holds.**

Since no rule **produces** a `grape` at the root of a position that could feed back into `R_apple_orange` or `R_mango_grape`, and without congruence closure, every rule either terminates immediately or consumes a `grape` constructor. The system is strongly normalizing.

**Strong normalization can be established from the presented calculus alone**, using the observation that (1) only root steps are defined, (2) no rule produces a left-hand-side head pattern that enables an infinite chain, and (3) a suitable well-founded measure (e.g., counting `grape` constructors plus term size) strictly decreases at each step.
