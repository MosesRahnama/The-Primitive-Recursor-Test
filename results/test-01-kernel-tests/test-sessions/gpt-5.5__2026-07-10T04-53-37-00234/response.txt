Yes — my raw assessment is that strong normalization can be established from the presented calculus alone.

The main caveat is interpretive:

- **For the Lean relation exactly as written**, `Step` only rewrites at the root. There are no congruence/context rules. For that relation, termination is quite direct.
- **Even if one takes the rules as a standard first-order TRS closed under contexts**, strong normalization still appears provable without adding guards, side conditions, structural axioms, or object-level assumptions.

A standard simplification ordering such as recursive path ordering can orient the rules. For example, take a precedence including roughly:

```text
recΔ  > app
eqW   > integrate
eqW   > merge
integrate > void
```

with the usual subterm property. Then:

- `integrate (delta t) → void` decreases by precedence.
- `merge void t → t`, `merge t void → t`, `merge t t → t` decrease to subterms.
- `recΔ b s void → b` decreases to a subterm.
- `recΔ b s (delta n) → app s (recΔ b s n)` is oriented because the recursive `recΔ` call has third argument `n` instead of `delta n`; the counter decreases structurally.
- `eqW a a → void` decreases by precedence.
- `eqW a b → integrate (merge a b)` is size-increasing syntactically, but orientable because `eqW` is placed above both `integrate` and `merge`.

The overlap between

```lean
R_eq_refl : Step (eqW a a) void
R_eq_diff : Step (eqW a b) (integrate (merge a b))
```

makes the system nondeterministic and likely non-confluent, but it does not by itself create nontermination.

So within the boundary you describe: **yes, strong normalization is plausibly/provably obtainable from the given syntax and rewrite rules alone.** The proof should use a well-founded term ordering rather than a naive size measure, since some rules, especially `R_rec_succ` and `R_eq_diff`, can increase raw term size.
