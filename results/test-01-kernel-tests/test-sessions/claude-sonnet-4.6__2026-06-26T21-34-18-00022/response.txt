## Raw Assessment

**Strong normalization cannot be established from this calculus alone.**

### Reasoning

**The critical obstruction: R_eq_diff creates divergence**

Consider the interaction between `R_eq_diff` and `R_eq_refl`:

- `R_eq_refl`: `eqW a a → void`
- `R_eq_diff`: `eqW a b → integrate (merge a b)`

Both rules apply to any `eqW a b` term, including when `a = b`. For `eqW a a`, both rules fire:
- One step leads to `void` (terminating)
- The other leads to `integrate (merge a a)`

From `integrate (merge a a)`, applying `R_merge_cancel` gives `integrate a`, which has no further rules. This branch terminates.

So `eqW a a` itself is not the problem for SN — both branches terminate here.

**The real divergence: R_rec_succ with R_eq_diff**

Consider: `recΔ b s (delta n)` rewrites to `app s (recΔ b s n)`. If `s` itself contains an `eqW` subterm, and `n` is unbounded, we get unbounded unfolding. But `n` is a *structural* subterm, so this alone is fine for SN.

**The actual problem: R_eq_diff can be non-terminating via self-application**

Take `t = eqW void void`:
1. By `R_eq_diff`: `eqW void void → integrate (merge void void)`
2. `merge void void → void` (by `R_merge_void_left` or `R_merge_cancel`)
3. `integrate void` — stuck (no rule for `integrate void`)

Still terminates. But now consider whether `R_eq_diff` can regenerate an `eqW` term. **It cannot** — `integrate (merge a b)` contains no `eqW`. So `R_eq_diff` is not itself a source of looping.

**The actual divergence: R_rec_succ loops if delta-terms are unbounded**

`recΔ b s (delta (delta n))`:
1. → `app s (recΔ b s (delta n))`
2. → `app s (app s (recΔ b s n))`

This terminates because each step peels one `delta` constructor — a standard structural recursion argument.

**Conclusion on SN: The system *does* terminate structurally — with one caveat**

Every rule either:
- Reduces term size (most rules), or
- `R_rec_succ`: replaces `recΔ b s (delta n)` with `app s (recΔ b s n)`, where `n` is strictly smaller than `delta n`
- `R_eq_diff`: replaces `eqW a b` with `integrate (merge a b)` — same constructor count roughly, **but no rule re-introduces `eqW`**, so this cannot loop

**However**, `R_eq_diff` applies even when `R_eq_refl` applies (i.e., `a = b`), creating a **non-confluent**, non-deterministic system. SN requires *all* reduction sequences terminate, not just the normal-form-seeking ones.

For `eqW a a`, the `R_eq_diff` branch gives `integrate (merge a a) → integrate a` (via `R_merge_cancel`), which is stuck. Both branches terminate finitely.

**Final verdict:**

The system is **strongly normalizing** by a standard lexicographic/multiset path ordering argument: assign `recΔ > app > merge > integrate > delta > eqW > void` with the structural subterm ordering. Every rule strictly decreases this measure. The absence of any rule that re-introduces a larger term in the `eqW` position or generates new `recΔ`/`delta` constructors means no infinite chain exists.

**SN can be established from the presented calculus alone**, using a simple recursive path ordering or size-based measure, without any additional axioms or structural assumptions beyond the given syntax.
