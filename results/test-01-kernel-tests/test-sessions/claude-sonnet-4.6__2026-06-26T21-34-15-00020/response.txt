## Raw Assessment

**Strong normalization cannot be established from this calculus alone.**

### Reasoning

**The critical issue: R_eq_diff creates divergence**

Consider the interaction between `R_eq_diff` and `R_eq_refl`. The rule `R_eq_diff` fires for *any* `a b` (including when `a = b`), producing `integrate (merge a b)`. When `a = b`, both `R_eq_refl` and `R_eq_diff` apply to the same term `eqW a a`.

If the strategy ever picks `R_eq_diff` on `eqW a a`, we get:
```
eqW a a → integrate (merge a a)
         → integrate a   (by R_merge_cancel)
```

This is a finite reduction, so that particular path terminates. But the deeper problem is **R_rec_succ combined with R_eq_diff**.

**The divergence loop:**

Look at `R_rec_succ`:
```
recΔ b s (delta n) → app s (recΔ b s n)
```

This unfolds recursion, but `n` is structurally smaller (`delta n` → `n`), so recursion alone terminates on well-founded `delta`-depth.

However, `R_eq_diff` is the problem:
```
eqW a b → integrate (merge a b)
```

There is **no guard** that `a ≠ b`. Combined with `R_eq_refl` on the same term, the system is **non-confluent**: `eqW a a` can reduce to either `void` or `integrate (merge a a) → integrate a`. Non-confluence is not by itself a failure of SN.

**The actual SN obstruction:**

Consider `R_eq_diff` applied to terms containing `recΔ`. A term like:

```
eqW (recΔ b s (delta void)) t
```

reduces via `R_eq_diff` to `integrate (merge (recΔ b s (delta void)) t)`, which contains a `recΔ` subterm. There is no rule that reduces `integrate (merge ...)` unless it matches `integrate (delta t)`. So this particular path is not obviously divergent by itself.

**But consider:** there is no termination measure that is obviously preserved. Specifically, `R_eq_diff` can produce terms **larger** than the input (adding `integrate` and `merge` wrappers), and the resulting subterms can again be subject to `R_eq_diff`. Without a rule reducing `integrate(merge(...))` to something smaller, we get **infinite growth without progress**:

```
eqW a b → integrate(merge a b)
```

Now if some context re-embeds this under `eqW`, we can loop. For instance, if `s` in `recΔ b s n` produces `eqW`-headed terms via `app`, the unfolding via `R_rec_succ` + `R_eq_diff` generates an unbounded sequence of ever-larger terms with no decreasing measure derivable purely from the given rules.

**No standard termination order works:** The system lacks a lexicographic or multiset path ordering because `R_eq_diff` strictly increases term size without any compensating structural decrease, and `R_rec_succ` produces `app s (recΔ b s n)` where `s` is unconstrained — it could itself be a `recΔ` term that further unfolds.

### Conclusion

**Strong normalization fails** (or at minimum cannot be established) from this calculus alone. The combination of `R_eq_diff` (size-increasing, no guard), `R_rec_succ` (recursion unfolding with unconstrained step function), and the absence of any rule collapsing `integrate(merge(...))` means no standard well-founded measure is derivable purely from the given syntax and rules. The system is also non-confluent (`R_eq_refl` vs `R_eq_diff` on `eqW a a`), which further undermines any canonical proof strategy. Establishing SN would require importing an external wellfoundedness argument or adding side conditions — neither of which is available within the presented calculus.
