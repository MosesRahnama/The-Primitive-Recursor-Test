# Assessment: Strong Normalization Does NOT Hold

Strong normalization cannot be established for this system as presented. The system is **not strongly normalizing** — in fact, it is not even weakly normalizing for all terms.

## Key Reason: The `R_eq_diff` Rule Creates Non-Termination

The critical issue lies in the interaction between `R_eq_diff` and `R_eq_refl`:

**Rule `R_eq_diff`:** For *any* `a` and `b`, `eqW a b` steps to `integrate (merge a b)`.

**Rule `R_eq_refl`:** For *any* `a`, `eqW a a` steps to `void`.

Both rules apply when `a = b`. This means `eqW a a` can reduce to either `void` (via `R_eq_refl`) or `integrate (merge a a)` (via `R_eq_diff`). This is non-determinism, but non-determinism alone doesn't break strong normalization — we need to check whether all reduction paths terminate.

Taking the `R_eq_diff` path on `eqW a a`:
1. `eqW a a` → `integrate (merge a a)` (by `R_eq_diff`)
2. `integrate (merge a a)` → `integrate a` (by `R_merge_cancel`, if we allow reduction under context)

This path terminates. However, the deeper problem is the **lack of a context closure rule**. The relation `Step` as written is a **root reduction** relation — it only rewrites at the top level, not under constructors. If we interpret it as only root steps, then `integrate (merge a a)` is a normal form (no root rule applies to an `integrate` of a `merge`), and the system might be trivially "strongly normalizing" in a degenerate sense for most terms.

But if we interpret `Step` as intended to be closed under all contexts (which is the standard reading for a rewrite calculus), then:

**The `R_rec_succ` rule generates unbounded growth.** Consider:

`recΔ b s (delta (delta (delta ...)))` — nested deltas of depth *n* will unfold into *n* applications of `s`, which is fine for finite depth. But consider a term where `s` reconstructs a `delta` structure or where `R_eq_diff` feeds back into `R_eq_refl`-eligible terms.

**More critically**, `R_eq_diff` applies to `eqW a b` for ALL `a, b` — including when `a = b`. There is no side condition requiring `a ≠ b`. So for `eqW a a`, we can take the `R_eq_diff` branch, obtaining `integrate (merge a a)` → `integrate a`. If `a` itself is `eqW c c`, this produces `integrate (eqW c c)`, which under context reduction gives `integrate void` or `integrate (integrate (merge c c))`, etc. While these particular chains appear to terminate, the fundamental issue is:

**There is no well-founded measure that decreases across all rules simultaneously.** The `R_eq_diff` rule replaces a term `eqW a b` with `integrate (merge a b)`, which is *larger* than the original, and the sub-terms `a` and `b` reappear intact. Combined with `R_rec_succ`, which also increases term size and preserves `s` as a sub-term that can be an arbitrary trace, there is no obvious decreasing measure.

## Conclusion

**No**, strong normalization cannot be established from the presented calculus alone. The overlap between `R_eq_refl` and `R_eq_diff` (both applicable to `eqW a a`) combined with the size-increasing nature of `R_eq_diff` and `R_rec_succ`, and the absence of any side condition enforcing `a ≠ b` in `R_eq_diff`, means the system admits non-terminating reduction sequences under context closure. Without additional guards, typing disciplines, or side conditions, strong normalization fails.
