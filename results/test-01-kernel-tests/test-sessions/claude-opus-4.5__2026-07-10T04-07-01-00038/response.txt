## Assessment

**No, strong normalization cannot be established from this calculus alone.**

### Reasoning

The critical issue is the `R_eq_diff` rule:

```lean
| R_eq_diff : ∀ a b, Step (eqW a b) (integrate (merge a b))
```

This rule applies to *any* `a` and `b`, including when `a = b`. Combined with `R_eq_refl`:

```lean
| R_eq_refl : ∀ a, Step (eqW a a) void
```

We have **non-confluence** and **critical overlap**, but more importantly for normalization, consider what happens with the interaction of rules.

The primary problem is the **non-terminating cycle** that can arise:

1. Starting with `eqW t t` for any term `t`
2. By `R_eq_diff`: `eqW t t → integrate (merge t t)`
3. By `R_merge_cancel`: `integrate (merge t t) → integrate t` (under congruence closure)
4. If `t = delta u`, then by `R_int_delta`: `integrate (delta u) → void`

But the issue is that `R_eq_diff` applies **unconditionally** even when `a = b`. The rules `R_eq_refl` and `R_eq_diff` both apply to `eqW a a`, creating a choice point. If we always choose `R_eq_diff`, we don't immediately loop, but the system lacks the guards to prevent problematic expansions.

More critically, the `R_rec_succ` rule:

```lean
| R_rec_succ : ∀ b s n, Step (recΔ b s (delta n)) (app s (recΔ b s n))
```

This is well-founded only if `delta n` is "larger" than `n` in some measure. However, nothing prevents constructing terms like `recΔ b s (delta (delta (delta ...)))` with the `s` argument itself containing `recΔ` expressions that can expand indefinitely when applied.

The system provides no **size decrease guarantee**: `app s (recΔ b s n)` introduces an `app` node and preserves the full `recΔ` structure with `s` appearing twice. Without restrictions on `s`, if `s` reduces to something that reconstructs or expands the recursion, normalization fails.

### Conclusion

The calculus as stated does not admit a straightforward strong normalization proof. A standard reducibility/logical relations argument would require a well-founded measure that decreases on every step, but `R_eq_diff` and the unrestricted `R_rec_succ` do not provide this without additional side conditions (e.g., `a ≠ b` for `R_eq_diff`, or structural constraints on `s` in `recΔ`).
