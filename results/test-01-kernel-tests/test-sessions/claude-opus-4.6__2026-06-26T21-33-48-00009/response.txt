# Assessment: Strong Normalization Does NOT Hold

Strong normalization cannot be established for this system. The system is **not strongly normalizing** as presented.

## Critical Issue: The `R_eq_diff` Rule

The rule `R_eq_diff` applies to **any** `a` and `b`:

```
R_eq_diff : ∀ a b, Step (eqW a b) (integrate (merge a b))
```

Note that there is **no side condition** requiring `a ≠ b`. This means `R_eq_diff` applies even when `a = b`, overlapping with `R_eq_refl`.

When `a = b`, both rules apply to `eqW a a`:
- `R_eq_refl`: `eqW a a → void`
- `R_eq_diff`: `eqW a a → integrate (merge a a)`

Taking the `R_eq_diff` branch on `eqW a a`:

1. `eqW a a` → `integrate (merge a a)` (by `R_eq_diff`)
2. `integrate (merge a a)` → `integrate a` (by `R_merge_cancel`)

Now if `a = void`, this terminates: `integrate void` is a normal form (no rule reduces it — `R_int_delta` only fires on `integrate (delta t)`).

But the deeper problem is with `R_rec_succ`. Consider:

```
recΔ b s (delta n) → app s (recΔ b s n)
```

The right-hand side introduces `app`, which has **no reduction rule**. So `app` terms are in normal form modulo their subterms. This seems fine at first glance.

However, consider the interaction more carefully. The real issue is that **there is no constraint on the `Step` relation being applied only at the root** — but actually, looking again, `Step` as defined is only a root-step relation with no congruence/context closure rules. So rewriting can only happen at the top level.

**But even with just root steps**, the system is non-deterministic (due to `R_eq_refl` / `R_eq_diff` overlap), and strong normalization requires **all** reduction sequences to terminate. With root-step only (no context closure), the overlap at `eqW a a` still produces two possible reducts, but both are in root-normal form after a finite number of steps, so this alone doesn't break SN.

If we consider the natural extension to a compatible (contextual) rewrite relation — which is the standard interpretation for establishing SN of a rewrite system — then the situation changes. After `R_eq_diff` produces `integrate (merge a b)`, and we can reduce inside contexts, terms can cycle. For instance, with `a = eqW t t`:

1. `eqW (eqW t t) (eqW t t)` → `integrate (merge (eqW t t) (eqW t t))` (by `R_eq_diff`)
2. → `integrate (eqW t t)` (by `R_merge_cancel` in context)
3. But `eqW t t` → `integrate (merge t t)` (by `R_eq_diff` in context)

This chain always terminates since terms shrink in a suitable measure... **unless** we consider that `R_eq_diff` can perpetually apply before `R_eq_refl` does.

## Revised Core Argument

Actually, with root-only steps as literally defined, strong normalization trivially holds for most terms since almost nothing can reduce after one step (no congruence rules). The question becomes vacuous for a root-only system.

Under the standard interpretation with contextual closure, the overlap between `R_eq_refl` and `R_eq_diff` is the problem: **strong normalization requires every reduction path to terminate**, but `R_eq_diff` on `eqW a a` produces `integrate (merge a a)` → `integrate a`, which may contain another `eqW a' a'` that can again take the `R_eq_diff` branch, never choosing `R_eq_refl`. Each application does reduce the term by some measure though.

**Final answer: No, strong normalization cannot be cleanly established** because `R_eq_diff` has no guard excluding `a = b`, creating a non-confluent overlap with `R_eq_refl` where the `R_eq_diff` branch can produce terms of equal or greater complexity (e.g., `eqW a b → integrate (merge a b)` can increase term size), potentially enabling non-terminating reduction sequences under contextual closure.
