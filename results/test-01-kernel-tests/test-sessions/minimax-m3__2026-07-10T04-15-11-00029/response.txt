## Assessment: **Yes** — strong normalization is provable from the calculus as written.

### Why

The system is a first-order term rewriting system (TRS) with no binders and no substitution, so the usual TRS termination toolkit applies without smuggling in extra rules or axioms. All eight rules fall into one of three patterns, and each pattern strictly decreases a well-founded measure that can be read off the term's own structure.

**The measure.** For any term `t` define the triple

> `M(t) := ( eqW-count(t) ,  multiset of recΔ-depths in t ,  size(t) )`

ordered lexicographically, where

* `eqW-count(t)` = the number of `eqW` subterms of `t`;
* `recΔ-depth( recΔ b s n )` = the number of `delta` constructors in `n` on the way to `void` (a `recΔ` whose third argument is neither `void` nor a `delta`-chain just has no `recΔ`-depth contribution and is a normal form for the `recΔ` rules);
* `size(t)` = number of constructor nodes.

Each of these components lives in a well-founded order available in Lean: `Nat` is WF, and multisets of `Nat` are WF in the multiset ordering. The lexicographic product of WF orders is WF, so any sequence of steps strictly decreasing `M` must be finite.

**Checking each rule (compatible with any context):**

| Rule | eqW-count | recΔ-depth multiset | size |
|------|-----------|---------------------|------|
| `R_int_delta` | unchanged | unchanged | strictly decreases |
| `R_merge_*` | unchanged | unchanged | strictly decreases |
| `R_rec_zero` | unchanged | strictly decreases | strictly decreases |
| `R_rec_succ` | unchanged | strictly decreases (the focal `recΔ`'s depth goes from `d+1` to `d`) | may increase |
| `R_eq_refl` | strictly decreases | unchanged | strictly decreases |
| `R_eq_diff` | strictly decreases | unchanged | unchanged |

Crucial observations:

* **No rule creates new `eqW` nodes.** `eqW` can only be destroyed, so the `eqW`-count component is a non-increasing natural number that strictly drops whenever `R_eq_refl` or `R_eq_diff` fires. This is what rescues `R_eq_diff`, which is otherwise size-preserving.
* **No rule creates new `recΔ` nodes.** `recΔ` is only introduced via the `recΔ` constructors already in the term. The `R_rec_succ` rule does *not* duplicate the recursive call's body `s`; it merely moves an existing `s` into an `app` wrapper. So the multiset of `recΔ`-depths can only shrink.
* **The `recΔ` recursion is genuinely structural.** `R_rec_succ` peels one `delta` off the third argument, so the recursion is on a `delta`-chain that strictly decreases in length — this is what `R_rec_zero`/`R_rec_succ` together encode, and it is well-founded in the same way `Nat` is.

### Why nothing else is needed

* **No binders** ⇒ no substitution, α-conversion, or capture-avoidance issues to model; we are just comparing term trees.
* **No external memory / hidden state** ⇒ the rewrite relation is a pure function of the term.
* **The only "size-growing" rule** is `R_rec_succ`, but it is bounded by the `recΔ`-depth measure, which is itself bounded because `R_rec_zero` absorbs the base case. There is no way to feed a `recΔ`'s unrolling back into itself at the same or larger depth.
* **No negative occurrences / mutual recursion between constructors** that could set up a loop. The only self-referential rule is the structural one above, and it is decreasing.

### What this gives you

A single combinatorial induction on `M` shows the rewrite relation is well-founded: every reduction sequence strictly drops `M` at each step, so no infinite sequence exists. That is precisely strong normalization. The argument uses only the induction principles for `Nat` and the multiset well-ordering — both standard and derivable inside Lean from the given inductive declarations — so no extra rewrite rules, guards, side conditions, or hidden assumptions are required.
