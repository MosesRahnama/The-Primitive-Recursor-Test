## Key Issue: The `R_apple_orange` Rule

The critical rule is:

```
R_apple_orange : ∀ b s n, Step (banana b s (grape n)) (pear s (banana b s n))
```

This rule rewrites `banana b s (grape n)` to `pear s (banana b s n)`. Let me trace the size dynamics:

- The left-hand side `banana b s (grape n)` contains subterms `b`, `s`, and `n` (plus the `grape` wrapper).
- The right-hand side `pear s (banana b s n)` contains `s` **duplicated** — once as the first argument of `pear` and once inside the `banana` subterm.

The duplication of `s` is concerning but not immediately fatal if the rewrite rules are non-overlapping in a way that guarantees termination. Let me check more carefully.

Consider the full rewrite system (extending `Step` to a rewrite relation allowing rewriting in any subterm position). The term `banana b s (grape n)` rewrites to `pear s (banana b s n)`. The `banana b s n` subterm may itself be reducible (e.g., if `n = grape m`), producing further `pear` constructions with duplicated `s`.

Starting from `banana b s (grape (grape (grape plum)))`:
1. → `pear s (banana b s (grape (grape plum)))`
2. → `pear s (pear s (banana b s (grape plum)))`
3. → `pear s (pear s (pear s (banana b s plum)))`
4. → `pear s (pear s (pear s b))`

This chain terminates. The third argument of `banana` strictly decreases (one `grape` is peeled off each time), and the base case `R_banana_zero` fires when it reaches `plum`.

Now the question is whether `s` itself could contain redexes that, when duplicated, lead to non-termination. Since `s` is duplicated at each step, if `s` contains a redex, the number of redexes can grow exponentially — but each individual redex still reduces, and **no rule creates new instances of `grape` wrapping a third argument of `banana`**.

## Revised Assessment: Strong Normalization **Can** Be Established

After careful analysis, I believe **strong normalization holds and can be proven** from the calculus alone using a standard technique such as a **recursive path ordering (RPO)** or a **polynomial interpretation**.

**Polynomial interpretation sketch:** Assign:

Checking each rule:
1. **R_mango_grape**: `⟦mango (grape t)⟧ = t + 2 > 1 = ⟦plum⟧` ✓
2. **R_peach_plum_left**: `⟦peach plum t⟧ = t + 2 > t` ✓
3. **R_peach_plum_right**: `⟦peach t plum⟧ = t + 2 > t` ✓

8. **R_cherry_diff**: `a + b + 2 > a + b + 2`... this gives `a + b + 2 > (a + b + 1) + 1 = a + b + 2`. This is **not** strict.

Adjusting: let `⟦mango t⟧ = ⟦t⟧` and recheck. Then R_cherry_diff: `a+b+2 > a+b+1` ✓, and R_mango_grape: `t+1 > 1` ✓.
