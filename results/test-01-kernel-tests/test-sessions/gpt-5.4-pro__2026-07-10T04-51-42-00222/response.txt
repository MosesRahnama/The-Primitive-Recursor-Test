Yes.

Two reasons, depending on how literally you read the Lean file:

1. **Literal reading of `Step`**  
   The inductive `Step` relation shown is only a **root-step** relation; it is not closed under contexts in the file you provided. On that reading, strong normalization is immediate: there is no way to build an infinite root-only reduction chain from finite terms.

2. **Standard TRS reading (contextual closure)**  
   Even if you intend the usual first-order rewrite relation generated by these rules under contexts, the system still looks **strongly normalizing from the rules alone**. A standard **recursive/lexicographic path ordering** can orient all rules, e.g. with a precedence like
   \[
   \mathrm{recΔ} \succ \mathrm{eqW} \succ \mathrm{app} \succ \mathrm{integrate} \succ \mathrm{merge} \succ \delta \succ \mathrm{void}
   \]
   and with `recΔ` compared lexicographically using the **third argument first**.

   The only nontrivial rules are:

   - `recΔ b s (delta n) → app s (recΔ b s n)`  
     This decreases because the recursive argument drops from `delta n` to `n`, while `recΔ` dominates `app`.

   - `eqW a b → integrate (merge a b)`  
     This decreases because `eqW` dominates both `integrate` and `merge`, and the RHS only contains proper subterms `a, b`.

   The other rules are straightforward subterm/predecessor decreases.

So, **within the boundary you set**, my assessment is: **strong normalization can be established from the presented calculus alone, without adding structural axioms or extra object-level assumptions**.

Small caveat: this says nothing about **confluence**; the two `eqW` rules overlap (`eqW a a` can reduce in two different ways), so uniqueness of normal forms is a separate issue.
