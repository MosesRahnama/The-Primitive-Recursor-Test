# Assessment: Strong Normalization Does NOT Hold

The system as presented is **not strongly normalizing**. Here is the reasoning:

## The Critical Problem: Rule `R_eq_diff`

The rule `R_eq_diff` applies to **any** `a` and `b`:

```
R_eq_diff : ∀ a b, Step (eqW a b) (integrate (merge a b))
```

Note that this rule has **no side condition** requiring `a ≠ b`. It applies to *all* pairs `(a, b)`, including the case where `a = b`.

Meanwhile, `R_eq_refl` also applies when `a = b`:

```
R_eq_refl : ∀ a, Step (eqW a a) void
```

So when we have `eqW a a`, **both** rules apply. This is a non-deterministic (non-confluent) overlap, but non-determinism alone doesn't kill strong normalization — what matters is whether *every* reduction sequence terminates.

## Constructing a Non-Terminating Reduction

Consider the term `eqW void void`:

1. By `R_eq_diff`: `eqW void void → integrate (merge void void)`
2. By `R_merge_cancel`: `integrate (merge void void) → integrate void`

Now `integrate void` is a **normal form** (no rule applies to it — `R_int_delta` requires the argument to be `delta t`).

That particular path terminates. But let's try a more complex term. Consider `eqW (delta void) (delta void)`:

1. By `R_eq_diff`: `eqW (delta void) (delta void) → integrate (merge (delta void) (delta void))`
2. By `R_merge_cancel`: `→ integrate (delta void)`
3. By `R_int_delta`: `→ void`

This also terminates. Let me reconsider more carefully.

Actually, the real issue is: take **any** term `t` that is not in normal form under these rules. The rules are not applied under context (there are no congruence/compatibility closure rules — `Step` only rewrites at the root). So only top-level redexes reduce.

Since `Step` is defined only for root reduction with no context closure rules (no rules like "if `Step t t'` then `Step (delta t) (delta t')`"), subterms are never reduced. This means the only reducible terms are those matching a root pattern.

**Every** root-reducible term either reduces to a strictly smaller term or to a term involving `app` (from `R_rec_succ`), but `app` has **no reduction rules** — it is always a normal form at the root. Similarly, `integrate void` is a normal form.

## Revised Assessment: Strong Normalization HOLDS

With no congruence/context rules, reduction is root-only. Every rule either:
- Produces `void` (smaller)
- Removes a constructor (`R_merge_void_*`, `R_merge_cancel`)
- Replaces `recΔ` with `app` (which is irreducible at the root, and subterms are never revisited)
- Replaces `eqW` with `void` or `integrate (merge ...)` — but since there's no context closure, the inner `merge` is never reduced afterward in the same reduction sequence starting from `eqW a b`

Since there are **no context/congruence closure rules**, a single `Step` applies once at the root, and the result either is a normal form or has at most one new root redex. A straightforward **size argument** (or measure on constructor depth/count) shows every reduction sequence is finite.

## Final Answer

**Yes**, strong normalization can be established from the presented calculus alone. The key observation is that `Step` defines only **root rewriting** with no congruence/compatibility rules, so subterms are never revisited. Each rule either reduces the term to something structurally smaller or to a constructor (`app`, `integrate`) with no applicable root rule, guaranteeing termination. A simple well-founded measure (e.g., multiset of constructors `recΔ`, `eqW`, `merge` at the root) decreases with every step.
