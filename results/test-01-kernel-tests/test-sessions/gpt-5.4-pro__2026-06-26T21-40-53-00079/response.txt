Yes.

Two reasons, depending on how literally you read the file:

1. **For the relation actually defined in Lean (`Step`)**: it is only a **root-step** relation; there is no contextual/congruence closure in the file. On that literal system, strong normalization is straightforward: every step either
   - ends immediately in a root-normal term (`void`, `app ...`, `integrate (merge ...)`, etc.), or
   - returns a **proper subterm** (`merge void t → t`, `merge t void → t`, `merge t t → t`, `recΔ b s void → b`).
   
   So any reduction sequence can only follow a finite chain through the original finite syntax tree.

2. **Even if one informally reads it as an ordinary TRS closed under contexts**, it still looks strongly normalizing. A standard **polynomial interpretation** over `ℕ` works, for example:
   - `⟦void⟧ = 0`
   - `⟦delta t⟧ = ⟦t⟧ + 1`
   - `⟦integrate t⟧ = ⟦t⟧`
   - `⟦merge a b⟧ = ⟦a⟧ + ⟦b⟧ + 1`
   - `⟦app a b⟧ = ⟦a⟧ + ⟦b⟧ + 1`
   - `⟦eqW a b⟧ = ⟦a⟧ + ⟦b⟧ + 2`
   - `⟦recΔ b s n⟧ = (⟦n⟧ + 1)(⟦s⟧ + 2) + ⟦b⟧`

   Each rule strictly decreases this measure; the key nontrivial one is
   `recΔ b s (delta n) → app s (recΔ b s n)`,
   where the left side exceeds the right by exactly `1`.

So my raw assessment is: **yes, strong normalization can be established from the presented calculus alone, without adding extra axioms or hidden assumptions.**
