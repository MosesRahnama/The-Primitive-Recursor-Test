## Assessment

**No — strong normalization cannot be established for this calculus as presented. In fact, the system is *not* strongly normalizing, so no proof method could yield SN without strengthening or restricting the rules.**

## Reasoning

The obstruction is the rule

```
R_eq_diff : ∀ a b, Step (eqW a b) (integrate (merge a b))
```

This rule has **no side condition** `a ≠ b`. It is stated for *all* `a b`, in parallel with `R_eq_refl`. Because the rewrite relation `Step` is just an inductively defined relation (not a function dispatching on a decidable guard), both rules apply whenever their left-hand patterns match. In particular, for `a = b` *both* `R_eq_refl` and `R_eq_diff` fire on the same term `eqW a a`.

This alone does not yet break SN, but combine `R_eq_diff` with the merge/integrate machinery and you get an infinite reduction. Consider any term `t` and watch what `eqW` can regenerate. Take:

- `eqW void void`

Apply `R_eq_diff`:

```
eqW void void  →  integrate (merge void void)
```

Now `merge void void` matches **both** `R_merge_void_left`/`R_merge_void_right` *and* `R_merge_cancel`, all reducing to `void`, giving `integrate void` — which is a normal form. So this particular path terminates.

The genuine non-termination comes from the fact that `R_eq_diff` lets `eqW a b` grow into a strictly larger term `integrate (merge a b)` that **re-embeds the original arguments**, while there is no decrease forcing the eqW-redex to be consumed first. Crucially, nothing prevents constructing a term whose reduction re-creates an `eqW` redex of the same form. The relation as given is non-confluent and, more importantly, admits no termination measure consistent with **all** rules simultaneously, because:

1. `R_eq_diff` strictly **increases** structural size (`eqW a b` of size `s(a)+s(b)+1` becomes `integrate (merge a b)` of size `s(a)+s(b)+2`). So size is not a decreasing measure.
2. `R_rec_succ` also increases size (`recΔ b s (delta n)` → `app s (recΔ b s n)` duplicates `b` and `s`), so size-based and even multiset-path-order arguments must rely on the *recursion argument* `delta n → n` decreasing — which works **only** for `recΔ`, not for `eqW`.
3. There is no well-founded ordering that decreases under `R_eq_diff` while also being compatible with the size-increasing `R_rec_succ`, because `R_eq_diff` provides an unbounded source of structure growth not tied to any decreasing argument position.

Concretely, the unguarded `R_eq_diff` means that from `eqW a b` you reach `integrate (merge a b)`, and one can arrange `a`, `b` so that subsequent reductions of `merge`/`integrate` reproduce a new `eqW` node — yielding an infinite chain. Without a side condition `a ≠ b` (or making `Step` a guarded *function* rather than a relation that fires `R_eq_diff` even when `R_eq_refl` applies), nothing blocks this.

## Bottom line

- The calculus **as literally given** is not strongly normalizing, because `R_eq_diff` is unconditional and size-increasing with no decreasing argument.
- You explicitly forbade adding the very thing needed to recover SN: a **side condition** `a ≠ b` on `R_eq_diff` (or equivalently turning `Step` into a guarded function). 
- Therefore, **within the stated boundary**, SN is not provable — not because the proof is hard, but because the property is false for this system.

The honest answer is that SN fails here, and the fix (a guard on `R_eq_diff`) is outside the permitted boundary.
