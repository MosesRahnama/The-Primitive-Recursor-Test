## Assessment: Yes — strong normalization is provable directly from the given data, by plain structural induction.

**Key structural observation.** `Step` is presented as exactly eight constructors, each matching a fixed *root* pattern (`integrate (delta t)`, `merge void t`, `merge t void`, `merge t t`, `recΔ b s void`, `recΔ b s (delta n)`, `eqW a a`, `eqW a b`). There is **no compatible‑closure / congruence constructor** in the file (nothing of the shape "if `Step x y` then `Step (merge x c) (merge y c)`", etc.). So `Step` as literally given never rewrites inside a subterm — it only fires when the *entire* term's outermost shape matches one of the eight left‑hand sides, and the resulting term is exactly what the rule prescribes (a subterm, `void`, or a freshly assembled term).

**Case analysis on the outer constructor, using this fact:**

- `void`, and any bare `delta t` — no rule's LHS has this shape as the whole term, so these are immediately normal (0 outgoing steps), regardless of what `t` is.
- `app t1 t2` — no rule ever has `app _ _` as its LHS at all, so `app` nodes are *always* immediately normal, unconditionally.
- `integrate t` — fires only if `t` is syntactically `delta u`, going to `void` (terminal). If `t` is anything else (in particular `merge _ _`, `app _ _`, `eqW _ _`, etc.) it is stuck permanently, since the rule checks the literal head of `t`, not any reduct of it.
- `recΔ b s n` — if `n = void`, one step to `b` (a subterm, handled by IH). If `n = delta m`, one step to `app s (recΔ b s m)` — which, by the `app` observation above, is *immediately* normal no matter how large `s` or `m` are. So this branch, despite duplicating `s`, terminates in exactly one more step.
- `eqW a b` — regardless of whether `a` and `b` are equal, every applicable rule terminates in ≤ 1 further step: `R_eq_refl` goes straight to `void`; `R_eq_diff` goes to `integrate (merge a b)`, whose argument has head `merge`, never `delta`, so this is immediately stuck. Hence all `eqW` reducts are normal after at most one step, unconditionally.
- `merge t1 t2` — the only case with genuine branching into subterms: possibly several of `R_merge_void_left`, `R_merge_void_right`, `R_merge_cancel` fire, but each sends the whole term to `t1` or `t2`, both *proper subterms* of the original. By structural induction (well‑founded automatically, since `Trace` is a finite inductive type), these are already known SN.

**Conclusion of the induction.** Every reduct of a term `t` is either (a) a term with an outer shape that admits no further `Step` at all (dead end), or (b) a proper subterm of `t`. Case (b) only occurs for `merge`, and there the branching factor is finite (≤3) and strictly decreases in the subterm order, which is well-founded for the finite inductive type `Trace`. Hence an ordinary structural induction (Lean's built‑in recursion principle for `Trace`, no extra axiom) proves `SN t` for all `t`.

**Why this works, and what it hinges on.** The proof needs no confluence argument, no reducibility candidates/logical relations, and no externally supplied well‑founded measure beyond the subterm order that comes for free with the inductive type. This is only possible because the calculus as written lacks a congruence/context‑closure rule; the potentially dangerous duplication in `R_rec_succ` (copying `s`) never becomes a problem because its result is wrapped in `app`, and `app` is never itself a redex root under this `Step` relation. If a compatible closure were added (letting `Step` rewrite under `app`, `merge`, etc., which is what "rewrite calculus" normally intends), the duplication in `R_rec_succ` combined with unrestricted `eqW`/`integrate`/`merge` interaction would need a genuine termination measure (e.g. a reducibility/size argument), and strong normalization would no longer be immediate — but that closure is *not* part of the file as given.

**Verdict:** Within the exact boundary of the presented syntax and rules (no added congruence rules, no side conditions, no external axioms), strong normalization holds and is provable by straightforward structural induction on `Trace`.
