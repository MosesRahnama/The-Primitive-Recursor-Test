Yes — strong normalization appears establishable from the presented calculus alone.

Reasoning:

- If `Step` is taken literally as the rewrite relation in the Lean file, it is only a root-step relation. Then termination is quite direct: every rule either collapses to a subterm/constant or produces a term whose root symbol has no outgoing rule, such as `app ... ...` or `integrate (merge ... ...)` unless further contextual closure is added.

- Even if one considers the usual first-order contextual closure of these rules, the system still looks strongly normalizing by a standard syntactic termination order, e.g. recursive path ordering / simplification ordering.

  A precedence such as

  ```text
  eqW > integrate > merge
  recΔ > app
  ```

  with suitable placement of `delta` and constants is enough to orient the rules decreasingly. The key nontrivial rule is

  ```lean
  recΔ b s (delta n) → app s (recΔ b s n)
  ```

  but this is orientable because the recursive argument decreases from `delta n` to `n`, and the outer root `recΔ` can be made greater than `app`. The duplication/retention of `s` is not by itself a termination obstruction under such an ordering.

- The overlapping rules

  ```lean
  eqW a a → void
  eqW a b → integrate (merge a b)
  ```

  make the system nondeterministic and non-confluent-looking, but nondeterminism does not imply nontermination. Both branches are still orientable downward.

- No rule creates a new `eqW`, no rule gives computation to `app`, and the only recursive unfolding of `recΔ` structurally decreases the third argument when it is a `delta`.

So my raw assessment is: **yes, strong normalization can be established from the given syntax and rewrite rules alone**, without adding guards, side conditions, object-level axioms, or extra rewrite rules. The proof would be a standard first-order termination proof using a well-founded syntactic ordering such as RPO.
