## Reasoning

The fatal rule is `R_eq_diff`:

```
R_eq_diff : ∀ a b, Step (eqW a b) (integrate (merge a b))
```

This rule has **no side condition** distinguishing it from `R_eq_refl`. Crucially, it is stated for *all* `a b`, including the case `a = b`. So for any term `t`, both of these are valid steps:

- `eqW t t → void` (via `R_eq_refl`)
- `eqW t t → integrate (merge t t)` (via `R_eq_diff`)

Now take `a = b = void` and chase a loop:

1. `eqW void void → integrate (merge void void)`  — by `R_eq_diff`
2. `merge void void → void` — by `R_merge_void_left` (or `_right`, or `R_merge_cancel`)

That alone terminates, so I need a term that regenerates an `eqW` redex. Consider instead building a cycle through `merge` and `eqW`. Take the term

```
eqW (void) (void)
```

The two competing rules already show the system is **non-confluent**, but non-confluence by itself doesn't kill SN. The decisive point is that `R_eq_diff` is **size-increasing and applicable to any `eqW` node regardless of its arguments**, including reflexive ones, and there is no rule consuming `integrate (merge ...)` back down in a way that is forced.

To get an actual infinite chain, note `R_eq_diff` produces `integrate (merge a b)` but does not reproduce an `eqW`. So a pure self-loop on a single redex does not exist; let me state the situation precisely rather than overclaim.

**Corrected, precise assessment.** Examining each rule's effect on term size, every rule *strictly decreases* the number of constructor nodes **except** `R_eq_diff`, which maps a 3-node term `eqW a b` to `integrate (merge a b)` (also adding nodes: `1 + 1 + size a + size b` vs `1 + size a + size b`), a net **+1**. But `R_eq_diff` cannot fire on the same position twice, because its result contains no `eqW` at the root. The redexes it *does* create (`merge a b`, `integrate ...`) are all strictly-decreasing redexes. So a measure exists:

- Assign weight where each `eqW` contributes enough "potential" to pay for the one expansion it can trigger, and every other rule strictly decreases a multiset/ordinal measure.

Concretely, define `μ(t)` counting `eqW` occurrences with high weight and total size with low weight. `R_eq_diff` removes one `eqW` (big decrease) while adding O(1) size (small increase) → net decrease. Every other rule removes structure → decrease. No rule *creates* an `eqW`. Therefore the count of `eqW` subterms is non-increasing, and strictly decreasing whenever `R_eq_diff` fires; between such firings, term size strictly decreases.

## Conclusion (revised)

**Yes — strong normalization *can* be established from the presented calculus alone.** A lexicographic / polynomial measure
```
μ(t) = (number of eqW subterms, total node count)
```
ordered lexicographically strictly decreases under every rule:

- `R_eq_diff`, `R_eq_refl` reduce the `eqW`-count (no rule on the RHS reintroduces an `eqW`).
- All remaining rules preserve the `eqW`-count and strictly reduce node count.

Since no right-hand side of any rule contains an `eqW` constructor that wasn't already in a strictly-smaller-count position, the first component is well-founded and the second handles the rest. This requires no extra rules, guards, or side conditions — only the closure of `Step` under the given constructors and a standard well-founded measure argument. Hence SN holds.
