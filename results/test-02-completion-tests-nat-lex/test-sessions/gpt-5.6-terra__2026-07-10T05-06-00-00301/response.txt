The five cases cannot all be completed with the stated measure: the `R_rec_succ` branch is false for `measure`.

In particular, take

```lean
b := void
s := integrate void
n := delta void
```

Then the rule instance is

```lean
recDelta void (integrate void) (delta (delta void))
  -->
app (integrate void) (recDelta void (integrate void) (delta void))
```

and the measures are:

```lean
measure (recDelta void (integrate void) (delta (delta void))) = (1, 4)
measure (app (integrate void) (recDelta void (integrate void) (delta void))) = (1, 6)
```

Thus the first components tie while `mu` increases, so

```lean
LexOrder (measure rhs) (measure lhs)
```

does not hold. Consequently, no Lean proof can fill the `R_rec_succ` `sorry` without changing the measure, the rule, or the theorem statement.

The other four branches have the following proof skeletons.

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    by_cases h0 : kappa t = 0
    · have hmu : mu void < mu (integrate (delta t)) := by
        simp [mu]
      have hk : kappa void = kappa (integrate (delta t)) := by
        simp [kappa, h0]
      exact drop_right hmu hk
    · have hpos : 0 < kappa t := Nat.pos_of_ne_zero h0
      apply drop_left
      simpa [kappa] using hpos
```

```lean
-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    have hmu : mu b < mu (recDelta b s void) := by
      simp [mu]
      omega

    by_cases hk : kappa b = kappa (recDelta b s void)
    · exact drop_right hmu hk
    · apply drop_left
      have hle : kappa b ≤ kappa (recDelta b s void) := by
        simp [kappa]
        exact Nat.le_max_left _ _
      exact lt_of_le_of_ne hle hk
```

Depending on simplifier normalization of the final inequality, the `hle` proof can also be written more explicitly as:

```lean
      change kappa b ≤ Nat.max (kappa b) (kappa s)
      exact Nat.le_max_left _ _
```

```lean
-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    by_cases h0 : kappa a = 0
    · have hmu : mu void < mu (eqW a a) := by
        simp [mu]
      have hk : kappa void = kappa (eqW a a) := by
        simp [kappa, h0]
      exact drop_right hmu hk
    · have hpos : 0 < kappa a := Nat.pos_of_ne_zero h0
      apply drop_left
      simpa [kappa] using hpos
```

```lean
-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]
      omega
    have hk : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

For the blocked successor branch, the intended shape would be:

```lean
| _, _, Step.R_rec_succ b s n => by
    -- A proof by `drop_left` works when the recursive argument does
    -- not itself expose another delta-recursive case.
    --
    -- However, when n = delta m, the kappa values can tie:
    --
    --   kappa (recDelta b s (delta (delta m)))
    --     =
    --   kappa (app s (recDelta b s (delta m)))
    --
    -- and mu increases because s occurs once on the left but twice
    -- on the right.
    --
    -- Therefore this goal is not derivable for the current `measure`.
    sorry
```

To finish the overall normalization proof, `kappa` must be strengthened so that recursive unfolding on nested `delta`s strictly lowers its primary component, or the lexicographic measure must be replaced by a measure capable of accounting for the duplication of `s` in `R_rec_succ`.
