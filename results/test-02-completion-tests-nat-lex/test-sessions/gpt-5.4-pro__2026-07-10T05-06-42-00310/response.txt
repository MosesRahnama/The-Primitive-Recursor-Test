Below is a paste-in proof skeleton for the five `sorry`s.

Important caveat: four of the five cases are routine with the current definitions. The `R_rec_succ` case exposes a real problem in the current measure: the subcase `n = delta m` does **not** decrease `(kappa, mu)` lexicographically. So I’ll give you the exact skeleton for the four good cases, and then the best possible skeleton for `R_rec_succ`, together with the obstruction.

## 1. `integrate (delta t) --> void`

```lean
| _, _, Step.R_int_delta t => by
    by_cases hk0 : kappa t = 0
    · have hmu : mu void < mu (integrate (delta t)) := by
        simp [mu]
      have hk : kappa void = kappa (integrate (delta t)) := by
        simp [kappa, hk0]
      exact drop_right hmu hk
    · have hpos : 0 < kappa t := Nat.pos_of_ne_zero hk0
      have hk : kappa void < kappa (integrate (delta t)) := by
        simpa [kappa] using hpos
      exact drop_left hk
```

## 2. `recDelta b s void --> b`

```lean
| _, _, Step.R_rec_zero b s => by
    have hmu : mu b < mu (recDelta b s void) := by
      simp [mu]
      omega
    cases Nat.lt_or_ge (kappa b) (kappa s) with
    | inl hlt =>
        have hlt' : kappa b < Nat.max (kappa b) (kappa s) :=
          lt_of_lt_of_le hlt (Nat.le_max_right _ _)
        have hmax : Nat.max (kappa b) (kappa s) ≤ kappa (recDelta b s void) := by
          simp [kappa]
          exact Nat.le_max_left _ _
        exact drop_left (lt_of_lt_of_le hlt' hmax)
    | inr hge =>
        have hk : kappa b = kappa (recDelta b s void) := by
          simp [kappa, Nat.max_eq_left hge, Nat.max_eq_left (Nat.zero_le (kappa b))]
        exact drop_right hmu hk
```

## 3. `eqW a a --> void`

```lean
| _, _, Step.R_eq_refl a => by
    by_cases hk0 : kappa a = 0
    · have hmu : mu void < mu (eqW a a) := by
        simp [mu]
      have hk : kappa void = kappa (eqW a a) := by
        simp [kappa, hk0]
      exact drop_right hmu hk
    · have hpos : 0 < kappa a := Nat.pos_of_ne_zero hk0
      have hk : kappa void < kappa (eqW a a) := by
        simpa [kappa] using hpos
      exact drop_left hk
```

## 4. `eqW a b --> integrate (merge a b)`

```lean
| _, _, Step.R_eq_diff a b => by
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]
      omega
    have hk : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

## 5. `recDelta b s (delta n) --> app s (recDelta b s n)`

This is the problematic one.

### What works
If you split on `n`, then in the six **non-`delta`** branches you can prove a strict `kappa` drop:

- source has `kappa = M + 1`
- target has `kappa = max (kappa s) M = M`
- so `drop_left` applies.

A skeleton for those branches looks like this:

```lean
| _, _, Step.R_rec_succ b s n => by
    cases n with
    | void =>
        have hsM :
            kappa s ≤ Nat.max (Nat.max (kappa b) (kappa s)) 0 := by
          exact le_trans (Nat.le_max_right _ _) (Nat.le_max_left _ _)
        have hk :
            kappa (app s (recDelta b s void))
              < kappa (recDelta b s (delta void)) := by
          simp [kappa]
          rw [Nat.max_eq_right hsM]
          exact Nat.lt_succ_self _
        exact drop_left hk

    | integrate u =>
        have hsM :
            kappa s ≤ Nat.max (Nat.max (kappa b) (kappa s)) (kappa u) := by
          exact le_trans (Nat.le_max_right _ _) (Nat.le_max_left _ _)
        have hk :
            kappa (app s (recDelta b s (integrate u)))
              < kappa (recDelta b s (delta (integrate u))) := by
          simp [kappa]
          rw [Nat.max_eq_right hsM]
          exact Nat.lt_succ_self _
        exact drop_left hk

    | merge u v =>
        have hsM :
            kappa s ≤ Nat.max (Nat.max (kappa b) (kappa s))
                              (Nat.max (kappa u) (kappa v)) := by
          exact le_trans (Nat.le_max_right _ _) (Nat.le_max_left _ _)
        have hk :
            kappa (app s (recDelta b s (merge u v)))
              < kappa (recDelta b s (delta (merge u v))) := by
          simp [kappa]
          rw [Nat.max_eq_right hsM]
          exact Nat.lt_succ_self _
        exact drop_left hk

    | app u v =>
        have hsM :
            kappa s ≤ Nat.max (Nat.max (kappa b) (kappa s))
                              (Nat.max (kappa u) (kappa v)) := by
          exact le_trans (Nat.le_max_right _ _) (Nat.le_max_left _ _)
        have hk :
            kappa (app s (recDelta b s (app u v)))
              < kappa (recDelta b s (delta (app u v))) := by
          simp [kappa]
          rw [Nat.max_eq_right hsM]
          exact Nat.lt_succ_self _
        exact drop_left hk

    | recDelta b' s' m =>
        have hsM :
            kappa s ≤ Nat.max (Nat.max (kappa b) (kappa s))
                              (kappa (recDelta b' s' m)) := by
          exact le_trans (Nat.le_max_right _ _) (Nat.le_max_left _ _)
        have hk :
            kappa (app s (recDelta b s (recDelta b' s' m)))
              < kappa (recDelta b s (delta (recDelta b' s' m))) := by
          simp [kappa]
          rw [Nat.max_eq_right hsM]
          exact Nat.lt_succ_self _
        exact drop_left hk

    | eqW u v =>
        have hsM :
            kappa s ≤ Nat.max (Nat.max (kappa b) (kappa s))
                              (Nat.max (kappa u) (kappa v)) := by
          exact le_trans (Nat.le_max_right _ _) (Nat.le_max_left _ _)
        have hk :
            kappa (app s (recDelta b s (eqW u v)))
              < kappa (recDelta b s (delta (eqW u v))) := by
          simp [kappa]
          rw [Nat.max_eq_right hsM]
          exact Nat.lt_succ_self _
        exact drop_left hk

    | delta m =>
        -- stuck with the current measure
        sorry
```

### Why the `delta` branch is genuinely stuck
For `n = delta m`, the rule is

```lean
recDelta b s (delta (delta m)) --> app s (recDelta b s (delta m))
```

and with the current definitions:

- `kappa` of source and target are equal
- `mu` of target is **larger** than `mu` of source

Concrete counterexample:

- take `b = void`, `s = void`, `m = void`
- source: `recDelta void void (delta (delta void))`
- target: `app void (recDelta void void (delta void))`

Then:

- `measure source = (1, 3)`
- `measure target = (1, 4)`

so `LexOrder (measure target) (measure source)` is false.

## Bottom line

You can complete these four cases as above:

- `R_int_delta`
- `R_rec_zero`
- `R_eq_refl`
- `R_eq_diff`

But `R_rec_succ` cannot be finished under the current `(kappa, mu)` measure. The right skeleton is to `cases n`; six branches close by `drop_left`, and the `n = delta m` branch reveals the measure bug.
