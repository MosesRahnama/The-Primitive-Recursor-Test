# Proof Skeleton for Remaining Cases

Here are the proof strategies for the five remaining cases:

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    have hk : kappa void < kappa (integrate (delta t)) := by simp [kappa]
    exact drop_left hk

-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    have hk : kappa b < kappa (recDelta b s void) := by simp [kappa]; omega
    exact drop_left hk

-- recDelta b s (delta n) --> app s (recDelta b s n)
| _, _, Step.R_rec_succ b s n => by
    have hk : kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n)) := by
      simp [kappa]; omega
    exact drop_left hk

-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    have hk : kappa void < kappa (eqW a a) := by simp [kappa]; omega
    exact drop_left hk

-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hk : kappa (integrate (merge a b)) < kappa (eqW a b) := by simp [kappa]; omega
    exact drop_left hk
```

**Key insight**: All five remaining cases achieve termination by **strict kappa decrease** (using `drop_left`), rather than the kappa-tie + mu-drop strategy used in the three proved cases. This is because:

- **R_int_delta**: `delta` is transparent to `kappa`, so `integrate(delta t)` has the same `kappa` as `integrate(t)`, which is higher than `void`'s kappa of 0.
- **R_rec_zero & R_rec_succ**: These reduce `recDelta` (which can have arbitrarily high `kappa` due to the +1 in the `delta` case), and the `+1` penalty is eliminated, causing strict `kappa` decrease.
- **R_eq_refl & R_eq_diff**: Similar principle—the `eqW` constructor contributes non-zero `kappa`, which decreases when eliminated.
