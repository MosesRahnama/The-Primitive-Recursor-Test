## Proof skeletons for the five remaining cases

The strategy is the same for all cases: try to show a strict drop in `kappa` (use `drop_left`) or a tie in `kappa` together with a strict drop in `mu` (use `drop_right`).

### `R_int_delta : integrate (delta t) → void`

We have `kappa (integrate (delta t)) = kappa t` and `kappa void = 0`. So either `kappa t > 0` (left drop) or `kappa t = 0` (right drop, since `mu void = 0 < 1 + mu t`).

```lean
| _, _, Step.R_int_delta t => by
    -- mu strictly decreases regardless; the question is which side of the lex we use.
    by_cases hk : kappa t = 0
    · -- right drop: kappa ties, mu strictly decreases
      have hmu : mu void < mu (integrate (delta t)) := by simp [mu]; omega
      have hk_eq : kappa void = kappa (integrate (delta t)) := by
        simp [kappa, hk]
      exact drop_right hmu hk_eq
    · -- left drop: kappa drops from kappa t > 0 down to 0
      have hk_lt : kappa void < kappa (integrate (delta t)) := by
        simp [kappa]; omega
      exact drop_left hk_lt
```

### `R_rec_zero : recDelta b s void → b`

We have `kappa (recDelta b s void) = max (kappa b) (kappa s)` (the `void` third argument contributes `0` to the max). Either `kappa s ≤ kappa b` (so the max equals `kappa b`, giving a tie) or `kappa s > kappa b` (so `kappa b` is the strict smaller one).

```lean
| _, _, Step.R_rec_zero b s => by
    by_cases hle : kappa s <= kappa b
    · -- right drop: max(kappa b, kappa s) = kappa b, so kappa ties;
      -- and mu b < 3 + mu b + mu s always.
      have hmu : mu b < mu (recDelta b s void) := by simp [mu]; omega
      have hk_eq : kappa b = kappa (recDelta b s void) := by
        simp [kappa, hle]
      exact drop_right hmu hk_eq
    · -- left drop: max(kappa b, kappa s) = kappa s > kappa b
      have hk_lt : kappa b < kappa (recDelta b s void) := by
        simp [kappa]; omega
      exact drop_left hk_lt
```

### `R_rec_succ : recDelta b s (delta n) → app s (recDelta b s n)`

Here `kappa` strictly decreases: the LHS has the `+1` from the `delta` arm, the RHS's `kappa (app s (recDelta b s n))` is exactly `max (kappa b) (kappa s) (kappa n)`, i.e. one less.

```lean
| _, _, Step.R_rec_succ b s n => by
    -- lhs = max(max(kb)(ks))(kn) + 1,  rhs = max(ks, max(max(kb)(ks))(kn)) = M
    -- so rhs = M = lhs - 1 < lhs.
    have hk_lt : kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n)) := by
      simp [kappa]; omega
    exact drop_left hk_lt
```

### `R_eq_refl : eqW a a → void`

`kappa (eqW a a) = kappa a` and `kappa void = 0`. Same shape as `R_int_delta`: split on whether `kappa a = 0`.

```lean
| _, _, Step.R_eq_refl a => by
    by_cases hk : kappa a = 0
    · -- right drop: kappa ties at 0; mu drops from 4 + 2*mu a down to 0
      have hmu : mu void < mu (eqW a a) := by simp [mu]; omega
      have hk_eq : kappa void = kappa (eqW a a) := by
        simp [kappa, hk]
      exact drop_right hmu hk_eq
    · -- left drop: 0 < kappa a
      have hk_lt : kappa void < kappa (eqW a a) := by
        simp [kappa]; omega
      exact drop_left hk_lt
```

### `R_eq_diff : eqW a b → integrate (merge a b)`

Both `kappa` values are `max (kappa a) (kappa b)`, but `mu` drops by exactly `1` (`4 + mu a + mu b` down to `3 + mu a + mu b`). Pure right drop.

```lean
| _, _, Step.R_eq_diff a b => by
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by simp [mu]; omega
    have hk_eq : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk_eq
```

### Summary table

| Rule | Strategy | Why it works |
|---|---|---|
| `R_int_delta` | case split on `kappa t = 0` | kappa either drops or ties; mu always drops |
| `R_rec_zero` | case split on `kappa s ≤ kappa b` | kappa either ties (and mu drops by `3 + mu s`) or drops |
| `R_rec_succ` | left drop | kappa drops by exactly 1 (the `+1` from the `delta n` arm) |
| `R_eq_refl` | case split on `kappa a = 0` | same shape as `R_int_delta` |
| `R_eq_diff` | right drop | kappa ties, mu drops by 1 |

Each case relies on `simp [kappa]` / `simp [mu]` to reduce the measure expressions and on `omega` to discharge the resulting linear arithmetic over `Nat`. The case splits are forced by the fact that neither `kappa` nor `mu` alone is guaranteed to drop monotonically on these rules.
