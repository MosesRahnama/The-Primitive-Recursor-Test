# Proof Skeleton for the Remaining Five Cases

Below is a case-by-case analysis with a proof skeleton for each `sorry`. The key strategic decision for each rule is whether `kappa` **drops strictly** (use `drop_left`) or **ties** while `mu` drops (use `drop_right`).

## Case 1: `integrate (delta t) → void`

**Analysis of measure:**
- `kappa (integrate (delta t)) = kappa (delta t) = kappa t` (both transparent)
- `kappa void = 0`
- So kappa may *not* strictly drop (if `kappa t = 0`, they tie). Use `mu`.
- `mu (integrate (delta t)) = 1 + mu (delta t) = 1 + mu t`
- `mu void = 0 < 1 + mu t` ✓ strict drop, and kappa ties requires `kappa t = 0`... 

**Caveat:** kappa does *not* always tie here (`kappa void = 0` but `kappa t` may be positive, meaning kappa *drops*). So this splits: either kappa drops (`drop_left`) or when they'd tie we need mu. Simplest is to note kappa **weakly decreases** and handle both. Skeleton:

```lean
| _, _, Step.R_int_delta t => by
    -- kappa void = 0 ≤ kappa t = kappa (integrate (delta t))
    rcases Nat.eq_zero_or_pos (kappa t) with hz | hpos
    · -- kappa ties at 0; use mu drop
      apply drop_right
      · simp [mu]              -- 0 < 1 + mu t
      · simp [kappa, hz]       -- 0 = 0
    · -- kappa strictly drops: 0 < kappa t
      apply drop_left
      simp [kappa]; exact hpos -- kappa void = 0 < kappa t
```

## Case 2: `recDelta b s void → b`

**Analysis:**
- `kappa (recDelta b s void) = max (max (kappa b) (kappa s)) (kappa void) = max (max (kappa b)(kappa s)) 0` (falls in the *non-delta* recDelta branch, no `+1`)
- `kappa b ≤ kappa (recDelta b s void)`, weak decrease again.
- `mu (recDelta b s void) = 3 + mu b + mu s + mu void = 3 + mu b + mu s`
- `mu b < 3 + mu b + mu s` ✓

Same split pattern (kappa weakly decreases):

```lean
| _, _, Step.R_rec_zero b s => by
    by_cases hk : kappa b = kappa (recDelta b s void)
    · apply drop_right
      · simp [mu]; omega
      · exact hk
    · apply drop_left
      -- kappa b ≤ RHS and ≠, hence <
      have : kappa b ≤ kappa (recDelta b s void) := by
        simp [kappa]; omega   -- b ≤ max(max b s) 0
      omega
```

## Case 3: `recDelta b s (delta n) → app s (recDelta b s n)` — **the crucial case**

**Analysis:** This is where `kappa` must strictly drop (mu likely *increases*: LHS has one recDelta, RHS has app + recDelta).
- LHS: `kappa (recDelta b s (delta n)) = max (max (kappa b)(kappa s)) (kappa n) + 1` (the delta branch, `+1`)
- RHS: `kappa (app s (recDelta b s n)) = max (kappa s) (kappa (recDelta b s n))`
  where `kappa (recDelta b s n) = max (max (kappa b)(kappa s)) (kappa n)` (non-delta branch, no `+1`)
- So RHS `= max (kappa s) (max (max (kappa b)(kappa s)) (kappa n)) = max (max (kappa b)(kappa s)) (kappa n)`
- LHS `= RHS_inner + 1 > RHS_inner`. **Strict kappa drop.** Use `drop_left`.

```lean
| _, _, Step.R_rec_succ b s n => by
    apply drop_left
    -- Goal: kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
    simp only [kappa_app, kappa_rec_delta]
    -- Note: kappa (recDelta b s n) uses the NON-delta branch.
    -- If n itself is delta, `simp [kappa]` may re-fire kappa_rec_delta;
    -- guard by not simplifying inner recDelta, or unfold kappa once:
    show Nat.max (kappa s) (kappa (recDelta b s n))
         < Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) + 1
    -- Reduce kappa (recDelta b s n): case on shape of n
    cases n with
    | delta n' =>
        simp [kappa]; omega   -- careful: inner is now recDelta b s (delta n')
    | _ =>
        simp [kappa]; omega
    -- In all subcases: LHS ≤ (max (max b s) (kappa n)) ≤ RHS_inner < RHS_inner+1
```

**Note:** The `cases n` is needed because `kappa (recDelta b s n)` unfolds differently depending on whether `n` is `delta _`. A cleaner alternative: prove a helper
`kappa (recDelta b s n) ≤ kappa (recDelta b s (delta n))` and combine with the `+1`.

## Case 4: `eqW a a → void`

**Analysis:**
- `kappa (eqW a a) = max (kappa a) (kappa a) = kappa a`; `kappa void = 0`. Weak decrease.
- `mu (eqW a a) = 4 + 2·mu a`; `mu void = 0`. ✓

Same split pattern as Case 1:

```lean
| _, _, Step.R_eq_refl a => by
    rcases Nat.eq_zero_or_pos (kappa a) with hz | hpos
    · apply drop_right
      · simp [mu]; omega       -- 0 < 4 + mu a + mu a
      · simp [kappa, hz]       -- max(0,0)=0
    · apply drop_left
      simp [kappa]; omega      -- 0 < max(kappa a)(kappa a)
```

## Case 5: `eqW a b → integrate (merge a b)`

**Analysis:**
- `kappa (eqW a b) = max (kappa a) (kappa b)`
- `kappa (integrate (merge a b)) = kappa (merge a b) = max (kappa a) (kappa b)`. **kappa ties exactly.** Use `drop_right`.
- `mu (eqW a b) = 4 + mu a + mu b`
- `mu (integrate (merge a b)) = 1 + (2 + mu a + mu b) = 3 + mu a + mu b < 4 + mu a + mu b` ✓

```lean
| _, _, Step.R_eq_diff a b => by
    apply drop_right
    · simp [mu]; omega         -- 3 + mu a + mu b < 4 + mu a + mu b
    · simp [kappa]             -- max = max, exact tie
```

## Summary of Strategy

| Rule | kappa behavior | Tactic |
|------|---------------|--------|
| `R_int_delta` | weakly drops (0 vs kappa t) | split: `drop_left` / `drop_right` |
| `R_rec_zero` | weakly drops | split: `drop_left` / `drop_right` |
| `R_rec_succ` | **strictly drops** (+1 removed) | `drop_left` |
| `R_eq_refl` | weakly drops (vs 0) | split: `drop_left` / `drop_right` |
| `R_eq_diff` | **exact tie** | `drop_right` |

**Recurring lemma to keep handy:** `Nat.eq_zero_or_pos` for the split cases, and `omega` after `simp [kappa]`/`simp [mu]` to close arithmetic on `Nat.max`. The only genuinely subtle case is **R_rec_succ**, where you must ensure `simp` does not incorrectly re-apply `kappa_rec_delta` to the inner `recDelta b s n` when `n` is itself a `delta`.
