A complete proof of `measure_decreases` cannot be constructed for the file as written: the `R_rec_succ` case is false for the stated `(kappa, mu)` measure.

In particular, take:

```lean
b = void
s = void
n = delta void
```

Then the rule is:

```lean
recDelta void void (delta (delta void))
  -->
app void (recDelta void void (delta void))
```

and the measures are:

```lean
measure (recDelta void void (delta (delta void))) = (1, 3)
measure (app void (recDelta void void (delta void))) = (1, 4)
```

Thus `kappa` ties while `mu` increases, so:

```lean
¬ LexOrder
    (measure (app void (recDelta void void (delta void))))
    (measure (recDelta void void (delta (delta void))))
```

The reason is that `kappa` only notices whether the *immediate* third argument of `recDelta` is a `delta`; since `delta` itself is transparent to `kappa`, peeling one outer `delta` can leave the target `recDelta` with the same `kappa`.

The other four remaining cases do admit the following proof skeletons.

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    have hmu : mu void < mu (integrate (delta t)) := by
      simp [mu]
    have hle : kappa void ≤ kappa (integrate (delta t)) := by
      simp [kappa]
    rcases Nat.lt_or_eq_of_le hle with hlt | heq
    · exact drop_left hlt
    · exact drop_right hmu heq
```

```lean
-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    have hmu : mu b < mu (recDelta b s void) := by
      simp [mu]
      omega
    have hle : kappa b ≤ kappa (recDelta b s void) := by
      change kappa b ≤ Nat.max (Nat.max (kappa b) (kappa s)) 0
      exact le_trans (Nat.le_max_left _ _) (Nat.le_max_left _ _)
    rcases Nat.lt_or_eq_of_le hle with hlt | heq
    · exact drop_left hlt
    · exact drop_right hmu heq
```

```lean
-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    have hmu : mu void < mu (eqW a a) := by
      simp [mu]
    have hle : kappa void ≤ kappa (eqW a a) := by
      simp [kappa]
    rcases Nat.lt_or_eq_of_le hle with hlt | heq
    · exact drop_left hlt
    · exact drop_right hmu heq
```

```lean
-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]
      omega
    have hk : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

For the impossible successor case, the natural intended skeleton would have been:

```lean
-- recDelta b s (delta n) --> app s (recDelta b s n)
| _, _, Step.R_rec_succ b s n => by
    -- Intended route:
    -- prove
    --   kappa (app s (recDelta b s n))
    --     < kappa (recDelta b s (delta n))
    -- and use `drop_left`.
    --
    -- This is not provable with the current definition of `kappa`.
    sorry
```

A measure repair would need to make repeated `delta` wrappers observable. For example, changing `kappa` so that `delta` contributes to the recursion-related rank, rather than being fully transparent, would allow the recursive call under `R_rec_succ` to drop even when `n` is itself `delta _`. The exact revised definition should be checked against all eight rules, but the current transparent clause

```lean
| .delta t => kappa t
```

is what makes the displayed counterexample possible.
