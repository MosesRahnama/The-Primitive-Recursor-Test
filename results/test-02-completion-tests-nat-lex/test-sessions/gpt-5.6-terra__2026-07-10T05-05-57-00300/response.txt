However, the requested `R_rec_succ` proof does not exist under the supplied definitions.

Take:

```lean
b = void
s = void
n = delta void
```

Then the rule instance is:

```lean
recDelta void void (delta (delta void))
  -->
app void (recDelta void void (delta void))
```

The measures are:

```lean
kappa (recDelta void void (delta (delta void))) = 1
kappa (app void (recDelta void void (delta void))) = 1

mu (recDelta void void (delta (delta void))) = 3
mu (app void (recDelta void void (delta void))) = 4
```

Hence the alleged decrease would require:

```lean
LexOrder (1, 4) (1, 3)
```

which is false: the `kappa` components tie, while `mu` increases.

The underlying issue is that `kappa` only adds one when the *immediate* third argument of `recDelta` is `delta _`. In the successor rule, if `n` is itself `delta _`, then the recursive call on the right again receives an immediate `delta`, so it preserves that extra `+1`; meanwhile the enclosing `app` makes `mu` larger.

Thus a proof skeleton for that branch could only begin after changing the measure or changing the theorem statement. A suitable repaired primary measure would need to count the entire leading-`delta` spine consumed by `R_rec_succ`, rather than treating `delta` as globally transparent while only inspecting the immediate third argument of `recDelta`.
