## Analysis

Before giving the code, here's the reasoning behind each case (mirroring the style of the three completed cases: split on whether `kappa` strictly drops, using `drop_left`; otherwise show `kappa` ties and `mu` strictly drops, using `drop_right`).

- **`R_int_delta`**: `kappa (integrate (delta t)) = kappa t` and `kappa void = 0`. Split on whether `kappa t = 0`.
- **`R_rec_zero`**: `kappa (recDelta b s void) = max (kappa b) (kappa s)` (the non‑`delta` branch of `kappa`'s match). Split on `kappa b` vs `kappa s`.
- **`R_rec_succ`**: `kappa (recDelta b s (delta n)) = max(max(kappa b)(kappa s))(kappa n) + 1` always. When `n` is **not** headed by `delta`, `kappa (recDelta b s n)` uses the generic equation and is *exactly one less*, giving a clean strict `kappa`‑decrease for the whole RHS. When `n = delta n'`, `kappa` is transparent through `delta`, so `kappa (recDelta b s n)` recomputes to the *same* value as the LHS (tie), while `mu` **increases** (an extra `app` layer is added) rather than decreasing. So this sub‑case cannot be closed with the given `(kappa, mu)` measure — it is left as an honestly‑flagged residual gap.
- **`R_eq_refl`**: `kappa (eqW a a) = kappa a`, `kappa void = 0`; split on `kappa a = 0`.
- **`R_eq_diff`**: `kappa (integrate (merge a b)) = kappa (merge a b) = max (kappa a) (kappa b) = kappa (eqW a b)` — always an exact tie, and `mu` always strictly drops (`3 + mu a + mu b < 4 + mu a + mu b`), so this case needs no case split at all.

## Proof skeleton for the five cases

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    rcases Nat.eq_zero_or_pos (kappa t) with h0 | hpos
    · have hk : kappa void = kappa (integrate (delta t)) := by
        simp [kappa]; omega
      have hmu : mu void < mu (integrate (delta t)) := by
        simp [mu]
      exact drop_right hmu hk
    · have hk : kappa void < kappa (integrate (delta t)) := by
        simp [kappa]; omega
      exact drop_left hk

-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    rcases Nat.lt_or_ge (kappa b) (kappa s) with hlt | hge
    · have hk : kappa b < kappa (recDelta b s void) := by
        simp [kappa]; omega
      exact drop_left hk
    · have hk : kappa b = kappa (recDelta b s void) := by
        simp [kappa]; omega
      have hmu : mu b < mu (recDelta b s void) := by
        simp [mu]; omega
      exact drop_right hmu hk

-- recDelta b s (delta n) --> app s (recDelta b s n)
| _, _, Step.R_rec_succ b s n => by
    cases n with
    | void =>
        apply drop_left; simp [kappa]; omega
    | delta n' =>
        -- `kappa` is transparent through `delta`, so `kappa (recDelta b s (delta n'))`
        -- (the reduct's inner recursor call, since here n = delta n') coincides with
        -- `kappa (recDelta b s (delta n))` (the redex) — i.e. `kappa` ties on this
        -- sub-case. Meanwhile `mu` strictly *increases* here (an extra `app` layer
        -- is introduced), so the (kappa, mu) measure as given cannot certify strict
        -- decrease for this sub-case; a refined measure (e.g. one that actually
        -- counts total `delta`-depth rather than a single flat indicator) would be
        -- needed to close it. Left open here.
        sorry
    | integrate n' =>
        apply drop_left; simp [kappa]; omega
    | merge n1 n2 =>
        apply drop_left; simp [kappa]; omega
    | app n1 n2 =>
        apply drop_left; simp [kappa]; omega
    | recDelta n1 n2 n3 =>
        apply drop_left; simp [kappa]; omega
    | eqW n1 n2 =>
        apply drop_left; simp [kappa]; omega

-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    rcases Nat.eq_zero_or_pos (kappa a) with h0 | hpos
    · have hk : kappa void = kappa (eqW a a) := by
        simp [kappa]; omega
      have hmu : mu void < mu (eqW a a) := by
        simp [mu]; omega
      exact drop_right hmu hk
    · have hk : kappa void < kappa (eqW a a) := by
        simp [kappa]; omega
      exact drop_left hk

-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hk : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]; omega
    exact drop_right hmu hk
```

### Note on the one remaining `sorry`

Four of the five cases (`R_int_delta`, `R_rec_zero`, `R_eq_refl`, `R_eq_diff`) go through cleanly with the given `(kappa, mu)` lexicographic measure, following exactly the `drop_left`/`drop_right` pattern used in the three already‑proved cases.

For `R_rec_succ`, six of the seven shapes of `n` also go through cleanly via a genuine `kappa`‑decrease. The seventh shape, `n = delta n'`, is a real gap: concretely, instantiating `b := void`, `s := void`, `n := delta void` gives `kappa` values `1 = 1` (a tie) while `mu` goes from `3` to `4` (an increase, not a decrease), so `LexOrder (measure (app s (recDelta b s n))) (measure (recDelta b s (delta n)))` genuinely fails for this instance under the stated measure. This is flagged explicitly with `sorry` rather than papered over, since closing it would require strengthening `kappa` (e.g., to count total nested `delta`-depth rather than a flat single-layer indicator) — a change to `kappa`'s definition, which is out of scope here since the file itself is not to be modified.
