Here's a proof skeleton for completing the remaining five cases in the `measure_decreases` theorem. The approach follows the same pattern as the proved cases: show that either `kappa` strictly decreases, or `kappa` stays the same while `mu` strictly decreases.

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    have hk : kappa void < kappa (integrate (delta t)) := by
      simp [kappa]
    exact drop_left hk

-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    have hmu : mu b < mu (recDelta b s void) := by
      simp [mu]
      omega
    have hk : kappa b = kappa (recDelta b s void) := by
      simp [kappa]
    exact drop_right hmu hk

-- recDelta b s (delta n) --> app s (recDelta b s n)
| _, _, Step.R_rec_succ b s n => by
    have hk : kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n)) := by
      simp [kappa]
      omega
    exact drop_left hk

-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    have hk : kappa void < kappa (eqW a a) := by
      simp [kappa]
      omega
    exact drop_left hk

-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]
      omega
    have hk : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

### Explanation of each case:

1. **`R_int_delta` (integrate (delta t) → void)**:
   - `kappa void = 0` is strictly less than `kappa (integrate (delta t)) = kappa t` (unless `t` is `void`, but even then `kappa void = 0`).
   - Thus, we use `drop_left` with the strict decrease in `kappa`.

2. **`R_rec_zero` (recDelta b s void → b)**:
   - `kappa b = kappa (recDelta b s void)` because `recDelta b s void` falls into the non-`delta` case for its third argument.
   - `mu b < mu (recDelta b s void)` because `mu (recDelta b s void) = 3 + mu b + mu s + mu void = 3 + mu b + mu s`, which is strictly greater than `mu b`.
   - Thus, we use `drop_right` with the strict decrease in `mu` and equality in `kappa`.

3. **`R_rec_succ` (recDelta b s (delta n) → app s (recDelta b s n))**:
   - `kappa (recDelta b s (delta n)) = max (max (kappa b) (kappa s)) (kappa n) + 1` (by definition).
   - `kappa (app s (recDelta b s n)) = max (kappa s) (kappa (recDelta b s n)) = max (kappa s) (max (max (kappa b) (kappa s)) (kappa n)) = max (max (kappa b) (kappa s)) (kappa n)`.
   - Thus, `kappa` strictly decreases by 1, so we use `drop_left`.

4. **`R_eq_refl` (eqW a a → void)**:
   - `kappa void = 0` is strictly less than `kappa (eqW a a) = max (kappa a) (kappa a) = kappa a` (unless `a` is `void`, but even then `kappa void = 0`).
   - Thus, we use `drop_left` with the strict decrease in `kappa`.

5. **`R_eq_diff` (eqW a b → integrate (merge a b))**:
   - `kappa (integrate (merge a b)) = kappa (merge a b) = max (kappa a) (kappa b) = kappa (eqW a b)`.
   - `mu (integrate (merge a b)) = 1 + mu (merge a b) = 1 + 2 + mu a + mu b = 3 + mu a + mu b`.
   - `mu (eqW a b) = 4 + mu a + mu b`.
   - Thus, `mu` strictly decreases by 1, and `kappa` stays the same, so we use `drop_right`.

The `omega` tactic is used to handle linear arithmetic goals that arise from the definitions of `mu` and `kappa`. The `simp` tactic unfolds the definitions and simplifies the expressions.
