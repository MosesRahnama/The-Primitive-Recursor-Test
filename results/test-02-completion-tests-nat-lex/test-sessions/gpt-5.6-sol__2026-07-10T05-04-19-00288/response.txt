## Obstruction in `R_rec_succ`

Take:

```lean
b := void
s := void
n := delta void
```

The rule instance is:

```lean
Step
  (recDelta void void (delta (delta void)))
  (app void (recDelta void void (delta void)))
```

For the source:

```lean
kappa (recDelta void void (delta (delta void))) = 1
mu    (recDelta void void (delta (delta void))) = 3
```

For the target:

```lean
kappa (app void (recDelta void void (delta void))) = 1
mu    (app void (recDelta void void (delta void))) = 4
```

Thus the combined measures are:

```lean
measure source = (1, 3)
measure target = (1, 4)
```

Consequently,

```lean
LexOrder (measure target) (measure source)
```

is false: `kappa` ties, while `mu` increases rather than decreases.

The problem arises whenever `n` is itself delta-wrapped. The recursive call `recDelta b s n` then retains the `+1` in `kappa`, so the primary measure does not drop; meanwhile `app` duplicates the contribution of `s`, causing `mu` to increase.

Therefore no proof skeleton exists for the fifth case under the current definitions. Completing the file requires changing at least one of:

- the definition of `kappa` or the combined measure,
- the `R_rec_succ` rule or its applicability conditions, or
- the statement that every step decreases this particular lexicographic measure.

As a result, the given proof of `strong_normalization`, which depends on `measure_decreases`, also cannot be completed unchanged.
