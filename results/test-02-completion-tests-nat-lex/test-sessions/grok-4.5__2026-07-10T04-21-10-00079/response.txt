## Proof skeleton for the five remaining cases

The three completed cases all follow the same pattern: exhibit either a strict `kappa` drop (`drop_left`) or a `kappa` tie plus a strict `mu` drop (`drop_right`). The five `sorry`s fit the same scaffolding. Below is a drop-in skeleton (comments record the measure arithmetic you need).

```lean
-- ── Remaining cases ───────────────────────────────────────────

-- integrate (delta t) --> void
--   κ :  0  ≤  κ t     (tie iff κ t = 0)
--   μ :  0  <  1 + μ t  (always)
| _, _, Step.R_int_delta t => by
    by_cases h : kappa t = 0
    · -- kappa ties at 0; mu drops
      have hmu : mu void < mu (integrate (delta t)) := by
        simp [mu]
      have hk : kappa void = kappa (integrate (delta t)) := by
        simp [kappa, h]
      exact drop_right hmu hk
    · -- kappa drops
      have hk : kappa void < kappa (integrate (delta t)) := by
        simp [kappa]; omega
      exact drop_left hk

-- recDelta b s void --> b
--   κ :  κ b  ≤  max(κ b, κ s)   (tie iff κ s ≤ κ b)
--   μ :  μ b  <  3 + μ b + μ s   (always)
| _, _, Step.R_rec_zero b s => by
    by_cases h : kappa s ≤ kappa b
    · -- kappa ties; mu drops
      have hmu : mu b < mu (recDelta b s void) := by
        simp [mu]; omega
      have hk : kappa b = kappa (recDelta b s void) := by
        simp [kappa]; omega
      exact drop_right hmu hk
    · -- kappa drops
      have hk : kappa b < kappa (recDelta b s void) := by
        simp [kappa]; omega
      exact drop_left hk

-- recDelta b s (delta n) --> app s (recDelta b s n)
--   Intended: the “+1” baked into kappa for a delta-wrapped third
--   argument is consumed, so kappa drops strictly (mu may rise,
--   so drop_right is unavailable — must use drop_left).
| _, _, Step.R_rec_succ b s n => by
    have hk :
        kappa (app s (recDelta b s n))
          < kappa (recDelta b s (delta n)) := by
      -- Goal after simp:
      --   max (κ s) (kappa (recDelta b s n))
      --     < max (max (κ b) (κ s)) (κ n) + 1
      --
      -- Supply the bounding lemma
      --   kappa (recDelta b s n)
      --     ≤ max (max (κ b) (κ s)) (κ n)
      -- then finish with max-arithmetic / omega.
      --
      -- Prove the bound by cases (or induction) on n:
      --   · n = delta m  →  uses the +1 clause of kappa
      --   · otherwise    →  uses the catch-all clause
      -- In every non-delta branch the inequality is immediate;
      -- the delta branch is the only delicate sub-goal
      -- (it is where the measure design is tightest).
      cases n with
      | void          => simp [kappa]; omega
      | delta m       =>
          simp [kappa]
          -- max (κ s) (max (max (κ b) (κ s)) (κ m) + 1)
          --   <  max (max (κ b) (κ s)) (κ m) + 1   ?  -- FALSE as written
          -- If this sub-goal does not go through, the combined
          -- (kappa, mu) measure needs a small adjustment
          -- (e.g. a third component, or a different weight on
          --  recDelta) before drop_left applies uniformly.
          sorry
      | integrate t   => simp [kappa]; omega
      | merge a b'    => simp [kappa]; omega
      | app a b'      => simp [kappa]; omega
      | recDelta b' s' n' => simp [kappa]; omega
      | eqW a b'      => simp [kappa]; omega
    exact drop_left hk

-- eqW a a --> void
--   κ :  0  ≤  κ a     (tie iff κ a = 0)
--   μ :  0  <  4 + 2·μ a  (always)
| _, _, Step.R_eq_refl a => by
    by_cases h : kappa a = 0
    · -- kappa ties at 0; mu drops
      have hmu : mu void < mu (eqW a a) := by
        simp [mu]; omega
      have hk : kappa void = kappa (eqW a a) := by
        simp [kappa, h]
      exact drop_right hmu hk
    · -- kappa drops
      have hk : kappa void < kappa (eqW a a) := by
        simp [kappa]; omega
      exact drop_left hk

-- eqW a b --> integrate (merge a b)
--   κ :  max(κ a, κ b) = max(κ a, κ b)   (always ties)
--   μ :  3 + μ a + μ b  <  4 + μ a + μ b  (drops by 1)
| _, _, Step.R_eq_diff a b => by
    have hmu :
        mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]; omega
    have hk :
        kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

### How each case uses the scaffolding

| Rule | `kappa` behaviour | `mu` behaviour | Combinator |
|------|-------------------|----------------|------------|
| `R_int_delta` | ≤, strict unless `κ t = 0` | always ↓ | `by_cases` → `drop_left` / `drop_right` |
| `R_rec_zero` | ≤, strict unless `κ s ≤ κ b` | always ↓ | `by_cases` → `drop_left` / `drop_right` |
| `R_rec_succ` | intended strict ↓ (the `+1`) | may ↑ | `drop_left` only |
| `R_eq_refl` | ≤, strict unless `κ a = 0` | always ↓ | `by_cases` → `drop_left` / `drop_right` |
| `R_eq_diff` | always ties | always ↓ by 1 | `drop_right` |

### Note on `R_rec_succ`

For every constructor of `n` except `delta`, the inequality

```text
kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
```

is immediate from the definition of `kappa` and `omega`. When `n = delta m` the two sides become equal, and `mu` *increases*, so the current lexicographic pair does not decrease. The skeleton isolates that single sub-goal under `sorry` so the rest of the development can proceed; closing it requires either a refined measure (extra component, or a different weight on `recDelta`) or a side lemma that rules out the nested-`delta` configuration in the contexts you care about.

Once `measure_decreases` is complete for all eight constructors, the existing `strong_normalization` argument (`Subrelation.wf` + `InvImage.wf` of `wf_LexOrder`) goes through unchanged.
