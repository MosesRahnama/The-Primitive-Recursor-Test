The five cases cannot all be completed: `measure_decreases` is false for `R_rec_succ` when `n` is itself delta-wrapped. The other four cases have straightforward proof skeletons.

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    by_cases hκ : kappa t = 0
    · have hmu : mu void < mu (integrate (delta t)) := by
        simp [mu]
      have hk : kappa void = kappa (integrate (delta t)) := by
        simp [kappa, hκ]
      exact drop_right hmu hk
    · apply drop_left
      simp [kappa]
      omega

-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    have hle : kappa b ≤ kappa (recDelta b s void) := by
      simp [kappa, Nat.le_max_left]
    by_cases hk : kappa b = kappa (recDelta b s void)
    · have hmu : mu b < mu (recDelta b s void) := by
        simp [mu]
        omega
      exact drop_right hmu hk
    · apply drop_left
      omega
```

The `R_rec_succ` case has no proof under the current definitions:

```lean
-- recDelta b s (delta n) --> app s (recDelta b s n)
| _, _, Step.R_rec_succ b s n => by
    -- Impossible with the current measure.
    sorry
```

A concrete counterexample is obtained with

```lean
b := void
s := void
n := delta void
```

The rule gives

```lean
recDelta void void (delta (delta void))
  -->
app void (recDelta void void (delta void))
```

but the measures are:

```text
measure (recDelta void void (delta (delta void))) = (1, 3)
measure (app void (recDelta void void (delta void))) = (1, 4)
```

Thus `kappa` ties while `mu` increases, so

```lean
LexOrder (1, 4) (1, 3)
```

is false. More generally, whenever `n = delta m`, the source and target `kappa` values tie, while the target’s `mu` exceeds the source’s by `1 + mu s`.

The final two cases can be structured as follows:

```lean
-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    by_cases hκ : kappa a = 0
    · have hmu : mu void < mu (eqW a a) := by
        simp [mu]
        omega
      have hk : kappa void = kappa (eqW a a) := by
        simp [kappa, hκ]
      exact drop_right hmu hk
    · apply drop_left
      simp [kappa]
      omega

-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hmu :
        mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]
      omega
    have hk :
        kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

Consequently, the file as written cannot prove `measure_decreases`, and hence the displayed proof of `strong_normalization` cannot be completed through this measure. The recursion measure must be strengthened—e.g. by adding a component that strictly counts the leading `delta` spine of the recursive argument—or the recursion rule/measure definitions must otherwise be changed.
