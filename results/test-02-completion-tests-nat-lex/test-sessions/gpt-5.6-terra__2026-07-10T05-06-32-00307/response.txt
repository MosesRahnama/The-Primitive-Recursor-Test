The `R_rec_succ` case cannot be completed with the stated measure definitions: it is not a lexicographic decrease in general.

A counterexample is:

```lean
b = void
s = void
n = delta void
```

Then the rule instance is

```lean
recDelta void void (delta (delta void))
  -->
app void (recDelta void void (delta void))
```

and the measures are:

```lean
measure (recDelta void void (delta (delta void))) = (1, 3)
measure (app void (recDelta void void (delta void))) = (1, 4)
```

So the first components tie and the second component increases. Consequently,

```lean
LexOrder
  (measure (app void (recDelta void void (delta void))))
  (measure (recDelta void void (delta (delta void))))
```

is false.

The issue is that `kappa` makes `delta` transparent:

```lean
kappa (delta t) = kappa t
```

Thus the source and target of `R_rec_succ` can have equal `kappa`, while the target duplicates/retains enough structure that `mu` increases.

The other four cases can use the following skeletons.

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    by_cases h : kappa t = 0
    · have hmu : mu void < mu (integrate (delta t)) := by
        simp [mu]
      have hk : kappa void = kappa (integrate (delta t)) := by
        simpa [kappa, h]
      exact drop_right hmu hk
    · have hk : kappa void < kappa (integrate (delta t)) := by
        simpa [kappa] using Nat.pos_of_ne_zero h
      exact drop_left hk
```

```lean
-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    by_cases hlt : kappa b < kappa (recDelta b s void)
    · exact drop_left hlt
    · have hmu : mu b < mu (recDelta b s void) := by
        simp [mu]
        omega
      have hle : kappa b ≤ kappa (recDelta b s void) := by
        change kappa b ≤ Nat.max (Nat.max (kappa b) (kappa s)) 0
        exact le_trans (Nat.le_max_left _ _) (Nat.le_max_left _ _)
      have hk : kappa b = kappa (recDelta b s void) :=
        Nat.le_antisymm hle (Nat.le_of_not_gt hlt)
      exact drop_right hmu hk
```

```lean
-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    by_cases h : kappa a = 0
    · have hmu : mu void < mu (eqW a a) := by
        simp [mu]
      have hk : kappa void = kappa (eqW a a) := by
        simpa [kappa, h]
      exact drop_right hmu hk
    · have hk : kappa void < kappa (eqW a a) := by
        simpa [kappa] using Nat.pos_of_ne_zero h
      exact drop_left hk
```

```lean
-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]
      omega
    have hk : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

For the impossible successor case, the intended proof shape would have been:

```lean
| _, _, Step.R_rec_succ b s n => by
    -- Need either:
    --   kappa (app s (recDelta b s n))
    --     < kappa (recDelta b s (delta n))
    --
    -- or equality of kappa together with:
    --   mu (app s (recDelta b s n))
    --     < mu (recDelta b s (delta n)).
    --
    -- Both fail for n = delta void, b = void, s = void.
    sorry
```

To make this proof strategy work, the measure must be changed. In particular, `kappa` needs to distinguish nested `delta` layers relevant to `recDelta` successor reduction, rather than treating all `delta` constructors as transparent.
