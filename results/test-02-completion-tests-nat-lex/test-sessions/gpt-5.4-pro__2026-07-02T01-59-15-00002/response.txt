Here is a proof skeleton you can paste into the five remaining branches.

Four of the five cases are routine with your current setup. The `R_rec_succ` branch is different: with the current `(kappa, mu)` it appears genuinely unprovable, because there is a concrete counterexample when `n` itself is `delta _`.

## Straightforward cases

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    by_cases hk0 : kappa t = 0
    · have hmu : mu void < mu (integrate (delta t)) := by
        simp [mu]
      have hk : kappa void = kappa (integrate (delta t)) := by
        simp [kappa, hk0]
      exact drop_right hmu hk
    · have hk : kappa void < kappa (integrate (delta t)) := by
        have hpos : 0 < kappa t := Nat.pos_of_ne_zero hk0
        simpa [kappa] using hpos
      exact drop_left hk

-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    by_cases hsb : kappa s ≤ kappa b
    · have hmu : mu b < mu (recDelta b s void) := by
        simp [mu]
        omega
      have hk : kappa b = kappa (recDelta b s void) := by
        simp [kappa,
          Nat.max_eq_left hsb,
          Nat.max_eq_left (Nat.zero_le (kappa b))]
      exact drop_right hmu hk
    · have hs : kappa b < kappa s := lt_of_not_ge hsb
      have hk : kappa b < kappa (recDelta b s void) := by
        simp [kappa,
          Nat.max_eq_right hs.le,
          Nat.max_eq_left (Nat.zero_le (kappa s)),
          hs]
      exact drop_left hk

-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    by_cases hk0 : kappa a = 0
    · have hmu : mu void < mu (eqW a a) := by
        simp [mu]
        omega
      have hk : kappa void = kappa (eqW a a) := by
        simp [kappa, hk0]
      exact drop_right hmu hk
    · have hk : kappa void < kappa (eqW a a) := by
        have hpos : 0 < kappa a := Nat.pos_of_ne_zero hk0
        simpa [kappa] using hpos
      exact drop_left hk

-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]
      omega
    have hk : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

## The problematic case: `R_rec_succ`

A natural skeleton is to split on the shape of `n`:

```lean
| _, _, Step.R_rec_succ b s n => by
    cases n with
    | void =>
        have hs :
            kappa s ≤ Nat.max (Nat.max (kappa b) (kappa s)) (kappa void) := by
          exact le_trans (Nat.le_max_right _ _) (Nat.le_max_left _ _)
        have hk :
            kappa (app s (recDelta b s void)) <
              kappa (recDelta b s (delta void)) := by
          simp [kappa, Nat.max_eq_right hs, Nat.lt_succ_self]
        exact drop_left hk

    | delta n' =>
        -- This is the obstructing branch.
        -- `simp [kappa, mu]` shows:
        --   kappa (app s (recDelta b s (delta n')))
        --     = kappa (recDelta b s (delta (delta n')))
        -- while `mu` actually goes *up* on the right-hand side of the step.
        --
        -- So this branch is not closable with the current `measure`.
        sorry

    | integrate t =>
        have hs :
            kappa s ≤ Nat.max (Nat.max (kappa b) (kappa s)) (kappa (integrate t)) := by
          exact le_trans (Nat.le_max_right _ _) (Nat.le_max_left _ _)
        have hk :
            kappa (app s (recDelta b s (integrate t))) <
              kappa (recDelta b s (delta (integrate t))) := by
          simp [kappa, Nat.max_eq_right hs, Nat.lt_succ_self]
        exact drop_left hk

    | merge a c =>
        have hs :
            kappa s ≤ Nat.max (Nat.max (kappa b) (kappa s)) (kappa (merge a c)) := by
          exact le_trans (Nat.le_max_right _ _) (Nat.le_max_left _ _)
        have hk :
            kappa (app s (recDelta b s (merge a c))) <
              kappa (recDelta b s (delta (merge a c))) := by
          simp [kappa, Nat.max_eq_right hs, Nat.lt_succ_self]
        exact drop_left hk

    | app a c =>
        have hs :
            kappa s ≤ Nat.max (Nat.max (kappa b) (kappa s)) (kappa (app a c)) := by
          exact le_trans (Nat.le_max_right _ _) (Nat.le_max_left _ _)
        have hk :
            kappa (app s (recDelta b s (app a c))) <
              kappa (recDelta b s (delta (app a c))) := by
          simp [kappa, Nat.max_eq_right hs, Nat.lt_succ_self]
        exact drop_left hk

    | recDelta b' s' n' =>
        have hs :
            kappa s ≤ Nat.max (Nat.max (kappa b) (kappa s)) (kappa (recDelta b' s' n')) := by
          exact le_trans (Nat.le_max_right _ _) (Nat.le_max_left _ _)
        have hk :
            kappa (app s (recDelta b s (recDelta b' s' n'))) <
              kappa (recDelta b s (delta (recDelta b' s' n'))) := by
          simp [kappa, Nat.max_eq_right hs, Nat.lt_succ_self]
        exact drop_left hk

    | eqW a c =>
        have hs :
            kappa s ≤ Nat.max (Nat.max (kappa b) (kappa s)) (kappa (eqW a c)) := by
          exact le_trans (Nat.le_max_right _ _) (Nat.le_max_left _ _)
        have hk :
            kappa (app s (recDelta b s (eqW a c))) <
              kappa (recDelta b s (delta (eqW a c))) := by
          simp [kappa, Nat.max_eq_right hs, Nat.lt_succ_self]
        exact drop_left hk
```

## Why `R_rec_succ` really fails with the current measure

Take `b = void`, `s = void`, `n = delta void`. Then the step is

```lean
recDelta void void (delta (delta void))
  --> app void (recDelta void void (delta void))
```

and:

- source measure = `(1, 3)`
- target measure = `(1, 4)`

So the target is **not** lexicographically smaller.

That means the theorem `measure_decreases` is false as stated for this rule set and this measure. So the first four skeletons above should be fine, but the `R_rec_succ` branch needs a **different measure** (for example, one that counts the full top-level `delta`-prefix depth in the third argument of `recDelta`, not just a single bonus `+1`).
