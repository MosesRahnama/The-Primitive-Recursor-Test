# Proof Skeleton for the Remaining Five Cases

Below is a skeleton with reasoning for each case, indicating which lemma (`drop_left` or `drop_right`) applies and the arithmetic facts needed.

## Case 1: `integrate (delta t) --> void`

**Analysis:** `kappa (integrate (delta t)) = kappa (delta t) = kappa t`, and `kappa void = 0`. So kappa may tie *only when* `kappa t = 0`; in general kappa could drop or tie. Safer to use `mu`: `mu (integrate (delta t)) = 1 + mu (delta t) = 1 + mu t > 0 = mu void`. But kappa does **not** always tie here (if `kappa t > 0` then kappa strictly drops). Handle both: if kappa drops use `drop_left`; otherwise it ties and use `drop_right`.

```lean
| _, _, Step.R_int_delta t => by
    -- kappa void = 0 ≤ kappa t = kappa (integrate (delta t))
    -- Either kappa strictly drops, or it ties (when kappa t = 0).
    rcases Nat.eq_zero_or_pos (kappa t) with hz | hpos
    · -- kappa ties: both sides have kappa 0; use mu
      apply drop_right
      · simp [mu]                       -- 0 < 1 + mu t
      · simp [kappa, hz]                -- kappa void = 0 = kappa t
    · -- kappa strictly drops: 0 < kappa t
      apply drop_left
      simp [kappa]                      -- kappa void = 0 < kappa t = kappa (integrate (delta t))
      exact hpos
```

## Case 2: `recDelta b s void --> b`

**Analysis:** `kappa (recDelta b s void) = max (max (kappa b) (kappa s)) (kappa void) = max (max (kappa b) (kappa s)) 0 = max (kappa b) (kappa s)`. The result `b` has `kappa b ≤ max (kappa b) (kappa s)`. Kappa ties only when `kappa b` dominates. Use a case split, or just note kappa never increases and mu strictly drops. Cleanest: split on whether kappa ties.

```lean
| _, _, Step.R_rec_zero b s => by
    -- kappa (recDelta b s void) = max (kappa b) (kappa s)  (void contributes 0)
    -- kappa b ≤ that maximum.
    rcases Nat.lt_or_ge (kappa b) (kappa (recDelta b s void)) with hlt | hge
    · apply drop_left; exact hlt
    · -- kappa ties (kappa b = max), use mu: mu b < 3 + mu b + mu s + 0
      apply drop_right
      · simp [mu]                       -- mu b < 3 + mu b + mu s + mu void
      · -- kappa b = kappa (recDelta b s void)
        have : kappa (recDelta b s void)
             = Nat.max (kappa b) (kappa s) := by simp [kappa]
        omega                           -- from hge and le_max_left
```

## Case 3: `recDelta b s (delta n) --> app s (recDelta b s n)`

**Analysis:** This is the crucial case. 
- LHS kappa `= max (max (kappa b) (kappa s)) (kappa n) + 1` (the `+1` from `kappa_rec_delta`).
- RHS: `kappa (app s (recDelta b s n)) = max (kappa s) (kappa (recDelta b s n))`. Here the inner `recDelta b s n` has `n` **not** delta-wrapped (generically), so `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n)` — with **no** `+1`.
- Thus RHS `= max (kappa s) (max (max (kappa b) (kappa s)) (kappa n)) = max (max (kappa b) (kappa s)) (kappa n)`, which is exactly LHS `- 1`. So **kappa strictly drops by 1**. Use `drop_left`.

⚠️ Subtlety: if `n` is itself `delta n'`, then `kappa (recDelta b s n)` gains a `+1`, but it is still `≤ LHS - 1 + 1 = LHS`... actually one must verify. The definition gives `kappa (recDelta b s (delta n')) = ... + 1` but the LHS is `kappa (recDelta b s (delta (delta n'))) = max(...,kappa(delta n')) + 1`. Since `kappa (delta n') = kappa n'`, the inner recDelta contributes the same max plus 1, and the `app`'s outer max with `kappa s` is absorbed. Careful expansion shows RHS = LHS still drops. Handle via a `cases n` split to expose the `kappa` reduction.

```lean
| _, _, Step.R_rec_succ b s n => by
    apply drop_left
    -- Goal: kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n))
    -- LHS kappa = max (max (kappa b) (kappa s)) (kappa n) + 1
    simp only [kappa_rec_delta, kappa_app]
    -- Now must compute kappa (recDelta b s n); split on n to unfold correctly.
    cases n with
    | void       => simp [kappa]; omega
    | delta n'   => simp [kappa]; omega
    | integrate _ => simp [kappa]; omega
    | merge _ _  => simp [kappa]; omega
    | app _ _    => simp [kappa]; omega
    | recDelta _ _ _ => simp [kappa]; omega
    | eqW _ _    => simp [kappa]; omega
    -- In each branch, RHS max ≤ LHS max, and the +1 provides strict decrease.
    -- The `omega` closes using max monotonicity facts introduced by simp;
    -- if simp does not surface them, add:
    --   have := Nat.le_max_left (kappa s) ...
    --   have := Nat.le_max_right ...
    -- before omega.
```

## Case 4: `eqW a a --> void`

**Analysis:** `kappa (eqW a a) = max (kappa a) (kappa a) = kappa a`, `kappa void = 0`. Ties iff `kappa a = 0`. `mu (eqW a a) = 4 + mu a + mu a > 0 = mu void`. Same split pattern as Case 1.

```lean
| _, _, Step.R_eq_refl a => by
    rcases Nat.eq_zero_or_pos (kappa a) with hz | hpos
    · apply drop_right
      · simp [mu]                       -- 0 < 4 + mu a + mu a
      · simp [kappa, hz]                -- kappa void = 0 = max (kappa a)(kappa a)
    · apply drop_left
      simp [kappa]                      -- 0 < max (kappa a) (kappa a) = kappa a
      exact hpos
```

## Case 5: `eqW a b --> integrate (merge a b)`

**Analysis:** 
- `kappa (eqW a b) = max (kappa a) (kappa b)`.
- `kappa (integrate (merge a b)) = kappa (merge a b) = max (kappa a) (kappa b)`. **Kappa ties exactly.**
- `mu (eqW a b) = 4 + mu a + mu b`; `mu (integrate (merge a b)) = 1 + (2 + mu a + mu b) = 3 + mu a + mu b < 4 + mu a + mu b`. **mu strictly drops by 1.** Use `drop_right`.

```lean
| _, _, Step.R_eq_diff a b => by
    apply drop_right
    · -- mu drops: 3 + mu a + mu b < 4 + mu a + mu b
      simp [mu]; omega
    · -- kappa ties: both equal max (kappa a) (kappa b)
      simp [kappa]
```

## General Notes / Fallback Tactics

- For every case, the invariant is: **kappa never increases**; either it strictly drops (`drop_left`) or ties and mu strictly drops (`drop_right`).
- The `void`-target cases (1 and 4) require the `Nat.eq_zero_or_pos` split because kappa ties *only* in the degenerate zero subcase.
- Case 3 is the only genuine `drop_left` from the `+1` in `kappa_rec_delta`; the `cases n` is needed because `kappa (recDelta b s n)` unfolds differently depending on the head of `n`.
- If a raw `omega` fails after `simp`, introduce the relevant `Nat.le_max_left`/`Nat.le_max_right`/`Nat.max_le` facts explicitly, then retry `omega`.
