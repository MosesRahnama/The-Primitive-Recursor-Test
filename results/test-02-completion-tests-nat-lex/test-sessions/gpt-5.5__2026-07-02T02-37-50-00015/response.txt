As written, four of the five remaining cases have standard lexicographic-decrease skeletons, but the `R_rec_succ` case cannot be completed with the current `kappa`/`mu` measure. The obstruction is real, not just a missing tactic.

Here are the four fillable cases:

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    by_cases hk0 : kappa t = 0
    · have hmu : mu void < mu (integrate (delta t)) := by
        simp [mu]
      have hk : kappa void = kappa (integrate (delta t)) := by
        simp [kappa, hk0]
      exact drop_right hmu hk
    · have hk : kappa void < kappa (integrate (delta t)) := by
        simpa [kappa] using Nat.pos_of_ne_zero hk0
      exact drop_left hk

-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    have hmu : mu b < mu (recDelta b s void) := by
      simp [mu]
      omega
    have hle : kappa b ≤ kappa (recDelta b s void) := by
      simpa [kappa] using
        (le_trans
          (Nat.le_max_left (kappa b) (kappa s))
          (Nat.le_max_left (Nat.max (kappa b) (kappa s)) 0))
    by_cases hk : kappa b = kappa (recDelta b s void)
    · exact drop_right hmu hk
    · exact drop_left (lt_of_le_of_ne hle hk)

-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    by_cases hk0 : kappa a = 0
    · have hmu : mu void < mu (eqW a a) := by
        simp [mu]
        omega
      have hk : kappa void = kappa (eqW a a) := by
        simp [kappa, hk0]
      exact drop_right hmu hk
    · have hk : kappa void < kappa (eqW a a) := by
        simpa [kappa] using Nat.pos_of_ne_zero hk0
      exact drop_left hk

-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]
      omega
    have hk : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

The problematic case is:

```lean
-- recDelta b s (delta n) --> app s (recDelta b s n)
| _, _, Step.R_rec_succ b s n => by
    sorry
```

The intended proof would presumably be by `drop_left`, showing that `kappa` strictly decreases. But this is false when `n` is itself a `delta`.

For example, take:

```lean
b = void
s = void
n = delta void
```

Then the step is:

```lean
recDelta void void (delta (delta void))
  -->
app void (recDelta void void (delta void))
```

The measures are:

```lean
measure (recDelta void void (delta (delta void))) = (1, 3)
measure (app void (recDelta void void (delta void))) = (1, 4)
```

So `kappa` ties and `mu` increases. Therefore:

```lean
LexOrder (measure (app void (recDelta void void (delta void))))
         (measure (recDelta void void (delta (delta void))))
```

is false.

Thus the theorem `measure_decreases` cannot be proved as stated. To make the `R_rec_succ` case provable, the measure needs to be changed, e.g. by making the recursion-depth component count all leading `delta`s in the third argument of `recDelta`, not merely whether the third argument is syntactically one `delta` deep.
