Here's a proof skeleton for completing the remaining five cases in the `measure_decreases` theorem. The approach follows the same pattern as the proved cases: show that either `kappa` strictly decreases, or it stays the same while `mu` strictly decreases.

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    have hk : kappa void < kappa (integrate (delta t)) := by
      simp [kappa]
    exact drop_left hk

-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    have hmu : mu b < mu (recDelta b s void) := by
      simp [mu]
      omega
    have hk : kappa b = kappa (recDelta b s void) := by
      simp [kappa]
    exact drop_right hmu hk

-- recDelta b s (delta n) --> app s (recDelta b s n)
| _, _, Step.R_rec_succ b s n => by
    have hk : kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n)) := by
      simp [kappa]
      omega
    exact drop_left hk

-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    have hk : kappa void < kappa (eqW a a) := by
      simp [kappa]
      omega
    exact drop_left hk

-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]
      omega
    have hk : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

### Explanation of each case:

1. **`R_int_delta` (integrate (delta t) → void)**:
   - `kappa void = 0` is strictly less than `kappa (integrate (delta t)) = kappa t` (unless `t` is `void`, but even then `kappa void = 0`).
   - Thus, we use `drop_left` with the strict decrease in `kappa`.

2. **`R_rec_zero` (recDelta b s void → b)**:
   - `kappa` is the same for both sides (since `kappa void = 0` and `kappa (recDelta b s void) = max (max (kappa b) (kappa s)) 0`).
   - `mu b` is strictly less than `mu (recDelta b s void) = 3 + mu b + mu s + 0` (since `mu s ≥ 0`).
   - Thus, we use `drop_right` with the strict decrease in `mu` and equality in `kappa`.

3. **`R_rec_succ` (recDelta b s (delta n) → app s (recDelta b s n))**:
   - `kappa (recDelta b s (delta n)) = max (max (kappa b) (kappa s)) (kappa n) + 1` (by definition).
   - `kappa (app s (recDelta b s n)) = max (kappa s) (max (max (kappa b) (kappa s)) (kappa n))` (since `kappa (recDelta b s n) = max (max (kappa b) (kappa s)) (kappa n)`).
   - The `+1` on the LHS ensures `kappa` strictly decreases, so we use `drop_left`.

4. **`R_eq_refl` (eqW a a → void)**:
   - `kappa void = 0` is strictly less than `kappa (eqW a a) = max (kappa a) (kappa a) = kappa a` (unless `a` is `void`, but even then `kappa void = 0`).
   - Thus, we use `drop_left` with the strict decrease in `kappa`.

5. **`R_eq_diff` (eqW a b → integrate (merge a b))**:
   - `kappa` is the same for both sides (both are `max (kappa a) (kappa b)`).
   - `mu (integrate (merge a b)) = 1 + mu (merge a b) = 1 + 2 + mu a + mu b = 3 + mu a + mu b`.
   - `mu (eqW a b) = 4 + mu a + mu b`.
   - Thus, `mu` strictly decreases, and we use `drop_right` with the strict decrease in `mu` and equality in `kappa`.

The `omega` tactic is used to handle linear arithmetic goals that arise from the `mu` and `kappa` definitions. The `simp` tactic unfolds the definitions of `mu` and `kappa` for the relevant constructors.
