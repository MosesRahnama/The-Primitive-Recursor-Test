The five remaining cases cannot all be completed with the stated measure: the `R_rec_succ` branch is false for this `kappa, mu` lexicographic measure.

In particular, take `b = void`, `s = void`, and `n = delta void`. Then the step is

```lean
recDelta void void (delta (delta void))
  -->
app void (recDelta void void (delta void))
```

and the measures are:

```text
source: (kappa, mu) = (1, 3)
target: (kappa, mu) = (1, 4)
```

Thus the target is not lexicographically smaller than the source. Consequently, no proof term for the `R_rec_succ` case of `measure_decreases` exists with the definitions in the file.

The other four cases can use the following proof skeletons.

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    by_cases h : kappa t = 0
    · have hmu : mu void < mu (integrate (delta t)) := by
        simp [mu]
      have hk : kappa void = kappa (integrate (delta t)) := by
        simp [kappa, h]
      exact drop_right hmu hk
    · have hk : kappa void < kappa (integrate (delta t)) := by
        simp [kappa]
        exact Nat.pos_of_ne_zero h
      exact drop_left hk
```

```lean
-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    have hle : kappa b ≤ kappa (recDelta b s void) := by
      simpa [kappa] using Nat.le_max_left (kappa b) (kappa s)
    rcases lt_or_eq_of_le hle with hlt | heq
    · exact drop_left hlt
    · have hmu : mu b < mu (recDelta b s void) := by
        simp [mu]
        omega
      exact drop_right hmu heq
```

```lean
-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    by_cases h : kappa a = 0
    · have hmu : mu void < mu (eqW a a) := by
        simp [mu]
      have hk : kappa void = kappa (eqW a a) := by
        simp [kappa, h]
      exact drop_right hmu hk
    · have hk : kappa void < kappa (eqW a a) := by
        simp [kappa]
        exact Nat.pos_of_ne_zero h
      exact drop_left hk
```

```lean
-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]
      omega
    have hk : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

For the problematic successor case, the expected intended argument would be “the outer successor `delta` lowers recursion depth.” But the current `kappa` only contributes `+1` for whether the *immediate* third argument is `delta`; it does not count a run of nested deltas. Therefore, when `n` itself is `delta m`, both sides retain the same `kappa`, while `mu` increases because the target wraps the recursive call in `app s`.

To complete the theorem as written, the measure must be changed—for example, by using a recursion-depth component that strictly decreases when one leading `delta` is removed from the third argument of `recDelta`.
