A complete proof skeleton for all five remaining cases does **not** exist as the file stands: the `R_rec_succ` case is false for nested `delta`s. The other four cases can be filled in with standard lexicographic arguments.

Here is a reasonable skeleton for the four provable cases:

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    by_cases h : kappa t = 0
    · have hmu : mu void < mu (integrate (delta t)) := by
        simp [mu]
      have hk : kappa void = kappa (integrate (delta t)) := by
        simpa [kappa] using h.symm
      exact drop_right hmu hk
    · have hk : kappa void < kappa (integrate (delta t)) := by
        have hp : 0 < kappa t := Nat.pos_of_ne_zero h
        simpa [kappa] using hp
      exact drop_left hk

-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    have hle : kappa b ≤ kappa (recDelta b s void) := by
      simpa [kappa] using
        Nat.le_trans
          (Nat.le_max_left (kappa b) (kappa s))
          (Nat.le_max_left (Nat.max (kappa b) (kappa s)) 0)

    have hmu : mu b < mu (recDelta b s void) := by
      simp [mu]
      omega

    rcases Nat.lt_or_eq_of_le hle with hlt | heq
    · exact drop_left hlt
    · exact drop_right hmu heq

-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    by_cases h : kappa a = 0
    · have hmu : mu void < mu (eqW a a) := by
        simp [mu]
        omega
      have hk : kappa void = kappa (eqW a a) := by
        simpa [kappa] using h.symm
      exact drop_right hmu hk
    · have hk : kappa void < kappa (eqW a a) := by
        have hp : 0 < kappa a := Nat.pos_of_ne_zero h
        simpa [kappa] using hp
      exact drop_left hk

-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]
      omega
    have hk : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

The problematic case is:

```lean
-- recDelta b s (delta n) --> app s (recDelta b s n)
| _, _, Step.R_rec_succ b s n => by
    sorry
```

This cannot be proved with the current `kappa` and `mu`. For example, take:

```lean
b = void
s = void
n = delta void
```

Then the step is:

```lean
recDelta void void (delta (delta void))
  -->
app void (recDelta void void (delta void))
```

But the measures are:

```lean
measure (recDelta void void (delta (delta void))) = (1, 3)
measure (app void (recDelta void void (delta void))) = (1, 4)
```

So `kappa` ties and `mu` increases. Therefore

```lean
LexOrder
  (measure (app void (recDelta void void (delta void))))
  (measure (recDelta void void (delta (delta void))))
```

is false.

The source of the issue is that `delta` is transparent to both `kappa` and `mu`, while `kappa` only adds `+1` when the third argument of `recDelta` is immediately `delta`-wrapped. Thus peeling one `delta` from `delta (delta void)` does not reduce `kappa`, and the added `app` increases `mu`.

So the file cannot be completed without changing at least one of the measures or restricting the `R_rec_succ` rule.
