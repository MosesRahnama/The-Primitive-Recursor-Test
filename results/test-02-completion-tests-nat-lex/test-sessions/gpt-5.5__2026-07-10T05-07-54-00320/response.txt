A full completion is not possible as the file currently stands: the `R_rec_succ` case is not a lexicographic decrease for the given `(kappa, mu)` measure.

You can prove the other four remaining cases with skeletons like the following.

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    by_cases ht : kappa t = 0
    · have hmu : mu void < mu (integrate (delta t)) := by
        simp [mu]
        omega
      have hk : kappa void = kappa (integrate (delta t)) := by
        simp [kappa, ht]
      exact drop_right hmu hk
    · have hpos : 0 < kappa t := Nat.pos_of_ne_zero ht
      have hk : kappa void < kappa (integrate (delta t)) := by
        simpa [kappa] using hpos
      exact drop_left hk
```

```lean
-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    by_cases hklt : kappa b < kappa (recDelta b s void)
    · exact drop_left hklt
    · have hkle : kappa b ≤ kappa (recDelta b s void) := by
        simpa [kappa] using
          Nat.le_trans
            (Nat.le_max_left (kappa b) (kappa s))
            (Nat.le_max_left (Nat.max (kappa b) (kappa s)) (kappa void))
      have hk : kappa b = kappa (recDelta b s void) := by
        exact Nat.le_antisymm hkle (Nat.le_of_not_gt hklt)
      have hmu : mu b < mu (recDelta b s void) := by
        simp [mu]
        omega
      exact drop_right hmu hk
```

```lean
-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    by_cases ha : kappa a = 0
    · have hmu : mu void < mu (eqW a a) := by
        simp [mu]
        omega
      have hk : kappa void = kappa (eqW a a) := by
        simp [kappa, ha]
      exact drop_right hmu hk
    · have hpos : 0 < kappa a := Nat.pos_of_ne_zero ha
      have hk : kappa void < kappa (eqW a a) := by
        simpa [kappa] using hpos
      exact drop_left hk
```

```lean
-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]
      omega
    have hk : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

The problematic case is:

```lean
-- recDelta b s (delta n) --> app s (recDelta b s n)
| _, _, Step.R_rec_succ b s n => by
    sorry
```

This cannot be completed for arbitrary `n`. For example, take:

```lean
b = void
s = void
n = delta void
```

Then the rule gives:

```lean
Step
  (recDelta void void (delta (delta void)))
  (app void (recDelta void void (delta void)))
```

But the measures are:

```lean
measure (recDelta void void (delta (delta void))) = (1, 3)
measure (app void (recDelta void void (delta void))) = (1, 4)
```

So the target has the same `kappa` and strictly larger `mu`. Hence

```lean
LexOrder (1, 4) (1, 3)
```

is false.

The obstruction is that `kappa` only adds `+1` when the third argument of a `recDelta` is syntactically `delta _`, while `delta` itself is transparent. Thus nested deltas do not create a strict `kappa` drop in the recursive call. The `R_rec_succ` case would need a different measure, or the rule would need to restrict `n` so that it is not itself a `delta` term.
