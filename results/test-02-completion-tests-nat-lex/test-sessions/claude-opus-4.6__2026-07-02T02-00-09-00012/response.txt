Looking at each remaining case, I need to determine whether kappa drops strictly (use `drop_left`) or kappa ties and mu drops (use `drop_right`).

Let me analyze each:

1. **`integrate (delta t) --> void`**: `kappa (integrate (delta t)) = kappa t`, `kappa void = 0`. `mu (integrate (delta t)) = 1 + mu t`, `mu void = 0`. Both kappa and mu could drop. Easiest: mu drops strictly (`1 + mu t > 0`), but kappa may not tie. Use `drop_left` if `kappa t > 0` isn't guaranteed. Actually, kappa could be 0 for both sides. We need: either kappa drops or (kappa ties and mu drops). Since `kappa void = 0 ≤ kappa t = kappa (integrate (delta t))`, if kappa ties (both 0) then mu drops. If kappa of t > 0, kappa drops. In general, we can just show the lex pair decreases. The simplest approach: show `LexOrder (0, 0) (kappa t, 1 + mu t)`. If `kappa t > 0`, left component drops. If `kappa t = 0`, right component drops (`0 < 1 + mu t`). We can handle this by cases or omega on the lex order directly.

2. **`recDelta b s void --> b`**: kappa ties or drops, mu drops.

3. **`recDelta b s (delta n) --> app s (recDelta b s n)`**: kappa drops strictly (from `max(max(kb,ks),kn)+1` to `max(ks, max(max(kb,ks),kn))`).

4. **`eqW a a --> void`**: Similar to case 1.

5. **`eqW a b --> integrate (merge a b)`**: kappa ties, mu drops (`4 + mu a + mu b` vs `1 + 2 + mu a + mu b = 3 + mu a + mu b`).
