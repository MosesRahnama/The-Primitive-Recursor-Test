## Overview of the proof strategy

Every case of `measure_decreases` follows the same two‑step recipe used in the solved cases:

1. Try to show `kappa` **strictly decreases** (`drop_left`).
2. If `kappa` can only be shown to **tie**, show `mu` strictly decreases in that tied situation (`drop_right`).

For the three "clean" merge rules `kappa` always ties exactly, so only step 2 was needed. For `integrate (delta t)`, `recDelta b s void`, and `eqW a a`, whether `kappa` ties or strictly drops **depends on whether the "other side" of the max is 0**, so a case split on `kappa` being `0` (or on which argument realizes the max) is needed before applying `drop_left`/`drop_right`. `eqW a b --> integrate (merge a b)` is again a pure tie case. `recDelta b s (delta n) --> app s (recDelta b s n)` needs a case split on the shape of `n` itself.

Below is the skeleton for each remaining `sorry`.

```lean
-- integrate (delta t) --> void
-- kappa void = 0 = kappa t when kappa t = 0 (tie, mu drops by the +1 from `integrate`)
-- kappa void = 0 < kappa t otherwise (strict drop)
| _, _, Step.R_int_delta t => by
    rcases Nat.eq_zero_or_pos (kappa t) with h0 | hpos
    · have hk : kappa void = kappa (integrate (delta t)) := by simp [kappa, h0]
      have hmu : mu void < mu (integrate (delta t)) := by simp [mu]; omega
      exact drop_right hmu hk
    · have hk : kappa void < kappa (integrate (delta t)) := by simp [kappa]; omega
      exact drop_left hk

-- recDelta b s void --> b
-- kappa (recDelta b s void) = max (kappa b) (kappa s)   (third arg is not delta-headed, no +1)
-- so kappa b ties with it when kappa s ≤ kappa b (tie, mu drops by the recDelta overhead),
-- and kappa b is strictly below it when kappa b < kappa s.
| _, _, Step.R_rec_zero b s => by
    rcases le_or_lt (kappa s) (kappa b) with h | h
    · have hk : kappa b = kappa (recDelta b s void) := by simp [kappa]; omega
      have hmu : mu b < mu (recDelta b s void) := by simp [mu]; omega
      exact drop_right hmu hk
    · have hk : kappa b < kappa (recDelta b s void) := by simp [kappa]; omega
      exact drop_left hk

-- recDelta b s (delta n) --> app s (recDelta b s n)
-- Case split on the shape of n, since kappa(recDelta b s n) picks up a "+1"
-- exactly when n itself is delta-headed.
| _, _, Step.R_rec_succ b s n => by
    cases n with
    | void =>
        have hk : kappa (app s (recDelta b s void)) < kappa (recDelta b s (delta void)) := by
          simp [kappa]; omega
        exact drop_left hk
    | integrate n' =>
        have hk : kappa (app s (recDelta b s (integrate n'))) <
                    kappa (recDelta b s (delta (integrate n'))) := by
          simp [kappa]; omega
        exact drop_left hk
    | merge n1 n2 =>
        have hk : kappa (app s (recDelta b s (merge n1 n2))) <
                    kappa (recDelta b s (delta (merge n1 n2))) := by
          simp [kappa]; omega
        exact drop_left hk
    | app n1 n2 =>
        have hk : kappa (app s (recDelta b s (app n1 n2))) <
                    kappa (recDelta b s (delta (app n1 n2))) := by
          simp [kappa]; omega
        exact drop_left hk
    | recDelta n1 n2 n3 =>
        have hk : kappa (app s (recDelta b s (recDelta n1 n2 n3))) <
                    kappa (recDelta b s (delta (recDelta n1 n2 n3))) := by
          simp [kappa]; omega
        exact drop_left hk
    | eqW n1 n2 =>
        have hk : kappa (app s (recDelta b s (eqW n1 n2))) <
                    kappa (recDelta b s (delta (eqW n1 n2))) := by
          simp [kappa]; omega
        exact drop_left hk
    | delta n' =>
        -- Here kappa ties: both sides evaluate to
        --   max (max (kappa b) (kappa s)) (kappa n') + 1
        have hk : kappa (app s (recDelta b s (delta n'))) =
                    kappa (recDelta b s (delta (delta n'))) := by
          simp [kappa]; omega
        -- NOTE: with mu as given, mu (app s (recDelta b s (delta n')))
        -- exceeds mu (recDelta b s (delta (delta n'))) by exactly `1 + mu s`
        -- (the extra `app` node plus the duplicated `recDelta` overhead),
        -- so `drop_right` cannot be discharged from this `mu`/`kappa` pair
        -- as literally defined; closing this branch requires a refined
        -- measure that counts the full leading-delta chain length rather
        -- than a single-level check. Left as the genuinely open sub-goal:
        sorry

-- eqW a a --> void
-- kappa void = 0 = kappa a when kappa a = 0 (tie, mu drops via eqW's weight 4)
-- kappa void = 0 < kappa a otherwise (strict drop)
| _, _, Step.R_eq_refl a => by
    rcases Nat.eq_zero_or_pos (kappa a) with h0 | hpos
    · have hk : kappa void = kappa (eqW a a) := by simp [kappa, h0]
      have hmu : mu void < mu (eqW a a) := by simp [mu]; omega
      exact drop_right hmu hk
    · have hk : kappa void < kappa (eqW a a) := by simp [kappa]; omega
      exact drop_left hk

-- eqW a b --> integrate (merge a b)
-- kappa always ties exactly (both reduce to max (kappa a) (kappa b));
-- mu strictly drops since eqW's weight (4) exceeds integrate+merge's weight (1+2=3).
| _, _, Step.R_eq_diff a b => by
    have hk : kappa (integrate (merge a b)) = kappa (eqW a b) := by simp [kappa]
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by simp [mu]; omega
    exact drop_right hmu hk
```

### Remarks

- `R_int_delta`, `R_rec_zero`, and `R_eq_refl` all share the same shape: `kappa` of the target is `≤` `kappa` of the source because the source's max includes a term that is `0` in the tied situation, so a case split on `Nat.eq_zero_or_pos`/`le_or_lt` cleanly routes into `drop_left` or `drop_right`.
- `R_eq_diff` needs no case split at all: the `eqW`/`integrate∘merge` kappa formulas coincide definitionally, and the fixed weight arithmetic (`4` vs `1+2`) gives an unconditional `mu` decrease.
- `R_rec_succ` is handled uniformly for six of the seven shapes of `n` (all strict `kappa` decreases via `drop_left`), but the `n = delta n'` branch is a genuine tie in `kappa`, and — as flagged in the comment — the given `mu` actually *increases* there (`mu` of the reduct exceeds `mu` of the redex by `1 + mu s`). That sub-goal cannot be closed with the `(kappa, mu)` pair as defined; it is left as the honest remaining `sorry`, since discharging it would require strengthening `kappa` (e.g. to measure the full length of a leading `delta`-chain rather than a single level) rather than just filling in tactics.
