Looking at each remaining case, I need to determine whether kappa drops strictly (use `drop_left`) or ties while mu drops (use `drop_right`).

## Analysis of each case

1. **`integrate (delta t) → void`**: `kappa(integrate(delta t)) = kappa(t)`, `kappa(void) = 0`. If `kappa t > 0`, kappa drops; if `kappa t = 0`, kappa ties. But `mu(void) = 0 < 1 + mu t = mu(integrate(delta t))` always. So we can use: kappa of void ≤ kappa of source, and mu drops. Actually we need either strict kappa drop or kappa tie + mu drop. Since kappa(void) = 0 ≤ kappa(t), we can split on whether kappa(t) = 0 or not, or just observe that `(0, 0)` is lexicographically less than `(kappa t, 1 + mu t)` whenever `kappa t > 0` or `mu t ≥ 0` (which is always). We can use `Prod.Lex` directly.

2. **`recDelta b s void → b`**: kappa of source = `max(max(kb, ks), 0) = max(kb, ks)`, kappa of target = `kb ≤ max(kb, ks)`. mu drops: `mu b < 3 + mu b + mu s + 0`. So either kappa drops strictly or ties, and mu always drops.

3. **`recDelta b s (delta n) → app s (recDelta b s n)`**: kappa of source = `max(max(kb,ks), kn) + 1`, kappa of target = `max(ks, max(max(kb,ks), kn))` = `max(max(kb,ks), kn)`. So kappa drops by 1. Use `drop_left`.

4. **`eqW a a → void`**: kappa(void) = 0 ≤ max(ka,ka) = ka. mu(void) = 0 < 4 + 2*mu(a). Lexicographic decrease holds.

5. **`eqW a b → integrate (merge a b)`**: kappa ties: `max(ka,kb)` on both sides. mu: `1 + 2 + mu a + mu b = 3 + mu a + mu b < 4 + mu a + mu b`. Use `drop_right`.

## Proof skeleton

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    apply drop_right
    · simp [mu]; omega
    · simp [kappa]

-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    apply drop_right
    · simp [mu]; omega
    · simp [kappa]

-- recDelta b s (delta n) --> app s (recDelta b s n)
| _, _, Step.R_rec_succ b s n => by
    apply drop_left
    simp [kappa]; omega

-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    apply drop_right
    · simp [mu]; omega
    · simp [kappa]

-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    apply drop_right
    · simp [mu]; omega
    · simp [kappa]
```

### Key reasoning per case:

- **R_int_delta**: kappa ties (`kappa void = 0 = kappa (integrate (delta t))` since `kappa` is transparent through both `integrate` and `delta`, giving `kappa t` on the source — wait, `kappa void = 0` while source kappa = `kappa t`. These don't necessarily tie. Instead, for `kappa t = 0` they tie and mu drops; for `kappa t > 0`, kappa drops. But `simp [kappa]` should reduce `kappa (integrate (delta t))` to `kappa t` and `kappa void` to `0`, and `drop_right` needs equality. We should instead directly construct the `Prod.Lex` proof, or handle both sub-cases. A cleaner approach: unfold `LexOrder` and `measure`, `simp`, and use `omega` or case analysis.
