# Proof Skeleton for Remaining Cases

## Case 1: `R_int_delta : integrate (delta t) → void`

**Computation.**
- `kappa (integrate (delta t)) = kappa t` and `mu (integrate (delta t)) = 1 + mu t`
- `measure void = (0, 0)`, `measure (integrate (delta t)) = (kappa t, 1 + mu t)`

**Issue.** `kappa t` may be `0` (e.g. `t = void`), so we cannot rely on a strict left-component drop alone.

**Strategy.** Case split on `kappa t`:
- If `kappa t > 0`: use `drop_left` (0 < kappa t).
- If `kappa t = 0`: kappa ties, and `mu void = 0 < 1 + mu t` because `mu t : Nat`, hence `1 + mu t ≥ 1`. Use `drop_right`.

**Skeleton.**
```lean
| _, _, Step.R_int_delta t => by
    by_cases hk : kappa t = 0
    · have hk' : kappa void = kappa (integrate (delta t)) := by simp [hk]
      have hmu : (0 : Nat) < 1 + mu t := Nat.succ_pos _
      have hmu' : mu void < mu (integrate (delta t)) := by simpa using hmu
      exact drop_right hmu' hk'
    · have hklt : (0 : Nat) < kappa t := Nat.pos_of_ne_zero hk
      have : kappa void < kappa (integrate (delta t)) := by simpa using hklt
      exact drop_left this
```

## Case 2: `R_rec_zero : recDelta b s void → b`

**Computation.**
- `kappa (recDelta b s void) = max (kappa b) (kappa s)` (the `+1` branch does not fire)
- `mu (recDelta b s void) = 3 + mu b + mu s`

**Issue.** `kappa b` may be strictly less than `max (kappa b) (kappa s)` (when `kappa s` dominates), so we cannot guarantee a kappa tie a priori. But we always have `mu b < 3 + mu b + mu s` since `mu s ≥ 0`.

**Strategy.** Case split on whether `kappa b < kappa (recDelta b s void)`:
- If strict: `drop_left`.
- If equal: `drop_right` with `mu b < 3 + mu b + mu s`.

**Skeleton.**
```lean
| _, _, Step.R_rec_zero b s => by
    by_cases hk : kappa b < kappa (recDelta b s void)
    · exact drop_left hk
    · have hk' : kappa b = kappa (recDelta b s void) :=
        (le_antisymm (Nat.le_max_left _ _) (le_of_not_gt hk))
      have hmu : mu b < mu (recDelta b s void) := by
        simp; omega  -- 0 ≤ mu s
      exact drop_right hmu hk'
```

## Case 3: `R_rec_succ : recDelta b s (delta n) → app s (recDelta b s n)`

**Computation.**
- `kappa (recDelta b s (delta n)) = max (kappa b) (kappa s) (kappa n) + 1`
- `kappa (recDelta b s n)        = max (kappa b) (kappa s) (kappa n)` (non-delta branch)
- `kappa (app s (recDelta b s n)) = max (kappa s) (max (kappa b) (kappa s) (kappa n)) = max (kappa b) (kappa s) (kappa n)`

So the RHS kappa is exactly one less than the LHS kappa. The mu actually **grows** on the RHS (because of the outer `app`), but the kappa drop dominates.

**Strategy.** Pure `drop_left` with `Nat.lt_succ_self`-style reasoning.

**Skeleton.**
```lean
| _, _, Step.R_rec_succ b s n => by
    have hk : kappa (app s (recDelta b s n))
            < kappa (recDelta b s (delta n)) := by
      simp; omega  -- k < k + 1
    exact drop_left hk
```

## Case 4: `R_eq_refl : eqW a a → void`

**Computation.**
- `kappa (eqW a a) = kappa a`, `mu (eqW a a) = 4 + 2 * mu a`
- `measure void = (0, 0)`

**Issue.** Same as `R_int_delta`: when `kappa a = 0`, the left component does not strictly drop, but mu does (4 + 2·mu a ≥ 4 > 0).

**Strategy.** Same shape: case split on `kappa a = 0`, then `drop_right` with `0 < 4 + 2*mu a`.

**Skeleton.**
```lean
| _, _, Step.R_eq_refl a => by
    by_cases hk : kappa a = 0
    · have hk' : kappa void = kappa (eqW a a) := by simp [hk]
      have hmu : (0 : Nat) < 4 + 2 * mu a := by omega
      have hmu' : mu void < mu (eqW a a) := by simpa using hmu
      exact drop_right hmu' hk'
    · have hklt : (0 : Nat) < kappa a := Nat.pos_of_ne_zero hk
      have : kappa void < kappa (eqW a a) := by simpa using hklt
      exact drop_left this
```

## Case 5: `R_eq_diff : eqW a b → integrate (merge a b)`

**Computation.**
- `kappa (eqW a b) = max (kappa a) (kappa b)`
- `kappa (integrate (merge a b)) = kappa (merge a b) = max (kappa a) (kappa b)` — **ties**
- `mu (eqW a b) = 4 + mu a + mu b`
- `mu (integrate (merge a b)) = 1 + (2 + mu a + mu b) = 3 + mu a + mu b`
- mu strictly drops by exactly 1.

**Strategy.** Straight `drop_right`.

**Skeleton.**
```lean
| _, _, Step.R_eq_diff a b => by
    have hk  : kappa (integrate (merge a b)) = kappa (eqW a b) := by simp
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp; omega  -- 3 + μa + μb < 4 + μa + μb
    exact drop_right hmu hk
```

---

## Summary of the Five Skeletons

| Rule | kappa behavior | mu behavior | Helper used |
|------|----------------|-------------|-------------|
| `R_int_delta` | may tie (when `κ t = 0`) | drops by `1 + μ t > 0` | `by_cases` on `κ t = 0`; `drop_left` / `drop_right` |
| `R_rec_zero` | may drop (when `κ s > κ b`) | always drops by `3 + μ s ≥ 3` | `by_cases` on `κ b < κ(...)`; `drop_left` / `drop_right` |
| `R_rec_succ` | drops by exactly 1 | grows | `drop_left` + `Nat.lt_succ_self`-style |
| `R_eq_refl` | may tie (when `κ a = 0`) | drops by `4 + 2·μ a ≥ 4` | `by_cases` on `κ a = 0`; `drop_left` / `drop_right` |
| `R_eq_diff` | always ties | drops by exactly 1 | `drop_right` only |

The two "may tie" cases (`R_int_delta`, `R_eq_refl`) are the only subtle ones; the others collapse to a single `drop_left` or `drop_right`. Once each `sorry` is replaced by its corresponding case above, the `measure_decreases` theorem is complete and `strong_normalization` follows.
