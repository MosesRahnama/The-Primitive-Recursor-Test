# Proof Skeleton for Remaining Cases

## Analysis of the Measure

The lexicographic measure `(kappa, mu)` works for most rules, but has a subtle issue with `R_rec_succ` when the recursion argument is `delta`-wrapped. Let me work through each case.

For each case below, I provide the Lean code to replace the corresponding `sorry`.

---

### `R_int_delta : integrate (delta t) → void`

- `kappa (integrate (delta t)) = kappa t` (both constructors transparent)
- `kappa void = 0`
- If `kappa t > 0`: kappa strictly drops → `drop_left`
- If `kappa t = 0`: kappa ties (both 0), `mu void = 0 < 1 + mu t` → `drop_right`

```lean
| _, _, Step.R_int_delta t => by
    rcases Nat.eq_zero_or_pos (kappa t) with hk | hk
    · -- kappa t = 0
      have hmu : mu void < mu (integrate (delta t)) := by simp [mu]; omega
      have hk' : kappa void = kappa (integrate (delta t)) := by
        simp [kappa, hk]
      exact drop_right hmu hk'
    · -- kappa t > 0
      have hk' : kappa void < kappa (integrate (delta t)) := by
        simp [kappa]; omega
      exact drop_left hk'
```

---

### `R_rec_zero : recDelta b s void → b`

- `kappa (recDelta b s void) = max(kappa b, kappa s)` (since `kappa void = 0`)
- `mu (recDelta b s void) = 3 + mu b + mu s`
- If `kappa b ≥ kappa s`: kappa ties at `kappa b`, mu drops (`mu b < 3 + mu b + mu s`) → `drop_right`
- If `kappa b < kappa s`: kappa strictly drops → `drop_left`

```lean
| _, _, Step.R_rec_zero b s => by
    rcases Nat.le_or_gt (kappa b) (kappa s) with hk | hk
    · -- kappa b >= kappa s
      have hmu : mu b < mu (recDelta b s void) := by simp [mu]; omega
      have hk' : kappa b = kappa (recDelta b s void) := by
        simp [kappa, kappa_void]; omega
      exact drop_right hmu hk'
    · -- kappa b < kappa s
      have hk' : kappa b < kappa (recDelta b s void) := by
        simp [kappa, kappa_void]; omega
      exact drop_left hk'
```

### `R_rec_succ : recDelta b s (delta n) → app s (recDelta b s n)` ⚠

**This case is not provable with the current measure.** A detailed analysis:

- LHS kappa: `max(max(kb, ks), kn) + 1`
- RHS kappa: `max(ks, kappa (recDelta b s n))`

**Sub-case A: `n` is not a `delta`-wrap.**
Then `kappa (recDelta b s n) = max(max(kb, ks), kn)`, so RHS kappa = `max(max(kb, ks), kn)` and LHS kappa = RHS kappa + 1. Kappa strictly drops. ✓

**Sub-case B: `n = delta n'`.** This is the problem.
- LHS = `recDelta b s (delta (delta n'))`: kappa = `max(max(kb, ks), kn') + 1`
- RHS = `app s (recDelta b s (delta n'))`: kappa = `max(ks, max(max(kb, ks), kn') + 1)` = `max(max(kb, ks), kn') + 1`
- **Kappa ties.**
- mu LHS = `3 + mb + ms + mn'`
- mu RHS = `1 + ms + (3 + mb + ms + mn')` = `4 + mb + 2·ms + mn'`
- **mu strictly increases** (by `1 + ms > 0`).

The pair `(kappa, mu)` does *not* decrease. No amount of `drop_left`/`drop_right` (or any fixed linear weighting) will fix this, because the mu gap is `1 + ms` regardless of kappa.

**Suggested fix (requires modifying the measure):** Either
1. Make `app`'s first argument transparent to `mu` (e.g., `mu (app a b) = mu b`) and add a separate `deltaDepth` measure, or
2. Redefine `kappa` so that `delta` is *not* transparent: e.g., `kappa (delta t) = kappa t + 1` (this would, however, require re-checking the `R_int_delta` case, which would still work via the same case-split).

With the current `kappa`/`mu`, the `R_rec_succ` skeleton would be:

```lean
| _, _, Step.R_rec_succ b s n => by
    -- NOTE: This case fails for n = delta n' under the current measure.
    sorry
```

### `R_eq_refl : eqW a a → void`

- `kappa (eqW a a) = kappa a`
- `mu (eqW a a) = 4 + 2·mu a`
- If `kappa a > 0`: kappa strictly drops → `drop_left`
- If `kappa a = 0`: kappa ties, `mu void = 0 < 4 + 2·mu a` → `drop_right`

```lean
| _, _, Step.R_eq_refl a => by
    rcases Nat.eq_zero_or_pos (kappa a) with hk | hk
    · -- kappa a = 0
      have hmu : mu void < mu (eqW a a) := by simp [mu]; omega
      have hk' : kappa void = kappa (eqW a a) := by
        simp [kappa, hk]
      exact drop_right hmu hk'
    · -- kappa a > 0
      have hk' : kappa void < kappa (eqW a a) := by
        simp [kappa]; omega
      exact drop_left hk'
```

---

### `R_eq_diff : eqW a b → integrate (merge a b)`

- Kappa: `max(kappa a, kappa b)` on both sides (delta/integrate/merge are all transparent to kappa). **Kappa ties.**
- mu LHS = `4 + mu a + mu b`
- mu RHS = `1 + (2 + mu a + mu b)` = `3 + mu a + mu b`
- mu strictly drops → `drop_right`

```lean
| _, _, Step.R_eq_diff a b => by
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]; omega
    have hk  : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

## Summary

| Rule | Status | Approach |
|------|--------|----------|
| `R_merge_void_left` | ✓ proved | `drop_right` (mu drop) |
| `R_merge_void_right` | ✓ proved | `drop_right` (mu drop) |
| `R_merge_cancel` | ✓ proved | `drop_right` (mu drop) |
| `R_int_delta` | skeleton above | case split on `kappa t` |
| `R_rec_zero` | skeleton above | case split on `kappa b` vs `kappa s` |
| `R_rec_succ` | ⚠ measure broken | requires measure redesign |
| `R_eq_refl` | skeleton above | case split on `kappa a` |
| `R_eq_diff` | skeleton above | `drop_right` (mu drop) |

**Key takeaway:** The `(kappa, mu)` lex measure is well-tuned for delta/integrate/merge/eqW rules but fails for the `R_rec_succ` rule in the `n = delta n'` sub-case because the `app` constructor and its second occurrence of `s` inflate `mu` faster than the `delta`-unwrap can reduce it. A correct termination proof would need a measure that tracks the "delta-depth of the recDelta's third argument" independently of the structural weight of `app`.
