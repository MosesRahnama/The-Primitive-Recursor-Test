# Proof Skeleton for Remaining Cases

Here is a proof skeleton for each of the five remaining `sorry` cases. For each I identify which projection (`kappa` or `mu`) drives the decrease and which helper lemma (`drop_left` or `drop_right`) applies.

| Rule | kappa behavior | mu behavior | Lemma |

## Skeletons

### 1. `integrate (delta t) --> void`
Here `kappa (integrate (delta t)) = kappa t` (not necessarily 0), while `kappa void = 0`. So kappa does **not** tie in general — but `kappa void = 0 ≤ kappa t`. This means we cannot always use `drop_right`. Use case split on whether kappa drops.

```lean
| _, _, Step.R_int_delta t => by
    -- kappa void = 0, kappa (integrate (delta t)) = kappa t
    -- mu void = 0 < 1 + mu t = mu (integrate (delta t))
    rcases Nat.eq_zero_or_pos (kappa t) with hk | hk
    · -- kappa ties at 0: use mu drop
      have hmu : mu void < mu (integrate (delta t)) := by simp [mu]; omega
      have hkeq : kappa void = kappa (integrate (delta t)) := by simp [kappa, hk]
      exact drop_right hmu hkeq
    · -- kappa strictly drops (0 < kappa t)
      have hklt : kappa void < kappa (integrate (delta t)) := by simp [kappa]; omega
      exact drop_left hklt
```

### 2. `recDelta b s void --> b`
`kappa (recDelta b s void) = max (max (kappa b) (kappa s)) (kappa void)` (falls in the catch-all `recDelta b s n` branch since `void ≠ delta _`), and `kappa void = 0`, so this `= max (kappa b) (kappa s) ≥ kappa b`. Again kappa may drop or tie; but here the target is `b`, so kappa need not tie. Case split.

```lean
| _, _, Step.R_rec_zero b s => by
    -- kappa (recDelta b s void) = max (max (kappa b) (kappa s)) 0
    -- mu b < 3 + mu b + mu s + 0
    have hkval : kappa (recDelta b s void)
        = Nat.max (Nat.max (kappa b) (kappa s)) (kappa void) := rfl
    rcases Nat.lt_or_ge (kappa b) (kappa (recDelta b s void)) with hklt | hkge
    · exact drop_left hklt
    · -- kappa ties: kappa b ≥ measure and ≤ (max), so equal
      have hkeq : kappa b = kappa (recDelta b s void) := by
        have : kappa b ≤ kappa (recDelta b s void) := by
          rw [hkval]; simp [kappa]; omega  -- kappa b ≤ max(max kb ks) 0
        omega
      have hmu : mu b < mu (recDelta b s void) := by simp [mu]; omega
      exact drop_right hmu hkeq
```

### 3. `recDelta b s (delta n) --> app s (recDelta b s n)`  ← **key case, kappa drops**
LHS: `kappa (recDelta b s (delta n)) = max (max (kappa b) (kappa s)) (kappa n) + 1`.
RHS: `kappa (app s (recDelta b s n)) = max (kappa s) (max (max (kappa b) (kappa s)) (kappa n))` (inner `recDelta b s n` uses catch-all branch since `n` may or may not be delta — but note the RHS `recDelta b s n` could add +1 if `n` is itself a delta!). Careful: if `n = delta n'`, then `kappa (recDelta b s n) = ... + 1`. Must handle via `omega` after establishing the max facts. The `+1` on the LHS still dominates because RHS is `max (kappa s) (kappa (recDelta b s n))` and `kappa (recDelta b s n) ≤ (max (max kb ks) (kappa n')) + 1`... This requires a bound lemma.

```lean
| _, _, Step.R_rec_succ b s n => by
    -- Goal: kappa RHS < kappa LHS  (strict, by the +1)
    -- LHS kappa = max (max (kappa b)(kappa s)) (kappa n) + 1
    -- RHS kappa = max (kappa s) (kappa (recDelta b s n))
    -- Need: kappa (recDelta b s n) < LHS  and  kappa s < LHS
    have hklt : kappa (app s (recDelta b s n))
                  < kappa (recDelta b s (delta n)) := by
      simp only [kappa_app, kappa_rec_delta]
      -- Establish: kappa (recDelta b s n) ≤ max (max kb ks) (kappa n)
      -- via auxiliary bound (see note below), then omega
      have hbound : kappa (recDelta b s n)
          ≤ Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) := by
        -- case split on whether n is delta-shaped
        sorry  -- fill with cases on n (see NOTE)
      have hs : kappa s ≤ Nat.max (Nat.max (kappa b) (kappa s)) (kappa n) := by
        simp [Nat.le_max_iff]; omega
      omega
    exact drop_left hklt
```

**NOTE for the bound `hbound`:** you need the fact that
`kappa (recDelta b s n) ≤ max (max (kappa b) (kappa s)) (kappa n)`.
Prove it by `cases n`:
- For all non-delta constructors, `kappa (recDelta b s n) = max (max kb ks) (kappa n)` (catch-all), so `≤` holds by `le_refl`.
- For `n = delta n'`: `kappa (recDelta b s (delta n')) = max (max kb ks) (kappa n') + 1` and `kappa (delta n') = kappa n'`, so we need `max (max kb ks) (kappa n') + 1 ≤ max (max kb ks) (kappa n')`, which is **false**.

This means the bound as stated fails when `n` is delta-shaped, so **kappa may not strictly drop** — reconsider. In that subcase `kappa (recDelta b s n)` could equal LHS. You must instead prove the theorem is still true because... it may **not** be. Recommended: extract a helper lemma establishing kappa strictly decreases only when it does, else fall back to `mu`. Concretely, split:

```lean
    -- Robust version:
    rcases Nat.lt_or_ge (kappa (app s (recDelta b s n)))
                        (kappa (recDelta b s (delta n))) with h | h
    · exact drop_left h
    · -- kappa ties; must show mu strictly drops. But mu RHS =
      -- (1 + mu s) + (3 + mu b + mu s + mu n) vs LHS (3 + mu b + mu s + mu n).
      -- mu INCREASES here → this branch must be vacuous.
      -- Prove h impossible: derive kappa strict drop unconditionally.
      exfalso
      sorry  -- show the ge-case cannot happen using kappa arithmetic
```

⚠️ **Design flag:** if `n` can be `delta`-shaped this case's measure may not decrease. Verify the intended `kappa` definition; you may need a stronger measure. Document this in the skeleton.

### 4. `eqW a a --> void`
`kappa (eqW a a) = max (kappa a) (kappa a) = kappa a`; `kappa void = 0`. Case split.

```lean
| _, _, Step.R_eq_refl a => by
    rcases Nat.eq_zero_or_pos (kappa a) with hk | hk
    · have hmu : mu void < mu (eqW a a) := by simp [mu]; omega
      have hkeq : kappa void = kappa (eqW a a) := by simp [kappa, hk]
      exact drop_right hmu hkeq
    · have hklt : kappa void < kappa (eqW a a) := by simp [kappa]; omega
      exact drop_left hklt
```

### 5. `eqW a b --> integrate (merge a b)`
`kappa (eqW a b) = max (kappa a) (kappa b)`; `kappa (integrate (merge a b)) = kappa (merge a b) = max (kappa a) (kappa b)`. **kappa ties exactly.** mu: LHS `= 4 + mu a + mu b`, RHS `= 1 + (2 + mu a + mu b) = 3 + mu a + mu b`. Drops by 1.

```lean
| _, _, Step.R_eq_diff a b => by
    have hk : kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]; omega
    exact drop_right hmu hk
```

## Summary of Risks

- Cases **2, 4, 1**: clean, need a kappa case-split (drop vs tie) — mechanical.
- Case **5**: fully clean, `drop_right`.
- Case **3** (`R_rec_succ`): **potential genuine gap**. The `kappa` `+1` bonus for delta-wrapped third arguments may fail to strictly decrease when `n` is itself delta-shaped, and `mu` *increases* on this rule. This is the case to scrutinize; the skeleton above isolates the problematic subgoal with `exfalso`/`sorry` so you can investigate whether the measure needs strengthening.
