A proof of all five cases is impossible with the stated measure: the `R_rec_succ` case does not always decrease lexicographically. The other four cases have the following proof skeletons.

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    have hmu : mu void < mu (integrate (delta t)) := by
      simp [mu]
    have hle : kappa void ≤ kappa (integrate (delta t)) :=
      Nat.zero_le _
    rcases Nat.lt_or_eq_of_le hle with hk | hk
    · exact drop_left hk
    · exact drop_right hmu hk

-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    have hmu : mu b < mu (recDelta b s void) := by
      simp [mu]
      omega
    have hle : kappa b ≤ kappa (recDelta b s void) := by
      simp [kappa]
    rcases Nat.lt_or_eq_of_le hle with hk | hk
    · exact drop_left hk
    · exact drop_right hmu hk

-- R_rec_succ cannot be proved with the current measure.

-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    have hmu : mu void < mu (eqW a a) := by
      simp [mu]
      omega
    have hle : kappa void ≤ kappa (eqW a a) :=
      Nat.zero_le _
    rcases Nat.lt_or_eq_of_le hle with hk | hk
    · exact drop_left hk
    · exact drop_right hmu hk

-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by
      simp [mu]
      omega
    have hk :
        kappa (integrate (merge a b)) = kappa (eqW a b) := by
      simp [kappa]
    exact drop_right hmu hk
```

The obstruction in `R_rec_succ` is witnessed by taking:

```lean
b := void
s := void
n := delta void
```

The rule then gives

```lean
recDelta void void (delta (delta void))
  -->
app void (recDelta void void (delta void))
```

but the measures are:

```lean
measure (recDelta void void (delta (delta void))) = (1, 3)
measure (app void (recDelta void void (delta void))) = (1, 4)
```

Thus `kappa` ties while `mu` increases, so

```lean
LexOrder (1, 4) (1, 3)
```

is false.

The problem is that `kappa` is transparent through `delta`. When `n` is itself delta-wrapped, both the source and the residual `recDelta b s n` receive the same `+1`. Meanwhile, the right-hand side introduces an `app` and duplicates the contribution of `s` to `mu`.

Consequently, `measure_decreases` and therefore the supplied proof of `strong_normalization` cannot be completed without changing some definition. A possible repair is to make `delta` increase `kappa`, e.g.

```lean
| .delta t => kappa t + 1
```

or to replace `kappa` with a measure that counts the leading delta depth of a `recDelta` argument. Another option is to restrict `R_rec_succ` so that its `n` is not itself delta-wrapped.
