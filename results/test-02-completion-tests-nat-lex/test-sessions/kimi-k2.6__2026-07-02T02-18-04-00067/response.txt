Here is a proof skeleton for the five remaining cases, following the pattern of the three already proved.  Each case either shows that `kappa` drops (so `drop_left` applies) or that `kappa` ties while `mu` drops (so `drop_right` applies).

```lean
-- integrate (delta t) --> void
| _, _, Step.R_int_delta t => by
    by_cases h : kappa t = 0
    · -- kappa ties: both sides are 0
      have hk  : kappa void = kappa (integrate (delta t)) := by simp [kappa, h]
      have hmu : mu void < mu (integrate (delta t)) := by simp [mu]; omega
      exact drop_right hmu hk
    · -- kappa drops strictly
      have hk : kappa void < kappa (integrate (delta t)) := by simp [kappa]; omega
      exact drop_left hk

-- recDelta b s void --> b
| _, _, Step.R_rec_zero b s => by
    by_cases h : kappa b < kappa s
    · -- kappa drops because max(kappa b, kappa s) = kappa s > kappa b
      have hk : kappa b < kappa (recDelta b s void) := by simp [kappa]; omega
      exact drop_left hk
    · -- kappa ties: max(kappa b, kappa s) = kappa b
      have hk  : kappa b = kappa (recDelta b s void) := by simp [kappa]; omega
      have hmu : mu b < mu (recDelta b s void) := by simp [mu]; omega
      exact drop_right hmu hk

-- recDelta b s (delta n) --> app s (recDelta b s n)
| _, _, Step.R_rec_succ b s n => by
    have hk : kappa (app s (recDelta b s n)) < kappa (recDelta b s (delta n)) := by
      simp [kappa]
      -- max (kappa s) (max (max (kappa b) (kappa s)) (kappa n))
      --   = max (max (kappa b) (kappa s)) (kappa n)
      rw [Nat.max_eq_right]
      · apply Nat.lt_succ_self
      · -- show kappa s ≤ max (max (kappa b) (kappa s)) (kappa n)
        apply le_trans (Nat.le_max_right (kappa b) (kappa s))
        apply Nat.le_max_left (Nat.max (kappa b) (kappa s)) (kappa n)
    exact drop_left hk

-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    by_cases h : kappa a = 0
    · -- kappa ties: both sides are 0
      have hk  : kappa void = kappa (eqW a a) := by simp [kappa, h]
      have hmu : mu void < mu (eqW a a) := by simp [mu]; omega
      exact drop_right hmu hk
    · -- kappa drops strictly
      have hk : kappa void < kappa (eqW a a) := by simp [kappa]; omega
      exact drop_left hk

-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    have hk  : kappa (integrate (merge a b)) = kappa (eqW a b) := by simp [kappa]
    have hmu : mu (integrate (merge a b)) < mu (eqW a b) := by simp [mu]; omega
    exact drop_right hmu hk
```

**Notes on the remaining cases:**

* **`R_int_delta` / `R_eq_refl`** – These rewrite to `void`.  If the source `kappa` is non‑zero, the first component of the lexicographic pair drops.  If it is zero, the first component ties and the `mu` component drops strictly (by at least `1` and `4` respectively).
* **`R_rec_zero`** – `kappa (recDelta b s void) = max (kappa b) (kappa s)`.  Either `kappa b < kappa s` (left drops) or `kappa b = kappa s` (left ties and `mu` drops by at least `3 + mu s`).
* **`R_rec_succ`** – The crucial observation is that the `+1` added by the outermost `delta` in the source is stripped away in the `recDelta` subterm of the target.  After expanding `kappa`, the target’s kappa equals `max (max (kappa b) (kappa s)) (kappa n)` while the source’s kappa equals that same quantity plus one, giving a strict decrease on the left component.
* **`R_eq_diff`** – Both terms have the same `kappa` (`max (kappa a) (kappa b)`), but the source `mu` is `4 + mu a + mu b` whereas the target `mu` is `3 + mu a + mu b`, so the right component drops by exactly one.
