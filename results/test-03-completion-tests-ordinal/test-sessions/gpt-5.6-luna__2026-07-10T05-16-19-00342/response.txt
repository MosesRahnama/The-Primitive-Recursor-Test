There is no valid proof skeleton for all three remaining cases as written: the `R_rec_succ` case is false for the given measure.

The problem is that the source contains `μ b` only in the lower-order term

```lean
omega0 * (mu b + 1)
```

whereas the target contains `μ b` inside `recDelta`, which is then multiplied by `omega0 ^ 2`. Since `b` is unrestricted, this can make the target larger than the source.

A concrete counterexample is obtained by taking

```lean
let s := void
let n := void
let q := delta (delta void)
let b := recDelta void void q
```

and considering

```lean
x := recDelta b s (delta n)
y := app s (recDelta b s n)
```

Then `Step x y` by `Step.R_rec_succ b s n`.

Writing `ω := omega0`, one gets

```text
μ (delta void) = ω^5 + 1
μ q            = ω^10 + ω^5 * 2 + 1
```

and hence, with `K := μ q + 6`,

```text
μ b = ω^K + ω + 1
```

where `K > ω^5 + 7`. Consequently,

```text
μ x = ω^K + ω^2 + ω + 1
```

while

```text
μ y = ω^K + ω^8 + ω^2 + 1
```

so

```text
μ y > μ x.
```

Thus the required conclusion

```lean
mu (app s (recDelta b s n)) <
  mu (recDelta b s (delta n))
```

does not hold in general.

The `R_eq_refl` case itself has a short skeleton:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr <| by
      apply ne_of_gt
      exact add_pos_right _ one_pos
```

But `R_rec_succ` must first be repaired, for example by changing the measure so that the `b`-component is sufficiently dominated, or by restricting the rule. Until then, `mu_decreases` and therefore `strong_normalization` cannot be completed.
