A full completion is not possible as the file stands: the `R_rec_succ` decrease statement is false for the given `mu`. The other two `sorry`s have straightforward skeletons, but the recursion-successor case cannot be proved without changing the measure or adding restrictions.

## 1. `eq_refl` skeleton

After `simp [mu]`, the goal is just positivity of a successor ordinal:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact add_pos_right _ one_pos
```

If that exact term does not elaborate, the style already used earlier should work:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

## 2. `eq_diff` proof skeleton

The intended proof is to bound the `integrate (merge a b)` measure by a lower omega-power than the one appearing in `eqW a b`.

After `simp [mu]`, abbreviate:

```lean
let x := mu a
let y := mu b
```

The goal is essentially:

```lean
omega0 ^ (4 : Ordinal)
  * (omega0 ^ (3 : Ordinal) * (x + 1)
     + omega0 ^ (2 : Ordinal) * (y + 1)
     + 1 + 1)
  + 1
<
omega0 ^ (x + y + (9 : Ordinal)) + 1
```

A useful skeleton is:

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]

    -- Main bounding lemma needed:
    have hmerge :
        omega0 ^ (3 : Ordinal) * (mu a + 1)
          + omega0 ^ (2 : Ordinal) * (mu b + 1)
          + 1 + 1
        < omega0 ^ (mu a + mu b + (5 : Ordinal)) := by
      -- prove by bounding each summand below omega^(mu a + mu b + 5)
      -- and using additively-principal closure of omega-powers.
      --
      -- Typical sub-bounds:
      --   omega^3 * (mu a + 1) < omega^(mu a + 4)
      --   omega^2 * (mu b + 1) < omega^(mu b + 3)
      -- then use:
      --   mu a + 4 ≤ mu a + mu b + 5
      --   mu b + 3 ≤ mu a + mu b + 5
      -- and closure under finite/additive sums below an omega-power.
      sorry

    have hmul :
        omega0 ^ (4 : Ordinal)
          * (omega0 ^ (3 : Ordinal) * (mu a + 1)
             + omega0 ^ (2 : Ordinal) * (mu b + 1)
             + 1 + 1)
        < omega0 ^ (mu a + mu b + (9 : Ordinal)) := by
      calc
        omega0 ^ (4 : Ordinal)
          * (omega0 ^ (3 : Ordinal) * (mu a + 1)
             + omega0 ^ (2 : Ordinal) * (mu b + 1)
             + 1 + 1)
            < omega0 ^ (4 : Ordinal)
                * omega0 ^ (mu a + mu b + (5 : Ordinal)) := by
                -- strict monotonicity of right multiplication by positive omega^4
                -- using hmerge and opow_pos
                sorry
        _ = omega0 ^ ((4 : Ordinal) + (mu a + mu b + (5 : Ordinal))) := by
                -- omega^α * omega^β = omega^(α + β)
                rw [← opow_add]
        _ ≤ omega0 ^ (mu a + mu b + (9 : Ordinal)) := by
                -- ordinal arithmetic:
                --   4 + (mu a + mu b + 5) ≤ mu a + mu b + 9
                -- then monotonicity of omega-exponentiation
                sorry

    -- Convert strict inequality before successor into strict inequality after successor.
    exact succ_lt_succ hmul
```

The important auxiliary lemma is the `hmerge` bound:

```lean
omega^3 * (x + 1) + omega^2 * (y + 1) + 2
  < omega^(x + y + 5)
```

Once that is available, multiplying by `omega^4` lands below `omega^(x + y + 9)`.

## 3. `rec_succ` cannot be completed as stated

The desired inequality is false for some concrete traces.

Take:

```lean
b := void
n := void
s := delta (delta void)
```

Let `Ω = omega0`. Then:

```text
mu (delta void) = Ω^5 + 1
mu s = mu (delta (delta void))
     = Ω^5 * (Ω^5 + 2) + 1
     = Ω^10 + Ω^5 * 2 + 1
```

Write:

```text
γ = Ω^10 + Ω^5 * 2
```

so that:

```text
mu s = γ + 1
```

Now compare source and target of the rule

```lean
recDelta void s (delta void) --> app s (recDelta void s void)
```

The source measure is:

```text
mu (recDelta void s (delta void))
= Ω^(mu (delta void) + mu s + 6) + Ω + 1
= Ω^(γ + 7) + Ω + 1
```

because the large leading term of `mu s` swallows `mu (delta void)` on the left.

The target measure contains:

```text
mu (recDelta void s void)
= Ω^(mu s + 6) + Ω + 1
= Ω^(γ + 7) + Ω + 1
```

so

```text
mu (app s (recDelta void s void))
= Ω^3 * (mu s + 1)
  + Ω^2 * (mu (recDelta void s void) + 1)
  + 1
= Ω^(γ + 7) + Ω^3 + Ω^2 * 2 + 1
```

up to lower terms. Therefore:

```text
mu target = Ω^(γ + 7) + Ω^3 + Ω^2 * 2 + 1
mu source = Ω^(γ + 7) + Ω + 1
```

and the target is strictly larger than the source, not smaller.

So the `R_rec_succ` case cannot be closed with ordinal arithmetic lemmas; the measure itself is insufficient. The problem is that in the exponent

```lean
mu n + mu s + 6
```

and

```lean
mu (delta n) + mu s + 6
```

a sufficiently large `mu s` can absorb the improvement from replacing `mu n` by `mu (delta n)`.

A likely repair would be to change the `recDelta` exponent so that the counter component occurs after `mu s`, for example something like

```lean
omega0 ^ (mu s + mu n + 6)
```

or to use a commutative/natural ordinal sum instead of ordinary ordinal addition. But with the current definition, the theorem is false.
