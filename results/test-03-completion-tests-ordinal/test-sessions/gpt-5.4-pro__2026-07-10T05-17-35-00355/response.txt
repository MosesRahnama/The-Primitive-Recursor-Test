Here is a usable skeleton for the three remaining cases.

Two notes first:

- `R_eq_refl` is routine and can be filled directly.
- `R_eq_diff` has a standard “bound the inner polynomial by a smaller `ω`-power, then multiply by `ω^4`” shape.
- `R_rec_succ` is different: with the current `mu`, the critical exponent comparison appears to be false in general, so that `sorry` is probably not fillable without changing the measure. I’ll show the exact bottleneck.

## 1. `eqW a a --> void`

This one can be completed exactly like `R_int_delta`:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

## 2. `eqW a b --> integrate (merge a b)`

A good way to structure this proof is to isolate the `merge`-body as an abbreviation, prove it is below a smaller `ω`-power, then left-multiply by `ω^4`.

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    let M : Ordinal :=
      omega0 ^ (3 : Ordinal) * (mu a + 1) +
        omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1

    have hM :
        M < omega0 ^ (mu a + mu b + (5 : Ordinal)) := by
      -- Skeleton:
      -- 1. Bound the two polynomial pieces separately:
      --      ω^3 * (mu a + 1) < ω^(mu a + 4)
      --      ω^2 * (mu b + 1) < ω^(mu b + 3)
      --
      -- 2. Show both exponents are < mu a + mu b + 5.
      --
      -- 3. Since ω^(mu a + mu b + 5) is additively principal,
      --    the full finite sum M is still below it.
      --
      -- In practice, it is convenient to prove two local lemmas:
      --   hA : omega0 ^ (3 : Ordinal) * (mu a + 1)
      --          < omega0 ^ (mu a + mu b + (5 : Ordinal))
      --   hB : omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1
      --          < omega0 ^ (mu a + mu b + (5 : Ordinal))
      -- and then combine them using additive principality of ω^γ.
      sorry

    have h4 :
        omega0 ^ (4 : Ordinal) * M <
          omega0 ^ (mu a + mu b + (9 : Ordinal)) := by
      have hmul :
          omega0 ^ (4 : Ordinal) * M <
            omega0 ^ (4 : Ordinal) * omega0 ^ (mu a + mu b + (5 : Ordinal)) := by
        -- monotonicity of left multiplication by a positive ordinal
        exact mul_lt_mul_of_pos_left hM (opow_pos 4 omega0_pos)

      have hexp :
          (4 : Ordinal) + (mu a + mu b + (5 : Ordinal))
            ≤ mu a + mu b + (9 : Ordinal) := by
        -- finite ordinal arithmetic:
        -- use `4 + X ≤ X + 4`, then reassociate.
        sorry

      exact lt_of_lt_of_le
        (by
          -- rewrite ω^4 * ω^(...) as ω^(4 + ...)
          simpa [M, opow_add, add_assoc] using hmul)
        (by
          -- monotonicity of exponentiation base ω
          -- (lemma name may be `opow_le_opow_right` or similar)
          simpa using opow_le_opow_right hexp)

    -- now reattach the trailing `+ 1`
    simpa [M] using add_lt_add_right h4 1
```

### What the missing arithmetic lemma `hM` should prove
The core claim is essentially:

```lean
omega0 ^ (3 : Ordinal) * (mu a + 1) +
  omega0 ^ (2 : Ordinal) * (mu b + 1) + 2
< omega0 ^ (mu a + mu b + 5)
```

That is the right helper to prove separately if you want the case to become short.

## 3. `recDelta b s (delta n) --> app s (recDelta b s n)`

Here is the *shape* the proof would have if the arithmetic worked:

```lean
| _, _, Step.R_rec_succ b s n => by
    simp [mu]
    let κ : Ordinal := mu n + mu s + (6 : Ordinal)
    let E : Ordinal := mu (delta n) + mu s + (6 : Ordinal)

    have hApp :
        omega0 ^ (3 : Ordinal) * (mu s + 1) +
          omega0 ^ (2 : Ordinal) *
            (omega0 ^ κ + omega0 * (mu b + 1) + 1 + 1) + 1
        < omega0 ^ E := by
      have hsmall :
          omega0 ^ (3 : Ordinal) * (mu s + 1) +
            omega0 ^ (2 : Ordinal) *
              (omega0 ^ κ + omega0 * (mu b + 1) + 1 + 1) + 1
          < omega0 ^ (κ + (3 : Ordinal)) := by
        -- CNF/principality estimate:
        -- the dominant contribution is ω^2 * ω^κ = ω^(2 + κ),
        -- so the whole app-side is below ω^(κ + 3).
        sorry

      have hexp :
          κ + (3 : Ordinal) < E := by
        -- THIS is the critical exponent comparison.
        sorry

      exact lt_of_lt_of_le hsmall (by
        simpa using opow_le_opow_right (le_of_lt hexp))

    exact lt_of_lt_of_le hApp (le_add_right _ _)
```

### But this is the problem
The missing exponent inequality

```lean
(mu n + mu s + 6) + 3 < mu (delta n) + mu s + 6
```

is **not true in general** with ordinary ordinal addition, because the right-hand `+ mu s` can swallow the increase from `mu (delta n)`.

A concrete bad pattern is:

- take `n := void`
- take `s := recDelta void void void`

Then:
- `mu n = 0`
- `mu (delta n) = ω^5 + 1`
- `mu s = ω^6 + ω + 1`

So:

```text
mu (delta n) + mu s + 6 = ω^6 + ω + 7
mu n + mu s + 6         = ω^6 + ω + 7
```

The exponents become equal. Then the target contains

```text
ω^2 * (ω^(ω^6 + ω + 7) + ...)
= ω^(ω^6 + ω + 7) + bigger tail
```

while the source is only

```text
ω^(ω^6 + ω + 7) + ω * (mu b + 1) + 1
```

so the target is actually larger, not smaller.

So for `R_rec_succ`, the `sorry` is not just “missing tactics”; the current measure likely does **not** decrease.

## Bottom line

If you only want the immediate replacements/skeletons:

- `R_eq_refl`: use the exact positivity proof above.
- `R_eq_diff`: use the `M`/`hM`/`h4` structure above.
- `R_rec_succ`: the natural skeleton is the `κ`/`E` one above, but the key exponent lemma appears false for the current `mu`.
