I would not try to fill all three `sorry`s as-is: the `R_rec_succ` case is not merely missing ordinal-arithmetic lemmas; with the current definition of `mu` the desired inequality is false.

The problematic case is:

```lean
| _, _, Step.R_rec_succ b s n => by
    simp [mu]
    sorry
```

It would require a lemma of roughly this form:

```lean
omega0 ^ (3 : Ordinal) * (mu s + 1)
+ omega0 ^ (2 : Ordinal) *
    (omega0 ^ (mu n + mu s + (6 : Ordinal))
      + omega0 * (mu b + 1) + 1 + 1)
+ 1
<
omega0 ^ (mu (delta n) + mu s + (6 : Ordinal))
+ omega0 * (mu b + 1) + 1
```

But this is false because the leading `mu (delta n)` can be swallowed by ordinal addition with a sufficiently large `mu s`.

For example take

```lean
b = void
n = void
s = delta (delta void)
```

Write `ω = omega0`. Then

```text
mu s = ω^10 + ω^5 * 2 + 1
```

and

```text
mu (delta void) = ω^5 + 1.
```

Let

```text
γ = mu s + 6 = ω^10 + ω^5 * 2 + 7.
```

Then ordinal addition gives

```text
mu (delta void) + mu s + 6 = γ,
```

because the initial `ω^5 + 1` is absorbed by the leading `ω^10` part of `mu s`.

So the source measure is

```text
mu (recDelta void s (delta void))
= ω^γ + ω + 1.
```

But the target measure is

```text
mu (app s (recDelta void s void))
= ω^3 * (mu s + 1)
  + ω^2 * (ω^γ + ω + 2)
  + 1
= ω^γ + ω^3 + ω^2 * 2 + 1,
```

since the preceding `ω^3 * (mu s + 1)` is absorbed by the later `ω^γ` term.

Thus

```text
mu target = ω^γ + ω^3 + ω^2 * 2 + 1
          > ω^γ + ω + 1
          = mu source.
```

So the `R_rec_succ` case cannot be completed without changing the measure.

The easy `eq_refl` case can be filled with the same positivity pattern already used earlier:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

For `eq_diff`, the intended proof skeleton would be to isolate one dominance lemma:

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]

    -- Main ordinal-arithmetic dominance lemma needed here:
    have hdom :
        omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1)
            + omega0 ^ (2 : Ordinal) * (mu b + 1)
            + 1 + 1)
        <
        omega0 ^ (mu a + mu b + (9 : Ordinal)) := by
      -- Prove by bounding the merge payload below an omega-power.
      --
      -- Desired internal estimates:
      --   omega0^3 * (mu a + 1) < omega0^(mu a + mu b + 5)
      --   omega0^2 * (mu b + 1) < omega0^(mu a + mu b + 5)
      --   1 + 1                  < omega0^(mu a + mu b + 5)
      --
      -- Then:
      --   bracket < omega0^(mu a + mu b + 5)
      --
      -- Multiplying by omega0^4 gives something below
      --   omega0^(mu a + mu b + 9).
      --
      -- This is the place to use the standard omega-power dominance lemmas.
      sorry

    -- Then use successor/right-addition monotonicity:
    exact add_lt_add_right hdom 1
```

But the whole theorem still cannot be finished because the `R_rec_succ` case is false for the current `mu`. The repair would need to change the recursive measure so that the source exponent cannot be absorbed by `mu s`; for example, the counter component has to occur after `mu s` in the ordinal sum, or otherwise be placed in a position that remains dominant under ordinal addition.
