## Skeleton for the three remaining `sorry` cases

Below I give a proof strategy and an outline (with the key ordinal lemmas that need to be discharged) for each of `R_rec_succ`, `R_eq_refl`, and `R_eq_diff`. I do not attempt a full term-mode proof; I describe the chain of inequalities the proof should establish, plus the supporting facts the skeleton should pull in from `Mathlib.SetTheory.Ordinal.*`.

---

### 1. `R_eq_refl` — `eqW a a → void`

**Goal after `simp [mu]`:**
```
0 < omega0 ^ (mu a + mu a + 9) + 1
```

**Strategy:** This is a pure positivity argument; the `+ 1` is the easy part. There are two natural ways to write the last step:

- *Variant A* (use `succ`): `omega0 ^ (mu a + mu a + 9) + 1 = succ (omega0 ^ (mu a + mu a + 9))`, and `succ_pos : (0 : Ordinal) < succ _` from `Mathlib.SetTheory.Ordinal.Basic`.
- *Variant B* (use `le_add_right` + `one_pos`):
  ```
  have h1 : (0 : Ordinal) < 1 := one_pos
  have h2 : (1 : Ordinal) ≤ omega0 ^ (mu a + mu a + 9) + 1 := le_add_right _ _
  exact lt_of_lt_of_le h1 h2
  ```

Either way the proof is two lines after the `simp`. This is by far the cheapest of the three cases — it is essentially identical in shape to the already-proven `R_int_delta` case (whose current proof, incidentally, looks like it has the tactics in the wrong order — `ne_of_gt` after `pos_iff_ne_zero.mpr` should be `ne_of_gt` *inside* the `mpr` argument — but the structure is the same).

**Skeleton:**
```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    -- 0 < omega^(2*mu a + 9) + 1, by positivity of the trailing +1.
    exact lt_of_lt_of_le one_pos (le_add_right _ _)
```

### 2. `R_eq_diff` — `eqW a b → integrate (merge a b)`

**Goal after `simp [mu]`:**
```
omega0 ^ 4 * (omega0 ^ 3 * (mu a + 1) + omega0 ^ 2 * (mu b + 1) + 2) + 1
  < omega0 ^ (mu a + mu b + 9) + 1
```

Expanding the left hand side using `opow_mul` / `mul_add`:
```
LHS = omega0 ^ 7 * (mu a + 1)
    + omega0 ^ 6 * (mu b + 1)
    + omega0 ^ 4 * 2
    + 1
RHS = omega0 ^ (mu a + mu b + 9) + 1
```

It suffices to show the (LHS − 1) part is `< omega0 ^ (mu a + mu b + 9) + 1`, i.e. that the three tower-headed summands are jointly dominated by a single tower of height `mu a + mu b + 9`. The shape of the measure is what makes this work: `mu a` and `mu b` appear in the *exponent* on the RHS, so an `omega0^k` term on the LHS can be absorbed provided `k < mu a + mu b + 9`.

**Strategy — push every LHS summand into the dominant tower:**

1. **Bound `mu a + 1 ≤ omega0 ^ (mu a + 1)` and `mu b + 1 ≤ omega0 ^ (mu b + 1)`.** This is the standard "any ordinal is below `omega0 ^ (its successor)`" fact, available as `le_opow_succ` (or provable by transfinite induction on `mu a`).
2. **Absorb the coefficients into the tower heights:**
   ```
   omega0 ^ 7 * (mu a + 1) ≤ omega0 ^ 7 * omega0 ^ (mu a + 1) = omega0 ^ (mu a + 8)
   omega0 ^ 6 * (mu b + 1) ≤ omega0 ^ 6 * omega0 ^ (mu b + 1) = omega0 ^ (mu b + 7)
   ```
3. **Strictly below the RHS tower.** For nonneg ordinals `α, β` we have `α + 8 < α + β + 9` (because `β + 1 > 0`, i.e. just `8 < β + 9` since `β ≥ 0`) and similarly `β + 7 < α + β + 9` (since `α + 2 > 0`). So by monotonicity of `opow` in the exponent:
   ```
   omega0 ^ (mu a + 8) < omega0 ^ (mu a + mu b + 9)
   omega0 ^ (mu b + 7) < omega0 ^ (mu a + mu b + 9)
   ```
4. **Constant term:** `omega0 ^ 4 * 2 < omega0 ^ 5 < omega0 ^ 9 ≤ omega0 ^ (mu a + mu b + 9)`.
5. **Combine the three terms.** The non-trivial step: with `α = mu a + mu b + 9`, we have
   ```
   omega0 ^ (mu a + 8) + omega0 ^ (mu b + 7) + omega0 ^ 5  <  omega0 ^ α
   ```
   Use the general fact that for limit ordinals `α` and terms `γ_i < α` whose *exponent-parts* are bounded below `α`, the sum stays below `α`. Concretely, the heaviest term is `omega0 ^ (mu a + 8)`, and `mu a + 8 + 1 ≤ mu a + mu b + 9` once `mu b ≥ 0`, so
   ```
   omega0 ^ (mu a + 8) + omega0 ^ (mu b + 7) < omega0 ^ (mu a + 8) * omega0 = omega0 ^ (mu a + 9) ≤ omega0 ^ α
   ```
   (this last step is `le_opow_succ` or `opow_le_opow_right` applied to `mu a + 9 ≤ mu a + mu b + 9`). Then add the `omega0 ^ 5` term similarly.
6. **Add the trailing `+ 1` on each side** via `lt_add_right`/`le_add_right`.

**Skeleton:**
```lean
| _, _, Step.R_eq_diff a b => by
    simp only [mu]
    -- LHS = omega^7*(mu a+1) + omega^6*(mu b+1) + omega^4*2 + 1
    -- RHS = omega^(mu a + mu b + 9) + 1
    -- Step 1: omega^7*(mu a+1) ≤ omega^(mu a+8)        (via le_opow_succ)
    -- Step 2: omega^6*(mu b+1) ≤ omega^(mu b+7)        (via le_opow_succ)
    -- Step 3: omega^4*2 < omega^5 < omega^9 ≤ omega^(mu a+mu b+9)
    -- Step 4: combine via opow_add / "sum of lower towers stays below the next"
    -- Step 5: bolt on the +1 with lt_add_right / le_add_right
    sorry
```

The supporting facts the skeleton needs to be wired up:
- `Ordinal.le_opow_succ : ∀ a, a ≤ omega0 ^ succ a` (or its induction proof).
- `Ordinal.opow_le_opow_right : a ≤ b → omega0 ^ a ≤ omega0 ^ b` for limit/monotone exponents.
- `Ordinal.opow_add : omega0 ^ a * omega0 ^ b = omega0 ^ (a + b)` (from `Mathlib.SetTheory.Ordinal.Arithmetic`).
- The ordinal `omega0^α * n < omega0^β` whenever `α < β` and `n < omega0`, which is what lets three "lower" towers stay under a higher one.

### 3. `R_rec_succ` — `recDelta b s (delta n) → app s (recDelta b s n)`

**Goal after `simp [mu]`:**
```
omega0 ^ 3 * (mu s + 1)
  + omega0 ^ 2 * (omega0 ^ (mu n + mu s + 6) + omega0 * (mu b + 1) + 1 + 1) + 1
  < omega0 ^ (omega0 ^ 5 * (mu n + 1) + 1 + mu s + 6) + omega0 * (mu b + 1) + 1
```

The LHS exponent on the right-hand side contains a sub-tower `omega0 ^ 5 * (mu n + 1)`, which is the *whole point* of the `delta gets base omega0^5` design choice. The LHS's tallest tower is `omega0 ^ (mu n + mu s + 6)` and `mu n + mu s + 6` is dwarfed by `omega0 ^ 5 * (mu n + 1) + mu s + 7`.

**Strategy — peel off and dominate:**

1. **Drop positive slack to get a clean LHS bound.** All of the trailing `+ 1`s and the `+ 1` inside `(...) + 1` on the LHS are positive; replace them by their bound `omega0` (or just drop, using `le_add_right`). A clean upper bound for the LHS is
   ```
   omega0 ^ 3 * (mu s + 1) + omega0 ^ 2 * omega0 ^ (mu n + mu s + 6)
              + omega0 ^ 2 * omega0 * (mu b + 1) + omega0 ^ 2 + 1
   = omega0 ^ 3 * (mu s + 1) + omega0 ^ (mu n + mu s + 8) + omega0 ^ 3 * (mu b + 1) + omega0 ^ 2 + 1
   ```
   (using `opow_add` twice and `omega0^2 * omega0 = omega0^3`).
2. **Bound the polynomial-prefix terms** `omega0^3 * (mu s + 1)` and `omega0^3 * (mu b + 1)` using the same `le_opow_succ` trick as in case 2:
   ```
   omega0 ^ 3 * (mu s + 1) ≤ omega0 ^ 3 * omega0 ^ (mu s + 1) = omega0 ^ (mu s + 4)
   omega0 ^ 3 * (mu b + 1) ≤ omega0 ^ (mu b + 4)
   ```
3. **Bound the giant tower by the RHS tower.** The dominating LHS term is `omega0 ^ (mu n + mu s + 8)`. Compare its exponent `mu n + mu s + 8` to the RHS exponent `omega0 ^ 5 * (mu n + 1) + mu s + 7`. Since `mu n + 1 ≥ 1` and `omega0 ^ 5 > 8`, we have `omega0 ^ 5 * (mu n + 1) ≥ omega0 ^ 5 > 8`, so
   ```
   mu n + mu s + 8 < omega0 ^ 5 * (mu n + 1) + mu s + 7
   ```
   Hence by monotonicity of `opow`,
   ```
   omega0 ^ (mu n + mu s + 8) < omega0 ^ (omega0 ^ 5 * (mu n + 1) + mu s + 7)
   ```
   This is the only place where the `+ 5` exponent on `delta` actually has to dominate an *additive* `+ 8`; everything else is absorbed.
4. **Combine.** Show that the whole LHS sits below `omega0 ^ (omega0 ^ 5 * (mu n + 1) + mu s + 7)` (the polynomial-prefix terms in step 2 are far smaller, and `omega0^2 + 1` is negligible). Then add the `omega0 * (mu b + 1) + 1` suffix of the RHS with `lt_add_right`/`le_add_right`.

**Skeleton:**
```lean
| _, _, Step.R_rec_succ b s n => by
    simp only [mu]
    -- LHS = omega^3*(mu s+1) + omega^2*(omega^(mu n+mu s+6) + omega*(mu b+1) + 2) + 1
    --     ≤ omega^3*(mu s+1) + omega^(mu n+mu s+8) + omega^3*(mu b+1) + omega^2 + 1
    -- RHS = omega^(omega^5*(mu n+1) + mu s + 7) + omega*(mu b+1) + 1
    --
    -- (a) omega^3*(mu s+1) ≤ omega^(mu s+4)              (le_opow_succ)
    -- (b) omega^3*(mu b+1) ≤ omega^(mu b+4)              (le_opow_succ)
    -- (c) omega^(mu n+mu s+8) < omega^(omega^5*(mu n+1) + mu s + 7)
    --     because  mu n+mu s+8 < omega^5*(mu n+1) + mu s + 7
    --     (since omega^5 ≥ 8 with strict inequality coming from mu n+1 ≥ 1)
    -- (d) combine (a)+(b)+(c) + (omega^2 + 1) below the dominant RHS tower
    -- (e) add the omega*(mu b+1)+1 tail on the RHS via le_add_right
    sorry
```

---

### What ties the three cases together

The single design idea that the skeleton should make explicit is the *self-similarity* of `mu`: the exponent on `omega0` in a constructor's measure is chosen to dominate every term that can appear on the RHS of its reduction. Concretely:

- `R_eq_refl` works because the measure is `omega^… + 1`, so the empty term `0 < + 1` is trivial.
- `R_eq_diff` works because the RHS's `omega0 ^ (mu a + mu b + 9)` carries *both* `mu a` and `mu b` in its exponent, so it can absorb the polynomial prefixes `omega0^7·(mu a+1)`, `omega0^6·(mu b+1)` that the LHS expansion produces.
- `R_rec_succ` works because `delta` carries the *multiplicative* base `omega0^5` in its measure, and `omega0^5 > 8` (the additive constant that the recursion RHS accumulates), so the tower on the LHS of the inequality strictly dominates the tower that the unrolled recursion reaches.

If you want one diagnostic for whether the `sorry`s are reachable: in each case, the inequality reduces to a single comparison of *exponents* of the form
```
   (constant from the constructor)  <  (something involving mu of the body of the step's LHS)
```
For `R_eq_refl` the constant is `0`; for `R_eq_diff` it is `9 > 7`; for `R_rec_succ` it is `omega0^5 > 8`. The `5` and the `9` are exactly the slack that was baked into `delta` and `eqW` in the definition of `mu`, and that is what should be made visible in the final proof.
