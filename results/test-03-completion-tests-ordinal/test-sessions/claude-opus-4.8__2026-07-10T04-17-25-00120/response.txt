# Proof Skeletons for the Three Remaining Cases

Below are proof skeletons for the three `sorry` cases. I'll present them in order of difficulty, since `R_eq_refl` is trivial and the other two require genuine ordinal arithmetic.

## Case 1: `R_eq_refl` (easiest — pure positivity)

The goal after `simp [mu]` is essentially `0 < omega0 ^ (mu a + mu a + 9) + 1` (or a normalized variant). This is just positivity of `x + 1`.

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    -- Goal reduces to: 0 < omega0 ^ (mu a + mu a + 9) + 1
    -- (or whatever normal form simp produces)
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
    -- Alternative if simp closes to `0 < _ + 1`:
    --   exact lt_of_lt_of_le zero_lt_one (le_add_left _ _)
    -- or simply:  positivity  (may or may not fire on Ordinal)
```

**Key lemmas:** `Ordinal.pos_iff_ne_zero`, `add_pos_right`, `one_pos`, mirroring the already-proved `R_int_delta` case.

## Case 2: `R_eq_diff` (medium — comparing exponents)

The strategy is to reduce everything to comparing a **single** `omega0 ^ e` term. The core fact is that the entire LHS is bounded above by some `omega0 ^ (small)` while the RHS contains `omega0 ^ (mu a + mu b + 9)` with a strictly larger exponent.

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    -- Goal: omega0^4 * (omega0^3 * (mu a + 1) + omega0^2 * (mu b + 1) + 1 + 1) + 1
    --        < omega0 ^ (mu a + mu b + 9) + 1

    -- STEP 1: Set up the target exponent and a comfortable intermediate bound.
    --   Choose an exponent E strictly below (mu a + mu b + 9), e.g. E = mu a + mu b + 8,
    --   such that the entire LHS is ≤ omega0 ^ E.
    set L := omega0 ^ (4:Ordinal) * (omega0^(3:Ordinal)*(mu a+1)
                + omega0^(2:Ordinal)*(mu b+1) + 1 + 1) + 1 with hL

    -- STEP 2: Bound L above by omega0 ^ (mu a + mu b + 8).
    --   Use that opow is monotone and that each factor/summand is dominated.
    have hbound : L ≤ omega0 ^ (mu a + mu b + 8) := by
      -- Bound the inner merge-part: the argument of omega0^4 is < omega0^(mu a+mu b+4)
      -- because omega0^3*(mu a+1) etc. are all < omega0^(mu a+mu b+4).
      -- Then omega0^4 * (< omega0^(mu a+mu b+4)) < omega0^(mu a+mu b+8), and +1 stays below.
      sorry
      -- Useful: Ordinal.opow_le_opow_right, Ordinal.mul_lt_opow /
      --         Ordinal.opow_add : omega0^(x+y) = omega0^x * omega0^y,
      --         Ordinal.lt_opow_iff / Principal.opow properties,
      --         Ordinal.mul_le_mul, le_add_right.

    -- STEP 3: omega0 ^ (mu a + mu b + 8) < omega0 ^ (mu a + mu b + 9).
    have hexp : (mu a + mu b + 8 : Ordinal) < mu a + mu b + 9 := by
      apply Ordinal.add_lt_add_left
      norm_num
    have hstrict : omega0 ^ (mu a + mu b + 8) < omega0 ^ (mu a + mu b + 9) :=
      Ordinal.opow_lt_opow_right one_lt_omega0 hexp   -- (name may be opow_lt_opow_left/right)

    -- STEP 4: chain and add the trailing +1 on the RHS.
    calc L ≤ omega0 ^ (mu a + mu b + 8) := hbound
      _ < omega0 ^ (mu a + mu b + 9)    := hstrict
      _ ≤ omega0 ^ (mu a + mu b + 9) + 1 := le_add_right _ _
```

**The only real work is STEP 2.** The recommended micro-structure for it:

```lean
    -- Sub-lemma A: the merge measure is dominated:
    --   omega0^3*(mu a+1) + omega0^2*(mu b+1) + 1 + 1 < omega0^(mu a + mu b + 4)
    have hmerge : omega0^(3:Ordinal)*(mu a+1) + omega0^(2:Ordinal)*(mu b+1) + 1 + 1
                    < omega0 ^ (mu a + mu b + 4) := by
      -- Each summand < omega0^(mu a + mu b + 4); a sum of finitely many terms each
      -- below a multiplicatively-closed (additively principal) power stays below.
      -- Use: omega0^3*(mu a+1) < omega0^(mu a+3) ≤ omega0^(mu a+mu b+4), etc.
      sorry
    -- Sub-lemma B: multiply by omega0^4 and use opow_add:
    --   omega0^4 * omega0^(mu a+mu b+4) = omega0^(mu a+mu b+8)
    have hmul : omega0^(4:Ordinal) * (omega0 ^ (mu a + mu b + 4))
                  = omega0 ^ (mu a + mu b + 8) := by
      rw [← Ordinal.opow_add]; ring_nf   -- reconcile 4 + (mu a+mu b+4) = mu a+mu b+8
    -- Combine: omega0^4 * inner < omega0^4 * omega0^(...) = omega0^(mu a+mu b+8),
    -- then handle the trailing +1.
    sorry
```

**Key lemmas for this case:**
- `Ordinal.opow_add : a ^ (b + c) = a ^ b * a ^ c`
- `Ordinal.opow_lt_opow_right` / `opow_lt_opow_left` (strict monotonicity of `omega0 ^ ·` in the exponent, using `one_lt_omega0`)
- `Ordinal.opow_le_opow_right` (weak monotonicity)
- `Ordinal.mul_lt_mul_of_pos_left` / `Ordinal.mul_le_mul_left'`
- Additive-principality of `omega0 ^ e`: `Ordinal.principal_add_opow_omega0` (a sum of terms each `< omega0^e` is `< omega0^e`); or `Ordinal.add_lt_of_lt` style lemmas.

## Case 3: `R_rec_succ` (hardest — nested exponent domination)

Here the LHS exponent is `mu (delta n) + mu s + 6 = omega0^5*(mu n+1) + 1 + mu s + 6`, which contains the huge summand `omega0^5*(mu n+1)`. The whole RHS is polynomial in `omega0^(mu n + mu s + 6)`, whose exponent `mu n + mu s + 6` is dwarfed by `omega0^5*(mu n+1)`.

```lean
| _, _, Step.R_rec_succ b s n => by
    simp [mu]
    -- LHS = omega0^3*(mu s+1) + omega0^2*(mu(recDelta b s n)+1) + 1
    --     = omega0^3*(mu s+1)
    --       + omega0^2*(omega0^(mu n+mu s+6) + omega0*(mu b+1) + 1 + 1) + 1
    -- RHS = omega0^(mu(delta n) + mu s + 6) + omega0*(mu b+1) + 1
    --     = omega0^(omega0^5*(mu n+1) + 1 + mu s + 6) + omega0*(mu b+1) + 1

    -- STRATEGY: bound the whole LHS below a single power omega0^K with K small,
    -- and show omega0^K is strictly below the leading power of the RHS.

    -- STEP 1: Name the RHS leading exponent and a comfortable middle exponent.
    set ERHS := mu (delta n) + mu s + 6 with hERHS   -- = omega0^5*(mu n+1)+1+mu s+6
    -- Pick a middle exponent that surely bounds the LHS, e.g. K = mu n + mu s + 8.
    set K := mu n + mu s + 8 with hK

    -- STEP 2: Bound the entire LHS above by omega0 ^ K.
    have hLHS : (omega0^(3:Ordinal)*(mu s+1)
                  + omega0^(2:Ordinal)*(omega0^(mu n+mu s+6)
                        + omega0*(mu b+1) + 1 + 1) + 1)
                  ≤ omega0 ^ K := by
      -- The dominating summand is omega0^2 * omega0^(mu n+mu s+6)
      --   = omega0^(mu n+mu s+8) = omega0^K  (via opow_add).
      -- Every other summand is strictly below omega0^K.
      -- Conclude with additive-principality of omega0^K.
      sorry
      -- Useful: Ordinal.opow_add, Ordinal.mul_le_mul_left',
      --         Ordinal.principal_add_opow_omega0, opow monotonicity.

    -- STEP 3: Show K < ERHS, i.e. the RHS exponent strictly dominates K.
    have hKlt : K < ERHS := by
      -- ERHS = omega0^5*(mu n+1) + 1 + mu s + 6 ≥ omega0^5*(mu n+1)
      -- and omega0^5*(mu n+1) ≥ omega0^5 > mu n + mu s + 8 = K,
      -- since omega0^5 is a limit exceeding any expression built from
      -- finite offsets and mu n, mu s at "polynomial" level.
      -- Concretely: K = mu n + mu s + 8 < omega0^5 ≤ omega0^5*(mu n+1) ≤ ERHS.
      have h1 : (mu n + mu s + 8 : Ordinal) < omega0 ^ (5:Ordinal) := by
        -- mu n, mu s are ordinals; but note omega0^5 is additively/mult. principal
        -- ... this step is only valid with an additional bound on mu n, mu s.
        sorry
      have h2 : omega0 ^ (5:Ordinal) ≤ omega0^(5:Ordinal)*(mu n+1) :=
        Ordinal.le_mul_right _ (by exact_mod_cast Nat.succ_pos _)  -- mu n + 1 > 0
      have h3 : omega0^(5:Ordinal)*(mu n+1) ≤ ERHS := by
        rw [hERHS]; simp [mu]; exact le_add_right _ _  -- adjust to normal form
      calc K = mu n + mu s + 8 := hK
        _ < omega0 ^ (5:Ordinal) := h1
        _ ≤ omega0^(5:Ordinal)*(mu n+1) := h2
        _ ≤ ERHS := h3

    -- STEP 4: strict monotonicity of the exponential, then reattach the tail.
    have hpow : omega0 ^ K < omega0 ^ ERHS :=
      Ordinal.opow_lt_opow_right one_lt_omega0 hKlt

    -- STEP 5: chain everything, adding RHS tail (omega0*(mu b+1)+1) as ≤ padding.
    calc (omega0^(3:Ordinal)*(mu s+1)
            + omega0^(2:Ordinal)*(omega0^(mu n+mu s+6)
                  + omega0*(mu b+1) + 1 + 1) + 1)
        ≤ omega0 ^ K       := hLHS
      _ < omega0 ^ ERHS    := hpow
      _ ≤ omega0 ^ ERHS + (omega0*(mu b+1) + 1) := le_add_right _ _
```

⚠️ **Important caveat on STEP 3, `h1`:** The claim `mu n + mu s + 8 < omega0^5` is **false in general**, because `mu n` and `mu s` can be arbitrarily large ordinals. The genuinely correct comparison must keep `mu s` inside the exponent on *both* sides. The corrected version of STEP 3 should be:

```lean
    have hKlt : mu n + mu s + 8 < mu (delta n) + mu s + 6 := by
      rw [show mu (delta n) = omega0^(5:Ordinal)*(mu n+1) + 1 from rfl]
      -- Goal: mu n + mu s + 8 < omega0^5*(mu n+1) + 1 + mu s + 6
      -- Since omega0^5*(mu n+1) ≥ omega0^5*1 ≥ omega0 > mu n + (finite),
      -- and mu s appears additively on both sides, use add_lt_add / cancellation.
      -- The safe route: show mu n + 8 < omega0^5*(mu n+1) + 1 (LHS finite offset,
      -- RHS a limit-scale multiple), then add mu s + 6 appropriately using
      -- left-additivity monotonicity. Note ordinal addition is NOT commutative,
      -- so re-associate carefully.
      sorry
```

**Key lemmas for this case:**
- `Ordinal.opow_add`, `Ordinal.opow_lt_opow_right`, `Ordinal.opow_le_opow_right`
- `Ordinal.le_mul_right`, `Ordinal.mul_le_mul_left'`
- `Ordinal.principal_add_opow_omega0` (additive absorption)
- `Ordinal.add_lt_add_left`, `Ordinal.add_le_add_left` (⚠️ ordinal addition is left-cancellative but **not** commutative)
- `one_lt_omega0`, `omega0_pos`

## Summary of the recommended proof pattern

All three hard cases follow the same three-move template:

1. **Collapse to a single power.** Bound the entire smaller term above by one `omega0 ^ K` using `opow_add` and additive-principality (`principal_add_opow_omega0`).
2. **Compare exponents.** Prove `K < E` where `E` is the leading exponent of the larger term (this is the arithmetically delicate part — mind non-commutativity of ordinal `+`).
3. **Lift and pad.** Apply `opow_lt_opow_right one_lt_omega0`, then absorb trailing `+ (...)` terms via `le_add_right`.

**Warning I want to flag explicitly:** the measure as written may not actually decrease for `R_rec_succ` without additional side conditions, because the exponent comparison in STEP 3 needs `mu s` handled *inside* the exponent on both sides. If, after formalizing, `hKlt` cannot be discharged, the `mu` definition itself likely needs the `recDelta` exponent adjusted (e.g. ensuring the `delta`-driven `omega0^5` term strictly dominates the `omega0^2`-scaled recursive expansion). I've left the two `sorry`s in STEP 2 and STEP 3 precisely at the points where the real mathematical content lives.
