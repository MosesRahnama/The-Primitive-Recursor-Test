Below is a proof skeleton for the three `sorry` cases, keeping your file unchanged and not assuming any compiler interaction. I’ll phrase it as “how to finish each branch” with Lean-style structure and the key lemmas/inequalities you’d likely invoke.

The main theme is:

- reduce the goal to a comparison of leading ordinal terms,
- use positivity to absorb trailing `+ 1`,
- prove a strict inequality between the dominant pieces,
- then conclude by monotonicity of addition/exponentiation.

## 1) `Step.R_rec_succ b s n`

### Goal shape after `simp [mu]`

You want something of the form

```lean
omega0 ^ (3 : Ordinal) * (mu s + 1)
  + omega0 ^ (2 : Ordinal) *
      (omega0 ^ (mu n + mu s + (6 : Ordinal)) + omega0 * (mu b + 1) + 1 + 1)
  + 1
<
omega0 ^ (omega0 ^ (5 : Ordinal) * (mu n + 1) + 1 + mu s + (6 : Ordinal))
  + omega0 * (mu b + 1) + 1
```

up to reassociation/simplification.

### Intended mathematical reason

The right-hand side has leading term

```lean
omega0 ^ (mu (delta n) + mu s + 6)
```

and since

```lean
mu (delta n) = omega0^5 * (mu n + 1) + 1,
```

that exponent is enormous. It strictly dominates the exponent `mu n + mu s + 6` occurring inside `mu (recDelta b s n)`, and therefore also dominates the whole `app` measure, whose largest contribution is only `omega^2 * mu(recDelta ...)` plus an `omega^3 * ...`.

So the proof should go by:
1. show the whole LHS is bounded above by some ordinal of the form `omega0 ^ E`,
2. show `E < mu (delta n) + mu s + 6`,
3. infer that LHS `< omega0 ^ (mu (delta n) + mu s + 6)`,
4. then conclude `< omega0 ^ (...) + omega0 * (mu b + 1) + 1`.

### Skeleton

```lean
| _, _, Step.R_rec_succ b s n => by
    simp [mu]

    -- Let abbreviations for the two relevant exponents.
    let α : Ordinal := mu n + mu s + (6 : Ordinal)
    let β : Ordinal := omega0 ^ (5 : Ordinal) * (mu n + 1) + 1 + mu s + (6 : Ordinal)

    -- First show α < β.
    have hαβ₁ : mu n < omega0 ^ (5 : Ordinal) * (mu n + 1) := by
      have h1 : mu n < mu n + 1 := lt_add_one (mu n)
      have h2 : mu n + 1 ≤ omega0 ^ (5 : Ordinal) * (mu n + 1) :=
        le_mul_right _ (opow_pos 5 omega0_pos)
      exact lt_of_lt_of_le h1 h2

    -- Upgrade that to α < β by monotonicity of addition.
    have hαβ : α < β := by
      -- enough to compare the left initial segment `mu n`
      -- with `omega0^5 * (mu n + 1) + 1`, then add `mu s + 6` on the right.
      -- This can be done with repeated `simpa [α, β, add_assoc]` using
      -- `add_lt_add_right` and `lt_add_one`.
      have h' : mu n + mu s + (6 : Ordinal) <
          (omega0 ^ (5 : Ordinal) * (mu n + 1) + 1) + mu s + (6 : Ordinal) := by
        -- e.g.
        -- exact add_lt_add_right (add_lt_add_right ?_ (mu s)) (6 : Ordinal)
        sorry
      simpa [α, β, add_assoc] using h'

    -- Next, bound the `app`-measure by something below `omega0 ^ β`.
    --
    -- A natural intermediate statement is that
    --   mu (recDelta b s n) < omega0 ^ α + omega0 * (mu b + 1) + 1
    -- by definition,
    -- hence in particular `mu (recDelta b s n) + 1 ≤ omega0 ^ α + ... + 1`.
    --
    -- Then `omega0^2 * (mu(recDelta...) + 1)` is still below `omega0 ^ β`
    -- because `ω^β` dominates `ω^2 * ω^α` whenever α < β.
    --
    -- Likewise `omega0^3 * (mu s + 1) < omega0 ^ β`.

    have hLead1 : omega0 ^ (3 : Ordinal) * (mu s + 1) < omega0 ^ β := by
      -- Since β ≥ 6 in particular, ω^β dominates every term of the form ω^3 * c.
      -- One way:
      --   show 3 < β, hence ω^3 < ω^β, then multiply/absorb coefficient.
      sorry

    have hLead2 : omega0 ^ (2 : Ordinal) *
        (omega0 ^ α + omega0 * (mu b + 1) + 1 + 1) < omega0 ^ β := by
      -- Use α < β and the fact that ω^β dominates ω^2 * (ω^α + lower terms).
      -- Typical route:
      -- 1. bound `(omega0 ^ α + omega0 * ... + 1 + 1)` by `omega0 ^ α * C` or at least by an ordinal < `omega0 ^ (α+1)`;
      -- 2. then show `omega0^2 * ... < omega0 ^ β` since `α + finite < β`.
      sorry

    have hAppBound :
        omega0 ^ (3 : Ordinal) * (mu s + 1) +
          omega0 ^ (2 : Ordinal) *
            (omega0 ^ α + omega0 * (mu b + 1) + 1 + 1) + 1
        < omega0 ^ β := by
      -- Combine hLead1 and hLead2, using that sum of two ordinals each < ω^β
      -- is still < ω^β when ω^β is principal/additively closed.
      --
      -- This is where `Mathlib.SetTheory.Ordinal.Principal` is meant to help:
      -- powers `ω^β` are additive principal.
      sorry

    -- Finally absorb the tail on the RHS.
    calc
      omega0 ^ (3 : Ordinal) * (mu s + 1) +
          omega0 ^ (2 : Ordinal) *
            (omega0 ^ α + omega0 * (mu b + 1) + 1 + 1) + 1
        < omega0 ^ β := hAppBound
      _ ≤ omega0 ^ β + omega0 * (mu b + 1) + 1 := by
            -- monotonicity of addition
            exact le_add_right _ _
```

### Practical note

This is the hardest case. The likely library strategy is to exploit that `omega0 ^ β` is **additively principal** and dominates any sum of smaller ordinals. So the central missing ingredients are lemmas of the shape:

- `α < β -> omega0 ^ α < omega0 ^ β`
- if `x < omega0 ^ β` and `y < omega0 ^ β`, then `x + y < omega0 ^ β`
- finite/low-degree multiplicative decorations stay below a sufficiently larger `omega0 ^ β`

If exact lemma names differ, that’s the proof architecture to implement.

## 3) `Step.R_eq_diff a b`

### Goal shape after `simp [mu]`

You need

```lean
omega0 ^ (4 : Ordinal) *
    (omega0 ^ (3 : Ordinal) * (mu a + 1) +
      omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1)
  + 1
<
omega0 ^ (mu a + mu b + (9 : Ordinal)) + 1
```

### Intended mathematical reason

The left side is at worst “on the order of” `omega^(4 + 3) = omega^7` times some coefficient coming from `mu a, mu b`, while the right side is `omega^(mu a + mu b + 9)`, whose exponent is at least `9`, hence much larger than anything generated by the `integrate ∘ merge` construction.

A very robust route is:

1. show
   ```lean
   mu (merge a b) < omega0 ^ (mu a + mu b + 8)
   ```
   or any exponent strictly below `mu a + mu b + 9`,
2. then by monotonicity of multiplication by `omega0^4`,
   ```lean
   omega0^4 * (mu (merge a b) + 1) < omega0 ^ (mu a + mu b + 9),
   ```
3. then add `1` on both sides using monotonicity.

### Skeleton

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]

    let γ : Ordinal := mu a + mu b + (9 : Ordinal)

    -- First show each component of `mu (merge a b)` is below `ω^(mu a + mu b + 8)`
    -- (or any exponent < γ that is convenient).
    have hA :
        omega0 ^ (3 : Ordinal) * (mu a + 1) < omega0 ^ (mu a + mu b + (8 : Ordinal)) := by
      -- Since `3 < mu a + mu b + 8`, ω^(...) on the right dominates this term.
      sorry

    have hB :
        omega0 ^ (2 : Ordinal) * (mu b + 1) < omega0 ^ (mu a + mu b + (8 : Ordinal)) := by
      sorry

    have hMerge :
        omega0 ^ (3 : Ordinal) * (mu a + 1) +
          omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1
        < omega0 ^ (mu a + mu b + (8 : Ordinal)) := by
      -- Use additive-principal closure of ω^(...)
      -- to absorb the sum of hA, hB, and the finite tail.
      sorry

    have hInt :
        omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1) +
            omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1)
        < omega0 ^ γ := by
      -- From hMerge and exponent arithmetic:
      -- ω^4 * (something below ω^(...+8)) is below ω^(...+9).
      --
      -- One standard way is to first deduce
      --   (...) ≤ ω^(mu a + mu b + 8)
      -- then
      --   ω^4 * (...) ≤ ω^4 * ω^(mu a + mu b + 8) = ω^(4 + (mu a + mu b + 8))
      -- and finally show
      --   4 + (mu a + mu b + 8) < mu a + mu b + 9
      -- or simplify via ordinal arithmetic to a suitable strict bound.
      sorry

    calc
      omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1) +
            omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1) + 1
        < omega0 ^ γ + 1 := by
            exact add_lt_add_right hInt 1
      _ = omega0 ^ (mu a + mu b + (9 : Ordinal)) + 1 := by
            simp [γ]
```

### A slightly simpler variant

Instead of proving a very sharp bound on `mu (merge a b)`, you can try a coarser one:

- show `mu (merge a b) + 1 < omega0 ^ (mu a + mu b + 8)`,
- then directly derive
  ```lean
  omega0 ^ 4 * (mu (merge a b) + 1) < omega0 ^ (mu a + mu b + 9)
  ```
  because multiplying by `omega^4` shifts exponent by only a finite amount, while the RHS exponent has an extra `+ 9`.

This may align better with available lemmas.

Again the core tool is monotonicity of `ω^(-)` plus closure/principality of powers of `ω`.
