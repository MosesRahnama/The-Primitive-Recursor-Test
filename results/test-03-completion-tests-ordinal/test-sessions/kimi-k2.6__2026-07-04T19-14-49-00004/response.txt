**Notes on the remaining arithmetic obligations (the inner `sorry`s):**

* **`R_rec_succ`** – After expanding `mu (recDelta b s n)`, the critical inequality is  
  `2 + (mu n + mu s + 6) < mu (delta n) + mu s + 6`.  
  This follows from `mu (delta n) = omega^5 * (mu n + 1) + 1`, which is always strictly larger than `mu n + 2`, and the fact that adding the same `mu s + 6` to both sides preserves the gap (when `mu s + 6` is finite the ordering is obvious; when it is infinite the extra `+2` is absorbed on the left while `mu (delta n)` guarantees strict growth).

* **`R_eq_diff`** – The three inequalities `h3`, `h4`, `h5` are obtained by observing that:
  * `omega^7 * (mu a + 1) < omega^(mu a + 8) <= omega^(mu a + mu b + 9)`,
  * `omega^6 * (mu b + 1) < omega^(mu b + 7) <= omega^(mu a + mu b + 9)`,
  * `omega^4 * 2 < omega^5 <= omega^(mu a + mu b + 9)`.  
  The `principal_add_opow` lemma from `Mathlib.SetTheory.Ordinal.Principal` then lets you sum the three smaller terms while staying below the single large `omega^(mu a + mu b + 9)` term.

These blocks slot directly into the existing pattern and complete the `mu_decreases` theorem without changing any other part of the file.
