A completion of `mu_decreases` is not possible for the file as written: the `R_rec_succ` case is false for the proposed measure.

The issue is that the `mu s` summand can absorb the purportedly dominating
`omega0 ^ 5 * (mu n + 1)` term in the source exponent. Then the target’s
`omega0 ^ 2` multiplier produces a larger tail at the same leading
`omega`-power.

For example, instantiate the successor rule with

```lean
b := void
n := void
s := eqW void void
```

Writing `E := omega0 ^ (9 : Ordinal) + 7`, the relevant measures simplify
ordinal-arithmetically to:

```text
mu (recDelta void s (delta void))
  = omega0 ^ E + omega0 + 1

mu (app s (recDelta void s void))
  = omega0 ^ E + omega0 ^ 3 + omega0 ^ 2 * 2 + 1
```

The latter is strictly larger, not smaller.  In particular, the desired
goal for that rule,

```lean
mu (app s (recDelta b s n)) < mu (recDelta b s (delta n))
```

fails for those concrete terms.

The problematic simplifications are:

```text
mu s = omega^9 + 1

mu (delta void) + mu s + 6
  = (omega^5 + 1) + (omega^9 + 1) + 6
  = omega^9 + 7

mu void + mu s + 6
  = omega^9 + 7
```

so both recursive measures have the same leading term
`omega^(omega^9 + 7)`.  The application target then has the larger tail
coming from multiplication by `omega^2`.

The `R_eq_refl` case itself has the same simple positivity proof shape as
the already-completed `R_int_delta` case:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

The `R_eq_diff` case could only be pursued after the overall measure is
repaired, because even if that individual inequality is provable, the
theorem `mu_decreases` cannot be completed while `R_rec_succ` is a
counterexample.

A likely repair is to change the `recDelta` measure so that its exponent
uses a construction that dominates `mu s` in a way not erased by ordinal
addition—e.g. placing the `s` contribution before the counter contribution
in a suitably designed lexicographic/Cantor-normal-form measure, or using
a higher-level nested exponent for the counter.  Simply relying on

```text
omega^5 * (mu n + 1) + mu s
```

does not work, since a sufficiently large `mu s` absorbs the left summand.
