```lean
/-! ### Helper facts reused by several cases -/

/-- A finite ordinal is swallowed by any ordinal `≥ ω` when added on the left. -/
private lemma nat_add_absorb {n : ℕ} {c : Ordinal} (hc : omega0 ≤ c) :
    (n : Ordinal) + c = c := by
  have h1 : (n : Ordinal) < omega0 ^ (1 : Ordinal) := by
    simpa using (nat_lt_omega0 n)
  simpa using Ordinal.add_absorp h1 (by simpa using hc)

/-- `ω^e` is closed under addition of strictly smaller ordinals
    (this is exactly `Ordinal.principal_add_omega0_opow`, spelled out
    for readability). -/
private lemma opow_principal_add {e a b : Ordinal}
    (ha : a < omega0 ^ e) (hb : b < omega0 ^ e) : a + b < omega0 ^ e :=
  Ordinal.principal_add_omega0_opow e ha hb
```

### `R_eq_diff`

Goal (after `simp [mu]`, with `p := mu a`, `q := mu b`):

```
ω^4 * (ω^3*(p+1) + ω^2*(q+1) + 1 + 1) + 1  <  ω^(p+q+9) + 1
```

Strategy: (1) push `ω^4` inside using left‑distributivity and `opow_add` to turn the LHS into a sum of three terms with exponents `7`, `6`, `4`(times a finite coefficient); (2) show each term is `< ω^(p+q+9)`; (3) combine using `opow_principal_add` (twice); (4) cancel the trailing `+1` with `add_lt_add_right`.

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    set p := mu a with hp_def
    set q := mu b with hq_def
    -- Step 1: expand ω^4 * (…) via left-distributivity + opow_add (ω^4*ω^k = ω^(4+k))
    have expand :
        omega0 ^ (4:Ordinal) *
            (omega0 ^ (3:Ordinal) * (p+1) + omega0 ^ (2:Ordinal) * (q+1) + 1 + 1)
          = omega0 ^ (7:Ordinal) * (p+1) + omega0 ^ (6:Ordinal) * (q+1)
              + omega0 ^ (4:Ordinal) * 2 := by
      simp [mul_add, ← opow_add, show (4:Ordinal)+3 = 7 by norm_num,
            show (4:Ordinal)+2 = 6 by norm_num, two_mul]
      ring_nf  -- or a manual `add_assoc`/`add_comm`-free rewrite chain
    -- Step 2: each summand is dominated by ω^(p+q+9)
    have hp7 : omega0 ^ (7:Ordinal) * (p+1) < omega0 ^ (p+q+9) := by
      -- p+1 ≤ ω^(p+1) (normal function ≥ id), so ω^7*(p+1) ≤ ω^7*ω^(p+1) = ω^(p+8) < ω^(p+q+9)
      sorry
    have hq6 : omega0 ^ (6:Ordinal) * (q+1) < omega0 ^ (p+q+9) := by
      sorry
    have hc4 : omega0 ^ (4:Ordinal) * 2 < omega0 ^ (p+q+9) := by
      -- ω^4*2 = ω^4+ω^4 < ω^4*ω = ω^5 ≤ ω^(p+q+9)
      sorry
    have hsum :
        omega0 ^ (7:Ordinal) * (p+1) + omega0 ^ (6:Ordinal) * (q+1)
            + omega0 ^ (4:Ordinal) * 2 < omega0 ^ (p+q+9) :=
      opow_principal_add (opow_principal_add hp7 hq6) hc4
    calc
      omega0 ^ (4:Ordinal) *
            (omega0 ^ (3:Ordinal) * (p+1) + omega0 ^ (2:Ordinal) * (q+1) + 1 + 1) + 1
          = (omega0 ^ (7:Ordinal) * (p+1) + omega0 ^ (6:Ordinal) * (q+1)
               + omega0 ^ (4:Ordinal) * 2) + 1 := by rw [expand]
      _ < omega0 ^ (p+q+9) + 1 := add_lt_add_right hsum 1
```

The only genuinely open sub‑goals are `hp7`, `hq6`, `hc4`, which are all instances of the single fact "a finite multiple of a small `ω`‑power is dominated by `ω^(bigger exponent)`"; they can be closed with the `opow_add`/monotonicity toolkit already used in the proved cases (`le_mul_right`, `opow_le_opow_right`, plus the normal‑function fact `x ≤ ω^x`).

### `R_rec_succ`

Goal (with `x := mu n`, `y := mu s`, `z := mu b`, `D := mu (delta n) = ω^5*(x+1)+1`):

```
ω^3*(y+1) + ω^2*((ω^(x+y+6) + ω*(z+1)+1) + 1) + 1   <   ω^(D+y+6) + ω*(z+1) + 1
```

Key fact: `x < D`, hence `x+y+6 ≤ D+y+6` (addition is *monotone*, not necessarily strict, in its left argument), so we must split on whether the exponents actually coincide.

```lean
| _, _, Step.R_rec_succ b s n => by
    simp [mu]
    set x := mu n
    set y := mu s
    set z := mu b
    set D := omega0 ^ (5:Ordinal) * (x+1) + 1 with hD_def
    have hDx : x < D := by
      have h1 : x + 1 ≤ omega0 ^ (5:Ordinal) * (x+1) :=
        le_mul_right _ (opow_pos 5 omega0_pos)
      calc x < x + 1 := lt_add_one x
        _ ≤ omega0 ^ (5:Ordinal) * (x+1) := h1
        _ ≤ D := le_add_right _ _
    have hE : x + y + 6 ≤ D + y + 6 :=
      add_le_add_right (add_le_add_right hDx.le y) 6
    rcases hE.lt_or_eq with hlt | heq
    · -- Case A: exponent strictly increases.
      -- ω^(x+y+6) < ω^(D+y+6), which leaves enough room to absorb
      -- ω^3*(y+1), the ω^2-factor overhead, and ω*(z+1)+1 as well.
      sorry
    · -- Case B: exponents coincide (heq : x+y+6 = D+y+6).
      -- Here ω^(x+y+6) = ω^(D+y+6) exactly, so the strict decrease
      -- must come from the *other* summands:
      --   * ω^3*(y+1) < ω^(x+y+6)  (since y < y+6 ≤ x+y+6), so it is
      --     absorbed into ω^(D+y+6) via `opow_principal_add`/`add_absorp`;
      --   * the "×ω^2" overhead ω^2*ω^(x+y+6) = ω^(2+(x+y+6)); since
      --     x+y+6 ≥ ω (as D ≥ ω already forces D+y+6 ≥ ω, and heq gives
      --     x+y+6 ≥ ω too), `nat_add_absorb` gives 2+(x+y+6) = x+y+6,
      --     so this term also collapses back to ω^(D+y+6);
      --   * the leftover ω*(z+1)+2 on the reduct side is exactly matched
      --     (up to the same absorption) by ω*(z+1)+1 on the redex side,
      --     with the redex retaining a genuinely "outermost" +1 slot
      --     that the reduct's internal +1's cannot reach past the
      --     ω^(D+y+6) barrier.
      sorry
```

Both branches bottom out in the same three tools used above: `Ordinal.add_absorp` / `opow_principal_add` (to swallow strictly‑smaller summands into a dominant `ω`‑power), `nat_add_absorb` (to swallow the finite shifts `2`, `3` coming from the `ω^2`, `ω^3` multipliers into an already‑infinite exponent), and `opow_add`/monotonicity in the exponent (to compare `ω^(x+y+6)` against `ω^(D+y+6)` in Case A). Filling in the two `sorry`s is routine but tedious symbol‑pushing along exactly these lines.
