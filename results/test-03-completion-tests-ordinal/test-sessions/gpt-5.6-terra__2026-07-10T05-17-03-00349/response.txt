A completion proof cannot exist for the file as written: the `R_rec_succ` decrease claim is false for the given `mu`.

The easy remaining case has the following skeleton:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact add_pos_right _ one_pos
```

However, `R_rec_succ` supplies a counterexample to `mu_decreases`. Take

```text
b = void
n = void
s = recDelta void void void
```

Then:

```text
mu s = ω^6 + ω + 1
```

Let

```text
E = ω^6 + ω + 7.
```

For the source of the successor rule,

```text
A = recDelta void s (delta void)
```

we have

```text
mu (delta void) = ω^5 + 1

mu A
  = ω^( (ω^5 + 1) + (ω^6 + ω + 1) + 6 ) + ω + 1
  = ω^E + ω + 1.
```

For the target,

```text
B = app s (recDelta void s void)
```

the recursive subterm has measure

```text
mu (recDelta void s void) = ω^E + ω + 1.
```

Therefore:

```text
mu B
  = ω^3 * (mu s + 1)
    + ω^2 * (mu (recDelta void s void) + 1) + 1
  = ω^E + ω^3 + ω^2 * 2 + 1.
```

In particular,

```text
mu A = ω^E + ω + 1
     < ω^E + ω^3 + ω^2 * 2 + 1
     = mu B.
```

But `Step.R_rec_succ void s void` is a step from `A` to `B`, whereas `mu_decreases` requires `mu B < mu A`. Thus the required theorem is mathematically false in this case.

Consequently:

* `R_eq_refl` can be filled as above.
* There can be no valid Lean proof skeleton completing `R_rec_succ` without changing the measure, the rule, or adding an inconsistent axiom.
* Even if an ordinal-arithmetic skeleton can be developed for `R_eq_diff`, it cannot make the overall `mu_decreases` theorem true while the `R_rec_succ` branch remains as stated.

The underlying issue is that the source exponent

```text
mu (delta n) + mu s + 6
```

does not uniformly dominate the exponent used in the recursive result. When `mu s` begins with a sufficiently large limit term, the initial `mu (delta n)` contribution is absorbed by ordinal addition, and the `ω^2` multiplier in the `app` result makes the target larger rather than smaller.
