There is **no sound proof skeleton for all three holes as the file stands**, because the `R_rec_succ` case appears to be false for the stated `mu`.

The easy hole is `R_eq_refl`, and `R_eq_diff` can plausibly be handled by standard bounding lemmas for ordinal powers, but `R_rec_succ` has a real obstruction: the large `mu s` term can swallow the supposed advantage coming from `mu (delta n)` in the exponent.

## 1. Easy case: `eqW a a --> void`

This case should be essentially the same positivity argument as the already-proved `R_int_delta` case.

Skeleton:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact add_pos_right _ one_pos
```

If Lean does not accept that directly, use the style already present:

```lean
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

## 2. Obstruction in `R_rec_succ`

The desired inequality is:

```lean
mu (app s (recDelta b s n)) < mu (recDelta b s (delta n))
```

After unfolding:

```lean
omega0 ^ (3 : Ordinal) * (mu s + 1)
+ omega0 ^ (2 : Ordinal) * (mu (recDelta b s n) + 1)
+ 1
<
omega0 ^ (mu (delta n) + mu s + (6 : Ordinal))
+ omega0 * (mu b + 1)
+ 1
```

The intended argument is that `mu (delta n)` is huge, so

```lean
mu (delta n) + mu s + 6
```

should dominate

```lean
mu n + mu s + 6
```

but ordinal addition is not commutative. If `mu s` is large enough, then the initial summand `mu (delta n)` can be swallowed.

A concrete counterexample shape is:

```lean
b := void
n := void
s := delta (delta void)
```

Let

```lean
d := delta void
S := mu (delta d)
```

Then:

```lean
mu d = omega0 ^ (5 : Ordinal) + 1
S = omega0 ^ (5 : Ordinal) * (omega0 ^ (5 : Ordinal) + 2) + 1
```

So `S` has leading term `omega0 ^ 10`, and therefore

```lean
mu d + S = S
```

Hence the source measure becomes

```lean
mu (recDelta void s (delta void))
= omega0 ^ (S + 6) + omega0 + 1
```

But the recursive call has measure

```lean
mu (recDelta void s void)
= omega0 ^ (S + 6) + omega0 + 1
```

and therefore the target measure contains

```lean
omega0 ^ (2 : Ordinal) * (omega0 ^ (S + 6) + omega0 + 2)
```

whose leading term is still

```lean
omega0 ^ (S + 6)
```

with a larger tail, roughly

```lean
omega0 ^ (S + 6) + omega0 ^ 3 + ...
```

Thus the target measure is larger than

```lean
omega0 ^ (S + 6) + omega0 + 1
```

not smaller.

So the `R_rec_succ` hole cannot be completed without changing the measure, e.g. by using a non-swallowing combination such as natural/Hessenberg sum in the exponent, or by placing `mu s` before the counter contribution in a way that preserves the dominance.

## 3. Possible skeleton for `R_eq_diff`

This one should be attacked by factoring the proof into ordinal-bounding lemmas.

After `simp [mu]`, the goal is essentially:

```lean
omega0 ^ (4 : Ordinal) *
  (omega0 ^ (3 : Ordinal) * (mu a + 1)
   + omega0 ^ (2 : Ordinal) * (mu b + 1)
   + 1
   + 1)
+ 1
<
omega0 ^ (mu a + mu b + (9 : Ordinal)) + 1
```

A useful local lemma would be:

```lean
have hmerge :
    omega0 ^ (3 : Ordinal) * (mu a + 1)
    + omega0 ^ (2 : Ordinal) * (mu b + 1)
    + 1
    + 1
      < omega0 ^ (mu a + mu b + (5 : Ordinal)) := by
  -- Bound each summand below an omega-power with exponent < mu a + mu b + 5.
  -- Use:
  --   mu a + 1 ≤ omega0 ^ (mu a + 1)
  --   mu b + 1 ≤ omega0 ^ (mu b + 1)
  --   omega0^m * omega0^γ = omega0^(m + γ)
  --   finite-left-addition bounds such as
  --       3 + (mu a + 1) ≤ mu a + mu b + 5
  --       2 + (mu b + 1) ≤ mu a + mu b + 5
  --   and closure of an additively principal ordinal under addition below it.
  sorry
```

Then multiply by `omega0 ^ 4`:

```lean
have hmain :
    omega0 ^ (4 : Ordinal) *
      (omega0 ^ (3 : Ordinal) * (mu a + 1)
       + omega0 ^ (2 : Ordinal) * (mu b + 1)
       + 1
       + 1)
      < omega0 ^ (mu a + mu b + (9 : Ordinal)) := by
  calc
    omega0 ^ (4 : Ordinal) *
      (omega0 ^ (3 : Ordinal) * (mu a + 1)
       + omega0 ^ (2 : Ordinal) * (mu b + 1)
       + 1
       + 1)
        < omega0 ^ (4 : Ordinal) * omega0 ^ (mu a + mu b + (5 : Ordinal)) := by
          -- monotonicity of left multiplication by positive ordinal
          exact mul_lt_mul_left' hmerge (opow_pos _ omega0_pos)
    _ = omega0 ^ ((4 : Ordinal) + (mu a + mu b + (5 : Ordinal))) := by
          -- omega power law
          rw [← opow_add]
    _ ≤ omega0 ^ (mu a + mu b + (9 : Ordinal)) := by
          -- because 4 + (mu a + mu b + 5) ≤ mu a + mu b + 9
          apply opow_le_opow_right omega0_pos
          -- ordinal arithmetic normalization/bounding
          sorry
```

Finally:

```lean
exact add_lt_add_right hmain 1
```

or, if strict monotonicity of successor is needed:

```lean
exact succ_lt_succ hmain
```

depending on the available ordinal lemmas/names.

So the rough case body would be:

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]

    have hmerge :
        omega0 ^ (3 : Ordinal) * (mu a + 1)
        + omega0 ^ (2 : Ordinal) * (mu b + 1)
        + 1
        + 1
          < omega0 ^ (mu a + mu b + (5 : Ordinal)) := by
      -- prove by bounding the two merge summands below the additively
      -- principal ordinal omega^(mu a + mu b + 5)
      sorry

    have hmain :
        omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1)
           + omega0 ^ (2 : Ordinal) * (mu b + 1)
           + 1
           + 1)
          < omega0 ^ (mu a + mu b + (9 : Ordinal)) := by
      calc
        omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1)
           + omega0 ^ (2 : Ordinal) * (mu b + 1)
           + 1
           + 1)
            < omega0 ^ (4 : Ordinal) *
                omega0 ^ (mu a + mu b + (5 : Ordinal)) := by
              exact mul_lt_mul_left' hmerge (opow_pos _ omega0_pos)
        _ = omega0 ^ ((4 : Ordinal) + (mu a + mu b + (5 : Ordinal))) := by
              rw [← opow_add]
        _ ≤ omega0 ^ (mu a + mu b + (9 : Ordinal)) := by
              apply opow_le_opow_right omega0_pos
              -- ordinal arithmetic: 4 + (x + 5) ≤ x + 9
              sorry

    exact add_lt_add_right hmain 1
```

## Bottom line

- `R_eq_refl` is straightforward.
- `R_eq_diff` needs standard ordinal bounding lemmas.
- `R_rec_succ` cannot be completed for the current `mu`; the measure does not strictly decrease in that case. The proof requires changing the measure, most likely replacing ordinary ordinal addition in the `recDelta` exponent with a non-swallowing combination or otherwise ensuring the `delta n` contribution cannot be absorbed by `mu s`.
