## 2. `R_eq_diff`

The clean proof pattern is:

1. `simp [mu]`
2. set `A := mu a`, `B := mu b`
3. expand the outer multiplication by right-distributivity, so the left-hand side becomes a sum of 5 terms:
   - `ω^7 * (A+1)`
   - `ω^6 * (B+1)`
   - `ω^4`
   - `ω^4`
   - `1`
4. show each of those terms is `< ω^(A+B+9)`
5. combine them using that powers of `ω` are **additively principal**
6. finish by `lt_of_lt_of_lt ... (lt_add_one _)`

A good skeleton is:

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    let A := mu a
    let B := mu b

    -- Helper: powers of ω are additively principal.
    have hAdd {e α β : Ordinal}
        (hα : α < omega0 ^ e) (hβ : β < omega0 ^ e) :
        α + β < omega0 ^ e := by
      -- use the principal-ordinal lemma for `omega0 ^ e`
      -- exact ...
      sorry

    -- Expand `ω^4 * (...)`
    rw [Ordinal.mul_add, Ordinal.mul_add, Ordinal.mul_add,
        Ordinal.mul_one, Ordinal.mul_one]

    -- Standard bounds: every ordinal is below the next ω-power.
    have hA : A + 1 < omega0 ^ (A + 1) := by
      -- exact ...
      sorry
    have hB : B + 1 < omega0 ^ (B + 1) := by
      -- exact ...
      sorry

    have h7 :
        omega0 ^ (7 : Ordinal) * (A + 1) < omega0 ^ (A + B + 9) := by
      calc
        omega0 ^ (7 : Ordinal) * (A + 1)
            < omega0 ^ (7 : Ordinal) * omega0 ^ (A + 1) := by
              -- monotonicity of left multiplication by a positive ordinal
              -- exact ...
              sorry
        _ = omega0 ^ ((7 : Ordinal) + (A + 1)) := by
              -- use `opow_add` (or its symmetric rewrite)
              simp [Ordinal.opow_add]
        _ ≤ omega0 ^ (A + B + 9) := by
              -- monotonicity of `omega0 ^ ·`
              -- reduce to the ordinal inequality
              --   7 + (A + 1) ≤ A + B + 9
              -- which is a finite-offset inequality
              sorry

    have h6 :
        omega0 ^ (6 : Ordinal) * (B + 1) < omega0 ^ (A + B + 9) := by
      calc
        omega0 ^ (6 : Ordinal) * (B + 1)
            < omega0 ^ (6 : Ordinal) * omega0 ^ (B + 1) := by
              sorry
        _ = omega0 ^ ((6 : Ordinal) + (B + 1)) := by
              simp [Ordinal.opow_add]
        _ ≤ omega0 ^ (A + B + 9) := by
              -- finite-offset inequality:
              --   6 + (B + 1) ≤ A + B + 9
              sorry

    have h4 :
        omega0 ^ (4 : Ordinal) < omega0 ^ (A + B + 9) := by
      -- monotonicity of `ω^·`, since `4 < A + B + 9`
      sorry

    have h1 :
        (1 : Ordinal) < omega0 ^ (A + B + 9) := by
      -- because `A + B + 9` is positive
      sorry

    have hsum :
        omega0 ^ (7 : Ordinal) * (A + 1) +
          (omega0 ^ (6 : Ordinal) * (B + 1) +
            (omega0 ^ (4 : Ordinal) + (omega0 ^ (4 : Ordinal) + 1)))
          < omega0 ^ (A + B + 9) := by
      apply hAdd h7
      apply hAdd h6
      apply hAdd h4
      exact hAdd h4 h1

    exact lt_of_lt_of_lt hsum (lt_add_one _)
```

### What the omitted helper facts are

The missing pieces are all standard:

- monotonicity of multiplication in the right argument for a positive left factor
- monotonicity of `omega0 ^ ·`
- additive-principality of `omega0 ^ e`
- the standard fact `x + 1 < omega0 ^ (x + 1)`

So the structure above is the right one even if theorem names need adjustment.

## 3. `R_rec_succ`: I think this case is **not actually true** for the current `mu`

You commented:

> The key insight is that `omega^(omega^5 * (mu(n) + 1) + ...)` dominates all terms in the RHS.

That would be enough **if the recursive-call measure were controlled only by `mu n` and `mu s`**. But your
```lean
mu (recDelta b s n) =
  omega0 ^ (mu n + mu s + 6) + omega0 * (mu b + 1) + 1
```
still contains an unrestricted `mu b`, and then `app` multiplies that by `ω^2`.

That is the obstruction.

### Concrete shape of the failure

Take:
```lean
u := recDelta void void void
b := eqW u u
s := void
n := void
```

Then `mu b = ω^β + 1` for a very large infinite `β` (in fact `β = mu u + mu u + 9`), and `β` is much bigger than `ω^5 + 7`.

Now compute the two sides of the redex:

- source:
  ```lean
  mu (recDelta b void (delta void))
    = ω^(ω^5 + 7) + ω * (mu b + 1) + 1
    = ω^(ω^5 + 7) + ω * (ω^β + 2) + 1
    = ω^β + ω*2 + 1
  ```

- target:
  ```lean
  mu (app void (recDelta b void void))
    = ω^3 + ω^2 * (mu (recDelta b void void) + 1) + 1
    = ω^3 + ω^2 * (ω^β + ω*2 + 2) + 1
    = ω^β + ω^3*2 + ω^2*2 + 1
  ```

and
```lean
ω^β + ω*2 + 1 < ω^β + ω^3*2 + ω^2*2 + 1.
```

So the desired inequality for `R_rec_succ` goes the **wrong way** on such examples.

## So what to do with `R_rec_succ`?

If you keep the current `mu`, I would **not** try to script that case: the issue is not “missing lemmas”, it is the measure.

### The intended proof shape, after fixing the measure

If you strengthen the `recDelta` measure so the leading exponent also depends on `mu b` (or lower the rank of `app`), then the proof skeleton would be:

```lean
| _, _, Step.R_rec_succ b s n => by
    simp [mu]
    let N := mu n
    let S := mu s
    let B := mu b

    -- 1. Bound the app-side by a smaller power tower.
    have happ :
        mu (app s (recDelta b s n)) < omega0 ^ (N + S + B + 9) := by
      -- bound each summand under `ω^(N + S + B + 9)`
      ...

    -- 2. Show the exponent on the source side is strictly larger.
    have hexp :
        N + S + B + 9 <
          (omega0 ^ (5 : Ordinal) * (N + 1) + 1) + S + B + 6 := by
      -- because `N + 1 ≤ ω^5 * (N + 1)` and then add the rest on the right
      ...

    have hpow :
        omega0 ^ (N + S + B + 9) <
          omega0 ^ ((omega0 ^ (5 : Ordinal) * (N + 1) + 1) + S + B + 6) := by
      -- monotonicity of `ω^·`
      ...

    exact lt_of_lt_of_le (lt_of_lt_of_lt happ hpow) (le_add_right _ _)
```

That is the right architecture, but it needs a stronger `mu`.
