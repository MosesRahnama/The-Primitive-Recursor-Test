Below is a proof skeleton for the three `sorry` cases, staying within your file and style. I am not claiming these lemmas all typecheck verbatim; the goal is to give a Lean-shaped route to finish each case without changing definitions.

The main idea in all three missing cases is:

- reduce by `simp [mu]`
- prove a simpler strict inequality into the big leading term
- then finish by monotonicity of addition on the right (`le_add_right`, `lt_of_lt_of_le`, etc.)
- for the two “large exponent dominates” cases, isolate a lemma comparing exponents first

## 1. `R_rec_succ`

You want:

```lean
| _, _, Step.R_rec_succ b s n => by
  simp [mu]
```

After `simp [mu]`, the goal is essentially

```lean
omega0 ^ (3 : Ordinal) * (mu s + 1) +
    omega0 ^ (2 : Ordinal) *
      (omega0 ^ (mu n + mu s + 6) + omega0 * (mu b + 1) + 1 + 1) + 1
  <
omega0 ^ (omega0 ^ (5 : Ordinal) * (mu n + 1) + 1 + mu s + 6) +
    omega0 * (mu b + 1) + 1
```

A workable skeleton is to prove the left side is bounded by a single term below the leading `omega0 ^ (...)` on the right.

### Suggested structure

```lean
| _, _, Step.R_rec_succ b s n => by
    simp [mu]

    -- Name the important exponents
    let α : Ordinal := mu n + mu s + (6 : Ordinal)
    let β : Ordinal := omega0 ^ (5 : Ordinal) * (mu n + 1) + 1 + mu s + (6 : Ordinal)

    -- First show α < β. This is the key exponent comparison.
    have hαβ : α < β := by
      -- enough to dominate α by the huge initial segment omega^5 * (mu n + 1)
      -- skeleton:
      have h1 : mu n + mu s + (6 : Ordinal) < omega0 ^ (5 : Ordinal) * (mu n + 1) := by
        sorry
      -- then β = (omega^5 * (mu n + 1)) + (1 + mu s + 6), so use left monotonicity into a larger sum
      exact lt_of_lt_of_le h1 (by
        -- omega^5 * (mu n + 1) ≤ omega^5 * (mu n + 1) + 1 + mu s + 6
        exact le_add_right _ _)

    -- Therefore omega^α < omega^β.
    have hopow : omega0 ^ α < omega0 ^ β := by
      exact opow_lt_opow hαβ omega0_isNormal
      -- or whatever monotonicity lemma for ordinal exponentiation by omega is available

    -- Next, bound the app-measure by something below omega^β.
    -- The exact estimate can be rough.
    have hsmall1 :
        omega0 ^ (3 : Ordinal) * (mu s + 1) < omega0 ^ β := by
      -- enough because 3 < β, so any omega^3 * (...) is below omega^β
      sorry

    have hsmall2 :
        omega0 ^ (2 : Ordinal) *
          (omega0 ^ α + omega0 * (mu b + 1) + 1 + 1) < omega0 ^ β := by
      -- enough because the parenthesized term is still < omega^β,
      -- and multiplying by omega^2 is absorbed by the much bigger exponent β
      -- one natural substep is:
      have hrec : omega0 ^ α + omega0 * (mu b + 1) + 1 + 1 < omega0 ^ β := by
        -- since omega^α < omega^β and lower-order summands are absorbed
        sorry
      sorry

    -- Combine the two lower-order bounds into a bound for the full left side.
    have hleft :
        omega0 ^ (3 : Ordinal) * (mu s + 1) +
            omega0 ^ (2 : Ordinal) *
              (omega0 ^ α + omega0 * (mu b + 1) + 1 + 1) + 1
          < omega0 ^ β := by
      -- standard “sum of two terms below a principal ordinal is still below it”
      -- This is exactly where using that omega^β is additively principal helps.
      sorry

    -- Finish by embedding into the RHS with extra positive tail.
    exact lt_of_lt_of_le hleft (by
      exact le_add_right _ _)
```

### What lemmas you’ll likely need

The skeleton above relies on one or more of these standard ordinal facts from `Principal` / `Exponential`:

- monotonicity of `ω^x` in the exponent
- `omega0 ^ β` is additively principal
- if `x < omega0 ^ β` and `y < omega0 ^ β`, then `x + y < omega0 ^ β`
- low finite towers like `omega0 ^ 3 * ...` are `< omega0 ^ β` when `β` is much larger

If the exact library names are awkward, you can package them as local helper lemmas first, e.g.

```lean
have hprincipal : AddPrincipal (omega0 ^ β) := by
  ...
```

and then use the principal closure property to combine `hsmall1` and `hsmall2`.

## 2. `R_eq_refl`

This one is easy; it should mirror `R_int_delta`.

Current goal after `simp [mu]` is essentially:

```lean
0 < omega0 ^ (mu a + mu a + 9) + 1
```

A minimal skeleton:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

If `simp [mu]` leaves the goal literally as `0 < ... + 1`, the above should be enough.  
If needed, you can also write:

```lean
    have h : 0 < omega0 ^ (mu a + mu a + (9 : Ordinal)) + 1 := by
      exact add_pos_right _ one_pos
    simpa using h
```

So this case is the same positivity pattern as the first proved case.

## 3. `R_eq_diff`

After `simp [mu]`, the goal is morally:

```lean
omega0 ^ (4 : Ordinal) *
    (omega0 ^ (3 : Ordinal) * (mu a + 1) +
      omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1) + 1
  <
omega0 ^ (mu a + mu b + 9) + 1
```

Again, the plan is:

1. show the whole left side before `+1` is `< omega0 ^ (mu a + mu b + 9)`
2. then conclude by `lt_of_lt_of_le` into `... + 1`

### Suggested skeleton

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]

    let γ : Ordinal := mu a + mu b + (9 : Ordinal)

    -- First show each component inside the integrate/merge expansion is far below omega^γ.
    have hA : omega0 ^ (3 : Ordinal) * (mu a + 1) < omega0 ^ γ := by
      -- because 3 < γ, and gamma has the extra +9
      sorry

    have hB : omega0 ^ (2 : Ordinal) * (mu b + 1) < omega0 ^ γ := by
      sorry

    have hInner :
        omega0 ^ (3 : Ordinal) * (mu a + 1) +
          omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1
        < omega0 ^ γ := by
      -- additive-principal closure of omega^γ
      sorry

    -- Multiplying by omega^4 still stays below omega^γ, since γ is much larger than 4.
    have hMul :
        omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1) +
            omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1)
        < omega0 ^ γ := by
      sorry

    -- Final step: append the trailing +1 on both sides.
    have hFinal :
        omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1) +
            omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1) + 1
        < omega0 ^ γ + 1 := by
      -- one route: first hMul, then monotonicity under adding 1 on the right side,
      -- or use lt_of_lt_of_le directly
      exact lt_of_lt_of_le hMul (le_add_right _ _)

    simpa [γ] using hFinal
```

### Stronger alternative

A cleaner route is to prove a direct exponent comparison showing the entire left side is `< ω^(μ a + μ b + 9)` because its effective top exponent is only `4 + 3` (or `4 + 2`), while the right exponent is `μ a + μ b + 9`. In ordinal arithmetic terms:

- `μ(merge a b)` is headed by `ω^3`
- `μ(integrate (merge a b))` is headed by `ω^4 * μ(merge a b)`, so still below something like `ω^(7 + ...)`
- but `ω^(μ a + μ b + 9)` is much bigger

So another proof skeleton is:

```lean
    have hTop :
      omega0 ^ (4 : Ordinal) *
        (omega0 ^ (3 : Ordinal) * (mu a + 1) +
          omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1)
      < omega0 ^ (mu a + mu b + (9 : Ordinal)) := by
      -- prove by estimating the parenthesized term by omega^(mu a + mu b + 8)
      -- then omega^4 * that < omega^(mu a + mu b + 9)
      sorry
```

Then finish exactly as above.

## Practical advice on helper lemmas

If the arithmetic lemmas are hard to locate, the cleanest way to complete these cases is to insert local helper claims inside the proof blocks, rather than trying to do everything in one `calc`. For example:

```lean
have hpow_mono {α β : Ordinal} (h : α < β) : omega0 ^ α < omega0 ^ β := by
  ...
```

or

```lean
have hprincipal (β : Ordinal) : IsNormal (fun x => omega0 ^ x) := by
  ...
```

or

```lean
have h_add_closed {β x y : Ordinal}
    (hx : x < omega0 ^ β) (hy : y < omega0 ^ β) :
    x + y < omega0 ^ β := by
  ...
```

The three missing cases really only need:

- positivity of `... + 1`
- monotonicity of exponentiation by `omega0`
- that `omega0 ^ β` is additively principal / absorbs smaller sums
