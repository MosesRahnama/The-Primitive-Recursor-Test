The three `sorry`s cannot all be completed: the `R_rec_succ` inequality is false for the stated `mu`. Ordinal addition can erase the difference between `mu n` and `mu (delta n)` because the counter occurs to the left of `mu s` in the exponent.

## 1. `R_eq_refl`

This case is immediate from the final `+ 1`:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact add_pos_right _ one_pos
```

If simplification leaves a coercion or does not close the goal directly, the same style as the first case works:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

## 2. `R_eq_diff`

After `simp [mu]`, this can be organized around the following ordinal-arithmetic helper:

```lean
lemma eqDiffOrdinal (x y : Ordinal) :
    omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (x + 1) +
           omega0 ^ (2 : Ordinal) * (y + 1) + 1 + 1) + 1
      <
    omega0 ^ (x + y + 9) + 1 := by
  let γ := x + y

  -- First bound each parameter by an omega power whose exponent is
  -- at most γ + 1.
  have hx : x + 1 < omega0 ^ (γ + 1) := by
    -- x ≤ x + y, followed by x + 1 < ω^(x + 1) and monotonicity of opow
    ...

  have hy : y + 1 < omega0 ^ (γ + 1) := by
    -- y ≤ x + y, followed by the analogous argument
    ...

  -- Closure of ω^(γ+4) under the finite sum occurring in merge.
  have hmerge :
      omega0 ^ (3 : Ordinal) * (x + 1) +
          omega0 ^ (2 : Ordinal) * (y + 1) + 1 + 1
        < omega0 ^ (γ + 4) := by
    -- Use hx and hy, monotonicity of multiplication, the identities
    -- ω^m * ω^α = ω^(m + α), and additive principality of ω^(γ+4).
    ...

  have hint :
      omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (x + 1) +
           omega0 ^ (2 : Ordinal) * (y + 1) + 1 + 1)
        < omega0 ^ (γ + 9) := by
    -- From hmerge:
    --   ω^4 * (...) < ω^4 * ω^(γ+4)
    --               = ω^(4 + (γ+4))
    --               ≤ ω^(γ+8)
    --               < ω^(γ+9).
    ...

  -- Both sides are successors.
  exact succ_lt_succ hint
```

The rule case then becomes:

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    simpa using eqDiffOrdinal (mu a) (mu b)
```

The exact Mathlib lemma names needed in the helper will depend on how one chooses to express:

- `x ≤ x + y` and `y ≤ x + y`;
- monotonicity of `omega0 ^ ·`;
- `omega0 ^ α` being additively principal;
- `omega0 ^ m * omega0 ^ α = omega0 ^ (m + α)`;
- the finite-shift inequality `4 + (γ + 4) ≤ γ + 8`.

This is the substantive arithmetic lemma needed by the case.

## 3. `R_rec_succ` is not provable

Take

```lean
n := void
b := void
s := delta (delta void)
```

Write `ω` for `omega0` and `S := mu s`. Then

\[
\mu(\delta\,\mathsf{void})=\omega^5+1
\]

and

\[
S
 = \omega^5((\omega^5+1)+1)+1
 = \omega^{10}+\omega^5\cdot2+1.
\]

Consequently, the large leading part of `S` absorbs `mu (delta void)` on its left:

\[
(\omega^5+1)+S=S.
\]

Thus the source and recursive target subterm have the same principal exponent:

\[
E := S+6,
\]

because

\[
\mu(\delta\,\mathsf{void})+S+6=S+6
\]

and

\[
\mu(\mathsf{void})+S+6=S+6.
\]

For `b = void`, the source measure is therefore

\[
\mu(\operatorname{recDelta}\ \mathsf{void}\ s\ (\delta\,\mathsf{void}))
 = \omega^E+\omega+1.
\]

The recursive subterm has the same measure:

\[
\mu(\operatorname{recDelta}\ \mathsf{void}\ s\ \mathsf{void})
 = \omega^E+\omega+1.
\]

In the target application, its second component contributes

\[
\begin{aligned}
\omega^2\big((\omega^E+\omega+1)+1\big)
 &= \omega^2(\omega^E+\omega+2)\\
 &= \omega^E+\omega^3+\omega^2\cdot2.
\end{aligned}
\]

The first application component is absorbed before the leading `ω^E`, so the complete target measure is

\[
\omega^E+\omega^3+\omega^2\cdot2+1,
\]

which is strictly greater than the source measure

\[
\omega^E+\omega+1.
\]

Hence this instance satisfies

\[
\mu(\text{source}) < \mu(\text{target}),
\]

the opposite of the required inequality.

The failed intermediate statement in any attempted proof is essentially

```lean
mu n + mu s + 6 < mu (delta n) + mu s + 6
```

which does not follow from `mu n < mu (delta n)`: ordinal addition is not strictly monotone in its left argument.

## Necessary repair

A natural repair is to place `mu s` before the recursion counter:

```lean
| .recDelta b s n =>
    omega0 ^ (mu s + mu n + (6 : Ordinal))
    + omega0 * (mu b + 1) + 1
```

Then the relevant exponents are

```lean
mu s + mu n + 6
mu s + mu (delta n) + 6
```

and strict monotonicity in the right argument preserves the strict counter decrease. After such a repair, the `R_rec_succ` proof can be structured as:

```lean
have hn : mu n < mu (delta n) := by
  -- direct from the definition of mu
  ...

have hexp :
    mu s + mu n + 6 < mu s + mu (delta n) + 6 := by
  -- strict monotonicity in the right argument, then successor addition
  ...

have hrec :
    mu (recDelta b s n) <
      omega0 ^ (mu s + mu (delta n) + 6) := by
  -- Bound the recursive measure using hexp and opow monotonicity.
  ...

-- Bound both summands of the application by the source's leading
-- principal term, use additive principality, and finally account for +1.
...
```

Therefore the two equality cases admit the skeletons above, but completing all three cases requires changing the `recDelta` measure (or using a strictly monotone commutative operation such as an appropriate natural/Hessenberg sum in its exponent).
