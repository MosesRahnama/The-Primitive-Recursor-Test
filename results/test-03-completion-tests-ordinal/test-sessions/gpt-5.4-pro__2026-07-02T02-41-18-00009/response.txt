## 2. `R_eq_diff` has a standard “bound by a smaller principal power, then multiply once more” proof

I would structure it like this.  
The exact names for the principal-ordinal lemmas may vary a bit in your mathlib version, so I’m writing this as a proof skeleton rather than compiler-checked code.

```lean
-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    simp [mu]

    let E₁ : Ordinal := mu a + mu b + (5 : Ordinal)
    let E₂ : Ordinal := mu a + mu b + (9 : Ordinal)
    let K₁ : Ordinal := omega0 ^ E₁
    let K₂ : Ordinal := omega0 ^ E₂

    -- You want three reusable helper facts here:
    --   1. strict monotonicity / normality of e ↦ ω^e
    --   2. additive-principal closure of ω^E
    --   3. multiplicative-principal closure of ω^E
    have hωmono : StrictMono (fun e : Ordinal => omega0 ^ e) := by
      -- use the normality of `fun e => omega0 ^ e`
      sorry

    have hAdd₁ : ∀ {x y : Ordinal}, x < K₁ → y < K₁ → x + y < K₁ := by
      -- additive-principal closure of `omega0 ^ E₁`
      sorry

    have hMul₁ : ∀ {x y : Ordinal}, x < K₁ → y < K₁ → x * y < K₁ := by
      -- multiplicative-principal closure of `omega0 ^ E₁`
      sorry

    have hAdd₂ : ∀ {x y : Ordinal}, x < K₂ → y < K₂ → x + y < K₂ := by
      -- additive-principal closure of `omega0 ^ E₂`
      sorry

    have hMul₂ : ∀ {x y : Ordinal}, x < K₂ → y < K₂ → x * y < K₂ := by
      -- multiplicative-principal closure of `omega0 ^ E₂`
      sorry

    -- First show the two coefficients `(mu a + 1)` and `(mu b + 1)` are below K₁.
    have ha_lt_K₁ : mu a + 1 < K₁ := by
      calc
        mu a + 1 < omega0 ^ (mu a + 1) := by
          -- usually `simpa using self_lt_omega0_opow (mu a + 1)`
          sorry
        _ ≤ K₁ := by
          -- compare exponents: `mu a + 1 ≤ mu a + mu b + 5`
          -- use associativity and monotonicity of ordinal addition
          sorry

    have hb_lt_K₁ : mu b + 1 < K₁ := by
      calc
        mu b + 1 < omega0 ^ (mu b + 1) := by
          -- same lemma as above
          sorry
        _ ≤ K₁ := by
          -- compare exponents: `mu b + 1 ≤ mu a + mu b + 5`
          sorry

    -- Small fixed powers are also below K₁.
    have hω3_lt_K₁ : omega0 ^ (3 : Ordinal) < K₁ := by
      apply hωmono
      -- show `(3 : Ordinal) < E₁`
      sorry

    have hω2_lt_K₁ : omega0 ^ (2 : Ordinal) < K₁ := by
      apply hωmono
      -- show `(2 : Ordinal) < E₁`
      sorry

    have h1_lt_K₁ : (1 : Ordinal) < K₁ := by
      -- e.g. compare exponents `0 < E₁`
      sorry

    -- Hence each merge summand is below K₁.
    have hleft_lt_K₁ :
        omega0 ^ (3 : Ordinal) * (mu a + 1) < K₁ := by
      exact hMul₁ hω3_lt_K₁ ha_lt_K₁

    have hright_lt_K₁ :
        omega0 ^ (2 : Ordinal) * (mu b + 1) < K₁ := by
      exact hMul₁ hω2_lt_K₁ hb_lt_K₁

    -- Combine them additively:
    have hmerge_plus_one_lt_K₁ :
        omega0 ^ (3 : Ordinal) * (mu a + 1) +
          omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1 < K₁ := by
      have hsum :
          omega0 ^ (3 : Ordinal) * (mu a + 1) +
            omega0 ^ (2 : Ordinal) * (mu b + 1) < K₁ := by
        exact hAdd₁ hleft_lt_K₁ hright_lt_K₁
      have hsum1 :
          omega0 ^ (3 : Ordinal) * (mu a + 1) +
            omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 < K₁ := by
        exact hAdd₁ hsum h1_lt_K₁
      exact hAdd₁ hsum1 h1_lt_K₁

    -- Now move from K₁ = ω^(...+5) up to K₂ = ω^(...+9).
    have hK₁_lt_K₂ : K₁ < K₂ := by
      apply hωmono
      -- show `E₁ < E₂`, i.e. `mu a + mu b + 5 < mu a + mu b + 9`
      sorry

    have hinner_lt_K₂ :
        omega0 ^ (3 : Ordinal) * (mu a + 1) +
          omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1 < K₂ := by
      exact lt_trans hmerge_plus_one_lt_K₁ hK₁_lt_K₂

    have hω4_lt_K₂ : omega0 ^ (4 : Ordinal) < K₂ := by
      apply hωmono
      -- show `(4 : Ordinal) < E₂`
      sorry

    have hprod_lt_K₂ :
        omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1) +
            omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1) < K₂ := by
      exact hMul₂ hω4_lt_K₂ hinner_lt_K₂

    have h1_lt_K₂ : (1 : Ordinal) < K₂ := by
      sorry

    have htotal_lt_K₂ :
        omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1) +
            omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1) + 1 < K₂ := by
      exact hAdd₂ hprod_lt_K₂ h1_lt_K₂

    calc
      omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1) +
            omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1) + 1
          < K₂ := htotal_lt_K₂
      _ ≤ K₂ + 1 := le_add_right _ _
```

### What the missing subproofs are
The omitted `sorry`s are all of one of these forms:

- monotonicity of `e ↦ ω^e`
- `x < ω^x` for ordinals
- additive/multiplicative principal closure of `ω^E`
- easy exponent comparisons like `3 < mu a + mu b + 5`

So this case should be salvageable with the current `mu`.

## 3. `R_rec_succ` is different: the current measure looks wrong

I would **not** try to finish that `sorry` against the current definition of `mu` until you sanity-check the statement. The usual “bound the app side by the leading `ω^(...)` term” strategy only works if the `ω * (mu b + 1)` tail is already below that leading term, and here it need not be.

A concrete obstruction is:

- `n = void`
- `s = void`
- `b = eqW (delta void) (delta void)`

Let  
`γ := (mu (delta void)) + (mu (delta void)) + 9`, so `μ b = ω^γ + 1`, and `γ > ω^5 + 7`.

Then the source of `R_rec_succ` has measure
\[
\mu(\mathrm{recDelta}\ b\ \mathrm{void}\ (\delta\ \mathrm{void}))
= \omega^{\omega^5+7} + \omega(\mu b + 1) + 1
= \omega^\gamma + \omega\cdot 2 + 1,
\]
while the target has measure
\[
\mu(\mathrm{app}\ \mathrm{void}\ (\mathrm{recDelta}\ b\ \mathrm{void}\ \mathrm{void}))
= \omega^3 + \omega^2(\omega^\gamma + \omega\cdot 2 + 2) + 1
= \omega^\gamma + \omega^3\cdot 2 + \omega^2\cdot 2 + 1,
\]
which is **strictly larger**.

So this is not just “missing ordinal lemmas”; the current `mu` appears not to decrease on `R_rec_succ`.

### Practical consequence
- `R_eq_refl`: fill directly.
- `R_eq_diff`: fill with the principal-ordinal skeleton above.
- `R_rec_succ`: likely requires **changing `mu`**, not just proving harder lemmas.

A repaired `recDelta` measure usually has to make the `b` contribution part of the dominating term, e.g. by putting it into the exponent or into a much larger coefficient, so that the app-side `ω^2 * (...)` can’t overtake it.

If you want, I can also sketch a replacement `mu` for `recDelta` that should make the `R_rec_succ` proof go through cleanly.
