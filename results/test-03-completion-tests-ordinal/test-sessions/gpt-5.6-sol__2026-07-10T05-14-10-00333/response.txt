The three `sorry`s cannot all be completed: the `R_rec_succ` case is false for the given measure. Ordinal addition can absorb the counter contribution `mu (delta n)` when it occurs to the left of a sufficiently large `mu s`.

The `R_eq_refl` case itself is routine:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact add_pos_right _ one_pos
```

Equivalently, if simplification changes the displayed goal slightly:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    apply Ordinal.pos_iff_ne_zero.mpr
    exact ne_of_gt (add_pos_right _ one_pos)
```

## Counterexample to `R_rec_succ`

Take

```lean
b := void
n := void
s := recDelta void void void
```

Write `ω` for `omega0`. Then

\[
\mu(s)=\omega^6+\omega+1=:S
\]

and

\[
\mu(\delta\,n)=\omega^5+1=:D.
\]

Since the leading term of \(S\) is \(\omega^6\), ordinal addition absorbs \(D\):

\[
D+S=(\omega^5+1)+(\omega^6+\omega+1)
    =\omega^6+\omega+1
    =S.
\]

Let \(E=S+6\). The measure of the redex is therefore

\[
\begin{aligned}
\mu(\operatorname{recDelta}\;\mathrm{void}\;s\;(\delta\;\mathrm{void}))
 &=\omega^{D+S+6}+\omega+1\\
 &=\omega^E+\omega+1.
\end{aligned}
\]

But

\[
\mu(\operatorname{recDelta}\;\mathrm{void}\;s\;\mathrm{void})
 =\omega^{0+S+6}+\omega+1
 =\omega^E+\omega+1.
\]

Thus the recursive call has exactly the same measure as the redex. Its enclosing `app` has measure

\[
\omega^3(S+1)+
\omega^2(\omega^E+\omega+2)+1.
\]

Because \(2+E=E\),

\[
\omega^2(\omega^E+\omega+2)
 =\omega^E+\omega^3+\omega^2\cdot2.
\]

Also \(\omega^3(S+1)<\omega^E\), so its addition on the left is absorbed by \(\omega^E\). Consequently, the contractum has measure

\[
\omega^E+\omega^3+\omega^2\cdot2+1,
\]

which is strictly **greater** than

\[
\omega^E+\omega+1,
\]

the measure of the redex. Hence the required goal

```lean
mu (app s (recDelta b s n)) <
  mu (recDelta b s (delta n))
```

is false for these terms.

## `R_eq_diff`

This case appears compatible with the intended measure. A proof skeleton would normalize the left-hand side to

\[
\omega^7(\mu a+1)+
\omega^6(\mu b+1)+
\omega^4\cdot2+1
\]

and then use additive principality of

\[
\omega^{\mu a+\mu b+9}.
\]

In Lean-style pseudocode:

```lean
| _, _, Step.R_eq_diff a b => by
    simp only [mu]

    -- Normalize using:
    --   α * (β + γ) = α * β + α * γ
    --   ω^m * ω^n = ω^(m+n)
    --
    -- The left side becomes:
    --   ω^7 * (mu a + 1)
    --   + ω^6 * (mu b + 1)
    --   + ω^4 * 2 + 1

    have ha :
        omega0 ^ (7 : Ordinal) * (mu a + 1) <
          omega0 ^ (mu a + mu b + 9) := by
      -- First prove the standard bound
      --   ω^k * (x + 1) < ω^(x + k + 1),
      -- then compare exponents:
      --   mu a + 8 ≤ mu a + mu b + 9.
      ...

    have hb :
        omega0 ^ (6 : Ordinal) * (mu b + 1) <
          omega0 ^ (mu a + mu b + 9) := by
      -- Use
      --   ω^6 * (mu b + 1) < ω^(mu b + 7)
      -- and
      --   mu b + 7 ≤ mu a + mu b + 9.
      ...

    have hc :
        omega0 ^ (4 : Ordinal) * 2 + 1 <
          omega0 ^ (mu a + mu b + 9) := by
      -- The exponent on the right is at least 9.
      ...

    have hp :
        AddPrincipal (omega0 ^ (mu a + mu b + 9)) := by
      -- Apply the Mathlib theorem saying positive omega powers
      -- are additively principal.
      ...

    -- Use hp repeatedly: a finite sum of ordinals strictly below
    -- an additively principal ordinal is still strictly below it.
    ...
```

Finally, append `+ 1` on both sides using strict monotonicity of right addition.

However, filling `R_eq_diff` and `R_eq_refl` does not rescue `mu_decreases`; the `R_rec_succ` counterexample prevents any proof of the theorem as stated. The measure must be changed—most directly by arranging the recursion exponent so that the counter occurs on the right of `mu s`, for example using an exponent based on

```lean
mu s + mu n + 6
```

or by using a commutative/natural ordinal sum that cannot erase the counter contribution.
