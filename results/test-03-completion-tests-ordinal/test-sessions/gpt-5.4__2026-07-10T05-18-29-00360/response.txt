## General proof pattern

For the hard cases, the clean approach is:

1. `simp [mu]`
2. prove a bound of the form
   - left side `< ω ^ E`
   - and `ω ^ E ≤ right side`
3. conclude by transitivity.

The useful meta-facts are:

- positivity:
  - `opow_pos _ omega0_pos`
  - `one_pos`
  - `Ordinal.pos_iff_ne_zero`
- monotonicity of addition/multiplication:
  - `le_add_right`, `le_add_left`
  - `lt_of_lt_of_le`, `lt_of_le_of_lt`
  - `mul_le_mul_left'` / analogous ordinal monotonicity lemmas if available
- monotonicity of exponentiation in the exponent:
  - if `e₁ < e₂`, then `omega0 ^ e₁ < omega0 ^ e₂`
- standard simplifications:
  - `simp [mu]`
  - `norm_num` may help for finite ordinal arithmetic
- for successor-on-the-right:
  - from `x < y`, infer `x + 1 ≤ y` or `x + 1 < y` only with care; usually better to show `x + 1 ≤ ω^E` via positivity/absorption rather than generic successor lemmas.

# 1. `R_eq_refl`

This one is easiest. After `simp [mu]`, the goal is just:

```lean
0 < omega0 ^ (mu a + mu a + (9 : Ordinal)) + 1
```

A minimal proof skeleton is:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

If `simp` leaves it as `<` instead of `≠ 0`, you can also do:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact add_pos_right _ one_pos
```

depending on what the simplifier produces.

# 2. `R_eq_diff`

## Goal after simplification

After `simp [mu]`, the goal should be essentially:

```lean
omega0 ^ (4 : Ordinal) *
    (omega0 ^ (3 : Ordinal) * (mu a + 1) +
      omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1) + 1
  < omega0 ^ (mu a + mu b + (9 : Ordinal)) + 1
```

The intended argument is:

- bound the inner merge measure by `ω^(mu a + mu b + 5)` or any exponent strictly below `mu a + mu b + 9`
- then multiplying by `ω^4` gives something below `ω^(mu a + mu b + 9)`
- then the final `+ 1` still stays below `ω^(mu a + mu b + 9) + 1`

A practical skeleton is to isolate two local lemmas:

### Step A: show the exponent on the RHS is large

You want a finite lower bound like:

```lean
have hExpPos : (5 : Ordinal) ≤ mu a + mu b + (9 : Ordinal) := by
  -- enough that 9 ≤ mu a + mu b + 9
  exact le_trans (by norm_num) (by
    -- show 9 ≤ mu a + mu b + 9
    simpa [add_assoc] using le_add_left ((mu a + mu b) : Ordinal) (9 : Ordinal))
```

But more useful is a decomposition showing
`4 + 3 < mu a + mu b + 9`, i.e. `7 < ...`.

### Step B: compare the left principal term to a smaller omega-power

A robust pattern is:

```lean
have hA : mu a + 1 ≤ omega0 ^ (mu a + 1) := by
  -- derive from positivity of omega-powers
  -- or first show mu a + 1 ≤ omega0 * (mu a + 1), then ≤ omega0 ^ (mu a + 1)
  sorry

have hB : mu b + 1 ≤ omega0 ^ (mu b + 1) := by
  sorry
```

Then obtain:

```lean
have hMergeBound :
    omega0 ^ (3 : Ordinal) * (mu a + 1) +
      omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1
    < omega0 ^ (mu a + mu b + (5 : Ordinal)) := by
  -- replace each coefficient by a suitable omega-power
  -- use identities like ω^3 * ω^(μa+1) = ω^(μa+4)
  -- and ω^2 * ω^(μb+1) = ω^(μb+3)
  -- then both summands are dominated by ω^(μa+μb+5)
  sorry
```

Once you have that, use monotonicity of left multiplication by `ω^4`:

```lean
have hMul :
    omega0 ^ (4 : Ordinal) *
      (omega0 ^ (3 : Ordinal) * (mu a + 1) +
        omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1)
    < omega0 ^ (mu a + mu b + (9 : Ordinal)) := by
  -- from hMergeBound and ordinal arithmetic:
  -- ω^4 * x < ω^4 * ω^(μa+μb+5) = ω^(μa+μb+9)
  sorry
```

Then conclude:

```lean
have hMain :
    omega0 ^ (4 : Ordinal) *
      (omega0 ^ (3 : Ordinal) * (mu a + 1) +
        omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1) + 1
    < omega0 ^ (mu a + mu b + (9 : Ordinal)) + 1 := by
  exact add_lt_add_right hMul 1
```

So the full case skeleton becomes:

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    have hMergeBound :
        omega0 ^ (3 : Ordinal) * (mu a + 1) +
          omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1
        < omega0 ^ (mu a + mu b + (5 : Ordinal)) := by
      sorry
    have hMul :
        omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1) +
            omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1)
        < omega0 ^ (mu a + mu b + (9 : Ordinal)) := by
      -- use hMergeBound and ω^4 * ω^(...) = ω^(4 + ...)
      sorry
    exact add_lt_add_right hMul 1
```

If `add_lt_add_right` is not the exact lemma name for ordinals, the fallback is a `calc` chain with `le_add_right` / strict monotonicity of `fun x => x + 1`.

# 3. `R_rec_succ`

This is the hardest case, and the comments in the file currently reverse “LHS/RHS”; the actual goal after `simp [mu]` is:

```lean
omega0 ^ (3 : Ordinal) * (mu s + 1) +
    omega0 ^ (2 : Ordinal) *
      (omega0 ^ (mu n + mu s + (6 : Ordinal)) + omega0 * (mu b + 1) + 1 + 1) + 1
  <
omega0 ^ (mu (delta n) + mu s + (6 : Ordinal)) + omega0 * (mu b + 1) + 1
```

and `mu (delta n) = omega0^5 * (mu n + 1) + 1`.

The conceptual route is:

- Let
  ```lean
  Esmall := mu n + mu s + 6
  Ebig   := mu (delta n) + mu s + 6
  ```
- Show `Esmall + 2 < Ebig` (or any enough margin to absorb the left-hand `ω^3`, `ω^2`, and lower-order terms).
- Then show the whole `app` measure is `< ω ^ Ebig`.
- Finally `ω ^ Ebig ≤ ω ^ Ebig + ω * (mu b + 1) + 1`, so done.

A good skeleton:

```lean
| _, _, Step.R_rec_succ b s n => by
    simp [mu]
    let Esmall : Ordinal := mu n + mu s + (6 : Ordinal)
    let Ebig   : Ordinal := omega0 ^ (5 : Ordinal) * (mu n + 1) + 1 + mu s + (6 : Ordinal)

    have hExp :
        Esmall < Ebig := by
      -- because mu n < ω^5 * (mu n + 1), hence
      -- mu n + mu s + 6 < ω^5 * (mu n + 1) + 1 + mu s + 6
      sorry

    have hRecSmall :
        omega0 ^ Esmall + omega0 * (mu b + 1) + 1 + 1
        < omega0 ^ Ebig := by
      -- principal term ω^Esmall is strictly below ω^Ebig,
      -- and the lower-order tail is still absorbed by ω^Ebig
      sorry

    have hSecond :
        omega0 ^ (2 : Ordinal) *
          (omega0 ^ Esmall + omega0 * (mu b + 1) + 1 + 1)
        < omega0 ^ Ebig := by
      -- from hRecSmall, or directly:
      -- ω^2 * (...) is still below ω^Ebig because Ebig is enormously larger than Esmall
      sorry

    have hFirst :
        omega0 ^ (3 : Ordinal) * (mu s + 1) < omega0 ^ Ebig := by
      -- same idea: μ s + 1 is tiny compared with ω^Ebig
      sorry

    have hSum :
        omega0 ^ (3 : Ordinal) * (mu s + 1) +
          omega0 ^ (2 : Ordinal) * (omega0 ^ Esmall + omega0 * (mu b + 1) + 1 + 1)
        < omega0 ^ Ebig := by
      -- sum of two terms both < ω^Ebig is still < ω^Ebig
      -- because ω^Ebig is additively principal
      sorry

    calc
      omega0 ^ (3 : Ordinal) * (mu s + 1) +
          omega0 ^ (2 : Ordinal) * (omega0 ^ Esmall + omega0 * (mu b + 1) + 1 + 1) + 1
          < omega0 ^ Ebig + 1 := by
              -- use hSum, then add 1 on the right
              sorry
      _ ≤ omega0 ^ Ebig + (omega0 * (mu b + 1) + 1) := by
              -- positivity of omega * (mu b + 1)
              exact le_add_right _ _
      _ = omega0 ^ Ebig + omega0 * (mu b + 1) + 1 := by
              rw [add_assoc]
```

## What to prove inside the `sorry`s

### `hExp`

This should come from the fact that
`mu n < omega0 ^ 5 * (mu n + 1) + 1`.

A useful mini-derivation:

```lean
have hn1 : mu n < mu n + 1 := lt_add_one (mu n)
have hn2 : mu n + 1 ≤ omega0 ^ (5 : Ordinal) * (mu n + 1) :=
  le_mul_right _ (opow_pos 5 omega0_pos)
have hn3 : mu n < omega0 ^ (5 : Ordinal) * (mu n + 1) := lt_of_lt_of_le hn1 hn2
have hn4 : mu n + mu s + (6 : Ordinal)
    < omega0 ^ (5 : Ordinal) * (mu n + 1) + mu s + (6 : Ordinal) := by
  -- monotonicity of addition on the right
  sorry
have hExp : Esmall < Ebig := by
  -- insert the `+1`
  exact lt_of_lt_of_le hn4 (by
    -- ω^5 * (...) + μs + 6 ≤ ω^5 * (...) + 1 + μs + 6
    sorry)
```

### `hRecSmall`

Use exponent monotonicity:
`omega0 ^ Esmall < omega0 ^ Ebig`.

Then absorb the tail `omega0 * (mu b + 1) + 1 + 1` below the same principal term. Since `ω^Ebig` is additively principal, it suffices to know the whole left ordinal has leading term `< ω^Ebig`.

A common skeleton:

```lean
have hpow : omega0 ^ Esmall < omega0 ^ Ebig := by
  exact opow_lt_opow_right omega0 hExp   -- lemma name may vary

-- then package the lower-order terms
have htail :
    omega0 * (mu b + 1) + 1 + 1 < omega0 ^ Ebig := by
  -- because Ebig is at least 7, so ω^Ebig dominates ω * (...)
  sorry

-- additive-principal absorption:
have hRecSmall :
    omega0 ^ Esmall + omega0 * (mu b + 1) + 1 + 1 < omega0 ^ Ebig := by
  sorry
```

The exact additive-principal lemma name may be something like:
- `add_lt_of_lt_of_le`
- or a theorem that if `a < ω^E` and `b < ω^E` then `a + b < ω^E` for positive principal powers.

If you can’t find that theorem, a workaround skeleton is to prove a stronger bound:
`omega0 ^ Esmall + omega0 * (mu b + 1) + 1 + 1 ≤ omega0 ^ (Esmall + 1)`,
then show `Esmall + 1 < Ebig`.

### `hSecond`

This is easiest if you first strengthen `hRecSmall` to
```lean
omega0 ^ Esmall + omega0 * (mu b + 1) + 1 + 1 ≤ omega0 ^ (Esmall + 1)
```
Then:
```lean
omega0 ^ 2 * (...) ≤ omega0 ^ 2 * omega0 ^ (Esmall + 1) = omega0 ^ (Esmall + 3)
```
and prove
`Esmall + 3 < Ebig`.

So a more proof-engine-friendly skeleton is:

```lean
have hInnerLe :
    omega0 ^ Esmall + omega0 * (mu b + 1) + 1 + 1 ≤ omega0 ^ (Esmall + 1) := by
  sorry

have hEsmall3 : Esmall + (3 : Ordinal) < Ebig := by
  sorry

have hSecond :
    omega0 ^ (2 : Ordinal) *
      (omega0 ^ Esmall + omega0 * (mu b + 1) + 1 + 1)
      < omega0 ^ Ebig := by
  have hle :
      omega0 ^ (2 : Ordinal) *
        (omega0 ^ Esmall + omega0 * (mu b + 1) + 1 + 1)
      ≤ omega0 ^ (2 : Ordinal) * omega0 ^ (Esmall + 1) := by
    exact mul_le_mul_left' hInnerLe _
  -- rewrite RHS as ω^(Esmall+3), then compare exponents using hEsmall3
  sorry
```

### `hFirst`

Similarly, show
```lean
omega0 ^ 3 * (mu s + 1) ≤ omega0 ^ (mu s + 4)
```
and then
```lean
mu s + 4 < Ebig
```
because `Ebig` contains `omega0^5 * (mu n + 1) + 1 + mu s + 6`.

So:

```lean
have hs1 : mu s + 1 ≤ omega0 ^ (mu s + 1) := by
  sorry
have hFirstLe : omega0 ^ (3 : Ordinal) * (mu s + 1) ≤ omega0 ^ (mu s + (4 : Ordinal)) := by
  sorry
have hsExp : mu s + (4 : Ordinal) < Ebig := by
  sorry
have hFirst : omega0 ^ (3 : Ordinal) * (mu s + 1) < omega0 ^ Ebig := by
  exact lt_of_le_of_lt hFirstLe (by
    -- exponent monotonicity from hsExp
    sorry)
```

## Final practical advice

The two hard cases are really about finding the right intermediate inequalities. In Lean, the most robust route is often:

- prove **coarse upper bounds** on complicated expressions by a single power `ω^K`
- compare exponents `K < K'`
- use monotonicity of `ω^(-)`.

So for both `R_rec_succ` and `R_eq_diff`, it may be easier to first establish auxiliary lemmas on paper like:

```lean
lemma mu_merge_lt_pow (a b) :
  mu (merge a b) + 1 < omega0 ^ (mu a + mu b + 5) := ...

lemma mu_app_rec_lt_pow (b s n) :
  mu (app s (recDelta b s n)) < omega0 ^ (mu (delta n) + mu s + 6) := ...
```

and then use them inline as local `have`s. You said not to modify the file, so I’m not suggesting adding top-level lemmas, only structuring the local proof that way.
