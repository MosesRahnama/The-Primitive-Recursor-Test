Here is a proof skeleton for the three remaining cases, keeping the existing definition of `mu_decreases` and its pattern-matching style.  Each `sorry` is left at the point where a purely ordinal-arithmetic inequality remains to be verified.

```tactics
-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    simp [mu]
    -- mu(void) = 0 < omega^(mu a + mu a + 9) + 1
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)

-- recDelta b s (delta n) --> app s (recDelta b s n)
| _, _, Step.R_rec_succ b s n => by
    simp [mu]
    -- Step 1: bound the recursive sub-term by a slightly larger tower
    have h_rec : mu (recDelta b s n) + 1 < omega0 ^ (mu n + mu s + (7 : Ordinal)) := by
      -- Unfold mu(recDelta) and observe that its leading summand
      -- omega^(mu n + mu s + 6) already dominates the rest.
      sorry
    -- Step 2: bound the LHS app-term (without the final +1)
    have h_lhs : omega0 ^ (3 : Ordinal) * (mu s + 1) + omega0 ^ (2 : Ordinal) * (mu (recDelta b s n) + 1)
        < omega0 ^ (mu n + mu s + (9 : Ordinal)) := by
      -- The first summand is < omega^(mu n + mu s + 9) because 3 < mu n + mu s + 9.
      -- The second summand is < omega^2 * omega^(mu n + mu s + 7) = omega^(mu n + mu s + 9)
      -- by h_rec.  Their sum is below the additively-principal ordinal omega^(mu n + mu s + 9).
      sorry
    -- Step 3: the RHS tower is vastly larger because mu(delta n) introduces omega^5*(mu n+1)
    have h_rhs : omega0 ^ (mu n + mu s + (9 : Ordinal))
        < omega0 ^ (mu (delta n) + mu s + (6 : Ordinal)) := by
      -- mu(delta n) = omega^5*(mu n+1)+1, so the RHS exponent is
      -- omega^5*(mu n+1) + mu s + 7, which dominates mu n + mu s + 9.
      sorry
    calc mu (app s (recDelta b s n))
        = omega0 ^ (3 : Ordinal) * (mu s + 1) + omega0 ^ (2 : Ordinal) * (mu (recDelta b s n) + 1) + 1 := by rfl
      _ < omega0 ^ (mu (delta n) + mu s + (6 : Ordinal)) + 1 := by
          have h4 : omega0 ^ (3 : Ordinal) * (mu s + 1) + omega0 ^ (2 : Ordinal) * (mu (recDelta b s n) + 1)
              < omega0 ^ (mu (delta n) + mu s + (6 : Ordinal)) := lt_trans h_lhs h_rhs
          have h5 : omega0 ^ (3 : Ordinal) * (mu s + 1) + omega0 ^ (2 : Ordinal) * (mu (recDelta b s n) + 1) + 1
              <= omega0 ^ (mu (delta n) + mu s + (6 : Ordinal)) := Ordinal.succ_le_of_lt h4
          exact lt_of_le_of_lt h5 (lt_add_one _)
      _ < omega0 ^ (mu (delta n) + mu s + (6 : Ordinal)) + omega0 * (mu b + 1) := by
          have h_one_lt : 1 < omega0 * (mu b + 1) := by
            -- omega0 * (mu b + 1) >= omega0 > 1
            sorry
          apply add_lt_add_left
          exact h_one_lt
      _ < omega0 ^ (mu (delta n) + mu s + (6 : Ordinal)) + omega0 * (mu b + 1) + 1 := by
          exact lt_add_one _

-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    -- It suffices to show the main product decreases; the trailing +1s then lift the inequality.
    have h : omega0 ^ (4 : Ordinal) * (mu (merge a b) + 1) < omega0 ^ (mu a + mu b + (9 : Ordinal)) := by
      -- Expand mu(merge a b).  Using left-distributivity of ordinal
      -- multiplication and monotonicity of opow, every summand that
      -- appears inside the omega^4 factor is bounded by
      -- omega^(mu a + mu b + 5).  Multiplying by omega^4 yields
      -- omega^(mu a + mu b + 9), which is additively principal and
      -- therefore dominates the whole left-hand side.
      sorry
    calc mu (integrate (merge a b))
        = omega0 ^ (4 : Ordinal) * (mu (merge a b) + 1) + 1 := by rfl
      _ < omega0 ^ (mu a + mu b + (9 : Ordinal)) + 1 := by
          have h2 : omega0 ^ (4 : Ordinal) * (mu (merge a b) + 1) + 1
              <= omega0 ^ (mu a + mu b + (9 : Ordinal)) := Ordinal.succ_le_of_lt h
          exact lt_of_le_of_lt h2 (lt_add_one _)
      _ = mu (eqW a b) := by rfl
```

**Key proof obligations to discharge at each `sorry`:**

1. **`R_eq_refl`** – No further work; the positivity of `omega0 ^ … + 1` follows immediately from `add_pos_right` and `one_pos`.

2. **`R_rec_succ`** – Three arithmetic gaps:
   * `h_rec`: Show `mu(recDelta b s n) + 1 < omega^(mu n + mu s + 7)`.  After unfolding `mu(recDelta)` the right-hand side exceeds the sum `omega^(mu n + mu s + 6) + omega*(mu b + 1) + 2`.
   * `h_lhs`: Use `h_rec` together with `omega^3*(mu s + 1) < omega^(mu n + mu s + 9)` to bound the full sum of the two LHS summands.
   * `h_rhs`: Reduce to `mu n + 9 < omega^5*(mu n + 1) + 7`, which holds because `omega^5*(mu n + 1)` dominates `mu n` for every ordinal `mu n`.
   * The final assembly only uses `succ_le_of_lt`, `lt_add_one`, and the fact that `1 < omega0 * (mu b + 1)`.

3. **`R_eq_diff`** – One arithmetic gap:
   * `h`: After expanding `mu(merge a b) = omega^3*(mu a+1) + omega^2*(mu b+1) + 1`, multiply by `omega^4` on the left.  By left-distributivity this yields a sum of terms each bounded by `omega^(mu a + mu b + 9)`.  Since `mu a + mu b + 9 > 0`, the ordinal `omega^(mu a + mu b + 9)` is additively principal, hence strictly larger than the whole sum.
