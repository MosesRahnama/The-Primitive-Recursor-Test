A complete proof cannot be supplied for the file as written, because the `R_rec_succ` decrease statement is false for the given `mu`.

The issue is that the intended dominating term

```lean
omega0 ^ (5 : Ordinal) * (mu n + 1)
```

occurs to the *left* of `mu s` in

```lean
mu (delta n) + mu s + 6
```

and can therefore be swallowed by a sufficiently large `mu s`.

For example, take

```lean
b = void
n = void
s = delta (delta void)
```

and write `ω` for `omega0`. Then

```text
mu s = ω^10 + ω^5 * 2 + 1
E    = mu s + 6 = ω^10 + ω^5 * 2 + 7.
```

The source of the recursive-success rule has measure

```text
mu (recDelta void s (delta void))
  = ω^E + ω + 1.
```

Indeed, the earlier `ω^5 + 1` coming from `mu (delta void)` is absorbed on addition with `mu s`.

But the target has measure

```text
mu (app s (recDelta void s void))
  = ω^3 * (mu s + 1) + ω^2 * (ω^E + ω + 2) + 1
  = ω^E + ω^3 + ω^2 * 2 + 1.
```

Here `ω^2 * ω^E = ω^(2 + E) = ω^E`, since `2 + E = E`. Consequently,

```text
mu (recDelta void s (delta void))
  < mu (app s (recDelta void s void)),
```

which is the opposite of the required conclusion for `Step.R_rec_succ`.

Thus this branch cannot be filled without changing the measure, the rule, or the theorem statement.

The `R_eq_refl` branch itself does have the same simple positivity proof shape as `R_int_delta`:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

For the `R_eq_diff` branch, assuming the recursive case and measure were repaired independently, the proof skeleton would be:

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    have hmain :
        omega0 ^ (4 : Ordinal) *
            (omega0 ^ (3 : Ordinal) * (mu a + 1) +
              omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1) + 1
          < omega0 ^ (mu a + mu b + (9 : Ordinal)) := by
      -- Establish a Cantor-normal-form / ordinal-exponent bound:
      --
      -- 1. Bound the merge expression by an ordinal whose leading
      --    omega-exponent is below `mu a + mu b + 9`.
      --
      -- 2. Use multiplication by omega^4 to increase that leading
      --    finite exponent by at most 4.
      --
      -- 3. Use strict monotonicity of `omega0 ^ ·`.
      sorry
    exact lt_of_lt_of_le hmain (le_add_right _ _)
```

However, even if that `R_eq_diff` ordinal-arithmetic subproof is completed, `mu_decreases` and hence `strong_normalization` remain unprovable because of the concrete `R_rec_succ` counterexample above.
