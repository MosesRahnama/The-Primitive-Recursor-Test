## 1. Easy completion: `eqW a a --> void`

This case should be essentially the same positivity argument as the `integrate (delta t)` case.

```lean
-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact add_pos_right _ one_pos
```

If Lean does not accept that directly because of the exact shape after `simp`, the following variant mirrors your existing proof style:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

## 2. Skeleton for `eq_diff`

The `eq_diff` case is plausibly true with the intended ordinal estimates. I would factor out the ordinal arithmetic into a helper lemma.

You want a helper of approximately this form:

```lean
private lemma eq_diff_core (A B : Ordinal) :
    omega0 ^ (4 : Ordinal) *
        (omega0 ^ (3 : Ordinal) * (A + 1)
         + omega0 ^ (2 : Ordinal) * (B + 1)
         + 1 + 1) + 1
      < omega0 ^ (A + B + (9 : Ordinal)) := by
  -- Skeleton:
  --
  -- 1. Show the merge payload is bounded by a smaller omega-power:
  --
  --    h_merge :
  --      omega0^3 * (A+1) + omega0^2 * (B+1) + 1 + 1
  --        < omega0 ^ (A + B + 4)
  --
  --    This uses:
  --      omega0^3 * (A+1) < omega0^(A+B+4)
  --      omega0^2 * (B+1) < omega0^(A+B+4)
  --      1 < omega0^(A+B+4)
  --    and additive-principality of omega powers.
  --
  -- 2. Multiply the bound by omega0^4:
  --
  --      omega0^4 * (...) < omega0 ^ (4 + (A+B+4))
  --
  -- 3. Bound the exponent:
  --
  --      4 + (A+B+4) ≤ A+B+8 < A+B+9
  --
  -- 4. Use monotonicity of omega-exponentiation.
  --
  -- 5. Absorb the final `+ 1`, since
  --
  --      omega0^(A+B+8) + 1 < omega0^(A+B+9).
  --
  sorry
```

Then the rule case becomes a short invocation:

```lean
-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    calc
      omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1)
           + omega0 ^ (2 : Ordinal) * (mu b + 1)
           + 1 + 1) + 1
          < omega0 ^ (mu a + mu b + (9 : Ordinal)) :=
            eq_diff_core (mu a) (mu b)
      _ ≤ omega0 ^ (mu a + mu b + (9 : Ordinal)) + 1 :=
            le_add_right _ _
```

The actual helper proof will likely need Mathlib lemmas about:

- monotonicity of `omega0 ^ ·`,
- multiplication of omega-powers,
- additive principality of `omega0 ^ e`,
- finite ordinal arithmetic such as `4 + (A + B + 4) ≤ A + B + 8`.

## 3. The `R_rec_succ` case is false as stated

The problematic case is:

```lean
Step (recDelta b s (delta n)) (app s (recDelta b s n))
```

The source measure is

```lean
mu (recDelta b s (delta n))
= omega0 ^ (mu (delta n) + mu s + 6)
  + omega0 * (mu b + 1) + 1
```

The target measure contains the term

```lean
omega0 ^ 2 * (mu (recDelta b s n) + 1)
```

The intended argument says that `mu (delta n)` in the source exponent dominates the target. But because ordinal addition is not commutative, the term `mu (delta n)` can be swallowed by a sufficiently large `mu s`.

A concrete counterexample is:

```lean
s := recDelta void void void
b := void
n := void
```

Compute:

```lean
mu s
= mu (recDelta void void void)
= omega0 ^ (0 + 0 + 6) + omega0 * (0 + 1) + 1
= omega0 ^ 6 + omega0 + 1
```

Also,

```lean
mu (delta void) = omega0 ^ 5 + 1
```

Now the source exponent is

```lean
mu (delta void) + mu s + 6
= (omega0 ^ 5 + 1) + (omega0 ^ 6 + omega0 + 1) + 6
= omega0 ^ 6 + omega0 + 7
```

But

```lean
mu void + mu s + 6
= 0 + (omega0 ^ 6 + omega0 + 1) + 6
= omega0 ^ 6 + omega0 + 7
```

So the recursive-call exponent is the same as the source exponent. Let

```lean
E := omega0 ^ 6 + omega0 + 7
```

Then:

```lean
mu (recDelta void s (delta void))
= omega0 ^ E + omega0 + 1
```

while

```lean
mu (recDelta void s void)
= omega0 ^ E + omega0 + 1
```

Therefore the target measure contains

```lean
omega0 ^ 2 * (mu (recDelta void s void) + 1)
= omega0 ^ 2 * (omega0 ^ E + omega0 + 2)
= omega0 ^ E + omega0 ^ 3 + ...
```

So the target is at least

```lean
omega0 ^ E + omega0 ^ 3
```

whereas the source is only

```lean
omega0 ^ E + omega0 + 1
```

Thus

```lean
mu (app s (recDelta void s void))
>
mu (recDelta void s (delta void))
```

for this instance of `R_rec_succ`.

So the theorem

```lean
theorem mu_decreases : forall {a b : Trace}, Step a b -> mu b < mu a
```

cannot be completed with the current `mu`.

---

## Consequence

A proof skeleton for all three remaining cases cannot be soundly given without changing the measure. The core defect is the exponent in

```lean
| .recDelta b s n =>
    omega0 ^ (mu n + mu s + 6)
    + omega0 * (mu b + 1) + 1
```

Because `mu n` is placed to the left of `mu s`, the larger `mu s` can absorb the increase from replacing `n` by `delta n`.

A likely repair would be to redesign the `recDelta` measure so that the counter contribution cannot be swallowed by `mu s`, for example by putting the counter contribution to the right of a large separator, or by using a lexicographic/natural-sum-style ordinal encoding rather than plain ordinal addition in the exponent.
