## 1) `R_eq_refl`

This branch can be finished exactly like `R_int_delta`:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

The target after `simp [mu]` is just `0 < omega0 ^ (...) + 1`.

## 2) `R_eq_diff`

### High-level plan

After `simp [mu]`, the goal is

```lean
omega0 ^ (4 : Ordinal) *
    (omega0 ^ (3 : Ordinal) * (mu a + 1)
      + omega0 ^ (2 : Ordinal) * (mu b + 1) + 2) + 1
  < omega0 ^ (mu a + mu b + 9) + 1
```

So it is enough to prove

```lean
omega0 ^ (4 : Ordinal) *
    (omega0 ^ (3 : Ordinal) * (mu a + 1)
      + omega0 ^ (2 : Ordinal) * (mu b + 1) + 2)
  < omega0 ^ (mu a + mu b + 9)
```

and then finish with `add_lt_add_right`.

A clean way is:

- Let `G := mu a + mu b + 5`
- Show the inner parenthesized term is `< omega0 ^ G`
- Multiply by `omega0 ^ 4`
- Rewrite `omega0 ^ 4 * omega0 ^ G = omega0 ^ (4 + G)`
- Compare exponents `4 + G ≤ mu a + mu b + 9`

### Skeleton

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    let G : Ordinal := mu a + mu b + (5 : Ordinal)
    let K : Ordinal := mu a + mu b + (9 : Ordinal)

    have hA_small :
        omega0 ^ (3 : Ordinal) * (mu a + 1) < omega0 ^ G := by
      -- standard estimate:
      --   ω^3 * (μa + 1) < ω^(μa + 4) ≤ ω^(μa + μb + 5)
      have hA₁ :
          omega0 ^ (3 : Ordinal) * (mu a + 1) < omega0 ^ (mu a + (4 : Ordinal)) := by
        -- prove once as a helper if you like:
        -- `ω^k * (x + 1) < ω^(x + k + 1)` for finite k
        sorry
      have hA₂ : mu a + (4 : Ordinal) < G := by
        -- because `4 < mu b + 5`, then add `mu a` on the left
        sorry
      exact lt_of_lt_of_le hA₁ (by
        -- monotonicity of `ω^·`
        simpa [G] using opow_le_opow_right hA₂.le)

    have hB_small :
        omega0 ^ (2 : Ordinal) * (mu b + 1) < omega0 ^ G := by
      -- similarly:
      --   ω^2 * (μb + 1) < ω^(μb + 3) ≤ ω^(μa + μb + 5)
      have hB₁ :
          omega0 ^ (2 : Ordinal) * (mu b + 1) < omega0 ^ (mu b + (3 : Ordinal)) := by
        sorry
      have hB₂ : mu b + (3 : Ordinal) < G := by
        sorry
      exact lt_of_lt_of_le hB₁ (by
        simpa [G] using opow_le_opow_right hB₂.le)

    have h2_small : (2 : Ordinal) < omega0 ^ G := by
      -- any finite ordinal is below `ω`, and `ω ≤ ω^G` since `G > 0`
      have hGpos : (0 : Ordinal) < G := by
        -- obvious from the trailing `+ 5`
        sorry
      sorry

    have hInner :
        omega0 ^ (3 : Ordinal) * (mu a + 1)
          + omega0 ^ (2 : Ordinal) * (mu b + 1) + 2
        < omega0 ^ G := by
      -- combine `hA_small`, `hB_small`, `h2_small`
      -- using that `ω^G` is add-principal
      --
      -- This is exactly where Mathlib’s `Principal` API is used.
      -- Depending on version, the lemma may be packaged as
      -- “if α < ω^G and β < ω^G then α + β < ω^G”.
      sorry

    have hOuter :
        omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1)
            + omega0 ^ (2 : Ordinal) * (mu b + 1) + 2)
        < omega0 ^ K := by
      have hMul :
          omega0 ^ (4 : Ordinal) *
            (omega0 ^ (3 : Ordinal) * (mu a + 1)
              + omega0 ^ (2 : Ordinal) * (mu b + 1) + 2)
          < omega0 ^ (4 : Ordinal) * omega0 ^ G := by
        -- strict monotonicity in the right factor because `ω^4 > 0`
        exact mul_lt_mul_of_pos_left hInner (opow_pos 4 omega0_pos)

      have hExp : (4 : Ordinal) + G ≤ K := by
        -- purely finite-tail arithmetic:
        --   4 + (μa + μb + 5) ≤ μa + μb + 9
        -- usually `simp [G, K, add_assoc, add_left_comm, add_comm]`
        sorry

      calc
        omega0 ^ (4 : Ordinal) *
            (omega0 ^ (3 : Ordinal) * (mu a + 1)
              + omega0 ^ (2 : Ordinal) * (mu b + 1) + 2)
            < omega0 ^ (4 : Ordinal) * omega0 ^ G := hMul
        _ = omega0 ^ ((4 : Ordinal) + G) := by
              rw [← opow_add]
        _ ≤ omega0 ^ K := by
              simpa using opow_le_opow_right hExp

    exact add_lt_add_right hOuter 1
```

## 3) `R_rec_succ`

## Important warning

I do **not** think this branch is merely “hard”; I think the current measure is likely **not decreasing** for this rule in full generality.

A concrete family to inspect is:

```lean
b := void
n := void
s := recDelta void void void
```

Then

- `mu s = omega0 ^ 6 + omega0 + 1`
- `mu n + mu s + 6 = omega0 ^ 6 + omega0 + 7`
- `mu (delta n) + mu s + 6 = (omega0 ^ 5 + 1) + (omega0 ^ 6 + omega0 + 1) + 6
                           = omega0 ^ 6 + omega0 + 7`

So the recursive-call exponent and the source exponent coincide. That means the target contains

```lean
omega0 ^ (2 : Ordinal) * (omega0 ^ E + omega0 + 2)
```

with `E = omega0 ^ 6 + omega0 + 7`, which expands to something of the form

```lean
omega0 ^ E + (strictly positive tail of ω^3-size) + ...
```

whereas the source is only

```lean
omega0 ^ E + omega0 + 1
```

So the app-side appears larger, not smaller.

So I would strongly recommend checking `mu` before trying to fill this proof.

## If the measure is repaired, this is the proof shape

If you change the measure so that the critical estimate becomes true, the branch should have this shape:

```lean
| _, _, Step.R_rec_succ b s n => by
    simp [mu]
    let E : Ordinal := mu (delta n) + mu s + (6 : Ordinal)
    let F : Ordinal := mu n + mu s + (6 : Ordinal)

    -- Goal after simp:
    --   ω^3 * (μ s + 1) + ω^2 * (ω^F + ω*(μ b + 1) + 2) + 1
    --     < ω^E + ω*(μ b + 1) + 1

    have hHead :
        omega0 ^ (3 : Ordinal) * (mu s + 1) < omega0 ^ E := by
      -- same kind of estimate as in `R_eq_diff`
      -- `ω^3*(μs+1) < ω^(μs+4) ≤ ω^E`
      sorry

    have hCritical :
        omega0 ^ (2 : Ordinal) *
          (omega0 ^ F + omega0 * (mu b + 1) + 2)
        ≤ omega0 ^ E := by
      -- THIS is the key inequality.
      -- For the current `mu`, this is the suspicious / likely false step.
      -- If you repair the measure, prove it here.
      sorry

    have hSum :
        omega0 ^ (3 : Ordinal) * (mu s + 1)
          + omega0 ^ (2 : Ordinal) *
              (omega0 ^ F + omega0 * (mu b + 1) + 2)
        ≤ omega0 ^ E := by
      calc
        omega0 ^ (3 : Ordinal) * (mu s + 1)
          + omega0 ^ (2 : Ordinal) *
              (omega0 ^ F + omega0 * (mu b + 1) + 2)
            ≤ omega0 ^ (3 : Ordinal) * (mu s + 1) + omega0 ^ E := by
                exact add_le_add_left hCritical _
        _ = omega0 ^ E := by
            -- absorb the smaller left summand into the principal ordinal `ω^E`
            -- use the add-principal lemma for `ω^E`
            sorry

    have hTail :
        (1 : Ordinal) < omega0 * (mu b + 1) + 1 := by
      have hpos : (0 : Ordinal) < omega0 * (mu b + 1) := by
        -- `μ b + 1 > 0`, hence product with `ω` is positive
        sorry
      -- add `1` on the right
      simpa [add_assoc] using add_lt_add_right hpos 1

    have hMain :
        omega0 ^ (3 : Ordinal) * (mu s + 1)
          + omega0 ^ (2 : Ordinal) *
              (omega0 ^ F + omega0 * (mu b + 1) + 2) + 1
        ≤ omega0 ^ E + 1 := by
      exact add_le_add_right hSum 1

    have hStrict :
        omega0 ^ E + 1 < omega0 ^ E + (omega0 * (mu b + 1) + 1) := by
      exact add_lt_add_left hTail _

    exact lt_of_le_of_lt hMain hStrict
```

So the branch reduces to one critical sublemma. My honest read is that this sublemma is not true with the current definition of `mu`.

## Bottom line

- `R_eq_refl`: fill it directly now.
- `R_eq_diff`: doable; use the `G := mu a + mu b + 5` intermediate bound and add-principality of `ω^G`.
- `R_rec_succ`: I would not try to “tactic harder” here. I would first re-check the measure, because this branch appears genuinely false as stated.

If you want, I can also rewrite the `R_eq_diff` skeleton into a more compact “calc-style” version with the helper lemmas isolated.
