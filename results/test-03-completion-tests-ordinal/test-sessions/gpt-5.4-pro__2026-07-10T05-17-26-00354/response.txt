Here is the honest proof skeleton I would use.

Two of the three `sorry`s are routine. The third (`R_rec_succ`) looks different: I do **not** think it is provable from the current `mu`. I’ll give you both the Lean-style skeleton and the reason.

I have **not** compiled this, so a few API names may need tiny adjustment (`opow_isNormal`, the additive-principal closure lemma, etc.).

---

## 1. `R_eq_refl`

This one can be filled exactly the same way as `R_int_delta`:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

Because after `simp [mu]` the goal is just

```lean
0 < omega0 ^ (mu a + mu a + (9 : Ordinal)) + 1
```

and anything of the form `x + 1` is positive.

---

## 2. `R_eq_diff`

This one should go through by:
1. setting `γ := mu a + mu b + 9`,
2. proving the predecessor term is `< ω^γ`,
3. then converting that to the desired successor inequality.

The cleanest route is to **distribute** the outer `ω^4` and compare each summand with `ω^γ`.

### Suggested skeleton

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    let γ : Ordinal := mu a + mu b + (9 : Ordinal)

    have hγpos : (0 : Ordinal) < γ := by
      dsimp [γ]
      exact add_pos_right _ (by norm_num)

    -- `ω^γ` is additively principal since γ > 0.
    have hP :
        ∀ {x y : Ordinal}, x < omega0 ^ γ → y < omega0 ^ γ → x + y < omega0 ^ γ := by
      -- use the library fact that `omega0 ^ γ` is principal / additively principal
      -- for `0 < γ`
      intro x y hx hy
      -- exact ...  -- additive-principal closure lemma

    -- First coefficient bound: `mu a + 1 < ω^(mu a + 1)`
    have ha_small : mu a + 1 < omega0 ^ (mu a + 1) := by
      -- use the standard "ordinal is below the next ω-power" lemma
      -- e.g. `lt_opow_succ`, `self_lt_omega0_opow_succ`, or equivalent
      sorry

    -- Second coefficient bound: `mu b + 1 < ω^(mu b + 1)`
    have hb_small : mu b + 1 < omega0 ^ (mu b + 1) := by
      sorry

    -- Bound the distributed `ω^7 * (mu a + 1)` term.
    have hA :
        omega0 ^ (7 : Ordinal) * (mu a + 1) < omega0 ^ γ := by
      calc
        omega0 ^ (7 : Ordinal) * (mu a + 1)
            < omega0 ^ (7 : Ordinal) * omega0 ^ (mu a + 1) := by
                exact mul_lt_mul_of_pos_left ha_small (opow_pos 7 omega0_pos)
        _ = omega0 ^ ((7 : Ordinal) + (mu a + 1)) := by
              rw [← opow_add]
        _ ≤ omega0 ^ γ := by
              -- enough to show `7 + (mu a + 1) ≤ mu a + mu b + 9`
              apply opow_le_opow
              -- prove:
              --   7 + (mu a + 1) ≤ mu a + 8
              --   mu a + 8 ≤ mu a + mu b + 9
              sorry

    -- Bound the distributed `ω^6 * (mu b + 1)` term.
    have hB :
        omega0 ^ (6 : Ordinal) * (mu b + 1) < omega0 ^ γ := by
      calc
        omega0 ^ (6 : Ordinal) * (mu b + 1)
            < omega0 ^ (6 : Ordinal) * omega0 ^ (mu b + 1) := by
                exact mul_lt_mul_of_pos_left hb_small (opow_pos 6 omega0_pos)
        _ = omega0 ^ ((6 : Ordinal) + (mu b + 1)) := by
              rw [← opow_add]
        _ ≤ omega0 ^ γ := by
              apply opow_le_opow
              -- enough to show `6 + (mu b + 1) ≤ mu a + mu b + 9`
              sorry

    -- Each bare `ω^4` is also below `ω^γ` since `4 < γ`.
    have hC : omega0 ^ (4 : Ordinal) < omega0 ^ γ := by
      have h4 : (4 : Ordinal) < γ := by
        dsimp [γ]
        -- `4 < mu a + mu b + 9`
        sorry
      exact opow_lt_opow_right omega0 h4  -- or the corresponding strict-mono lemma

    -- Combine the distributed pieces under additive-principal closure.
    have hcore :
        omega0 ^ (7 : Ordinal) * (mu a + 1) +
          (omega0 ^ (6 : Ordinal) * (mu b + 1) + (omega0 ^ (4 : Ordinal) + omega0 ^ (4 : Ordinal)))
        < omega0 ^ γ := by
      have hCC : omega0 ^ (4 : Ordinal) + omega0 ^ (4 : Ordinal) < omega0 ^ γ := by
        exact hP hC hC
      have hBC : omega0 ^ (6 : Ordinal) * (mu b + 1) + (omega0 ^ (4 : Ordinal) + omega0 ^ (4 : Ordinal))
          < omega0 ^ γ := by
        exact hP hB hCC
      exact hP hA hBC

    -- Rewrite the predecessor exactly into the distributed shape.
    have hrewrite :
        omega0 ^ (4 : Ordinal) *
            (omega0 ^ (3 : Ordinal) * (mu a + 1) +
              (omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1))
        =
        omega0 ^ (7 : Ordinal) * (mu a + 1) +
          (omega0 ^ (6 : Ordinal) * (mu b + 1) + (omega0 ^ (4 : Ordinal) + omega0 ^ (4 : Ordinal))) := by
      -- use right-distributivity of ordinal multiplication and `← opow_add`
      -- plus reassociation/commutation of `+`
      sorry

    have hpred :
        omega0 ^ (4 : Ordinal) *
            (omega0 ^ (3 : Ordinal) * (mu a + 1) +
              (omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1))
        < omega0 ^ γ := by
      simpa [hrewrite] using hcore

    -- From predecessor `< ω^γ`, get successor `< ω^γ + 1`.
    have hsucc :
        omega0 ^ (4 : Ordinal) *
            (omega0 ^ (3 : Ordinal) * (mu a + 1) +
              (omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1)) + 1
        ≤ omega0 ^ γ := by
      simpa [Ordinal.succ_eq_add_one] using succ_le_of_lt hpred

    exact lt_of_le_of_lt hsucc (lt_add_one _)
```

### What the proof is doing mathematically

After `simp [mu]`, you want

\[
\omega^4\cdot(\omega^3(\mu a+1)+\omega^2(\mu b+1)+2)+1
< \omega^{\mu a+\mu b+9}+1.
\]

Distribute `ω^4`:

\[
\omega^7(\mu a+1)+\omega^6(\mu b+1)+\omega^4+\omega^4.
\]

Each summand is `< ω^γ` where `γ := μa + μb + 9`, and since `ω^γ` is additively principal (`γ>0`), the whole sum is still `< ω^γ`.

## 3. `R_rec_succ`

This is the one I would **not** try to finish as-is.

### Why the obvious proof attempt breaks

The natural idea is the same:
- let `γ := mu n + mu s + 6`,
- let `β := mu (delta n) + mu s + 6`,
- expand the `ω^2 * (mu (recDelta b s n) + 1)` piece,
- try to show everything on the app-side is `< ω^β`,
- then absorb into `ω^β + ω * (mu b + 1) + 1`.

After expansion you get the problematic term

\[
\omega^3 \cdot (\mu b + 1),
\]

coming from

\[
\omega^2 \cdot (\omega \cdot (\mu b + 1)).
\]

But on the right-hand side the `b`-part is only

\[
\omega \cdot (\mu b + 1),
\]

and there is no uniform inequality
\[
\omega^3(\mu b+1) \le \omega(\mu b+1).
\]

So the intended domination argument does not go through.

### Concrete counterexample

Take

```lean
b := eqW (delta void) (delta void)
s := void
n := void
```

Then:
- `mu (delta void) = ω^5 + 1`,
- hence `mu b = ω^δ + 1` for `δ = (ω^5 + 1) + (ω^5 + 1) + 9`, so `δ > ω^5 + 7`.

Now compute:

\[
\mu(\operatorname{recDelta}\ b\ \text{void}\ \text{void})
= \omega^6 + \omega(\mu b + 1) + 1
= \omega^\delta + \omega\cdot 2 + 1.
\]

So

\[
\mu(\operatorname{app}\ \text{void}\ (\operatorname{recDelta}\ b\ \text{void}\ \text{void}))
= \omega^3 + \omega^2(\omega^\delta + \omega\cdot 2 + 2) + 1
= \omega^\delta + \omega^3\cdot 2 + \omega^2\cdot 2 + 1.
\]

On the other hand,

\[
\mu(\operatorname{recDelta}\ b\ \text{void}\ (\delta\ \text{void}))
= \omega^{\omega^5+7} + \omega(\mu b + 1) + 1
= \omega^\delta + \omega\cdot 2 + 1.
\]

Comparing tails after the common leading term `ω^δ`, we get

\[
\omega^3\cdot 2 + \omega^2\cdot 2 + 1
\;>\;
\omega\cdot 2 + 1,
\]

so the alleged decrease fails here.

### So what to do?

For this branch, I would not recommend filling the `sorry` with a fake arithmetic proof. The right next step is to **change the measure** for `recDelta`.

A typical repair is to make the `b`-component live at least at the same “tier” that the `app` case creates after one unfolding, for example by putting more of `b` into the exponent or by raising its coefficient level. For instance, something morally like

```lean
| .recDelta b s n =>
    omega0 ^ (mu n + mu s + mu b + (6 : Ordinal)) + 1
```

or another variant where the `b`-part cannot be turned from `ω*(...)` into a larger `ω^3*(...)` on the reduct side.

---

## Bottom line

- `R_eq_refl`: fill exactly as above.
- `R_eq_diff`: should be provable by distributing `ω^4`, bounding each summand below `ω^(mu a + mu b + 9)`, and using additive principality.
- `R_rec_succ`: I strongly suspect the current `mu` makes the theorem false; the hole is not just “missing arithmetic”.
