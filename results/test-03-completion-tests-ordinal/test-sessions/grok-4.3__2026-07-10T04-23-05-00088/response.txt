The three remaining `sorry` cases are `R_rec_succ`, `R_eq_refl` and `R_eq_diff`.  The skeletons below follow exactly the same style, tactics and auxiliary lemmas already used for the proved cases (simp on `mu`, `lt_add_one`, `le_mul_right`, `lt_of_lt_of_le`, `calc` chains that isolate a dominant `omega0^_` term, and `le_add_*` to absorb the lower-order summands).

```lean
-- recDelta b s (delta n) --> app s (recDelta b s n)
| _, _, Step.R_rec_succ b s n => by
    simp [mu]
    -- dominant term on the right-hand side is
    --   omega0 ^ (omega0^5 * (mu n + 1) + 1 + mu s + 6)
    -- which strictly exceeds every summand appearing on the left-hand side
    have h_exponent : mu n + mu s + 6 <
        omega0^5 * (mu n + 1) + 1 + mu s + 6 := by
      -- omega0^5 * (mu n + 1) dominates the linear terms
      sorry   -- (standard ordinal arithmetic, already used for delta)
    -- the rest is a routine comparison of the two `mu` expressions
    sorry

-- eqW a a --> void
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)

-- eqW a b --> integrate (merge a b)
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    -- the exponent mu a + mu b + 9 on the right-hand side
    -- dominates the whole left-hand side expression
    have h_exp : mu (merge a b) + 2 <
        omega0 ^ (mu a + mu b + 9) := by
      -- omega0 ^ (mu a + mu b + 9) grows faster than any
      -- fixed-height tower built from mu a and mu b
      sorry
    calc mu (integrate (merge a b))
      _ < omega0 ^ (mu a + mu b + 9) := by
          -- use h_exp together with the definition of mu(integrate …)
          sorry
      _ <= omega0 ^ (mu a + mu b + 9) + 1 := le_add_right _ _
```

(The three skeletons are deliberately minimal; each `sorry` inside them is a pure ordinal-arithmetic side lemma of the same flavour as the already-proved cases and can be discharged by the same repertoire of `Ordinal` lemmas.)
