A proof skeleton for all three remaining cases cannot exist as stated, because the `R_rec_succ` decrease claim is false for the given `mu`.

Take the concrete instance

```lean
b = void
n = void
s = eqW void void
```

Then:

```text
mu s = ω^9 + 1
mu (delta void) = ω^5 + 1
```

Let

```text
Ω = ω^(ω^9 + 7).
```

The source of the successor rule has measure

```text
mu (recDelta void s (delta void))
  = Ω + ω + 1.
```

Indeed, its exponent is

```text
(ω^5 + 1) + (ω^9 + 1) + 6 = ω^9 + 7.
```

But the target has measure

```text
mu (app s (recDelta void s void))
  = Ω + ω^3 + ω^2 * 2 + 1.
```

The relevant part is

```text
ω^2 * Ω = ω^(2 + (ω^9 + 7)) = ω^(ω^9 + 7) = Ω,
```

while the lower-order tail of the `app` measure is larger than the tail of the source:

```text
Ω + ω + 1 < Ω + ω^3 + ω^2 * 2 + 1.
```

Thus, for this instance,

```text
mu (recDelta void s (delta void))
<
mu (app s (recDelta void s void))
```

rather than the required reverse inequality. Consequently, the `Step.R_rec_succ` branch cannot be filled without changing either `mu`, the reduction rule, or the theorem statement.

The `eqW` reflexivity branch, however, has the same simple positivity shape as the already proved `R_int_delta` branch and can be completed as:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

For `R_eq_diff`, assuming a separately proved ordinal-arithmetic bounding lemma, the intended skeleton is:

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    have hmain :
        omega0 ^ (4 : Ordinal) *
            (omega0 ^ (3 : Ordinal) * (mu a + 1) +
             omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1) + 1
          < omega0 ^ (mu a + mu b + (9 : Ordinal)) := by
      -- Prove this as a standalone ordinal-arithmetic lemma.
      --
      -- The proof should normalize the left side using distributivity of
      -- multiplication over ordinal addition and bound its leading terms
      -- by powers strictly below
      --
      --   omega0 ^ (mu a + mu b + 9).
      --
      -- The finite margin `9` is intended to dominate the `4 + 3`
      -- contribution from integrate ∘ merge.
      sorry
    exact lt_of_lt_of_le hmain
      (le_add_right
        (omega0 ^ (mu a + mu b + (9 : Ordinal))) 1)
```

Equivalently, it is cleaner to first extract the needed arithmetic statement into a helper theorem:

```lean
lemma integrate_merge_lt_eqW_bound (A B : Ordinal) :
    omega0 ^ (4 : Ordinal) *
        (omega0 ^ (3 : Ordinal) * (A + 1) +
         omega0 ^ (2 : Ordinal) * (B + 1) + 1 + 1) + 1
      < omega0 ^ (A + B + (9 : Ordinal)) := by
  -- detailed CNF / ordinal-exponent arithmetic
  sorry
```

and then use it as:

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    exact lt_of_lt_of_le
      (integrate_merge_lt_eqW_bound (mu a) (mu b))
      (le_add_right _ _)
```

So the viable completion status is:

* `R_eq_refl`: directly provable as above.
* `R_eq_diff`: plausibly provable after supplying a substantial ordinal-arithmetic helper lemma.
* `R_rec_succ`: not provable for the displayed measure, due to the explicit counterexample above.

Therefore `mu_decreases`, and hence `strong_normalization` via this particular measure, cannot be completed without revising the `recDelta`/`app` measure design.
