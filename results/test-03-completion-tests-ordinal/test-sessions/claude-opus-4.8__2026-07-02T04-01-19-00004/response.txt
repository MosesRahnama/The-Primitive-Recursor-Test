# Proof Skeletons for the Three Remaining Cases

Below are proof skeletons for the three `sorry` cases. I'll present them in increasing order of difficulty.

## Case 1: `R_eq_refl` (easiest — pure positivity)

Goal after `simp [mu]`: `0 < omega0 ^ (mu a + mu a + 9) + 1` (or a similar normalized form).

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    -- Goal reduces to positivity of `omega0 ^ (…) + 1`.
    -- Strategy: it is a successor / has a positive summand `+ 1`.
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
    -- Alternative if `simp` fully closes to `0 < X + 1`:
    --   exact Order.lt_add_one_iff.mpr (Ordinal.zero_le _)
    -- or simply: exact lt_of_lt_of_le one_pos (le_add_left _ _)
```

Fallback tactics if the `simp`-normal form differs:
- `positivity` may not know ordinals; instead use `exact add_pos_right _ one_pos`.
- If the exponent got simplified (`mu a + mu a` → `2 * mu a`), the same positivity closer works since only the trailing `+ 1` matters.

## Case 2: `R_eq_diff` (moderate — one dominant exponent)

Goal: `mu (integrate (merge a b)) < mu (eqW a b)`, i.e. roughly
```
omega0^4 * (omega0^3*(mu a+1) + omega0^2*(mu b+1) + 1 + 1) + 1
  < omega0 ^ (mu a + mu b + 9) + 1
```

Key lemma structure: reduce to comparing exponents via `opow`, then bound the LHS by a single power `omega0 ^ e_L` with `e_L < mu a + mu b + 9`.

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    -- Step A: Set N := mu a + mu b + 9 as the target exponent.
    set N : Ordinal := mu a + mu b + 9 with hN
    -- Step B: Bound the inner merge measure by some power omega0 ^ k.
    --   omega0^3*(mu a+1) + omega0^2*(mu b+1) + 2  ≤  omega0 ^ (mu a + mu b + 4)
    -- Justify each summand is < omega0 ^ (mu a + mu b + 4) using:
    --   mul_lt_opow / opow_lt_opow_right and additive principality of powers of ω.
    have hInner :
        omega0 ^ (3:Ordinal) * (mu a + 1)
          + omega0 ^ (2:Ordinal) * (mu b + 1) + 1 + 1
        ≤ omega0 ^ (mu a + mu b + 4) := by
      sorry  -- use Principal.add / principal_add_omega0_opow, mul_le_of_lt
    -- Step C: Multiply by omega0^4 and collapse exponents by addition:
    --   omega0^4 * omega0^(mu a+mu b+4) = omega0 ^ (4 + (mu a+mu b+4))
    have hMul :
        omega0 ^ (4:Ordinal) *
          (omega0 ^ (3:Ordinal) * (mu a + 1)
            + omega0 ^ (2:Ordinal) * (mu b + 1) + 1 + 1)
        ≤ omega0 ^ ((4:Ordinal) + (mu a + mu b + 4)) := by
      calc _ ≤ omega0 ^ (4:Ordinal) * omega0 ^ (mu a + mu b + 4) :=
                mul_le_mul_left' hInner _
           _ = omega0 ^ ((4:Ordinal) + (mu a + mu b + 4)) :=
                (opow_add omega0 _ _).symm
    -- Step D: Show the collapsed exponent is < N = mu a + mu b + 9.
    have hExp : (4:Ordinal) + (mu a + mu b + 4) < mu a + mu b + 9 := by
      -- 4 + (x + 4) = x + 8 < x + 9  (ordinal addition is left-cancellative on the right chunk)
      sorry  -- rewrite using add_assoc / natural-number arithmetic on the tail
    -- Step E: Powers with smaller exponent are strictly below; then re-add the +1.
    have hPow :
        omega0 ^ ((4:Ordinal) + (mu a + mu b + 4)) < omega0 ^ N :=
      opow_lt_opow_right one_lt_omega0 hExp
    -- Step F: Combine to get LHS + 1 < RHS + 1 (or ≤ then <), closing the goal.
    calc _ ≤ omega0 ^ ((4:Ordinal) + (mu a + mu b + 4)) + 1 :=
              add_le_add_right hMul 1
         _ < omega0 ^ N + 1 := by
              exact (add_lt_add_iff_right 1).mpr hPow
                -- or: use that hPow gives strict gap absorbing the +1
```

Notes:
- For `hInner`, the essential fact is that `omega0 ^ k` is **additively principal** (`Ordinal.principal_add_omega0_opow` / `Principal.add`), so a finite sum of terms each `< omega0 ^ (mu a + mu b + 4)` stays below it. Each factor bound like `omega0^3*(mu a+1) < omega0^(mu a + mu b + 4)` follows from `mul_lt_opow`-style reasoning combined with `opow_lt_opow_right`.
- For `hExp`, since the exponent addition ends in fixed finite constants, `add_assoc` plus `omega0`-free `Nat` comparison on the constant tail suffices; watch that ordinal `+` is not commutative — keep the variable part `mu a + mu b` on the left.

## Case 3: `R_rec_succ` (hardest — nested exponent domination)

Goal: `mu (app s (recDelta b s n)) < mu (recDelta b s (delta n))`.

The LHS exponent is `mu (delta n) + mu s + 6 = omega0^5*(mu n+1)+1 + mu s + 6`, which dominates everything on the RHS because the RHS's largest term is a `omega0^2 * (omega0^(mu n + mu s + 6) + …)`.

```lean
| _, _, Step.R_rec_succ b s n => by
    simp [mu]
    -- Abbreviations:
    set E_big : Ordinal :=
        (omega0 ^ (5:Ordinal) * (mu n + 1) + 1) + mu s + 6 with hEbig
        -- this is the LHS's outer exponent (mu (delta n) + mu s + 6)
    set E_sml : Ordinal := mu n + mu s + 6 with hEsml
        -- exponent appearing inside the RHS via mu (recDelta b s n)
    -- Step A: Bound the entire RHS by a single power omega0 ^ M with M < E_big.
    --   RHS = omega0^3*(mu s+1) + omega0^2*(omega0^E_sml + omega0*(mu b+1) + 1 + 1) + 1
    --   Each additive block is < omega0 ^ (E_sml + 3), say, so RHS ≤ omega0 ^ (E_sml + 3).
    have hRHS_le :
        omega0 ^ (3:Ordinal) * (mu s + 1)
          + omega0 ^ (2:Ordinal) *
              (omega0 ^ E_sml + omega0 * (mu b + 1) + 1 + 1) + 1
        ≤ omega0 ^ (E_sml + 3) := by
      -- Use additive principality of omega0 ^ (E_sml + 3):
      --  * omega0^3*(mu s+1) < omega0^(E_sml+3)      (since 3 ≤ E_sml+3 and factor bounded)
      --  * omega0^2 * (omega0^E_sml + …) < omega0^(E_sml+3)
      --        because omega0^E_sml + … ≤ omega0^(E_sml+1), then times omega0^2
      sorry
    -- Step B: Show the exponent E_sml + 3 is strictly below E_big.
    --   E_big = omega0^5*(mu n+1) + 1 + mu s + 6
    --   E_sml + 3 = (mu n + mu s + 6) + 3 = mu n + mu s + 9
    -- Since omega0^5*(mu n+1) ≥ omega0^5 dominates the polynomial mu n + mu s + 9:
    have hExp_lt : E_sml + 3 < E_big := by
      rw [hEbig, hEsml]
      -- mu n + mu s + 9  <  omega0^5*(mu n+1) + 1 + mu s + 6
      -- The RHS has a leading omega0^5-block absorbing the linear left side.
      sorry  -- use opow dominance: mu n + mu s + 9 < omega0^5 ≤ omega0^5*(mu n+1)
    -- Step C: The LHS's dominant part is omega0 ^ E_big; smaller lower-order
    --   summands (omega0*(mu b+1)+1) are absorbed.  Compare via opow monotonicity.
    have hPow_lt : omega0 ^ (E_sml + 3) < omega0 ^ E_big :=
      opow_lt_opow_right one_lt_omega0 hExp_lt
    -- Step D: Assemble. RHS ≤ omega0^(E_sml+3) < omega0^E_big ≤ LHS.
    have hLHS_ge : omega0 ^ E_big ≤ mu (app s (recDelta b s n)) := by
      -- mu(app …) = omega0^E_big + omega0*(mu b+1) + 1  ≥ omega0^E_big
      simp [mu, hEbig]
      exact le_add_right _ _   -- or le_self_add / add-monotonicity
    calc
      (omega0 ^ (3:Ordinal) * (mu s + 1)
        + omega0 ^ (2:Ordinal) *
            (omega0 ^ E_sml + omega0 * (mu b + 1) + 1 + 1) + 1)
          ≤ omega0 ^ (E_sml + 3) := hRHS_le
        _ < omega0 ^ E_big       := hPow_lt
        _ ≤ _                    := hLHS_ge
```

### Supporting lemma inventory (Mathlib names to reach for)

- `Ordinal.opow_lt_opow_right` / `opow_lt_opow_right` : `1 < b → e₁ < e₂ → b^e₁ < b^e₂`.
- `Ordinal.opow_add` : `b^(x+y) = b^x * b^y` — for collapsing products of powers.
- `Ordinal.principal_add_omega0_opow` / `Principal.add_omega0_opow` : `omega0 ^ e` is additively principal (closed under `+`), the crux for `hInner`/`hRHS_le`.
- `Ordinal.mul_lt_opow` / `Ordinal.lt_opow_succ` style lemmas, plus `mul_le_mul_left'`, `add_le_add_right`, `le_add_right`, `le_add_left`, `le_mul_right`.
- `one_lt_omega0`, `omega0_pos`, `opow_pos`.

### Practical tips for finishing

1. **Watch the `simp [mu]` normal form.** The exact bracketing/order of summands may differ from the comments; run `simp only [mu]` mentally and adjust the `set …` definitions to match the literal goal.
2. **The `sorry`-marked sub-lemmas** (`hInner`, `hRHS_le`, `hExp`, `hExp_lt`) are each of the shape "a finite sum of ω-powers with small exponents is below a single ω-power with a larger exponent." The uniform recipe is:
   - bound each summand `omega0^k * c < omega0^(target)` via `k < target` (or `k = target` with `c` absorbed by principality),
   - then use additive principality (`Principal.add`) to combine.
3. **Exponent arithmetic** (`hExp`, `hExp_lt`) reduces to: linear ordinal `x + finite` versus a term containing `omega0^5 * (…)`. Use `lt_of_lt_of_le (nat_lt_opow …) (le_mul_right …)`-style chains; the key is `mu n + mu s + 9 < omega0^5` is **not** generally true (mu n can be large), so instead compare *matching leading blocks*: on both sides `mu n` and `mu s` appear, and the RHS additionally carries `omega0^5*(mu n+1)`, giving strict dominance by `add_lt_add`/`lt_add_of_...`. Be careful: prefer proving `mu n + mu s + 9 < omega0^5*(mu n+1) + 1 + mu s + 6` by isolating the `mu s + const` tails and using left-monotonicity, *not* commutativity.

These skeletons preserve the file's existing style (calc chains + explicit `have`s) and localize each remaining obligation to a small, individually dischargeable ordinal fact.
