The file cannot be completed as stated: the `R_rec_succ` case is false for this measure because ordinal addition can absorb the contribution of `mu (delta n)` when it occurs to the left of `mu s`.

### Counterexample to `R_rec_succ`

Take
```lean
b := void
n := void
s := delta (delta void)
```

Write
```text
δ = mu (delta void) = ω^5 + 1
σ = mu s
  = ω^5 * (δ + 1) + 1
  = ω^10 + ω^5 * 2 + 1.
```

The initial `δ` is absorbed when added to `σ`:

```text
δ + σ = σ = 0 + σ.
```

Let
```text
E = σ + 6
A = ω^E.
```

Consequently, the source and the recursive call have the same leading exponent:

```text
mu (recDelta void s (delta void)) = A + ω + 1
mu (recDelta void s void)         = A + ω + 1.
```

But the target has measure

```text
mu (app s (recDelta void s void))
  = ω^3 * (σ + 1) + ω^2 * (A + ω + 2) + 1.
```

Since `2 + E = E`, ordinal exponent arithmetic gives

```text
ω^2 * A = ω^(2 + E) = ω^E = A,
```

and hence

```text
ω^2 * (A + ω + 2)
  = A + ω^3 + ω^2 * 2
  > A + ω + 1.
```

Thus in this instance the target measure is strictly larger than the source measure. Therefore no proof term can replace the `sorry` in `R_rec_succ`, and consequently `mu_decreases` and the final proof through this `mu` cannot be completed.

The other two holes are individually plausible and have the following proof skeletons.

---

## `R_eq_refl`

This one is just positivity of the final `+ 1`:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact add_pos_right _ one_pos
```

If `simp` changes the goal’s normal form, the more robust version is:

```lean
| _, _, Step.R_eq_refl a => by
    change 0 < omega0 ^ (mu a + mu a + (9 : Ordinal)) + 1
    exact add_pos_right _ one_pos
```

---

## `R_eq_diff`

After unfolding, set

```text
α = mu a
β = mu b
γ = α + β
X = ω^3 * (α + 1) + ω^2 * (β + 1) + 2.
```

The required inequality follows from the CNF-style bound

```text
X < ω^(γ + 5).
```

Then

```text
ω^4 * X
  < ω^4 * ω^(γ + 5)
  = ω^(4 + (γ + 5))
  ≤ ω^(γ + 9).
```

Finally, take successors on both sides.

A Lean-oriented skeleton is:

```lean
| _, _, Step.R_eq_diff a b => by
    simp only [mu]

    let α : Ordinal := mu a
    let β : Ordinal := mu b
    let γ : Ordinal := α + β
    let X : Ordinal :=
      omega0 ^ (3 : Ordinal) * (α + 1) +
      omega0 ^ (2 : Ordinal) * (β + 1) + 2

    have hα : α ≤ γ := by
      dsimp [γ]
      exact le_add_right α β

    have hβ : β ≤ γ := by
      dsimp [γ]
      exact le_add_left β α

    have hX : X < omega0 ^ (γ + 5) := by
      -- Bound each summand below the additively-principal ordinal
      -- omega0 ^ (γ + 5):
      --
      --   omega0^3 * (α + 1) < omega0^(γ + 5)
      --   omega0^2 * (β + 1) < omega0^(γ + 5)
      --   2                    < omega0^(γ + 5)
      --
      -- Use hα, hβ, monotonicity of opow, `opow_add`, and the
      -- fact that a positive omega-power is additively principal.
      --
      -- Then close the finite sum using the corresponding
      -- principal/addition lemma.
      sorry

    have hexp : (4 : Ordinal) + (γ + 5) ≤ γ + 9 := by
      -- Routine finite ordinal arithmetic; the finite prefix `4`
      -- is either retained (when γ is finite) or absorbed by γ.
      sorry

    have hscaled :
        omega0 ^ (4 : Ordinal) * X <
          omega0 ^ (γ + 9) := by
      calc
        omega0 ^ (4 : Ordinal) * X
            < omega0 ^ (4 : Ordinal) * omega0 ^ (γ + 5) := by
                -- Strict monotonicity of right multiplication by
                -- the positive ordinal omega0^4.
                exact mul_lt_mul_left (opow_pos 4 omega0_pos) hX
        _ = omega0 ^ ((4 : Ordinal) + (γ + 5)) := by
                rw [← opow_add]
        _ ≤ omega0 ^ (γ + 9) := by
                -- Monotonicity of exponentiation in the exponent.
                exact opow_le_opow_right omega0_pos hexp

    -- Unfold α, β, γ, X and take successors.
    dsimp [X, γ, α, β] at hscaled ⊢
    exact succ_lt_succ hscaled
```

The exact Mathlib names for strict multiplication monotonicity, monotonicity of `opow`, and additive-principality may differ, but these are the required intermediate inequalities.

To repair `R_rec_succ`, the exponent must preserve the strict counter decrease instead of allowing it to be absorbed by `mu s`. A likely starting point is to place `mu s` before the counter,

```lean
omega0 ^ (mu s + mu n + 6)
```

or to use a commutative/natural ordinal sum. The revised measure would then need all eight cases rechecked.
