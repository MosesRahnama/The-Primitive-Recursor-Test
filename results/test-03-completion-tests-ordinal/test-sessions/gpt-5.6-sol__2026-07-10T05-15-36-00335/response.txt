The three cases cannot all be completed as written: the `R_rec_succ` inequality is false for this measure. The other two cases have standard proofs.

### `eq_refl`

The same positivity argument as in `R_int_delta` suffices:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

Depending on what `simp [mu]` leaves, this may shorten to `exact add_pos_right _ one_pos`.

### `eq_diff`

A useful proof skeleton is to isolate the ordinal-polynomial estimate:

```lean
private lemma eq_payload_lt (A B : Ordinal) :
    omega0 ^ (4 : Ordinal) *
        (omega0 ^ (3 : Ordinal) * (A + 1) +
         omega0 ^ (2 : Ordinal) * (B + 1) + 1 + 1)
      < omega0 ^ (A + B + 9) := by
  let E := A + B + 9

  have hE : 0 < E := by
    dsimp [E]
    exact add_pos_right _ (by norm_num)

  -- Distribute the outer omega^4:
  --
  --   omega^4 * (...) =
  --     omega^7 * (A + 1)
  --       + omega^6 * (B + 1)
  --       + omega^4 * 2.
  --
  -- Prove separately that all three summands are below omega^E.
  --
  -- Useful bounds:
  --   A + 1 < omega^(A + 1)
  --   B + 1 < omega^(B + 1)
  --   7 + (A + 1) < A + B + 9
  --   6 + (B + 1) < A + B + 9
  --
  -- After multiplying powers, use:
  --   omega^p * omega^q = omega^(p + q).
  --
  -- Finally use that omega^E, for E > 0, is additively principal,
  -- so a finite sum of ordinals below omega^E remains below omega^E.
  --
  -- Relevant Mathlib ingredients are the lemmas around:
  --   opow_add,
  --   monotonicity/strict monotonicity of opow,
  --   mul_add and mul_assoc,
  --   and the additive-principal instance for omega powers.
  sorry
```

The rule case then becomes:

```lean
| _, _, Step.R_eq_diff a b => by
    simp only [mu]
    have h := eq_payload_lt (mu a) (mu b)
    -- Both sides are successors of the payloads.
    exact Ordinal.succ_lt_succ h
```

The final line may need to be presented through the identity `x + 1 = succ x`, depending on simplification:

```lean
    simpa [Ordinal.succ_eq_add_one] using Ordinal.succ_lt_succ h
```

The central idea is to normalize the left payload to

```text
ω^7 * (mu a + 1) + ω^6 * (mu b + 1) + ω^4 * 2
```

and use the additive indecomposability of `ω^(mu a + mu b + 9)`.

## Why `R_rec_succ` cannot be proved

The problem is ordinal absorption in

```lean
mu n + mu s + 6.
```

Increasing `mu n` to `mu (delta n)` need not increase this exponent, because the following `+ mu s` can erase the difference.

For a concrete counterexample, take

```lean
b := void
n := void
s := delta (delta void)
```

and abbreviate `ω := omega0`. Then

```text
D := mu (delta void) = ω^5 + 1

S := mu s
   = ω^5 * (D + 1) + 1
   = (ω^10 + ω^5 * 2) + 1.
```

Writing `L := ω^10 + ω^5 * 2`, we have `S = L + 1`. Since `D + L = L`,

```text
D + S = D + (L + 1) = L + 1 = S.
```

Consequently, the source and the recursive call have the same leading exponent:

```text
mu (recDelta void s (delta void))
  = ω^(D + S + 6) + ω + 1
  = ω^(S + 6) + ω + 1,

mu (recDelta void s void)
  = ω^(0 + S + 6) + ω + 1
  = ω^(S + 6) + ω + 1.
```

Let `E := S + 6`. The reduct has measure

```text
mu (app s (recDelta void s void))
  = ω^3 * (S + 1)
      + ω^2 * (ω^E + ω + 2) + 1.
```

Here `2 + E = E`, hence

```text
ω^2 * ω^E = ω^(2 + E) = ω^E.
```

After the smaller preceding term is absorbed, the reduct has a tail beginning at least with `ω^3`, whereas the source only has the tail `ω + 1`. In particular,

```text
mu (recDelta void s (delta void))
  < mu (app s (recDelta void s void)),
```

the opposite of the required inequality.

Thus no Lean proof skeleton can close `R_rec_succ` without changing the measure or restricting the terms. A likely repair is to put the step argument before the recursion counter in the exponent,

```lean
omega0 ^ (mu s + mu n + 6)
```

or to use a commutative/natural ordinal sum. With ordinary ordinal addition, placing `mu s` after `mu n` allows it to absorb the decrease in the counter.
