The proof cannot be completed as stated: the `R_rec_succ` case is false for the given measure. The other two missing cases have straightforward proof skeletons.

### `R_eq_refl`

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact add_pos_right _ one_pos
```

If `simp` leaves the goal in a slightly different positivity form, the same pattern used in `R_int_delta` works:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

### `R_eq_diff`

The remaining arithmetic can be isolated as a general ordinal bound:

```lean
| _, _, Step.R_eq_diff a b => by
    simp only [mu]
    let α := mu a
    let β := mu b

    have hpoly :
        omega0 ^ (4 : Ordinal) *
            (omega0 ^ (3 : Ordinal) * (α + 1) +
             omega0 ^ (2 : Ordinal) * (β + 1) + 1 + 1)
          < omega0 ^ (α + β + 9) := by
      -- Expand the left product using left distributivity.
      -- Bound:
      --   ω⁴ * (ω³ * (α+1)) < ω^(α+β+9),
      --   ω⁴ * (ω² * (β+1)) < ω^(α+β+9),
      --   ω⁴ * 2             < ω^(α+β+9).
      --
      -- A convenient intermediate bound is:
      --   α + 1 < ω^(α+β+2)
      --   β + 1 < ω^(α+β+2)
      --
      -- Then multiplication by the finite powers ω⁷ and ω⁶
      -- remains below ω^(α+β+9). Combine the summands using
      -- add_lt_of_lt_opow (or the corresponding additive-principal
      -- lemma for powers of ω).
      sorry

    -- Strict right addition preserves the inequality.
    exact add_lt_add_right hpoly 1
```

The helper needed here can equivalently be stated outside the case as:

```lean
lemma eq_diff_ordinal_bound (α β : Ordinal) :
    omega0 ^ (4 : Ordinal) *
        (omega0 ^ (3 : Ordinal) * (α + 1) +
         omega0 ^ (2 : Ordinal) * (β + 1) + 1 + 1)
      < omega0 ^ (α + β + 9) := by
  -- Finite-power polynomial expressions in α and β are below
  -- the additively principal ordinal ω^(α+β+9).
  ...
```

### Why `R_rec_succ` cannot be proved

Take

```lean
n := void
s := void
b := eqW (delta void) void
```

Write `ω` for `omega0`. Then

```text
mu (delta void) = ω⁵ + 1
mu b            = ω^(ω⁵ + 10) + 1
```

Set `F = ω⁵ + 10`. For the source,

```text
mu (recDelta b void (delta void))
  = ω^(ω⁵ + 7) + ω * (ω^F + 2) + 1
  = ω^F + ω * 2 + 1.
```

The first term is swallowed because `ω⁵ + 7 < F`, while
`1 + F = F`.

For the inner recursive term on the target side,

```text
mu (recDelta b void void)
  = ω⁶ + ω * (ω^F + 2) + 1
  = ω^F + ω * 2 + 1.
```

Consequently,

```text
mu (app void (recDelta b void void))
  = ω³ + ω² * (ω^F + ω * 2 + 2) + 1
  = ω^F + ω³ * 2 + ω² * 2 + 1.
```

Thus

```text
mu (recDelta b void (delta void))
  = ω^F + ω * 2 + 1

mu (app void (recDelta b void void))
  = ω^F + ω³ * 2 + ω² * 2 + 1,
```

so the target measure is strictly larger, not smaller.

The issue is that the source stores the base measure as

```lean
omega0 * (mu b + 1),
```

whereas the target’s `app` wraps the entire recursive-call measure in

```lean
omega0 ^ 2 * (mu (recDelta b s n) + 1).
```

For sufficiently large `mu b`, that outer `ω²` multiplication increases the relevant lower-order tail. Therefore no proof skeleton can fill all three holes without changing `mu`, weakening the theorem, or restricting the rewrite rule.
