Here is a usable skeleton for the three `sorry`s, with one important caveat:

- `R_eq_refl` is straightforward and can likely be filled exactly.
- `R_eq_diff` should be finishable with two small auxiliary ordinal lemmas.
- `R_rec_succ` looks problematic with the current `mu`: the natural proof skeleton is clear, but the key exponent comparison is where ordinal absorption can break it. I’ll show the skeleton and also point out the obstruction.

## 1. `R_eq_refl`

This one should be the same positivity argument you already used for `R_int_delta`:

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

## 2. `R_eq_diff`

The clean way to do this is to factor out two helper lemmas.

### Helper lemma A: additive closure below an `ω`-power
You want a lemma of the form

```lean
-- exact theorem name may differ
have hAddClosed :
    ∀ {γ x y : Ordinal}, x < omega0 ^ γ -> y < omega0 ^ γ -> x + y < omega0 ^ γ := by
  -- use that `omega0 ^ γ` is additively principal
  ...
```

This should come from `Mathlib.SetTheory.Ordinal.Principal`.

### Helper lemma B: finite left multiplication shifts the exponent finitely
You also want

```lean
-- exact theorem name / proof shape may differ
have hMulShift :
    ∀ {k : ℕ} {β x : Ordinal},
      x < omega0 ^ β ->
      omega0 ^ (k : Ordinal) * x < omega0 ^ (β + k) := by
  ...
```

This is the standard “prefix by a finite `ω^k` only raises the exponent by `k`” fact.

---

### Skeleton for the case

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]

    let L : Ordinal := mu a + mu b + 5

    have hCoeffA : mu a + 1 < omega0 ^ (mu a + 1) := by
      -- standard fact: α < ω^α, applied to α = mu a + 1
      ...

    have hCoeffB : mu b + 1 < omega0 ^ (mu b + 1) := by
      -- same
      ...

    have hA0 : omega0 ^ (3 : Ordinal) * (mu a + 1) < omega0 ^ ((mu a + 1) + 3) := by
      simpa [Ordinal.add_assoc] using
        (hMulShift (k := 3) hCoeffA)

    have hA : omega0 ^ (3 : Ordinal) * (mu a + 1) < omega0 ^ L := by
      have hExp : (mu a + 1) + 3 ≤ L := by
        -- `(mu a + 1) + 3 = mu a + 4 ≤ mu a + mu b + 5`
        ...
      exact lt_of_lt_of_le hA0 <|
        -- monotonicity of `γ ↦ ω^γ`
        ...
    
    have hB0 : omega0 ^ (2 : Ordinal) * (mu b + 1) < omega0 ^ ((mu b + 1) + 2) := by
      simpa [Ordinal.add_assoc] using
        (hMulShift (k := 2) hCoeffB)

    have hB : omega0 ^ (2 : Ordinal) * (mu b + 1) < omega0 ^ L := by
      have hExp : (mu b + 1) + 2 ≤ L := by
        -- `(mu b + 1) + 2 = mu b + 3 ≤ mu a + mu b + 5`
        ...
      exact lt_of_lt_of_le hB0 <|
        ...

    have hOne : (1 : Ordinal) < omega0 ^ L := by
      -- since `L` has a `+ 5`, it is positive, so `ω^L` is > 1
      ...

    have hInner :
        omega0 ^ (3 : Ordinal) * (mu a + 1) +
          omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1
        < omega0 ^ L := by
      -- combine hA, hB, and the two trailing `1`s using additive principality
      have hB1 :
          omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 < omega0 ^ L := by
        exact hAddClosed hB hOne
      have hB2 :
          omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1 < omega0 ^ L := by
        exact hAddClosed hB1 hOne
      exact hAddClosed hA hB2

    have hMain :
        omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1) +
            omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1)
        < omega0 ^ (L + 4) := by
      simpa [Ordinal.add_assoc] using
        (hMulShift (k := 4) hInner)

    have hPow :
        omega0 ^ (L + 4) ≤ omega0 ^ (mu a + mu b + 9) := by
      -- `L + 4 = (mu a + mu b + 5) + 4 = mu a + mu b + 9`
      simpa [L, Ordinal.add_assoc]

    have hFinal :
        omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1) +
            omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1)
        < omega0 ^ (mu a + mu b + 9) := by
      exact lt_of_lt_of_le hMain hPow

    exact add_lt_add_right hFinal 1
```

The exact monotonicity lemma for `ω^_` may be something like using `opow_isNormal` / `strictMono`; I can’t guarantee the identifier without a compiler, but that’s the shape.

## 3. `R_rec_succ`

## The intended proof skeleton

If the measure were adequate, the natural skeleton would be:

```lean
| _, _, Step.R_rec_succ b s n => by
    simp [mu]

    let K : Ordinal := mu n + mu s + 6

    have hTail :
        omega0 * (mu b + 1) + 1 + 1 < omega0 ^ K := by
      -- because `K` has a trailing `+ 6`, so `ω^K` dominates all `ω * (...) + finite`
      ...

    have hInner :
        omega0 ^ K + (omega0 * (mu b + 1) + 1 + 1) < omega0 ^ (K + 1) := by
      -- use additive principality of `ω^(K+1)` plus:
      --   `ω^K < ω^(K+1)` and `hTail`
      ...

    have hSecond :
        omega0 ^ (2 : Ordinal) *
          (omega0 ^ K + omega0 * (mu b + 1) + 1 + 1)
        < omega0 ^ (K + 3) := by
      -- apply the finite-prefix lemma with k = 2
      simpa [K, Ordinal.add_assoc] using
        (hMulShift (k := 2) hInner)

    have hCoeffS : mu s + 1 < omega0 ^ (mu s + 1) := by
      ...

    have hFirst0 :
        omega0 ^ (3 : Ordinal) * (mu s + 1) < omega0 ^ ((mu s + 1) + 3) := by
      simpa [Ordinal.add_assoc] using
        (hMulShift (k := 3) hCoeffS)

    have hFirst :
        omega0 ^ (3 : Ordinal) * (mu s + 1) < omega0 ^ (K + 3) := by
      have hExp : (mu s + 1) + 3 ≤ K + 3 := by
        -- `mu s + 4 ≤ mu n + mu s + 9`
        ...
      exact lt_of_lt_of_le hFirst0 <|
        ...

    have hApp :
        omega0 ^ (3 : Ordinal) * (mu s + 1) +
          omega0 ^ (2 : Ordinal) *
            (omega0 ^ K + omega0 * (mu b + 1) + 1 + 1) + 1
        < omega0 ^ (K + 3) := by
      -- additive principality again, combining hFirst, hSecond, and `1`
      ...

    have hExp :
        K + 3 < omega0 ^ (5 : Ordinal) * (mu n + 1) + 1 + mu s + 6 := by
      -- this is the key comparison
      ...

    have hPow :
        omega0 ^ (K + 3) <
          omega0 ^
            (omega0 ^ (5 : Ordinal) * (mu n + 1) + 1 + mu s + 6) := by
      -- monotonicity of `ω^_`
      ...

    exact lt_of_lt_of_le hApp <|
      le_trans hPow.le (le_add_right _ _)
```

---

## Why this case is likely not actually provable as written

The problematic subgoal is exactly:

```lean
have hExp :
  K + 3 < omega0 ^ (5 : Ordinal) * (mu n + 1) + 1 + mu s + 6 := ...
```

with `K = mu n + mu s + 6`.

Because ordinal addition is **not** strictly monotone in the left argument, the `mu (delta n)` contribution can be absorbed by a large `mu s`.

A concrete bad pattern is:

```lean
s₀ := recDelta void void (delta void)
b  := void
n  := void
```

Then

- `mu s₀ = ω^(ω^5 + 7) + ω + 1`
- `mu (recDelta void s₀ (delta void)) = ω^(mu s₀ + 6) + ω + 1`
- `mu (app s₀ (recDelta void s₀ void))`
  unfolds to
  `ω^3 * (mu s₀ + 1) + ω^2 * (ω^(mu s₀ + 6) + ω + 2) + 1`

and the leading exponent in the `ω^2 * (...)` term collapses back to `mu s₀ + 6`, so the target measure appears **larger**, not smaller.

So, unless I’m missing an extra invariant on `s`, I do **not** think `R_rec_succ` can be finished under the current definition of `mu`.

---

## Bottom line

- `R_eq_refl`: use the exact positivity proof above.
- `R_eq_diff`: prove it via two helpers:
  1. additively-principal closure below `ω^γ`,
  2. `ω^k * x < ω^(β + k)` for finite `k` when `x < ω^β`.
- `R_rec_succ`: the same helper-based approach gives the natural skeleton, but the key exponent comparison is where the current measure seems to fail because of ordinal absorption.
