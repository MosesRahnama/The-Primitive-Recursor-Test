# Proof Skeleton for the Three Remaining Cases

Below is a skeleton for each `sorry`, with the key lemmas and structural steps identified. I keep the design invariants of `mu` in mind: the constructor exponents create a strict hierarchy so that a single dominant `omega0`-power term absorbs everything below it.

## Case 1: `R_eq_refl` (the easy positivity case)

Here the goal after `simp [mu]` is essentially `0 < omega0 ^ (mu a + mu a + 9) + 1`. This is pure positivity — the `+ 1` guarantees it.

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    -- Goal: 0 < omega0 ^ (mu a + mu a + 9) + 1
    -- Strategy: the trailing "+ 1" is enough; the opow term is nonneg.
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
    -- Alternative if the simp normal form differs:
    -- exact lt_of_lt_of_le one_pos (le_add_left _ _)
    -- or: positivity-style: `exact add_pos_right _ one_pos` after matching shape.
```

**Note:** Check what `simp [mu]` produces exactly. If the RHS collapses differently (e.g. the exponent is normalized), you may need `Ordinal.add_pos` / `opow_pos` combinators. The reliable fallback is:
```lean
    calc (0 : Ordinal)
      _ < 1 := one_pos
      _ ≤ omega0 ^ (mu a + mu a + 9) + 1 := le_add_left _ _
```

## Case 2: `R_eq_diff` (exponent domination)

Goal shape: `omega0^4 * (mu(merge a b) + 1) + 1 < omega0^(mu a + mu b + 9) + 1`.

The key is that the LHS is bounded by some `omega0^k` with `k < mu a + mu b + 9`, and a smaller power tower is dominated.

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]
    -- Let e := mu a + mu b + 9 (the RHS exponent).
    -- STEP 1: Bound the LHS by a single power omega0 ^ c with c < e.
    --   mu(integrate (merge a b))
    --     = omega0^4 * (omega0^3*(mu a+1) + omega0^2*(mu b+1) + 1 + 1) + 1
    --   Every factor here is < omega0^(mu a + mu b + 4) or so, and multiplying
    --   by omega0^4 keeps the exponent below mu a + mu b + 9.
    --
    -- Helper lemma A (principal-additive / opow monotonicity):
    have hexp : mu a + mu b + 4 < mu a + mu b + 9 := by
      apply Ordinal.add_lt_add_left
      -- 4 < 9
      decide  -- or `norm_num`/explicit `Ordinal` cast lemma
    -- Helper lemma B: bound the inner merge measure by a power.
    have hmerge_le :
        omega0 ^ (3:Ordinal) * (mu a + 1)
          + omega0 ^ (2:Ordinal) * (mu b + 1) + 1
          < omega0 ^ (mu a + mu b + 4) := by
      -- Use that omega0^(mu a + mu b + 4) is additively principal (limit power)
      -- and each summand is strictly below it:
      --   omega0^3*(mu a+1)   < omega0^(mu a + 4)   ≤ omega0^(mu a + mu b + 4)
      --   omega0^2*(mu b+1)   < omega0^(mu b + 3)   ≤ omega0^(mu a + mu b + 4)
      --   1                   < omega0^(...)
      sorry
    -- STEP 2: Lift through the outer omega0^4 * (· + 1).
    have hlhs_le :
        omega0 ^ (4:Ordinal)
          * (omega0 ^ (3:Ordinal) * (mu a + 1)
             + omega0 ^ (2:Ordinal) * (mu b + 1) + 1 + 1)
          < omega0 ^ (mu a + mu b + 9) := by
      -- omega0^4 * X  where X < omega0^(mu a + mu b + 4)+1 ≤ omega0^(mu a + mu b + 4)*ω
      -- so omega0^4 * X < omega0^(4 + (mu a + mu b + 4) + 1) ≤ omega0^(mu a + mu b + 9)
      -- Key lemma: `Ordinal.opow_add`, `Ordinal.mul_lt_opow`-style,
      -- and `Principal.principal_add_omega0_opow`.
      sorry
    -- STEP 3: Add the trailing "+1" and conclude.
    calc omega0 ^ (4:Ordinal) * (_ + 1) + 1
        _ < omega0 ^ (mu a + mu b + 9)     := by
              -- from hlhs_le plus absorbing the "+1" using that the RHS is a limit
              sorry
        _ ≤ omega0 ^ (mu a + mu b + 9) + 1 := le_add_right _ _
```

**Key Mathlib lemmas to use:**
- `Ordinal.opow_lt_opow_right` / `opow_le_opow_right` (monotone exponent)
- `Ordinal.opow_add` : `omega0 ^ (x + y) = omega0 ^ x * omega0 ^ y`
- `Principal.principal_add_omega0_opow` (additive principality of `omega0 ^ e` for absorbing sums and `+1`)
- `Ordinal.mul_lt_opow` or `lt_opow_iff` style bounds for `omega0^k * c < omega0^(k + ...)`

## Case 3: `R_rec_succ` (the hardest — exponent tower domination)

Goal: `mu(app s (recDelta b s n)) < mu(recDelta b s (delta n))`.

The dominating fact: RHS exponent is `mu(delta n) + mu s + 6 = omega0^5*(mu n+1)+1 + mu s + 6`, which is **enormously** larger than any exponent appearing in the LHS. So the whole RHS is a single `omega0`-power that dwarfs the LHS.

```lean
| _, _, Step.R_rec_succ b s n => by
    simp [mu]
    -- Abbreviations:
    --   E_rhs := mu(delta n) + mu s + 6 = omega0^5*(mu n + 1) + 1 + mu s + 6
    --   LHS   := omega0^3*(mu s + 1)
    --           + omega0^2*(mu(recDelta b s n) + 1) + 1
    --   where mu(recDelta b s n) = omega0^(mu n + mu s + 6) + omega0*(mu b + 1) + 1
    --
    -- STEP 0: Establish the exponent gap. Everything in the LHS lives below
    --   omega0^(mu n + mu s + 7)  (say), and E_rhs > that because of the
    --   omega0^5*(mu n+1) summand.
    have hgap : (mu n + mu s + 7) < (omega0 ^ (5:Ordinal) * (mu n + 1) + 1 + mu s + 6) := by
      -- mu n + mu s + 7 is dwarfed by omega0^5*(mu n+1); use:
      --   mu n + mu s + 7 < omega0^5      (since finite + smaller powers < omega0^5 * 1)
      --   ≤ omega0^5*(mu n+1) ≤ E_rhs
      sorry
    -- STEP 1: Bound mu(recDelta b s n) by a power with exponent < E_rhs.
    have hrec_le :
        omega0 ^ (mu n + mu s + 6) + omega0 * (mu b + 1) + 1
          < omega0 ^ (mu n + mu s + 7) := by
      -- omega0^(mu n+mu s+6) < omega0^(mu n+mu s+7); the lower-order
      -- omega0*(mu b+1)+1 is absorbed by additive principality of the bigger power.
      sorry
    -- STEP 2: Bound the whole LHS by a single power < E_rhs.
    have hlhs_le :
        omega0 ^ (3:Ordinal) * (mu s + 1)
          + omega0 ^ (2:Ordinal)
            * (omega0 ^ (mu n + mu s + 6) + omega0 * (mu b + 1) + 1 + 1)
          + 1
          < omega0 ^ (omega0 ^ (5:Ordinal) * (mu n + 1) + 1 + mu s + 6) := by
      -- Bound each summand:
      --   omega0^3*(mu s+1)                     < omega0^(mu s + 4)
      --   omega0^2*(mu(recDelta b s n)+1)       < omega0^2 * omega0^(mu n+mu s+7)
      --                                          = omega0^(mu n + mu s + 9)  (via hrec_le, opow_add)
      --   1                                     < the target
      -- Then all are < omega0^(mu n + mu s + 9) ≤ omega0^E_rhs by hgap + opow monotonicity,
      -- and additive principality of omega0^E_rhs absorbs the sum.
      sorry
    -- STEP 3: Add "+1" and conclude with the RHS "+1".
    calc (_ : Ordinal)
        _ < omega0 ^ (omega0 ^ (5:Ordinal) * (mu n + 1) + 1 + mu s + 6) := hlhs_le
        _ ≤ omega0 ^ (omega0 ^ (5:Ordinal) * (mu n + 1) + 1 + mu s + 6)
              + omega0 * (mu b + 1) + 1 := by
              exact le_trans (le_add_right _ _) (le_add_right _ _)
    -- NB: match the RHS shape produced by `simp [mu]`; you may need to reassociate
    --     using `add_assoc` / `Ordinal.add_assoc` before applying the calc.
```

**Key Mathlib lemmas / tactics for the tower case:**
- `Ordinal.opow_add : a ^ (b + c) = a ^ b * a ^ c` — to turn `omega0^2 * omega0^k` into `omega0^(2+k)`.
- `Ordinal.opow_lt_opow_right` (strict, needs `1 < omega0`, use `Ordinal.one_lt_omega0`).
- `Ordinal.mul_lt_opow` / `Ordinal.lt_opow_of_lt` for `omega0^k * (c+1) < omega0^(k+1)` (finite/small coefficient absorbed).
- `Principal.principal_add_omega0_opow : Principal (·+·) (omega0 ^ e)` — the workhorse for STEP 2/hlhs_le: it lets you conclude `x + y < omega0^e` from `x < omega0^e` and `y < omega0^e`.
- `Ordinal.add_lt_add_left`, `Ordinal.add_lt_add_right` for the finite `+7 < ...` gaps.

## General Advice

1. **Inspect the post-`simp` goal first.** The exact associativity and whether `mu void = 0` is already substituted determines the calc shapes. Insert a temporary `sorry` and use the goal display, then match `add_assoc`.

2. **Factor out a reusable absorption lemma** to avoid repetition across cases 2 and 3:
   ```lean
   private lemma absorb {e x y : Ordinal}
       (hx : x < omega0 ^ e) (hy : y < omega0 ^ e) : x + y < omega0 ^ e :=
     (Ordinal.principal_add_omega0_opow e) hx hy
   ```
   and a "power dominates smaller-power-times-coefficient" lemma:
   ```lean
   private lemma pow_mul_lt {k c : Ordinal} (hc : c < omega0) :
       omega0 ^ k * c < omega0 ^ (k + 1) := by
     rw [Ordinal.opow_add, opow_one]; exact Ordinal.mul_lt_mul_left' hc _ -- adjust
   ```

3. **Order of difficulty:** do `R_eq_refl` first (trivial), then `R_eq_diff`, then `R_rec_succ` (reuse the two helper lemmas).

I have not run the compiler; lemma names such as `Ordinal.principal_add_omega0_opow`, `Ordinal.opow_lt_opow_right`, and `Ordinal.one_lt_omega0` should be verified against your Mathlib version and adjusted (some may be spelled `Principal.principal_add_...` or require `open Ordinal`).
