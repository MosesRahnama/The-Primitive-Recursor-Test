Below is a proof skeleton for the three remaining cases. I am not modifying the file; I’m only indicating a plausible Lean strategy and the key lemmas/shape of the arguments.

The main idea in all three cases is:

- reduce by `simp [mu]`
- prove positivity / nonzeroness for the easy `eq_refl` case
- for the two hard cases, first prove a comparison between exponents, then lift it through monotonicity/strict monotonicity of `ω ^ _`
- finally absorb smaller additive tails with `le_add_right` / `lt_of_lt_of_le` / `succ_le_iff`

---

## 1. `R_eq_refl`

This one should be very close to the first proved case.

```lean
| _, _, Step.R_eq_refl a => by
    simp [mu]
    exact Ordinal.pos_iff_ne_zero.mpr (by
      apply ne_of_gt
      exact add_pos_right _ one_pos)
```

### Why this works
After `simp [mu]`, the goal is essentially
```lean
0 < omega0 ^ (mu a + mu a + 9) + 1
```
and `add_pos_right _ one_pos` proves any ordinal plus `1` is positive.

If `simp` leaves the goal as `<` rather than `≠ 0`, the above is still the same pattern as the already completed `R_int_delta`.

## 2. `R_rec_succ`

This is the genuinely delicate case. The intended proof pattern is:

1. `simp [mu]`
2. Let
   - `α := mu n + mu s + 6`
   - `β := omega0 ^ 5 * (mu n + 1) + 1 + mu s + 6`
     (or whatever exact parenthesization `simp` produces)
3. Show `α < β`
4. Conclude `omega0 ^ α < omega0 ^ β`
5. Use that to show
   ```lean
   mu (recDelta b s n) + 1 ≤ omega0 ^ β
   ```
   hence
   ```lean
   omega0 ^ 2 * (mu (recDelta b s n) + 1) ≤ omega0 ^ 2 * omega0 ^ β
   ```
6. Rewrite / bound `omega0 ^ 2 * omega0 ^ β ≤ omega0 ^ β`
   or more realistically show the whole left side
   ```lean
   omega0 ^ 3 * (mu s + 1) + omega0 ^ 2 * (mu (recDelta b s n) + 1) + 1
   ```
   is below `omega0 ^ β + omega0 * (mu b + 1) + 1`
   by using that `omega0 ^ β` dominates all terms with much smaller exponents.

A skeleton:

```lean
| _, _, Step.R_rec_succ b s n => by
    simp [mu]
    -- Set the key exponents for readability.
    let α : Ordinal := mu n + mu s + (6 : Ordinal)
    let β : Ordinal := omega0 ^ (5 : Ordinal) * (mu n + 1) + 1 + mu s + (6 : Ordinal)

    -- First show the old recursion exponent is strictly smaller than the new one.
    have hαβ : α < β := by
      -- enough: mu n < omega^5 * (mu n + 1) + 1
      have h1 : mu n < mu n + 1 := lt_add_one (mu n)
      have h2 : mu n + 1 ≤ omega0 ^ (5 : Ordinal) * (mu n + 1) :=
        le_mul_right _ (opow_pos 5 omega0_pos)
      have h3 : mu n < omega0 ^ (5 : Ordinal) * (mu n + 1) := lt_of_lt_of_le h1 h2
      -- then add the common tail `mu s + 6`
      -- use monotonicity of addition in the left argument
      -- something like:
      -- exact add_lt_add_right (add_lt_add_right h3 1) (mu s + 6)
      --
      -- Depending on simp's parenthesization, you may need a few `simpa [α, β, add_assoc]`.
      sorry

    -- Lift strict inequality through exponentiation base omega.
    have hpow : omega0 ^ α < omega0 ^ β := by
      -- use strict monotonicity of `a ↦ omega0 ^ a`
      -- likely lemma shape: opow_lt_opow_right omega0 one_lt_omega0 hαβ
      -- or `Ordinal.opow_lt_opow_right`
      sorry

    -- The recursive payload is below the leading omega^β term.
    have hrec : omega0 ^ α + omega0 * (mu b + 1) + 1 < omega0 ^ β := by
      -- Here use that `omega0 ^ β` is an additive principal ordinal,
      -- and both `omega0 ^ α` and the lower-order tail are below it.
      --
      -- Typical route:
      -- 1. from hpow get `omega0 ^ α + ... < omega0 ^ β`
      --    because adding lower-order terms below `omega0 ^ β` still stays below
      -- 2. use principal-ordinal closure / `isNormal` lemmas for `ω^_`
      sorry

    -- Therefore the app's second argument is small enough.
    have htail :
        omega0 ^ (2 : Ordinal) * (omega0 ^ α + omega0 * (mu b + 1) + 1 + 1)
          < omega0 ^ β := by
      -- Use hrec together with domination of multiplication by ω² on a smaller ordinal.
      -- Since the exponent β begins with an `ω^5 * ...`, it dominates any `ω^2 * (...)`
      -- built from terms below `ω^β`.
      sorry

    have hleft :
        omega0 ^ (3 : Ordinal) * (mu s + 1)
          + omega0 ^ (2 : Ordinal) * (omega0 ^ α + omega0 * (mu b + 1) + 1 + 1) + 1
          < omega0 ^ β + omega0 * (mu b + 1) + 1 := by
      -- absorb the `ω^3 * (mu s + 1)` term and the final `+1` into the dominant `ω^β`
      -- using `hpow` / `htail` and then `lt_of_lt_of_le` with `le_add_right`.
      sorry

    simpa [α, β, add_assoc, add_left_comm, add_comm]
      using hleft
```

### Practical note
The exact library lemmas for monotonicity of `ω^_` may differ in name. The shape you likely want is one of:

- `Ordinal.opow_lt_opow_right`
- `Ordinal.opow_le_opow_right`
- monotonicity from `Ordinal.isNormal_opow` / `IsNormal`

Also, for the “dominant leading term absorbs lower tails” steps, Mathlib often has principal-ordinal lemmas tied to `ω^a`; if those are annoying to find, a workaround skeleton is:

- first prove each smaller summand is `≤ omega0 ^ β`
- then chain inequalities into a final `≤ omega0 ^ β + omega0 * ... + 1`
- use one strict inequality somewhere to keep the whole result strict.

## 3. `R_eq_diff`

This is similar in spirit but easier than `rec_succ`: show the exponent `mu a + mu b + 9` is large enough that `ω^(mu a + mu b + 9)` dominates the entire `integrate (merge a b)` measure.

After `simp [mu]`, the goal is essentially:

```lean
omega0 ^ (4 : Ordinal) *
    (omega0 ^ (3 : Ordinal) * (mu a + 1)
      + omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1) + 1
  < omega0 ^ (mu a + mu b + 9) + 1
```

A good skeleton:

```lean
| _, _, Step.R_eq_diff a b => by
    simp [mu]

    let γ : Ordinal := mu a + mu b + (9 : Ordinal)

    -- First show the merge-measure is below ω^γ.
    have hA : omega0 ^ (3 : Ordinal) * (mu a + 1) < omega0 ^ γ := by
      -- Since 3 < γ (because γ has a +9 tail), ω^3 * (mu a + 1) is far below ω^γ.
      -- One route: show `3 < γ`, then `omega0 ^ 3 < omega0 ^ γ`,
      -- then multiply by `(mu a + 1)` still remains below `omega0 ^ γ`.
      sorry

    have hB : omega0 ^ (2 : Ordinal) * (mu b + 1) < omega0 ^ γ := by
      -- same idea
      sorry

    have hmerge :
        omega0 ^ (3 : Ordinal) * (mu a + 1)
          + omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1
        < omega0 ^ γ := by
      -- combine hA and hB; ω^γ being principal absorbs finite / lower-order additions
      sorry

    have hint :
        omega0 ^ (4 : Ordinal) *
            (omega0 ^ (3 : Ordinal) * (mu a + 1)
              + omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1)
        < omega0 ^ γ := by
      -- multiplying a smaller ordinal by ω^4 still stays below ω^γ
      -- because γ is much larger than 4, indeed γ = mu a + mu b + 9.
      sorry

    calc
      omega0 ^ (4 : Ordinal) *
          (omega0 ^ (3 : Ordinal) * (mu a + 1)
            + omega0 ^ (2 : Ordinal) * (mu b + 1) + 1 + 1) + 1
          < omega0 ^ γ + 1 := add_lt_add_right hint 1
      _ = omega0 ^ (mu a + mu b + (9 : Ordinal)) + 1 := by
            simp [γ]
```

### Alternate skeleton
A more “ordinal-arithmetic” way is to prove directly that the left side is bounded by something like `ω^8` times a smaller tail, hence `< ω^(mu a + mu b + 9)`. For example:

- `merge` has leading rank `ω^3`
- `integrate` wraps with `ω^4 * (...)`
- so overall the left side is of “height at most `ω^7` over the subterms”
- while `eqW` uses exponent `mu a + mu b + 9`, which is intentionally much larger.

That suggests a proof by showing:
```lean
omega0 ^ (4 : Ordinal) * (...) < omega0 ^ (mu a + mu b + 8)
```
and then
```lean
omega0 ^ (mu a + mu b + 8) < omega0 ^ (mu a + mu b + 9)
```
then add `1` on the right.

## Summary of likely missing lemma types

When you actually fill these in, the needed lemmas will likely be among these shapes:

- positivity:
  - `Ordinal.pos_iff_ne_zero`
  - `add_pos_right`
  - `one_pos`
- monotonicity:
  - `lt_add_one`
  - `le_add_right`
  - `le_add_left`
  - `add_lt_add_right`
- multiplication positivity:
  - `opow_pos`
  - `omega0_pos`
  - `le_mul_right`
- exponentiation monotonicity / normality:
  - something like `Ordinal.opow_lt_opow_right`
  - or normal-function lemmas for `fun x => omega0 ^ x`
- absorption of lower terms into `ω^β`:
  - principal ordinal lemmas for `ω^β`
  - or proving each summand `< ω^β` and combining carefully
